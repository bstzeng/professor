垃圾回收

這一課的目標

  • 理解手動與自動記憶體管理
  • 認識主要的垃圾回收演算法
  • 了解 Rust 的所有權

記憶體的兩種錯誤

在 C 語言中，用 malloc 配置的記憶體必須用 free 釋放。忘記釋放，就是記憶體洩漏；釋放之後又使用，就是懸置指標（use-after-free），可能造成當機或安全漏洞。據微軟與 Google 的統計，它們產品中約七成的嚴重安全漏洞與記憶體安全有關。

垃圾回收

垃圾回收（GC）由執行環境自動找出「不再被使用」的物件並回收。Java、C#、Go、JavaScript、Python 都使用 GC。

方法原理特點
參考計數每個物件記錄有幾個指標指向它，歸零就回收即時；但無法回收「循環參考」（CPython 另有輔助的回收器）
標記—清除從根（全域變數、堆疊）出發，標記所有可到達的物件，其餘清除能處理循環；可能需要暫停程式
複製回收把活著的物件複製到新的區域，舊區域整個清空沒有碎片；需要兩倍空間
世代回收大部分物件「年紀輕輕就死去」；頻繁回收年輕世代，少回收老世代Java、.NET、V8 都使用

暫停的問題

早期的 GC 會「停止整個世界」，讓程式暫停數百毫秒，對遊戲與即時系統很不友善。現代的回收器（例如 Java 的 ZGC、Go 的回收器）大部分工作與程式同時進行，暫停時間可以壓到毫秒以下。

Rust 的第三條路

Rust 既沒有 GC，也不需要手動 free：每個值都有唯一的擁有者，擁有者離開作用域時自動釋放；借用的規則由編譯器的「借用檢查器」在編譯時驗證。這讓記憶體安全的檢查，從執行時移到了編譯時——正是編譯器能力的展現。

🧭 這一課的重點

C 用 malloc 配置須 free 釋放，忘記是記憶體洩漏、釋放後又使用是懸置指標，微軟與 Google 統計約七成嚴重漏洞與記憶體安全有關；垃圾回收由執行環境自動回收不再使用的物件（Java C# Go JavaScript Python）：參考計數歸零即回收但無法回收循環參考、標記清除從根標記可到達物件能處理循環可能暫停、複製回收無碎片需兩倍空間、世代回收利用大部分物件年輕就死（Java .NET V8）；早期 GC 停止整個世界數百毫秒，現代 ZGC 與 Go 大部分工作同時進行暫停壓到毫秒以下；Rust 每個值有唯一擁有者離開作用域自動釋放，借用檢查器在編譯時驗證，把記憶體安全檢查移到編譯時。
