組譯器與連結器

這一課的目標

  • 理解組譯的工作
  • 理解連結的工作
  • 區分靜態與動態連結

組譯

組譯器把組合語言翻譯成機器碼，產生目的檔（.o、.obj）。目的檔裡的機器碼還不完整：呼叫其他檔案裡的函式時，還不知道它的位址，只能留下一個「待填」的記號（重定位項目）。

連結

連結器把所有的目的檔與函式庫合在一起：

  • 符號解析：找出每一個被引用的函式與全域變數，定義在哪個檔案。找不到時，就是常見的「undefined reference」錯誤；定義了兩次，就是「multiple definition」錯誤。
  • 重定位：決定每一段程式與資料最後的位址，把所有「待填」的位址填上。

靜態連結與動態連結

靜態連結動態連結
做法把函式庫的程式碼複製進執行檔執行時才載入共用的函式庫（.so、.dll、.dylib）
優點單一檔案、部署簡單省空間；函式庫更新（例如安全修補）時不必重新編譯
缺點檔案大；函式庫的漏洞修補需要重新編譯版本衝突（「DLL 地獄」）

Go 與 Rust 預設產生靜態連結的執行檔，部署方便；大多數 Linux 程式則動態連結到系統的 C 函式庫。

執行檔如何被作業系統載入、動態連結器如何在執行時找到函式庫，見〈執行檔是怎麼跑起來的〉；執行檔的格式見〈檔案格式解剖學〉。

🧭 這一課的重點

組譯器把組合語言翻成機器碼產生目的檔，呼叫其他檔案函式時位址未知留下待填的重定位項目；連結器合併目的檔與函式庫，符號解析找出每個引用的定義（找不到是 undefined reference、定義兩次是 multiple definition），重定位決定最終位址並填上；靜態連結把函式庫複製進執行檔單一檔案部署簡單但檔案大漏洞修補要重編，動態連結執行時載入共用函式庫省空間可單獨更新但有版本衝突 DLL 地獄；Go Rust 預設靜態連結，多數 Linux 程式動態連結系統 C 函式庫。

🛠️ 互動工具實作了一個極小的算式語言（數字、變數、+ − × ÷ ^ 與括號），用來示範編譯器的各個階段。

  2. undefined reference 錯誤代表什麼？
  3. 靜態連結與動態連結各有什麼優缺點？
