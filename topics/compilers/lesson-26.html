呼叫慣例與堆疊框

這一課的目標

  • 理解呼叫慣例
  • 理解堆疊框的結構
  • 了解緩衝區溢位的危險

約定

函式 A 呼叫函式 B，B 可能是另一個人、另一種語言、另一個編譯器編譯的。它們必須遵守共同的呼叫慣例：參數放在哪裡？回傳值放在哪裡？哪些暫存器由呼叫者保存、哪些由被呼叫者保存？這些規則屬於 ABI（應用程式二進位介面）。

例如在 Linux 的 x86-64 上，前六個整數參數依序放在 rdi、rsi、rdx、rcx、r8、r9 暫存器，回傳值放在 rax，其餘的參數放在堆疊上。

堆疊框

每次呼叫函式，就在呼叫堆疊上推入一個堆疊框，裡面有：

高位址 │ 呼叫者的堆疊框 │ │ 多出來的參數 │ │ 返回位址 ← 返回時跳回這裡 │ │ 保存的舊框架指標 │ │ 區域變數 │ │ 保存的暫存器 │ ▼ （堆疊往低位址成長）

函式返回時，彈出自己的堆疊框，跳回返回位址。遞迴之所以可行，就是因為每一次呼叫都有自己的堆疊框；遞迴太深時，堆疊用完，就是「堆疊溢位」（stack overflow）。

緩衝區溢位

區域陣列與返回位址都在堆疊上。如果程式把太長的輸入寫進一個區域陣列（C 語言不檢查邊界），就可能覆蓋返回位址，讓函式返回時跳到攻擊者指定的程式碼。這是歷史上最著名的攻擊手法之一（1988 年的莫里斯蠕蟲就利用了它）。現代的編譯器與作業系統用「堆疊金絲雀」、位址隨機化、不可執行的堆疊等方法防禦（見〈資訊安全與駭客攻防〉）。

🧭 這一課的重點

A 呼叫 B 可能是不同人語言編譯器編譯的，必須遵守共同呼叫慣例：參數回傳值放哪、哪些暫存器誰保存，屬於 ABI，Linux x86-64 前六個整數參數放 rdi rsi rdx rcx r8 r9 回傳值放 rax；每次呼叫在呼叫堆疊推入堆疊框，有多出參數返回位址舊框架指標區域變數保存的暫存器，返回時彈出並跳回，遞迴可行因每次有自己的框，太深堆疊用完是堆疊溢位；區域陣列與返回位址都在堆疊，C 不檢查邊界寫入太長可能覆蓋返回位址跳到攻擊者程式碼，1988 年莫里斯蠕蟲利用，現代用堆疊金絲雀位址隨機化不可執行堆疊防禦。
