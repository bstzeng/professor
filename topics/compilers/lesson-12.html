符號表與作用域

這一課的目標

  • 理解符號表的作用
  • 理解作用域的規則
  • 認識名稱遮蔽與閉包

名稱解析

程式中出現 count，它指的是哪一個變數？是這個函式的區域變數、外層的變數，還是全域變數？編譯器用符號表記錄每個名稱的宣告：它的種類（變數、函式、型別）、型別、所在的位置。

作用域

大多數語言使用詞法作用域：名稱的意義由它在原始碼中的位置決定。每進入一個區塊 { }，就推入一層新的作用域；離開時彈出。查找名稱時，從最內層往外找。

int x = 1; // 全域的 x void f() { int x = 2; // 遮蔽了全域的 x { int y = x; // 找到最近的 x：2 } // 這裡看不到 y }

內層宣告了和外層同名的變數，外層的就被遮蔽。許多程式碼檢查工具會對遮蔽發出警告，因為它容易造成錯誤。

閉包

在支援巢狀函式的語言（JavaScript、Python）中，內層函式可以「記住」外層的變數，即使外層函式已經結束——這叫閉包。編譯器必須發現這種情況，把被捕捉的變數從堆疊搬到堆積上，否則外層函式返回後，它就消失了。

常見的錯誤

  • 使用未宣告的名稱（打錯字）。
  • 同一個作用域重複宣告。
  • JavaScript 的 var 沒有區塊作用域，造成迴圈中閉包的經典錯誤——這是 ES6 加入 let 的原因之一。

🧭 這一課的重點

程式中的名稱可能是區域外層或全域變數，編譯器用符號表記錄每個名稱的種類型別位置；多數語言用詞法作用域由原始碼位置決定，進區塊推入新作用域離開彈出，查找從最內層往外；內層同名變數遮蔽外層，檢查工具常警告；JavaScript Python 的內層函式可記住外層變數即使外層已結束叫閉包，編譯器要把被捕捉變數從堆疊搬到堆積；常見錯誤有未宣告名稱、重複宣告、JavaScript var 無區塊作用域造成迴圈閉包錯誤是 ES6 加入 let 的原因之一。

🛠️ 互動工具實作了一個極小的算式語言（數字、變數、+ − × ÷ ^ 與括號），用來示範編譯器的各個階段。

檢查你的理解

  1. 什麼是符號表？它記錄哪些資訊？
  2. 什麼是名稱遮蔽？為什麼可能造成錯誤？
  3. 什麼是閉包？編譯器要為它做什麼特別的處理？
