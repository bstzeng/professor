型別推論

這一課的目標

  • 理解型別推論的想法
  • 認識辛德利—米爾納演算法
  • 了解現代語言的型別推論

少寫一點

早期的 Java 要寫 HashMap<String, List<Integer>> m = new HashMap<String, List<Integer>>();——型別寫了兩遍。型別推論讓編譯器從上下文自動算出型別：C++ 的 auto、Java 的 var、Rust 與 Go 的 :=、Kotlin、Swift、TypeScript 都支援。

像解方程式

型別推論的原理，像是解聯立方程式。看這段程式：

fn f(x) { return x + 1 }
  • x 的型別未知，記為 α。
  • x + 1：+ 要求兩邊型別相同，1 是 int，所以 α = int。
  • 回傳值是 x + 1 的型別：int。
  • 所以 f 的型別是 int → int。

編譯器在 AST 上蒐集所有的型別限制，再用「統一」（unification）的演算法同時解出所有的未知數。

辛德利—米爾納

1970 年代，辛德利與米爾納發展出一套型別推論系統，可以在完全不寫型別的情況下，推論出每個函式最一般的型別，包括泛型。例如 fn id(x) = x 的型別是「對任何 α，α → α」。ML、Haskell、OCaml 等函數式語言使用這套系統；Rust 與 Swift 的型別推論也受到它的影響。

推論的界限

推論太強也有缺點：當推論失敗時，錯誤訊息可能出現在離真正錯誤很遠的地方，令人困惑。所以許多語言要求在函式的邊界（參數與回傳值）寫明型別，在函式內部才進行推論——兼顧可讀性與方便。

🧭 這一課的重點

早期 Java 型別要寫兩遍，型別推論讓編譯器從上下文自動算出，C++ auto、Java var、Rust Go :=、Kotlin Swift TypeScript 支援；原理像解聯立方程式，x 型別記為 α，x＋1 要求兩邊相同 1 是 int 所以 α＝int，f 是 int→int，編譯器蒐集所有限制再用統一演算法解出；1970 年代辛德利與米爾納的系統可完全不寫型別推出最一般型別包括泛型，id 是對任何 α 的 α→α，ML Haskell OCaml 使用、Rust Swift 受影響；推論太強時錯誤訊息可能離真錯誤很遠，許多語言要求函式邊界寫型別內部推論。
