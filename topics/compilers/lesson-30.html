JIT 與 V8

這一課的目標

  • 理解 JIT 的運作方式
  • 理解推測式最佳化
  • 了解 V8 的架構

動態語言的難題

JavaScript 的 a + b：a、b 可能是整數、浮點數、字串、物件……每次執行都要檢查型別，非常慢。2008 年以前，JavaScript 主要由直譯器執行，被認為只適合寫網頁上的小效果。

V8

2008 年，Google 隨 Chrome 瀏覽器推出了 V8 JavaScript 引擎，大幅提升了 JavaScript 的速度，引發了瀏覽器之間的效能競賽，也讓 Gmail、Google 地圖這類大型網頁應用，以及伺服器端的 Node.js 成為可能。

分層編譯

  1. 直譯器（Ignition）：先快速地把程式編成位元組碼並執行，同時觀察：每個運算實際看到了什麼型別。
  2. 最佳化編譯器（TurboFan 等）：對執行次數多的「熱」函式，根據觀察到的型別，產生高度最佳化的機器碼。

推測與反最佳化

如果某個函式的 a、b 到目前為止一直是整數，JIT 就推測以後也是，產生只處理整數的快速機器碼，並在前面加上一個便宜的檢查。如果有一天傳進來的是字串，檢查失敗，就反最佳化：丟掉這段機器碼，回到直譯器，之後可能再根據新的資訊重新編譯。

這就是 JIT 能比事先編譯更快的情況：它根據實際的執行情況做最佳化。代價是需要「暖機」時間與額外的記憶體。

隱藏類別與內聯快取

JavaScript 的物件可以隨時增加屬性，查找屬性本來很慢。V8 在背後為「形狀相同」的物件建立隱藏類別，並在每個存取屬性的地方記住上次看到的形狀與位置（內聯快取）。所以一個實用的建議是：同一種物件，用相同的順序初始化相同的屬性。

🧭 這一課的重點

JavaScript 的 a＋b 可能是整數浮點字串物件每次要檢查型別很慢，2008 年前主要由直譯器執行；2008 年 Google 隨 Chrome 推出 V8 大幅提升速度，引發瀏覽器效能競賽，讓 Gmail Google 地圖與 Node.js 成為可能；分層編譯先用直譯器 Ignition 快速執行並觀察型別，再對熱函式用最佳化編譯器 TurboFan 依觀察的型別產生最佳化機器碼；若 a b 一直是整數 JIT 推測以後也是，產生只處理整數的快速碼加檢查，傳進字串就反最佳化回直譯器；JIT 依實際執行情況最佳化能比事先編譯快，代價是暖機與記憶體；隱藏類別為形狀相同的物件建立、內聯快取記住上次形狀位置，建議同種物件用相同順序初始化相同屬性。
