SSA 形式

這一課的目標

  • 理解 SSA 的規則
  • 理解 φ 函數
  • 理解 SSA 為什麼方便最佳化

單一賦值

在一般的程式中，同一個變數可以被賦值很多次，分析時很難知道「這裡用到的 x，是哪一次賦值的結果」。靜態單一賦值（SSA）形式規定：每個變數只能被賦值一次。每次重新賦值，就給它一個新的名字。

原本： SSA： x = 1 x1 = 1 x = x + 2 x2 = x1 + 2 y = x * 3 y1 = x2 * 3

φ 函數

遇到分支怎麼辦？

if (c) x1 = 1; else x2 = 2; x3 = φ(x1, x2) // 從 if 來就取 x1，從 else 來就取 x2 y1 = x3 + 1

φ 函數放在控制流程匯合的地方，表示「依照從哪一條路走過來，選擇對應的值」。它不是真實的指令，在最後產生機器碼時會被消除。

為什麼好用

  • 每個變數只有一個定義，「這個值從哪裡來」一目了然。
  • 常數傳播：如果 x1 = 5，所有用到 x1 的地方都可以直接換成 5。
  • 死碼消除：一個變數如果沒有任何地方使用，它的定義就可以刪掉。
  • 許多最佳化在 SSA 上變得簡單又快速。

SSA 在 1980 年代末由 IBM 的研究者發展出來，今天幾乎所有的主流編譯器——GCC、LLVM、V8、HotSpot、Go——都使用 SSA 形式的 IR。

🧭 這一課的重點

一般程式同變數可多次賦值，分析時難知道用到的 x 是哪次賦值，靜態單一賦值 SSA 規定每變數只賦值一次，每次重新賦值給新名字 x1 x2；分支匯合處用 φ 函數表示依從哪條路來選對應值，不是真實指令產生機器碼時消除；好處是每變數只有一個定義來源一目了然、常數傳播、無人使用的定義可刪除、許多最佳化變簡單快速；SSA 1980 年代末由 IBM 研究者發展，GCC LLVM V8 HotSpot Go 都使用。
