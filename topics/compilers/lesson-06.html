正規表示式與有限自動機

這一課的目標

  • 用正規表示式描述 token
  • 理解有限自動機
  • 了解詞法分析器產生器

用正規表示式描述 token

token正規表示式
整數[0-9]+
識別字[A-Za-z_][A-Za-z_0-9]*
浮點數（簡化）[0-9]+\.[0-9]+
空白[ \t\n]+

有限自動機

每一個正規表示式，都可以轉換成一台有限自動機：一組狀態，以及「讀到某個字元就從某狀態跳到另一個狀態」的規則。例如辨識整數的自動機：

[0-9] [0-9] (開始) ──────▶ ((數字)) ◀────┐ └─────────┘ 雙圈＝接受狀態：停在這裡，就是一個合法的整數

詞法分析器的核心，就是把所有 token 的正規表示式合併成一台大自動機，然後一個字元一個字元地「走」。每個字元只需要查一次表，所以非常快——時間與輸入長度成正比。

理論的基礎

1950 年代，克萊尼證明了正規表示式與有限自動機的能力相同；1968 年，湯普森（後來的 UNIX 共同發明人）提出把正規表示式轉成自動機的演算法，並用在文字編輯器的搜尋功能中。這些理論在〈計算理論〉與〈離散數學〉中有更多介紹。

自動產生

實務上，可以用 lex／flex 等工具：只要寫下 token 的正規表示式，工具就自動產生詞法分析器的程式碼。不過許多實際的編譯器（例如 GCC、Clang、Go）為了速度與錯誤訊息的品質，選擇手寫詞法分析器。

正規表示式的極限

有限自動機沒有「記憶」，所以無法檢查括號是否配對——那需要計數，可以任意深。這是詞法分析與語法分析的分界：配對、巢狀的結構，需要更強的工具——文法。

🧭 這一課的重點

用正規表示式描述 token：整數 [0-9]+、識別字 [A-Za-z_][A-Za-z_0-9]*；每個正規表示式可轉成有限自動機，一組狀態與讀到字元跳到另一狀態的規則，詞法分析器把所有 token 合併成大自動機逐字元走，每字元查一次表時間與長度成正比；1950 年代克萊尼證明正規表示式與有限自動機能力相同，1968 年湯普森提出轉換演算法用在編輯器搜尋；lex flex 從正規表示式自動產生詞法分析器，但 GCC Clang Go 為速度與錯誤訊息選擇手寫；有限自動機沒有記憶無法檢查括號配對，配對巢狀結構需要文法。

🛠️ 互動工具實作了一個極小的算式語言（數字、變數、+ − × ÷ ^ 與括號），用來示範編譯器的各個階段。
