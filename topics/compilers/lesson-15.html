錯誤訊息

這一課的目標

  • 理解好的錯誤訊息的要素
  • 了解錯誤恢復
  • 比較不同編譯器的錯誤訊息

錯誤訊息很重要

對程式設計師來說，編譯器最常「說話」的時候，就是出錯的時候。一個好的錯誤訊息，可以讓人在幾秒內找到問題；一個糟糕的錯誤訊息，可能浪費一整個下午。

好的錯誤訊息

  • 精確的位置：檔案、行號、欄位，並標出出錯的範圍。
  • 說人話：「預期一個分號」比「語法錯誤」好；「型別不符：預期 int，得到 String」更好。
  • 建議修正：「你是不是想打 length？」
  • 不要連鎖爆炸：一個錯誤不應該引發一百個後續的錯誤。

Rust 與 Elm 的編譯器以友善、詳細的錯誤訊息聞名，常常附上彩色的程式碼片段、解釋與修正建議。這讓許多人改變了「編譯器就是很嚴厲」的印象。

錯誤恢復

編譯器遇到第一個錯誤時，不應該立刻放棄，而是要恢復並繼續檢查，一次回報多個錯誤。常見的方法是「恐慌模式」：跳過 token，直到遇到一個可靠的同步點（例如分號或右大括號），再重新開始剖析。

C++ 樣板的惡名

C++ 的樣板錯誤曾經以「數百行難以理解的錯誤訊息」著稱：因為錯誤發生在樣板展開的深處，編譯器把整個展開的過程都印了出來。C++20 加入的「概念」（concepts），讓樣板可以宣告需求，錯誤訊息因此改善許多。

現代的編譯器也是 IDE 的引擎：一邊打字，一邊即時剖析與檢查（語言伺服器協定 LSP），讓紅色波浪線即時出現在錯誤的地方。

🧭 這一課的重點

編譯器最常說話是出錯時，好的錯誤訊息讓人幾秒找到問題，糟糕的浪費一下午；好的錯誤訊息有精確位置與範圍、說人話（型別不符預期 int 得到 String）、建議修正（是不是想打 length）、不連鎖爆炸；Rust 與 Elm 以友善詳細彩色片段與建議聞名；錯誤恢復讓編譯器遇錯不放棄繼續檢查，恐慌模式跳過 token 到分號或右大括號等同步點再剖析；C++ 樣板錯誤曾以數百行難懂訊息著稱，C++20 概念改善；現代編譯器也是 IDE 引擎，用 LSP 邊打字邊檢查即時顯示紅色波浪線。

🛠️ 互動工具實作了一個極小的算式語言（數字、變數、+ − × ÷ ^ 與括號），用來示範編譯器的各個階段。
