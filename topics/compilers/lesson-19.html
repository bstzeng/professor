常數摺疊與死碼消除

這一課的目標

  • 理解常見的區域最佳化
  • 理解死碼消除
  • 了解共同子運算式消除

常數摺疊

如果運算的兩邊都是常數，編譯器在編譯時就直接算出結果：seconds = 60 * 60 * 24 變成 seconds = 86400。在上一個模組的迷你編譯器中，打開「常數摺疊」就能看到。

常數傳播

如果 x = 5，後面用到 x 的地方就換成 5，然後可能又產生新的常數摺疊機會。最佳化常常是連鎖的：一個最佳化為另一個創造機會。

代數化簡與強度削減

  • x × 1 → x；x + 0 → x；x × 0 → 0（對浮點數要小心：0 × NaN 不是 0）。
  • 強度削減：用便宜的運算取代昂貴的運算。x × 2 → x + x 或 x << 1；x ÷ 8 → x >> 3（對正整數）。

共同子運算式消除

a = (x + y) * 2 t = x + y b = (x + y) * 3 → a = t * 2 b = t * 3

x + y 只需要算一次。

死碼消除

計算結果從未被使用的程式碼，以及永遠不會執行到的程式碼（例如 if (false) 之後的區塊），都可以刪除。這在除錯模式與發布模式的切換中特別有用：if (DEBUG) log(...) 在發布版本中會完全消失。

最佳化等級

GCC 與 Clang 的 -O0、-O1、-O2、-O3 選項，就是開啟越來越多的最佳化。-O0 方便除錯（程式碼和原始碼一一對應），-O2 是發布程式常用的平衡點。

🧭 這一課的重點

常數摺疊編譯時直接算出常數運算 60*60*24→86400；常數傳播把 x＝5 後的 x 換成 5 又產生新摺疊機會，最佳化常連鎖；代數化簡 x×1→x、x＋0→x、x×0→0（浮點要小心 NaN），強度削減 x×2→x＋x 或左移、x÷8→右移 3；共同子運算式消除 x＋y 只算一次；死碼消除刪除結果未被使用與永遠不執行的程式碼，if (DEBUG) log 在發布版完全消失；GCC Clang 的 -O0 到 -O3 開啟越來越多最佳化，-O0 方便除錯、-O2 是發布常用平衡點。
