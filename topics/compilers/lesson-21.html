模組 D｜中介碼與最佳化 · 第 21 課

內聯與跨程序最佳化

這一課的目標

  • 理解函式內聯
  • 理解內聯的取捨
  • 認識連結時最佳化

函式呼叫的代價

呼叫一個函式需要：準備參數、跳過去、建立堆疊框、執行、返回、清理。對一個只有一行的小函式（例如取得某個欄位的 getter），這些額外的工作可能比函式本身還多。

內聯

內聯（inlining）把被呼叫的函式主體，直接複製到呼叫的地方。這不只省掉了呼叫的代價，更重要的是：函式的程式碼和呼叫端合在一起後，其他最佳化有了更多的機會。

int square(int x) { return x * x; } int f() { return square(5) + 1; } // 內聯後：return 5 * 5 + 1; // 常數摺疊後：return 26;

內聯被稱為「最佳化之母」，因為它為常數傳播、死碼消除等打開了大門。

取捨

  • 內聯太多，程式碼膨脹，反而讓指令快取放不下，變慢。
  • 遞迴函式無法完全內聯。
  • 編譯器用啟發式的規則決定：函式夠小、被呼叫的地方在熱點迴圈中，就內聯。

連結時最佳化

傳統上，每個 .c 檔案分開編譯，編譯器看不到其他檔案裡的函式，無法跨檔案內聯。連結時最佳化（LTO）在連結階段把所有檔案的 IR 合在一起，進行整個程式的最佳化。

剖析導向最佳化（PGO）則先用實際的輸入執行程式，記錄哪些分支常走、哪些函式常被呼叫，再重新編譯——讓編譯器「知道」程式真正的行為。瀏覽器與資料庫等大型軟體常用 PGO，獲得可觀的效能提升。

🧭 這一課的重點

呼叫函式需準備參數跳過去建堆疊框執行返回清理，一行的 getter 這些額外工作可能比函式本身多；內聯把被呼叫函式主體複製到呼叫處，不只省呼叫代價更讓其他最佳化有機會，square(5)＋1 內聯後常數摺疊成 26，被稱最佳化之母；太多內聯程式膨脹指令快取放不下反而變慢、遞迴無法完全內聯，編譯器用啟發式規則；傳統每個 .c 分開編譯無法跨檔內聯，連結時最佳化 LTO 在連結時合併所有 IR；剖析導向最佳化 PGO 先用實際輸入執行記錄常走分支常呼叫函式再重新編譯，瀏覽器資料庫常用。
