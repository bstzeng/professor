抽象語法樹

這一課的目標

  • 區分剖析樹與抽象語法樹
  • 理解 AST 的用途
  • 認識走訪 AST 的方法

剖析樹與 AST

剖析樹（具體語法樹）忠實地記錄文法的每一步，包括括號、分號、每一層 expr → term → factor。抽象語法樹（AST）只保留意義：括號不見了（樹的形狀已經表達了先後），中間的單一層級被省略。

例如 (1 + 2) * 3 的 AST 只有三種節點：乘法節點，左邊是加法節點（1、2），右邊是 3。

AST 是編譯器的中心

剖析之後，編譯器的大部分工作都在 AST 上進行：檢查名稱、推論型別、產生中介碼。不只是編譯器——許多開發工具都在操作 AST：

  • 格式化工具（Prettier、gofmt、Black）：把程式剖析成 AST，再用統一的風格印出來。
  • 程式碼檢查（ESLint、Clippy）：在 AST 上尋找可疑的模式。
  • 重構：IDE 的「重新命名變數」在 AST 上找出所有的引用。
  • 轉譯器（Babel、TypeScript）：把新語法的 AST 轉換成舊語法。

走訪 AST

def evaluate(node): if node.kind == 'num': return node.value if node.kind == 'var': return env[node.name] a = evaluate(node.left) b = evaluate(node.right) if node.op == '+': return a + b if node.op == '*': return a * b ...

用遞迴走訪 AST，就得到了一個最簡單的直譯器——稱為「樹走訪直譯器」。早期的 Ruby 與許多教學用的語言都是這樣實作的。

🧭 這一課的重點

剖析樹忠實記錄文法每步包括括號分號與每層 expr term factor，抽象語法樹只保留意義，括號不見（樹形已表達先後）中間單一層級省略，(1＋2)*3 只有乘法加法與數字節點；剖析後編譯器大部分工作在 AST 上進行，開發工具也操作 AST：格式化工具 Prettier gofmt Black、程式碼檢查 ESLint Clippy、IDE 重新命名、轉譯器 Babel TypeScript；用遞迴走訪 AST 就得到最簡單的樹走訪直譯器，早期 Ruby 與教學語言如此實作。

🛠️ 互動工具實作了一個極小的算式語言（數字、變數、+ − × ÷ ^ 與括號），用來示範編譯器的各個階段。
