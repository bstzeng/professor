資料危障與轉送

這一課的目標

  • 理解資料危障
  • 理解轉送的原理
  • 理解載入使用危障

資料危障

add x1, x2, x3 # x1 在第 5 週期（WB）才寫回 sub x4, x1, x5 # 第 3 週期（ID）就要讀 x1

sub 要在 ID 階段讀 x1，但 add 要到 WB 才寫回。如果什麼都不做，sub 會讀到舊的值。最簡單的辦法是讓 sub 停下來等，但這會浪費好幾個週期。

轉送（forwarding）

仔細看：add 的結果在 EX 階段結束時就已經算出來了，只是還沒寫回暫存器。轉送就是加一條捷徑，把 ALU 的結果直接送到下一條指令的 ALU 輸入，不必等寫回。這樣 ALU 之間的相依就完全不用停頓。

載入使用危障

lw x1, 0(x2) # 資料在 MEM 階段結束時才拿到 add x3, x1, x4 # 下一個週期的 EX 就要用

載入的資料要到 MEM 結束才拿到，即使有轉送，緊接著的指令還是得停頓一個週期。編譯器會試著把一條不相關的指令搬到兩者之間，填補這個空檔——這叫指令排程。

回到第 11 課的互動元件，切換「ALU 結果相依」與「載入後立刻使用」，並開關轉送，比較停頓的數量。

🧭 這一課的重點

資料危障發生在後一條指令要讀前一條尚未寫回的結果；轉送把 EX 算出的結果直接送到下一條的 ALU，消除 ALU 相依的停頓；載入資料到 MEM 結束才有，緊接使用仍需停頓一週期，編譯器以指令排程填補。

🖥️ 本課的數字多為教學用的簡化例子；互動元件是示意模型，實際的設計與計算請以專業文件與標準為準。
