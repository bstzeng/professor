亂序執行

這一課的目標

  • 理解亂序執行的動機
  • 理解暫存器重新命名
  • 理解重排序緩衝器

動機

lw x1, 0(x2) # 快取失誤，要等 100 個週期 add x3, x1, x4 # 必須等 x1 mul x5, x6, x7 # 和上面無關！ sub x8, x9, x10 # 也無關

照順序執行的話，mul 和 sub 也要乾等。亂序執行讓處理器看得更遠：只要資料準備好的指令，就先執行，不管它在程式中的順序。

三個關鍵機制

機制作用
保留站（Reservation Station）指令在這裡等待，運算元一到齊就送去執行
暫存器重新命名把程式中的 32 個架構暫存器，對應到上百個實體暫存器，消除「假相依」
重排序緩衝器（ROB）指令可以亂序執行，但要照原來的順序提交結果，確保發生例外時狀態正確

假相依

add x1, x2, x3 sw x1, 0(x4) add x1, x5, x6 # 重複使用 x1，但和上面其實無關

第三條指令只是剛好也用 x1 這個名字，和前兩條沒有真正的資料關係。重新命名後，它寫入的是另一個實體暫存器，就能提前執行。

這個想法最早出現在 1967 年 IBM System/360 Model 91 的 Tomasulo 演算法，1990 年代後成為高效能處理器的標準設計。代價是龐大的硬體與耗電，所以很多低功耗的小核心仍然照順序執行。

🧭 這一課的重點

亂序執行讓資料準備好的指令先執行，避免快取失誤時乾等；保留站等運算元到齊、暫存器重新命名把架構暫存器對應到大量實體暫存器以消除假相依、重排序緩衝器保證照原順序提交；源自 1967 年 IBM 360/91 的 Tomasulo 演算法，代價是硬體與耗電。

🖥️ 本課的數字多為教學用的簡化例子；互動元件是示意模型，實際的設計與計算請以專業文件與標準為準。
