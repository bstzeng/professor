記憶體模型與同步

這一課的目標

  • 理解記憶體一致性模型
  • 理解原子操作與鎖
  • 理解記憶體屏障

一個令人意外的例子

初始 x = 0, y = 0 核心 A：x = 1; r1 = y; 核心 B：y = 1; r2 = x;

直覺上，r1 和 r2 不可能同時是 0。但在真實的處理器上，這是可能發生的：為了效能，處理器會把寫入先放在「儲存緩衝區」中，讀取可能先於寫入被別的核心看到。

記憶體模型

ISA 會規定一套記憶體一致性模型，說明哪些重新排序是允許的。x86 相對嚴格（TSO，只允許上面這種「寫後讀」的重新排序）；ARM 與 RISC-V 較寬鬆，允許更多的重新排序，以換取效能與省電。

同步的工具

  • 原子操作：例如「比較並交換」（CAS），在一個不可分割的步驟中讀取、比較、寫入。RISC-V 的 A 擴充提供這類指令。
  • 鎖：用原子操作實作，確保同一時間只有一個執行緒進入臨界區。
  • 記憶體屏障（fence）：強迫屏障之前的記憶體操作，在屏障之後的操作之前完成。

大多數程式設計者不需要直接使用屏障：程式語言（C++、Java、Rust）的鎖、原子變數，會在底層自動插入適當的指令。但寫作業系統、資料庫或高效能函式庫時，必須深入理解記憶體模型。分散式系統中的一致性問題見〈分散式系統與共識〉。

🧭 這一課的重點

為了效能，處理器的儲存緩衝區會讓寫入延後被看見，使兩個核心可能同時讀到 0；ISA 規定記憶體一致性模型，x86 較嚴格（TSO）、ARM 與 RISC-V 較寬鬆；同步工具有原子操作 CAS、鎖與記憶體屏障，程式語言的鎖與原子變數會自動插入適當指令。
