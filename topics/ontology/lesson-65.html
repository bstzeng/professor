模組 K｜總結 · 第 65 課

哲學的老問題，在 AI 時代的新答案

這一課的目標

  • 串起整門課的主線
  • 理解本體在 AI 時代的價值
  • 規劃下一步的學習與實作

兩千多年前，亞里斯多德問：「存在的東西有哪些種類？」今天，企業在導入 AI 時問的問題驚人地相似：「我們的業務裡有哪些東西？它們之間是什麼關係？我們可以對它們做什麼？」

一條貫穿的主線

時代問題答案的形式
古希臘存在的是什麼？如何分類？範疇、屬加種差、波菲利之樹
中世紀到近代共相存在嗎？概念如何組合？實在論與唯名論、萊布尼茲的通用文字
20 世紀如何讓機器表示知識？一階邏輯、語意網路、框架、專家系統
1990～2000 年代如何共享與推理？格魯伯的定義、描述邏輯、OWL、語意網
2010 年代如何整合海量資料？知識圖譜、Wikidata、schema.org、企業本體
2020 年代如何讓 AI 可靠地理解與行動？GraphRAG、語意層、Palantir 式的物件 + 動作 + AI

為什麼 LLM 沒有讓本體過時

  • LLM 懂語言，不懂你的組織：「客戶」在你的公司裡精確指的是什麼，只有你的本體知道。
  • 可驗證：本體讓 AI 的輸出可以被檢查（SHACL、型別、驗證規則）。
  • 可追溯：答案能指回具體的物件與資料來源。
  • 可控制：AI 透過定義好的動作行事，而不是任意修改系統。
  • 反過來，LLM 讓本體更容易建：知識擷取、對齊、文件撰寫的成本大幅下降（第 53 課）。

符號主義與連結主義的長期爭論，在這裡找到了一種分工：神經網路負責感知與語言，本體負責結構、約束與行動。這種結合常被稱為神經符號（neuro-symbolic）AI。

下一步：一個實作專案

  1. 選一個你熟悉的小領域（社團、家庭收支、課程、店鋪）。
  2. 寫 5～10 個能力問題（第 46 課）。
  3. 用 rdflib 或 owlready2 建立本體與測試資料，重用 schema.org 或 SKOS。
  4. 用推理機檢查一致性，用 SHACL 驗證資料，用 SPARQL 回答能力問題。
  5. 加上「動作」：寫幾個會修改資料、帶有驗證規則的 Python 函式。
  6. 最後接上 LLM：讓它根據本體回答問題、提出動作建議，由你核准。
# 最小的「本體 + 動作 + 驗證」骨架：你的實作專案可以從這裡開始 from rdflib import Graph, Namespace, Literal, RDF from pyshacl import validate EX = Namespace("http://example.org/club#") g = Graph().parse(data=''' @prefix : <http://example.org/club#> . :Alice a :Member ; :name "Alice" . :Chess a :Activity ; :capacity 2 . ''', format="turtle") shapes = Graph().parse(data=''' @prefix sh: <http://www.w3.org/ns/shacl#> . @prefix : <http://example.org/club#> . :ActivityShape a sh:NodeShape ; sh:targetClass :Activity ; sh:property [ sh:path :participant ; sh:class :Member ] . ''', format="turtle") def action_join(member, activity): """動作：報名活動。先檢查前提，再修改，再驗證；失敗就回復。""" cap = int(g.value(activity, EX.capacity)) if len(list(g.objects(activity, EX.participant))) >= cap: return "拒絕：名額已滿" g.add((activity, EX.participant, member)) ok, _, report = validate(g, shacl_graph=shapes) if not ok: g.remove((activity, EX.participant, member)); return "拒絕：" + report return "完成" print(action_join(EX.Alice, EX.Chess)) # 完成 print(action_join(EX.Bob, EX.Chess)) # 拒絕：Bob 不是 Member（SHACL 驗證失敗）

結語

Ontology 從來不只是技術。它是一種思考方式：在動手之前，先問清楚「這裡有什麼、它們是什麼關係、我們能做什麼、什麼不該做」。這個問題，亞里斯多德問過，萊布尼茲問過，格魯伯問過，今天的 AI 工程師也必須回答。

🧭 這一課的重點

從亞里斯多德的範疇到企業 AI，本體始終在回答「存在什麼、如何關聯、能做什麼」：古希臘的分類、中世紀的共相之爭、20 世紀的知識表示、OWL 與語意網、知識圖譜，到 GraphRAG 與 Palantir 式的物件加動作。LLM 沒有讓本體過時，因為本體提供組織專屬的語意、可驗證、可追溯與可控制，而 LLM 反過來降低建構成本，形成神經符號的分工。下一步可從能力問題出發，建立含推理、SHACL、SPARQL、動作與 LLM 的小專案。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
