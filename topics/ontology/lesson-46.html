方法論與能力問題

這一課的目標

  • 認識主要的本體工程方法論
  • 會寫能力問題並轉成 SPARQL 測試
  • 理解本體開發的生命週期

建本體和寫軟體一樣，需要方法。最常見的失敗是：一開始就畫一棵大樹，想把「所有東西」都放進去，結果做了兩年沒人用。

主要方法論

方法論年代特點
Ontology 101（諾伊與麥吉尼斯，史丹佛）2001七步驟入門指南：決定範圍 → 考慮重用 → 列術語 → 定類別階層 → 定屬性 → 定屬性限制 → 建個體
METHONTOLOGY（馬德里理工大學）1997借用軟體工程：規格、概念化、形式化、實作、維護，加上評估與文件
NeOn2010 前後九種情境，強調重用既有本體、非本體資源（資料庫綱要、詞彙表）
敏捷方法（如 XD 極限設計、SAMOD）2010 年代小步快跑：一次處理幾個能力問題，以測試驅動開發

能力問題（Competency Questions）

格魯寧格與福克斯在 1995 年提出：本體的需求，就是它必須能回答的問題。例如一個圖書館本體：

  1. 某位作者寫過哪些書？
  2. 目前有哪些書逾期未還？逾期的讀者是誰？
  3. 某本書屬於哪些主題（含上層主題）？
  4. 哪些書有中譯本？譯者是誰？

能力問題決定了範圍（不在任何問題裡的概念可以先不做），也是最好的驗收測試：每個問題寫成一個 SPARQL 查詢，本體與測試資料要能給出預期答案。

# 把能力問題寫成自動化測試（pytest），每次修改本體都跑一次 import pytest from rdflib import Graph import owlrl @pytest.fixture(scope="module") def kg(): g = Graph().parse("library.ttl").parse("test_data.ttl") owlrl.DeductiveClosure(owlrl.OWLRL_Semantics).expand(g) # 先物化推論結果 return g CQS = { "CQ1 托爾金寫過哪些書": ('''SELECT ?b WHERE { ?b :writtenBy :Tolkien }''', {":LOTR", ":Hobbit"}), "CQ3 魔戒的所有主題（含上層）": ('''SELECT ?t WHERE { :LOTR :subject/skos:broader* ?t }''', {":Fantasy", ":Fiction", ":Literature"}), } @pytest.mark.parametrize("name", CQS) def test_competency_question(kg, name): q, expected = CQS[name] ns = {"": "http://example.org/lib#", "skos": "http://www.w3.org/2004/02/skos/core#"} got = {kg.qname(r[0]) for r in kg.query(q, initNs=ns)} assert got == expected, name

生命週期

  1. 規格：目的、範圍、使用者、能力問題。
  2. 知識擷取：訪談領域專家、讀文件、分析既有資料庫。
  3. 概念化：列出術語，區分類別、屬性、個體。
  4. 重用：找可以引用的現有本體（第 48 課）。
  5. 形式化與實作：用 OWL 寫下來（第 47 課的 Protégé）。
  6. 評估：推理機檢查一致性、跑能力問題測試、專家審查（第 50 課）。
  7. 部署與維護：版本控制、變更管理（第 49 課）。

🧭 這一課的重點

本體工程需要方法，避免想涵蓋一切卻無人使用。主要方法論有七步驟的 Ontology 101、借用軟體工程的 METHONTOLOGY、強調重用的 NeOn 與測試驅動的敏捷方法。能力問題是本體必須回答的問題，決定範圍，也可寫成 SPARQL 自動化測試作為驗收。生命週期包括規格、知識擷取、概念化、重用、形式化、評估與維護。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
