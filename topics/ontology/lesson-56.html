Gotham：情報分析起家

這一課的目標

  • 理解情報分析的資料整合問題
  • 認識 Gotham 的核心功能
  • 理解存取控制與稽核在其中的地位

情報分析師面對的資料來自四面八方：通聯紀錄、金融交易、出入境、報告文件、衛星影像、線人資料……每一種存放在不同的系統，格式不同，權限不同。分析師的工作是找出其中的關聯：這個電話號碼和那個帳戶有關嗎？這兩個人在同一個時間出現在同一個地點嗎？

Gotham 的做法

  • 以實體為中心：不論資料來自哪裡，都對應到「人」「組織」「地點」「事件」「物品」等物件，同一個實體的資料合併在一起——這就是一個本體。
  • 圖形分析：以節點和連線呈現物件之間的關係，分析師可以從一個人出發，一步步展開他的關聯網路。
  • 時間與地理：事件放在時間軸與地圖上，找出時空上的交會。
  • 協作：分析成果可以分享、標註，形成組織的共同知識。

安全模型

情報資料的權限極為複雜：同一份報告，不同人能看到的部分不同。Gotham 從一開始就把細粒度存取控制和稽核放在核心：每一筆資料都帶有標記（例如機密等級、來源限制），每一次查看與操作都留下紀錄。Palantir 一直把這點當作回應隱私疑慮的主要論點（第 64 課）。

# 以實體為中心的關聯分析：多來源資料 → 同一張圖 → 找出兩人之間的關聯路徑 import networkx as nx calls = [("號碼A", "號碼B"), ("號碼B", "號碼C")] # 通聯紀錄 owners = [("甲", "號碼A"), ("乙", "號碼C")] # 門號登記 money = [("乙", "帳戶X"), ("丙", "帳戶X")] # 金融資料（共用帳戶） trips = [("丙", "事件：某日某港口"), ("甲", "事件：某日某港口")] # 出入境 G = nx.Graph() for src, edges in [("通聯", calls), ("門號", owners), ("金融", money), ("出入境", trips)]: for a, b in edges: G.add_edge(a, b, source=src) # 每條邊記得它來自哪個資料源（出處） path = nx.shortest_path(G, "甲", "丙") print(" → ".join(path)) for a, b in zip(path, path[1:]): print(f" {a} — {b}：來源 {G[a][b]['source']}")

和 Ontology 的關係

這個程式片段裡其實已經有一個隱含的本體：人、門號、帳戶、事件是不同的物件類型，「撥打」「登記」「持有」「出現於」是不同的連結類型。Gotham 的價值在於把這個本體明確化、規模化，並套上安全控制。

🧭 這一課的重點

情報分析的難題是資料散落於格式與權限各異的系統，而分析師需要找出其中的關聯。Gotham 以實體為中心合併多來源資料，提供圖形、時間與地理分析與協作，本質上就是一個本體。它從一開始就以細粒度存取控制與完整稽核為核心，資料帶有機密等級等標記，每次操作皆有紀錄，這也是 Palantir 回應隱私疑慮的主要論點。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
