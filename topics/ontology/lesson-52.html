Ontology 與大型語言模型：GraphRAG

這一課的目標

  • 理解 LLM 的知識問題與 RAG
  • 理解 GraphRAG 與知識圖譜增強的做法
  • 了解本體在 AI 代理人中的角色

大型語言模型（LLM）擅長理解與生成語言，但有幾個根本問題：

  • 幻覺：一本正經地說錯。
  • 知識過時：只知道訓練資料截止前的事。
  • 不知道你的私有資料：公司內部的產品、客戶、流程。
  • 難以追溯：答案從哪裡來？

RAG：檢索增強生成

RAG 的做法是：先從資料庫檢索相關內容，再把它放進提示讓 LLM 回答。最常見的是把文件切塊、轉成向量，用語意相似度檢索。但向量 RAG 有弱點：遇到需要多步推理或彙整的問題（「我們有哪些供應商同時供貨給 A 廠和 B 廠，且位於颱風高風險區？」），文件片段很難拼出答案。

知識圖譜增強的幾種做法

做法流程適合
Text-to-SPARQL／CypherLLM 根據本體綱要，把問題翻譯成查詢語言，執行後再把結果寫成回答結構化、精確的問題
子圖檢索找出問題中的實體，取出它們周圍的子圖，轉成文字放進提示關於特定實體的問題
GraphRAG（微軟，2024）用 LLM 從文件中抽取實體與關係建圖，再用社群偵測分群並為每群寫摘要；回答時用摘要處理「全域」問題「這批文件的主要主題是什麼？」這類彙整問題
混合向量檢索找文件、圖譜找關係、兩者合併多數實務場景

本體的角色

  • 綱要即提示：把本體的類別與屬性放進提示，LLM 才知道可以查什麼、怎麼查。
  • 約束輸出：LLM 產生的查詢或抽取結果，可以用本體與 SHACL 驗證。
  • 消除歧義：「蘋果」是水果還是公司？實體連結到知識圖譜的 IRI 後就明確了。
  • 可追溯：答案中的每個事實都能指回圖中的三元組與它的出處。
  • AI 代理人的工具：本體中定義的「動作」可以變成代理人能呼叫的工具（第 60、62 課）。
# Text-to-SPARQL：把本體綱要放進提示，請 Claude 產生查詢，再用 rdflib 執行並驗證 import anthropic from rdflib import Graph g = Graph().parse("supply_chain.ttl") schema = ''' Classes: :Supplier, :Plant, :Region, :Part Properties: :supplies (Supplier -> Plant), :locatedIn (Supplier -> Region), :typhoonRisk (Region -> xsd:string, values "high"/"medium"/"low") ''' question = "哪些供應商同時供貨給 A 廠和 B 廠，而且位於颱風高風險區？" MODEL = "claude-..." # 填入目前可用的 Claude 模型名稱 client = anthropic.Anthropic() msg = client.messages.create( model=MODEL, max_tokens=1024, system="你把問題翻譯成 SPARQL。只能使用下列綱要中的類別與屬性，前綴 : 為 <http://example.org/sc#>。只輸出查詢本身。\n" + schema, messages=[{"role": "user", "content": question}], ) sparql = msg.content[0].text.strip().removeprefix("```sparql").removesuffix("```") try: rows = list(g.query(sparql)) # 語法錯誤會在這裡被抓到 print(rows) except Exception as e: print("查詢無效，可把錯誤訊息回傳給模型修正：", e)

注意

把 LLM 產生的查詢直接拿去執行時，要限制成唯讀、設定逾時與結果數上限，並檢查只用到綱要中存在的詞彙。這和 SQL 注入的防範道理相同。

🧭 這一課的重點

LLM 有幻覺、知識過時、不知私有資料與難以追溯等問題，RAG 先檢索再生成，但向量 RAG 難處理多步推理與彙整。知識圖譜增強的做法包括 Text-to-SPARQL、子圖檢索、微軟 2024 年的 GraphRAG（抽取建圖、社群摘要）與混合方式。本體提供綱要提示、約束輸出、消除歧義、可追溯，並讓動作成為代理人工具。執行 LLM 產生的查詢須限制唯讀、逾時與詞彙。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
