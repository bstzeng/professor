AIP：讓 AI 在 Ontology 上工作

這一課的目標

  • 理解 AIP 的架構與設計理念
  • 理解 AI 代理人以動作為工具的模式
  • 認識 AIP 訓練營的推廣方式

2023 年，Palantir 推出 AIP（Artificial Intelligence Platform）。它的核心論點是：大型語言模型本身不知道你的企業，也不應該直接存取你的資料庫；但如果讓它在 Ontology 上工作，它就能理解業務概念、查詢正確的資料、並透過受控的動作採取行動。

AIP 的組成（簡化）

元件作用
模型接入接入多家廠商的大型語言模型，以及客戶自己的模型
AIP Logic用低程式碼方式組合 LLM、Ontology 查詢、函數與動作，建立 AI 功能
代理人（AIP Agent Studio 等）建立能多步驟推理、呼叫工具的 AI 代理人
Ontology 作為工具物件查詢、函數、動作都可以作為 LLM 的工具
安全與稽核AI 只能看到使用者有權限看到的資料；每次呼叫都有紀錄
評估對 AI 功能建立測試案例並評估表現

關鍵設計：AI 提建議，人做決定

在剛才的模擬中，「② AIP 產生建議」只是建議；要按「③ 核准」才會真正執行動作。這種「人在迴圈中」（human-in-the-loop）的設計，是在高風險場景（航空、醫療、國防）使用 AI 的關鍵。隨著信心累積，部分低風險動作可以逐步改為自動執行。

# 以「Ontology 動作」作為 Claude 的工具；AI 只能提出動作，由人核准後才執行 import anthropic, json def affected_flights(tail): # 函數（唯讀） return [{"flight": "CI-301", "pax": 182, "time": "08:30"}, {"flight": "CI-305", "pax": 160, "time": "14:10"}] def available_aircraft(min_seats): # 函數（唯讀） return [{"tail": "B-104", "seats": 194}, {"tail": "B-103", "seats": 307}] tools = [ {"name": "affected_flights", "description": "列出由某架飛機執飛的航班", "input_schema": {"type": "object", "properties": {"tail": {"type": "string"}}, "required": ["tail"]}}, {"name": "available_aircraft", "description": "列出可用且座位數不少於 min_seats 的飛機", "input_schema": {"type": "object", "properties": {"min_seats": {"type": "integer"}}, "required": ["min_seats"]}}, {"name": "propose_reassignment", "description": "提出改派方案（不會立即執行，需人工核准）", "input_schema": {"type": "object", "properties": {"flight": {"type": "string"}, "tail": {"type": "string"}}, "required": ["flight", "tail"]}}, ] READ_ONLY = {"affected_flights": affected_flights, "available_aircraft": available_aircraft} proposals = [] MODEL = "claude-..." # 填入目前可用的 Claude 模型名稱 client = anthropic.Anthropic() messages = [{"role": "user", "content": "B-101 停飛維修，請為受影響的航班提出改派方案。"}] while True: msg = client.messages.create(model=MODEL, max_tokens=2048, tools=tools, messages=messages) messages.append({"role": "assistant", "content": msg.content}) if msg.stop_reason != "tool_use": break results = [] for b in msg.content: if b.type != "tool_use": continue if b.name in READ_ONLY: out = READ_ONLY[b.name](**b.input) else: # 寫入類動作：只記錄為提案 proposals.append(b.input); out = {"status": "pending_human_approval"} results.append({"type": "tool_result", "tool_use_id": b.id, "content": json.dumps(out, ensure_ascii=False)}) messages.append({"role": "user", "content": results}) for p in proposals: # 人類核准後，才透過有驗證規則的動作真正執行 if input(f"核准 {p['flight']} 改由 {p['tail']} 執飛？(y/n) ") == "y": print("執行動作 reassign_aircraft", p)

AIP 訓練營

Palantir 推廣 AIP 的方式也很特別：訓練營（bootcamp）。客戶帶著自己的資料與問題，和 Palantir 工程師在一到數天內直接做出可用的 AI 應用。這取代了傳統漫長的試點與銷售流程，也是 2023 年後美國商業客戶快速成長的重要原因之一。

給學習者的啟示

不論是否使用 Palantir，「LLM + 明確的本體 + 受控的動作 + 人類核准 + 完整稽核」這個架構，已經是企業 AI 代理人設計的通用模式。第 52 課的 GraphRAG 與本課的動作工具，分別對應「讓 AI 讀懂」與「讓 AI 安全地做事」。

🧭 這一課的重點

AIP 於 2023 年推出，核心論點是讓 LLM 在 Ontology 上工作，以理解業務概念、查詢正確資料並透過受控動作行動。組成包括多模型接入、AIP Logic、代理人、以 Ontology 作為工具、安全稽核與評估。關鍵設計是 AI 提建議、人核准後執行，低風險動作再逐步自動化。AIP 訓練營讓客戶在數天內做出應用，帶動美國商業成長。LLM、本體、受控動作、人類核准與稽核已成企業 AI 代理人的通用模式。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
