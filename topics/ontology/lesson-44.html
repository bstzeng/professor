工程與製造：IFC/BIM 與工業 4.0

這一課的目標

  • 認識 IFC 與 ifcOWL
  • 認識工業 4.0 的資產管理殼
  • 理解本體在製造業的角色

建築：IFC 與 BIM

建築資訊模型（BIM）需要在建築師、結構技師、機電、營造廠、業主之間交換資料。IFC（Industry Foundation Classes，ISO 16739）由 buildingSMART 制定，定義了牆、梁、柱、門、空間、管線等上千個類別及其關係。

  • IFC 原本是以 EXPRESS 語言定義的資料模型。
  • ifcOWL 把 IFC 轉成 OWL，讓建築資料能和其他鏈結資料（地理、能源、產品）整合。
  • BOT（Building Topology Ontology）是 W3C 社群提出的輕量建築本體：基地、建築、樓層、空間、元件，以及包含、相鄰等關係。
  • Brick Schema：描述建築中的設備與感測器（空調、照明、溫度計），讓能源管理軟體能跨大樓使用。

製造：工業 4.0

德國提出的工業 4.0 中，每一台機器、每一個零件都要有數位分身。標準化的方式是資產管理殼（Asset Administration Shell, AAS）：用一組標準的「子模型」描述資產（銘牌、技術資料、維護紀錄、碳足跡），並引用 ECLASS 或 IEC 61360 的標準化屬性定義。

  • OPC UA：工廠設備的通訊標準，其資訊模型本身就是一套物件導向的「本體」。
  • ISO 15926：石化與流程工廠的生命週期資料，採用四維主義的上層本體（第 12 課）。
  • 產業本體：例如工業本體鑄造所（IOF）以 BFO 為基礎，建立製造、維護、供應鏈的共用本體。
# 用 Brick Schema 描述一間會議室的空調與感測器（Brick 是 RDF/OWL 本體） from rdflib import Graph, Namespace, RDF BRICK = Namespace("https://brickschema.org/schema/Brick#") BLDG = Namespace("http://example.org/building#") g = Graph(); g.bind("brick", BRICK) g.add((BLDG.Room301, RDF.type, BRICK.Room)) g.add((BLDG.VAV3, RDF.type, BRICK.Variable_Air_Volume_Box)) g.add((BLDG.VAV3, BRICK.feeds, BLDG.Room301)) g.add((BLDG.T301, RDF.type, BRICK.Zone_Air_Temperature_Sensor)) g.add((BLDG.T301, BRICK.isPointOf, BLDG.Room301)) # 能源管理程式只要查「哪些房間有溫度感測器」，不必知道每棟大樓的點位命名規則 q = '''SELECT ?room ?s WHERE { ?s a brick:Zone_Air_Temperature_Sensor ; brick:isPointOf ?room }''' print(list(g.query(q, initNs={"brick": BRICK})))

為什麼製造業需要本體

一間工廠可能有上千個感測器、數十種設備品牌、多套系統（MES、ERP、維護系統）。每個系統的點位命名都不一樣（「T_301_ZN」「Room301Temp」…）。本體讓分析與 AI 應用寫一次就能在所有工廠使用——這也是 Palantir 在製造業的切入點（第 63 課）。

🧭 這一課的重點

建築領域以 buildingSMART 的 IFC（ISO 16739）交換 BIM 資料，ifcOWL 將其轉為 OWL，另有輕量的 BOT 與描述設備感測器的 Brick Schema。製造領域的工業 4.0 以資產管理殼的標準子模型與 ECLASS 屬性描述數位分身，另有 OPC UA 資訊模型、四維主義的 ISO 15926 與以 BFO 為基礎的 IOF。本體讓分析與 AI 應用跨大樓、跨工廠重用。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
