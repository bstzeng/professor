爭議與倫理

  • 理解各方的論點
  • 思考資料整合技術的倫理問題

Palantir 可能是全世界最具爭議的軟體公司之一。理解這些爭議，有助於思考任何強大的資料整合技術——包括你可能親手建立的知識圖譜——所帶來的責任。

卡普的立場：《科技共和國》

2025 年，卡普與尼古拉斯・札米斯卡出版《科技共和國》（The Technological Republic）。核心主張是：矽谷曾經與國家緊密合作（從二戰到太空計畫），後來卻轉向消費性應用與廣告；西方民主國家需要科技菁英重新投入國防與公共事務，否則將在 AI 時代輸給威權國家。批評者則認為這是在為國防承包商的商業利益包裝意識形態。

從技術角度思考倫理

  • 整合本身就是力量：分開來無害的資料，連起來就可能識別、追蹤一個人。本體越好，這個力量越大。
  • 設計中的價值：一個系統把什麼東西建模成物件、哪些關係可以被查詢、哪些動作可以被執行，都是價值選擇。
  • 技術性護欄：細粒度權限、目的限制、稽核紀錄、資料保存期限、人類核准——這些都可以寫進本體與動作的設計中。
  • 技術性護欄不足以取代制度：誰能看稽核紀錄？誰決定什麼是合法目的？這些需要法律、監督機關與公眾參與。
# 用 Python 檢查一份 Ontology 設計是否內建了基本的倫理護欄（自我檢查清單的示意） design = { "objects": {"Person": {"pii": True, "retention_days": None}, "Case": {"pii": True, "retention_days": 1825}}, "actions": {"flag_person": {"human_approval": False, "audit": True, "purpose_required": False}}, } issues = [] for name, o in design["objects"].items(): if o["pii"] and o["retention_days"] is None: issues.append(f"物件 {name} 含個資但沒有保存期限") for name, a in design["actions"].items(): if not a["human_approval"]: issues.append(f"動作 {name} 影響個人卻不需要人工核准") if not a["purpose_required"]: issues.append(f"動作 {name} 沒有要求填寫使用目的") if not a["audit"]: issues.append(f"動作 {name} 沒有稽核紀錄") print("\n".join(issues) or "通過基本檢查")

開放討論

本課刻意呈現多方論點，而非下結論。值得思考的問題是：如果你是一位知識圖譜工程師，被要求為某個用途建立 Ontology，你會在什麼情況下拒絕？你會要求哪些護欄？

🧭 這一課的重點

Palantir 的爭議包括：自 2014 年起支援 ICE 的移民執法、2018 年揭露與紐奧良警方的預測性警務合作、NHS 醫療資料隱私、Maven 與 TITAN 等 AI 軍事化，以及私人公司掌握關鍵基礎設施的權力集中，公司則以合法政府、權限稽核與民主國家需要技術回應。卡普 2025 年的《科技共和國》主張科技菁英重返國防。技術倫理上，整合即力量、設計即價值，權限、目的限制、稽核、保存期限與人類核准等護欄可寫入設計，但仍需制度監督。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
