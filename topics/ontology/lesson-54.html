資料網格、語意層與數位孿生

這一課的目標

  • 理解語意層與指標定義
  • 理解資料網格與資料產品
  • 理解數位孿生與本體的關係

語意層

同一間公司裡，財務部和業務部算出的「營收」常常不一樣：要不要扣退貨？用訂單日還是出貨日？語意層（semantic layer）把商業概念與指標的定義集中管理，所有報表與 AI 工具都透過它查詢。

  • 例子：dbt 語意層（MetricFlow）、Cube、LookML 等。
  • 它像是一個輕量的本體：定義實體（客戶、訂單）、維度、指標及它們的關係。
  • LLM 時代特別重要：讓 AI 透過語意層查詢，就不會自己發明「營收」的算法。

資料網格

德赫加尼（2019）提出資料網格（data mesh）：不再由中央資料團隊包辦所有資料，而是讓各業務領域把自己的資料當成資料產品來經營。四個原則：

  1. 領域擁有資料。
  2. 資料即產品（有負責人、文件、品質保證）。
  3. 自助式資料平台。
  4. 聯邦式運算治理：全公司共用的標準（例如「客戶」的識別方式）由各領域共同制定，並以程式自動執行。

第 4 點正是本體的用武之地：共用的本體讓各領域的資料產品能互相連結。

數位孿生

數位孿生是實體世界（工廠、城市、供應鏈、組織）在數位世界中的即時對應。它需要三樣東西：

元素內容本體的角色
結構有哪些東西、它們怎麼連接類別、屬性、關係
狀態即時感測資料與交易資料把資料串流對應到物件
行為能做什麼、會發生什麼動作、規則、模擬模型

微軟 Azure Digital Twins 用 DTDL（Digital Twins Definition Language，以 JSON-LD 為基礎）定義孿生模型；工業界用資產管理殼（第 44 課）。而 Palantir 把它的 Ontology 稱為組織的數位孿生——不只描述機器，也描述訂單、人員、決策（第 61 課）。

# 一個極簡的「語意層」：指標只定義一次，任何人（或 AI）都透過它查詢 import pandas as pd orders = pd.DataFrame({"order_id": [1, 2, 3, 4], "amount": [1000, 500, 800, 300], "status": ["shipped", "returned", "shipped", "cancelled"], "region": ["北", "北", "南", "南"]}) METRICS = { # 指標的唯一定義 "net_revenue": {"desc": "已出貨訂單金額（不含退貨與取消）", "filter": lambda d: d.status == "shipped", "agg": ("amount", "sum")}, "order_count": {"desc": "所有成立的訂單數（不含取消）", "filter": lambda d: d.status != "cancelled", "agg": ("order_id", "count")}, } def query(metric, by=None): m = METRICS[metric]; d = orders[m["filter"](orders)] col, fn = m["agg"] return d.groupby(by)[col].agg(fn) if by else d[col].agg(fn) print(query("net_revenue")) # 1800 print(query("net_revenue", by="region"))

🧭 這一課的重點

語意層集中定義商業概念與指標（如 dbt MetricFlow、Cube、LookML），像輕量本體，讓報表與 AI 用同一套算法。資料網格主張領域擁有資料、資料即產品、自助平台與聯邦式運算治理，共用本體讓資料產品互相連結。數位孿生需要結構、狀態與行為，Azure 以 DTDL、工業界以資產管理殼定義，Palantir 則把 Ontology 稱為組織的數位孿生。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
