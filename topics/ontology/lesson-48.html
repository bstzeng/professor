設計模式與重用

這一課的目標

  • 認識本體設計模式
  • 認識應該優先重用的常用詞彙
  • 理解重用的方式與取捨

軟體工程有設計模式；本體工程也有。本體設計模式（ODP）是針對反覆出現的建模問題、經過驗證的小型解法。

常見的設計模式

模式解決的問題做法
N 元關係RDF 只有二元關係，「張三於 2020～2023 年在甲公司擔任經理」怎麼表示？把關係變成一個個體（任職），再連到人、公司、職位、起訖時間
部分–整體部件、成員、區域包含各有不同性質分開定義 hasPart、hasMember、containedIn，並各自設定傳遞性
角色病人、員工是暫時的角色是依存於人的個體，有起訖時間（第 25、39 課）
值分割「尺寸」只能是小中大用列舉類別 owl:oneOf 或 SKOS 概念
情境（Situation）一個事件涉及多個參與者與角色把情境當作個體，連到各參與者
出處這筆資料從哪來使用 PROV-O：Entity、Activity、Agent
# N 元關係模式：任職（Employment） from rdflib import Graph, Namespace, Literal, RDF from rdflib.namespace import XSD EX = Namespace("http://example.org/hr#") g = Graph() job = EX.employment_42 # 把「關係」變成一個個體 g.add((job, RDF.type, EX.Employment)) g.add((job, EX.employee, EX.ZhangSan)) g.add((job, EX.employer, EX.CompanyA)) g.add((job, EX.role, EX.Manager)) g.add((job, EX.start, Literal("2020-03-01", datatype=XSD.date))) g.add((job, EX.end, Literal("2023-06-30", datatype=XSD.date))) q = '''SELECT ?who ?org WHERE { ?j a :Employment ; :employee ?who ; :employer ?org ; :start ?s ; :end ?e . FILTER(?s <= "2022-01-01"^^xsd:date && ?e >= "2022-01-01"^^xsd:date) }''' print(list(g.query(q, initNs={"": EX, "xsd": XSD}))) # 2022 年初誰在哪裡工作

應該優先重用的詞彙

詞彙領域
Dublin Core（dcterms）標題、作者、日期、主題等詮釋資料
FOAF人與社群關係
SKOS分類表、詞彙表、主題詞（broader、narrower、related）
schema.org一般網路實體
PROV-O資料出處
OWL-Time時間點、時間區間
GeoSPARQL地理空間
QUDT量與單位
ORG組織結構

重用的方式

  • 直接引用 IRI：最輕量，例如在你的資料中使用 dcterms:title。
  • owl:imports 整個本體：完整，但可能帶進大量不需要的東西。
  • 模組抽取（如 MIREOT、SLME）：只抽出需要的類別及其上層，ROBOT extract 可以自動化。
  • 對齊：自己定義，再用 subClassOf 或 equivalentClass 對應到標準詞彙（第 49 課）。

🧭 這一課的重點

本體設計模式是反覆出現的建模問題的驗證解法，例如 N 元關係（將關係個體化）、部分整體、角色、值分割、情境與出處。應優先重用 Dublin Core、FOAF、SKOS、schema.org、PROV-O、OWL-Time、GeoSPARQL、QUDT、ORG 等詞彙。重用方式包括直接引用 IRI、owl:imports、模組抽取與對齊，各有完整度與複雜度的取捨。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
