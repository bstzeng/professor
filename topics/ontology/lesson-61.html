模組 J｜Palantir：把 Ontology 變成作業系統 · 第 61 課

語意與動能：企業的數位孿生

這一課的目標

  • 整合語意元素與動能元素
  • 理解「組織的數位孿生」的含義
  • 理解治理與動態安全

把前兩課合起來：語意元素（物件、屬性、連結）描述組織中有什麼、彼此怎麼關聯；動能元素（動作、函數）描述能做什麼、會發生什麼。兩者合起來，Palantir 稱之為組織的數位孿生——不只是機器與設備的孿生，而是訂單、人員、資產、決策的整體模型。

語言學類比Ontology 元素例子
語意名詞物件類型飛機、航班、機場、工單、旅客
語意形容詞屬性座位數、狀態、起飛時間
語意介系詞與關係連結類型航班由飛機執飛、工單針對飛機
動能動詞動作類型回報故障、改派飛機、核准工單
動能推理與計算函數受影響旅客數、延誤成本

一個完整的決策迴圈

  1. 感知：資料管線把維修系統的新故障紀錄同步進來，B-101 的狀態變成「停飛」。
  2. 理解：函數算出 CI-301、CI-305 受影響，共 342 名旅客。
  3. 決策：調度員（或 AI 代理人）比較幾個改派方案的成本與風險。
  4. 行動：透過動作類型執行改派，驗證規則確保方案可行。
  5. 寫回與紀錄：排程系統更新、通知發出，整個決策過程被記錄下來。
  6. 學習：累積的決策紀錄用來評估與改進未來的決策（包括訓練模型）。

治理與動態安全

當 Ontology 成為全組織的作業系統，安全就必須做在 Ontology 層，而不是每個應用各自處理：

  • 物件與屬性層級的權限：同一個「員工」物件，人資看得到薪資，主管只看得到職稱。
  • 標記：資料帶有分類標記（例如個資、機密），標記會沿著資料管線傳遞到衍生的資料與物件。
  • 動作權限：誰可以執行哪些動作、在什麼條件下。
  • 稽核：每一次讀取與動作都留下紀錄。

Palantir 的文件把這類能力稱為動能元素中的「動態安全」（dynamic security）。

# 概念示意：屬性層級權限 + 標記傳遞（不是 Palantir 的 API） EMPLOYEE = {"id": "E17", "name": "林小芳", "title": "工程師", "salary": 96000, "national_id": "A2********"} MARKINGS = {"salary": {"HR"}, "national_id": {"HR", "PII"}} # 需要的權限標記 def view(obj, user_groups): return {k: (v if MARKINGS.get(k, set()) <= user_groups else "▇▇▇") for k, v in obj.items()} print(view(EMPLOYEE, {"Manager"})) # 主管：看不到薪資與身分證號 print(view(EMPLOYEE, {"HR", "PII"})) # 人資：全部可見 # 標記傳遞：由含 PII 的欄位計算出的衍生欄位，也會繼承 PII 標記 def derive(field, sources): MARKINGS[field] = set().union(*(MARKINGS.get(s, set()) for s in sources)) derive("salary_band", ["salary"]); print(MARKINGS["salary_band"]) # {'HR'}

🧭 這一課的重點

語意元素描述組織中有什麼與如何關聯，動能元素描述能做什麼與會發生什麼，合起來即 Palantir 所稱組織的數位孿生，可類比名詞、形容詞、關係與動詞。完整的決策迴圈包括感知、理解、決策、行動、寫回紀錄與學習。安全必須做在 Ontology 層：物件與屬性權限、沿管線傳遞的標記、動作權限與稽核，官方文件稱之為動態安全。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
