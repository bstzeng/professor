用 LLM 輔助建構 Ontology

這一課的目標

  • 了解 LLM 在本體工程各階段的用途
  • 會設計結構化的抽取流程
  • 理解人類審查的必要性

傳統的本體建構最貴的部分是知識擷取：訪談專家、讀大量文件、整理術語。LLM 能大幅加速這些工作，但不能取代判斷。

LLM 可以幫忙的地方

階段LLM 的工作人類的工作
規格根據使用情境草擬能力問題確認優先順序與範圍
術語擷取從手冊、法規、規格書中列出候選術語與定義去除重複、確認意思
階層與關係建議上下層關係、屬性、定義域值域檢查是否混淆 is-a 與 part-of 等錯誤
公理把自然語言規則轉成 OWL 公理（Manchester 語法）用推理機驗證、檢查意外推論
對齊判斷兩個概念是否對應（第 49 課）審查低信心的結果
資料填充從文件抽取個體與關係以 SHACL 驗證、抽樣檢查
文件為每個類別撰寫說明與範例校對

結構化抽取

讓 LLM 輸出符合固定結構的 JSON（工具呼叫或 JSON Schema），比自由文字可靠得多。再用程式把 JSON 轉成 RDF，交給推理機與 SHACL 檢查。

# 用 Claude 的工具呼叫，從文件中抽取符合本體的實體與關係（結構化輸出） import anthropic, json from rdflib import Graph, Namespace, Literal, RDF, RDFS doc = "B-101 號機於 6 月 3 日在桃園機場執行 A 檢，技師陳大明發現左側發動機滑油壓力感測器異常，更換零件 P-8841 後放行。" tool = {"name": "record_maintenance", "description": "記錄維修事件，所有欄位都必須出現在原文中", "input_schema": {"type": "object", "properties": { "aircraft": {"type": "string"}, "date": {"type": "string"}, "station": {"type": "string"}, "technician": {"type": "string"}, "finding": {"type": "string"}, "parts_replaced": {"type": "array", "items": {"type": "string"}}}, "required": ["aircraft", "finding"]}} MODEL = "claude-..." # 填入目前可用的 Claude 模型名稱 client = anthropic.Anthropic() msg = client.messages.create(model=MODEL, max_tokens=1024, tools=[tool], tool_choice={"type": "tool", "name": "record_maintenance"}, messages=[{"role": "user", "content": doc}]) data = next(b.input for b in msg.content if b.type == "tool_use") AV = Namespace("http://example.org/aviation#") g = Graph(); ev = AV["event/" + data["aircraft"] + "-" + data.get("date", "unknown")] g.add((ev, RDF.type, AV.MaintenanceEvent)) g.add((ev, AV.onAircraft, AV["aircraft/" + data["aircraft"]])) g.add((ev, RDFS.comment, Literal(data["finding"], lang="zh-TW"))) for p in data.get("parts_replaced", []): g.add((ev, AV.replacedPart, AV["part/" + p])) print(g.serialize(format="turtle")) # 接著交給 SHACL 驗證、人工抽樣審查

常見問題

  • 表面相似：LLM 擅長命名，但容易把「部分」當成「子類別」、把角色當成類別。
  • 不一致：同一份文件問兩次，得到不同的階層；需要固定流程、合併與去重。
  • 過度生成：產生一大堆沒人需要的類別；用能力問題控制範圍。
  • 來源：每一筆抽取結果都要記錄來自哪份文件的哪一段（PROV-O）。

建議的工作方式

把 LLM 當成一位很勤快、讀很快、但需要被審查的助理：它產生候選，推理機與 SHACL 做自動檢查，領域專家做最後判斷。人類審查的負擔從「從零寫起」變成「審核與修正」。

🧭 這一課的重點

LLM 可加速本體工程中最昂貴的知識擷取：草擬能力問題、擷取術語、建議階層與關係、把規則轉成 OWL 公理、對齊、資料填充與撰寫文件，人類負責確認、檢查與驗證。以工具呼叫或 JSON Schema 做結構化抽取，再轉成 RDF 交給推理機與 SHACL。常見問題有混淆部分與子類別、結果不一致、過度生成與缺乏出處，應以 LLM 產生候選、自動檢查、專家審核的流程進行。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
