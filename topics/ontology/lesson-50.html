OOPS!：本體陷阱掃描

馬德里理工大學的 OOPS!（OntOlogy Pitfall Scanner!）整理了四十多種常見陷阱，例如：

  • P04：建立了沒有連到任何東西的孤立元素。
  • P08：缺少標籤或說明。
  • P10：缺少互斥公理（第 25 課的經典錯誤）。
  • P11：缺少定義域或值域。
  • P13：缺少反向屬性。
  • P19：在定義域或值域中用多個類別，被誤解為「或」（實際是「且」）。
  • P24：遞迴定義。
  • P41：沒有宣告授權。
# 自製品質檢查：缺標籤、缺定義、沒有任何互斥公理、定義域多個類別 from rdflib import Graph, RDF, RDFS, OWL from rdflib.namespace import SKOS g = Graph().parse("library.ttl") classes = set(g.subjects(RDF.type, OWL.Class)) props = set(g.subjects(RDF.type, OWL.ObjectProperty)) no_label = [c for c in classes if (c, RDFS.label, None) not in g] no_def = [c for c in classes if (c, SKOS.definition, None) not in g and (c, RDFS.comment, None) not in g] multi_domain = [p for p in props if len(list(g.objects(p, RDFS.domain))) > 1] has_disjoint = any(g.triples((None, OWL.disjointWith, None))) or any(g.triples((None, RDF.type, OWL.AllDisjointClasses))) print(f"{len(classes)} 個類別；缺標籤 {len(no_label)}；缺定義 {len(no_def)}") print("定義域有多個類別（是交集，不是聯集！）：", multi_domain) if not has_disjoint: print("警告：沒有任何互斥公理，推理機幾乎抓不到錯誤")

品質檢查清單

  1. 推理機：一致，沒有不可滿足的類別。
  2. 每個類別與屬性都有標籤與文字定義。
  3. 兄弟類別之間是否該互斥？該宣告的都宣告了。
  4. 屬性的定義域、值域、特性（傳遞、函數性……）都經過思考。
  5. 所有能力問題的測試都通過。
  6. 有版本 IRI、授權、作者、變更紀錄。
  7. 重用了標準詞彙，而不是重新發明。

🧭 這一課的重點

本體品質從邏輯正確、需求滿足、領域正確、資料符合、結構品質、可用性與實際效益評估，方法包括推理機、能力問題測試、專家審查、SHACL 與度量工具。OOPS! 整理四十多種常見陷阱，如孤立元素、缺標籤、缺互斥、缺定義域值域、定義域多類別被誤解為聯集、缺授權。可用 rdflib 撰寫自製檢查，並依清單逐項確認。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
