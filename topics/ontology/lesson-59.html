Palantir Ontology 的架構：物件、屬性與連結

這一課的目標

  • 理解物件類型、屬性、連結類型
  • 理解資料集與物件的對應
  • 比較 Palantir Ontology 與 OWL 的建模方式

Palantir 的官方文件把 Ontology 的元素分為兩類：語意元素（semantic elements）——物件、屬性、連結；以及動能元素（kinetic elements）——動作、函數等（下一課）。

語意元素

元素說明OWL 的近似對應
物件類型（object type）一種實體或事件的綱要，例如飛機、航班、工單、客戶。每個物件類型有一個主鍵，並由一個或多個資料集提供資料類別（owl:Class）
物件（object）物件類型的一個實例，對應資料集中的一列個體
屬性（property）物件的特徵，有型別（字串、數字、日期、地理位置、時間序列等）資料屬性
連結類型（link type）兩個物件類型之間的關係，有基數（一對一、一對多、多對多），例如「航班 由…執飛 飛機」物件屬性
介面（interface）多個物件類型共有的形狀，例如「可維修的資產」上層類別（但更接近程式語言的介面）

和 OWL 的建模差異

  • 封閉世界、資料驅動：物件就是資料集裡的列，沒有的就是沒有（第 29 課的 CWA）。
  • 主鍵與型別嚴格：更像資料庫或程式語言的型別系統，而不是邏輯理論。
  • 沒有描述邏輯推理：不會自動推論「有子女的人是父母」；需要的話用函數或資料管線計算。
  • 面向應用：物件類型的設計以「使用者要在畫面上看到什麼、要做什麼決定」為準。

下面用 Python 寫一個極簡的模擬，幫助理解這些元素如何組合（這不是 Palantir 的程式碼）：

# 極簡模擬：物件類型、屬性、連結類型、物件集合（概念示意，不是 Palantir 的 API） from dataclasses import dataclass, field import pandas as pd @dataclass class ObjectType: name: str primary_key: str backing: pd.DataFrame # 資料集：每一列 = 一個物件 def get(self, pk): return self.backing.set_index(self.primary_key).loc[pk].to_dict() def where(self, **kw): d = self.backing for k, v in kw.items(): d = d[d[k] == v] return d @dataclass class LinkType: name: str; source: ObjectType; target: ObjectType; fk: str # 一對多：以外鍵實作 def follow(self, src_pk): tgt = self.source.get(src_pk)[self.fk] return self.target.get(tgt) aircraft = ObjectType("Aircraft", "tail", pd.DataFrame( {"tail": ["B-101", "B-102"], "type": ["A321", "A321"], "seats": [194, 194], "status": ["可用", "可用"]})) flight = ObjectType("Flight", "flight_no", pd.DataFrame( {"flight_no": ["CI-301", "CI-512"], "dest": ["成田", "新加坡"], "pax": [182, 188], "tail": ["B-101", "B-102"]})) operated_by = LinkType("operatedBy", flight, aircraft, fk="tail") print(operated_by.follow("CI-301")) # 沿著連結：CI-301 由哪架飛機執飛 print(flight.where(dest="成田")) # 物件集合（object set）的篩選

Ontology SDK

Palantir 提供 Ontology SDK（OSDK），會根據你的 Ontology 自動產生 TypeScript 或 Python 的型別化客戶端，讓外部應用以「物件」而不是「資料表」的方式存取資料。下一課會看到它的概念性寫法。

🧭 這一課的重點

Palantir 官方文件將 Ontology 元素分為語意元素（物件、屬性、連結）與動能元素（動作、函數等）。物件類型有主鍵並由資料集支撐，物件對應資料列，屬性有嚴格型別，連結類型帶基數，介面描述共有形狀。和 OWL 相比，它採封閉世界、資料驅動、型別嚴格、不做描述邏輯推理、以應用為導向。OSDK 會依 Ontology 產生 TypeScript 或 Python 的型別化客戶端。

🕸️ 本課程的程式範例以 Python 為主（rdflib、owlready2 等），Turtle 與 SPARQL 以字串形式出現在 Python 中；Palantir 相關內容依公開資料整理，產品與財務資訊以撰寫時為準。
