模組 C｜注意力與 KV Cache · 第 15 課

長上下文的代價

這一課的目標

  • 理解注意力計算的平方成長
  • 理解長上下文對兩個階段的影響
  • 認識長上下文的工程對策

注意力有一個本質的成本問題：每個 token 都要和前面所有 token 比對。

階段注意力的成本MLP 等其他部分
Prefill N 個 token∝ N²（每個 token 和前面所有 token 比對）∝ N
Decode 第 n 個 token∝ n（讀取整個 KV Cache）固定（讀一次權重）

在短上下文時，MLP 的計算佔大部分，注意力的平方項不明顯。但當上下文到了數萬甚至數十萬 token，注意力會變成主要成本：

  • Prefill 變慢：一次讀十萬 token 的文件，TTFT 可能從幾百毫秒變成十幾秒
  • Decode 變慢：每一步都要讀取巨大的 KV Cache，讀 KV 的時間可能超過讀權重的時間
  • 記憶體爆炸：KV Cache 隨長度線性成長，能同時服務的人數大幅下降

工程上的對策包括：FlashAttention 減少記憶體讀寫（第 19 課）、chunked prefill（第 20 課）、prefix caching 避免重算（第 30 課）、序列平行把長序列切到多張卡上，以及前面提到的 GQA、MLA、滑動視窗等架構改良。

🧭 這一課的重點

Prefill 的注意力成本隨長度平方成長，decode 每步隨長度線性成長；長上下文讓 TTFT、TPOT 與記憶體都惡化，需要 FlashAttention、chunked prefill、prefix cache 等對策。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
