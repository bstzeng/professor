自回歸生成

這一課的目標

  • 理解自回歸生成的迴圈
  • 理解為什麼 decode 無法平行
  • 知道 decode 每一步讀了什麼

Prefill 產出第一個 token 後，進入 decode 迴圈：

關鍵在於：第 n+1 個 token 取決於第 n 個 token 是什麼，而第 n 個 token 要等這一步算完、抽樣之後才知道。所以同一個請求的 decode 步驟只能一步一步來，無法像 prefill 那樣把所有位置一起算。

每一步 decode 要做的事：

  1. 把新 token 的 embedding 送進第一層
  2. 在每一層，為這一個 token 算 Q、K、V，把 K、V 寫入快取，用 Q 對整個 KV Cache 做注意力，再過 MLP
  3. 最後一層的輸出乘上 unembedding 得到 logits
  4. 從 logits 抽樣出下一個 token

一個回答有 500 個 token，就要跑這個迴圈 500 次，每次都要把整個模型的權重讀一遍。這就是為什麼長回答總是比長問題花更多時間。

🧭 這一課的重點

Decode 迴圈每步把上一個 token 送進所有層、讀 KV Cache、算 logits 並抽樣；下一個 token 取決於上一個，所以同一請求的 decode 無法平行。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
