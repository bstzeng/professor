位置資訊：RoPE

這一課的目標

  • 理解位置編碼的必要性
  • 認識 RoPE 的原理
  • 了解它和長上下文的關係

注意力機制本身不管順序：「狗咬人」和「人咬狗」如果沒有位置資訊，看起來是一樣的。所以模型必須以某種方式把位置加進去。

現代 LLM 多半使用 RoPE（Rotary Position Embedding，旋轉位置編碼，2021 年提出）：把 Q 和 K 向量的每一對維度，依照 token 的位置旋轉一個角度。位置越後面，旋轉得越多。

\[\text{RoPE}(x, m) = R(m\theta)\,x,\qquad \langle R(m\theta)q,\; R(n\theta)k\rangle \text{ 只取決於 } m-n\]

這個設計的巧妙之處在於：兩個 token 的注意力分數，只取決於它們的相對距離，而不是絕對位置。而且每一對維度用不同的旋轉頻率，低頻的維度能表示很遠的距離。

RoPE 也和長上下文息息相關：模型如果只在 8K 長度上訓練，直接拿去處理 128K 的輸入會表現很差。研究者發展出 NTK-aware 縮放、YaRN 等方法調整旋轉頻率，讓模型能以較少的額外訓練延伸上下文長度。

推論上的影響

RoPE 是在每一層對 Q、K 做旋轉，計算量很小。KV Cache 中存的 K 通常已經是旋轉後的版本，所以 decode 時不必重算。

🧭 這一課的重點

注意力本身不分順序，需要位置資訊；RoPE 依位置旋轉 Q、K，使注意力只取決於相對距離；調整旋轉頻率可延伸上下文長度。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
