怎麼測推論效能

這一課的目標

  • 認識推論 benchmark 的主要指標
  • 理解測試條件的影響
  • 學會判讀效能數字

「這個引擎每秒能跑 10,000 個 token！」——這樣的數字在沒有條件的情況下幾乎沒有意義。推論效能高度取決於測試條件：

條件影響
輸入／輸出長度長輸入考驗 prefill，長輸出考驗 decode；兩者的比例決定結果
並發數或請求速率並發越高吞吐量越高，但每人延遲越長
模型與精度BF16 和 FP8、4-bit 的速度差很多
硬體與卡數不同 GPU、不同平行策略
是否命中 prefix cache重複的 prompt 會讓 TTFT 看起來極快
抽樣與輸出長度控制是否固定輸出長度、是否忽略結束 token

可靠的 benchmark 應該：

  • 報告延遲的分布（P50、P90、P99），而不只是平均
  • 畫出吞吐量對延遲的曲線：在不同負載下各量一次，看在某個延遲目標下能達到多少吞吐量
  • 使用接近真實流量的資料集（例如真實對話的長度分布）
  • 說明所有測試條件，並與相同條件下的基準比較

常用的工具包括各推論框架附帶的 benchmark 腳本、MLPerf Inference 等產業基準。對使用者來說，最實際的方法是用自己的實際工作負載來測——別人的數字只能當參考。

🧭 這一課的重點

推論效能高度取決於輸入輸出長度、並發、精度、硬體與快取命中；可靠的 benchmark 報告延遲分布、畫吞吐量對延遲曲線、用真實流量並說明條件。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
