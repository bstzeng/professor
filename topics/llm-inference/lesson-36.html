記憶體階層

這一課的目標

  • 認識 GPU 的記憶體階層
  • 理解 HBM 的角色
  • 理解為什麼搬資料比算還貴

推論的所有權重和 KV Cache 都放在 HBM（高頻寬記憶體）中。HBM 是把多層 DRAM 晶片堆疊起來、透過矽中介層緊貼著 GPU 晶片，提供每秒數 TB 的頻寬——比一般電腦的 DDR5 記憶體快數十倍。

但即使如此，HBM 和晶片上的 SRAM 相比仍然很慢。每次運算都要把資料從 HBM 搬到 SRAM、暫存器，算完再寫回。一個經驗法則是：搬一個位元組的能量和時間，遠超過對它做一次運算。

這解釋了很多最佳化技術的共同邏輯：

  • FlashAttention：在 SRAM 裡把注意力算完，不把中間結果寫回 HBM
  • Kernel 融合：把多個小運算合成一個 kernel，資料只讀寫一次
  • 量化：讓要搬的位元組變少
  • Batching：讓搬來的每個位元組被用更多次

HBM 的容量也是推論的硬限制：H100 80 GB、H200 141 GB、B200 與 MI300X 192 GB。模型權重加上 KV Cache 必須放得下，否則就要用多張卡。

🧭 這一課的重點

GPU 記憶體從暫存器、SRAM、L2 到 HBM 越來越大越慢；權重與 KV Cache 放在 HBM，搬資料比運算昂貴；FlashAttention、融合、量化與 batching 都在減少或攤提搬運。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
