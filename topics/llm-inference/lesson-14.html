模組 C｜注意力與 KV Cache · 第 14 課

MHA、MQA、GQA、MLA

這一課的目標

  • 認識四種注意力架構
  • 理解它們如何縮小 KV Cache
  • 了解品質與效率的取捨

既然 KV Cache 這麼大，模型設計者開始從架構上想辦法縮小它：

架構提出做法代表模型
MHA（多頭注意力）2017每個 Q 頭都有自己的 K、VGPT-3、Llama 2 7B
MQA（多查詢注意力）Shazeer，2019所有 Q 頭共用一組 K、VPaLM、Falcon
GQA（分組查詢注意力）Ainslie 等，2023Q 頭分組，每組共用一組 K、VLlama 2 70B、Llama 3、Mistral
MLA（多頭潛在注意力）DeepSeek-V2，2024把 K、V 壓縮成一個低維的潛在向量存起來，用時再展開DeepSeek-V2、V3

GQA 是目前最主流的折衷：Llama 3 8B 有 32 個 Q 頭、8 個 KV 頭，KV Cache 只有 MHA 的四分之一，品質幾乎沒有損失。

MLA 則走得更遠：DeepSeek-V3 每層每個 token 只存一個 576 維的向量，雖然模型有 6710 億參數，KV Cache 卻比許多小得多的模型還小。代價是計算變得更複雜。

其他縮小 KV Cache 的方法還有：滑動視窗注意力（只看最近的 N 個 token，例如 Mistral 7B）、KV Cache 量化（用 FP8 或更低精度存）、以及部分層不做全域注意力的混合架構。

🧭 這一課的重點

MHA 每個 Q 頭有自己的 KV；MQA 全部共用；GQA 分組共用是主流折衷；MLA 將 KV 壓成潛在向量；另有滑動視窗與 KV 量化等方法。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
