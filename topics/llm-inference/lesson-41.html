模組 H｜系統與實務 · 第 41 課

成本結構

這一課的目標

  • 理解推論成本的組成
  • 理解輸入與輸出 token 的成本差異
  • 了解影響成本的因素

推論服務的成本，本質上是 GPU 時間（硬體折舊、電力、機房）除以產出的 token 數。從前面學到的原理，可以理解許多 API 的定價結構：

  • 輸出 token 比輸入 token 貴（常見數倍）：輸入在 prefill 中平行處理、充分使用算力；輸出要一步一步 decode，每一步都要讀整個模型，GPU 的算力大部分閒置
  • 快取命中的輸入比較便宜：prefix cache 讓這些 token 不必重新 prefill
  • 長上下文可能更貴：KV Cache 佔用記憶體、降低 batch 大小，注意力計算也更多
  • 批次 API 比較便宜：不要求即時回應，伺服器可以在空閒時以大 batch 處理，把吞吐量拉到最高
  • 小模型便宜很多：參數少，讀得快、算得快、需要的卡也少

從系統的角度，降低成本就是提高每張 GPU 每秒產出的 token 數。這門課提到的所有技術——batching、PagedAttention、量化、推測解碼、prefix cache、MoE、分離部署——最終都反映在這個數字上。過去幾年，同等能力模型的推論價格下降了一到兩個數量級，硬體進步與這些軟體最佳化都功不可沒。

推理模型的成本

會先「思考」再回答的推理模型，可能在給出答案前生成數千到數萬個思考 token。這些都是 decode，讓輸出 token 的比例大增，也讓 decode 效率變得更加關鍵。

🧭 這一課的重點

推論成本是 GPU 時間除以 token 數；輸出 token 需逐步 decode、算力閒置所以較貴，快取命中與批次 API 較便宜；所有最佳化最終都在提升每 GPU 每秒 token 數。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
