Chat template 與系統提示

這一課的目標

  • 了解對話如何被組成一段文字
  • 認識特殊 token
  • 理解系統提示與工具定義的成本

你在介面上看到的是一則一則對話，但模型實際看到的是一長串 token。對話會依照模型的 chat template 被組裝起來，用特殊 token 標示角色與邊界，大致像這樣：

<|begin|><|system|>你是一個樂於助人的助理……<|end|> <|user|>今天台北天氣如何？<|end|> <|assistant|>

模型的任務就是接著 <|assistant|> 之後繼續寫下去，直到生成代表結束的特殊 token。不同模型的 template 格式不同，用錯格式會讓模型表現明顯變差。

  • 系統提示：可能長達數千 token，每次請求都要 prefill 一次（除非有 prefix cache，第 30 課）
  • 對話歷史：每一輪都要把之前的所有對話重新送進去——模型本身沒有記憶，「記憶」就是 prompt
  • 工具定義、檢索的文件：同樣變成 prompt 的一部分

所以一段聊了很久的對話，每一次回覆的 prefill 成本都在增加。這也是為什麼長對話會越來越慢、越來越貴。

🧭 這一課的重點

對話依 chat template 以特殊 token 組成一長串輸入，模型從 assistant 標記後接著寫；系統提示、歷史對話與工具定義每次都要 prefill，長對話越來越貴。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
