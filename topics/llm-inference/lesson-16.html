Prefill 做了什麼

這一課的目標

  • 理解 prefill 的計算過程
  • 理解為什麼 prefill 可以平行
  • 認識 prefill 的輸出

Prefill 階段，整段輸入的 N 個 token 被排成一個 N × d 的矩陣，一起穿過每一層。

為什麼可以一起算？因為輸入的所有 token 都已經知道了，而因果遮罩保證每個 token 只依賴前面的 token——這和訓練時的「teacher forcing」完全相同。所以 prefill 的計算方式和訓練的前向傳播幾乎一模一樣。

Prefill 結束時產出兩樣東西：

  1. 整段輸入的 KV Cache：每一層、每個 token 的 K 和 V
  2. 第一個輸出 token：只需要用最後一個 token 位置的輸出向量算 logits

注意第 2 點：雖然 prefill 為每個位置都算了輸出向量，但只有最後一個位置會被拿來預測下一個 token。前面位置的輸出只用來產生下一層需要的 K、V。

🧭 這一課的重點

Prefill 把 N 個輸入 token 排成矩陣一起穿過每層，因所有 token 已知且有因果遮罩，與訓練前向傳播相同；產出整段 KV Cache 與第一個輸出 token。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
