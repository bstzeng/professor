KV Cache

這一課的目標

  • 理解 KV Cache 存了什麼
  • 理解它省下了多少計算
  • 理解 prefill 與 KV Cache 的關係

生成第 n 個 token 時，它的 Query 需要和前面所有 n−1 個 token 的 Key、Value 做注意力。如果每次都重新計算前面所有 token，計算量會隨長度平方成長。

KV Cache 的做法是：每算出一個 token 在每一層的 K 和 V，就存在 GPU 記憶體裡。之後的每一步只需要：

  1. 為新的 token 計算它的 Q、K、V（只有一個 token）
  2. 把新的 K、V 加進快取
  3. 用新的 Q 和快取中所有的 K、V 做注意力

現在可以更精確地定義兩個階段了：

  • Prefill ＝ 為整段輸入一次建立 KV Cache（並算出第一個輸出 token）
  • Decode ＝ 每一步讀取 KV Cache、加入一個新 token 的 K、V

KV Cache 是推論系統中最重要、也最麻煩的資料結構：它讓 decode 變得可行，卻佔用大量記憶體，而且大小隨著上下文長度與同時服務的人數不斷增長（下一課）。

🧭 這一課的重點

KV Cache 存下每個 token 在每層的 K、V，讓 decode 每步只算新 token；prefill 是為整段輸入建立快取，decode 是讀取並擴充快取；它以大量記憶體換取計算。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
