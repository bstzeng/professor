模組 E｜Decode 階段 · 第 26 課

停止條件與結構化輸出

這一課的目標

  • 認識生成的停止條件
  • 理解受限解碼
  • 了解它對推論系統的影響

Decode 迴圈什麼時候結束？常見的停止條件有：

  • 結束 token：模型生成了代表「回答結束」的特殊 token（例如 <|eot_id|>）
  • 長度上限：達到使用者或系統設定的最大輸出 token 數
  • 停止字串：輸出中出現指定的字串（例如程式碼區塊結束）
  • 使用者取消：關掉視窗或按下停止，伺服器要及時釋放 KV Cache

推論系統事先不知道一個請求會生成多少 token。這讓排程變得困難：KV Cache 該預留多少空間？要不要接受新的請求？這也是 PagedAttention 要解決的問題之一（第 29 課）。

受限解碼（constrained decoding）

當應用程式需要模型輸出合法的 JSON、符合某個 schema 或某種文法時，可以在抽樣前把不合法的 token 的機率設為 0。例如目前已經輸出了 {"age": ，下一個 token 就只允許數字。

實作上，系統把 JSON schema 或文法轉成一個有限狀態機，每一步計算哪些 token 合法。挑戰在於詞彙表有十幾萬個 token，每一步都要快速算出遮罩；Outlines、XGrammar 等函式庫用預先計算與快取讓這個開銷變得很小。

🧭 這一課的重點

生成在遇到結束 token、長度上限、停止字串或使用者取消時停止，輸出長度事先未知；受限解碼在抽樣前遮掉不合文法的 token，保證輸出格式。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
