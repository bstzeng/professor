MoE 模型的推論

這一課的目標

  • 理解 MoE 架構
  • 理解 MoE 對推論的影響
  • 認識專家平行

混合專家（Mixture of Experts, MoE）模型把 MLP 換成很多個「專家」，每個 token 由路由器挑選其中少數幾個來計算。

模型總參數每 token 啟用參數
Mixtral 8x7B約 470 億約 130 億（8 選 2）
DeepSeek-V36,710 億約 370 億（256 個路由專家選 8＋1 共享）

對推論來說，MoE 是一把雙面刃：

  • 計算少：每個 token 的 FLOPs 只和啟用參數有關，prefill 很便宜
  • 記憶體大：所有專家都要放在 GPU 記憶體中，671B 模型即使用 FP8 也要約 700 GB
  • 小 batch 時頻寬吃虧：batch 中不同 token 選了不同專家，batch 一大幾乎每個專家都要讀，讀取量接近總參數
  • 大 batch 時划算：每個專家分到足夠多的 token，算術強度回升

所以 MoE 特別適合大規模服務：用專家平行把專家分散到數十甚至上百張 GPU 上，每張卡只放幾個專家，token 透過 all-to-all 通訊送到對應的卡。挑戰在於負載平衡——熱門的專家會成為瓶頸。

🧭 這一課的重點

MoE 讓每個 token 只用少數專家，計算量低但所有專家都要放進記憶體；小 batch 時頻寬吃虧，大 batch 時划算，適合用專家平行做大規模部署。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
