為什麼 prefill 是算力受限

這一課的目標

  • 理解算術強度
  • 理解 prefill 的算術強度
  • 理解什麼是 compute-bound

GPU 做一次運算需要兩樣東西：資料（從記憶體讀進來）和運算單元（Tensor Core）。哪一個先不夠用，就是瓶頸。

算術強度（arithmetic intensity）＝ 運算次數 ÷ 讀寫的位元組數。強度越高，代表每讀一份資料能做越多事。

Prefill 時，一個 d × d 的權重矩陣（d² × 2 bytes）被讀進來一次，卻要和 N 個 token 相乘（2 × d² × N 次運算）：

\[\text{算術強度} \approx \frac{2 d^2 N}{2 d^2} = N\ \text{FLOP/byte}\]

一段 2,000 token 的輸入，強度約 2,000。而 H100 的「轉折點」（算力 ÷ 頻寬）約 295 FLOP/byte。強度遠高於轉折點，代表資料供應綽綽有餘，瓶頸在運算單元——這就是 compute-bound。

一個實用的結論：只要 prefill 的 token 數超過幾百個，它就能把 GPU 的算力用得很滿。進一步加快 prefill 只能靠更多的算力（更快的 GPU、更多張卡）或更少的運算（更小的模型、prefix cache 避免重算）。

🧭 這一課的重點

算術強度是運算次數除以讀寫位元組數；prefill 的強度約等於 token 數 N，遠高於 H100 的轉折點約 295，所以 prefill 是算力受限。

⚡ 文中的硬體規格取自廠商公開資料（稠密運算、未計稀疏加速），速度與記憶體計算都是理論估算，實際數字會因軟體實作、批次與排程而不同。
