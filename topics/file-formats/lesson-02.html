模組 A｜共同基礎：所有檔案都只是一串位元組 · 第 2 課

附檔名只是名字：真正決定格式的魔術數字

這一課的目標

  • 理解副檔名和實際格式是兩回事
  • 說出什麼是魔術數字（檔頭簽章）
  • 認得幾個常見格式的開頭位元組

.jpg、.mp3 這些副檔名，只是檔名的一部分，方便「作業系統」決定用哪個程式打開，以及決定顯示哪個圖示。它本身不改變檔案內容：把 photo.jpg 改名成 photo.txt，裡面的位元組一個都沒變。

1. 魔術數字

真正說明「我是什麼格式」的，是檔案開頭的幾個位元組，稱為魔術數字或檔頭簽章。看圖軟體、播放器打開檔案時，先讀這幾個位元組來確認格式，通常不太理會副檔名。

2. 為什麼有些看得懂、有些看不懂

PDF 開頭是 25 50 44 46，剛好是 ASCII 的「%PDF」；ZIP 是「PK」（來自發明者 Phil Katz 的姓名縮寫）。PNG 的 89 50 4E 47 中間是「PNG」，但前面那個 89 是故意放的「非文字」位元組，用來偵測檔案在傳輸中有沒有被錯誤地當成純文字處理而損壞。

3. 副檔名的另一面：安全風險

因為副檔名可以隨便改，壞人會利用這一點：把執行檔命名成 發票.pdf.exe，在會隱藏副檔名的系統上看起來就像 PDF。這門課最後的資安單元會詳談（第 63 課）。

Linux／Mac 的 file 指令、以及各種語言的函式庫，都是靠魔術數字來判斷真正的格式。

動手試試

把一個小圖片複製一份、改名成 .txt，用 Hex 檢視器打開，確認開頭位元組完全沒變；再改回 .jpg，看圖軟體照樣打得開。
