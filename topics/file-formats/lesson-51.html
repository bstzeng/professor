純文字格式：TXT、CSV、JSON、XML、YAML

這一課的目標

  • 認識幾種常見的純文字資料格式
  • 理解換行符號的跨系統差異
  • 知道 BOM 造成的問題

繞了一大圈複雜格式，回到最樸素的純文字。它們就是一堆字元（第 4 課），人和機器都直接讀得懂——但正因為太簡單，反而藏著一些惱人的陷阱。

1. 幾種常見格式

格式長相常見用途
CSV用逗號分隔的表格試算表匯出、資料交換
JSON鍵值對與陣列（{...}）程式之間、網路 API 傳資料
XML巢狀標籤（<a>...</a>）docx、SVG 內部；較囉嗦
YAML靠縮排表達層次軟體設定檔；好讀好寫

2. 換行符號的陷阱

「換行」在不同系統用不同位元組：Windows 用兩個（0D 0A，CR＋LF），Mac／Linux 用一個（0A，LF）。這就是為什麼有時把檔案在不同系統間搬動，會出現「整篇擠成一行」或多出奇怪符號。

3. 編碼與 BOM

另一個陷阱是編碼（第 4 課）。同一個 CSV 用 Big5 存、用 UTF-8 開，中文就變亂碼。還有隱形的 BOM（開頭看不見的 EF BB BF）：它有時能幫程式判斷編碼，有時卻讓程式把第一行的欄位名讀錯而出 bug。

教訓：純文字看起來最單純，卻是跨系統、跨語言最容易出問題的地方。處理別人給的文字檔前，先確認它的編碼和換行格式，能省下很多麻煩。

動手試試

用記事本和另一個編輯器（如 VS Code）打開同一個文字檔，VS Code 右下角會顯示它的編碼（UTF-8／Big5）和換行（CRLF／LF）——這兩個資訊常是解決亂碼的關鍵。

檢查你的理解

  2. Windows 和 Linux 的換行符號差在哪？
  3. BOM 是什麼？可能造成什麼問題？
