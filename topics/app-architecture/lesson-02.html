分層架構

這一課的目標

  • 認識四層架構
  • 理解依賴方向
  • 知道分層帶來的好處
// 領域層：不認識任何 UI 或檔案系統 class Document { paragraphs: Paragraph[] = []; insertText(pos: Position, text: string) { /* 規則 */ } } // 應用層：協調使用情境，透過介面依賴基礎設施 class SaveDocument { constructor(private storage: Storage) {} async run(doc: Document, path: string) { await this.storage.write(path, serialize(doc)); } }

好處

  • 可測試：領域層可以不開視窗、不碰磁碟就測試。
  • 可替換：換掉 UI 框架或儲存方式，核心不用改。
  • 好分工：不同的人負責不同層。

🧭 這一課的重點

分層讓每層只承擔一種責任，依賴由上往下，核心邏輯不受 UI 與技術細節影響。

🧰 本課以通用的軟體架構說明概念，程式碼為教學用的簡化片段（以 TypeScript 為主），重點在設計思路而非特定框架的完整寫法。

檢查你的理解

  1. 四層各負責什麼？
  2. 為什麼領域層不應該認識 UI？
  3. 分層對測試有什麼幫助？
