專案結構與模組化

這一課的目標

  • 比較依技術分與依功能分
  • 理解模組邊界
  • 知道依賴規則的自動檢查
src/ ├── core/ # 領域模型、共用型別（不依賴任何 UI） ├── editor/ # 編輯功能：自己的 model、view、commands │ └── index.ts # 只從這裡公開 API ├── search/ ├── settings/ └── platform/ # 檔案、網路、系統 API 的包裝
  • 每個模組只從 index 公開必要的東西，內部可以自由改。
  • 禁止循環依賴；可以用工具在建置時自動檢查「誰可以 import 誰」。
  • 大型軟體會把模組拆成獨立套件，甚至獨立團隊負責。

🧭 這一課的重點

依功能劃分模組、只透過公開介面溝通、用工具守住依賴規則。

🧰 本課以通用的軟體架構說明概念，程式碼為教學用的簡化片段（以 TypeScript 為主），重點在設計思路而非特定框架的完整寫法。

檢查你的理解

  1. 依功能分資料夾有什麼好處？
  2. 為什麼要禁止循環依賴？
  3. 模組的公開介面是什麼？
