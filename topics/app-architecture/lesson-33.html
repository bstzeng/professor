測試金字塔

這一課的目標

  • 認識三種測試
  • 理解測試金字塔
  • 知道架構對可測試性的影響
// 單元測試：測領域邏輯，不需要 UI test("插入文字後可以復原", () => { const doc = new Doc("你好"); const h = new History(); h.execute(new InsertText(doc, 2, "世界")); expect(doc.text).toBe("你好世界"); h.undo(); expect(doc.text).toBe("你好"); });
類型測什麼特點
單元一個函式或類別毫秒級、大量
整合多個模組合作，例如存檔再讀回較慢
介面（端對端）模擬使用者點擊整個程式最慢、最脆弱，只測關鍵流程

🧭 這一課的重點

大量快速的單元測試為底，少量整合與介面測試在上；分層架構讓核心易於單元測試。

🧰 本課以通用的軟體架構說明概念，程式碼為教學用的簡化片段（以 TypeScript 為主），重點在設計思路而非特定框架的完整寫法。
