突破 640K:真實模式、保護模式與記憶體

這一課的目標

  • 理解真實模式與保護模式的差別
  • 知道保護模式如何突破 640K
  • 看出「記憶體保護」帶來的穩定

還記得 DOS 那個惱人的640K 天花板嗎(第 28 課)?程式越做越大,640K 根本不夠。Windows 要跑得動眾多圖形程式,就非突破它不可。關鍵在於善用新 CPU 提供的保護模式。

1. 真實模式:被 640K 困住的舊世界

早期 CPU(和為了相容它的 DOS)工作在真實模式(real mode):為了相容老程式,它只能用到約 1MB記憶體,而且程式能亂碰任何位置(沒有保護,第 29 課)。這就是 640K 世界的由來。

2. 保護模式:新 CPU 的新能力

後來的 CPU 提供了保護模式(protected mode),帶來兩個關鍵能力:

  • 能定址大得多的記憶體:遠遠超過 1MB,640K 的枷鎖就此打開。
  • 記憶體保護:每支程式有自己的領地,想亂碰別人的區域會被 CPU 擋下,而不是默默把系統弄壞。

3. Windows 善用它,一石二鳥

Windows 利用保護模式,一方面讓程式用到更多記憶體(能跑更大、更多的軟體),另一方面提升了穩定性——因為程式比較不會一寫錯就拖垮全機(雖然當年還做得不徹底,當機仍時有所聞)。

(補充:為了相容既有的 DOS 程式,Windows 還得在這些模式之間巧妙切換、讓新舊程式並存,工程相當精巧。這也再次體現「背負相容包袱」的難處,第 35 課。)

記憶體的問題解決了。還剩最後一塊拼圖:DOS 一次只能跑一個程式(第 28 課),Windows 又是怎麼讓好幾個視窗程式看起來同時在跑的?(第 39 課)

想一想

「保護」這個概念影響深遠:現代系統之所以一支程式當掉,其他程式還好好的,正是靠記憶體保護把大家的領地隔開。從 DOS 的「大家擠一間、一個出事全遭殃」,到今天的「各有隔間」,是穩定性的一大躍進。
