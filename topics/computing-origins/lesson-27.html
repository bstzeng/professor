INT 21h:程式怎麼請 DOS 幫忙(系統呼叫)

這一課的目標

  • 理解系統呼叫的概念
  • 認識 INT 21h 的運作方式
  • 連結到中斷機制

一支 DOS 程式想「讀一個檔」或「在螢幕印字」,它不必自己去操作磁碟或顯卡——那太麻煩又危險(第 19 課)。它只要請 DOS 代勞。DOS 提供的這個求助窗口,最有名的就是 INT 21h。

1. 這其實就是「軟體中斷」

還記得模組 D 說,程式可以主動觸發中斷來呼叫作業系統服務嗎(第 21 課)?INT 21h 正是這個機制的招牌實例:INT 是「觸發中斷」的指令,21h(十六進位的 21)是 DOS 服務所在的編號。

2. 怎麼用:填好參數,喊一聲

用法像去櫃台辦事——先填單,再喊號:

  1. 在暫存器 AH 裡放功能編號(想做哪件事,例如「印一個字」是某個號)。
  2. 在其他暫存器放需要的資料(例如 DL 放要印的那個字)。
  3. 執行 INT 21h——DOS 接手,看 AH 是哪個功能,幫你做完,把結果放回暫存器。

3. 為什麼這樣設計很好

  • 程式不必知道硬體細節,換一台機器也能跑(只要都有 DOS)。
  • DOS 可以統一管理對硬體的存取,比較不會亂。
  • 這就是作業系統當「中間人」的具體實現——提供一套標準服務給所有程式用。

(小補充:對速度要求極高的程式——如遊戲——有時會略過 DOS、直接操作硬體以求快。這帶來相容與穩定的隱憂,也埋下 DOS 侷限的伏筆。)

了解程式怎麼和 DOS 互動後,我們來面對 DOS 最著名的一個限制:那個神祕的640K 記憶體(第 28 課)。

想一想

「填好表單、喊個號,剩下交給櫃台」——系統呼叫的精神,和你去公家機關辦事一模一樣。你不需要懂公務系統內部怎麼運作,只要按格式提出請求。今天手機 App 呼叫系統服務,骨子裡還是這套模式。
