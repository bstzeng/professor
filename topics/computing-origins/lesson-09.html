CPU 真正讀的語言:機器碼

這一課的目標

  • 理解機器碼是 CPU 直接執行的數字
  • 知道每個數字對應一個動作
  • 認識「指令集」的概念

程式被讀進電腦後,CPU 看到的是什麼?不是中文、不是英文,而是一長串數字——這就是機器碼(machine code),是 CPU 唯一能直接執行的語言。

1. 每個數字,代表一個動作

CPU 內部有一本「對照表」:看到某個數字,就做某個動作。例如某顆 CPU 看到位元組 B8,意思是「接下來兩個位元組,放進 AX 暫存器」;於是 B8 05 00 就是「把數字 5 放進 AX」。CPU 不理解「放進暫存器」這句話,它只是照著數字查表、動作。

2. 什麼是「指令集」

這一整套「哪個數字代表哪個動作」的規則,叫做指令集(instruction set)。不同家族的 CPU 有不同的指令集(例如 x86、ARM),所以同一份機器碼,換一種 CPU 就不一定看得懂。這也是為什麼軟體常要分「給哪種處理器用」的版本。

3. 人怎麼可能直接寫這個?

早期程式員真的得和機器碼搏鬥:把動作一個個查成數字,再打進卡片。這極度枯燥又容易出錯——把 B8 打成 B9,程式就跑錯了。於是人們發明了一層「翻譯」,讓程式至少能用文字來寫,這就是下一課的組合語言(第 10 課)。

想一想

機器碼提醒我們一件事:CPU 一點也不「聰明」,它只是「看到數字 A 就做動作 A」的超快查表機器。所有你覺得電腦很聰明的表現,都是無數這種笨動作,以每秒數十億次的速度堆疊出來的。
