模組 G｜Windows 3.1 怎麼在 DOS 上蓋出視窗 · 第 39 課

合作式多工:好幾個程式怎麼「輪流」用一顆 CPU

這一課的目標

  • 理解「輪流使用 CPU」造成同時感
  • 分清合作式與搶佔式多工
  • 看出合作式多工的先天脆弱

DOS 是單工的:一次一個程式(第 28 課)。但用 Windows 時,你能同時開好幾個視窗,它們看起來一起在跑。問題是:一顆 CPU 在同一瞬間其實只能做一件事,那「同時」是怎麼變出來的?

1. 祕密:快速輪流

祕密是輪流:讓 CPU 一下子做這個程式、一下子做那個程式,切換得夠快,你的眼睛就以為它們同時在跑(就像翻頁動畫,靜態圖切得夠快就成了動畫)。這就是多工的基本想法。

2. 合作式:靠程式「自願讓位」

Windows 3.x 用的是合作式多工(cooperative multitasking):CPU 給某個程式用一陣子,然後那個程式要「自願」把控制權交回來,系統才能換下一個。就像一群人講好輪流發言:講完一段就主動讓位。乖乖配合的程式,大家就輪得很順,看起來一起在跑。

3. 先天的脆弱:一個不讓位,全體卡住

問題來了:這套機制完全依賴每個程式的「自律」。萬一有個程式卡住了、或設計不良「不肯讓位」,系統就拿它沒辦法——CPU 一直被它佔著,其他所有程式(連同整個介面)就一起凍結。這是合作式多工的先天弱點,也是那個年代 Windows 容易「整個當住」的原因之一。

4. 後來的解法:搶佔式多工

更可靠的做法是搶佔式多工(preemptive):不靠程式自律,而是由系統當「主持人」,用計時器強制分配時間——時間到就強制把 CPU 收回給下一個。這樣單一程式再壞,也拖不垮全體。後來的作業系統普遍改用這種方式,才根治了「一個卡住、全體卡住」的問題。

至此,Windows 3.1 在 DOS 上補齊了圖形、互動、記憶體、多工。最後一課,回頭看:為什麼偏偏是 3.1 這一版,讓視窗真正普及?(第 40 課)

想一想

「靠大家自律 vs 由主持人強制」——這個對比不只在電腦裡。任何需要多方共享資源的系統(交通、會議、網路),都面臨同樣選擇。合作式多工的教訓很清楚:一旦有人不守規矩,純靠自律的系統就會失靈。強制的規則,有時反而讓大家都更好。
