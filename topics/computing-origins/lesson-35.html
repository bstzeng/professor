模組 G｜Windows 3.1 怎麼在 DOS 上蓋出視窗 · 第 35 課

關鍵真相:早期 Windows 其實是「跑在 DOS 上的一支程式」

這一課的目標

  • 理解早期 Windows 與 DOS 的關係
  • 看懂「圖形環境」與「作業系統」的差別
  • 建立本模組的整體圖像

先破除一個常見誤解。很多人以為 Windows 從一開始就是一套獨立的作業系統,其實早期的 Windows(包含 3.1)是「跑在 DOS 之上」的一層圖形環境。這個真相,是理解「視窗怎麼在文字的 DOS 上長出來」的鑰匙。

1. 開機順序透露了真相

在那個年代,你開機其實是先進入 DOS(還記得那個 C:\> 嗎,第 25 課),然後打一個指令(WIN)才啟動 Windows。也就是說,Windows 是被 DOS 載入、在 DOS 上面跑的一支大程式。關掉 Windows,你會回到 DOS。

2. 分層:各司其職

  • DOS 在最底層,負責開機、檔案系統、基本服務(第 18 課、第 26 課)。
  • Windows 疊在上面,提供圖形環境:視窗、繪圖、選單、滑鼠。
  • 你的應用程式(視窗軟體)再疊在 Windows 上,享用它提供的圖形能力。

3. 為什麼要「蓋在 DOS 上」,而不砍掉重練

因為當時整個世界都在跑 DOS:無數 PC、無數使用者、無數既有的軟體與習慣(第 23 課)。與其推倒重來、要大家全部換掉,不如站在 DOS 這個既有地基上,逐步加上圖形能力——這樣既相容舊世界,又能把人平順地帶往新介面。

接下來幾課,我們就一塊塊看 Windows 在 DOS 上補了哪些東西:怎麼畫視窗(第 36 課)、怎麼回應你的操作(第 37 課)、怎麼突破 640K(第 38 課)、怎麼讓多個程式並存(第 39 課)。

想一想

「站在既有地基上逐步改良」而不是「打掉重練」,是科技演進的常態。Windows 蓋在 DOS 上,正如很多新技術都要背負「相容舊系統」的包袱。這既是限制,也是智慧——因為使用者的既有投資,不能說丟就丟。
