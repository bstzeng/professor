中斷:硬體怎麼「舉手」找 CPU

這一課的目標

  • 理解輪詢與中斷的差別
  • 認識中斷的運作流程
  • 知道中斷也用來呼叫系統服務

這一課補上一個貫穿作業系統與硬體溝通的核心機制:中斷(interrupt)。它回答一個問題:CPU 正埋頭跑程式,怎麼及時知道「鍵盤被按了」「磁碟資料好了」?

1. 笨方法:一直問(輪詢)

一種做法是讓 CPU 不停地輪流問每個裝置:「你有事嗎?你呢?」這叫輪詢(polling)。但這很浪費:大部分時間裝置都沒事,CPU 卻要一直問,問的時間根本沒法拿去算正事。

2. 聰明方法:讓裝置「舉手」

更好的辦法是中斷:平常 CPU 專心跑程式,不管裝置;哪個裝置有事了,就自己發出一個訊號「舉手」。CPU 收到後:

  1. 暫停手邊的工作,記住做到哪。
  2. 跳去執行對應的中斷處理程式(例如把剛按下的鍵讀進來)。
  3. 處理完,回到原點,繼續剛才被打斷的工作。

這樣 CPU 就能專心做事,有事再說,效率高得多。

3. 中斷還能用來「呼叫系統服務」

中斷不只給硬體用。程式也能主動觸發一個中斷,對 OS 說「請幫我做某件事」(例如讀檔)。這叫軟體中斷,是應用程式呼叫作業系統服務的經典方式。下個模組你會看到 DOS 最著名的 INT 21h——程式就是靠它請 DOS 幫忙的(第 27 課)。

到這裡,「作業系統是什麼、怎麼跟硬體與程式打交道」的觀念齊備了。接著把鏡頭轉向歷史:第一批個人電腦的 OS 長什麼樣?我們的主角 DOS 又從何而來?(第 22 課)

想一想

「中斷」的智慧在日常也常見:你不會每分鐘檢查一次信箱有沒有信,而是讓它「有信再通知你」,這樣你才能專心做事。CPU 對待硬體,用的正是這種「別打擾我,有事再舉手」的高效策略。
