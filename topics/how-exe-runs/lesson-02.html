機器碼與組合語言：CPU 真正讀的東西

這一課的目標

  • 理解機器碼是 CPU 直接執行的位元組
  • 說明組合語言與機器碼的關係
  • 讀懂幾條最基本的指令

執行檔裡最核心的東西是機器碼：一串位元組，每一段對應一條 CPU 指令。CPU 不認得 if、for，它只會一條一條讀這些位元組並執行。

1. 組合語言：機器碼的人話版

直接讀 B8 01 00 00 00 很痛苦，所以有組合語言：把每條指令寫成好記的名字，例如 mov eax, 1（把 1 放進 eax 這個暫存器）。組合語言和機器碼一對一，組譯器負責在兩者間翻譯。

2. 幾條基本指令

組合語言意思
mov eax, 1把數字 1 放進暫存器 eax
syscall / call呼叫作業系統或某個函式
push / pop把資料放上／取下堆疊
jmp / je跳到別的地方（迴圈、判斷就靠它）

3. 暫存器與系統呼叫

暫存器是 CPU 裡少數幾個超高速的小格子（eax、edi…），運算都在這裡進行。程式要做「印字」「開檔」這類事得請作業系統幫忙，方法是把功能編號放進暫存器，再用 syscall（Linux）呼叫作業系統。下一課的手寫程式，就是這樣印出一句話的。

高階語言（C、Python）是更上一層：你寫一行，編譯器／直譯器把它展開成許多條這種底層指令。

動手試試

用線上的組譯器（如 Compiler Explorer, godbolt.org）貼一小段 C，右邊會即時顯示對應的組合語言——你會看到一行 C 展開成好幾條指令。

🔧 本課用最小範例與觀察工具，說明執行檔的結構與載入原理，屬於系統知識與資安基礎；不含惡意程式技術。手工打造的極小執行檔常被防毒軟體視為可疑，請只在自己的環境、用自己的檔案練習。
