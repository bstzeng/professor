匯入表：程式怎麼借用 DLL 的函式

這一課的目標

  • 理解 Windows 程式為何要透過 DLL
  • 說明匯入表的作用
  • 對比 Linux 的動態連結

Linux 程式可以直接 syscall 叫作業系統（第 3 課），但 Windows 程式不行——它必須透過 DLL（動態連結函式庫）裡的函式。程式怎麼知道去哪找這些函式？靠匯入表。

1. 借來的功能

想跳出訊息視窗？程式自己沒這功能，但 user32.dll 有 MessageBoxA。於是程式在匯入表裡記一筆：「我要用 user32.dll 的 MessageBoxA」。要結束自己？記「我要用 kernel32.dll 的 ExitProcess」。

2. 載入時填入真正位址

程式被載入時，作業系統的載入器（第 13 課）會：找到這些 DLL、載入它們、查出每個被借用函式的真正記憶體位址，填進匯入表。填完，程式呼叫 MessageBoxA 時就能正確跳到 user32.dll 裡那段程式碼。

3. 為什麼 exe 可以很小

因為真正的功能大多在系統的 DLL 裡，程式只是借來用，所以一個功能豐富的 exe 可能只有幾 KB。這也是動態連結的好處：許多程式共用同一份 DLL，省記憶體、也方便統一更新（例如修補安全漏洞）。

Linux 也有一樣的機制（.so 檔、動態連結器），概念相通，只是名字不同。這個「借用外部函式」的設計，是現代程式能小巧又強大的關鍵。

動手試試

在 PE 檢視工具裡看 Import Table，你會看到這個程式依賴哪些 DLL、各借用了哪些函式——像 kernel32.dll、user32.dll 幾乎每個程式都會用到。

🔧 本課用最小範例與觀察工具，說明執行檔的結構與載入原理，屬於系統知識與資安基礎；不含惡意程式技術。手工打造的極小執行檔常被防毒軟體視為可疑，請只在自己的環境、用自己的檔案練習。
