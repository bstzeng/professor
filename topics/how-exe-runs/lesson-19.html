.NET、Java、Python 打包的 exe 有什麼不同

這一課的目標

  • 區分原生、位元組碼、打包直譯器三種 exe
  • 理解為什麼有些 exe 特別大
  • 連結到位元組碼的概念

一個 .exe 一定是原生機器碼嗎？不一定。很多「exe」其實不是直接給 CPU 讀的機器碼。

1. 三種可能

  • 原生（C／Rust／Go）：直接是機器碼，CPU 直接跑，最快、依賴最少。
  • .NET／Java：編譯成位元組碼（下一課），執行時由虛擬機（CLR／JVM）邊翻譯邊跑。exe 可能只是個啟動殼。
  • 打包的 Python 等：exe 是個「殼」，裡面塞了整個直譯器加上你的腳本，執行時先解壓到暫存資料夾，再由內附的直譯器來跑。

2. 為什麼有些 exe 大得誇張

這解釋了一個常見疑問：一個功能簡單的小工具，做成 exe 卻有好幾十 MB。因為它把整個執行環境（直譯器、函式庫、執行期）都打包進去了，好處是使用者不必另外安裝任何東西，代價就是檔案很大、啟動稍慢。

3. 怎麼分辨

原生 exe 通常小而依賴系統 DLL；打包型的則很大、執行時會在暫存資料夾冒出一堆檔案。用工具看它的匯入表與資源，也能看出端倪（例如發現內嵌了 python.dll 或大量 .NET 中繼資料）。所以「它是不是原生程式」，也是你拿到一個 exe 時可以判斷的一件事。

動手試試

觀察你電腦裡的程式：有些安裝後只有幾 MB（多半原生或依賴系統元件），有些單一 exe 就好幾十 MB（多半打包了執行環境）。

🔧 本課用最小範例與觀察工具，說明執行檔的結構與載入原理，屬於系統知識與資安基礎；不含惡意程式技術。手工打造的極小執行檔常被防毒軟體視為可疑，請只在自己的環境、用自己的檔案練習。
