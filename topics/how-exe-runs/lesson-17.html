程式結束：ExitProcess、資源回收與結束代碼

這一課的目標

  • 說明程式正常結束的流程
  • 理解結束代碼的意義
  • 區分正常結束與當機

旅程的最後一站：程式結束。無論是你按了關閉、程式跑完，還是它出錯，作業系統都要負責讓它乾淨地離場。

1. 正常結束

程式正常結束時：main 回傳（或呼叫 exit）→ 執行清理（關檔案、跑收尾程式）→ 呼叫 ExitProcess 通知作業系統 → 作業系統回收它用的全部資源。

2. 結束代碼

程式離開時會留下一個結束代碼：慣例上 0 代表成功，非 0 代表某種錯誤。你平常看不到它，但它對自動化很重要——例如批次腳本會看前一個程式的結束代碼，決定要不要繼續。

3. 作業系統會全部收回

重要的是：程式結束後，作業系統會回收它的全部記憶體與資源。所以就算程式執行期間有記憶體洩漏（第 16 課忘了還記憶體），一旦結束也一筆勾銷——這是行程隔離（第 11 課）的又一個好處。

4. 當機：非自願的結束

當機（crash）是「被迫結束」：程式做了非法的事（例如存取不屬於它的記憶體、除以零），被作業系統強制中止，通常還會產生一份「當機報告」。因為有行程隔離，一個程式當掉不會拖垮整台電腦。

到這裡，一個執行檔從雙擊到結束的完整旅程就走完了。最後一個模組帶你看看其他系統的做法，以及實際觀察這一切的工具（第 18 課）。

動手試試

在命令列執行一個程式後，Windows 打 echo %errorlevel%、Linux/Mac 打 echo $? ，就能看到它剛剛的結束代碼——成功的程式通常回傳 0。

🔧 本課用最小範例與觀察工具，說明執行檔的結構與載入原理，屬於系統知識與資安基礎；不含惡意程式技術。手工打造的極小執行檔常被防毒軟體視為可疑，請只在自己的環境、用自己的檔案練習。
