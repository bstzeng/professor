從進入點到 main：C 執行期環境做了哪些準備

這一課的目標

  • 理解進入點與 main 的差別
  • 說明 C 執行期啟動碼做的準備
  • 知道 main 回傳後發生什麼

載入器把控制權交給進入點。但這裡有個常見誤會：進入點不是你寫的 main，中間還隔著一段C 執行期啟動碼。

1. main 之前的準備

進入點其實是一段由編譯器附上的啟動碼（C runtime startup）。它在呼叫你的 main 之前，先幫你把環境準備好：

  • 整理命令列參數，變成 main 收到的 argc、argv。
  • 初始化全域變數與 C++ 的全域物件。
  • 設定標準輸入輸出（讓你能 printf、cin）。
  • 準備好堆積，讓你之後能動態配置記憶體。

2. 才輪到 main

這些都就緒，啟動碼才呼叫你寫的 main，你的程式邏輯這時才真正開始。所以「程式從 main 開始」只是我們寫程式時的方便說法，底層還有一段前置作業。

3. main 回傳之後

當 main 回傳（或你呼叫 exit），控制權交回啟動碼，它負責清理：跑完該做的收尾、把 main 的回傳值當成整個程式的結束代碼交給作業系統（0 通常代表成功）。這部分第 17 課會再細講。

如果是圖形介面程式，main（或 WinMain）裡通常會進入一個訊息迴圈，讓視窗持續運作，這就是下一課的主題（第 15 課）。

動手試試

寫一個簡單的 C 程式，在 main 第一行印一句話。用除錯器從「進入點」開始單步執行，你會看到在到達你的 main 之前，先跑了一堆啟動碼。
