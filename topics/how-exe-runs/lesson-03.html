模組 J｜exe 裡面有什麼 · 第 3 課

動手：用 184 個位元組手寫一個執行檔

這一課的目標

  • 逐區段讀懂一個最小 ELF 執行檔
  • 理解檔頭、程式標頭、機器碼的分工
  • 親眼看到「程式只是位元組」

理論講完，來真的。下面是一個完整、只有 184 位元組、手工打造的 Linux 執行檔（ELF 格式），它會印出一句話然後結束。這是真的能跑的程式——下載它（在 Linux 上 chmod +x 後執行）。

1. 三大部分

部分大小作用
ELF 檔頭64 位元組魔術數字 7F ELF、64 位元、進入點位址、程式標頭在哪
程式標頭56 位元組告訴作業系統：把這個檔載到記憶體哪、給什麼權限（可讀可執行）
機器碼＋字串64 位元組33 位元組的 CPU 指令，加上要印的那句話

2. 那 33 個位元組在做什麼

就是上一課的兩次系統呼叫：

  • B8 01…／BF 01…：設定「功能＝寫出」「目標＝螢幕」。
  • 0F 05：syscall，請作業系統把字串印出來。
  • B8 3C…／0F 05：功能 60＝結束程式，乾淨地離開。

3. Windows 的 .exe 呢

Windows 的 PE 格式（第 4 課）道理相同，只是檔頭更囉嗦（要有 MZ 檔頭、匯入表等），手寫更麻煩，而且極小的手寫 exe 常被防毒軟體當成可疑檔案。所以這門課提供 Linux 版讓你實際下載執行，Windows 版只拆解結構、不提供下載。

這一課的重點不是要你以後手寫程式，而是破除「執行檔很神祕」的迷思：它就是一串你能看懂、甚至能親手寫出的位元組。

動手試試

在 Linux（或 WSL）下載 hello.elf，執行 chmod +x hello.elf 再 ./hello.elf，它會印出一句中文。再用 readelf -h hello.elf 或 xxd hello.elf，對照上圖的每一個位元組。

🔧 本課用最小範例與觀察工具，說明執行檔的結構與載入原理，屬於系統知識與資安基礎；不含惡意程式技術。手工打造的極小執行檔常被防毒軟體視為可疑，請只在自己的環境、用自己的檔案練習。
