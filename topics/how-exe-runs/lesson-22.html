安裝程式：.msi、.deb、.rpm 到底做了什麼

這一課的目標

  • 理解安裝程式的職責
  • 區分 Windows 與 Linux 的安裝方式
  • 知道套件管理員如何處理相依

下載一個軟體常要「安裝」，而不是直接執行。安裝到底做了什麼？它其實是一套把檔案放對位置、登記到系統的自動化流程。

1. 安裝做的事

  • 把程式檔複製到正確的資料夾。
  • 在系統登記（Windows 寫登錄檔、Linux 記到套件資料庫），以便日後乾淨移除。
  • 建立開始功能表／桌面捷徑、副檔名關聯（第 9 課）。
  • 確認並安裝相依的函式庫。

2. 不同系統的做法

格式系統本質
.msiWindows一個資料庫，描述要裝什麼、寫哪些登錄檔
.debDebian／Ubuntu封裝檔：程式檔＋安裝前後腳本＋相依資訊
.rpm紅帽／Fedora類似 .deb，由套件管理員安裝

.deb、.rpm 其實是封裝檔（和 ZIP／封裝的概念相通），裡面裝著程式檔和幾段安裝腳本。

3. 套件管理員與相依

Linux 的套件管理員（apt、dnf）和 Windows 的 winget，最大的價值是自動處理相依：你要裝的軟體需要某個函式庫，它會一併裝好，也會在你移除時清理乾淨。這正是對抗「DLL 地獄」的現代解法——用一個中央資料庫統一管理所有軟體與它們的相依關係。

所以「安裝」是一門關於相依管理與系統整潔的學問，遠比複製檔案複雜。

動手試試

在 Linux 用 dpkg -L 某套件名，可以列出它安裝了哪些檔案、放在哪裡。Windows 的「新增/移除程式」則對應到安裝時登記的資訊。

🔧 本課用最小範例與觀察工具，說明執行檔的結構與載入原理，屬於系統知識與資安基礎；不含惡意程式技術。手工打造的極小執行檔常被防毒軟體視為可疑，請只在自己的環境、用自己的檔案練習。
