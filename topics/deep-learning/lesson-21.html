批次大小與 epoch

這一課的目標

  • 分辨 batch、iteration、epoch
  • 了解批次大小的取捨
  • 會計算一個 epoch 有幾步
名詞意思
Batch（批次）一次送進模型、算一次梯度的一小群資料
Iteration／Step更新一次參數
Epoch把整個訓練集看過一遍

例：6 萬張圖、批次大小 64 → 一個 epoch 約 938 步。訓練 10 個 epoch 就是約 9,380 步。

批次大小的取捨

小批次（例如 32）大批次（例如 4096）
梯度雜訊大較準確
GPU 利用率較低較高，每秒處理更多資料
記憶體少多
泛化雜訊有時有幫助有時需要搭配調大學習率

記憶體不夠放大批次時，可以用梯度累積：連續算好幾個小批次的梯度加起來，再更新一次，效果等同大批次。

LLM 的單位不同

LLM 預訓練通常只把資料看過約 1 遍（甚至不到），所以不太講 epoch，而是講「訓練了多少 token」，例如 Llama 3 訓練了約 15 兆 token。批次大小也常以 token 計，可達數百萬 token。

🧭 這一課的重點

Batch 是一次算梯度的資料量，step 是更新一次，epoch 是看完整個訓練集。大批次梯度準、GPU 利用率高但耗記憶體，可用梯度累積模擬。LLM 以訓練的 token 數計量。

🧠 本課的互動工具都在瀏覽器裡即時計算；資料是教學用的小例子，詞向量、注意力等數值為示意，真實模型的維度從數百到數萬維。歷史年份以原始論文發表年份為準。
