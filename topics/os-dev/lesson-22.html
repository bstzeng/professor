分頁錯誤的妙用

這一課的目標

  • 理解需求分頁
  • 認識寫入時複製
  • 知道記憶體映射檔與置換
技巧做法好處
需求分頁程式要 1 GB，先只登記不配置；真的存取某頁時才在分頁錯誤中配置沒用到的記憶體不佔空間
寫入時複製fork 時共用頁面並設唯讀，寫入時才複製（第 29 課）fork 很快
記憶體映射檔把檔案映射到位址空間，存取時才從磁碟讀入大檔案、共用函式庫
置換（swap）把不常用的頁寫到磁碟，存在位元清 0；再存取時讀回可用記憶體看起來比實體多
bool handle_page_fault(uint64_t addr, uint64_t err) { struct vma* v = find_vma(current->mm, addr); // 這個位址屬於程式登記過的區域嗎？ if (!v) return false; // 沒有 → 真正的錯誤（segmentation fault） if ((err & PF_WRITE) && is_cow(addr)) return cow_copy(addr); map_page(current->pml4, page_align(addr), pmm_alloc(), v->flags); // 需求分頁 return true; }

🧭 這一課的重點

分頁錯誤不只是錯誤：需求分頁、寫入時複製、記憶體映射檔、置換都建立在它之上。

🖥️ 本課的核心程式碼為教學用的極簡範例（C 與 x86-64 組合語言），省略了許多錯誤處理與邊界情況；真實作業系統（Linux、Windows、macOS）的實作複雜得多，細節以其原始碼與文件為準。
