開機載入程式

這一課的目標

  • 理解開機程式的工作
  • 認識開機協定
  • 知道核心從開機程式得到什麼

開機程式負責：讀取核心檔案、放到正確位置、準備好 CPU 模式，最後跳進核心。核心和開機程式之間需要一份「約定」（開機協定），說明交接時的狀態與資訊。

協定使用者交給核心的資訊
Multiboot2GRUB記憶體地圖、framebuffer、模組、命令列
Limine 協定Limine同上，並直接進入 64 位元、已映射上半部核心
Linux boot protocolLinux 核心boot_params 結構
// 用 Limine 協定向開機程式「要」資訊：在核心裡放一個請求結構 __attribute__((section(".requests"))) static volatile struct limine_memmap_request memmap_req = { .id = LIMINE_MEMMAP_REQUEST, .revision = 0 }; // 開機後，memmap_req.response 就指向記憶體地圖

教學核心選用 Limine，因為它直接把我們帶進 64 位元長模式，省去大量組合語言。

🧭 這一課的重點

開機程式依開機協定載入核心並提供記憶體地圖等資訊；選好協定能省去許多底層工作。

🖥️ 本課的核心程式碼為教學用的極簡範例（C 與 x86-64 組合語言），省略了許多錯誤處理與邊界情況；真實作業系統（Linux、Windows、macOS）的實作複雜得多，細節以其原始碼與文件為準。
