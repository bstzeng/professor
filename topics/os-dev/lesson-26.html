使用者模式與核心模式

這一課的目標

  • 理解 Ring 0 與 Ring 3
  • 知道從使用者模式進入核心的時機
  • 認識 TSS 的作用

CPU 目前的特權等級記錄在程式碼區段選擇子的最低兩位。使用者程式在 Ring 3 執行，只能透過三種方式進入核心：系統呼叫、例外、硬體中斷。

// 從 Ring 3 被中斷時，CPU 必須換到核心堆疊——它從 TSS 讀取 rsp0 struct tss { uint32_t r0; uint64_t rsp0, rsp1, rsp2; uint64_t r1; uint64_t ist[7]; /* … */ } __attribute__((packed)); void set_kernel_stack(void* top) { tss.rsp0 = (uint64_t)top; } // 每次切換行程都要更新
; 第一次進入使用者模式：偽造一個「從中斷返回」的堆疊框架 push USER_DS | 3 ; ss push user_stack_top ; rsp push 0x202 ; rflags（IF=1：開中斷） push USER_CS | 3 ; cs push user_entry ; rip iretq ; CPU 以為要「返回」Ring 3

🧭 這一課的重點

使用者程式在 Ring 3 執行，只能經由系統呼叫、例外、中斷進入核心；TSS 提供核心堆疊位址。

🖥️ 本課的核心程式碼為教學用的極簡範例（C 與 x86-64 組合語言），省略了許多錯誤處理與邊界情況；真實作業系統（Linux、Windows、macOS）的實作複雜得多，細節以其原始碼與文件為準。
