實體記憶體地圖

這一課的目標

  • 理解記憶體地圖
  • 知道保留區域的來源
  • 讀取開機程式提供的地圖
struct limine_memmap_response* mm = memmap_req.response; for (uint64_t i = 0; i < mm->entry_count; i++) { struct limine_memmap_entry* e = mm->entries[i]; kprintf("%x - %x %s\n", e->base, e->base + e->length, type_name(e->type)); if (e->type == LIMINE_MEMMAP_USABLE) pmm_add_region(e->base, e->length); }

實體位址空間裡有很多「洞」：韌體資料、ACPI 表、裝置的記憶體映射 I/O（第 9 課）。核心絕不能把這些地方當成一般記憶體使用，否則會覆蓋韌體資料或寫進裝置暫存器。

🧭 這一課的重點

核心從開機程式取得記憶體地圖，只把「可用」區域交給實體記憶體配置器。

🖥️ 本課的核心程式碼為教學用的極簡範例（C 與 x86-64 組合語言），省略了許多錯誤處理與邊界情況；真實作業系統（Linux、Windows、macOS）的實作複雜得多，細節以其原始碼與文件為準。

  2. 記憶體地圖從哪裡來？
  3. 核心誤用保留區域會發生什麼事？
