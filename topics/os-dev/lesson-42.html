C 標準函式庫怎麼接到系統呼叫

這一課的目標

  • 理解 libc 的角色
  • 認識 crt0 與 _start
  • 知道緩衝的影響
// libc/crt0.S：使用者程式真正的進入點 _start: mov rdi, [rsp] ; argc lea rsi, [rsp + 8] ; argv call main mov rdi, rax ; main 的回傳值 call exit ; 先清空緩衝區，再呼叫 sys_exit // libc/syscall.c long write(int fd, const void* buf, size_t n) { long r; asm volatile("syscall" : "=a"(r) : "a"(1), "D"(fd), "S"(buf), "d"(n) : "rcx", "r11", "memory"); return r; }
層次例子
高階函式printf、fopen、malloc（用使用者空間緩衝與記憶體池）
系統呼叫包裝write、open、mmap、fork
核心sys_write、sys_open

printf 不會每次都呼叫 write：它先寫進緩衝區，滿了或遇到換行（終端機）才真的系統呼叫。所以程式當掉時，最後幾行 printf 可能來不及出現。malloc 則向核心要大塊記憶體（brk、mmap）後自己切。常見的 libc 實作有 glibc、musl。

🧭 這一課的重點

libc 提供 _start、系統呼叫包裝與緩衝等高階功能，是使用者程式和核心之間的橋樑。

🖥️ 本課的核心程式碼為教學用的極簡範例（C 與 x86-64 組合語言），省略了許多錯誤處理與邊界情況；真實作業系統（Linux、Windows、macOS）的實作複雜得多，細節以其原始碼與文件為準。

  2. 為什麼 printf 的輸出可能在當機時遺失？
