模組 A｜開始之前 · 第 3 課

開發環境

這一課的目標

  • 理解為什麼需要交叉編譯
  • 認識核心專用的編譯選項
  • 學會用 QEMU 執行與除錯
# 核心專用的編譯選項（重點） CFLAGS = -ffreestanding # 沒有標準函式庫，main 不是進入點 -fno-stack-protector # 沒有 libc 提供的堆疊保護函式 -mno-red-zone # 中斷會覆蓋紅區，核心不能用 -mcmodel=kernel # 核心放在位址空間的最上方 -mno-sse -mno-mmx # 避免在中斷中使用浮點暫存器 qemu-system-x86_64 -cdrom os.iso -serial stdio -s -S # -s -S：等待 GDB 連線
  • 交叉編譯器：產生「沒有作業系統」的目標檔，避免意外連結到主機的 libc。
  • QEMU：模擬整台電腦，當掉只要重開模擬器；可以印出 CPU 狀態。
  • GDB：連上 QEMU，在核心程式碼設中斷點、逐步執行。

🧭 這一課的重點

核心要用獨立（freestanding）的方式編譯，並在 QEMU 中執行、用 GDB 除錯。

🖥️ 本課的核心程式碼為教學用的極簡範例（C 與 x86-64 組合語言），省略了許多錯誤處理與邊界情況；真實作業系統（Linux、Windows、macOS）的實作複雜得多，細節以其原始碼與文件為準。

  2. -ffreestanding 的意義是什麼？
  3. 為什麼核心要關閉紅區？
