行程與執行緒的資料結構

這一課的目標

  • 認識行程控制區塊
  • 理解行程狀態
  • 區分行程與執行緒
enum state { READY, RUNNING, BLOCKED, ZOMBIE }; struct process { int pid; enum state state; struct context* ctx; // 被切走時保存的暫存器（在核心堆疊上） uint64_t* pml4; // 位址空間（第 21 課） void* kstack; // 每個執行緒自己的核心堆疊 struct file* files[64]; // 檔案描述元表（第 34 課） struct process* parent; uint64_t vruntime; // 排程資訊（第 25 課） struct process* next; // 串在就緒佇列裡 };

執行緒是 CPU 排程的單位；行程是資源（位址空間、檔案）的容器。同一個行程的多條執行緒共用位址空間，各有自己的暫存器與堆疊。Linux 把兩者統一成 task_struct，差別只在共用了哪些資源。

🧭 這一課的重點

PCB 記錄行程的一切：狀態、暫存器、位址空間、檔案；執行緒共用行程的資源但有自己的堆疊。

🖥️ 本課的核心程式碼為教學用的極簡範例（C 與 x86-64 組合語言），省略了許多錯誤處理與邊界情況；真實作業系統（Linux、Windows、macOS）的實作複雜得多，細節以其原始碼與文件為準。
