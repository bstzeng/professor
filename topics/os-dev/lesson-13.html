例外處理與核心恐慌

這一課的目標

  • 認識常見的 CPU 例外
  • 理解分頁錯誤的資訊
  • 知道核心恐慌的處理
向量例外常見原因
0除以零（#DE）整數除以 0
6無效指令（#UD）跳到錯誤位址執行
13一般保護錯誤（#GP）權限不足、非正規位址
14分頁錯誤（#PF）存取沒有映射或權限不符的頁；CR2 存著出錯位址
8雙重錯誤（#DF）處理例外時又發生例外
—三重錯誤連雙重錯誤都處理不了 → CPU 直接重新開機
void interrupt_dispatch(struct regs* r) { if (r->vector == 14) { uint64_t addr; asm volatile("mov %%cr2, %0" : "=r"(addr)); if (handle_page_fault(addr, r->error_code)) return; // 可處理的情況（第 22 課） } if (r->vector < 32) { if (from_user_mode(r)) { kill_current_process(); return; } // 使用者程式的錯：只殺它 panic("exception %d at %p", r->vector, r->rip); // 核心的錯：停機 } // ……硬體中斷 }

同樣是除以零：發生在使用者程式，核心只要終止那個程式；發生在核心裡，代表核心本身有錯，只能停機並印出資訊——Linux 的 kernel panic、Windows 的藍色畫面就是這個。

🧭 這一課的重點

CPU 例外會跳到核心；使用者程式的錯誤就終止該程式，核心自己的錯誤只能恐慌停機。

🖥️ 本課的核心程式碼為教學用的極簡範例（C 與 x86-64 組合語言），省略了許多錯誤處理與邊界情況；真實作業系統（Linux、Windows、macOS）的實作複雜得多，細節以其原始碼與文件為準。
