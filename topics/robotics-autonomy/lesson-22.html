BEV 鳥瞰圖與佔據網格

這一課的目標

  • 理解 BEV 表示法的優點
  • 理解佔據網格與 Occupancy Network
  • 理解為什麼這是近年的重大進展

為什麼需要鳥瞰圖

一台車有 6～8 顆鏡頭，每顆看到的是透視的畫面：遠的東西小、近的東西大，而且彼此有重疊。但規劃路徑時，最方便的是一張從上往下看的地圖：車道在哪、車子在哪、行人在哪，距離一目了然。

BEV（Bird's-Eye View）方法用神經網路把多顆鏡頭的畫面（以及光達、雷達）直接轉換成一張統一的鳥瞰圖。2021 年前後起，特斯拉、各大中國車廠與研究機構大量採用這種架構。

佔據網格

傳統的物件偵測只認得「訓練過的類別」：車、人、腳踏車。但路上可能出現任何東西：掉落的貨物、倒下的樹、施工圍欄。

佔據網格換一個問法：不問「這是什麼」，只問「這個空間有沒有被東西佔據、它在怎麼移動」。把周圍空間切成許多小方塊（3D 版本稱為體素），每個方塊預測是否被佔據。這讓車子能避開從沒見過的障礙物。

表示法回答的問題優點
2D 物件框畫面中有哪些物件簡單，但缺乏距離
3D 物件框物件在哪裡、多大、往哪走適合追蹤與預測
BEV 特徵圖俯瞰的語意地圖多鏡頭統一，方便規劃
3D 佔據網格哪些空間被佔據能處理未知物體與不規則形狀

這些表示法通常同時存在，一起送給下一步的預測與規劃；在端到端系統中，它們成為神經網路內部的中間表示。

🧭 這一課的重點

多顆鏡頭的透視畫面不利於規劃，BEV 方法以神經網路將多鏡頭與光達雷達資料轉換成統一的鳥瞰圖，2021 年前後起被特斯拉與中國車廠大量採用。傳統物件偵測只認得訓練過的類別，佔據網格則只問空間是否被佔據及如何移動，將周圍切成體素逐一預測，可避開從未見過的障礙物。2D 框、3D 框、BEV 特徵圖與 3D 佔據網格常同時存在並送入預測與規劃。

🤖 本課程重直覺、輕推導，程式範例以 Python 為主。產業數字多來自 2025～2026 年的公司公告與研究機構彙整，各家數字常有出入，課中以「約」與資料日期標示；硬體規格以廠商公布值為準，實際可用效能通常低於標稱峰值。
