安裝n8n：Docker vs npm兩種方式

這一課的目標

  • 認識n8n是什麼：一個開源、視覺化的工作流自動化平台
  • 能用npx n8n或Docker其中一種方式，在本機把n8n跑起來
  • 知道n8n啟動後，要用瀏覽器連到哪個位址才能打開編輯器介面

模組C確認了地端LLM已經能被外部程式透過HTTP API呼叫。 這一課要開始動手架設真正負責「呼叫它」的平台——n8n， 一個開源的視覺化工作流自動化工具。跟模組B安裝Ollama 類似，n8n也有幾種安裝方式，這一課介紹兩種最常見、 最適合起步的做法。

1. 方式一：npx n8n，最快的試用方式

如果本機已經裝好Node.js，不需要另外安裝任何東西， 直接在終端機執行：

npx n8n

npx會暫時下載並執行n8n套件，很適合 「我只是想先看看n8n長什麼樣子」的情境——不需要事先 走一次完整的安裝流程，馬上就能啟動一份可以互動的 n8n實例。

2. 方式二：Docker，推薦的穩定做法

對於要長期使用的情境，用Docker啟動n8n是更推薦的 做法——容器把n8n跟它的執行環境包在一起，不會受到 本機Node.js版本差異的影響，也更容易當成一個長期在 背景運作的服務來管理：

docker run -it --rm --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n n8nio/n8n
  • -it：以互動模式啟動，終端機能看到n8n的即時輸出
  • --rm：容器停止後自動清除容器本身（資料不會不見，因為掛載了volume）
  • --name n8n：給這個容器一個好記的名字
  • -p 5678:5678：把主機的5678埠對應到容器內n8n監聽的5678埠——這是n8n的預設埠號
  • -v n8n_data:/home/node/.n8n：把n8n儲存工作流、憑證等資料的目錄，掛載到一個叫做n8n_data的Docker volume，就算容器被刪除重建，之前建立的工作流資料依然保留
方式指令特點
npx n8nnpx n8n免安裝，Node.js就緒即可執行，適合快速試用
Dockerdocker run …環境獨立、不受本機Node.js版本影響，資料透過volume明確保存，適合長期穩定使用

3. 啟動後，去哪裡打開n8n

不管用哪一種方式，n8n啟動後都是透過瀏覽器存取的 視覺化介面，而不是像Ollama那樣主要用終端機互動。 開啟瀏覽器，前往：

http://localhost:5678

第一次連上時，n8n通常會引導你建立一個本機帳號（僅 存在於你自己的n8n實例裡），完成後就會進入工作流 編輯器——下一課要介紹的主角。

檢查你的理解

  1. 寫出用npx啟動n8n的指令，以及用Docker啟動n8n並掛載persistent volume的完整docker run指令
  2. 解釋docker run指令裡-p 5678:5678這個參數在做什麼
  3. n8n啟動後，要用瀏覽器連到哪個網址才能打開編輯器
