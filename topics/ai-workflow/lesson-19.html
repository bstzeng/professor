n8n表達式（Expression）：動態取用前一個節點的資料

這一課的目標

  • 能把節點的參數欄位切換成「表達式模式」，寫出動態的值，而不是寫死的固定文字
  • 能寫出{{ $json.欄位名稱 }}，取用目前這筆item的資料
  • 能用$node["節點名稱"].json.欄位名稱或$('節點名稱').item.json.欄位名稱，指定讀取某個特定前面節點的輸出

上一課看到資料在n8n裡是以item陣列的形式流動，但光是 「資料存在」還不夠——要讓後面的節點真的用得到前面 節點算出來的東西，需要一套語法，能在某個節點的設定 欄位裡，指到「另一個節點輸出的某個欄位」。這套語法 就是n8n的表達式（Expression）。

1. 從固定值切換到表達式模式

n8n裡幾乎每一個節點的參數欄位，預設都是「固定值」 模式——你打進去的文字，會被當成字面上的字串直接使用。 要讓這個欄位變成「動態值」，通常要先切換到表達式模式， 編輯器裡一般會在欄位旁邊提供一個小圖示或切換開關（常見 標示為fx），點下去之後欄位就會變成可以 輸入{{ }}語法的表達式編輯器，通常還會即時 顯示這個表達式目前實際算出來的值，方便邊寫邊確認結果 對不對。

2. {{ $json.欄位名稱 }}：取用目前這筆item的資料

最基本、也最常用的表達式，是取用「目前這個節點正在 處理的這一筆item」裡的某個欄位。假設前一個節點輸出的 item長這樣：

{ "json": { "name": "Alice", "score": 90 } }

在下一個節點的某個欄位裡寫：

{{ $json.name }}

執行時就會被替換成Alice。$json 永遠指的是「這個節點正在處理的目前這筆item」的 json內容，這也是為什麼上一課要先把item跟 json欄位的結構講清楚——表達式裡幾乎所有的路徑，都是 建立在這個結構上。

3. 取用特定前一個節點的輸出

$json只能拿到「緊接在前面」那個節點的 資料，但工作流常常有好幾條分支，或是需要回頭引用更早 以前某一步的結果。這時候可以用節點名稱，明確指定要讀 哪一個節點的輸出：

{{ $node["取得使用者資料"].json.name }}

比較新、也比較簡潔的寫法，則是用$()這個 函式搭配節點名稱：

{{ $('取得使用者資料').item.json.name }}

兩種寫法效果類似，都是明確指名「去讀某個特定節點輸出 的這個欄位」，而不是只看緊接在前面的那個節點。節點 名稱如果包含空白或特殊字元，記得要放在引號裡，就像 上面範例的中文節點名稱一樣。

小提醒：節點名稱會隨著你重新命名而改變

表達式裡引用的節點名稱，是節點在畫布上顯示的名稱 （可以雙擊節點標題重新命名），不是節點的類型。如果 之後把某個節點改了名字，所有引用它的表達式通常也會 自動一併更新，但養成先把重要節點取一個清楚、穩定的 名稱的習慣，能讓表達式讀起來更容易理解，也比較不會 在流程變複雜之後搞混。

檢查你的理解

  1. 說明一個欄位要進入「可以寫表達式」的狀態，通常要先做什麼操作
  2. 寫出取用目前這筆item裡score欄位的表達式
  3. 寫出取用一個叫做「篩選資料」的節點裡，email欄位的表達式，並說出兩種可能的寫法
