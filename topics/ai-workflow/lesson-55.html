模組 N｜AI Agent與工具呼叫基礎 · 第 55 課

什麼是工具呼叫（Tool Calling）

這一課的目標

  • 理解工具呼叫（Tool Calling，又稱Function Calling）的基本機制：LLM可以在回應裡「決定呼叫某個函式」，而不是只能輸出純文字
  • 認識這個機制需要的三個要件：工具清單、名稱與描述、參數結構（schema）
  • 建立「工具呼叫是AI Agent能自主決策的技術地基」這個框架，為模組N後面兩課鋪路

模組I（第35～38課）已經讓LLM輸出結構化的JSON，再用IF／ Switch節點依照這個JSON分流——但那整套流程，「要呼叫哪個 後續動作」始終是工作流設計者事先寫死的邏輯，LLM只負責 判斷內容、n8n負責決定走哪條路。這一課要介紹一個更進一步 的機制：讓LLM本身就能在產生回應的當下，直接「決定」要 呼叫某個工具、並且決定要帶什麼參數——這個機制叫做 工具呼叫（Tool Calling），早期也常被稱為 Function Calling。它正是模組N接下來要談 的AI Agent，能夠自主做決策的技術基礎。

1. 傳統做法：LLM只能輸出文字，決策邏輯寫死在工作流裡

回顧模組I的做法：你要求LLM輸出一個像 {"category": "urgent", "confidence": 0.9} 這樣的JSON字串，接著n8n用Switch節點檢查 category欄位的值，決定要走「發Slack通知」 還是「寫進資料庫」這條路。這裡LLM做的事情，本質上仍然 只是「生成一段文字」——文字剛好被格式化成JSON，方便後續 節點解析。至於「這個分類結果該對應到哪個動作」，是設計 工作流的人事先用IF／Switch節點寫死的規則，LLM本身完全 不知道後面接的是什麼系統、也無法自己決定要不要多查一筆 資料再下判斷。

2. 工具呼叫：讓LLM自己決定要不要呼叫、呼叫哪個、帶什麼參數

工具呼叫改變的，正是這個關係。做法是：在呼叫LLM時，除了 平常的prompt之外，額外附上一份工具清單 ——每個工具都有一個名稱（例如 lookup_sheet_row）、一段描述 （用自然語言說明這個工具是做什麼用的，LLM會依賴這段描述 判斷什麼時候該用它），以及一份參數結構（schema） （用JSON Schema之類的格式，定義呼叫這個工具需要 帶哪些參數、各自是什麼型別）。LLM生成回應時，會依據使用者 的任務，自行判斷「這個當下該不該呼叫某個工具」——如果要， 它輸出的不是一段自然語言文字，而是一個結構化的呼叫請求： 工具名稱＋一組符合該工具參數結構的引數。

// 提供給LLM的工具清單，其中一個工具的定義（示意格式） { "name": "lookup_sheet_row", "description": "依照日期查詢Google試算表裡當天的紀錄，回傳符合條件的資料列", "parameters": { "type": "object", "properties": { "date": { "type": "string", "description": "查詢日期，格式YYYY-MM-DD" } }, "required": ["date"] } } // LLM對某個任務的回應，不是純文字，而是一次工具呼叫請求 { "tool_call": { "name": "lookup_sheet_row", "arguments": { "date": "2026-08-27" } } }

要特別澄清一個常見誤解：LLM本身不會真的去執行 這個工具——它只負責「決定要呼叫哪個工具、帶什麼 參數」，並把這個決定以結構化格式輸出出來。真正執行這個 工具（例如真的去查Google試算表、真的發一則Slack訊息） 的，是LLM外部的程式（在這門課的情境裡，就是n8n）。n8n 收到LLM的工具呼叫請求後，實際執行對應的節點，把結果再 回傳給LLM，讓它可以根據這個結果，決定下一步——是繼續呼叫 別的工具，還是已經有足夠資訊可以直接生成最終的文字回應。

3. 為什麼這是AI Agent能自主決策的地基

有了工具呼叫這個機制，LLM第一次有能力做到「依照任務內容， 自己判斷該用哪個工具、要不要用、用幾次、用完之後要不要再 用別的工具」——而不是被工作流設計者事先寫死唯一一條路徑。 當這個「決策 → 執行 → 回饋 → 再決策」的迴路被包裝成一個 可以重複跑好幾輪、直到LLM判斷任務完成為止的機制時，就構成 了下一課要介紹的AI Agent。可以先建立一個 直覺：Agent之所以看起來像會「自己想辦法完成任務」，底層 靠的正是這一課介紹的工具呼叫機制，而不是什麼全新的、 神秘的能力。

小提醒：不是所有模型都支援工具呼叫

工具呼叫需要模型在訓練階段就特別針對這種輸出格式做過 調校，不是每個LLM都支援。透過Ollama執行地端模型時， 需要挑選有標示支援工具呼叫（tools／function calling） 能力的模型——這點下一課實際設定n8n的AI Agent節點時會 再具體說明。
