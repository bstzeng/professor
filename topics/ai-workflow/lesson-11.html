用curl測試API：確認地端LLM真的能被呼叫

這一課的目標

  • 能寫出一個完整的curl指令，對Ollama的/api/generate端點發出請求
  • 認識請求JSON裡model、prompt、stream三個欄位各自的作用
  • 能讀懂回應JSON裡response欄位與其餘中繼資料欄位的意思

上一課說明了Ollama背後有一個HTTP伺服器在運作，這一課 要用最基本的工具——curl——親手驗證這件事。選curl的 原因很單純：它幾乎每台電腦的終端機都內建，不需要 另外寫程式，是驗證任何HTTP API最快的方式。之後要接 n8n之前，先用curl確認地端LLM真的「聽得懂」外部送 進來的HTTP請求，是一個很值得養成的習慣。

1. 準備動作

確保Ollama伺服器正在背景執行（Mac、Windows的Ollama 應用程式開著，或Linux上執行過ollama serve）， 並且已經用第6課教過的ollama pull拉取過 至少一個模型。可以先用第8課介紹過的指令，確認本機 目前有哪些可用的模型標籤：

ollama list

2. 發出第一個請求

接下來對本機的/api/generate端點發出一個 POST請求，把model與prompt 放進請求的JSON主體裡：

curl http://localhost:11434/api/generate -d '{ "model": "llama3.2", "prompt": "用一句話說明什麼是HTTP", "stream": false }'

curl 網址 -d '...'會用POST方法，把後面 的JSON字串當作請求主體送出去；model欄位 要填一個本機已經拉取過的模型標籤（跟ollama list列出來的名稱一致）；prompt 欄位放你要問模型的文字；stream設為 false，代表要模型把整段回答生成完畢後， 一次回傳一個完整的JSON物件——如果不加這個欄位， Ollama預設會用串流方式，每生成一小段文字就送出一行 JSON，這種方式很適合即時顯示逐字輸出的介面，但測試 階段先設為false比較好讀。

3. 讀懂回應

請求送出後，會拿到類似這樣的JSON回應：

{ "model": "llama3.2", "created_at": "2026-08-27T09:12:03.185Z", "response": "HTTP是一種讓瀏覽器與伺服器之間交換網頁內容的通訊協定。", "done": true, "total_duration": 3221345900, "eval_count": 24 }

response是真正要的答案文字； done: true代表這次生成已經完整結束； 其餘像total_duration（整個請求耗費的 奈秒數）、eval_count（生成了幾個token） 這類欄位屬於效能相關的中繼資料，日後要比較不同模型 的生成速度時會用到，現階段先知道它們存在就好。

4. 這證明了什麼

這個結果證明了一件很關鍵的事：地端的LLM，現在能被 「終端機以外」的東西呼叫了。curl只是一個示範——任何 能發出HTTP請求的程式，都能用一模一樣的方式跟這個 模型對話，包括之後要介紹的n8n。這正是模組D要開始 動手架設工作流平台之前，必須先確認的地基。

檢查你的理解

  1. 寫出一個呼叫/api/generate、使用本機已拉取模型、並要求一次回傳完整結果的curl指令
  2. 說明請求JSON裡model、prompt、stream三個欄位分別的作用
  3. 在回應JSON裡，哪一個欄位才是真正要的生成文字？
