System Prompt與User Prompt的分工

這一課的目標

  • 理解System Prompt與User Prompt各自該負責什麼內容，為什麼要分開設計
  • 針對客服信件分類任務，寫出一份完整、可重複使用的System Prompt
  • 寫出會套用第32課整理好欄位的User Prompt模板，並理解兩者在聊天模型節點裡怎麼分別設定

第28課建立聊天模型節點時提過，這個節點有現成的欄位 分工可以設定System Prompt跟User Prompt，但當時還沒 細講兩者該怎麼分工。這一課要把這件事講清楚，並且直接 寫出這個專案接下來會實際使用的完整版本。

1. System Prompt：定義角色、任務、輸出格式——每次都一樣

System Prompt（系統提示）負責告訴LLM「你是誰、你的 任務是什麼、我要你用什麼格式回答」。這部分內容的特徵 是：不管處理的是哪一封信，這段指示都應該維持 完全一致。它定義的是LLM在這個工作流裡扮演的 固定角色，而不是任何一次具體的輸入。

2. User Prompt：這次要處理的實際內容——每次都不同

User Prompt（使用者訊息）則負責帶入「這一次執行、這一 封信」實際的內容。它的角色比較像是每次呼叫LLM時遞交的 「這次的作業」，內容會隨著第32課Set節點整理出的 subject、body、sender 欄位而改變。

3. 完整範例：這個專案的System Prompt

以下是針對客服信件分類任務，寫出的一份完整System Prompt，定義了分類的四個類別、要擷取的欄位，以及明確 規定的輸出格式（這裡先用條列式文字描述格式，第35課會 再進一步把格式規定收斂成嚴格的JSON）：

// 聊天模型節點的System Prompt欄位 你是一個客服信件分類助手。你的任務是閱讀使用者提供的一封 客服信件，完成以下三件事： 1. 判斷這封信屬於以下四種類型的哪一種： - 詢問：單純提出問題，沒有明顯不滿情緒 - 客訴：對服務或商品表達不滿，或要求退款、賠償 - 意見回饋：對產品或服務提出建議，沒有要求處理 - 垃圾信：廣告、行銷信、與客服無關的內容 2. 用一句話（不超過30個字）摘要這封信的重點內容。 3. 依照以下格式回覆，不要加上其他說明文字： 類型：（四選一） 摘要：（一句話重點摘要）

這段文字寫進節點的System Prompt欄位之後，不管接下來 送進哪一封信，這份規則都原封不動地生效——這正是它跟 User Prompt最本質的差異。

4. 完整範例：套用整理過欄位的User Prompt模板

User Prompt則負責帶入這一次要處理的信件內容，用表達式 引用第32課Set節點整理好的欄位：

// 聊天模型節點的User Prompt欄位 以下是這次要處理的客服信件： 主旨：{{ $json.subject }} 內文：{{ $json.body }} 寄件人：{{ $json.sender }} 請依照你被交代的格式回覆分類結果。

對照第28課那個把所有內容混在一起、寫死給單一情境用的 版本，現在的Prompt已經清楚拆成兩層：System Prompt管 「規則」，User Prompt管「這次的資料」，兩者透過聊天 模型節點各自獨立的欄位分開設定，互不干擾。

為什麼要特別拆開，而不是全部寫在一起

把兩者混在同一段文字裡（就像第28課的第一版）也能跑， 但往後如果要調整分類標準（例如新增一個「合作邀約」 類別），得在一大段文字裡找到規則的部分小心修改，容易 不小心動到不該動的地方。拆開之後，調整分類規則只需要 動System Prompt，資料的引用方式改變只需要動User Prompt，兩件事互相獨立，也更容易個別測試與除錯。

檢查你的理解

  1. 說明System Prompt跟User Prompt在這個專案裡各自負責的內容
  2. 解釋為什麼System Prompt「每一封信都完全相同」是它的關鍵特徵
  3. 說明為什麼把兩者分開設計，比全部寫在同一段文字裡更容易維護
