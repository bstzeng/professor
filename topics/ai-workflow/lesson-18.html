模組 E｜n8n核心概念 · 第 18 課

節點之間的資料傳遞：JSON結構

這一課的目標

  • 理解n8n節點之間傳遞資料的基本格式：一個由item組成的陣列，每個item底下用json欄位包著實際資料
  • 能讀懂n8n編輯器裡顯示的資料結構，找到某個欄位實際的路徑
  • 理解一個節點在處理多筆item時，預設是怎麼逐筆執行的

模組D把n8n的編輯器、觸發器、空白工作流都建立起來了， 但一個工作流真正有用的地方，在於節點跟節點之間能傳遞 資料——前一個節點處理完的結果，會變成下一個節點的輸入。 模組E這四堂課要把這件事講清楚：資料在n8n裡到底長什麼 樣子、怎麼被讀取、又怎麼被分流跟整理。這一課先從最 基礎的資料格式開始。

1. n8n的資料格式：item陣列

n8n裡的每個節點，輸入跟輸出永遠是同一種結構：一個 陣列，陣列裡的每一個元素叫做一個 item。就算只有一筆資料，它也會被包在 一個只有一個元素的陣列裡；如果前一個節點抓回了十筆 資料（例如十封信件、十筆表單紀錄），輸出就會是一個 有十個item的陣列。每一個item底下，實際的欄位資料放在 一個叫做json的鍵裡面：

[ { "json": { "name": "Alice", "score": 90 } }, { "json": { "name": "Bob", "score": 76 } } ]

這個例子是一個有兩筆item的陣列，第一筆item的 json.name是"Alice"、 json.score是90；第二筆 item則是Bob的資料。之後不管是哪一種節點——不管是從 資料庫抓資料、呼叫Ollama的API、還是讀一個試算表—— 輸出到下一個節點的，都會是這種「item陣列，每個item 底下包一層json」的結構。

2. 為什麼每個item要多包一層json

剛接觸n8n的人常常會覺得奇怪：為什麼不能直接是 [{ "name": "Alice" }, { "name": "Bob" }]， 非要多包一層json？原因是item除了 json這個欄位資料的鍵之外，還可能帶著 另一個鍵：binary，用來放檔案（例如附件、 圖片）這類二進位資料。把「一般欄位資料」跟「二進位 檔案資料」分開放在json跟binary 這兩個獨立的鍵底下，讓n8n可以在同一個item上，同時 攜帶「這筆資料的欄位內容」跟「這筆資料附帶的檔案」， 而不會互相混在一起。這門課後面用到檔案的地方比較少， 但理解這個設計，能幫助你看懂n8n文件裡對item結構的 描述。

3. 一個節點預設怎麼處理多筆item

大部分節點的處理邏輯，預設是逐筆執行 ——輸入有幾筆item，節點的邏輯就針對每一筆item各跑一次， 然後把每一筆處理完的結果，各自輸出成一筆item。舉例來說， 如果一個節點的工作是「把每筆資料的分數乘以1.1」，輸入 是上面Alice跟Bob兩筆item，這個節點就會分別對Alice跟 Bob的score各做一次運算，輸出仍然是兩筆 item，只是score欄位的值變了。這個「輸入 幾筆、預設處理幾筆」的行為，是接下來要介紹的IF、Switch 這類分流節點，還有第22課要接上Ollama的AI節點，共同 遵守的基本規則。

檢查你的理解

  1. 寫出一個有兩筆item的陣列範例，每筆item底下的json要各帶一個自訂欄位
  2. 說明item底下除了json之外，還可能有哪個鍵，用途是什麼
  3. 解釋一個節點在輸入有五筆item時，預設會怎麼處理，輸出通常會有幾筆
