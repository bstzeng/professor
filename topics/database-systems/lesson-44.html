文件資料庫：MongoDB

這一課的目標

  • 理解文件模型
  • 比較嵌入與參照
  • 評估文件資料庫的適用場景

文件資料庫把一筆資料存成一個 JSON（MongoDB 內部是二進位的 BSON）文件，裡面可以有巢狀的物件與陣列：

{ "_id": 1001, "客戶": {"姓名": "王小明", "電話": "0912-345-678"}, "下單時間": "2026-10-30T10:15:00Z", "明細": [ {"品名": "手沖咖啡壺", "數量": 1, "單價": 1280}, {"品名": "濾紙", "數量": 3, "單價": 120} ], "狀態": "已出貨" }

嵌入 vs. 參照

嵌入（把相關資料放在同一個文件）參照（存另一個文件的 id）
讀取一次讀到全部，不用 JOIN要多次查詢或 $lookup
適合一起讀寫、一對少、屬於父物件的資料（訂單明細）一對很多、多對多、會被獨立更新的資料（商品、客戶）
風險文件無限長大（MongoDB 單一文件上限 16 MB）；資料重複效能類似關聯式 JOIN

優點與代價

  • 彈性綱要：不同文件可以有不同的欄位，新增欄位不需要 ALTER TABLE。
  • 與程式物件對應：一個文件就是程式中的一個物件，減少物件—關聯對應的麻煩。
  • 內建分片：設計之初就考慮水平擴展。
  • 代價：綱要的檢查從資料庫移到了應用程式；多對多關係與跨文件的查詢較不方便。MongoDB 從 4.0 版（2018 年）起支援多文件 ACID 交易。

綱要還是存在

「無綱要」其實是「讀取時才套用綱要」：程式讀資料時仍要假設欄位存在、型別正確。實務上許多團隊會用 JSON Schema 驗證文件。另一方面，PostgreSQL 的 JSONB 型別也讓關聯式資料庫能存放與索引文件。

🧭 這一課的重點

文件資料庫把資料存成可巢狀物件與陣列的 JSON（MongoDB 內部為 BSON）。嵌入把相關資料放在同一文件，一次讀取不需 JOIN，適合一起讀寫、一對少的資料，但文件可能無限長大（上限 16 MB）；參照存另一文件 id，適合一對很多、多對多與獨立更新的資料。優點是彈性綱要、與程式物件對應、內建分片，代價是綱要檢查移到應用程式、多對多與跨文件查詢不便；MongoDB 4.0（2018 年）起支援多文件交易。無綱要其實是讀取時套用綱要，PostgreSQL 的 JSONB 也能存放與索引文件。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
