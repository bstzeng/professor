頁、緩衝池與資料的實際排列

這一課的目標

  • 理解頁的結構
  • 理解緩衝池與替換策略
  • 用 Python 實作簡化的緩衝池

頁：讀寫的基本單位

資料庫不會一次只讀一筆資料，而是以頁為單位（PostgreSQL 8 KB、MySQL InnoDB 16 KB、SQLite 預設 4 KB）。一頁裡放了許多資料列。

頁的組成（簡化）說明
頁標頭頁的編號、剩餘空間、校驗碼、最後修改的日誌位置
槽目錄（slot directory）每一筆資料在頁內的位置；從前面往後長
資料列從後面往前長；中間是空白空間

這種「槽頁」設計讓資料列可以是不同長度，刪除與更新時只要改槽目錄。資料列的實體位置用（頁號, 槽號）表示，PostgreSQL 稱為 ctid。

緩衝池

緩衝池是記憶體中的一大塊區域，快取磁碟上的頁。資料庫要讀一頁時，先看緩衝池裡有沒有（命中），沒有才去讀磁碟。

  • 命中率：線上交易系統通常希望 99% 以上。
  • 髒頁：在記憶體中被修改過、還沒寫回磁碟的頁。由背景程序定期寫回（安全性靠日誌保證，第 34 課）。
  • 替換策略：緩衝池滿時要踢掉哪一頁？最常見的是 LRU（最久沒用的）及其變形——因為一次全表掃描就可能把所有熱資料擠出去，InnoDB 把 LRU 分成新、舊兩段，PostgreSQL 使用 clock-sweep 演算法。
from collections import OrderedDict class BufferPool: """簡化的 LRU 緩衝池""" def __init__(self, capacity, disk): self.cap, self.disk, self.pages = capacity, disk, OrderedDict() self.hits = self.misses = 0 def get(self, page_no): if page_no in self.pages: self.hits += 1 self.pages.move_to_end(page_no) # 最近用過的移到最後 else: self.misses += 1 if len(self.pages) >= self.cap: self.pages.popitem(last=False) # 踢掉最久沒用的（髒頁要先寫回） self.pages[page_no] = self.disk[page_no] # 從「磁碟」讀入 return self.pages[page_no] disk = {i: f"page-{i}" for i in range(1000)} bp = BufferPool(100, disk) for p in [1, 2, 3, 1, 2, 999, 1]: bp.get(p) print(bp.hits, bp.misses) # 3 4

🧭 這一課的重點

資料庫以頁為讀寫單位（PostgreSQL 8 KB、InnoDB 16 KB、SQLite 預設 4 KB），槽頁設計包含頁標頭、從前往後長的槽目錄與從後往前長的資料列，支援變長資料，資料位置以頁號與槽號表示。緩衝池在記憶體快取磁碟頁，線上系統希望命中率 99% 以上，髒頁由背景程序寫回、安全性靠日誌保證。替換策略以 LRU 及其變形為主，InnoDB 分新舊兩段、PostgreSQL 用 clock-sweep，以免全表掃描擠出熱資料。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
