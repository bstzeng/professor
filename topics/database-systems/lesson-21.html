複合索引、覆蓋索引與最左前綴

這一課的目標

  • 理解複合索引的排序方式
  • 掌握最左前綴原則
  • 理解覆蓋索引與索引的代價

複合索引

CREATE INDEX idx_訂單 ON 訂單 (客戶編號, 下單日期, 金額);

複合索引像電話簿：先依「客戶編號」排序，同一位客戶再依「下單日期」排序，再依「金額」排序。

最左前綴原則

查詢條件能用到這個索引嗎
客戶編號 = 42可以
客戶編號 = 42 AND 下單日期 >= '2026-01-01'可以，而且非常有效
下單日期 >= '2026-01-01'（沒有客戶編號）通常不行：就像只知道名字、不知道姓氏，電話簿幫不上忙
客戶編號 = 42 AND 金額 > 1000（跳過下單日期）只能用到客戶編號的部分
客戶編號 > 10 AND 下單日期 = '2026-01-01'只有客戶編號能有效縮小範圍（範圍條件之後的欄位幫助有限）

設計原則：等值條件的欄位放前面，範圍條件的欄位放後面；常一起出現的查詢條件，依選擇性與使用頻率排序。

覆蓋索引

如果查詢需要的所有欄位都在索引裡，資料庫只讀索引就能回答，不用再回到資料表（「回表」）：

SELECT 下單日期, 金額 FROM 訂單 WHERE 客戶編號 = 42; -- 三個欄位都在索引中：Index Only Scan

索引不是越多越好

  • 每一次 INSERT、UPDATE、DELETE，都要同步更新所有相關的索引，寫入變慢。
  • 索引佔用空間，也佔用緩衝池。
  • 最佳化器選擇變多，也可能選錯。
  • 原則：根據實際的查詢模式建索引，定期檢查沒被用到的索引並移除。

讓索引失效的常見寫法

  • 在索引欄位上套函數：WHERE YEAR(下單日期) = 2026（改成範圍條件，或建立函數索引）。
  • 隱含型別轉換：欄位是文字，條件卻寫成數字。
  • LIKE '%關鍵字'（開頭是萬用字元）。

🧭 這一課的重點

複合索引如電話簿依序排序多個欄位，遵守最左前綴原則：有第一欄條件才能有效使用，跳過中間欄位或範圍條件後的欄位幫助有限，因此等值條件欄位放前、範圍條件欄位放後。覆蓋索引包含查詢需要的所有欄位，可只讀索引不回表（Index Only Scan）。索引會拖慢寫入、佔空間與緩衝池並增加最佳化器誤判機會，應依查詢模式建立並移除未使用者。在索引欄位套函數、隱含型別轉換與開頭萬用字元的 LIKE 會讓索引失效。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
