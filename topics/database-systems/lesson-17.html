列式儲存 vs. 欄式儲存

這一課的目標

  • 理解列式與欄式儲存的差別
  • 理解欄式儲存為何適合分析
  • 理解壓縮與向量化執行

一張有 100 個欄位、十億筆資料的銷售表，資料在磁碟上可以怎麼排？

列式（row store）欄式（column store）
排法一筆資料的所有欄位放在一起同一個欄位的所有值放在一起
讀一筆完整的訂單一次讀到要從 100 個地方各讀一點
「每個月的營收總和」要讀全部 100 個欄位只讀「日期」與「金額」兩個欄位
適合OLTP：常常讀寫整筆資料OLAP：掃描大量資料的少數欄位
代表PostgreSQL、MySQLSnowflake、BigQuery、ClickHouse、DuckDB、Parquet 檔案

欄式儲存的三個優勢

  1. 只讀需要的欄位：分析查詢通常只用幾個欄位，I/O 可以少一到兩個數量級。
  2. 壓縮效果極好：同一欄的值型別相同、常常重複。例如「國家」欄只有幾十種值，可以用字典編碼；排序後的日期可以用差值編碼；連續相同的值可以用連續長度編碼。壓縮率常有 5～10 倍以上。
  3. 向量化執行：一次處理一整批（例如 1,024 個）同型別的值，充分利用 CPU 的 SIMD 指令與快取。
# 連續長度編碼（RLE）：欄式儲存中排序後的欄位非常適合 def rle(values): out, prev, n = [], None, 0 for v in values: if v == prev: n += 1 else: if prev is not None: out.append((prev, n)) prev, n = v, 1 out.append((prev, n)) return out country = ["台灣"] * 50000 + ["日本"] * 30000 + ["美國"] * 20000 print(rle(country)) # [('台灣', 50000), ('日本', 30000), ('美國', 20000)]：十萬個值只剩三組

混合式

有些資料庫同時支援兩種（HTAP），例如 TiDB 的 TiFlash、SQL Server 的欄式索引：交易寫進列式儲存，再非同步複製一份欄式副本給分析用。

🧭 這一課的重點

列式儲存把一筆資料的所有欄位放在一起，適合常讀寫整筆資料的 OLTP（PostgreSQL、MySQL）；欄式儲存把同一欄位的值放在一起，適合掃描大量資料少數欄位的 OLAP（Snowflake、BigQuery、ClickHouse、DuckDB、Parquet）。欄式三大優勢是只讀需要的欄位、壓縮效果極好（字典、差值、連續長度編碼，常 5～10 倍以上）與向量化執行充分利用 SIMD 與快取。HTAP 混合式如 TiFlash 與 SQL Server 欄式索引同時支援兩種。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
