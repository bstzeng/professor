模組 A｜導論 · 第 3 課

資料庫全景

這一課的目標

  • 認識主要的資料庫類型
  • 理解 OLTP 與 OLAP 的差別
  • 建立選型的初步框架

兩大工作負載

OLTP（交易處理）OLAP（分析處理）
典型操作下訂單、轉帳、更新會員資料「過去三年每個月、每個地區的營收」
每次存取少量資料列，很多次大量資料列，次數少
重點低延遲、高並行、正確性掃描速度、壓縮、平行運算
儲存方式列式儲存（第 17 課）欄式儲存
代表PostgreSQL、MySQL、OracleSnowflake、BigQuery、ClickHouse、DuckDB

資料庫的種類

類型資料模型擅長代表
關聯式資料表、SQL一般業務資料、交易PostgreSQL、MySQL、SQLite
鍵值鍵 → 值快取、工作階段Redis、DynamoDB
文件JSON 文件結構多變的資料MongoDB
寬欄列鍵＋大量欄位超大量寫入Cassandra、HBase
圖節點與邊關係與路徑Neo4j
時序時間戳記＋數值監控、物聯網、金融行情InfluxDB、TimescaleDB
向量高維向量語意搜尋、AI 的 RAGpgvector、Milvus、Pinecone
分散式 SQL資料表、SQL，跨多台機器全球規模的交易Spanner、CockroachDB、TiDB

這些類型的界線越來越模糊：PostgreSQL 有 JSON、全文檢索、向量（pgvector）擴充；MongoDB 支援交易；雲端資料倉儲也能處理半結構化資料。

一個常見的建議

如果不確定，先從 PostgreSQL 開始。它功能完整、穩定、開源，能處理絕大多數的需求；等到真的遇到它處理不了的規模或模式，再引入專門的資料庫（第 51 課）。

🧭 這一課的重點

工作負載分為 OLTP（下單、轉帳，少量資料多次存取，重低延遲高並行，列式儲存，如 PostgreSQL、MySQL）與 OLAP（大量資料分析，重掃描、壓縮、平行，欄式儲存，如 Snowflake、BigQuery、ClickHouse、DuckDB）。資料庫類型包括關聯式、鍵值（Redis）、文件（MongoDB）、寬欄（Cassandra）、圖（Neo4j）、時序、向量（pgvector、Milvus）與分散式 SQL（Spanner、CockroachDB、TiDB），界線日益模糊。不確定時先從 PostgreSQL 開始。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
