子查詢與 CTE

這一課的目標

  • 掌握子查詢的幾種用法
  • 理解相關子查詢
  • 使用 CTE 與遞迴 CTE

子查詢

-- 純量子查詢：成績高於全體平均的選課 SELECT * FROM 選課 WHERE 成績 > (SELECT AVG(成績) FROM 選課); -- EXISTS：至少選了一門資料庫課的學生 SELECT 姓名 FROM 學生 s WHERE EXISTS (SELECT 1 FROM 選課 e WHERE e.學號 = s.學號 AND e.課程 = '資料庫');

第二個例子是相關子查詢：子查詢裡引用了外層的 s.學號。概念上每一位學生都要執行一次子查詢；但現代的最佳化器通常會把它改寫成「半連接」，效率和 JOIN 差不多。

CTE：WITH 子句

WITH 系所平均 AS ( SELECT s.系所, AVG(e.成績) AS 平均 FROM 學生 s JOIN 選課 e ON s.學號 = e.學號 GROUP BY s.系所 ) SELECT s.姓名, e.成績, a.平均 FROM 學生 s JOIN 選課 e ON s.學號 = e.學號 JOIN 系所平均 a ON s.系所 = a.系所 WHERE e.成績 > a.平均; -- 成績高於自己系所平均的人

CTE 讓複雜的查詢像寫程式一樣，一步一步命名每個中間結果，可讀性大幅提升。

遞迴 CTE：走訪樹與圖

-- 員工(編號, 姓名, 主管編號)：找出某位主管底下的所有人（不論幾層） WITH RECURSIVE 部屬 AS ( SELECT 編號, 姓名, 1 AS 層級 FROM 員工 WHERE 主管編號 = 1 UNION ALL SELECT e.編號, e.姓名, d.層級 + 1 FROM 員工 e JOIN 部屬 d ON e.主管編號 = d.編號 ) SELECT * FROM 部屬;

🧭 這一課的重點

子查詢包括純量子查詢（如成績高於平均）與 EXISTS 子查詢；引用外層欄位的相關子查詢概念上逐列執行，但最佳化器常改寫成半連接。CTE 以 WITH 子句命名中間結果，使複雜查詢像程式一樣逐步可讀，例如先算系所平均再找高於平均者。遞迴 CTE（WITH RECURSIVE）以起始查詢加 UNION ALL 遞迴部分，可走訪樹與圖，例如找出某主管底下所有層級的部屬。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
