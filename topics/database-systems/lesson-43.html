鍵值資料庫與快取：Redis

這一課的目標

  • 理解鍵值模型
  • 認識 Redis 的資料結構與用途
  • 理解快取策略與失效問題

鍵值資料庫只有兩個操作：GET(key) 與 PUT(key, value)。沒有 JOIN、沒有複雜查詢，換來的是極致的速度與擴展性。

Redis

Redis（2009 年）把所有資料放在記憶體裡，一次操作通常在一毫秒以內。它不只是鍵值，還提供多種資料結構：

結構用途
字串快取、計數器（INCR 是原子操作）
雜湊存放物件的欄位（使用者資料）
串列訊息佇列
集合、有序集合排行榜（依分數排序）、標籤
串流（Stream）事件紀錄、訊息佇列
HyperLogLog用極少的記憶體估計相異值數量（例如每日不重複訪客）

快取策略

import json def get_user(user_id, cache, db): """Cache-aside：先查快取，沒有再查資料庫並寫入快取""" key = f"user:{user_id}" if (hit := cache.get(key)) is not None: return json.loads(hit) user = db.query_one("SELECT * FROM 使用者 WHERE id = ?", user_id) cache.set(key, json.dumps(user), ex=300) # 5 分鐘後過期 return user def update_user(user_id, fields, cache, db): db.update(user_id, fields) cache.delete(f"user:{user_id}") # 更新資料庫後「刪除」快取，而不是更新它

快取的難題

  • 失效：資料更新了，快取裡的舊資料怎麼辦？常見做法是更新資料庫後刪除快取，並設定過期時間作為保險。電腦科學有句名言：「只有兩件難事：快取失效與命名。」
  • 快取擊穿：一個熱門的鍵過期瞬間，大量請求同時打到資料庫。解法：加鎖讓只有一個請求去重建，或提前更新。
  • 快取雪崩：大量鍵在同一時間過期。解法：過期時間加上隨機值。

持久性

Redis 可以用快照（RDB）或附加日誌（AOF）把資料寫到磁碟，但它的設計重點是速度；需要強持久性的資料，主要存放處仍應是資料庫。

🧭 這一課的重點

鍵值資料庫只有 GET 與 PUT，沒有 JOIN 與複雜查詢，換取極致速度與擴展性。2009 年的 Redis 把資料放在記憶體，一次操作通常一毫秒內，提供字串（快取、原子計數器）、雜湊、串列（佇列）、集合與有序集合（排行榜）、串流與 HyperLogLog（估計相異值）。Cache-aside 策略先查快取再查資料庫並寫入快取，更新後刪除快取。快取難題包括失效、熱門鍵過期造成的擊穿（加鎖或提前更新）與大量鍵同時過期的雪崩（隨機過期時間）。Redis 可用 RDB 或 AOF 持久化，但強持久資料仍應存在資料庫。
