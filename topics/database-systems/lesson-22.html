全文索引與倒排索引

這一課的目標

  • 理解倒排索引的結構
  • 理解中文斷詞的挑戰
  • 認識相關性排序

B+ 樹適合「整個值」或「前綴」的查詢。但要找「內容包含『資料庫』這個詞的所有文章」，就需要倒排索引。

結構

正排：文章 → 包含哪些詞。倒排：詞 → 出現在哪些文章（以及位置）。

import re from collections import defaultdict docs = {1: "資料庫 索引 原理", 2: "倒排 索引 是 搜尋引擎 的 核心", 3: "資料庫 交易 與 日誌"} index = defaultdict(set) for doc_id, text in docs.items(): for term in text.split(): # 實務上需要斷詞、正規化、去除停用字 index[term].add(doc_id) def search(*terms): # AND 查詢 = 取交集 sets = [index.get(t, set()) for t in terms] return set.intersection(*sets) if sets else set() print(search("索引")) # {1, 2} print(search("資料庫", "索引")) # {1}

中文的挑戰：斷詞

  • 英文用空白分隔單字，中文沒有。「台北市長」可以是「台北／市長」或「台北市／長」。
  • 做法：用斷詞工具（例如 jieba、CKIP）依詞典與統計模型切詞；或用 n-gram（把文字切成每 2 個字一組：台北、北市、市長），不需要詞典但索引較大。
  • PostgreSQL 的全文檢索需要搭配中文斷詞擴充；Elasticsearch 也有對應的中文分析器。

相關性排序

找到所有包含關鍵字的文件後，要決定哪些排前面。經典的方法是 TF-IDF 與其改良 BM25：

\[\text{tfidf}(t,d) = \text{tf}(t,d) \times \log\frac{N}{\text{df}(t)}\]
  • 詞在這篇文章出現越多次（tf），越相關。
  • 詞在越少文章出現（df 小），越有鑑別力——「的」出現在每篇文章，幾乎沒有價值。

從關鍵字到語意

倒排索引只能比對「相同的詞」。搜尋「汽車」找不到只寫「轎車」的文章——這是向量搜尋要解決的問題（第 48 課）。現代搜尋系統常把兩者結合，稱為混合搜尋。

🧭 這一課的重點

倒排索引把詞對應到出現的文件與位置，AND 查詢即取交集，是搜尋引擎的核心。中文沒有空白分隔，需要以 jieba、CKIP 等工具依詞典與統計模型斷詞，或用 n-gram 切分（不需詞典但索引較大），PostgreSQL 與 Elasticsearch 都需中文分析擴充。相關性排序以 TF-IDF 與其改良 BM25 為經典：詞在文中出現越多越相關、出現的文件越少越有鑑別力。倒排索引只能比對相同詞，語意比對需要向量搜尋，現代系統常用混合搜尋。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
