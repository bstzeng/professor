模組 B｜關聯模型與 SQL · 第 7 課

SQL 基礎：SELECT、WHERE、ORDER BY

這一課的目標

  • 掌握 SELECT 的基本語法
  • 理解 SQL 的邏輯執行順序
  • 理解 NULL 的三值邏輯

SQL 起源於 1970 年代 IBM 的 System R 計畫（最初叫 SEQUEL），1979 年 Oracle 推出第一個商業化的 SQL 資料庫。它是宣告式語言：你描述想要的結果，資料庫決定怎麼取得。

SELECT 姓名, 系所 FROM 學生 WHERE 系所 IN ('資工', '電機') AND 姓名 LIKE '林%' ORDER BY 系所, 姓名 DESC LIMIT 10;

邏輯執行順序

SQL 的寫法順序和「邏輯上」的執行順序不同。理解這個順序，就能避開很多錯誤（例如為什麼 WHERE 不能用 SELECT 裡取的別名）：

  1. FROM／JOIN：決定資料來源
  2. WHERE：過濾資料列
  3. GROUP BY：分組
  4. HAVING：過濾分組
  5. SELECT：計算輸出欄位
  6. ORDER BY：排序
  7. LIMIT：取前幾筆

NULL：三值邏輯

NULL 代表「未知」或「不適用」，不是 0，也不是空字串。任何和 NULL 的比較，結果都是 UNKNOWN（第三種真假值）：

  • NULL = NULL 的結果是 UNKNOWN，不是 TRUE。所以要用 IS NULL。
  • WHERE 只保留結果為 TRUE 的列，UNKNOWN 會被濾掉。
  • NOT IN 的陷阱：如果子查詢結果中有 NULL，x NOT IN (…) 永遠不會是 TRUE，整個查詢可能回傳 0 筆。
import sqlite3 db = sqlite3.connect(":memory:") db.executescript(''' CREATE TABLE 學生 (學號 INTEGER PRIMARY KEY, 姓名 TEXT, 系所 TEXT); INSERT INTO 學生 VALUES (1,'王小明','資工'), (2,'林小華','電機'), (3,'陳大文',NULL); ''') print(db.execute("SELECT 姓名 FROM 學生 WHERE 系所 = NULL").fetchall()) # [] 永遠找不到 print(db.execute("SELECT 姓名 FROM 學生 WHERE 系所 IS NULL").fetchall()) # [('陳大文',)]

🧭 這一課的重點

SQL 起源於 1970 年代 IBM System R（最初稱 SEQUEL），1979 年 Oracle 推出第一個商業 SQL 資料庫，是宣告式語言。SELECT 搭配 WHERE、IN、LIKE、ORDER BY、LIMIT 使用。邏輯執行順序為 FROM／JOIN、WHERE、GROUP BY、HAVING、SELECT、ORDER BY、LIMIT，因此 WHERE 不能用 SELECT 的別名。NULL 代表未知，與之比較結果為 UNKNOWN，須用 IS NULL；WHERE 只保留 TRUE；子查詢含 NULL 時 NOT IN 可能永遠不成立。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
