正規化：1NF 到 BCNF

這一課的目標

  • 理解資料重複帶來的異常
  • 理解函數相依
  • 掌握 1NF、2NF、3NF、BCNF

為什麼要正規化

看這張表：(學號, 姓名, 系所, 系主任, 課程, 成績)。系主任的名字在每一位該系學生的每一筆選課中都重複一次。這會造成三種異常：

  • 更新異常：換系主任時，要改上千筆，漏改一筆就不一致。
  • 插入異常：新成立的系還沒有學生，就無法記錄它的系主任。
  • 刪除異常：某系最後一位學生退學，系主任的資訊也跟著消失。

函數相依

\[X \rightarrow Y\]

「知道 X 就能唯一決定 Y」。例如 學號 → 姓名、系所 → 系主任、(學號, 課程) → 成績。正規化就是根據函數相依，把表拆開。

正規形式要求違反的例子
1NF每個欄位都是單一值（不可再分）「電話」欄位存「0912…, 0223…」兩支電話
2NF1NF，且非鍵欄位要相依於整個主鍵主鍵 (學號, 課程)，但 姓名 只相依於學號
3NF2NF，且非鍵欄位不能透過其他非鍵欄位間接相依於主鍵學號 → 系所 → 系主任（遞移相依）
BCNF每一個決定因子都必須是候選鍵3NF 的少數特殊情況

拆成：學生(學號, 姓名, 系所)、系所(系所, 系主任)、選課(學號, 課程, 成績)，每一件事都只記一次。

什麼時候反正規化

  • 讀取遠多於寫入，而且 Join 很昂貴時（例如報表、資料倉儲的星狀綱要）。
  • 需要歷史快照時（上一課的成交單價）。
  • 反正規化是有意識的取捨：用寫入的複雜度與重複，換取讀取的速度。

🧭 這一課的重點

未正規化的表會造成更新異常、插入異常與刪除異常。函數相依 X → Y 表示知道 X 即可唯一決定 Y，正規化據此拆表：1NF 要求欄位單一值，2NF 要求非鍵欄位相依於整個主鍵，3NF 不允許透過非鍵欄位的遞移相依，BCNF 要求每個決定因子都是候選鍵。例如拆成學生、系所、選課三表。讀多寫少且 Join 昂貴（報表、星狀綱要）或需要歷史快照時，可有意識地反正規化。
