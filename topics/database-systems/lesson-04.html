關聯模型：資料表、主鍵與外鍵

這一課的目標

  • 理解關聯模型的基本元素
  • 理解主鍵與外鍵
  • 理解參照完整性

1970 年，IBM 的柯德（Edgar Codd）發表論文〈大型共享資料庫的關聯模型〉，提出用數學上的關聯（集合）來表示資料。他因此在 1981 年獲得圖靈獎。

基本元素

數學名詞日常名詞例子
關聯（relation）資料表學生
值組（tuple）資料列(1, 王小明, 資工)
屬性（attribute）欄位姓名
定義域（domain）型別整數、文字、日期

鍵

  • 主鍵：唯一識別每一列的欄位（或欄位組合），不能重複、不能是 NULL。例如學號。
  • 外鍵：指向另一個表主鍵的欄位，用來表示關係。例如選課表的「學號」指向學生表。
  • 候選鍵：所有可以當主鍵的選擇（例如學號、身分證字號）。
  • 自然鍵 vs. 代理鍵：用真實世界的值（身分證字號）還是系統產生的流水號？實務上多用代理鍵，因為真實世界的值可能改變。
CREATE TABLE 學生 ( 學號 INTEGER PRIMARY KEY, 姓名 TEXT NOT NULL, 系所 TEXT ); CREATE TABLE 選課 ( 學號 INTEGER REFERENCES 學生(學號), -- 外鍵 課程 TEXT, 成績 INTEGER CHECK (成績 BETWEEN 0 AND 100), PRIMARY KEY (學號, 課程) -- 複合主鍵：同一人不能重複選同一門課 );

參照完整性

外鍵保證：選課表裡的每一個學號，都必須存在於學生表中。如果要刪除一位學生，資料庫會拒絕（RESTRICT），或連同他的選課紀錄一起刪除（CASCADE），或把外鍵設為 NULL（SET NULL）——由設計者決定。

為什麼關聯模型能勝出

之前的階層式與網狀資料庫，程式必須知道資料怎麼串在一起，結構一改程式就要重寫。關聯模型只描述資料「是什麼」，查詢「要什麼」，至於「怎麼找」交給資料庫——這就是第 1 課說的資料獨立性。

🧭 這一課的重點

1970 年 IBM 的柯德提出以數學關聯（集合）表示資料的關聯模型，1981 年獲圖靈獎。關聯即資料表、值組即資料列、屬性即欄位、定義域即型別。主鍵唯一識別每列且不可為 NULL，外鍵指向另一表的主鍵以表示關係，候選鍵是所有可當主鍵者，實務上多用代理鍵。外鍵保證參照完整性，刪除時可設定 RESTRICT、CASCADE 或 SET NULL。關聯模型只描述資料是什麼、查詢要什麼，怎麼找交給資料庫，因而勝過階層式與網狀資料庫。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
