統計資訊與成本估計

這一課的目標

  • 理解選擇性與基數估計
  • 認識直方圖與常見值
  • 理解估計錯誤的後果

最佳化器要選計畫，必須先估計每一步會產生多少資料列（基數）。它依賴資料庫定期收集的統計資訊（PostgreSQL 的 ANALYZE、MySQL 的 ANALYZE TABLE）。

統計資訊包括

  • 表的總筆數、總頁數。
  • 每個欄位的相異值數量、NULL 的比例。
  • 最常見值（MCV）與它們的頻率。
  • 直方圖：把值的範圍切成多個桶，每桶的筆數大致相同。

選擇性估計

\[\text{sel}(A = c) \approx \frac{1}{\text{ndistinct}(A)} \qquad \text{sel}(A \lt c) \approx \frac{c - \min}{\max - \min}\]
\[\text{sel}(p_1 \wedge p_2) \approx \text{sel}(p_1) \times \text{sel}(p_2) \quad \text{(independence)}\]

獨立性假設的陷阱

「縣市 = 台北市」選擇性 10%，「郵遞區號 = 100」選擇性 0.5%。最佳化器假設兩者獨立，估計同時成立的比例是 0.05%；但實際上郵遞區號 100 一定在台北市，真實比例是 0.5%——低估了 10 倍。

  • 低估 → 以為結果很少 → 選了巢狀迴圈 → 實際上要跑幾百萬次，查詢慢了上千倍。
  • 解法：PostgreSQL 的「延伸統計」（CREATE STATISTICS）可以記錄欄位之間的相依；或改寫查詢、使用提示。
# 用等深直方圖估計範圍條件的選擇性 import bisect, random values = sorted(random.gauss(50, 15) for _ in range(100_000)) buckets = 20 bounds = [values[i * len(values) // buckets] for i in range(buckets)] + [values[-1]] def est_less_than(c): i = bisect.bisect_right(bounds, c) - 1 # 落在第 i 個桶 if i < 0: return 0.0 if i >= buckets: return 1.0 lo, hi = bounds[i], bounds[i + 1] frac = (c - lo) / (hi - lo) if hi > lo else 0 # 桶內假設均勻分布 return (i + frac) / buckets real = sum(v < 30 for v in values) / len(values) print(f"估計 {est_less_than(30):.3f}，實際 {real:.3f}")

🧭 這一課的重點

最佳化器依 ANALYZE 收集的統計資訊估計每步產生的資料列數（基數），統計包括總筆數與頁數、欄位相異值數與 NULL 比例、最常見值 MCV 與頻率，以及每桶筆數相近的直方圖。等值選擇性約為 1/相異值數，範圍條件依值域比例估計，多條件假設獨立而相乘。獨立性假設在相關欄位（如縣市與郵遞區號）會低估 10 倍，導致錯選巢狀迴圈而慢上千倍，可用 PostgreSQL 延伸統計 CREATE STATISTICS、改寫查詢或提示解決。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
