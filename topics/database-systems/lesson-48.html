向量資料庫：AI 與 RAG 的基礎

這一課的目標

  • 理解向量嵌入與相似度
  • 理解近似最近鄰搜尋與 HNSW
  • 理解向量資料庫在 RAG 中的角色

向量嵌入

AI 模型可以把一段文字、一張圖片轉成一個高維向量（例如 768 或 1,536 維），意思相近的內容，向量也相近。「汽車」和「轎車」的向量很接近，即使字面完全不同。

\[\cos(\mathbf{a}, \mathbf{b}) = \frac{\mathbf{a} \cdot \mathbf{b}}{\lVert \mathbf{a} \rVert\, \lVert \mathbf{b} \rVert}\]

問題：怎麼在一億個向量中快速找到最接近的

暴力法要和每一個向量計算一次相似度——一億次。傳統的 B+ 樹在高維空間中失效（維度詛咒）。解法是近似最近鄰（ANN）：犧牲一點準確度（例如找到 95% 的真正最近鄰），換取快上千倍的速度。

方法原理
HNSW（階層式可導航小世界圖）把向量連成多層的圖，上層稀疏、下層稠密；從上層快速跳到大致區域，再往下層精細搜尋。目前最常用
IVF（倒排檔案）先用分群把向量分成很多群，查詢時只搜尋最近的幾群
乘積量化（PQ）把向量壓縮成很短的編碼，大幅減少記憶體
import numpy as np docs = ["資料庫索引的原理", "B+ 樹與磁碟 I/O", "今天天氣很好", "交易與隔離等級"] emb = np.random.default_rng(0).normal(size=(len(docs), 384)) # 實務上由嵌入模型產生 emb /= np.linalg.norm(emb, axis=1, keepdims=True) # 正規化後，內積 = 餘弦相似度 def search(query_vec, k=2): scores = emb @ (query_vec / np.linalg.norm(query_vec)) # 暴力法：和每一個向量比 top = np.argsort(-scores)[:k] return [(docs[i], float(scores[i])) for i in top]

RAG：檢索增強生成

  1. 把公司文件切成段落，每段轉成向量存進向量資料庫。
  2. 使用者提問時，把問題也轉成向量，找出最相關的幾段。
  3. 把這幾段和問題一起交給大型語言模型，讓它根據資料回答。
產品類型
pgvectorPostgreSQL 擴充：向量與一般資料放在同一個資料庫
Milvus、Qdrant、Weaviate開源的專用向量資料庫
Pinecone雲端託管服務
Elasticsearch、OpenSearch全文檢索加上向量，方便做混合搜尋

🧭 這一課的重點

AI 模型可把文字或圖片轉成數百到上千維的向量，意思相近則向量相近，以餘弦相似度衡量。暴力搜尋要比較每個向量，B+ 樹在高維失效，因此用近似最近鄰 ANN 犧牲些許準確度換取快上千倍：最常用的 HNSW 以多層圖從稀疏上層跳到大致區域再往下精細搜尋，IVF 先分群再搜尋最近幾群，乘積量化壓縮向量節省記憶體。RAG 把文件段落轉成向量存入資料庫，提問時找出最相關段落交給語言模型回答。產品有 pgvector、Milvus、Qdrant、Weaviate、Pinecone 與 Elasticsearch。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
