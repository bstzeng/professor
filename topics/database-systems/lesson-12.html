DDL 與約束：讓資料庫幫你守規則

這一課的目標

  • 掌握建立與修改資料表
  • 理解各種約束的作用
  • 理解線上修改綱要的挑戰
CREATE TABLE 帳戶 ( 帳號 BIGINT PRIMARY KEY, 戶名 TEXT NOT NULL, 身分證 CHAR(10) UNIQUE, 餘額 NUMERIC(14,2) NOT NULL DEFAULT 0 CHECK (餘額 >= 0), 幣別 CHAR(3) NOT NULL DEFAULT 'TWD', 開戶時間 TIMESTAMPTZ NOT NULL DEFAULT now() ); ALTER TABLE 帳戶 ADD COLUMN 狀態 TEXT NOT NULL DEFAULT '正常';

選對型別

  • 金額用 NUMERIC（十進位），不要用 FLOAT：浮點數無法精確表示 0.1，累加後會出現分毫誤差。
  • 時間盡量用帶時區的型別，存 UTC。
  • 文字長度不確定時用 TEXT（PostgreSQL 中 TEXT 與 VARCHAR 效能相同）。

約束是最後一道防線

約束保證
NOT NULL一定要有值
UNIQUE不能重複（資料庫會自動建立索引）
CHECK符合條件，例如餘額不能是負數
FOREIGN KEY參照的資料一定存在
EXCLUDE（PostgreSQL）例如同一間會議室的預約時段不能重疊

應用程式也會檢查這些規則，但程式有 bug、有多個服務同時寫入、有人直接在資料庫下指令……只有資料庫的約束能保證「無論如何都成立」。

線上修改綱要

在一個一億筆、持續被寫入的大表上 ALTER TABLE，可能會鎖住整個表好幾個小時。實務上的做法：

  • 新增可為 NULL 或有預設值的欄位，現代資料庫多半能瞬間完成（只改中繼資料）。
  • 建索引用 CREATE INDEX CONCURRENTLY（PostgreSQL）。
  • 大改動用工具（例如 gh-ost、pt-online-schema-change）建一個新表、背景複製資料、最後切換。

🧭 這一課的重點

DDL 以 CREATE TABLE 與 ALTER TABLE 建立與修改資料表。選型時金額應用 NUMERIC 而非無法精確表示 0.1 的 FLOAT，時間用帶時區型別存 UTC。約束包括 NOT NULL、UNIQUE（自動建索引）、CHECK（如餘額不能為負）、FOREIGN KEY 與 PostgreSQL 的 EXCLUDE（如時段不重疊），是無論程式如何都成立的最後防線。在大表上線上修改綱要可能長時間鎖表，可利用只改中繼資料的新增欄位、CREATE INDEX CONCURRENTLY，或 gh-ost 等工具背景複製後切換。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
