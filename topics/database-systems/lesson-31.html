鎖與兩階段鎖定

這一課的目標

  • 理解共享鎖與排他鎖
  • 理解兩階段鎖定的規則

兩種鎖

共享鎖（S，讀）排他鎖（X，寫）
已有 S相容：可以多人同時讀衝突：要等
已有 X衝突：要等衝突：要等

兩階段鎖定（2PL）

每個交易分成兩個階段：

  1. 成長階段：只能取得鎖，不能釋放。
  2. 收縮階段：一旦釋放了任何一個鎖，就不能再取得新的鎖。

可以證明：只要所有交易都遵守 2PL，執行結果一定是可序列化的。實務上用的是嚴格兩階段鎖定：所有排他鎖都持有到交易提交或中止才釋放，避免別人讀到未提交的資料（以及連鎖中止）。

import threading from collections import defaultdict class LockManager: """簡化的鎖管理器：S／X 鎖，等待時阻塞""" def __init__(self): self.cv = threading.Condition() self.shared = defaultdict(set) # 資源 -> 持有共享鎖的交易 self.excl = {} # 資源 -> 持有排他鎖的交易 def lock_s(self, tx, res): with self.cv: while res in self.excl and self.excl[res] != tx: self.cv.wait() self.shared[res].add(tx) def lock_x(self, tx, res): with self.cv: while (res in self.excl and self.excl[res] != tx) or (self.shared[res] - {tx}): self.cv.wait() self.excl[res] = tx def release_all(self, tx): # 嚴格 2PL：提交時一次釋放 with self.cv: for r in list(self.excl): if self.excl[r] == tx: del self.excl[r] for s in self.shared.values(): s.discard(tx) self.cv.notify_all()

鎖的粒度

  • 資料列鎖：並行度高，但鎖的數量多、管理成本高。
  • 頁鎖、表鎖：管理簡單，但並行度低。
  • 意向鎖：要鎖一列之前，先在表上放一個「意向排他鎖」，讓想鎖整個表的人不必檢查每一列。
  • 間隙鎖（InnoDB）：鎖住索引中兩個值之間的「空隙」，防止別人插入新資料（防止幻讀）。

🧭 這一課的重點

共享鎖（讀）彼此相容，排他鎖（寫）與任何鎖衝突。兩階段鎖定 2PL 分為只能取得鎖的成長階段與釋放後不能再取得的收縮階段，所有交易遵守 2PL 即可保證可序列化；實務用嚴格 2PL，排他鎖持有到提交或中止，避免讀到未提交資料與連鎖中止。鎖管理器可用條件變數實作。鎖粒度有並行度高的資料列鎖、管理簡單的頁鎖表鎖，以及意向鎖與 InnoDB 防幻讀的間隙鎖。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
