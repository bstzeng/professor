模組 A｜導論 · 第 2 課

資料庫系統的架構

這一課的目標

  • 認識資料庫的分層架構
  • 理解各元件的分工
  • 知道後續課程對應到哪一層

一個關聯式資料庫（例如 PostgreSQL、MySQL）內部大致分成幾層：

層元件做什麼課程
介面連線管理、SQL 解析接收 SQL，檢查語法，轉成內部的樹狀結構第 23 課
查詢處理改寫、最佳化器、執行器決定怎麼執行（用哪個索引、哪種 Join），然後執行模組 D
存取方法資料表、索引（B+ 樹、雜湊）找到需要的資料列第 17～22 課
緩衝管理緩衝池（buffer pool）把常用的磁碟頁快取在記憶體第 16 課
交易管理鎖管理、MVCC、日誌確保並行正確與當機復原模組 E
儲存檔案、頁資料在磁碟上的實際格式第 15、16 課

一次查詢的旅程

  1. 應用程式送出 SELECT * FROM 訂單 WHERE 客戶 = 42。
  2. 解析器檢查語法，轉成語法樹。
  3. 最佳化器估計：訂單有一千萬筆，客戶 42 大約有 30 筆，用「客戶」索引比較快。
  4. 執行器用索引找到 30 筆資料的位置。
  5. 緩衝池檢查這些頁是否已在記憶體；不在就從磁碟讀進來。
  6. 結果回傳給應用程式。

三種部署方式

  • 主從式伺服器：PostgreSQL、MySQL、Oracle、SQL Server——資料庫是一個獨立的程式，應用程式透過網路連線。
  • 嵌入式：SQLite、DuckDB——資料庫就是應用程式裡的一個函式庫，資料存在一個檔案裡。SQLite 存在於幾乎每一支手機與每一個瀏覽器中，是全世界部署數量最多的資料庫。
  • 雲端託管：Amazon RDS／Aurora、Google Cloud SQL、Azure SQL——由雲端業者負責維運。

🧭 這一課的重點

關聯式資料庫分為介面（連線與 SQL 解析）、查詢處理（改寫、最佳化器、執行器）、存取方法（資料表與 B+ 樹、雜湊索引）、緩衝管理（緩衝池）、交易管理（鎖、MVCC、日誌）與儲存（檔案與頁）。一次查詢經過解析、最佳化器估計並選擇索引、執行器找資料、緩衝池讀頁、回傳結果。部署方式有主從式伺服器（PostgreSQL、MySQL）、嵌入式（SQLite、DuckDB，SQLite 是部署數量最多的資料庫）與雲端託管。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
