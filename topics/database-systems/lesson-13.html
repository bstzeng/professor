檢視、預存程序與觸發器

這一課的目標

  • 理解檢視與實體化檢視
  • 認識預存程序與觸發器
  • 評估邏輯放在資料庫的取捨

檢視（View）

CREATE VIEW 資工系成績 AS SELECT s.姓名, e.課程, e.成績 FROM 學生 s JOIN 選課 e ON s.學號 = e.學號 WHERE s.系所 = '資工'; SELECT * FROM 資工系成績 WHERE 成績 >= 90; -- 像查一般的表一樣
  • 檢視是一個「存起來的查詢」，不存資料；查詢時展開成原本的 SQL。
  • 用途：簡化複雜查詢、限制權限（只讓某些人看到部分欄位）。

實體化檢視

把查詢結果真的存起來，查詢時直接讀取，速度很快；但資料不會自動更新，需要定期 REFRESH。適合計算昂貴、可以接受稍微過時的報表。

預存程序與觸發器

做什麼例子
預存程序／函數把一段邏輯（包含多個 SQL 與流程控制）存在資料庫裡執行轉帳：檢查餘額、扣款、入帳、寫紀錄
觸發器在 INSERT／UPDATE／DELETE 時自動執行每次修改帳戶都自動寫一筆稽核紀錄

取捨

好處代價
減少應用程式與資料庫之間的往返，效能好邏輯分散在兩個地方，難以維護、測試與版本控制
規則集中，所有應用程式都會遵守觸發器的副作用不容易被看見，除錯困難
適合資料密集、需要強一致的操作綁定特定資料庫產品，難以遷移

現代的常見做法是：資料完整性（約束）放在資料庫，業務邏輯放在應用程式，只有效能關鍵或稽核需求才使用預存程序與觸發器。

🧭 這一課的重點

檢視是存起來的查詢、不存資料，可簡化查詢與限制權限；實體化檢視把結果存起來、查詢快但需定期 REFRESH。預存程序把含流程控制的邏輯存在資料庫執行（如轉帳），觸發器在增刪改時自動執行（如寫稽核紀錄）。好處是減少往返、規則集中、適合資料密集與強一致操作；代價是邏輯分散難維護測試、觸發器副作用不易察覺、綁定特定產品。常見做法是完整性約束放資料庫、業務邏輯放應用程式。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
