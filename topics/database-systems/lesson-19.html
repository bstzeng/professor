雜湊索引

這一課的目標

  • 理解雜湊索引的原理
  • 理解擴充雜湊與線性雜湊
  • 知道雜湊索引的適用場景

雜湊索引用雜湊函數把鍵直接對應到「桶」（bucket），等值查找平均只需要一次存取：

\[\text{bucket} = h(\text{key}) \bmod B\]

問題：桶滿了怎麼辦

  • 靜態雜湊：桶的數量固定，資料增加後溢出鏈越來越長，效能下降；要擴大就得全部重新雜湊。
  • 擴充雜湊（extendible hashing）：用一個目錄指向桶，桶滿了只分裂那一個桶，目錄需要時倍增。
  • 線性雜湊（linear hashing）：依序逐一分裂桶，不需要目錄，擴充過程平滑。

雜湊 vs. B+ 樹

雜湊索引B+ 樹
等值查找（WHERE id = 5）非常快快
範圍查詢（BETWEEN、>、<）不支援支援
排序（ORDER BY）不支援支援
前綴查詢（LIKE 'abc%'）不支援支援

所以 B+ 樹是預設的索引。雜湊索引用在：記憶體中的資料結構（例如 Redis 的雜湊表、資料庫內部的雜湊連接與雜湊聚合）、只需要等值查找的場合。PostgreSQL 提供雜湊索引，MySQL InnoDB 有「自適應雜湊索引」——自動為常被查詢的 B+ 樹頁建立雜湊捷徑。

class ExtendibleHash: """簡化的擴充雜湊：桶容量 cap；目錄大小 2^global_depth""" def __init__(self, cap=2): self.cap, self.gd = cap, 1 b0, b1 = {"ld": 1, "items": {}}, {"ld": 1, "items": {}} self.dir = [b0, b1] def _bucket(self, k): return self.dir[hash(k) & ((1 << self.gd) - 1)] def put(self, k, v): b = self._bucket(k) if k in b["items"] or len(b["items"]) < self.cap: b["items"][k] = v; return if b["ld"] == self.gd: # 目錄倍增 self.dir += self.dir; self.gd += 1 b["ld"] += 1 # 只分裂這一個桶 nb = {"ld": b["ld"], "items": {}} for i, x in enumerate(self.dir): if x is b and (i >> (b["ld"] - 1)) & 1: self.dir[i] = nb old, b["items"] = b["items"], {} for kk, vv in old.items(): self._bucket(kk)["items"][kk] = vv self.put(k, v) def get(self, k): return self._bucket(k)["items"].get(k)

🧭 這一課的重點

雜湊索引以 bucket = h(key) mod B 把鍵對應到桶，等值查找平均一次存取。靜態雜湊溢出鏈會變長且擴大須全部重新雜湊；擴充雜湊以目錄指向桶，只分裂滿的桶並在需要時倍增目錄；線性雜湊依序逐一分裂、不需目錄。雜湊索引等值查找極快，但不支援範圍查詢、排序與前綴查詢，因此 B+ 樹是預設索引；雜湊用於記憶體結構、雜湊連接與聚合，以及只需等值查找的場合，InnoDB 另有自適應雜湊索引。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
