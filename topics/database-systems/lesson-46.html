圖資料庫：Neo4j 與圖查詢

這一課的目標

  • 理解屬性圖模型
  • 認識 Cypher 查詢語言
  • 理解圖資料庫的適用場景

在關聯式資料庫中，「朋友的朋友的朋友」要做三次自我連接，每多一層就慢一大截。圖資料庫把關係直接存成指標，沿著邊走訪的成本與資料庫的總大小無關。

屬性圖模型

  • 節點：人、公司、帳戶，可以有標籤與屬性。
  • 邊：認識、任職於、轉帳給，有方向、類型與屬性（例如轉帳金額、時間）。

Cypher

// 找出和「王小明」在三層關係內、而且在同一家公司任職過的人 MATCH (a:人 {姓名: '王小明'})-[:認識*1..3]-(b:人), (a)-[:任職於]->(c:公司)<-[:任職於]-(b) RETURN DISTINCT b.姓名, c.名稱; // 反洗錢：找出資金繞了一圈回到原帳戶的轉帳環 MATCH p = (x:帳戶)-[:轉帳*3..6]->(x) WHERE all(t IN relationships(p) WHERE t.金額 > 1000000) RETURN p;

Cypher 以 ASCII 圖案描述要找的形狀：(節點)-[邊]->(節點)。2024 年 ISO 發布了圖查詢語言 GQL 標準，很大程度以 Cypher 為基礎。

適用場景

場景為什麼適合圖
社群網路與推薦朋友的朋友、買了這個的人也買了
詐欺與反洗錢找出帳戶之間的環狀轉帳、共用的設備與地址
知識圖譜實體與關係（本站《Ontology》課程）
網路與供應鏈相依關係、影響範圍分析

不一定需要圖資料庫

如果關係的深度固定而且不深，關聯式資料庫加上遞迴 CTE（第 10 課）往往就夠了。圖資料庫的優勢在深度不固定的多層走訪與圖演算法（最短路徑、社群偵測、PageRank）。

🧭 這一課的重點

關聯式資料庫查詢多層關係需要多次自我連接，圖資料庫把關係存成指標，走訪成本與資料庫總大小無關。屬性圖模型由帶標籤與屬性的節點，以及有方向、類型與屬性的邊組成。Cypher 以 ASCII 圖案描述要找的形狀，可查詢多層關係與反洗錢的環狀轉帳，2024 年 ISO 發布以其為基礎的 GQL 標準。適用於社群推薦、詐欺與反洗錢、知識圖譜、網路與供應鏈。關係深度固定且淺時遞迴 CTE 即可，圖資料庫的優勢在深度不固定的走訪與圖演算法。

🗄️ 本課程以原理為主，程式範例用 SQL 與 Python（以 Python 實作簡化版的 B+ 樹、WAL、LSM 樹等核心結構）。各資料庫的實際行為依產品與版本而異，文中以 PostgreSQL、MySQL（InnoDB）與 SQLite 為主要參考。
