SIP 入門

這一課的目標

  • 認識 SIP 協定
  • 理解一通 SIP 通話的訊息流程
  • 認識常見的 SIP 回應碼

SIP 是什麼

SIP（工作階段初始協定）是網路電話最主要的信令協定，標準是 RFC 3261。它的格式很像網頁的 HTTP：純文字、有請求與回應。每個使用者有一個像電子郵件的位址，例如 sip:1234@company.com。

一通電話的流程

請求與回應

請求用途
REGISTER電話開機時，告訴伺服器「我在這個 IP 位址」
INVITE發起通話（或在通話中重新協商，稱為 re-INVITE）
ACK確認收到最終回應
BYE結束通話
CANCEL在對方接起之前取消
REFER請對方去撥給某人（轉接，第 21 課）
NOTIFY通知狀態的變化
回應碼意義
1xx處理中：100 Trying、180 Ringing
2xx成功：200 OK、202 Accepted
3xx重新導向：請改撥另一個位址
4xx請求的問題：404 找不到、486 忙線、487 已取消
5xx伺服器的問題
6xx全域失敗：603 拒接

對話（dialog）

INVITE 成功後，雙方之間就建立了一個 SIP「對話」，由 Call-ID 與雙方的標籤（tag）識別。之後在這通電話中的所有訊息——保留、恢復、轉接、掛斷——都在這個對話中進行。記住這個概念，第 19、21 課會用到。

🧭 這一課的重點

SIP 工作階段初始協定是網路電話最主要的信令協定 RFC 3261，格式像 HTTP 純文字請求回應，位址如 sip:1234@company.com；流程 INVITE 附 SDP、100 Trying、180 Ringing、200 OK 附 SDP、ACK、RTP 語音直接在兩端、BYE、200 OK；請求有 REGISTER 告訴伺服器位址、INVITE 發起或通話中 re-INVITE、ACK、BYE、CANCEL、REFER 請對方撥給某人、NOTIFY；回應碼 1xx 處理中、2xx 成功、3xx 重新導向、4xx 請求問題 404 486 忙線 487、5xx 伺服器問題、6xx 全域失敗 603 拒接；INVITE 成功後建立 SIP 對話由 Call-ID 與標籤識別，之後保留恢復轉接掛斷都在這個對話中進行。
