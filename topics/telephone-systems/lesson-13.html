信令與媒體分離

這一課的目標

  • 理解 SDP 的作用
  • 理解信令與媒體分離的意義
  • 理解提議與回應模型

SDP

INVITE 和 200 OK 裡面都夾帶了一段 SDP（工作階段描述協定）。它描述的是：聲音要送到哪裡、用什麼格式。一段簡化的 SDP：

c=IN IP4 192.0.2.10 ← 請把聲音送到這個 IP m=audio 40000 RTP/AVP 0 8 101 ← 用連接埠 40000，支援 G.711 μ-law、A-law 與按鍵事件 a=sendrecv ← 雙向

提議與回應

發起的一方送出提議（offer）：我在這裡、我支援這些編碼。另一方回覆回應（answer）：我在那裡、我們就用這個編碼。雙方談好之後，聲音就直接依照 SDP 的位址傳送。

同一通電話中，任何一方都可以用 re-INVITE 再提一次新的提議：換一個位址、換一個編碼、改變方向（只送、只收、不送不收）。SIP 對話不變，媒體的路徑卻可以改變——這就是保留與轉接能夠「不斷線」的基礎。

信令與媒體分離的好處

  • 效率：伺服器只處理少量的信令，大量的語音封包直接在端點之間傳送。
  • 彈性：可以在不改變信令的情況下，把聲音改送到錄音伺服器、會議橋或另一個人。
  • 擴充：同一套信令也能建立視訊、即時文字等不同的媒體。

代價

聲音直接在端點之間傳送，意味著雙方必須能夠互相連到對方的 IP 位址——但在家用路由器與企業防火牆之後，這常常做不到（下一課）。

🧭 這一課的重點

INVITE 與 200 OK 夾帶 SDP 工作階段描述協定描述聲音送到哪裡用什麼格式，c= 指定 IP、m=audio 指定連接埠與支援編碼、a=sendrecv 雙向；發起方送提議 offer 我在這裡支援這些編碼，另一方回應 answer 我在那裡用這個編碼，談好後聲音依 SDP 位址傳送；同通電話中可用 re-INVITE 再提新提議換位址編碼改方向，SIP 對話不變媒體路徑可改變是保留轉接不斷線的基礎；好處效率伺服器只處理少量信令語音在端點間、彈性可把聲音改送錄音伺服器會議橋另一個人、擴充視訊即時文字；代價是雙方必須能互相連到對方 IP，在路由器防火牆後常做不到。
