SIP 的轉接

這一課的目標

  • 理解 SIP 的 REFER 機制
  • 理解 Replaces 如何實現先問再轉
  • 理解 NOTIFY 的回報作用

請對方自己去撥

在點對點的 SIP 世界中，沒有一台交換機可以「改接」線路。SIP 的轉接用的是另一種思路：請對方自己去撥給新的人。這個請求就是 REFER（RFC 3515）。

  • REFER：轉接者（客服 B）送給被轉者（來電者 A）的請求，裡面的 Refer-To 寫著要撥給誰（專員 C）。
  • 202 Accepted：A 同意照做。
  • INVITE：A 的電話自動撥給 C——對 A 的使用者來說，什麼都不用做。
  • NOTIFY：A 回報 B 轉接的進度（響鈴中、成功、失敗），內容是一小段 SIP 回應。
  • BYE：B 得知成功後，掛掉自己與 A 的通話。

Replaces：天衣無縫的先問再轉

先問再轉時，B 已經和 C 有一通通話。B 送給 A 的 REFER 會在 Refer-To 中附上 Replaces 參數（RFC 3891），指明 B↔C 那通通話的身分。A 撥給 C 時帶著 Replaces，C 的電話就知道：「這通新電話要取代我和 B 的那通」，於是自動接起、不再響鈴，並掛掉與 B 的通話。

為什麼不會斷？

在 REFER 方式中，A 與 B 的通話，要等到 A 與 C 的通話建立之後才結束（「先接再斷」）。A 的電話在背景完成了這一切；使用者感受到的，只是等候音樂之後換了一個人說話。

其他相關的標頭

  • Referred-By：說明是誰要求這次轉接，讓 C 知道。
  • Target-Dialog 等：協助驗證這次轉接是合法的。
  • 安全上，被轉者的電話應該檢查 REFER 是否來自正在通話的對方，避免被陌生人任意「轉走」。

🧭 這一課的重點

點對點 SIP 沒有交換機可改接，轉接思路是請對方自己去撥給新的人這請求是 REFER RFC 3515：客服 B 送給來電者 A 的 REFER 中 Refer-To 寫要撥給專員 C、A 回 202 Accepted、A 的電話自動 INVITE 給 C 使用者不用做事、A 用 NOTIFY 回報進度響鈴成功失敗、B 得知成功後 BYE 掛掉與 A 的通話；先問再轉時 B 已和 C 通話，REFER 的 Refer-To 附 Replaces 參數 RFC 3891 指明 B↔C 通話身分，A 帶 Replaces 撥 C，C 知道要取代與 B 的那通自動接起不響鈴並掛掉與 B 的通話；REFER 方式 A 與 B 的通話要等 A 與 C 建立後才結束先接再斷所以不斷；Referred-By 說明誰要求轉接、Target-Dialog 協助驗證、被轉者應檢查 REFER 來自正在通話的對方。
