實作橫幅廣告（Banner Ad）

這一課的目標

  • 能建立GADBannerView並正確設定adUnitID、rootViewController
  • 能呼叫load(GADRequest())載入廣告，並理解開發階段為什麼要用官方測試廣告單元ID
  • 能規劃橫幅廣告在打磚塊遊戲畫面中適當、不遮擋玩法的擺放位置

SDK裝好、初始化完成，這一課要實作第52課規劃的第一種 廣告——常駐在畫面上的橫幅廣告。橫幅廣告是三種格式裡 程式碼最單純的一種，很適合當作第一次串接廣告SDK的 練習。

1. 建立GADBannerView

橫幅廣告對應的類別是GADBannerView，本質上 就是一個顯示廣告內容的view。建立時要指定廣告尺寸、 廣告單元ID，並且告訴它目前是由哪個view controller 負責呈現這個廣告，最後呼叫load(_:)並傳入 一個GADRequest()，正式發出載入廣告的請求：

import GoogleMobileAds let bannerView = GADBannerView(adSize: GADAdSizeBanner) bannerView.adUnitID = "ca-app-pub-3940256099942544/2934735716" bannerView.rootViewController = self bannerView.load(GADRequest())

2. 開發階段一定要用測試廣告單元ID

上面程式碼裡用的ca-app-pub-3940256099942544/ 2934735716，正是Google官方文件公開提供、專門 給iOS開發測試用的橫幅廣告單元ID。開發、測試階段請務必 使用這組（或AdMob文件裡列出的其他官方測試ID），而不是 直接套用第55課在後台建立的正式Ad Unit ID——如果拿正式 ID在還沒有真實使用者的開發機上反覆測試、大量發出請求， 等於製造不具真實使用者意義的「無效流量」，可能違反 AdMob的服務條款，情節嚴重甚至可能導致帳號被停權。 正確做法是整個開發、除錯過程都用官方測試ID，等真正 要送出上架審核前，才換回自己專屬的正式Ad Unit ID （第60課的檢查清單會再次提醒這一點）。

3. 版面配置：橫幅要放哪裡才不擋到玩法

橫幅廣告應該用一個獨立的容器，固定釘在畫面的頂部或 底部，而不是疊加在遊戲畫面正中央。以這款打磚塊遊戲 來說，球拍通常活動在畫面偏下方的區域，比較保險的做法 是把橫幅廣告固定在畫面最頂端，讓 SKView負責的整個遊戲畫面完整保留在橫幅下方，球拍的 操作區域完全不受影響。如果採用UIKit搭配Auto Layout， 典型的作法是把橫幅釘在安全區域頂端：

view.addSubview(bannerView) bannerView.translatesAutoresizingMaskIntoConstraints = false NSLayoutConstraint.activate([ bannerView.topAnchor.constraint(equalTo: view.safeAreaLayoutGuide.topAnchor), bannerView.centerXAnchor.constraint(equalTo: view.centerXAnchor) ])

關鍵原則是：橫幅廣告的容器要獨立於SKView所佔的畫面 範圍之外，兩者不重疊——這樣即使橫幅廣告的實際內容 會隨著載入的廣告素材而變化，也不會有任何機率蓋住球拍 或飛行中的球，影響玩家操作。

檢查你的理解

  1. 寫出建立GADBannerView、設定adUnitID與rootViewController，並載入廣告的完整程式碼
  2. 解釋開發階段為什麼要用官方測試廣告單元ID，而不是直接用正式的Ad Unit ID
  3. 說明這款打磚塊遊戲的橫幅廣告應該放在畫面哪裡，以及為什麼
