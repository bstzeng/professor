模組 K｜資料儲存與遊戲設定 · 第 47 課

儲存最高分與遊戲進度

這一課的目標

  • 能寫出「讀取已存最高分、跟本局分數比較、有需要才寫回」的完整程式邏輯
  • 理解為什麼要先讀取比較，而不是每次遊戲結束都直接覆寫
  • 能把這段邏輯正確接到遊戲結束（game over）的時機點上

上一課認識了UserDefaults的基本讀寫方式，這一課把它套進 一個具體、幾乎每款遊戲都會用到的場景：儲存最高分。整個 邏輯並不複雜，但有一個容易忽略的細節——不是每次遊戲 結束都要寫入，只有玩家真的打破紀錄的那一次才需要。

1. 完整的邏輯：讀取、比較、有需要才寫回

func updateHighScoreIfNeeded(currentScore: Int) { let savedHighScore = UserDefaults.standard.integer(forKey: "highScore") if currentScore > savedHighScore { UserDefaults.standard.set(currentScore, forKey: "highScore") } }

這段程式碼分三步：先用integer(forKey:)讀出 目前已經存好的最高分——就算App是第一次執行、根本還沒 存過"highScore"這個key，也會安全地拿到 0，不需要另外判斷key存不存在；接著比較本局 的currentScore是否大於savedHighScore； 只有在「打破紀錄」的情況下，才呼叫set(_:forKey:) 把新的分數寫回去。平常沒有破紀錄的那些局，完全不需要 寫入，既避免了不必要的磁碟寫入，邏輯上也更清楚地表達了 「只在真正需要時才更新」的意圖。

2. 接到遊戲結束的時機點

func endGame() { run(SKAction.playSoundFileNamed("gameOver.wav", waitForCompletion: false)) updateHighScoreIfNeeded(currentScore: score) // 顯示遊戲結束畫面…… }

這段邏輯應該在遊戲確定進入「結束」狀態的那一刻呼叫一次 ——也就是模組H勝負判定邏輯裡，狀態機切換到game over 狀態的地方。這裡也一併示範了模組I第38課的音效邏輯跟 這一課的最高分更新邏輯，很自然地並排放在同一個 endGame()函式裡：兩件事各自獨立，互不干擾， 卻都掛在同一個時機點上觸發。

3. 顯示目前的最高分

let highScore = UserDefaults.standard.integer(forKey: "highScore") highScoreLabel.text = "最高分：\(highScore)"

存起來的最高分，當然也要有地方讀回來顯示——常見的做法 是在開始畫面或遊戲結束畫面，讀取這個值並更新對應的 SKLabelNode文字，讓玩家清楚看到自己目前 的最佳紀錄，也讓「打破紀錄」這件事有明確的參考基準。

檢查你的理解

  1. 依序說出（或寫出）判斷是否要更新最高分的完整邏輯順序
  2. 說明為什麼不能每次遊戲結束都直接把本局分數寫進highScore
  3. 說明updateHighScoreIfNeeded這段邏輯應該放在遊戲流程的哪個時間點呼叫
