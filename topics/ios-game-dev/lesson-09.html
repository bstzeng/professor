模組 B｜Swift語言快速上手 · 第 9 課

protocol與擴充功能基礎

這一課的目標

  • 理解protocol在定義什麼、以及型別怎麼「遵循」一個protocol
  • 知道為什麼後續模組G的碰撞偵測，需要場景遵循SKPhysicsContactDelegate這個protocol
  • 認識extension的基本語法，知道它可以幫既有型別加上新功能

模組B最後一個語言概念，要介紹protocol（協定）與 extension（擴充功能）。這兩個概念單獨看可能會覺得 有點抽象，但它們在SpriteKit裡有非常具體的用途——尤其 是protocol，後面模組G處理碰撞偵測時會直接用到，這一課 先把底層邏輯建立起來。

1. protocol：定義一份「必須做到什麼」的清單

protocol本身不實作任何邏輯，它只是定義一份 清單，列出「任何遵循這個protocol的型別，都必須提供 哪些屬性或方法」：

protocol Damageable { var health: Int { get set } func takeDamage(_ amount: Int) }

這段程式碼定義了一個叫做Damageable（可被 造成傷害）的protocol，規定任何遵循它的型別，都必須有 一個health屬性，以及一個 takeDamage(_:)方法。protocol本身只列出 「要有什麼」，不寫「具體怎麼做」。

2. 讓一個型別遵循protocol

型別要遵循某個protocol，寫法跟繼承class很像，用冒號 接在型別名稱後面，接著就必須把protocol要求的內容 全部實作出來，否則編譯器會報錯：

class Enemy: Damageable { var health: Int = 30 func takeDamage(_ amount: Int) { health -= amount print("敵人受到\(amount)點傷害，剩餘血量：\(health)") } }

class Enemy: Damageable裡的 Damageable就是Enemy遵循的 protocol——因為Enemy確實提供了 health屬性跟takeDamage(_:) 方法，符合Damageable的要求，所以能成功 遵循。protocol的好處是：只要一個型別遵循了某個 protocol，其他程式碼就可以放心地把它當成「一定具備這些 能力」的物件來使用，不需要知道它實際上是哪個具體的類別。

先看一眼：後面碰撞偵測會用到的SKPhysicsContactDelegate

模組G處理球撞到磚塊、球拍的碰撞偵測時，會讓 GameScene遵循SpriteKit框架提供的一個 protocol，叫做SKPhysicsContactDelegate， 寫法大致是class GameScene: SKScene, SKPhysicsContactDelegate（一個class可以同時 繼承一個父類別、並遵循多個protocol）。這個protocol 要求場景實作一個「當兩個物體發生碰撞時會被呼叫」的 方法，SpriteKit的物理引擎偵測到碰撞後，就會自動呼叫 這個方法，把細節丟給我們自己實作的邏輯處理。現在只 需要記得：「遵循protocol」代表「答應提供某些特定的 方法或屬性」，屆時回頭看這一課會更清楚。

3. extension：幫既有型別加上新功能

extension可以在不修改原本型別定義的情況下， 幫一個既有型別（包括自己寫的、或是Swift／SpriteKit內建 的型別）加上新的方法或計算屬性：

extension Int { var isEvenScore: Bool { return self % 2 == 0 } } let score = 120 print(score.isEvenScore) // true

這個例子替Swift內建的Int型別加上了一個新的 計算屬性isEvenScore，之後任何Int 值都能直接使用它。實務上，extension常被用來把某個型別 相關、但跟主要定義無關的功能（例如格式化字串、額外的 便利方法）獨立整理在一起，讓程式碼更有組織。

檢查你的理解

  1. 解釋protocol定義的是什麼，以及型別「遵循」protocol代表什麼義務
  2. 說明為什麼後面模組G的GameScene需要遵循SKPhysicsContactDelegate
  3. 用自己的話說明extension的用途，跟直接修改原本的型別定義有什麼不同
