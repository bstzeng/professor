模組 M｜App內廣告整合 · 第 59 課

實作獎勵型廣告（Rewarded Ad）：讓玩家自願看廣告換獎勵

這一課的目標

  • 能用GADRewardedAd.load(withAdUnitID:request:completionHandler:)載入一支獎勵型廣告
  • 能設計一個玩家自願點擊的UI（例如「看廣告復活」按鈕），只在適當時機出現
  • 理解為什麼一定要在userDidEarnRewardHandler回呼裡才發放獎勵，不能提前發放

插頁廣告是遊戲流程走到某個時機點，強制顯示給玩家看的 廣告；這一課要實作的獎勵型廣告，方向完全相反——第52課 分類過，這是「使用者主動點開型」的廣告：玩家自己決定 要不要看，看完換到一個實際的遊戲內好處。對這款打磚塊 遊戲來說，最自然的應用就是「看廣告復活」。

1. 載入廣告：GADRewardedAd.load(withAdUnitID:request:completionHandler:)

跟插頁廣告一樣，獎勵型廣告也是先在背景載入好，等玩家 真的觸發時再顯示。宣告一個變數保存載入完成的廣告實例：

import GoogleMobileAds var rewardedAd: GADRewardedAd? func loadRewardedAd() { let request = GADRequest() GADRewardedAd.load(withAdUnitID: "ca-app-pub-3940256099942544/1712485313", request: request) { [weak self] ad, error in if let error = error { print("獎勵廣告載入失敗：\(error.localizedDescription)") return } self?.rewardedAd = ad self?.rewardedAd?.fullScreenContentDelegate = self } }

ca-app-pub-3940256099942544/1712485313是 Google官方公開提供、專門給獎勵型廣告測試用的廣告單元 ID，開發階段一樣先用它。載入完成的GADRewardedAd 實例存進rewardedAd，並設定 fullScreenContentDelegate接收後續的顯示、 關閉通知——跟第58課的插頁廣告是同一套流程結構。

2. UI：只在玩家失去所有生命時出現的按鈕

獎勵型廣告的按鈕不應該一直顯示在畫面上，而是只在真的 有意義的時機出現。以模組H的生命值系統來說，最合理的 時機就是玩家的lives歸零、原本要直接判定 遊戲結束的那一刻：

func showReviveButtonIfAvailable() { guard lives <= 0, rewardedAd != nil else { return } reviveButton.isHidden = false }

這裡刻意多加一個rewardedAd != nil的判斷： 如果這支獎勵廣告根本還沒載入完成，就不該顯示「看廣告 復活」的按鈕，避免玩家點了按鈕卻什麼都沒發生。

3. 顯示：present(fromRootViewController:userDidEarnRewardHandler:)

玩家點擊按鈕之後，呼叫的是GADRewardedAd 專屬的顯示方法，它跟插頁廣告的present不同， 多了一個「使用者已獲得獎勵」的回呼：

func reviveButtonTapped() { guard let rewardedAd = rewardedAd, let rootVC = self.view?.window?.rootViewController else { return } rewardedAd.present(fromRootViewController: rootVC) { [weak self] in guard let self = self else { return } self.lives += 1 self.resumeGame() } }

這個尾隨閉包就是userDidEarnRewardHandler ——只有在玩家實際把廣告看到系統認定「已達成獎勵條件」 的那一刻，這段程式碼才會被執行。如果需要知道廣告本身 設定的獎勵內容（例如聯播網後台設定的獎勵數量、類型）， 可以在同一時間讀取rewardedAd.adReward。

4. 關鍵原則：獎勵只能在回呼裡發放，絕不能提前給

這一課最重要的觀念，就是self.lives += 1 這一行，只能寫在userDidEarnRewardHandler 這個閉包裡面，絕對不能寫在按鈕被點擊的 當下、或是廣告畫面顯示出來的那一刻——玩家點了按鈕， 不代表他真的看完了廣告；如果獎勵在按下按鈕時就先給， 玩家只要點一下再立刻把廣告畫面關掉，就能免費拿到復活 機會，完全繞過了「用廣告換獎勵」這個交換前提，也會讓 廣告曝光數據失真。把發放獎勵的邏輯，跟廣告SDK認定「已 達成觀看條件」的那個時間點綁在一起，是這整套機制唯一 正確的做法。

5. 用完之後，記得預先載入下一支

一支GADRewardedAd也是只能顯示一次，比照 第58課插頁廣告的做法，在委派方法裡於廣告關閉時重新 載入：

extension GameScene: GADFullScreenContentDelegate { func adDidDismissFullScreenContent(_ ad: GADFullScreenPresentingAd) { rewardedAd = nil loadRewardedAd() } }

這裡要注意的是，adDidDismissFullScreenContent 只負責「廣告關閉了，該準備下一支」這件事，跟要不要 發放獎勵完全無關——即使玩家中途把廣告關掉、沒有看完， 這個委派方法一樣會被呼叫，但因為 userDidEarnRewardHandler沒有被觸發， lives += 1那段程式碼就不會執行，兩件事 各自獨立、互不影響。

檢查你的理解

  1. 寫出載入一支獎勵型廣告、並保存到變數裡的完整程式碼
  2. 說明「看廣告復活」按鈕應該在遊戲的什麼狀態下才出現，為什麼還要額外檢查rewardedAd是否為nil
  3. 解釋為什麼發放獎勵的程式碼一定要寫在userDidEarnRewardHandler裡，寫在按鈕被點擊的當下會有什麼問題
