模組 I｜音效與視覺效果 · 第 38 課

音效播放

這一課的目標

  • 理解SKAction.playSoundFileNamed的用法，以及waitForCompletion參數的意義
  • 學會把音效檔案正確加入Xcode專案，並確認target membership有勾選
  • 找出遊戲中三個最適合加入音效的時機點，並實際寫出觸發程式碼

模組H結束時，打磚塊遊戲已經有一套完整能跑的狀態機—— 球會彈、磚塊會消失、分數會累加、輸贏會判定。但整個過程 是全然安靜的：球打到球拍、磚塊碎裂、遊戲結束，畫面上 什麼都在變化，耳朵卻什麼都聽不到。模組I要開始幫遊戲 加上這一層「回饋」，而音效通常是成本最低、效果卻最 明顯的第一步。

1. SKAction.playSoundFileNamed：一行程式碼播放音效

SpriteKit裡任何SKNode都能呼叫run(_:) 方法，執行一個SKAction——播放音效也不例外， 只是這個動作本身不是移動或縮放，而是播放一段聲音檔案：

let hitSound = SKAction.playSoundFileNamed("paddleHit.wav", waitForCompletion: false) run(hitSound)

waitForCompletion決定的是「這個動作在action queue裡算不算佔用時間」：設成false，代表 SpriteKit會立刻觸發播放，但不會等音效播完才繼續執行 後面排隊的其他動作；設成true則會讓這個動作 一直到音效播放結束才視為完成。遊戲音效通常會跟其他 動畫、邏輯同時發生，所以絕大多數情況都會用 false，讓聲音單純疊加播放，不卡住遊戲其他 部分的節奏。

2. 把音效素材加入Xcode專案

要讓上面那行程式碼真的找得到檔案，音效檔要先進到Xcode 專案裡：把音效檔案從Finder拖進Project Navigator，拖曳 時勾選「Copy items if needed」，確保檔案實際被複製進 專案資料夾，並且確認對應的target有打勾（target membership），這樣建置時檔案才會被打包進App裡。常見的 WAV、CAF、MP3等格式都能正常播放；短促的音效建議用WAV 或CAF這類未壓縮或輕量壓縮的格式，播放延遲比較低，比較 適合需要即時反應的碰撞音效。

3. 三個常見的觸發時機

音效不是加得越多越好，關鍵是挑對「事件真正發生的那一 瞬間」觸發。對這款打磚塊遊戲來說，最直覺的三個時機， 分別對應到模組G、H已經寫好的碰撞與狀態邏輯：

func didBegin(_ contact: SKPhysicsContact) { let collision = contact.bodyA.categoryBitMask | contact.bodyB.categoryBitMask if collision == PhysicsCategory.ball | PhysicsCategory.paddle { run(SKAction.playSoundFileNamed("paddleHit.wav", waitForCompletion: false)) } if collision == PhysicsCategory.ball | PhysicsCategory.brick { run(SKAction.playSoundFileNamed("brickBreak.wav", waitForCompletion: false)) // 這裡接續模組G的邏輯，找出對應的磚塊節點並移除 } } func endGame() { run(SKAction.playSoundFileNamed("gameOver.wav", waitForCompletion: false)) // 顯示遊戲結束畫面…… }

注意這段程式碼完全沒有動到didBegin(_:)原本 判斷碰撞類別、移除磚塊的邏輯——只是在正確的分支裡多加 一行播放音效的呼叫。這正是模組I這幾課的共同精神：在 既有、已經測試過的邏輯上疊加回饋，而不是重寫它。

觸發時機對應程式位置建議音效檔名示意
球拍碰撞didBegin：ball | paddle分支paddleHit.wav
磚塊消失didBegin：ball | brick分支brickBreak.wav
遊戲結束endGame()／狀態機切換到結束狀態時gameOver.wav
