模組 F｜實作專案①：打磚塊遊戲——基礎架構 · 第 23 課

專案初始化與場景規劃

這一課的目標

  • 知道這門課接下來的實作專案，是沿用哪一課建立的Xcode專案
  • 規劃打磚塊遊戲場景由上到下的區域配置：分數區、磚塊陣列、球、球拍
  • 訂出一套一致的物件命名規範，方便之後查找與碰撞偵測

模組E把輸入處理的邏輯準備好了，從這一課開始的模組F， 要正式動手做這門課的第一個實作專案——一款打磚塊風格的 休閒遊戲：畫面底部有一支球拍，球在畫面裡彈來彈去，撞 擊畫面上方排列整齊的磚塊陣列。接下來好幾個模組（F到H） 都會持續建立在同一個專案上，這一課先把場景規劃底定， 再開始寫程式。

1. 沿用模組C建立的SpriteKit專案

不需要另外開一個新專案——直接沿用第13課「建立你的第一個 SpriteKit專案」時建立的那個專案即可。打開專案後，把 GameScene.swift裡原本Xcode範本自動產生的 示範內容（例如一個會旋轉的示範圖形、點擊產生火花的邏輯） 清空，保留空的GameScene: SKScene類別骨架， 當作接下來每一課疊加內容的起點：

import SpriteKit class GameScene: SKScene { override func didMove(to view: SKView) { // 接下來每一課會陸續在這裡加上球拍、球、磚塊陣列 } }

didMove(to:)會在場景被SKView 呈現出來的那一刻被呼叫一次，是建立初始畫面內容最自然的 位置（回顧第19課的遊戲迴圈與生命週期）。

2. 場景整體佈局規劃

在動手建立任何節點之前，先把畫面由上到下大致分成幾個 區域，讓後面每一課要新增的物件，都有明確該放的位置：

  • 頂部：標題／分數區——顯示目前分數、 剩餘生命等資訊（模組H會實際加上）
  • 中上：磚塊陣列——一整排整列排列整齊 的磚塊，第26課會用巢狀迴圈建立
  • 中下：球的活動空間——球在磚塊與球拍 之間彈跳的主要區域，第25課先建立靜止的球
  • 底部：球拍——玩家實際操作、左右移動 的物件，第24課接上模組E的觸控邏輯

3. 物件命名規範

每個要加入場景的節點，都應該設定name屬性， 給它一個固定的字串識別碼。這門課採用最直接的命名方式： 球拍叫做"paddle"，球叫做"ball"， 每一塊磚塊都叫做"brick"。為了避免打錯字， 可以把這些字串集中定義成常數：

enum NodeName { static let paddle = "paddle" static let ball = "ball" static let brick = "brick" }

之後不管是用node.name = NodeName.paddle設定 名稱，還是之後查找節點，都用同一組常數，比在程式碼裡到處 寫死字串安全許多——打錯一個字元，編譯器不會提醒你，但 名稱比對就會悄悄失敗。第26課建立磚塊陣列、模組G做碰撞 偵測時，都會依賴這一課訂下的命名規範。

檢查你的理解

  1. 說明這門課從這一課開始的打磚塊專案，是延續哪一課建立的Xcode專案
  2. 描述打磚塊遊戲場景由上到下大致分成哪幾個區域
  3. 說明為什麼替遊戲物件的name屬性設定一致的命名規範很重要
