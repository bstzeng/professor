模組 B｜Swift語言快速上手 · 第 4 課

變數、常數與基本型別

這一課的目標

  • 分清楚var與let的差異，並知道Swift建議優先用哪一個
  • 認識遊戲開發最常用到的幾種基本型別：Int、Double、String、Bool、Array、Dictionary
  • 看懂型別推斷與明確標註型別這兩種寫法，並知道各自適合的場合

模組A把大方向講清楚了，從這一課開始，正式進入Swift語言 本身。這一課從最基本、也是寫任何程式都躲不掉的東西 開始——怎麼「存」一個值，還有這個值可能是哪幾種型別。 這些語法看起來簡單，但後面每一課、甚至整個遊戲專案， 都是建立在這個基礎之上。

1. var與let：可以改變的值，跟不能改變的值

Swift裡宣告一個「裝值的容器」，有兩個關鍵字： var宣告的是變數，值之後可以 被重新指定；let宣告的是常數， 一旦給定初始值之後，就不能再被更改。

var score = 0 score = 10 // 合法，var可以重新指定值 let maxLives = 3 maxLives = 5 // 編譯錯誤！let宣告的值不能再被更改

Swift官方風格建議：預設優先使用let， 只有真的需要之後改變這個值時，才用var。 這聽起來像是個小習慣，但好處很實際——當你在一段很長的 程式碼裡看到let，就能立刻確定這個值從宣告 到結束都不會變，減少追蹤程式邏輯時的心智負擔；用打磚塊 遊戲舉例，maxLives（初始生命值上限）這種 整個遊戲過程中都不會變的設定，適合用let； 而score（目前分數）這種會隨著遊戲進行不斷 更新的值，才需要用var。

2. 幾種最常用的基本型別

Swift是強型別（strongly typed）語言， 每個值都有明確的型別。遊戲開發最常碰到的幾種基本型別：

let score: Int = 0 // 整數 let ballSpeed: Double = 4.5 // 帶小數的浮點數 let playerName: String = "Alex" // 文字字串 let isGameOver: Bool = false // 布林值（真／假） let highScores: [Int] = [120, 98, 75] // 陣列：一串同型別的值 let settings: [String: Bool] = ["sound": true, "vibration": false] // 字典：一組「鍵—值」對應

Int用來存整數，例如分數、生命值、磚塊排數； Double用來存帶小數點的數字，例如球的移動 速度；String存文字，例如玩家名稱或畫面上 顯示的文字；Bool只有true或 false兩種值，很適合拿來表示「遊戲是否結束」 這類二選一的狀態；Array（陣列）是一串排列好 順序、型別相同的值，很適合用來管理「畫面上所有磚塊」； Dictionary（字典）則是一組「鍵—值」的對應 關係，例如用文字當鍵，快速查到對應的設定值。

3. 型別推斷 vs 明確標註型別

上面的例子每個值都寫了: Int、: String 這樣的明確型別標註，但其實這在很多時候 不是必要的——Swift的編譯器很聰明，能從你給的初始值直接 推斷（infer）出型別：

let score = 0 // 編譯器看到0，自動推斷型別是Int let ballSpeed = 4.5 // 看到帶小數點的數字，自動推斷是Double let playerName = "Alex" // 看到雙引號字串，自動推斷是String

這兩種寫法在效果上完全一樣，差別只在於「型別是不是寫在 程式碼裡讓人一眼看到」。實務上的習慣是：型別一看就懂的 情況（例如直接賦予初始值），大多讓Swift自動推斷、省略 標註，程式碼會比較簡潔；但如果宣告的當下還沒有值、或是 想讓程式碼的意圖更明確（例如函式的參數、還沒有初始值的 變數），就會明確標註型別。

小提醒：常數不代表「遊戲設定不能調」

很多新手會誤以為用let宣告的值，代表這個 設定永遠固定、以後改版也不能動。其實let 限制的只是「這一次執行程式時，這個值賦予之後不能再被 改變」——如果之後想調整磚塊排數或球速的預設值，直接 回到程式碼裡修改let那一行的初始值、重新 編譯即可，跟「這個值在程式執行過程中能不能被更改」是 兩回事。
