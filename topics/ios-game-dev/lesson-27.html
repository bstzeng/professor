模組總結：場景切換與開始畫面

這一課的目標

  • 認識SKTransition，能在不同SKScene之間做出轉場效果
  • 理解「點一下開始」開始畫面的基本實作模式：獨立場景＋觸控後轉場
  • 回顧模組F目前的進度，並銜接模組G要處理的物理與碰撞

模組F前四課依序建立了球拍、球、磚塊陣列，但目前打開 遊戲，會直接看到一整個排好的畫面，玩家連準備的時間都 沒有。這一課要補上一個常見的體驗細節——先出現一個 「點一下開始」的畫面，玩家點擊之後，才真正切換進遊戲 場景，同時也是模組F收尾、銜接模組G之前，回顧目前進度 的好時機。

SKTransition：場景之間的轉場效果

SpriteKit允許一個SKView隨時切換成呈現不同 的SKScene，而SKTransition提供 了一整組現成的轉場效果，讓切換不會是生硬的一刀切畫面。 最常用、也最不容易出錯的是淡入淡出：

let transition = SKTransition.fade(withDuration: 0.5) if let view = self.view { let gameScene = GameScene(size: view.bounds.size) gameScene.scaleMode = .aspectFill view.presentScene(gameScene, transition: transition) }

SKTransition.fade(withDuration:)建立一個 0.5秒的淡入淡出轉場；view.presentScene(_: transition:)才是真正觸發切換的呼叫——把新場景 跟轉場效果一起傳進去，SpriteKit會自動處理整個轉場動畫， 不需要自己手動計算透明度或寫額外的動畫程式碼。

一個簡單的開始畫面

「點一下開始」的做法，其實就是另外準備一個獨立的 SKScene子類別，放標題文字跟提示文字， 並在touchesBegan裡觸發轉場：

class StartScene: SKScene { override func didMove(to view: SKView) { let titleLabel = SKLabelNode(text: "打磚塊") titleLabel.fontSize = 40 titleLabel.position = CGPoint(x: frame.midX, y: frame.midY + 40) addChild(titleLabel) let promptLabel = SKLabelNode(text: "點一下開始") promptLabel.fontSize = 20 promptLabel.position = CGPoint(x: frame.midX, y: frame.midY - 20) addChild(promptLabel) } override func touchesBegan(_ touches: Set<UITouch>, with event: UIEvent?) { guard let view = self.view else { return } let gameScene = GameScene(size: size) gameScene.scaleMode = scaleMode view.presentScene(gameScene, transition: SKTransition.fade(withDuration: 0.5)) } }

SKLabelNode(text:)是SpriteKit裡專門顯示 文字的節點，跟第17課的SKSpriteNode一樣， 都是SKNode的子類別，設定fontSize 跟position的方式也相同。當玩家點一下畫面， touchesBegan會建立GameScene的 實例，並用淡入淡出轉場切換過去——這裡沿用第20課學過的 touchesBegan覆寫方式，只是這次觸發的不是 移動節點，而是切換整個場景。

模組F進度回顧

整理一下模組F這五課做出來的東西：GameScene 裡已經有可以隨手指左右移動的paddle（第24課）、 定位在球拍正上方、暫時保持靜止的ball（第25課）， 以及一整排整列、依規律座標排好的磚塊陣列（第26課）， 現在還加上了一個獨立的StartScene負責開場。 但打開遊戲實際玩玩看會發現：球不會掉落、球拍撞不到球、 球也不會撞壞任何一塊磚塊——因為場景裡目前所有節點都還 沒有physicsBody，SpriteKit不會偵測任何 接觸或碰撞。這正是接下來模組G「物理引擎與碰撞」要解決 的問題：讓球真正動起來，並且讓球拍、球、磚塊之間開始 有實際的物理互動。
