struct與class的差異

這一課的目標

  • 理解struct是值型別、class是參考型別，兩者被指定或傳遞時行為完全不同
  • 能用具體例子解釋這個差異在實際寫程式時會造成什麼影響
  • 知道SpriteKit的SKNode、SKSpriteNode、SKScene為什麼統統是class，以及這代表什麼

Swift裡有兩種主要用來定義「自訂資料型別」的方式： struct與class。表面上兩者的 語法非常像，都可以有屬性、方法，但背後的運作方式有一個 根本性的差異，一旦沒搞清楚，很容易寫出行為跟預期不一樣 的程式碼——這一課要把這個差異講透。

1. struct是值型別：指定或傳遞時，會被複製

struct定義的是值型別（value type）。 當一個struct的實體被指定給另一個變數、或當作參數傳給 函式時，Swift會建立一份獨立的複本—— 之後修改其中一份，不會影響到另一份：

struct Score { var value: Int } var scoreA = Score(value: 100) var scoreB = scoreA // scoreB是scoreA的一份獨立複本 scoreB.value = 200 print(scoreA.value) // 仍然是100，沒有被scoreB的修改影響 print(scoreB.value) // 200

2. class是參考型別：指定或傳遞時，是共享同一個實體

class定義的是參考型別（reference type）。當一個class的實體被指定給另一個變數、 或當作參數傳遞時，並不會複製出新的一份，而是讓兩個 變數指向同一個實體——透過任何一個變數 修改內容，另一個看到的也會是修改後的結果：

class Player { var health: Int init(health: Int) { self.health = health } } let playerA = Player(health: 100) let playerB = playerA // playerB指向跟playerA同一個Player實體 playerB.health = 50 print(playerA.health) // 也變成50了！因為指向同一個實體 print(playerB.health) // 50

注意這裡即使playerA、playerB 都用let宣告，playerB.health 還是可以被修改——因為let限制的是「變數本身 不能重新指向另一個實體」，而不是「這個實體內部的屬性不能 變」，這是新手很容易混淆的一個細節。

3. 另一個差異：class支援繼承，struct不支援

除了值型別／參考型別的差異，class還支援 繼承（inheritance）——一個class可以繼承 另一個class的屬性與方法，並在此基礎上擴充或覆寫（第2課 看到的GameScene: SKScene就是繼承的例子）； struct則不支援繼承。這也是為什麼SpriteKit 設計節點型別時，選擇用class而不是 struct——需要有一套共通的節點基礎行為 （SKNode），再讓更具體的類型（例如能顯示 圖片的SKSpriteNode）繼承並擴充它。

關鍵洞察：SpriteKit的節點全部都是class

SKNode（節點基礎類別）、SKSpriteNode （顯示圖片的節點）、SKScene（一整個遊戲 畫面）——這些之後會天天用到的SpriteKit型別，全部都是 class，也就是參考型別。這件事在後面模組D 管理遊戲物件時會變得很實際：當你把畫面上的球拍節點 存進一個變數、又傳給另一個函式做碰撞判斷，傳來傳去的 其實一直是「同一個球拍」，而不是好幾個各自獨立的複本 ——這正是遊戲裡「移動球拍、畫面上立刻反映出來」能夠 正常運作的底層原因。

檢查你的理解

  1. 解釋值型別跟參考型別的差異，並各舉一個struct跟class的例子
  2. 說明為什麼即使playerA用let宣告，playerA.health還是可以被修改
  3. 解釋為什麼SpriteKit選擇用class而不是struct來定義SKNode、SKSpriteNode等節點型別
