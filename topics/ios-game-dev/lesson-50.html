Instruments效能檢測入門

這一課的目標

  • 知道Xcode的Product > Profile選單會啟動Instruments，以及它跟一般除錯的差別
  • 認識Time Profiler樣板的用途：抓出程式裡最耗CPU的程式碼路徑
  • 知道不用開Instruments，Xcode除錯導覽列跟SKView本身就能即時顯示FPS等效能數字

上一課的中斷點跟po指令，解決的是「邏輯對不對」的問題—— 程式跑出了不該有的結果，需要抓出來修正。但還有另一種 完全不同的問題：邏輯本身是對的，遊戲玩起來卻卡卡的、 掉幀。這種「效能」問題，不是靠中斷點一行行檢查能找到的， 需要換一套工具——這一課要認識的Instruments。

1. 什麼是Instruments，怎麼打開

Instruments是隨Xcode一起安裝的獨立效能分析工具。打開 方式是在Xcode選單列點選Product > Profile （快捷鍵Cmd+I），Xcode會用接近正式發布的最佳化設定重新 建置一次App，接著跳出Instruments，讓你選擇要用哪一種 樣板（template）分析——不同樣板專注在 不同面向的效能問題，例如CPU使用率、記憶體配置、能源 消耗等。

2. Time Profiler：抓出最耗CPU的程式碼

對新手來說，最實用的入門樣板是Time Profiler。 它的原理是每隔極短的時間間隔，就對App當下的呼叫堆疊 （call stack）取樣一次，長時間累積下來，就能統計出 「哪些函式在CPU時間裡佔的比例最高」。如果遊戲明顯掉幀， 用Time Profiler跑一段實際遊玩的過程，通常就能看到某個 函式（例如塞了太多邏輯的update(_:)，下一課 會細談）在報表裡佔了不成比例的高比例，指出效能瓶頸 大概在哪裡，而不用憑感覺亂猜。

3. 不開Instruments也能看：Xcode除錯導覽列與SKView

很多時候甚至不需要特地跑一次Instruments。用Cmd+R在 Xcode裡直接執行App時，左側邊欄切到除錯導覽列 （debug navigator），就能即時看到目前App的CPU、 記憶體用量等簡易圖表，適合快速掃一眼有沒有明顯異常。

SpriteKit更進一步，直接提供了遊戲開發最在意的 FPS（每秒畫面更新次數）即時顯示——只要在建立 SKView的地方打開對應的除錯選項：

skView.showsFPS = true skView.showsNodeCount = true skView.showsPhysics = true

showsFPS會在畫面角落直接顯示目前的幀率， 理想情況應該穩定貼近裝置的更新頻率（例如60）； showsNodeCount顯示場景裡目前的節點總數， 節點數異常飆升往往代表有物件該移除卻沒被移除； showsPhysics則會把每個physics body的邊界 用線框畫出來，方便肉眼確認碰撞範圍設定得對不對（回顧 模組G的物理引擎設定）。這三個開關幾乎是SpriteKit開發 時最常開著跑的除錯資訊，比正式跑一次Instruments還 方便日常隨手檢查。

4. 新手的實用態度：先知道工具存在，需要時再深入

Instruments本身功能相當深，除了Time Profiler，還有 Allocations、Leaks等專門分析記憶體的樣板，各自都能再 單獨開一整堂課講。這門課的定位是：先知道這些 工具存在、各自大概解決什麼問題，真的遇到明顯 的效能異常時，知道該往Product > Profile裡的哪個樣板 去找，而不是強求現在就精通每一個樣板的每一個細節功能。 下一課會換個角度，直接列出SpriteKit新手最容易踩到的 幾個效能陷阱，通常比深入鑽研Instruments更能立即改善 新手專案的效能。

檢查你的理解

  1. 說明怎麼啟動Instruments，以及Time Profiler樣板主要用來分析什麼
  2. 說明showsFPS、showsNodeCount、showsPhysics這三個SKView開關各自顯示什麼資訊
  3. 解釋為什麼日常開發時，除錯導覽列與SKView的即時資訊常常比正式跑一次Instruments更方便
