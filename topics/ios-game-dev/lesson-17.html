SKSpriteNode：讓圖片動起來

這一課的目標

  • 認識SKSpriteNode是SpriteKit裡最常用來顯示遊戲物件的節點類型
  • 能用兩種方式建立SKSpriteNode：從圖片資源建立，或用純色矩形建立
  • 認識position、size、zPosition這幾個關鍵屬性各自的用途

上一課用SKSpriteNode(imageNamed:)建立了 player跟hat兩個節點，這一課要正式把 SKSpriteNode講清楚——它是這門課接下來做 打磚塊遊戲時，用得最多的一種節點。

1. 從圖片資源建立：SKSpriteNode(imageNamed:)

當美術素材（模組J會介紹去哪裡找）已經放進 Assets.xcassets（回顧第14課）之後，最直接 的建立方式，就是用圖片的名稱建立一個精靈節點：

let ball = SKSpriteNode(imageNamed: "ball") ball.position = CGPoint(x: frame.midX, y: frame.midY) addChild(ball)

SKSpriteNode(imageNamed: "ball")會去資源 目錄裡尋找名稱是ball的圖片，用它的內容 建立一個節點，畫面上就會顯示這張圖片。

2. 用純色矩形建立：SKSpriteNode(color:size:)

在還沒有美術素材、或是想先專心把遊戲邏輯做出來時， SKSpriteNode也支援直接用一個顏色跟尺寸， 建立一個純色矩形節點，完全不需要任何圖片檔案：

let paddle = SKSpriteNode(color: .white, size: CGSize(width: 100, height: 20)) paddle.position = CGPoint(x: frame.midX, y: frame.minY + 60) addChild(paddle)

這種寫法在原型製作（prototyping）階段非常實用——之後 模組F開始做打磚塊遊戲時，球拍、球、磚塊都可以先用不同 顏色的色塊代表，把碰撞、分數、關卡這些遊戲邏輯先做對， 等邏輯都驗證沒問題了，再回頭把色塊換成真正的美術圖片， 兩者用的都是同一個SKSpriteNode類別，換 起來很直接。

3. 三個關鍵屬性：position、size、zPosition

  • position——節點在父節點座標空間 裡的位置，型別是CGPoint（回顧第16課， 這個位置是相對父節點，不是相對整個畫面）
  • size——節點的寬高，型別是 CGSize，決定這個節點視覺上占據多大的 範圍，也會影響之後模組G物理引擎判斷碰撞範圍時參考 的邊界
  • zPosition——一個浮點數，決定節點 的繪製順序（layering）：數值愈大，愈會被畫在愈上層， 也就是視覺上愈「靠近觀察者」。當兩個節點的位置有 重疊，zPosition較高的那一個會蓋住zPosition較低的
let background = SKSpriteNode(color: .darkGray, size: scene!.size) background.zPosition = -1 addChild(background) let ball = SKSpriteNode(imageNamed: "ball") ball.zPosition = 1 addChild(ball)

這裡把背景的zPosition設成負值，球的 zPosition設成正值，確保不管兩者的 addChild(_:)呼叫順序為何，球一定會畫在 背景前面，不會被蓋住。

  2. 說明position、size、zPosition這三個屬性各自控制什麼
  3. 舉例說明為什麼在還沒有美術素材時，用色塊建立節點是實用的做法
