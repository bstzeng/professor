SKScene：遊戲畫面的容器

這一課的目標

  • 理解SKScene在SpriteKit裡扮演的角色——一個畫面或關卡的容器
  • 認識didMove(to:)這個生命週期方法，知道它什麼時候被呼叫、適合放什麼程式碼
  • 理解SKView如何透過presentScene(_:)把一個場景實際顯示到螢幕上

模組C的最後一課，導覽到GameScene.swift裡那個繼承自 SKScene的類別，當時先賣了個關子。這一課 正式把SKScene講清楚——它是SpriteKit整套架構裡最基本的 概念之一，之後每一課幾乎都會建立在這個理解之上。

1. SKScene是什麼：一個畫面或關卡的容器

可以把SKScene想成遊戲裡「一整個畫面」的 容器——像一塊畫布，所有玩家看得到的物件（背景、角色、 UI文字等）最終都會被放進某一個場景裡。一款遊戲通常 不會只有一個場景：例如可以有一個開始畫面的場景、一個 實際遊玩的場景、一個結束畫面的場景，各自是 SKScene的一個子類別，之後模組F會實際 建立這種場景之間切換的架構。

2. didMove(to:)：場景第一次顯示時執行的程式碼

SKScene提供了幾個生命週期方法，其中最常 用的是didMove(to view: SKView)——當這個 場景第一次被呈現到畫面上時，SpriteKit會自動呼叫這個 方法。它是設定初始遊戲物件最適合的地方，原因是：到了 這個時間點，場景已經確定跟一個實際的SKView 建立了關聯，場景的尺寸（size）等資訊都已 經確定，可以放心地根據這些資訊去計算物件該擺在哪裡。

import SpriteKit class GameScene: SKScene { override func didMove(to view: SKView) { backgroundColor = .black // 場景第一次顯示時，在這裡建立初始物件 let label = SKLabelNode(text: "準備開始") label.position = CGPoint(x: frame.midX, y: frame.midY) addChild(label) } }

這段程式碼把背景顏色設成黑色，接著建立一個顯示文字的 SKLabelNode，放在場景正中央，再用 addChild(_:)把它加進場景裡—— addChild(_:)的細節，下一課會完整說明。

3. presentScene(_:)：SKView如何把場景顯示出來

場景本身不會自己出現在螢幕上，需要一個SKView （SpriteKit專用的畫面元件）把它「呈現」出來，靠的就是 presentScene(_:)這個方法。這通常發生在 App啟動、準備顯示第一個畫面的時候：

if let skView = self.view as? SKView { let scene = GameScene(size: skView.bounds.size) scene.scaleMode = .aspectFill skView.presentScene(scene) }

這幾行程式碼先建立一個GameScene的實體， 設定好它的尺寸與縮放模式（scaleMode決定 場景內容要怎麼配合裝置螢幕尺寸縮放，這裡先知道有這回 事即可），再呼叫skView.presentScene(scene) 正式把它顯示出來——這一呼叫，就是觸發前面 didMove(to:)被執行的時機。之後想要從一個 場景切換到另一個場景（例如從開始畫面切到遊戲畫面）， 也是再呼叫一次presentScene(_:)，傳入新的 場景即可。
