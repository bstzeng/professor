實作插頁廣告（Interstitial Ad）：強制型廣告的觸發時機與頻率拿捏

這一課的目標

  • 能用GADInterstitialAd.load(withAdUnitID:request:completionHandler:)載入一支插頁廣告，並正確保存載入完成的廣告實例
  • 能在遊戲進入game over畫面這個自然的中斷點，呼叫present(fromRootViewController:)顯示廣告
  • 能在廣告關閉的委派方法裡預先載入下一支廣告，並理解為什麼顯示頻率要有所節制

橫幅廣告完成之後，這一課要實作第52課分類過的第二種格式 ——插頁廣告（interstitial ad）：一支蓋住整個畫面、玩家 必須主動關閉才能繼續的全螢幕廣告。它的視覺衝擊力最強， 但也最容易因為出現的時機或頻率不對，變成惹惱玩家的 來源，這一課會把「怎麼寫」跟「什麼時候該顯示」兩件事 一起講清楚。

1. 載入廣告：GADInterstitialAd.load(withAdUnitID:request:completionHandler:)

跟橫幅廣告不同，插頁廣告不是一個常駐畫面上的view，而是 先在背景載入好、之後才在恰當的時機呼叫出來顯示的一個 物件。先宣告一個變數保存載入完成的廣告實例：

import GoogleMobileAds var interstitialAd: GADInterstitialAd? func loadInterstitialAd() { let request = GADRequest() GADInterstitialAd.load(withAdUnitID: "ca-app-pub-3940256099942544/4411468910", request: request) { [weak self] ad, error in if let error = error { print("插頁廣告載入失敗：\(error.localizedDescription)") return } self?.interstitialAd = ad self?.interstitialAd?.fullScreenContentDelegate = self } }

這裡用的ca-app-pub-3940256099942544/4411468910 同樣是Google官方公開提供、專門給插頁廣告測試用的廣告 單元ID，開發階段請比照第57課的原則使用它，而不是正式 的Ad Unit ID。load(withAdUnitID:request:completionHandler:) 是一個類別方法（static method），載入成功會在回呼裡拿到 一個GADInterstitialAd實例，這裡把它存進 interstitialAd這個變數，並設定 fullScreenContentDelegate，讓後續顯示、 關閉的過程都能收到委派通知。

2. 顯示的時機：遊戲結束畫面，而不是遊戲進行中

插頁廣告最重要的原則，就是只在遊戲流程自然的 中斷點顯示——例如回顧模組H的遊戲狀態機，玩家 輸掉、進入game over狀態的那個時刻，正是一個現成、玩家 本來就會停下來的節點。把顯示廣告的邏輯接在第47課寫過的 endGame()函式裡：

func endGame() { playSound("gameOver.wav") updateHighScoreIfNeeded(currentScore: score) showGameOverScreen() presentInterstitialIfReady() } func presentInterstitialIfReady() { guard let interstitialAd = interstitialAd, let rootVC = self.view?.window?.rootViewController else { return } interstitialAd.present(fromRootViewController: rootVC) }

絕對不要把插頁廣告的顯示邏輯放進遊戲進行中的畫面——例如 球正在飛、玩家正專心操作球拍的當下，這種時機顯示的全螢幕 廣告不只打斷體驗，更常見的結果是玩家在慌亂中誤觸廣告， 兩者都會嚴重傷害玩家對這款遊戲的觀感。

3. 關閉後預先載入下一支廣告

載入一支插頁廣告需要時間，如果每次要顯示前才臨時呼叫 load，玩家很可能等不到廣告準備好。比較好 的做法是實作GADFullScreenContentDelegate， 在上一支廣告被關閉的當下，立刻著手載入下一支，讓它在 下一次game over時已經準備就緒：

extension GameScene: GADFullScreenContentDelegate { func adDidDismissFullScreenContent(_ ad: GADFullScreenPresentingAd) { interstitialAd = nil loadInterstitialAd() } func ad(_ ad: GADFullScreenPresentingAd, didFailToPresentFullScreenContentWithError error: Error) { print("插頁廣告顯示失敗：\(error.localizedDescription)") interstitialAd = nil loadInterstitialAd() } }

adDidDismissFullScreenContent會在玩家關閉 廣告、回到App時被呼叫；因為一支GADInterstitialAd 只能顯示一次，這裡先把舊的實例清成nil， 再重新呼叫loadInterstitialAd()載入新的一支。 如果顯示過程本身失敗（例如網路問題），也一併在 didFailToPresentFullScreenContentWithError 裡做同樣的處理，確保下一次還有機會顯示。

4. 頻率拿捏：不是每次game over都要跳出來

即使插頁廣告已經接到正確的時機點，也不代表每一次觸發 這個時機點就該顯示——太頻繁的插頁廣告，是玩家評價、 留存率下滑最常見的原因之一，也是Apple與Google廣告 聯播網政策明確不鼓勵的做法（過度、干擾性的廣告頻率， 在App Store審查時也可能被認定為不良使用者體驗而導致 退件，後面模組P會更詳細說明審查指南的相關規定）。 實務上常見的做法，是用一個計數器控制顯示的間隔：

var gameOverCount = 0 func presentInterstitialIfReady() { gameOverCount += 1 guard gameOverCount % 3 == 0 else { return } guard let interstitialAd = interstitialAd, let rootVC = self.view?.window?.rootViewController else { return } interstitialAd.present(fromRootViewController: rootVC) }

這段程式碼讓插頁廣告平均每三次game over才顯示一次， 其餘兩次玩家可以直接重新開始，不會每一局結束都被打斷。 實際要抓多少次顯示一次、要不要在玩家剛開始玩的前幾局 完全不顯示，都是可以依實際數據調整的細節，但「不是 每次都跳」這個原則，值得從一開始就寫進邏輯裡。

檢查你的理解

  1. 寫出載入一支插頁廣告、並保存到變數裡的完整程式碼
  2. 說明插頁廣告應該接在打磚塊遊戲的哪個時機點顯示，為什麼不能放在遊戲進行中
  3. 說明為什麼要在adDidDismissFullScreenContent委派方法裡重新呼叫loadInterstitialAd()，以及為什麼顯示頻率需要節制
