模組 H｜實作專案③：遊戲邏輯與狀態管理 · 第 35 課

勝負判定邏輯

這一課的目標

  • 理解怎麼追蹤「磚塊是不是都被消滅了」，藉此判斷玩家獲勝
  • 理解lives歸零代表遊戲失敗，需要觸發對應的處理
  • 學會在勝利、落敗發生時，做出畫面上的對應反應

上一課留了一個缺口：lives會一路被扣成負數， 遊戲也永遠不會判斷「磚塊全部消滅了」代表獲勝。這一課 要把這兩個判斷補齊，讓打磚塊真正變成一款有明確終點的 遊戲——而不是一場永遠打不完的球。

1. 勝利條件：磚塊清空

判斷磚塊是否清空，最直接、效能也最好的做法，是用一個 計數器記錄「還剩多少顆磚塊」，在場景初始化時設成磚塊 總數，之後每消滅一顆就減1：

var bricksRemaining = 0 override func didMove(to view: SKView) { // ...其餘設定 bricksRemaining = bricks.count }

接著在第32、33課的didBegin(_:)裡，磚塊被 移除的同時把計數器減1，並檢查是不是已經歸零：

func didBegin(_ contact: SKPhysicsContact) { let bodyA = contact.bodyA let bodyB = contact.bodyB let brickBody: SKPhysicsBody if bodyA.categoryBitMask == PhysicsCategory.brick { brickBody = bodyA } else if bodyB.categoryBitMask == PhysicsCategory.brick { brickBody = bodyB } else { return } brickBody.node?.removeFromParent() score += 10 scoreLabel.text = "分數：\(score)" bricksRemaining -= 1 if bricksRemaining == 0 { gameWin() } }

另一種比較直覺、但效能較差的替代做法，是不維護計數器， 而是每次都直接算場景裡目前還剩幾個名字是"brick" 的節點：scene.children.filter { $0.name == "brick" }.count == 0。這種寫法不需要額外的變數，邏輯 上更好理解，但每次呼叫都要遍歷整個節點樹，磚塊數量一多 就會比維護一個計數器慢，所以正式專案通常還是採用 bricksRemaining計數器的寫法。

2. 失敗條件：生命值歸零

失敗的判斷則接在第34課的ballLost()之後—— 扣血後檢查lives是否已經小於等於0：

func ballLost() { lives -= 1 livesLabel.text = "生命：\(lives)" if lives <= 0 { gameOver() } else { resetBall() } }

這裡刻意用if／else分開處理：生命值歸零時 不再呼叫resetBall()——沒有意義讓一顆球在 遊戲已經結束的情況下繼續發射，直接進入落敗流程即可。

3. 觸發勝利／失敗的處理

gameWin()跟gameOver()目前先做 最基本的事：暫停場景、顯示一段結果文字。之後第36課的 暫停機制、第37課的狀態機都會讓這部分變得更完整，這一課 先求「能明確判斷勝負、畫面上看得出來」：

func gameWin() { let label = SKLabelNode(fontNamed: "Helvetica-Bold") label.text = "遊戲勝利！" label.fontSize = 36 label.fontColor = .white label.position = CGPoint(x: frame.midX, y: frame.midY) label.zPosition = 20 addChild(label) isPaused = true } func gameOver() { let label = SKLabelNode(fontNamed: "Helvetica-Bold") label.text = "遊戲結束" label.fontSize = 36 label.fontColor = .white label.position = CGPoint(x: frame.midX, y: frame.midY) label.zPosition = 20 addChild(label) isPaused = true }

isPaused = true會讓整個場景的物理模擬跟 動作都暫停下來（下一課會詳細說明這個屬性），先讓球 停在原地、磚塊不再變化，把結果文字清楚地顯示給玩家看。

檢查你的理解

  1. 比較用bricksRemaining計數器跟每次過濾節點樹算磚塊數量，這兩種判斷勝利條件的方式各有什麼優缺點
  2. 說明ballLost()裡為什麼要用if／else分開處理「還有命」跟「沒命了」這兩種情況
  3. 解釋gameWin()跟gameOver()目前用isPaused = true達成了什麼效果
