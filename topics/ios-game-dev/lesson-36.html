重新開始與暫停

這一課的目標

  • 理解SKScene的isPaused屬性，怎麼暫停整個場景的物理與動作
  • 學會用「重新建立場景」的方式實作重新開始，而不是手動一個一個重設變數
  • 做出一個簡單的暫停／重新開始按鈕互動範例

上一課讓遊戲能正確判斷勝負，但玩家看到「遊戲勝利」或 「遊戲結束」的文字之後，除了退出App，沒有任何方法可以 再玩一次。這一課要把兩件事補上：讓玩家能主動暫停遊戲， 以及在結束後，能重新開始一局全新的遊戲。

1. isPaused：暫停整個場景

isPaused是SKScene（其實是它的 父類別SKNode）內建的屬性，設成 true時，這個場景底下所有的物理模擬、 SKAction動作、update(_:)的 遊戲邏輯都會停止推進，畫面就像被按了暫停鍵一樣凍結 住——上一課的gameWin()、gameOver() 正是靠這個屬性讓球停在原地：

isPaused = true // 暫停 isPaused = false // 繼續

要特別注意的是，isPaused只會凍結物理與 動作系統，並不會阻止觸控事件被送進來—— touchesBegan(_:with:)這類方法在場景暫停時 依然會被呼叫，這其實是件好事：暫停狀態下，玩家還是 需要能點擊「繼續」或「重新開始」的按鈕，如果連觸控都 被凍結，就沒辦法跟已暫停的畫面互動了。

2. 重新開始：重新建立一份新的場景

遊戲玩到一半結束後，場景裡累積了許多狀態：分數、 生命值、剩餘磚塊數、球目前的位置與速度、哪些磚塊還在 場上……如果要「重新開始」，手動把每一個變數逐一重設 回初始值，很容易漏掉某個角落（尤其磚塊這種一開始就是 一大群節點的情況）。更穩健、也是SpriteKit常見的做法， 是乾脆整個場景重新建立一次——用一個全新的 GameScene實例，取代舊的那一個：

func restartGame() { guard let view = self.view else { return } let newScene = GameScene(size: self.size) newScene.scaleMode = self.scaleMode view.presentScene(newScene, transition: SKTransition.fade(withDuration: 0.5)) }

self.view是目前這個場景所在的SKView； GameScene(size: self.size)建立一份全新的 場景，所有屬性（包含score、 lives、bricksRemaining）都會 回到宣告時的初始值，didMove(to:)也會重新 跑一次，磚塊陣列會照第26課的排版邏輯整批重新產生； scaleMode需要跟原本的場景設成一樣，畫面 才不會突然跑版；presentScene(_:transition:) 則負責把畫面切換到這個新場景，這裡用了 SKTransition.fade(withDuration:)做一個淡入 淡出的轉場效果，呼應第27課場景切換學過的概念。

3. 簡單的暫停／重新開始按鈕

有了isPaused跟restartGame()， 接著要讓玩家能透過點擊觸發它們。延續第20課學過的觸控 處理，先在場景裡放兩個當按鈕用的SKLabelNode， 再於touchesBegan(_:with:)裡判斷觸控位置是否 落在按鈕範圍內：

let pauseButton = SKLabelNode(text: "暫停") let restartButton = SKLabelNode(text: "重新開始") override func touchesBegan(_ touches: Set, with event: UIEvent?) { guard let touch = touches.first else { return } let location = touch.location(in: self) if pauseButton.contains(location) { isPaused.toggle() return } if restartButton.contains(location) { restartGame() return } // 其餘觸控（例如移動球拍）交給原本的邏輯處理 }

contains(_:)是SKNode內建的 方法，會檢查傳入的座標是否落在這個節點的範圍內； isPaused.toggle()則是Swift布林值常見的寫法， 直接把目前的值反轉，暫停中就繼續、播放中就暫停，不需要 額外寫if／else判斷目前狀態。

檢查你的理解

  1. 說明isPaused = true會影響哪些系統，又不會影響哪些
  2. 解釋為什麼重新開始遊戲時，建立一份全新的場景實例，比手動重設每個變數更穩健
  3. 說明restartGame()裡scaleMode為什麼要跟原本場景設成一樣
