模組 E｜觸控與使用者輸入 · 第 21 課

手勢辨識器

這一課的目標

  • 認識UIGestureRecognizer家族：UITapGestureRecognizer、UISwipeGestureRecognizer、UIPanGestureRecognizer
  • 知道手勢辨識器要加到SKView上，並用target-action接收辨識結果
  • 判斷這門課的打磚塊遊戲，球拍移動該用touches系列還是手勢辨識器

上一課用touchesBegan、touchesMoved、touchesEnded拿到的是 最原始、逐幀更新的觸控資料，什麼都要自己判斷。但很多 常見的手勢——點一下、往某個方向滑一下、用手指拖曳—— UIKit早就包裝成現成的UIGestureRecognizer子 類別，不需要自己計算方向或判斷距離，是另一種處理輸入的 方式。

1. UIGestureRecognizer家族總覽

這門課會用到的三種手勢辨識器，各自對應不同的操作情境：

類別辨識的手勢常見用途
UITapGestureRecognizer點一下（可設定次數、手指數）暫停鍵、開始畫面的「點一下開始」
UISwipeGestureRecognizer朝固定方向快速滑動切換選單、翻頁
UIPanGestureRecognizer手指按住並持續拖曳拖曳式操作、鏡頭平移

2. 加到SKView上，而不是SKScene

手勢辨識器是UIKit的元件，要加在UIView上—— 對SpriteKit來說就是承載場景的SKView，而不是 SKScene本身。最自然的時機，是在場景的 didMove(to:)裡，透過拿到的view 參數加上去：

override func didMove(to view: SKView) { let tapRecognizer = UITapGestureRecognizer( target: self, action: #selector(handlePauseTap) ) view.addGestureRecognizer(tapRecognizer) } @objc private func handlePauseTap(_ recognizer: UITapGestureRecognizer) { togglePause() }

target: self把辨識到手勢後要通知的對象設成 場景自己，action: #selector(handlePauseTap) 指定要呼叫的方法。因為手勢辨識器底層用的是Objective-C 的selector機制，被指定的方法前面要加上@objc， 而SKScene本身繼承自NSObject， 所以可以直接當target，不需要額外處理。

3. 這門課怎麼選：touches系列還是手勢辨識器

兩種方式並不是互斥的，甚至可以在同一個場景裡並存， 差別在於它們各自比較適合的情境：

  • 需要連續、精確追蹤手指位置——例如 打磚塊遊戲裡球拍要跟著手指左右移動，這種每一幀都要 知道最新x座標的需求，上一課學的touchesMoved 反而更直接，不需要額外包一層手勢辨識器
  • 只在意「發生了什麼手勢」，不在意過程細節 ——例如暫停鍵只需要知道「有沒有被點一下」， UITapGestureRecognizer幫你把整個判斷邏輯 都寫好了，比自己在touchesBegan／touchesEnded裡判斷 「是不是點在按鈕範圍內、有沒有拖出範圍」簡潔很多

所以這門課接下來實作球拍時，會延續上一課 touchesMoved的模式；等到模組H加入暫停功能 時，才會用UITapGestureRecognizer處理暫停鍵 這類單純的點擊互動。

小提醒：兩者同時使用時的注意事項

如果場景上同時有覆寫touchesBegan／touchesMoved，又替 同一個SKView加了手勢辨識器，某些情況下手勢辨識器可能 會「吃掉」原始的觸控事件，讓場景收不到完整的touches 序列。實務上的作法通常是分工清楚：需要連續追蹤的區域 （例如球拍操作區）用touches系列處理，獨立的按鈕（例如 暫停鍵）才用手勢辨識器，避免兩者互相干擾。

檢查你的理解

  2. 說明手勢辨識器應該加到SKView還是SKScene上
  3. 針對打磚塊遊戲的球拍移動，為什麼touches系列的持續追蹤比手勢辨識器更合適
