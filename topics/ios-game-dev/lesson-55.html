模組 M｜App內廣告整合 · 第 55 課

申請AdMob帳號與建立廣告單元

這一課的目標

  • 能完成AdMob帳號註冊，並在後台建立一個App項目
  • 理解App ID的用途與格式，知道它是整個App在AdMob裡的識別碼
  • 能為橫幅、插頁、獎勵型三種廣告格式分別建立對應的廣告單元，並理解Ad Unit ID與App ID的差異

決定好用AdMob之後，這一課要離開概念層面，實際到AdMob 後台把帳號跟必要的ID都準備好——這些ID會在第56課裝 SDK、第57～59課實作三種廣告時直接用到。

1. 註冊AdMob帳號

到admob.google.com，用一組既有的Google 帳號登入（沒有的話可以直接申請一組新的）。第一次登入 會需要同意AdMob的服務條款，並填寫一些帳戶層級的資訊 （例如所在國家、時區）。要開始請求測試廣告、把SDK 接進App，這個階段就已經足夠；真正要收到廣告收入的 款項，之後還需要在後台補上付款方式與稅務資訊，但這 不影響現在先把開發階段的整合流程走完。

2. 在AdMob後台建立「App」項目

登入後台後，找到「Apps（應用程式）」區塊，點選新增 App。系統會先詢問這個App的平台（選iOS），以及是否 已經在App Store上架——因為打磚塊遊戲這時候還在開發 階段、尚未上架，這裡選擇「否」，之後可以在真正上架後 回頭補上App Store的連結。輸入App名稱等基本資訊送出後， AdMob會為這個App產生一組專屬的App ID， 格式看起來像這樣：

ca-app-pub-XXXXXXXXXXXXXXXX~XXXXXXXXXX

中間用~（波浪號）分隔——前半段是你AdMob 帳戶專屬的發布商代碼，後半段則是這個App專屬的編號。 這組App ID代表的是整個App，第56課會 把它填進Info.plist，讓Google Mobile Ads SDK知道目前 是哪一個App在請求廣告。

3. 建立廣告單元：橫幅、插頁、獎勵型各一個

有了App項目之後，進到這個App底下的「Ad units（廣告 單元）」頁面，點選新增廣告單元。每建立一個廣告單元， 都要先選擇它的廣告格式（Banner／ Interstitial／Rewarded），再取一個容易辨識的名稱， 例如Breakout_Banner_遊戲畫面、 Breakout_Interstitial_遊戲結束、 Breakout_Rewarded_復活，方便日後在後台 報表裡分辨各個版位的表現。這款打磚塊遊戲對應第52課 規劃的三個廣告位置，需要分別建立三個廣告單元——每 建立一個，AdMob都會產生一組獨立的Ad Unit ID，格式類似：

ca-app-pub-XXXXXXXXXXXXXXXX/XXXXXXXXXX

注意這裡的分隔符號是/（斜線），跟App ID 用的~不一樣。前半段一樣是同一組發布商 代碼，後半段則是這一個特定廣告版位 的專屬編號——同一個App底下的橫幅、插頁、獎勵型廣告， 會各自拿到不同的Ad Unit ID。

4. App ID vs Ad Unit ID：新手最容易搞混的兩個東西

這是整合AdMob時最常讓新手混淆的地方，值得對照著記清楚：

App IDAd Unit ID
代表什麼整個App本身App裡的某一個廣告版位／格式
分隔符號波浪號 ~斜線 /
用在哪裡Info.plist的GADApplicationIdentifier（第56課）個別GADBannerView／GADInterstitialAd／GADRewardedAd的adUnitID（第57～59課）
一個App有幾個固定只有一個依照廣告格式與版位數量，可以有多個

檢查你的理解

  1. 說明在AdMob後台建立一個App項目之後，會拿到什麼、格式大致長什麼樣
  2. 說明這款打磚塊遊戲需要建立幾個廣告單元，各自對應什麼格式
  3. 用自己的話解釋App ID跟Ad Unit ID的差異，包含分隔符號與各自的用途
