模組 K｜資料儲存與遊戲設定 · 第 48 課

模組總結：簡易設定畫面

這一課的目標

  • 能做出一個簡單的設定畫面，讓玩家可以自己開關音效
  • 能用UserDefaults儲存這個開關狀態，並在每次要播放音效前先檢查它
  • 回顧模組K兩堂課的UserDefaults基礎與最高分儲存邏輯，銜接下一模組的效能優化與除錯主題

前兩課分別學了UserDefaults的基本讀寫（第46課），以及一段 實際會用到的完整邏輯——判斷、比較、只在需要時才寫回的 最高分儲存（第47課）。模組K收尾的這一課，要把同一套 機制套進另一個幾乎每款遊戲都會有的畫面：一個能讓玩家 自己決定要不要聽音效的簡易設定畫面。

一個開關，一個key：soundEnabled

這個設定畫面的核心其實只有一件事——一個能切換的開關 （可以是SpriteKit場景裡一個可觸控的SKLabelNode， 也可以是UIKit的UISwitch），對應一個 UserDefaults的key。這裡沿用第46課示範過的 "soundEnabled"這個key：

func toggleSound() { let current = UserDefaults.standard.bool(forKey: "soundEnabled") UserDefaults.standard.set(!current, forKey: "soundEnabled") updateToggleLabel() } func updateToggleLabel() { let isOn = UserDefaults.standard.bool(forKey: "soundEnabled") soundToggleLabel.text = isOn ? "音效：開" : "音效：關" }

每次玩家點擊這個開關節點，就讀出目前值、反轉它、寫 回去，再更新畫面上顯示的文字，讓玩家清楚看到目前的 狀態——這跟第47課讀取、比較、寫回的三步驟結構其實 是同一種思路。

別忽略的細節：第一次啟動時的預設值

這裡有一個容易踩到的陷阱——第46課提過， bool(forKey:)在key不存在時會回傳 false。如果什麼都不做，玩家第一次打開這款 遊戲、還沒點過設定畫面的開關，音效就會被判定成「關閉」， 但大多數遊戲其實希望音效預設是開著的。解法是在App一 啟動時，就呼叫UserDefaults.standard.register(defaults:)， 先「登記」一個預設值：

UserDefaults.standard.register(defaults: ["soundEnabled": true])

register(defaults:)不會真的把值寫進磁碟， 只是告訴UserDefaults「如果這個key還沒有人明確設定過， 讀取時就當作是這個值」。玩家還沒碰過設定畫面時， bool(forKey: "soundEnabled")就會讀到 true；一旦玩家自己點過開關、 set(_:forKey:)寫入過明確的值， register(defaults:)登記的預設值就不會再 蓋過它。這行程式碼通常放在App啟動時只會執行一次的 地方，例如第一個場景的didMove(to:)裡。

播放音效前，先檢查這個設定

把第38課直接呼叫SKAction.playSoundFileNamed 的地方，改包成一個統一的輔助函式，在真正播放之前先讀 一次這個設定：

func playSound(_ fileName: String) { guard UserDefaults.standard.bool(forKey: "soundEnabled") else { return } run(SKAction.playSoundFileNamed(fileName, waitForCompletion: false)) }

遊戲裡任何原本會發出聲音的地方——球拍碰撞、磚塊消失、 第47課endGame()裡的遊戲結束音效——只要 統一改成呼叫這個playSound(_:)，就會自動 尊重玩家在設定畫面裡做的選擇，不需要在每一個呼叫音效 的地方各自重複判斷一次。

回顧模組K，銜接模組L

模組K三堂課，從最基礎的UserDefaults讀寫（第46課），到 一段實際的判斷邏輯（第47課的最高分儲存），最後在這一課 整合出一個玩家真的看得到、摸得到的設定畫面。三堂課背後 其實是同一件事：讓遊戲不再是「一關掉App就全部歸零」的 狀態。下一個模組L要換一個角度，處理開發過程中另外兩個 不可或缺的主題——除錯與效能優化，教你在遊戲邏輯出錯， 或是玩起來卡卡的時候，該用什麼工具系統化地找出問題。

檢查你的理解

  1. 說明register(defaults:)的作用，以及為什麼這門課要在設定soundEnabled這個key時特別呼叫它
  2. 寫出（或說明）一個切換音效開關的完整邏輯：讀取、反轉、寫回
  3. 說明為什麼把播放音效的程式碼包成playSound(_:)這樣一個函式，會比在每個要發出聲音的地方各自檢查UserDefaults更好
