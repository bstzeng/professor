模組 G｜實作專案②：物理引擎與碰撞 · 第 32 課

模組總結：球、球拍、磚塊的完整互動

這一課的目標

  • 把模組G學到的physics body、重力／速度、contactDelegate、bitmask四個環節，串成一套完整能動的碰撞系統
  • 讀懂一份完整的didBegin(_:)實作，知道怎麼判斷「這次撞到的是不是磚塊」
  • 能自己檢查一輪：球拍擋得住球、球撞到邊界會反彈、球撞到磚塊磚塊會消失

模組G花了四課，分別處理physics body的形狀與動態屬性 （第28課）、重力歸零與初始速度（第29課）、 contactDelegate的通知機制（第30課）、以及分類用的三種 bitmask（第31課）。這一課不引入新概念，而是把這四塊 接起來，寫出一份真正完整、可以執行的碰撞邏輯，讓球拍、 球、磚塊之間第一次有了「玩得起來」的互動。

完整的physicsBody設定回顧

先把整個場景初始化時該做的physics設定，整理成一個 清楚的didMove(to:)——包含物理世界本身的 設定，以及三種節點各自的physics body：

override func didMove(to view: SKView) { physicsWorld.gravity = CGVector(dx: 0, dy: 0) physicsWorld.contactDelegate = self let border = SKPhysicsBody(edgeLoopFrom: self.frame) border.categoryBitMask = PhysicsCategory.wall self.physicsBody = border paddle.physicsBody = SKPhysicsBody(rectangleOf: paddle.size) paddle.physicsBody?.isDynamic = false paddle.physicsBody?.categoryBitMask = PhysicsCategory.paddle paddle.physicsBody?.collisionBitMask = PhysicsCategory.ball ball.physicsBody = SKPhysicsBody(circleOfRadius: ball.size.width / 2) ball.physicsBody?.isDynamic = true ball.physicsBody?.affectedByGravity = false ball.physicsBody?.restitution = 1.0 ball.physicsBody?.friction = 0 ball.physicsBody?.linearDamping = 0 ball.physicsBody?.categoryBitMask = PhysicsCategory.ball ball.physicsBody?.collisionBitMask = PhysicsCategory.paddle | PhysicsCategory.wall ball.physicsBody?.contactTestBitMask = PhysicsCategory.brick ball.physicsBody?.velocity = CGVector(dx: 140, dy: -220) for brick in bricks { brick.physicsBody = SKPhysicsBody(rectangleOf: brick.size) brick.physicsBody?.isDynamic = false brick.physicsBody?.categoryBitMask = PhysicsCategory.brick brick.physicsBody?.collisionBitMask = PhysicsCategory.none } }

這裡多用到一個第28、31課還沒提到的寫法： SKPhysicsBody(edgeLoopFrom: self.frame)， 它會沿著場景邊界建立一圈沒有厚度、不會移動的physics body，讓球撞到畫面的上、左、右邊時能自然反彈——這正是 第31課PhysicsCategory.wall對應的實體。 （螢幕底部通常刻意不算進反彈邊界，讓球能真的掉出畫面， 這件事留到模組H處理生命值時再實作。）

didBegin(_:)：分辨誰撞到誰

有了分類設定，didBegin(_:)裡就能用 categoryBitMask判斷這次撞到的兩個body裡， 哪一個是磚塊：

func didBegin(_ contact: SKPhysicsContact) { let bodyA = contact.bodyA let bodyB = contact.bodyB let brickBody: SKPhysicsBody if bodyA.categoryBitMask == PhysicsCategory.brick { brickBody = bodyA } else if bodyB.categoryBitMask == PhysicsCategory.brick { brickBody = bodyB } else { // 這次碰撞跟磚塊無關，直接結束 return } brickBody.node?.removeFromParent() }

先用if／else if找出兩個body裡哪一個是磚塊 （因為didBegin(_:)不保證磚塊一定放在 bodyA還是bodyB，兩種情況都要 判斷），如果兩個都不是磚塊，就直接return， 不做任何事——記得球的contactTestBitMask目前 只包含brick，所以理論上這個函式只會在球撞 磚塊時被呼叫，但寫上判斷式仍是穩健的好習慣，未來 擴充更多碰撞情境（例如模組I要加的撞牆音效）時也不會 互相干擾。

移除磚塊：removeFromParent()

brickBody.node是一個optional的 SKNode?，指回physics body所依附的那個節點 （也就是磚塊本身的SKSpriteNode）；呼叫它的 removeFromParent()，會把這個節點從場景的 節點樹上移除（回顧第16課的節點樹概念）——移除後這顆 磚塊就不會再被畫出來，也不再參與物理模擬，等於完成了 「撞到即消滅」的效果。

動手驗證：這一課該看到的效果

把這一課的程式碼接上專案後，執行遊戲應該會看到：球從 畫面中間往下發射，碰到左右與上方邊界會反彈、碰到球拍 也會反彈，而球拍可以用第20、21課學過的觸控來左右移動 擋球；球撞到任何一顆磚塊時，那顆磚塊會立刻從畫面上 消失。如果磚塊沒有消失，優先檢查 contactTestBitMask是否漏設，以及 GameScene是否確實遵循了 SKPhysicsContactDelegate。
