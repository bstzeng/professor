Sprite Sheet基礎概念

這一課的目標

  • 理解sprite sheet／texture atlas的概念：把多張相關圖片打包成一份素材
  • 學會用Xcode的.atlas資料夾慣例，讓Xcode自動幫你打包圖集
  • 能用SKTextureAtlas在程式碼裡載入圖集裡的個別圖片，並理解圖集為什麼能改善效能

有了素材來源，下一個實際問題是：一個像磚塊爆炸這樣的 動畫效果，往往需要好幾張連續的圖片（一張一張畫出爆炸 逐漸擴散的樣子）。如果每張圖都是專案裡各自獨立的檔案， 管理起來既凌亂，執行時的效能也不理想。這就是sprite sheet（也叫texture atlas，圖集）要解決的問題。

1. 什麼是Sprite Sheet（Texture Atlas）

Sprite sheet／texture atlas的概念很直接：把多張相關的 圖片（例如一組動畫的每一幀、或是一組UI圖示）打包成一份 素材，而不是各自獨立的散落檔案。這樣做除了讓專案結構 更整齊、相關的圖片放在一起容易管理之外，稍後會看到， 在渲染效能上也有實際好處。

2. Xcode的.atlas資料夾慣例

Xcode提供了一個很方便的慣例來建立圖集：在Project Navigator裡建立一個資料夾，把資料夾命名成 某個名稱.atlas的格式（例如 BrickBreak.atlas），再把個別的圖片檔案， 依照順序命名放進這個資料夾裡（例如 brickBreak_0.png、brickBreak_1.png ……）。只要資料夾名稱以.atlas結尾，Xcode在 建置時就會自動辨識、把裡面所有圖片打包成一份最佳化過的 合併圖集，開發者完全不需要自己動手拼接圖片，也不用手動 跑額外的打包工具，程式碼裡照樣用原本的檔名引用個別 圖片就好。

3. 用SKTextureAtlas載入與使用

程式碼裡透過SKTextureAtlas載入這個資料夾， 再用textureNamed(_:)取出個別的貼圖：

let explosionAtlas = SKTextureAtlas(named: "BrickBreak") var frames: [SKTexture] = [] for i in 0..<6 { let textureName = "brickBreak_\(i)" frames.append(explosionAtlas.textureNamed(textureName)) } let animation = SKAction.animate(with: frames, timePerFrame: 0.05) brick.run(SKAction.sequence([animation, SKAction.removeFromParent()]))

SKTextureAtlas(named:)用資料夾名稱（不含 .atlas副檔名）載入整個圖集； textureNamed(_:)則用個別圖片原本的檔名（不含 副檔名）取出對應的SKTexture。這裡刻意用 迴圈搭配已知的命名規則（brickBreak_0、 brickBreak_1……）逐一組出檔名，而不是直接 依賴圖集的textureNames屬性——因為那個屬性 回傳的順序不保證跟原本的動畫順序一致，用固定的命名規則 自己組檔名，動畫幀的順序才會穩定正確。組好陣列後，交給 SKAction.animate(with:timePerFrame:)，就會 像播放逐格動畫一樣，依序切換這些貼圖。

4. 為什麼圖集能改善渲染效能

GPU在渲染畫面時，理想狀況是把使用「同一份貼圖來源」的 多個sprite盡量合併成一次繪製呼叫（draw call）一起處理； 如果場景裡的sprite各自使用不同的獨立圖片檔案，渲染器 往往需要在繪製之間不斷切換貼圖（texture swap），這帶來 額外的效能開銷。把多張小圖打包進同一份圖集之後， SpriteKit能把使用同一個圖集的sprite合併批次繪製，減少 貼圖切換與繪製呼叫的次數——當畫面上同時有大量小型 sprite（例如整排的磚塊）時，這個差異會更明顯。
