生命值系統

這一課的目標

  • 加入lives變數，追蹤玩家剩餘的生命數
  • 學會偵測球掉到球拍下方、掉出畫面底部的情況，判斷玩家漏接了球
  • 學會在漏接後扣血、把球重新放回起始位置並給予新的初始速度，讓玩家能重新發球

第32課建立場景邊界physics body時，特別提到畫面底部通常 刻意不列入反彈範圍——原因就在這一課：底部不反彈，球 才有可能真的「掉出去」，也才需要一套生命值系統，來 處理玩家沒接到球之後該怎麼辦。

1. 宣告lives變數

跟分數一樣，先在GameScene加入一個追蹤生命 值的屬性，打磚塊常見的起始生命數是3，也可以額外加一個 label顯示在畫面上（作法跟第33課的scoreLabel 相同，這裡不重複列出）：

var lives = 3 let livesLabel = SKLabelNode(fontNamed: "Helvetica-Bold")

2. 偵測球掉出畫面底部

因為場景邊界的physics body刻意不包含底部，球掉出畫面 下緣時不會觸發任何碰撞通知，所以沒辦法靠 didBegin(_:)偵測——必須改用另一種方式：在 每一幀的update(_:)裡，主動檢查球目前的 position.y是不是已經低於畫面底部。回顧 第18課的座標系統，SKScene預設的anchorPoint 是(0, 0)，代表場景左下角就是座標 (0, 0)，所以「球掉出底部」等於球的 position.y小於0：

override func update(_ currentTime: TimeInterval) { if ball.position.y < 0 { ballLost() } }

這種在update(_:)裡每一幀主動檢查的方式， 稱為輪詢（polling），是判斷「某個持續變化的狀態是否 跨過一個邊界值」最直接的做法，很適合這種場景邊界沒有 physics body可以依靠的情況。

3. 扣血與重新發球：ballLost()

把「漏接一次球該做的事」整理成一個獨立的函式，包含 扣血、更新畫面文字、把球重新放回起始位置：

func ballLost() { lives -= 1 livesLabel.text = "生命：\(lives)" resetBall() } func resetBall() { ball.position = CGPoint(x: frame.midX, y: frame.midY) ball.physicsBody?.velocity = CGVector(dx: 140, dy: -220) }

resetBall()把球放回畫面正中央，再重新指定 一次velocity——這一步不能省略，因為球掉出 底部之後，原本的velocity可能已經是朝下的方向，如果不 重新設定，球一移回中央就會立刻再次往下掉出畫面。

每失去一條命，畫面上發生了什麼

整理一下漏接一次球的完整流程：球的y座標低於0觸發 ballLost()→ lives減1、 livesLabel文字同步更新 → 球被瞬間移回畫面 中央、並重新獲得一組初始速度，讓玩家能立刻繼續遊戲。 目前這個版本還沒有檢查lives是不是已經歸 零——如果扣到負數，遊戲會繼續讓球一直重生，這個問題 留到下一課的勝負判定邏輯處理。

檢查你的理解

  1. 說明為什麼球掉出畫面底部無法靠didBegin(_:)偵測，需要改用update(_:)輪詢
  2. 解釋resetBall()裡為什麼一定要重新設定velocity，而不能只改position
  3. 說明目前ballLost()的實作，還缺少哪個判斷，可能會讓lives一路扣成負數

下一課預告

下一課要補上這一課留下的缺口，正式處理勝負判定邏輯—— 判斷磚塊是不是已經全部消滅（獲勝），以及 lives是不是已經歸零（落敗），並且在這兩種 情況發生時，讓遊戲對應地做出反應。
