模組 E｜觸控與使用者輸入 · 第 22 課

模組總結：把觸控轉換成遊戲動作

這一課的目標

  • 統整模組E學到的touchesBegan／Moved／Ended與手勢辨識器兩種輸入方式
  • 掌握把觸控x座標轉換成球拍水平移動的核心公式，並加上邊界限制
  • 在模組F實際建立球拍之前，先看過一次完整的移動邏輯雛形

模組E兩課分別學了SpriteKit處理輸入的兩套機制：第20課的 touches系列方法，讓場景可以逐幀拿到觸控點的位置；第21課 的UIGestureRecognizer家族，把「點一下」「滑一下」這類 高階手勢包裝成現成的元件。這一課要把兩者收斂成打磚塊 遊戲實際會用到的東西：一段能把觸控位置轉換成球拍移動、 而且不會讓球拍滑出畫面的邏輯。

從觸控位置到球拍位置

球拍只需要左右移動，所以核心邏輯很單純：在 touchesMoved裡拿到觸控點的x座標，直接指定 給球拍的position.x，讓球拍的水平位置永遠 跟手指目前的x座標一致：

override func touchesMoved(_ touches: Set<UITouch>, with event: UIEvent?) { guard let touch = touches.first else { return } let location = touch.location(in: self) paddle.position.x = location.x }

這段程式碼已經能讓球拍跟著手指移動，但有一個明顯的問題： 如果手指滑到螢幕最左或最右邊，球拍會被帶著一路滑出畫面， 變成半個球拍甚至整個球拍都看不到。

加上邊界限制：clamp

解法是在指定position.x之前，先把值限制在 合理範圍內——這個技巧叫做clamp（夾住），概念是「不小於 下限、也不大於上限」。因為球拍本身有寬度，下限跟上限 還要各自扣掉／加上半個球拍寬，球拍的邊緣才會剛好貼齊 畫面邊界，而不是球拍的中心點：

override func touchesMoved(_ touches: Set<UITouch>, with event: UIEvent?) { guard let touch = touches.first else { return } let location = touch.location(in: self) let halfPaddleWidth = paddle.size.width / 2 let minX = frame.minX + halfPaddleWidth let maxX = frame.maxX - halfPaddleWidth paddle.position.x = min(max(location.x, minX), maxX) }

max(location.x, minX)確保結果不會小於 minX；外層再包一層min(..., maxX) 確保結果也不會大於maxX。兩層函式疊在一起， 就是最常見的clamp寫法：不管手指滑到螢幕外多遠，球拍的 position.x永遠會被夾在minX和 maxX之間。

模組E學到了什麼

整理一下模組E兩課建立的兩種輸入處理方式，以及它們在這 門課裡各自的定位：

方式特性這門課的用途
touches系列逐幀取得原始觸控位置，需要自己判斷邏輯球拍的連續移動（模組F）
UIGestureRecognizer包裝好的高階手勢，處理離散事件暫停鍵等單純的點擊互動（模組H）
