碰撞偵測delegate

這一課的目標

  • 理解SKPhysicsContactDelegate這個protocol的角色，呼應第9課學過的protocol概念
  • 學會在didMove(to:)裡把physicsWorld.contactDelegate設成self，讓場景開始接收碰撞通知
  • 理解didBegin(_:)什麼時候會被呼叫，以及SKPhysicsContact帶了哪些資訊

上一課讓球開始在畫面裡彈來彈去，撞到球拍、牆壁時也 會自然反彈——但這只是物理引擎自己在處理「彈開」這件 事，我們的程式碼完全不知道碰撞發生過。要讓球撞到磚塊 時能真的把磚塊消滅、要讓球掉出畫面時能扣血，都需要在 碰撞發生的當下，收到一個「這裡剛剛撞到了」的通知—— 這正是SKPhysicsContactDelegate要解決的問題。

1. 回顧protocol：一份「承諾實作」的合約

第9課介紹過，protocol是一份定義了「必須實作哪些方法或 屬性」的合約，任何型別只要宣告遵循某個protocol，就承諾 會提供合約要求的實作。SKPhysicsContactDelegate 正是SpriteKit框架定義好的一個protocol——它要求遵循者 實作didBegin(_:)方法（didEnd(_:) 則是選擇性的），讓物理引擎知道「碰撞發生時，要呼叫你 這個方法」。

2. 讓GameScene遵循SKPhysicsContactDelegate

要遵循一個protocol，只要在型別宣告後面加上protocol 名稱即可，跟繼承類別的語法寫在同一個位置、用逗號分開：

class GameScene: SKScene, SKPhysicsContactDelegate { // ... }

這裡GameScene繼承自SKScene， 同時遵循SKPhysicsContactDelegate這個 protocol——繼承只能有一個父類別，但protocol可以同時 遵循多個，用逗號一直接下去即可。

3. 設定contactDelegate

單純遵循protocol還不夠，還要明確告訴physics world「碰撞 發生時，通知的對象就是我」，這件事透過 physicsWorld.contactDelegate屬性完成，通常 放在didMove(to:)裡，跟第29課設定重力的地方 放在一起：

override func didMove(to view: SKView) { physicsWorld.gravity = CGVector(dx: 0, dy: 0) physicsWorld.contactDelegate = self // 球拍、球、磚塊的physics body設定... }

physicsWorld是每個SKScene都有的屬性，代表 整個場景共用的物理世界；把contactDelegate 設成self（也就是這個GameScene自己）， 物理引擎才會在偵測到碰撞時，主動呼叫這個場景實作的 didBegin(_:)。

4. 實作didBegin(_:)：碰撞發生時做什麼

didBegin(_:)的參數是一個SKPhysicsContact， 裡面記錄了這次碰撞的資訊，最常用到的是bodyA 跟bodyB——兩個發生碰撞的SKPhysicsBody （另外還有contactPoint碰撞座標、 collisionImpulse碰撞力道等資訊，先有印象即可）：

func didBegin(_ contact: SKPhysicsContact) { let bodyA = contact.bodyA let bodyB = contact.bodyB // 之後會用bodyA.node、bodyB.node取得對應的SKNode， // 判斷這次碰撞是「誰」撞到「誰」 }

目前先把這個空殼實作出來，讓專案能夠編譯、也能在中斷點 或print裡確認碰撞真的有被偵測到。要注意的 是，didBegin(_:)並不是「兩個物理body只要 彼此靠近」就一定會呼叫——它只在雙方的 contactTestBitMask設定允許的情況下才會觸發， 這正是下一課要處理的碰撞分類問題。
