Optional：處理「可能不存在的值」

這一課的目標

  • 理解Optional型別（T?）在解決什麼問題，以及它跟一般型別的差異
  • 學會用if let、guard let安全地把Optional的值取出來用
  • 認識可選鏈?.、nil合併運算子??，並知道強制解包!為什麼危險

上一課提到的Int、String這些型別，宣告出來之後一定「有 一個值」。但寫程式的過程中，常常會遇到「這裡可能有值， 也可能什麼都沒有」的情況——例如遊戲畫面還沒被載入之前， 代表這個畫面的變數就還不存在。Swift用Optional （可選型別）這個機制，把「這個值有可能不存在」 這件事，直接寫進型別系統裡，而不是讓程式在執行到一半時 意外爆炸。這是Swift最有特色、也是後面SpriteKit程式碼裡 會不斷出現的概念，值得花一整課扎實搞懂。

1. 什麼是Optional：可能不存在的值

在型別後面加上一個問號?，就宣告了一個 Optional型別，代表「這個變數要嘛裝著某個值，要嘛就是 nil（什麼都沒有）」：

var playerName: String? = "Alex" // 有值的情況 var savedScore: Int? = nil // 目前沒有值 playerName = nil // 合法，Optional的值可以被設回nil

關鍵在於：String?跟String是 兩種不同的型別——一個一般的String 永遠保證裡面有內容，但String?必須先確認 「裡面真的有值」，才能像一般字串一樣使用它，這個確認、 取出值的過程，Swift稱為解包（unwrapping）。

2. 安全解包：if let與guard let

最常見、也最安全的解包方式，是用if let： 如果Optional裡面真的有值，就把值取出來、賦予一個新的 名稱，並進入接下來的程式區塊；如果是nil， 就直接跳過那個區塊：

var savedScore: Int? = 120 if let score = savedScore { print("讀到之前的分數：\(score)") } else { print("沒有存過分數") }

另一種常用的寫法是guard let，通常用在函式 一開始，「如果拿不到值就提早結束」的情境（第7課會完整 介紹guard）：

func loadScore(_ savedScore: Int?) { guard let score = savedScore else { print("沒有存過分數，使用預設值0") return } print("讀到之前的分數：\(score)") }

if let跟guard let做的事情 很類似，差別在於guard let解包失敗時一定要 離開目前的作用域（例如return），寫法上更 適合「先檢查條件、不符合就提早離開」的流程。

3. 可選鏈與nil合併運算子

可選鏈（optional chaining）用?. 表示，可以在Optional的值上安全地連續呼叫屬性或方法—— 只要鏈中有任何一環是nil，整條鏈就直接 回傳nil，而不會讓程式意外中斷：

let currentView = self.view?.frame.width

這行程式碼稍微提前預告：後面SpriteKit裡，self.view 本身就是一個Optional（因為場景不一定已經被放進畫面裡）， 用?.而不是直接用.，代表「如果 view目前是nil，就別繼續往下取 frame.width了，整句直接得到nil」。

nil合併運算子（nil-coalescing operator） 用??表示，用來給Optional一個「萬一是 nil時的預設值」：

let savedScore: Int? = nil let score = savedScore ?? 0 // savedScore是nil，所以score會是0

4. 強制解包：能避免就避免

Swift還提供了在型別或變數後面加驚嘆號!的 強制解包（force unwrapping），直接跳過 檢查、假設裡面一定有值：

let savedScore: Int? = nil let score = savedScore! // 執行時直接當機（crash）！

警告：強制解包一個nil，App會直接閃退

!等於是在跟編譯器說「我保證這裡一定有值， 不用檢查了」——如果保證是錯的，實際上是nil， App會在執行的當下直接當機閃退，而且 這種錯誤在寫程式的當下編譯器不會擋下來，往往要到使用者 實際操作時才會爆出來，非常難排查。新手階段的建議是： 盡量避免使用!，改用 if let、guard let或?? 安全處理；只有在你百分之百確定這個值不可能是nil （例如剛用常數賦值、邏輯上不可能失敗），才考慮使用它。
