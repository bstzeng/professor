函式與閉包

這一課的目標

  • 能寫出帶參數、回傳型別、預設參數值的Swift函式
  • 看懂閉包的完整語法，以及更常見的尾隨閉包寫法
  • 理解為什麼閉包在SpriteKit與後續廣告整合裡會不斷出現

有了變數、型別、Optional這些基礎，這一課要學怎麼把一段 邏輯包裝成可以重複使用的單位——函式，以及函式的一個 近親、之後會非常常見的東西——閉包。

1. 函式：把邏輯包裝起來重複使用

Swift用func關鍵字定義函式，接著是函式名稱、 括號裡的參數列表（每個參數要寫名稱跟型別），以及用 ->標示的回傳型別：

func addScore(current: Int, points: Int) -> Int { return current + points } let newScore = addScore(current: 100, points: 20) // newScore是120

如果函式不需要回傳任何值，可以省略->跟 回傳型別：

func logGameOver(finalScore: Int) { print("遊戲結束，最終分數：\(finalScore)") }

Swift的函式還支援預設參數值——呼叫時 如果不特別指定，就會用預先寫好的值：

func resetGame(startingLives: Int = 3) { print("遊戲重新開始，生命值：\(startingLives)") } resetGame() // 使用預設值3 resetGame(startingLives: 5) // 明確指定5

這在遊戲開發裡很實用——例如打磚塊遊戲重新開始時，大多 情況都用同一組預設生命值，只有少數特殊模式才需要傳入 不同的數字，用預設參數值可以讓大部分的呼叫寫起來更簡短。

2. 閉包：可以到處傳遞的一段程式碼

閉包（closure）本質上是一段「沒有名字 的函式」，可以被賦值給變數、當作參數傳給另一個函式、 或是在需要的時候才被呼叫執行。完整的閉包語法長這樣：

let showGameOver = { (finalScore: Int) -> Void in print("遊戲結束！分數：\(finalScore)") } showGameOver(80)

拆開來看：花括號{ }包住整個閉包；括號裡是 參數列表，寫法跟函式的參數很像；-> Void 表示這個閉包不回傳任何值（Void代表「沒有 回傳值」，等同於省略回傳型別）；in之後才是 真正要執行的程式碼。

3. 尾隨閉包：更常見的簡化寫法

當一個函式的最後一個參數是閉包時，Swift 允許把這個閉包移到函式呼叫的括號外面，寫法會清爽很多， 這叫做尾隨閉包（trailing closure）：

func runAfterDelay(seconds: Double, action: () -> Void) { // 概念示意：延遲seconds秒之後，執行action這個閉包 action() } // 一般寫法：閉包當成參數放在括號裡 runAfterDelay(seconds: 1.0, action: { print("一秒後執行") }) // 尾隨閉包寫法：閉包移到括號外面 runAfterDelay(seconds: 1.0) { print("一秒後執行") }

這兩種寫法效果完全一樣，但尾隨閉包在實際的SpriteKit、 UIKit程式碼裡是壓倒性常見的寫法，值得先熟悉它的長相。

先有印象就好，不用現在全部背熟

閉包的語法初次看到常常覺得抽象，但它的核心概念其實 很直覺：「先把一段之後要執行的動作準備好，等時機到了 再觸發」。模組D會看到SpriteKit用尾隨閉包描述「動作 播完之後要做什麼」，模組M會看到AdMob用類似的寫法描述 「廣告播放完畢之後要做什麼」——到時候回頭對照這一課， 會發現語法其實一直是同一套。
