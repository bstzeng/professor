SKNode節點樹：遊戲物件怎麼組織

這一課的目標

  • 理解SpriteKit裡所有看得到或邏輯上存在的物件，都是SKNode或它的子類別
  • 認識節點樹（node tree）的父子結構，以及場景本身就是這棵樹的根節點
  • 理解子節點的position、rotation等變換是相對父節點，而不是相對整個畫面

上一課用addChild(_:)把一個文字節點加進了 場景，卻還沒解釋這個方法背後的邏輯。這一課要把 SpriteKit裡最基礎、也最重要的組織方式講清楚：所有東西 都是節點，節點之間組成一棵樹。

1. SKNode：一切物件的共同基礎

SKNode是SpriteKit裡幾乎所有類別的共同 基礎類別。顯示圖片的SKSpriteNode、顯示 文字的SKLabelNode、甚至場景本身的 SKScene，全部都是SKNode的 子類別。除了這些「看得到」的節點，也可以直接使用 SKNode本身——它沒有任何視覺內容，常常用 來當作純粹的組織用容器，把一群相關的節點包在一起管理。

2. 節點樹：場景是根節點，addChild(_:)建立父子關係

SpriteKit用一個樹狀結構來組織所有節點：場景 （SKScene）本身就是整棵樹最頂端的根節點， 其他所有節點，都要透過addChild(_:)掛在 某個節點底下，才會真正出現在畫面上、被視為這個場景的 一部分。

let player = SKSpriteNode(imageNamed: "player") addChild(player) // 把player加到目前場景底下 let hat = SKSpriteNode(imageNamed: "hat") player.addChild(hat) // 把hat加到player底下，而不是直接加到場景

這段程式碼裡，player被加到場景底下，是 場景的直接子節點；hat則被加到 player底下，成為player的 子節點——同時也算是場景的「孫節點」。一個節點可以同時 擁有多個子節點，子節點底下也能繼續有自己的子節點， 像這樣一層一層延伸下去，就組成了一棵完整的節點樹。

3. 相對座標：子節點的position是相對父節點

這是節點樹最重要、也最容易讓新手誤解的一點： 子節點的position（以及rotation等其他變換）不是相對 整個畫面或場景，而是相對它的父節點。以上面 的例子來說，如果幫hat設定 hat.position = CGPoint(x: 0, y: 40)， 意思是「相對player往上偏移40點」，而不是「畫面座標 (0, 40)的位置」。這樣設計的好處是：只要移動或旋轉 player，hat會自動跟著一起 移動、旋轉，完全不需要額外寫程式碼去同步兩者的位置—— 這在組合式的遊戲物件（例如角色加上裝飾、砲塔加上砲管） 特別有用。

檢查你的理解

  1. 說明SKNode跟SKScene、SKSpriteNode之間是什麼樣的繼承／父子關係
  2. 說明addChild(_:)做了什麼事，以及一個節點是否能同時是某節點的子節點、又是另一節點的父節點
  3. 舉例說明為什麼子節點的position是「相對父節點」而不是「相對整個畫面」，這件事在什麼情境下特別重要
