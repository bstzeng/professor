觸控事件的基本處理

這一課的目標

  • 理解SKScene本身可以直接覆寫touchesBegan、touchesMoved、touchesEnded來接收觸控事件
  • 能用touch.location(in:)取得觸控點在場景座標系中的正確位置
  • 分辨touchesBegan、touchesMoved、touchesEnded／touchesCancelled各自代表的時機

模組D把SpriteKit的場景、節點樹與座標系統都建立起來了， 但畫面上的東西目前都不會回應玩家。從這一課開始的模組E， 要處理遊戲最基本的輸入來源——手指觸控。SpriteKit在這 方面的設計其實很直接：SKNode（包含 SKScene本身）在iOS上繼承自UIResponder， 所以只要覆寫幾個熟悉的方法，就能拿到觸控資料，完全不需要 額外設定delegate或target-action。

1. SKScene就是一個UIResponder

SKScene預設isUserInteractionEnabled 就是true，所以只要在你的GameScene: SKScene 類別裡覆寫下面三個方法，就能立刻收到觸控事件，不需要 任何額外設定：

override func touchesBegan(_ touches: Set<UITouch>, with event: UIEvent?) { // 手指剛碰到螢幕的瞬間 } override func touchesMoved(_ touches: Set<UITouch>, with event: UIEvent?) { // 手指在螢幕上移動時，會持續被呼叫 } override func touchesEnded(_ touches: Set<UITouch>, with event: UIEvent?) { // 手指離開螢幕的瞬間 }

三個方法的參數都是Set<UITouch>而不是單一 一個UITouch，因為iOS裝置支援多指觸控，一次 手勢動作理論上可能同時包含好幾根手指的資料。這門課的 打磚塊遊戲只需要處理單指操作，所以後面會用 touches.first直接取出第一個觸控點即可。

2. 取得觸控點在場景座標系中的位置

拿到UITouch之後，最常用的就是它的 location(in:)方法——把觸控在螢幕上的原始 座標，轉換成指定節點座標系中的位置。因為場景本身也是 一個SKNode，在GameScene內部 直接傳入self，取得的就是模組D lesson-18 介紹過的那套場景座標：

override func touchesBegan(_ touches: Set<UITouch>, with event: UIEvent?) { guard let touch = touches.first else { return } let location = touch.location(in: self) print("觸控開始於：\(location)") }

guard let touch = touches.first else { return } 這一行是很常見的寫法：先確認集合裡真的有觸控資料再繼續， 沒有的話就直接return，避免處理空集合。

3. 完整範例：讓一個節點跟著手指移動

把三個方法組合起來，可以做一個最簡單的驗證：讓一個測試 用的方塊節點，在觸控開始與移動時都跟著手指跑：

class GameScene: SKScene { private let testNode = SKSpriteNode(color: .systemTeal, size: CGSize(width: 40, height: 40)) override func didMove(to view: SKView) { testNode.position = CGPoint(x: frame.midX, y: frame.midY) addChild(testNode) } override func touchesBegan(_ touches: Set<UITouch>, with event: UIEvent?) { guard let touch = touches.first else { return } testNode.position = touch.location(in: self) } override func touchesMoved(_ touches: Set<UITouch>, with event: UIEvent?) { guard let touch = touches.first else { return } testNode.position = touch.location(in: self) } override func touchesEnded(_ touches: Set<UITouch>, with event: UIEvent?) { // 手指離開螢幕後想做的收尾動作，先留空 } }

這個範例目前還只是驗證觸控有沒有正確接上，實際跑起來會 看到方塊跳到手指第一次碰到的位置，接著在拖曳過程中持續 跟著移動。模組F建立球拍時，會把同樣的位置資訊，改成拿來 更新球拍的position.x，而不是整個節點的位置。

  2. 寫出從一組觸控事件中，取得觸控點在場景座標系中位置的程式碼
  3. 為什麼touchesBegan的參數型別是Set<UITouch>而不是單一一個UITouch
