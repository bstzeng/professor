Claude Code 的 Skill

這一課的目標

  • 知道 Claude Code 從哪裡載入 Skill
  • 了解 Claude Code 的擴充欄位
  • 會使用參數與子代理執行

載入位置

  • 個人：~/.claude/skills/<name>/SKILL.md
  • 專案：.claude/skills/<name>/SKILL.md（子資料夾裡的 .claude/skills/ 也會在該資料夾工作時載入）
  • 外掛：<plugin>/skills/<name>/SKILL.md
  • 組織：管理設定目錄下的 .claude/skills/
  • 修改 Skill 不需重新啟動；新增頂層的 .claude/skills/ 目錄時用 /reload-skills。

常用擴充欄位

欄位作用
when_to_use補充觸發情境，接在描述後面
disable-model-invocation: true只能由使用者用 /名稱 呼叫，Claude 不會自己載入（適合部署、發文等有副作用的流程）
user-invocable: false從 / 選單隱藏，只讓 Claude 自己判斷使用
allowed-tools這個 Skill 執行時可以免確認使用的工具
disallowed-tools執行時移除某些工具
context: fork／agent在子代理中執行，搭配 agent 指定子代理類型（Explore、Plan 等）
model／effort指定模型或推理強度
paths只在處理符合路徑的檔案時自動載入
arguments／argument-hint定義參數與輸入提示

參數

--- name: fix-issue description: Fix a GitHub issue by number argument-hint: "[issue-number]" disable-model-invocation: true --- Fix issue #$ARGUMENTS. Read the issue, reproduce it, write a failing test, fix it, and run the full test suite.

輸入 /fix-issue 123 時，$ARGUMENTS 會被換成 123；也可以用 $0、$1 取第幾個參數。

在子代理中執行

--- name: deep-research description: Research a topic thoroughly context: fork agent: Explore --- Research $ARGUMENTS thoroughly ...

設定 context: fork 後，Skill 的內容會成為子代理的任務說明，子代理看不到原本的對話，工作完成後只把結果帶回來。中間大量的搜尋與閱讀不會塞進主對話——這是多工 Skill 的重要工具（模組 D、E）。

權限控制

可以在設定中用 Skill(名稱) 規則允許或禁止特定 Skill，或用 skillOverrides 把某個 Skill 設為關閉、只顯示名稱、只能手動呼叫。

🧭 這一課的重點

Claude Code 從個人、專案（含子資料夾）、外掛與組織目錄載入 Skill，修改免重啟。擴充欄位包括 when_to_use、disable-model-invocation、user-invocable、allowed-tools、disallowed-tools、context: fork 與 agent、model、effort、paths、arguments。/名稱 後的文字以 $ARGUMENTS 或 $0、$1 帶入；context: fork 讓 Skill 在看不到原對話的子代理中執行。可用 Skill(名稱) 規則與 skillOverrides 控制權限。

🧩 本課程介紹的工具與格式變化很快，內容依撰寫時（2026 年）的官方文件與原始碼庫整理，實際行為以各工具最新文件為準。收藏庫中的自製 Skill 為教學範本，使用前請依自己的專案調整；安裝任何第三方 Skill 前，請先完整閱讀其內容（第 40 課）。

  2. context: fork 有什麼好處？子代理看得到原對話嗎？
  3. /fix-issue 123 中的 123 怎麼被帶進 Skill？
