Skill 和其他機制的差別

這一課的目標

  • 分辨 Skill 與其他擴充機制
  • 知道什麼情況該用哪一種
  • 理解它們如何組合
機制是什麼什麼時候載入適合
專案說明檔（CLAUDE.md／AGENTS.md）專案的長期規則與背景每次對話一開始就載入程式風格、測試指令、禁止事項等「永遠適用」的事
Skill一套可重複使用的做法需要時才載入特定任務的流程：寫週報、做審查、除錯
斜線指令使用者手動呼叫的快捷提示使用者輸入 /名稱 時在 Claude Code 中，Skill 也能用 /名稱 呼叫，指令與 Skill 已經合流
MCP 伺服器讓 AI 連接外部工具與資料的協定一直可用（工具清單）查資料庫、操作 GitHub、讀雲端文件
子代理（subagent）有自己上下文的另一個 AI 助手主代理派工作時隔離上下文、平行處理（第 14 課）
Hooks在特定事件自動執行的程式事件發生時（例如每次改檔後）一定要執行、不能靠 AI 記得的事：格式化、檢查、記錄
外掛（plugin）把以上幾種打包在一起分享安裝後團隊或社群發布一整套工具

一個簡單的判斷方法

  • 「每次都要遵守」→ 專案說明檔。
  • 「做某類工作時要這樣做」→ Skill。
  • 「需要連接外部系統」→ MCP。
  • 「絕對不能忘，最好不要靠 AI 自覺」→ Hooks。
  • 「工作量大、會塞爆上下文或可以平行」→ 子代理。

組合使用

這些機制常常一起出現：一個「發布新版」的 Skill 會呼叫 MCP 讀取 issue、派子代理平行跑測試，而 Hook 確保每次改檔都自動格式化；最後把它們包成外掛分享給團隊。

MCP 與 Skill 的分工

MCP 提供「手」（能做什麼），Skill 提供「方法」（怎麼做比較好）。例如 GitHub 的 MCP 讓 AI 能讀寫 PR，而「PR 看守」Skill 告訴它遇到 CI 失敗時該怎麼處理（第 29 課）。

🧭 這一課的重點

專案說明檔放永遠適用的規則，Skill 放特定任務的做法並按需載入，斜線指令在 Claude Code 中已與 Skill 合流，MCP 連接外部工具與資料，子代理提供隔離上下文與平行處理，Hooks 在事件發生時強制執行，外掛把它們打包分享。MCP 提供能力，Skill 提供方法。

🧩 本課程介紹的工具與格式變化很快，內容依撰寫時（2026 年）的官方文件與原始碼庫整理，實際行為以各工具最新文件為準。收藏庫中的自製 Skill 為教學範本，使用前請依自己的專案調整；安裝任何第三方 Skill 前，請先完整閱讀其內容（第 40 課）。
