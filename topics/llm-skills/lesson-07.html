模組 B｜怎麼寫出好 Skill · 第 7 課

附帶腳本與參考資料

這一課的目標

  • 知道何時該寫腳本
  • 學會在內文中引用附帶檔案
  • 注意腳本的安全與可攜性

什麼時候寫腳本

  • 需要精確：計算、格式轉換、驗證 JSON 結構。
  • 重複而機械：收集資料、重新命名、產生檔案清單。
  • 模型容易出錯：複雜的指令參數、特定 API 的呼叫順序。
  • 結果要可重現：同樣的輸入每次都要一樣的輸出。

在內文中引用

## 2. Collect data Run `python scripts/collect.py --days 7` and read its JSON output. ## 3. Format Follow the section order in references/format.md. Only read references/edge-cases.md if a PR has no linked issue.

Claude Code 提供 ${CLAUDE_SKILL_DIR} 代表 Skill 所在的資料夾，可以用來寫出不受工作目錄影響的路徑；它也能在 allowed-tools 中預先允許執行自己附帶的腳本，例如 Bash(${CLAUDE_SKILL_DIR}/scripts/render.sh *)。

動態背景

Claude Code 的 Skill 可以在內文中寫 !`git diff HEAD`：在 AI 讀到 Skill 之前先執行指令，把輸出直接放進內文。這樣 AI 一開始就看到最新狀態。指令失敗會讓整個 Skill 載入失敗，可能失敗的指令要加上 || true。

安全與可攜性

  • 腳本以使用者的權限執行，等於讓 AI 執行你給它的程式：要像審查程式一樣審查腳本（第 40 課）。
  • 不要在腳本或參考檔裡寫密碼、API 金鑰。
  • 註明需要的語言版本與套件；跨平台的腳本避免依賴特定作業系統的指令。

🧭 這一課的重點

需要精確、重複機械、容易出錯或要可重現的步驟應寫成腳本，在內文中明確寫出何時執行哪個腳本、何時讀哪份參考檔。Claude Code 提供 ${CLAUDE_SKILL_DIR} 路徑與 !`指令` 動態背景，allowed-tools 可預先允許附帶腳本。腳本以使用者權限執行，需審查、不可含密鑰並註明依賴。

🧩 本課程介紹的工具與格式變化很快，內容依撰寫時（2026 年）的官方文件與原始碼庫整理，實際行為以各工具最新文件為準。收藏庫中的自製 Skill 為教學範本，使用前請依自己的專案調整；安裝任何第三方 Skill 前，請先完整閱讀其內容（第 40 課）。
