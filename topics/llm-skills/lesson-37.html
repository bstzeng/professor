權限與沙箱

這一課的目標

  • 了解 Claude Code 與 Codex 的權限機制
  • 學會用最小權限原則設定代理
  • 知道 Skill 層級的權限設定

Skill 告訴代理應該怎麼做；權限設定決定它能夠做什麼。兩者要一起設計：再好的 Skill 也可能被誤解或被注入的內容誤導，權限是最後一道防線。

Claude Code

  • 權限模式：預設模式會在改檔、執行指令前詢問；另有自動接受編輯、只規劃不執行的計畫模式，以及略過所有確認的模式（只應在隔離環境使用）。
  • 允許與禁止規則：在設定檔中用規則精確控制，例如允許 Bash(npm test *)、禁止 Bash(git push --force *)。
  • Skill 層級：allowed-tools 讓 Skill 執行時免確認使用特定工具，disallowed-tools 則移除工具；也可以用 Skill(名稱) 規則允許或禁止某個 Skill。
  • 組織可以用管理設定統一部署規則。

Codex

  • 沙箱模式：唯讀、只能寫入工作區、完全存取等層級，限制代理能碰到的檔案與網路。
  • 核准政策：決定什麼時候要停下來問使用者（例如每個指令都問、需要時才問、從不問）。
  • 確切的選項名稱與預設值會隨版本調整，請以 Codex 文件為準。

最小權限原則

  • 只給完成任務需要的權限：寫報告的 Skill 不需要推送 git 的權限。
  • 唯讀優先：研究、審查類 Skill 盡量在唯讀模式下執行。
  • 隔離環境：要讓代理長時間無人監督自主執行，最好在容器、雲端沙箱或專用的虛擬機中。
  • 密鑰不放進上下文：用環境變數或密鑰管理服務，而不是寫在 Skill 或提示裡。

收藏庫的風險標籤

收藏庫中每個 Skill 都標示了風險等級：唯讀（只讀取與回報）、會修改檔案、會對外操作（推送、開 PR、發訊息）。等級越高，越需要搭配嚴格的權限設定與確認點。

🧭 這一課的重點

Skill 決定代理應該怎麼做，權限決定它能做什麼。Claude Code 有權限模式、允許／禁止規則、Skill 層級的 allowed-tools 與 disallowed-tools 及 Skill(名稱) 規則，組織可統一部署；Codex 有沙箱模式與核准政策。原則是最小權限、唯讀優先、無人監督時使用隔離環境、密鑰不放進上下文。

🧩 本課程介紹的工具與格式變化很快，內容依撰寫時（2026 年）的官方文件與原始碼庫整理，實際行為以各工具最新文件為準。收藏庫中的自製 Skill 為教學範本，使用前請依自己的專案調整；安裝任何第三方 Skill 前，請先完整閱讀其內容（第 40 課）。
