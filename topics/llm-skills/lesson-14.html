模組 D｜操縱 Agent 的基礎 · 第 14 課

子代理：把工作交出去

這一課的目標

  • 理解子代理的運作方式
  • 會定義自訂子代理
  • 學會寫出自足的任務說明

子代理（subagent）是主代理派出去的「另一個 AI 助手」：它有自己的上下文，做完只回傳一份結果。主對話不會被大量的搜尋、閱讀、試錯塞滿。

在 Claude Code 中

  • 內建幾種子代理類型，例如專門搜尋程式碼的 Explore、規劃用的 Plan，以及通用型。
  • 自訂子代理放在 .claude/agents/<name>.md（專案）或 ~/.claude/agents/（個人），用 /agents 管理。
  • 子代理可以在背景執行，主代理同時做其他事；完成時會收到通知。
  • Skill 加上 context: fork 就會在子代理中執行（第 10 課）。
--- name: test-runner description: Run the test suite, find the root cause of failures, and report. Use after code changes or when tests fail. tools: Read, Grep, Glob, Bash model: sonnet --- You run tests and diagnose failures. Report: which tests failed, the root cause for each, and the smallest fix. Do not edit test files.

在 Codex 中

撰寫時 Codex 的多代理功能屬於實驗性功能，需要在設定中開啟，可以產生多個專門的代理平行工作再彙整結果，也能定義自訂代理。另一種常見做法是用非互動的 codex exec 開多個程序，各自在不同的工作目錄執行（第 16 課）。

任務說明要「自足」

子代理看不到主對話。主代理常犯的錯是寫出「照我們剛才說的方法處理」這種說明。好的說明要包含：

  1. 目標與背景（為什麼要做）。
  2. 範圍：要看哪些檔案、不要動哪些東西。
  3. 已知的資訊與已排除的可能性。
  4. 回報格式與長度上限（例如「300 字以內、條列、附檔案路徑」）。
  5. 完成條件。

什麼時候不要用子代理

  • 任務很小，自己做比寫說明還快。
  • 需要大量來回討論與使用者確認的工作。
  • 每一步都依賴上一步結果、無法切開的工作。

🧭 這一課的重點

子代理擁有獨立上下文、只回傳結果，避免主對話被塞滿。Claude Code 有 Explore、Plan 等內建類型，可在 .claude/agents 定義自訂子代理（name、description、tools、model），也能背景執行；Skill 用 context: fork 即在子代理中執行。Codex 的多代理撰寫時屬實驗功能，也可用 codex exec 開多個程序。子代理看不到主對話，任務說明必須自足。

🧩 本課程介紹的工具與格式變化很快，內容依撰寫時（2026 年）的官方文件與原始碼庫整理，實際行為以各工具最新文件為準。收藏庫中的自製 Skill 為教學範本，使用前請依自己的專案調整；安裝任何第三方 Skill 前，請先完整閱讀其內容（第 40 課）。
