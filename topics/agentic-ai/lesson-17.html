任務分解與待辦清單

這一課的目標

  • 用待辦清單工具管理多步驟任務
  • 理解清單對代理與使用者的價值
  • 設計整份覆寫的狀態更新

「幫我加一個登入功能」是個大任務。好的代理會先把它拆成小項目——讀需求、寫程式、寫測試、跑測試——並在做的過程中持續更新每一項的狀態：待辦、進行中、完成。

這件事可以做成一個簡單的工具：todo_write(todos)，模型每次送出整份最新清單。整份覆寫比「新增一項」「修改第三項」這種細碎操作可靠得多，模型不容易搞亂。

  • 對代理：任務很長時，清單是它的「外部記憶」，不會做到一半忘了還剩什麼。
  • 對使用者：隨時看得到代理做到哪裡、打算做什麼，方便及早糾正方向。

Claude Code 的 TodoWrite 工具就是這個設計；你在使用它時看到的勾選清單，就是模型呼叫這個工具的結果。

🐍 Python 範例（離線版）　下載 c17_todo.py　需同資料夾的 mockllm.py

代理建立四項清單，每做一項就把它從「進行中」改成「完成」。

# -*- coding: utf-8 -*- """第 17 課：待辦清單工具——讓代理把大任務拆成小項目並追蹤進度（Claude Code 的 TodoWrite 就是這個概念）。""" import json from mockllm import MockClient, text, tool_use TODOS = [] def todo_write(todos): """整份清單覆寫：模型每次送出完整的最新狀態。""" TODOS[:] = todos icon = {"pending": "☐", "in_progress": "▶", "completed": "☑"} print(" " + " ".join("%s %s" % (icon[t["status"]], t["content"]) for t in TODOS)) return "ok" def work(name): return "%s 完成" % name ITEMS = ["讀需求", "寫程式", "寫測試", "跑測試"] def policy(ctx): k = ctx.turn # 第 0 輪建立清單；之後每兩輪：標記進行中 → 做事並標記完成 if k == 0: return tool_use("todo_write", {"todos": [{"content": c, "status": "pending"} for c in ITEMS]}) idx, phase = divmod(k - 1, 2) if idx >= len(ITEMS): return text("全部 %d 項都完成了。" % len(ITEMS)) st = lambda j: "completed" if j < idx or (j == idx and phase == 1) else ("in_progress" if j == idx else "pending") calls = [tool_use("todo_write", {"todos": [{"content": c, "status": st(j)} for j, c in enumerate(ITEMS)]})] if phase == 0: calls.append(tool_use("work", {"name": ITEMS[idx]})) return calls tools = [{"name": "todo_write", "description": "更新待辦清單", "input_schema": {"type": "object", "properties": {"todos": {"type": "array"}}}}, {"name": "work", "description": "執行一項工作", "input_schema": {"type": "object", "properties": {"name": {"type": "string"}}}}] impl = {"todo_write": todo_write, "work": work} client, msgs = MockClient(policy), [{"role": "user", "content": "幫我加一個登入功能"}] while True: r = client.messages.create(model="mock", max_tokens=800, tools=tools, messages=msgs) msgs.append({"role": "assistant", "content": r.content}) if r.stop_reason != "tool_use": break msgs.append({"role": "user", "content": [{"type": "tool_result", "tool_use_id": b.id, "content": json.dumps(impl[b.name](**b.input), ensure_ascii=False)} for b in r.content if b.type == "tool_use"]}) print(r.content[0].text, "清單讓代理（和你）隨時知道：做到哪、還剩什麼。")

☁️ Claude API 版（換成真的 Claude，點我展開）

需要 pip install anthropic 並設定環境變數 ANTHROPIC_API_KEY；會實際呼叫 API 並計費。下載 c17_todo.py

# -*- coding: utf-8 -*- """第 17 課（Claude API 版）：給 Claude 一個 todo_write 工具，要求它先列清單、邊做邊更新。""" import json import anthropic client = anthropic.Anthropic() TODOS = [] tools = [{ "name": "todo_write", "description": "建立或更新整份待辦清單。開始多步驟工作前先列出清單；每開始或完成一項就送出完整的最新清單。", "input_schema": {"type": "object", "properties": {"todos": {"type": "array", "items": { "type": "object", "properties": {"content": {"type": "string"}, "status": {"type": "string", "enum": ["pending", "in_progress", "completed"]}}, "required": ["content", "status"]}}}, "required": ["todos"]}, }] messages = [{"role": "user", "content": "規劃「把部落格從 WordPress 搬到靜態網站」的工作，用 todo_write 列出清單，並把第一項標成進行中。"}] while True: r = client.messages.create(model="claude-opus-5-5", max_tokens=16000, tools=tools, messages=messages) messages.append({"role": "assistant", "content": r.content}) if r.stop_reason != "tool_use": break results = [] for b in r.content: if b.type == "tool_use": TODOS[:] = b.input["todos"] for t in TODOS: print({"pending": "☐", "in_progress": "▶", "completed": "☑"}[t["status"]], t["content"]) results.append({"type": "tool_result", "tool_use_id": b.id, "content": "清單已更新"}) messages.append({"role": "user", "content": results}) print(json.dumps(TODOS, ensure_ascii=False, indent=1))

🧭 這一課的重點

代理可用待辦清單工具把大任務拆成小項目並追蹤狀態；模型每次送出整份最新清單較可靠。清單是代理的外部記憶，也讓使用者看到進度並及早糾正方向。Claude Code 的 TodoWrite 就是此設計。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
