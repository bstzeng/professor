結構化輸出

這一課的目標

  • 理解為什麼代理需要結構化輸出
  • 驗證模型產生的 JSON
  • 使用約束解碼保證格式

代理的輸出常常要交給程式處理：存進資料庫、決定下一步、傳給另一個代理。這時「好的！以下是結果：……希望有幫助！」這種回答就是災難——你得從一堆文字中挖出 JSON，還可能漏欄位、型別錯誤。

三種做法，可靠度遞增：

  1. 在提示中要求「只輸出 JSON」，再用程式解析並驗證——大多時候可行，偶爾會壞。
  2. 把輸出定義成一個工具的參數（模型「呼叫」它來交答案）。
  3. 結構化輸出（約束解碼）：在 API 指定 JSON Schema，模型產生的 token 被限制在合法範圍內，保證符合格式。Python SDK 可以直接用 Pydantic 類別定義，回傳驗證好的物件。

即使格式保證正確，內容仍可能不合理（例如日期在過去），重要的值要再用程式檢查。

🐍 Python 範例（離線版）　下載 g38_structured.py　需同資料夾的 mockllm.py

比較沒約束（包在一堆文字裡、型別錯誤）與有約束（乾淨的 JSON）的輸出，並用程式驗證。

# -*- coding: utf-8 -*- """第 38 課：結構化輸出——讓模型的回答變成程式能直接用的資料（JSON），而且要驗證。 沒有約束時，模型可能多講廢話、漏欄位、用錯型別；約束解碼（constrained decoding）則保證符合 schema。""" import json import re from mockllm import MockClient, text SCHEMA_KEYS = {"name": str, "email": str, "plan": str, "demo": bool} EMAIL = "我是王小美（mei@example.com），想試用企業方案，可以安排展示嗎？" loose = MockClient(lambda ctx: text('好的！以下是擷取結果：\n```json\n{"name": "王小美", "email": "mei@example.com", "plan": "企業", "demo": "要"}\n```\n希望有幫助！')) strict = MockClient(lambda ctx: text('{"name": "王小美", "email": "mei@example.com", "plan": "enterprise", "demo": true}')) def parse_and_check(raw): m = re.search(r"\{.*\}", raw, re.S) # 從一堆文字中挖出 JSON（脆弱的做法） data = json.loads(m.group(0)) errs = ["%s 應為 %s" % (k, t.__name__) for k, t in SCHEMA_KEYS.items() if not isinstance(data.get(k), t)] return data, errs for name, c in [("沒約束", loose), ("有約束", strict)]: raw = c.messages.create(model="mock", max_tokens=300, messages=[{"role": "user", "content": EMAIL}]).content[0].text data, errs = parse_and_check(raw) print("【%s】原始輸出：%s" % (name, raw.replace("\n", "⏎"))) print(" 驗證：%s" % ("通過 ✓ → " + str(data) if not errs else "失敗 ✗ " + "；".join(errs)))

▶ 執行結果（這是實際執行的輸出）

【沒約束】原始輸出：好的！以下是擷取結果：⏎```json⏎{"name": "王小美", "email": "mei@example.com", "plan": "企業", "demo": "要"}⏎```⏎希望有幫助！ 驗證：失敗 ✗ demo 應為 bool 【有約束】原始輸出：{"name": "王小美", "email": "mei@example.com", "plan": "enterprise", "demo": true} 驗證：通過 ✓ → {'name': '王小美', 'email': 'mei@example.com', 'plan': 'enterprise', 'demo': True}
☁️ Claude API 版（換成真的 Claude，點我展開）

需要 pip install anthropic 並設定環境變數 ANTHROPIC_API_KEY；會實際呼叫 API 並計費。下載 g38_structured.py

# -*- coding: utf-8 -*- """第 38 課（Claude API 版）：用 Pydantic 定義格式，messages.parse() 自動驗證並回傳物件。""" from typing import Literal from pydantic import BaseModel import anthropic class Lead(BaseModel): name: str email: str plan: Literal["free", "pro", "enterprise"] demo: bool client = anthropic.Anthropic() r = client.messages.parse( model="claude-opus-5-5", max_tokens=16000, messages=[{"role": "user", "content": "擷取資料：我是王小美（mei@example.com），想試用企業方案，可以安排展示嗎？"}], output_format=Lead, ) lead = r.parsed_output # 已驗證的 Lead 物件 print(lead.name, lead.email, lead.plan, lead.demo)

🧭 這一課的重點

代理的輸出常交給程式處理，必須是可靠的結構化資料。可在提示中要求 JSON 並驗證、把輸出定義為工具參數，或使用約束解碼的結構化輸出保證符合 schema（Python 可用 Pydantic）；內容合理性仍要程式檢查。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
