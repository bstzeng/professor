模組 C｜推理與規劃 · 第 16 課

先規劃再執行

這一課的目標

  • 認識先規劃後執行的模式
  • 用結構化輸出產生計畫
  • 知道何時需要重新規劃

ReAct 每一步都要問模型，任務長時又慢又貴。另一種風格是先規劃再執行：讓模型一次產生完整的步驟清單（最好是結構化的 JSON），再由程式或較便宜的模型逐步執行。

計畫趕不上變化時——某一步失敗，或結果和預期不同——就把「已完成什麼、哪裡失敗、為什麼」回饋給規劃者，請它重新規劃。

實務上兩者常混用：先有一個粗略計畫讓方向清楚，執行時每一步仍保留 ReAct 式的彈性。Claude Code 在做大型修改前會先擬計畫（甚至有只規劃不動手的 plan 模式），就是這個概念。

🐍 Python 範例（離線版）　下載 c16_plan_execute.py　需同資料夾的 mockllm.py

規劃者產生四步計畫；第一步的資料來源連不上，回饋後規劃者改用備用來源。

# -*- coding: utf-8 -*- """第 16 課：先規劃、再執行（Plan-and-Execute）。 規劃者一次產生完整計畫（結構化 JSON），執行者逐步完成；某步失敗時才請規劃者「重新規劃」。""" import json from mockllm import MockClient, text def planner_policy(ctx): if "失敗" in ctx.user_text(): return text(json.dumps(["用備用來源 B 下載資料", "清理資料", "產生圖表", "寫摘要"], ensure_ascii=False)) return text(json.dumps(["從來源 A 下載資料", "清理資料", "產生圖表", "寫摘要"], ensure_ascii=False)) planner = MockClient(planner_policy) def execute(step): if "來源 A" in step: raise ConnectionError("來源 A 連不上") return "完成：" + step def plan(goal, feedback=""): r = planner.messages.create(model="mock", max_tokens=500, system="把目標拆成步驟，只輸出 JSON 陣列", messages=[{"role": "user", "content": goal + feedback}]) return json.loads(r.content[0].text) goal = "做一份上個月營收的分析報告" steps, done = plan(goal), [] print("初始計畫：", steps) i = 0 while i < len(steps): try: done.append(execute(steps[i])) print(" ✓", done[-1]) i += 1 except Exception as e: print(" ✗ %s → %s，請規劃者重新規劃" % (steps[i], e)) steps = plan(goal, "\n已完成：%s\n失敗：%s（%s）" % (done, steps[i], e)) print("新計畫：", steps) i = 0 done = [] print("共呼叫規劃者 %d 次。優點：省 token、步驟清楚；缺點：計畫趕不上變化時要重規劃。" % planner.calls)

▶ 執行結果（這是實際執行的輸出）

初始計畫： ['從來源 A 下載資料', '清理資料', '產生圖表', '寫摘要'] ✗ 從來源 A 下載資料 → 來源 A 連不上，請規劃者重新規劃 新計畫： ['用備用來源 B 下載資料', '清理資料', '產生圖表', '寫摘要'] ✓ 完成：用備用來源 B 下載資料 ✓ 完成：清理資料 ✓ 完成：產生圖表 ✓ 完成：寫摘要 共呼叫規劃者 2 次。優點：省 token、步驟清楚；缺點：計畫趕不上變化時要重規劃。
☁️ Claude API 版（換成真的 Claude，點我展開）

需要 pip install anthropic 並設定環境變數 ANTHROPIC_API_KEY；會實際呼叫 API 並計費。下載 c16_plan_execute.py

# -*- coding: utf-8 -*- """第 16 課（Claude API 版）：用結構化輸出（output_config.format）讓規劃者回傳保證合法的 JSON 計畫。""" import json import anthropic client = anthropic.Anthropic() PLAN_SCHEMA = { "type": "object", "properties": {"steps": {"type": "array", "items": {"type": "string"}}}, "required": ["steps"], "additionalProperties": False, } def plan(goal, feedback=""): r = client.messages.create( model="claude-opus-5-5", max_tokens=16000, system="你是規劃者。把目標拆成 3～6 個具體、可執行的步驟。", messages=[{"role": "user", "content": goal + feedback}], output_config={"format": {"type": "json_schema", "schema": PLAN_SCHEMA}}, ) return json.loads(next(b.text for b in r.content if b.type == "text"))["steps"] steps = plan("做一份上個月營收的分析報告") for i, s in enumerate(steps, 1): print(i, s) # 執行失敗時：plan(goal, "\n已完成：...\n失敗：...（原因）") 讓 Claude 重新規劃

🧭 這一課的重點

先規劃再執行：模型一次產生結構化的步驟清單，再逐步執行；失敗或結果不如預期時，把已完成與失敗原因回饋給規劃者重新規劃。實務上常與 ReAct 混用。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
