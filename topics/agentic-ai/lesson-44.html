可觀測性：日誌與追蹤

這一課的目標

  • 記錄代理每一步的追蹤資料
  • 用父子關係組織追蹤
  • 從追蹤找出問題

代理出錯時，最常聽到的問題是：「它為什麼會這樣做？」要回答，就需要追蹤（trace）：每一次模型呼叫（輸入、輸出、token、耗時）、每一次工具呼叫（參數、結果、錯誤），以及它們的先後與父子關係。

  • 除錯：看到模型在第幾步拿到錯誤資訊、做了錯誤判斷。
  • 效能：時間花在哪一步？哪個工具最慢？
  • 成本：哪類任務最燒 token？
  • 稽核：代理做過哪些動作，誰核准的。

實務上可以把追蹤資料存成 JSON Lines，或送進 OpenTelemetry 相容的觀測平台。注意追蹤裡可能有個資與機密，要遮蔽並控管存取。

🐍 Python 範例（離線版）　下載 g44_tracing.py　需同資料夾的 mockllm.py

用一個裝飾器記錄每個步驟的種類、耗時、父步驟與狀態，一眼看出讀網頁那一步逾時。

# -*- coding: utf-8 -*- """第 44 課：可觀測性——把代理的每一步（模型呼叫、工具、耗時、token）記成「追蹤（trace）」， 出事時才查得出：它看到什麼、為什麼這樣做、卡在哪一步。""" import functools import json import time import itertools from mockllm import MockClient, text, tool_use TRACE = [] _stack = [] _ids = itertools.count(1) def span(kind): """裝飾器：記錄一個步驟的開始、結束、耗時、輸入摘要、父子關係。""" def deco(fn): @functools.wraps(fn) def wrap(*a, **kw): sid = "s%d" % next(_ids) rec = {"id": sid, "parent": _stack[-1] if _stack else None, "kind": kind, "name": fn.__name__, "input": str(kw or a)[:60]} _stack.append(sid) t0 = time.perf_counter() try: out = fn(*a, **kw) rec["status"] = "ok" return out except Exception as e: rec["status"] = "error: %s" % e raise finally: rec["ms"] = round((time.perf_counter() - t0) * 1000, 1) _stack.pop() TRACE.append(rec) return wrap return deco @span("tool") def search(q): time.sleep(0.05) return ["結果 1", "結果 2"] @span("tool") def fetch(url): time.sleep(0.12) raise TimeoutError("連線逾時") client = MockClient(lambda ctx: [tool_use("search", {"q": "agent"}), tool_use("fetch", {"url": "https://x.example"})] if ctx.turn == 0 else text("搜尋成功，但讀取網頁逾時。")) @span("llm") def call_llm(msgs): r = client.messages.create(model="mock", max_tokens=500, messages=msgs, tools=[{"name": n, "input_schema": {"type": "object"}} for n in ("search", "fetch")]) TRACE.append({"kind": "usage", "in": r.usage.input_tokens, "out": r.usage.output_tokens}) return r @span("agent") def run(task): msgs = [{"role": "user", "content": task}] while True: r = call_llm(msgs) msgs.append({"role": "assistant", "content": r.content}) if r.stop_reason != "tool_use": return r.content[0].text res = [] for b in r.content: if b.type == "tool_use": try: res.append({"type": "tool_result", "tool_use_id": b.id, "content": json.dumps(globals()[b.name](**b.input), ensure_ascii=False)}) except Exception as e: res.append({"type": "tool_result", "tool_use_id": b.id, "content": str(e), "is_error": True}) msgs.append({"role": "user", "content": res}) run(task="研究 agent") print("追蹤紀錄（可存成 JSON Lines，送進 OpenTelemetry 等工具）：") for r in TRACE: if r["kind"] == "usage": print(" · tokens in=%d out=%d" % (r["in"], r["out"])) else: print(" %-6s %-9s %6.1f ms parent=%-6s %s" % (r["kind"], r["name"], r["ms"], r["parent"], r["status"]))

🧭 這一課的重點

追蹤記錄代理每一次模型與工具呼叫的輸入、輸出、token、耗時與父子關係，用於除錯、效能分析、成本控管與稽核。可存成 JSON Lines 或送入 OpenTelemetry 相容平台，並注意遮蔽個資。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
