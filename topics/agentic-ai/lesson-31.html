Computer use：操作電腦畫面

這一課的目標

  • 理解 computer use 的截圖－動作迴圈
  • 知道它的適用時機與代價
  • 認識它的安全風險

很多軟體沒有 API：老舊的內部系統、只有網頁介面的服務。Computer use 讓代理像人一樣操作電腦：截圖 → 模型看圖決定動作（點擊某座標、輸入文字、捲動）→ 執行 → 再截圖。

它是最通用的工具——理論上人能用電腦做的事它都能做——但也是最慢、最貴、最容易出錯的：每一步都要傳一張圖，點錯一個像素就前功盡棄。原則是：有 API 就用 API，真的沒有才用 computer use。

一定要隔離

讓 AI 操作滑鼠鍵盤，風險很高：畫面上的網頁可能有提示注入，誤點可能刪除資料或送出表單。務必在專用的虛擬機或容器中執行，不要登入重要帳號，敏感動作要人工確認。

在 Claude API 上，computer use 是一組由你的程式執行的工具（截圖、點擊、輸入等動作），Anthropic 負責理解畫面、決定動作，實際的桌面環境由你提供。

🐍 Python 範例（離線版）　下載 e31_computer.py　需同資料夾的 mockllm.py

用文字模擬一個登入畫面，代理以截圖、點擊、輸入共 7 個動作完成登入。

# -*- coding: utf-8 -*- """第 31 課：Computer use——沒有 API 可呼叫時，讓代理「看螢幕、動滑鼠、打字」。 迴圈：截圖 → 模型看圖決定動作（點哪個座標、輸入什麼）→ 執行 → 再截圖。 這裡用文字畫面模擬一個登入表單，模型「看到」的是畫面描述。""" from mockllm import MockClient, text, tool_use class Screen(object): def __init__(self): self.fields = {"帳號": "", "密碼": ""} self.focus = None self.page = "login" self.layout = {"帳號": (100, 80), "密碼": (100, 120), "登入": (100, 170)} # 元件中心座標 def screenshot(self): if self.page == "home": return "[畫面] 歡迎回來，xiaoan！（首頁）" return "[畫面] 登入頁｜帳號框@(100,80)=「%s」｜密碼框@(100,120)=「%s」｜[登入]按鈕@(100,170)" % ( self.fields["帳號"], "•" * len(self.fields["密碼"])) def left_click(self, x, y): for name, (cx, cy) in self.layout.items(): if abs(x - cx) < 60 and abs(y - cy) < 15: if name == "登入": self.page = "home" if self.fields["帳號"] and self.fields["密碼"] else "login" else: self.focus = name return "OK" return "OK（點到空白處）" def type(self, text): if self.focus: self.fields[self.focus] += text return "OK" scr = Screen() PLAN = [("screenshot", {}), ("left_click", {"x": 100, "y": 80}), ("type", {"text": "xiaoan"}), ("left_click", {"x": 100, "y": 120}), ("type", {"text": "s3cret"}), ("left_click", {"x": 100, "y": 170}), ("screenshot", {})] def policy(ctx): if ctx.turn < len(PLAN): return tool_use(*PLAN[ctx.turn]) return text("已登入成功。") tools = [{"name": n, "description": n, "input_schema": {"type": "object"}} for n in ("screenshot", "left_click", "type")] client, msgs = MockClient(policy), [{"role": "user", "content": "幫我用帳號 xiaoan 登入"}] while True: r = client.messages.create(model="mock", max_tokens=500, tools=tools, messages=msgs) msgs.append({"role": "assistant", "content": r.content}) if r.stop_reason != "tool_use": break b = r.content[0] out = getattr(scr, b.name)(**b.input) print("%-11s %-28s → %s" % (b.name, b.input, out)) msgs.append({"role": "user", "content": [{"type": "tool_result", "tool_use_id": b.id, "content": out}]}) print(r.content[0].text, "（共 %d 個動作；比呼叫 API 慢得多，也更容易出錯——能用 API 就用 API）" % len(PLAN))

# -*- coding: utf-8 -*- """第 31 課（Claude API 版）：computer use 工具組（computer_toolset_20260801，Claude Opus 5.5 只接受這個形式）。 Claude 的 tool_use 名稱就是動作（screenshot、left_click、type…），並帶 toolset_name="computer"； 每個 tool_result 也要回傳 toolset_name="computer"。截圖與實際操作需要你自己實作 （例如在虛擬機或容器裡用 pyautogui、xdotool）。務必在隔離環境中執行！""" import base64 import anthropic client = anthropic.Anthropic() def take_screenshot_png(): raise NotImplementedError("在隔離的虛擬桌面中截圖，回傳 PNG bytes") def perform(action, args): raise NotImplementedError("在虛擬桌面執行 %s %s" % (action, args)) messages = [{"role": "user", "content": "打開瀏覽器，搜尋今天的天氣。"}] for _ in range(30): # 動作上限 r = client.messages.create(model="claude-opus-5-5", max_tokens=16000, tools=[{"type": "computer_toolset_20260801"}], messages=messages) messages.append({"role": "assistant", "content": r.content}) if r.stop_reason != "tool_use": break results = [] for b in r.content: if b.type != "tool_use": continue if b.name in ("screenshot", "zoom"): img = base64.standard_b64encode(take_screenshot_png()).decode() content = [{"type": "image", "source": {"type": "base64", "media_type": "image/png", "data": img}}] else: perform(b.name, b.input) content = "OK" results.append({"type": "tool_result", "tool_use_id": b.id, "toolset_name": "computer", "content": content}) messages.append({"role": "user", "content": results})

🧭 這一課的重點

Computer use 讓代理以截圖、決定動作、執行、再截圖的迴圈操作電腦畫面，適用於沒有 API 的系統。它最通用但也最慢、最貴、最易出錯，有 API 就用 API；而且風險高，務必在隔離的虛擬機中執行。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
