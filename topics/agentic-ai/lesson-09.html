平行工具呼叫

這一課的目標

  • 理解模型可以一次發出多個工具呼叫
  • 用執行緒平行執行工具
  • 知道結果必須放在同一則訊息

問「台北、東京、首爾哪裡最暖」時，聰明的模型不會查一個、等結果、再查下一個——它會在同一則回應裡放三個 tool_use。這三個呼叫彼此獨立，你的程式可以同時執行。

Python 用 concurrent.futures.ThreadPoolExecutor 就能簡單做到。對網路請求這類「大部分時間在等待」的工具，平行可以大幅縮短延遲。

一定要放在同一則訊息

所有 tool_result 必須放在同一則 user 訊息裡送回，每個都對應自己的 tool_use_id。如果拆成好幾則訊息，模型會逐漸「學到」不要平行呼叫，反而變慢。

🐍 Python 範例（離線版）　下載 b09_parallel.py　需同資料夾的 mockllm.py

比較依序與平行執行的耗時，並把三個結果一起送回。

# -*- coding: utf-8 -*- """第 9 課：平行工具呼叫——模型一次要求多個工具，我們同時執行，再「一起」送回。""" import json import time from concurrent.futures import ThreadPoolExecutor from mockllm import MockClient, text, tool_use def get_weather(city): time.sleep(0.5) # 模擬網路延遲 0.5 秒 return {"台北": 27, "東京": 22, "首爾": 18}[city] def policy(ctx): if ctx.turn == 0: # 一次回應裡放 3 個 tool_use return [text("三個城市我同時查。")] + [tool_use("get_weather", {"city": c}) for c in ("台北", "東京", "首爾")] temps = {json.loads(r[1])["city"]: json.loads(r[1])["temp"] for r in ctx.results()} return text("最暖的是%s（%d°C）。" % max(temps.items(), key=lambda kv: kv[1])) tools = [{"name": "get_weather", "description": "查氣溫", "input_schema": {"type": "object", "properties": {"city": {"type": "string"}}}}] client = MockClient(policy) messages = [{"role": "user", "content": "台北、東京、首爾哪裡最暖？"}] r = client.messages.create(model="mock", max_tokens=500, tools=tools, messages=messages) calls = [b for b in r.content if b.type == "tool_use"] print("模型一次要求了 %d 個工具呼叫" % len(calls)) def run_one(b): return {"type": "tool_result", "tool_use_id": b.id, "content": json.dumps({"city": b.input["city"], "temp": get_weather(**b.input)}, ensure_ascii=False)} t0 = time.time() for b in calls: # 依序執行：約 1.5 秒 run_one(b) print("依序執行耗時 %.1f 秒" % (time.time() - t0)) t0 = time.time() with ThreadPoolExecutor() as pool: # 平行執行：約 0.5 秒 results = list(pool.map(run_one, calls)) # map 會保持原本順序 print("平行執行耗時 %.1f 秒" % (time.time() - t0)) messages += [{"role": "assistant", "content": r.content}, {"role": "user", "content": results}] # 重點：所有 tool_result 放在「同一則」user 訊息 r = client.messages.create(model="mock", max_tokens=500, tools=tools, messages=messages) print(r.content[0].text)

▶ 執行結果（這是實際執行的輸出）

模型一次要求了 3 個工具呼叫 依序執行耗時 1.5 秒 平行執行耗時 0.5 秒 最暖的是台北（27°C）。
☁️ Claude API 版（換成真的 Claude，點我展開）

需要 pip install anthropic 並設定環境變數 ANTHROPIC_API_KEY；會實際呼叫 API 並計費。下載 b09_parallel.py

# -*- coding: utf-8 -*- """第 9 課（Claude API 版）：Claude 預設可以在一則回應裡發出多個 tool_use。 平行執行後，把所有 tool_result 放在同一則 user 訊息送回。""" import json from concurrent.futures import ThreadPoolExecutor import anthropic client = anthropic.Anthropic() MODEL = "claude-opus-5-5" TEMPS = {"台北": 27, "東京": 22, "首爾": 18} tools = [{"name": "get_weather", "description": "查一個城市的目前氣溫（攝氏）", "input_schema": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]}}] messages = [{"role": "user", "content": "台北、東京、首爾哪裡最暖？"}] while True: r = client.messages.create(model=MODEL, max_tokens=16000, tools=tools, messages=messages) messages.append({"role": "assistant", "content": r.content}) if r.stop_reason != "tool_use": break calls = [b for b in r.content if b.type == "tool_use"] print("這一輪有 %d 個工具呼叫" % len(calls)) with ThreadPoolExecutor() as pool: results = list(pool.map(lambda b: {"type": "tool_result", "tool_use_id": b.id, "content": json.dumps({"temp_c": TEMPS.get(b.input["city"])})}, calls)) messages.append({"role": "user", "content": results}) print(next(b.text for b in r.content if b.type == "text"))

🧭 這一課的重點

模型可以在一則回應中發出多個獨立的 tool_use；程式可用執行緒平行執行以縮短延遲。所有 tool_result 必須放在同一則 user 訊息送回，否則會讓模型逐漸不再平行呼叫。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
