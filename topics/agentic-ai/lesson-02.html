LLM 只會「接下一個字」

這一課的目標

  • 理解 LLM 逐 token 產生文字的方式
  • 認識 temperature 對輸出的影響
  • 明白為什麼 LLM 本身不會「做事」

大型語言模型做的事，說穿了只有一件：給定前面的文字，預測下一個 token 的機率分布，從中挑一個接上去，再重複。token 是文字的小片段，英文大約 4 個字母一個，中文大約一個字一個。

這個簡單的機制，經過海量文字訓練後，產生了驚人的能力：理解問題、推理、寫程式。但要記住：模型本身不會上網、不會執行程式、不會記得上一次對話。它只是一個「文字進、文字出」的函數。

那代理怎麼「做事」？答案是：讓模型輸出一段特定格式的文字（例如「我要呼叫 get_weather，參數是台北」），由外面的程式解析並真的去執行，再把結果當成新的文字餵回去。模型負責決定，程式負責執行。

🐍 Python 範例（離線版）　下載 a02_next_token.py　需同資料夾的 mockllm.py

用一個只有幾十個字的「二元語法」模型，示範統計下一個字的機率並一個一個接下去。真正的 LLM 用的是有數千億參數的神經網路，但「接下一個字」的流程一樣。

# -*- coding: utf-8 -*- """第 2 課：LLM 的本質——一次預測一個 token。 用一個極小的「二元語法（bigram）」模型示範：統計『下一個字』的機率，再一個一個接下去。""" import random from collections import Counter, defaultdict corpus = ("代理會呼叫工具。代理會讀取結果。代理會決定下一步。" "模型會預測下一個字。模型會呼叫工具。工具會回傳結果。") nxt = defaultdict(Counter) for a, b in zip(corpus, corpus[1:]): nxt[a][b] += 1 # 「a 後面接 b」出現幾次 def probs(ch): c = nxt[ch] total = sum(c.values()) return {k: v / total for k, v in c.most_common()} print("「會」後面可能接：", {k: round(v, 2) for k, v in probs("會").items()}) def generate(start, n, temperature=1.0, seed=0): rnd = random.Random(seed) out = start for _ in range(n): p = probs(out[-1]) if not p: break # temperature 越低越「保守」（偏向最常見的字），越高越「隨機」 w = [v ** (1.0 / temperature) for v in p.values()] out += rnd.choices(list(p.keys()), weights=w)[0] if out[-1] == "。": break return out for t in (0.2, 1.0, 2.0): print("temperature=%.1f →" % t, [generate("代", 12, t, seed=s) for s in range(3)]) print("重點：模型本身只會『接下一個字』。它不會自己上網、不會自己執行程式——") print("　　　要讓它『做事』，得靠外面的程式把它包進一個迴圈，並提供工具。")

▶ 執行結果（這是實際執行的輸出）

「會」後面可能接： {'呼': 0.33, '讀': 0.17, '決': 0.17, '預': 0.17, '回': 0.17} temperature=0.2 → ['代理會呼叫工具。', '代理會呼叫工具。', '代理會呼叫工具。'] temperature=1.0 → ['代理會讀取結果。', '代理會預測下一個字。', '代理會呼叫工具會呼叫工具。'] temperature=2.0 → ['代理會讀取結果。', '代理會預測下一個字。', '代理會呼叫工具會讀取結果。'] 重點：模型本身只會『接下一個字』。它不會自己上網、不會自己執行程式—— 　　　要讓它『做事』，得靠外面的程式把它包進一個迴圈，並提供工具。

temperature

temperature 越低，模型越傾向挑機率最高的 token，輸出穩定但單調；越高越隨機、越有創意也越容易出錯。代理通常需要穩定可靠的行為。注意：在最新的 Claude 模型上，取樣參數由模型自行管理，API 不開放調整 temperature。

🧭 這一課的重點

LLM 只做一件事：根據前文預測下一個 token 並逐一接上；它本身不會上網、執行程式或記憶。代理的做法是讓模型輸出特定格式的「行動要求」，由外部程式執行並把結果餵回去——模型決定、程式執行。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
