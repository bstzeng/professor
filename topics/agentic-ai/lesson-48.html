案例剖析：Claude Code 與 Codex

這一課的目標

  • 把課程概念對應到兩個真實的程式代理
  • 比較兩者的設計取捨
  • 理解它們為什麼有效

Anthropic 的 Claude Code 與 OpenAI 的 Codex，是目前最廣泛使用的兩個程式代理。它們都是這門課所介紹架構的實作：一個 LLM 在迴圈中，透過工具讀寫程式碼、執行指令，依測試與錯誤訊息自我修正。

課程概念Claude CodeCodex
代理迴圈（第 5 課）模型呼叫工具、看結果、決定下一步相同
檔案工具（第 28 課）Read、Edit、Write、Grep、Glob 等讀檔、套用修補（patch）、搜尋
執行程式（第 27 課）Bash 工具shell 指令
待辦清單（第 17 課）TodoWrite計畫清單
專案記憶（第 24 課）CLAUDE.mdAGENTS.md
MCP（第 30 課）支援支援
子代理（第 33 課）可派出子代理處理子任務雲端可平行執行多個任務
上下文管理（第 21 課）接近上限時自動壓縮類似的長對話管理
人在迴路／沙箱（第 40、41 課）權限模式：預設詢問、自動接受修改、只規劃（plan）等沙箱等級（唯讀、可寫工作區、完全存取）與核准政策
執行位置終端機、IDE、桌面與網頁版；網頁版在雲端隔離容器中執行本機 CLI（開源）、IDE；雲端版在預載儲存庫的沙箱中執行並可產生 PR

兩者的差異主要在預設的工作方式：Claude Code 起源於終端機中的互動協作，強調你隨時看得到、隨時能介入；Codex 除了本機 CLI，也強調把任務丟到雲端沙箱背景執行、完成後交回一個 PR。不過兩者的功能都在快速演進，彼此的界線越來越模糊。

它們為什麼有效？回到第 46 課的四個問題：程式任務複雜但可驗證（測試）、可回復（git）、價值高，而且模型非常擅長讀寫程式碼。加上良好的工具設計（str_replace、grep）、上下文管理與權限機制，就成了實用的產品。

🐍 Python 範例（離線版）　下載 h48_case_study.py　需同資料夾的 mockllm.py

模擬一次「修 bug」任務的軌跡，標出每一步對應這門課的哪一課。

# -*- coding: utf-8 -*- """第 48 課：案例剖析——Claude Code 與 Codex 這類程式代理，本質上就是這門課教的架構： 一個代理迴圈 ＋ 檔案／搜尋／終端機工具 ＋ 待辦清單 ＋ 專案說明檔 ＋ 權限模式 ＋ 上下文壓縮 ＋ 子代理。 這裡用 60 行模擬一次『修 bug』任務的軌跡，標出每一步用到哪一課的概念。""" from mockllm import MockClient, text, tool_use PROJECT_MEMO = "# CLAUDE.md / AGENTS.md\n- 測試指令：python -m unittest\n- 不要修改 tests/ 底下的檔案" PERMISSION = "ask_before_edit" # 權限模式：plan（只看不改）/ ask_before_edit / auto TRAJ = [ ("todo_write", {"todos": ["重現錯誤", "找出原因", "修改", "驗證"]}, "第 17 課 待辦清單"), ("bash", {"command": "python -m unittest"}, "第 27 課 執行程式／第 41 課 沙箱"), ("grep", {"pattern": "def total"}, "第 26 課 按需載入上下文"), ("read", {"path": "pricing.py"}, "第 28 課 檔案工具"), ("edit", {"path": "pricing.py", "old": "s - discount", "new": "s * (1 - discount)"}, "第 28 課 str_replace／第 40 課 核准"), ("bash", {"command": "python -m unittest"}, "第 18 課 用外部回饋自我修正"), ] def policy(ctx): if ctx.turn < len(TRAJ): name, args, _ = TRAJ[ctx.turn] return tool_use(name, args) return text("已修好：折扣算法錯誤，所有測試通過。") FAKE = {"todo_write": "清單已更新", "grep": "pricing.py:1: def total(prices, discount=0):", "read": "…return round(s - discount, 2)", "edit": "已修改"} bash_runs = [0] def run_tool(name, args): if name == "bash": bash_runs[0] += 1 return "FAILED (failures=1)" if bash_runs[0] == 1 else "OK" if name == "edit" and PERMISSION == "ask_before_edit": print(" 🙋 權限模式 %s：詢問使用者 → 允許" % PERMISSION) return FAKE[name] tools = [{"name": n, "description": n, "input_schema": {"type": "object"}} for n in ("todo_write", "bash", "grep", "read", "edit")] client = MockClient(policy) msgs = [{"role": "user", "content": "test_discount 失敗了，幫我修"}] print("系統提示會自動附上專案說明檔：\n" + PROJECT_MEMO + "\n") step = 0 while True: r = client.messages.create(model="mock", max_tokens=1000, system=PROJECT_MEMO, tools=tools, messages=msgs) msgs.append({"role": "assistant", "content": r.content}) if r.stop_reason != "tool_use": break b = r.content[0] print("%d. %-10s %s\n （%s）" % (step + 1, b.name, b.input, TRAJ[step][2])) out = run_tool(b.name, b.input) print(" → %s" % out) msgs.append({"role": "user", "content": [{"type": "tool_result", "tool_use_id": b.id, "content": out}]}) step += 1 print("✅", r.content[0].text)

▶ 執行結果（這是實際執行的輸出）

系統提示會自動附上專案說明檔： # CLAUDE.md / AGENTS.md - 測試指令：python -m unittest - 不要修改 tests/ 底下的檔案 1. todo_write {'todos': ['重現錯誤', '找出原因', '修改', '驗證']} （第 17 課 待辦清單） → 清單已更新 2. bash {'command': 'python -m unittest'} （第 27 課 執行程式／第 41 課 沙箱） → FAILED (failures=1) 3. grep {'pattern': 'def total'} （第 26 課 按需載入上下文） → pricing.py:1: def total(prices, discount=0): 4. read {'path': 'pricing.py'} （第 28 課 檔案工具） → …return round(s - discount, 2) 5. edit {'path': 'pricing.py', 'old': 's - discount', 'new': 's * (1 - discount)'} （第 28 課 str_replace／第 40 課 核准） 🙋 權限模式 ask_before_edit：詢問使用者 → 允許 → 已修改 6. bash {'command': 'python -m unittest'} （第 18 課 用外部回饋自我修正） → OK ✅ 已修好：折扣算法錯誤，所有測試通過。

產品功能更新很快，細節以兩家公司的官方文件為準。你在第 32 課寫的迷你程式代理，就是它們的縮小版——差別主要在工具的完整度、上下文管理與安全機制的成熟度。

🧭 這一課的重點

Claude Code 與 Codex 都是本課程架構的實作：代理迴圈加上檔案、終端機、待辦清單、專案說明檔（CLAUDE.md／AGENTS.md）、MCP、子代理、上下文壓縮與權限沙箱。差別在預設工作方式；它們有效是因為程式任務可驗證、可回復、價值高。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
