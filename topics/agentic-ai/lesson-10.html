工具錯誤處理

這一課的目標

  • 把例外轉成 tool_result 而不是讓程式崩潰
  • 使用 is_error 標記錯誤
  • 寫出能幫助模型自我修正的錯誤訊息

工具會出錯：檔案不存在、網路逾時、參數不合法。天真的寫法是讓例外往上丟，整個代理當掉。正確的做法是攔下例外，把錯誤訊息當成工具結果回給模型，並標上 is_error: true。

模型看到錯誤後，通常會自己調整：換個參數、換個工具、或向使用者說明。所以錯誤訊息要有幫助——不只說「錯了」，還要說「為什麼錯、正確的應該長什麼樣子」。

沒幫助的錯誤有幫助的錯誤
KeyError找不到商品「蘋果」。可用商品：apple, banana
Invalid inputdate 格式錯誤，應為 YYYY-MM-DD，收到「下週五」
Error 500庫存服務暫時無法使用，請稍後再試或改查 check_stock_cache

🐍 Python 範例（離線版）　下載 b10_tool_errors.py　需同資料夾的 mockllm.py

模型第一次用中文名稱查庫存而失敗，看到錯誤訊息中列出的可用名稱後，自己改用英文再查一次。

# -*- coding: utf-8 -*- """第 10 課：工具出錯怎麼辦？——不要讓程式當掉，把錯誤「告訴模型」(is_error=True)，讓它自己修正。""" import json from mockllm import MockClient, text, tool_use STOCK = {"apple": 12, "banana": 0} def check_stock(item): if item not in STOCK: raise ValueError("找不到商品 '%s'。可用商品：%s" % (item, ", ".join(STOCK))) return STOCK[item] def policy(ctx): res = ctx.results() if ctx.turn == 0: return tool_use("check_stock", {"item": "蘋果"}) # 第一次：用了中文名稱（錯） name, out, err = res[0] if err: # 看到錯誤訊息 → 自我修正 return [text("名稱要用英文，我改用 apple 再查一次。"), tool_use("check_stock", {"item": "apple"})] return text("蘋果還有 %s 個。" % out) def execute(b): """把例外轉成 tool_result，而不是讓整個代理崩潰。""" try: return {"type": "tool_result", "tool_use_id": b.id, "content": json.dumps(check_stock(**b.input))} except Exception as e: return {"type": "tool_result", "tool_use_id": b.id, "content": "錯誤：%s" % e, "is_error": True} tools = [{"name": "check_stock", "description": "查商品庫存（商品名稱用英文小寫）", "input_schema": {"type": "object", "properties": {"item": {"type": "string"}}, "required": ["item"]}}] client, messages = MockClient(policy), [{"role": "user", "content": "蘋果還有貨嗎？"}] while True: r = client.messages.create(model="mock", max_tokens=500, tools=tools, messages=messages) messages.append({"role": "assistant", "content": r.content}) if r.stop_reason != "tool_use": break results = [execute(b) for b in r.content if b.type == "tool_use"] for x in results: print(" tool_result%s：%s" % ("（is_error）" if x.get("is_error") else "", x["content"])) messages.append({"role": "user", "content": results}) print(r.content[-1].text)

▶ 執行結果（這是實際執行的輸出）

tool_result（is_error）：錯誤：找不到商品 '蘋果'。可用商品：apple, banana tool_result：12 蘋果還有 12 個。

🧭 這一課的重點

工具出錯時要攔下例外，把錯誤訊息以 is_error 的 tool_result 回給模型，而不是讓代理崩潰。錯誤訊息要說明原因與正確格式，模型通常能據此自我修正。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
