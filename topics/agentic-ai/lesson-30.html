MCP：模型上下文協定

這一課的目標

  • 理解 MCP 要解決的問題
  • 看懂 MCP 的 JSON-RPC 訊息
  • 把 MCP 工具轉成 API 工具

每個代理都要連 GitHub、資料庫、Slack、筆記……如果每個代理都要為每個服務各寫一次整合，就是 M × N 的工作量。MCP（Model Context Protocol）是 Anthropic 在 2024 年底提出的開放標準：服務提供者寫一個 MCP 伺服器，任何支援 MCP 的代理（客戶端）都能直接使用。之後 OpenAI、Google 等也陸續支援。

MCP 底層是 JSON-RPC 2.0：客戶端送出帶有 method 與 id 的請求，伺服器回應對應 id 的結果。最常用的幾個方法：

方法作用
initialize握手，交換協定版本與能力
tools/list列出伺服器提供的工具（名稱、說明、inputSchema）
tools/call呼叫某個工具並取得結果
resources/*、prompts/*提供可讀取的資料與提示範本

傳輸方式有兩種：本機的 stdio（代理把伺服器當子行程啟動）與遠端的 HTTP。Claude Code、Codex 都能設定 MCP 伺服器；Claude API 也有 MCP 連接器，可以直接把遠端伺服器交給 Claude。

🐍 Python 範例（離線版）　下載 e30_mcp.py　需同資料夾的 mockllm.py

在同一個行程裡做一個迷你 MCP 伺服器與客戶端，印出每一則 JSON-RPC 訊息，最後把 MCP 工具轉成 API 工具格式。

# -*- coding: utf-8 -*- """第 30 課：MCP（Model Context Protocol）——工具的「USB 介面標準」。 工具提供者寫一個 MCP 伺服器；任何支援 MCP 的代理（客戶端）都能用同一套協定發現並呼叫它。 MCP 底層是 JSON-RPC 2.0。這裡在同一個行程裡做一個迷你伺服器與客戶端，看清楚往返的訊息。""" import json # ───── 伺服器端（工具提供者）───── NOTES = {"購物": "牛奶、雞蛋", "會議": "週五 10 點"} SERVER_TOOLS = [{"name": "get_note", "description": "依標題讀取筆記", "inputSchema": {"type": "object", "properties": {"title": {"type": "string"}}, "required": ["title"]}}] def server_handle(raw): req = json.loads(raw) m, rid = req["method"], req.get("id") if m == "initialize": res = {"protocolVersion": "2025-06-18", "capabilities": {"tools": {}}, "serverInfo": {"name": "notes-server", "version": "1.0"}} elif m == "tools/list": res = {"tools": SERVER_TOOLS} elif m == "tools/call": title = req["params"]["arguments"]["title"] res = {"content": [{"type": "text", "text": NOTES.get(title, "沒有這則筆記")}], "isError": title not in NOTES} else: return json.dumps({"jsonrpc": "2.0", "id": rid, "error": {"code": -32601, "message": "Method not found"}}) return json.dumps({"jsonrpc": "2.0", "id": rid, "result": res}, ensure_ascii=False) # ───── 客戶端（代理這一側）───── class MCPClient(object): def __init__(self, transport): self.send, self.n = transport, 0 def request(self, method, params=None): self.n += 1 raw = json.dumps({"jsonrpc": "2.0", "id": self.n, "method": method, "params": params or {}}, ensure_ascii=False) print("→", raw) resp = self.send(raw) print("←", resp) return json.loads(resp)["result"] c = MCPClient(server_handle) # 真實情況的傳輸層是 stdio（本機子行程）或 HTTP c.request("initialize", {"protocolVersion": "2025-06-18", "capabilities": {}, "clientInfo": {"name": "my-agent", "version": "0.1"}}) # （完整流程中，客戶端接著會送一個 notifications/initialized 通知，這裡省略） tools = c.request("tools/list")["tools"] # 把 MCP 工具轉成 LLM API 的工具格式：只差在 inputSchema → input_schema api_tools = [{"name": t["name"], "description": t["description"], "input_schema": t["inputSchema"]} for t in tools] print("\n轉成 API 工具：", json.dumps(api_tools, ensure_ascii=False)) # 當模型要求 get_note({"title": "會議"}) 時，代理轉送給 MCP 伺服器： out = c.request("tools/call", {"name": "get_note", "arguments": {"title": "會議"}}) print("\n要放進 tool_result 的內容：", out["content"][0]["text"])

# -*- coding: utf-8 -*- """第 30 課（Claude API 版）：MCP 連接器（beta）——直接把遠端 MCP 伺服器交給 Claude， API 會自己做 tools/list 與 tools/call。兩半都要給：mcp_servers 與對應名稱的 mcp_toolset。 （本機的 stdio MCP 伺服器則可用 SDK 的 anthropic.lib.tools.mcp 輔助函式轉成工具，交給 tool_runner。）""" import anthropic client = anthropic.Anthropic() r = client.beta.messages.create( model="claude-opus-5-5", max_tokens=16000, betas=["mcp-client-2025-11-20"], mcp_servers=[{"type": "url", "url": "https://example.com/mcp", "name": "notes"}], # 換成你的 MCP 伺服器 tools=[{"type": "mcp_toolset", "mcp_server_name": "notes"}], messages=[{"role": "user", "content": "我的會議筆記寫了什麼？"}], ) for b in r.content: print(b.type, getattr(b, "text", "") or getattr(b, "input", ""))

🧭 這一課的重點

MCP 是開放的工具介面標準：服務方寫 MCP 伺服器，任何支援的代理都能使用，解決 M×N 整合問題。底層是 JSON-RPC 2.0，核心方法有 initialize、tools/list、tools/call；傳輸有本機 stdio 與遠端 HTTP。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
