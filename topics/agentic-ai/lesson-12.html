參數驗證與嚴格模式

這一課的目標

  • 在執行前驗證工具參數
  • 把驗證錯誤回饋給模型
  • 認識 strict 模式的保證與限制

模型產生的參數大多數時候是對的，但「大多數」不夠。人數填成「兩位」、日期填成「下週五」、多出不存在的欄位——這些都會讓你的程式出錯，甚至造成危險（例如金額被填成負數）。

所以在執行工具之前一定要驗證：型別、必填欄位、範圍、可選值、不允許的多餘欄位。驗證失敗就把錯誤訊息當 is_error 的 tool_result 回給模型，它通常會修正。

Claude API 提供嚴格模式（工具定義加上 "strict": true），透過「約束解碼」保證產生的參數一定符合 schema。但 schema 能表達的有限（例如數值範圍、字串長度不支援），而且「格式正確」不等於「商業上合理」——退款金額不能超過訂單金額這種規則，仍然要在你的程式裡檢查。

🐍 Python 範例（離線版）　下載 b12_validate.py　需同資料夾的 mockllm.py

一個 40 行的迷你 JSON Schema 驗證器，檢查四組參數。

# -*- coding: utf-8 -*- """第 12 課：參數驗證——永遠不要相信模型給的參數一定正確。 寫一個迷你 JSON Schema 驗證器，在執行工具前先檢查。""" def validate(schema, data, path="input"): errs = [] t = schema.get("type") types = {"object": dict, "string": str, "integer": int, "number": (int, float), "boolean": bool, "array": list} if t and not isinstance(data, types[t]) or (t in ("integer", "number") and isinstance(data, bool)): return ["%s 應為 %s，收到 %r" % (path, t, data)] if "enum" in schema and data not in schema["enum"]: errs.append("%s 必須是 %s 之一，收到 %r" % (path, schema["enum"], data)) if t in ("integer", "number"): if "minimum" in schema and data < schema["minimum"]: errs.append("%s 不可小於 %s" % (path, schema["minimum"])) if "maximum" in schema and data > schema["maximum"]: errs.append("%s 不可大於 %s" % (path, schema["maximum"])) if t == "object": for k in schema.get("required", []): if k not in data: errs.append("缺少必填欄位 %s.%s" % (path, k)) props = schema.get("properties", {}) for k, v in data.items(): if k in props: errs += validate(props[k], v, path + "." + k) elif schema.get("additionalProperties") is False: errs.append("不允許的欄位 %s.%s" % (path, k)) return errs schema = {"type": "object", "additionalProperties": False, "required": ["destination", "passengers"], "properties": {"destination": {"type": "string"}, "passengers": {"type": "integer", "minimum": 1, "maximum": 8}, "cabin": {"type": "string", "enum": ["economy", "business"]}}} for call in [{"destination": "東京", "passengers": 2}, {"destination": "東京", "passengers": "兩位"}, {"passengers": 12, "cabin": "first"}, {"destination": "大阪", "passengers": 1, "seat": "窗邊"}]: e = validate(schema, call) print(("✓ 通過 " if not e else "✗ 拒絕 ") + str(call)) for x in e: print(" →", x) print("被拒絕時，把錯誤文字當成 is_error=True 的 tool_result 回給模型，它通常會自己修正參數。")

▶ 執行結果（這是實際執行的輸出）

✓ 通過 {'destination': '東京', 'passengers': 2} ✗ 拒絕 {'destination': '東京', 'passengers': '兩位'} → input.passengers 應為 integer，收到 '兩位' ✗ 拒絕 {'passengers': 12, 'cabin': 'first'} → 缺少必填欄位 input.destination → input.passengers 不可大於 8 → input.cabin 必須是 ['economy', 'business'] 之一，收到 'first' ✗ 拒絕 {'destination': '大阪', 'passengers': 1, 'seat': '窗邊'} → 不允許的欄位 input.seat 被拒絕時，把錯誤文字當成 is_error=True 的 tool_result 回給模型，它通常會自己修正參數。

# -*- coding: utf-8 -*- """第 12 課（Claude API 版）：strict: true 讓 Claude 產生的工具參數「保證」符合 schema。 schema 需要 additionalProperties: false 與 required。仍建議在伺服器端再驗證一次商業規則。""" import anthropic client = anthropic.Anthropic() r = client.messages.create( model="claude-opus-5-5", max_tokens=16000, messages=[{"role": "user", "content": "幫我訂兩張下週五飛東京的商務艙機票"}], tools=[{ "name": "book_flight", "description": "預訂機票", "strict": True, "input_schema": { "type": "object", "properties": { "destination": {"type": "string"}, "date": {"type": "string", "format": "date"}, "passengers": {"type": "integer", "enum": [1, 2, 3, 4, 5, 6, 7, 8]}, "cabin": {"type": "string", "enum": ["economy", "business"]}, }, "required": ["destination", "date", "passengers", "cabin"], "additionalProperties": False, }, }], ) for b in r.content: if b.type == "tool_use": print("符合 schema 的參數：", b.input)

🧭 這一課的重點

執行工具前一定要驗證參數的型別、必填、範圍、可選值與多餘欄位，失敗時以 is_error 回饋給模型。strict 模式保證參數符合 schema，但無法表達所有限制，商業規則仍須在程式中檢查。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
