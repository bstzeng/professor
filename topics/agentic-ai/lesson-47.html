模組 H｜實務與未來 · 第 47 課

代理框架與 SDK

這一課的目標

  • 認識各種建構代理的方式
  • 比較手寫迴圈與框架的取捨
  • 知道各方案負責的範圍

這門課一直手寫迴圈，因為這是理解原理最好的方式。實務上有幾種現成的選擇，差別在於誰負責迴圈、誰負責執行環境：

做法迴圈執行環境適合
手寫迴圈（Messages API）你你需要完全掌控
SDK Tool RunnerSDK你自訂工具、少寫程式
Claude Agent SDKSDK（等於 Claude Code 當函式庫）你需要讀檔、改檔、Bash 等內建工具
Managed Agents（託管）AnthropicAnthropic 的沙箱容器長時間執行、不想管基礎設施
第三方框架（如 LangGraph）框架你跨模型供應商、複雜的狀態流程

選擇時考慮：需要多少客製化、是否要內建工具、要不要自己維運、能否接受依賴特定平台。無論用哪一種，理解底下的迴圈都能讓你在出問題時知道該往哪裡查。

🐍 Python 範例（離線版）　下載 h47_frameworks.py　需同資料夾的 mockllm.py

▶ 執行結果（這是實際執行的輸出）

■ 手寫迴圈（Messages API） 分工：你寫：迴圈、工具、錯誤處理、記憶 優點：最大彈性、沒有黑盒子 注意：要自己處理很多細節 ■ SDK Tool Runner（beta） 分工：你寫：工具函式；SDK 跑迴圈 優點：程式碼最少、仍在自己的機器上 注意：客製流程時要用它提供的掛鉤 ■ Claude Agent SDK 分工：你寫：提示與設定；內建讀檔、改檔、Bash、搜尋等工具 優點：等於把 Claude Code 當函式庫用 注意：比較重；你仍需自己部署 ■ Managed Agents（託管） 分工：你寫：代理設定；Anthropic 跑迴圈並提供沙箱容器 優點：不用管基礎設施、可長時間執行 注意：依賴平台；設定要版本控管 ■ 第三方框架（LangGraph 等） 分工：你寫：用框架的節點與狀態圖描述流程 優點：可跨模型供應商、生態系豐富 注意：抽象層多，除錯時要穿透框架 建議：先用手寫迴圈理解原理（就是這門課做的事），再依需要換成框架。

🧭 這一課的重點

建構代理可手寫迴圈、用 SDK Tool Runner、Claude Agent SDK（內建 Claude Code 工具）、託管的 Managed Agents，或第三方框架；差別在誰負責迴圈與執行環境。理解底層迴圈有助於除錯。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
