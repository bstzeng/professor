路由與交接

這一課的目標

  • 用路由把請求分派給專門代理
  • 實作代理之間的交接
  • 理解路由的好處

客服系統常有帳務、技術、一般三類問題。與其讓一個代理背所有規則與工具，不如先路由：用一個小而快的模型（甚至只是分類器）判斷類型，交給對應的專門代理。

有時路由會判斷錯，或者問題處理到一半發現需要另一個專長。這時可以交接（handoff）：專門代理說「這不是我的範圍」，把原問題與已知資訊轉給另一個代理。交接時要帶上足夠的脈絡，別讓使用者重講一次。

  • 每個代理的提示與工具都很聚焦，表現更穩定。
  • 權限可以分開：帳務代理才有退款工具。
  • 路由本身便宜又快。

🐍 Python 範例（離線版）　下載 f35_router.py　需同資料夾的 mockllm.py

四個問題經過路由分派；第四個被誤判為帳務，帳務代理把它交接給技術代理。

# -*- coding: utf-8 -*- """第 35 課：路由（routing）與交接（handoff）。 路由器先判斷問題類型，交給專門的代理；專門代理處理不了時，可以把對話「交接」給另一個代理。""" from mockllm import MockClient, text def classify(q): r = MockClient(lambda ctx: text("billing" if any(w in q for w in ("扣款", "發票", "退費")) else "tech" if any(w in q for w in ("當機", "錯誤", "登入")) else "general")) return r.messages.create(model="mock", max_tokens=10, system="只輸出 billing / tech / general 其中之一", messages=[{"role": "user", "content": q}]).content[0].text AGENTS = { "billing": lambda q: "【帳務代理】已查到重複扣款，3 個工作天內退回。" if "扣款" in q else "HANDOFF:tech", "tech": lambda q: "【技術代理】請清除快取後重新登入；若仍失敗，我幫你重設密碼。", "general": lambda q: "【一般客服】我們的營業時間是 9:00～18:00。", } def handle(q): route = classify(q) print("問題：%s\n 路由 → %s" % (q, route)) ans = AGENTS[route](q) if ans.startswith("HANDOFF:"): # 交接：把原問題與已知資訊轉給另一個代理 to = ans.split(":")[1] print(" 帳務代理判斷不是帳務問題 → 交接給 %s" % to) ans = AGENTS[to](q) print(" " + ans) for q in ["這個月被扣款兩次！", "App 一直顯示登入錯誤", "你們幾點開門？", "發票上的登入帳號錯誤"]: handle(q) print("\n好處：每個代理的提示與工具都很聚焦；路由本身可以用小而快的模型。")

▶ 執行結果（這是實際執行的輸出）

問題：這個月被扣款兩次！ 路由 → billing 【帳務代理】已查到重複扣款，3 個工作天內退回。 問題：App 一直顯示登入錯誤 路由 → tech 【技術代理】請清除快取後重新登入；若仍失敗，我幫你重設密碼。 問題：你們幾點開門？ 路由 → general 【一般客服】我們的營業時間是 9:00～18:00。 問題：發票上的登入帳號錯誤 路由 → billing 帳務代理判斷不是帳務問題 → 交接給 tech 【技術代理】請清除快取後重新登入；若仍失敗，我幫你重設密碼。 好處：每個代理的提示與工具都很聚焦；路由本身可以用小而快的模型。

🧭 這一課的重點

路由先判斷請求類型再交給專門代理，可用小而快的模型；專門代理遇到範圍外問題時可交接給其他代理，並帶上足夠脈絡。好處是提示與工具聚焦、權限可分開、路由成本低。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
