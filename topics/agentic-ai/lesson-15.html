ReAct：推理與行動交錯

這一課的目標

  • 認識 ReAct 的 Thought／Action／Observation 格式
  • 理解早期代理如何用文字解析運作
  • 比較文字格式與原生工具呼叫

2022 年的論文〈ReAct〉提出一個影響深遠的想法：讓模型交替輸出推理（Thought）和行動（Action），再把行動的觀察結果（Observation）接回去。推理幫助模型決定做什麼，觀察結果又修正推理。

在 API 還沒有原生工具呼叫的年代，代理就是靠這種文字格式運作：模型輸出「Action: search」「Action Input: 玉山高度」，程式用正規表達式解析、執行，再把「Observation: 3952 公尺」貼回提示。

缺點是脆弱：模型格式寫錯一點就解析失敗。現代 API 改用結構化的 tool_use 區塊，可靠得多——但「想一步、做一步、看結果再想」的精神，正是今天所有代理的基礎。

🐍 Python 範例（離線版）　下載 c15_react.py　需同資料夾的 mockllm.py

用純文字格式與正規表達式，跑一個三步的 ReAct 代理。

# -*- coding: utf-8 -*- """第 15 課：ReAct（Reason + Act）——在原生工具呼叫出現前，代理是靠「文字格式」運作的： 模型輸出 Thought / Action / Action Input，程式用正規表達式解析、執行，再把 Observation 接回去。""" import re KB = {"台灣最高的山": "玉山", "玉山高度": "3952 公尺", "富士山高度": "3776 公尺"} def search(q): return KB.get(q, "查無資料") # 假模型：根據目前的 scratchpad 產生下一段文字 def fake_llm(scratch): n = scratch.count("Observation:") return ["Thought: 先找出台灣最高的山。\nAction: search\nAction Input: 台灣最高的山", "Thought: 是玉山，再查它的高度。\nAction: search\nAction Input: 玉山高度", "Thought: 也要查富士山來比較。\nAction: search\nAction Input: 富士山高度", "Thought: 3952 − 3776 = 176。\nFinal Answer: 玉山（3952 公尺）比富士山高 176 公尺。"][n] scratch = "Question: 台灣最高的山比富士山高多少？\n" for step in range(6): out = fake_llm(scratch) scratch += out + "\n" print(out) if "Final Answer:" in out: break act = re.search(r"Action: (\w+)\nAction Input: (.+)", out) # 解析文字 → 動作 obs = {"search": search}[act.group(1)](act.group(2).strip()) scratch += "Observation: %s\n" % obs print("Observation:", obs) print("\n缺點：格式一錯就解析失敗。現代 API 改用結構化的 tool_use 區塊，但『想一步、做一步』的精神沒變。")

▶ 執行結果（這是實際執行的輸出）

Thought: 先找出台灣最高的山。 Action: search Action Input: 台灣最高的山 Observation: 玉山 Thought: 是玉山，再查它的高度。 Action: search Action Input: 玉山高度 Observation: 3952 公尺 Thought: 也要查富士山來比較。 Action: search Action Input: 富士山高度 Observation: 3776 公尺 Thought: 3952 − 3776 = 176。 Final Answer: 玉山（3952 公尺）比富士山高 176 公尺。 缺點：格式一錯就解析失敗。現代 API 改用結構化的 tool_use 區塊，但『想一步、做一步』的精神沒變。

🧭 這一課的重點

ReAct 讓模型交替輸出推理（Thought）與行動（Action），再接回觀察（Observation）。早期代理靠文字格式與正規表達式解析，容易出錯；現代改用結構化 tool_use，但交錯推理與行動的精神不變。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
