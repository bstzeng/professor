評估者與優化者

這一課的目標

  • 認識評估者－優化者模式
  • 設計明確的評分標準
  • 知道這個模式適合什麼任務

評估者－優化者（evaluator-optimizer）模式：一個代理負責產生，另一個代理依明確的評分標準檢查並給回饋，產生者據此修改，直到合格或達到次數上限。

它適合「好壞可以清楚描述，而且回饋能帶來改進」的任務：翻譯、文案、程式碼審查、依規範撰寫文件。評分標準越具體越好——「有具體數字、不超過 40 字、有行動呼籲」比「寫得好一點」有用得多。

評估者可以是另一個模型，也可以是程式規則，或兩者混合。能用程式檢查的（字數、格式、測試）就用程式，客觀又便宜；需要判斷的（語氣、說服力）才交給模型。

🐍 Python 範例（離線版）　下載 f36_evaluator.py　需同資料夾的 mockllm.py

寫手連寫三稿，評審依三項標準打分，第三稿才全部通過。

# -*- coding: utf-8 -*- """第 36 課：評估者－優化者（evaluator-optimizer）。一個代理寫、另一個代理依評分標準打分並給建議，反覆到合格。""" import json from mockllm import MockClient, text RUBRIC = ["有具體數字", "不超過 40 字", "有行動呼籲"] DRAFTS = ["我們的新咖啡很好喝，歡迎大家來試試看，真的非常好喝喔，保證你會喜歡！", "新品冷萃咖啡，口感滑順，第二杯半價，歡迎嘗鮮。", "新品冷萃咖啡，12 小時低溫萃取，第二杯半價——今天就來店嘗鮮！"] writer = MockClient(lambda ctx: text(DRAFTS[min(ctx.turn, 2)])) def judge(draft): checks = {"有具體數字": any(ch.isdigit() for ch in draft), "不超過 40 字": len(draft) <= 40, "有行動呼籲": any(w in draft for w in ("今天就", "立即", "馬上"))} j = MockClient(lambda ctx: text(json.dumps({"pass": all(checks.values()), "failed": [k for k, v in checks.items() if not v]}, ensure_ascii=False))) return json.loads(j.messages.create(model="mock", max_tokens=200, system="依評分標準評分，輸出 JSON", messages=[{"role": "user", "content": draft}]).content[0].text) msgs = [{"role": "user", "content": "寫一句新品咖啡的廣告文案"}] for i in range(1, 5): draft = writer.messages.create(model="mock", max_tokens=200, messages=msgs).content[0].text v = judge(draft) print("第 %d 稿（%d 字）：%s\n 評審：%s" % (i, len(draft), draft, "✓ 合格" if v["pass"] else "✗ 未達 " + "、".join(v["failed"]))) if v["pass"]: break msgs += [{"role": "assistant", "content": draft}, {"role": "user", "content": "請修改：未達 " + "、".join(v["failed"])}]

▶ 執行結果（這是實際執行的輸出）

第 1 稿（34 字）：我們的新咖啡很好喝，歡迎大家來試試看，真的非常好喝喔，保證你會喜歡！ 評審：✗ 未達 有具體數字、有行動呼籲 第 2 稿（23 字）：新品冷萃咖啡，口感滑順，第二杯半價，歡迎嘗鮮。 評審：✗ 未達 有具體數字、有行動呼籲 第 3 稿（32 字）：新品冷萃咖啡，12 小時低溫萃取，第二杯半價——今天就來店嘗鮮！ 評審：✓ 合格

🧭 這一課的重點

評估者－優化者模式由一個代理產生、另一個依明確標準評分並回饋，反覆修改直到合格。適合好壞可清楚描述的任務；標準要具體，能用程式檢查的就用程式，需要判斷的才交給模型。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
