對話歷史管理：截斷與摘要

這一課的目標

  • 比較滑動視窗、摘要、清除舊輸出三種策略
  • 理解各策略的取捨
  • 認識伺服器端壓縮

歷史太長時，有三種基本策略：

策略做法優點缺點
滑動視窗只保留最近 N 則最簡單會忘記最初的任務與早期資訊
摘要把舊對話濃縮成一段重點保留脈絡可能漏掉細節；摘要本身要花錢
清除舊工具輸出保留對話骨架，把舊的大段結果換成佔位符保留做過什麼看不到原文，需要時得重新讀取

實務上常組合使用：永遠保留最初的任務說明，清除很舊的工具輸出，接近上限時再做摘要。

Claude API 提供兩種伺服器端的做法：compaction（接近門檻時自動摘要較早的內容）與 context editing（自動清除舊的工具結果）。使用 compaction 時要特別注意：回應中的壓縮區塊必須整個接回歷史，只存文字會遺失壓縮狀態。

🐍 Python 範例（離線版）　下載 d21_history.py　需同資料夾的 mockllm.py

同一段 20 則訊息的歷史，比較三種策略後剩下多少 tokens、開頭變成什麼。

# -*- coding: utf-8 -*- """第 21 課：對話太長怎麼辦？三種策略比較—— ① 滑動視窗：只留最近 N 則 ② 摘要：把舊的濃縮成一段 ③ 清除舊工具結果：保留骨架、丟掉大段輸出""" from mockllm import MockClient, text, count_tokens history = [] for i in range(1, 11): history += [{"role": "user", "content": "第 %d 個問題：請分析 log_%d" % (i, i)}, {"role": "assistant", "content": "（分析了 log_%d 的 2000 行輸出……）" % i + "細節" * 300}] print("原始：%d 則訊息，約 %d tokens" % (len(history), count_tokens(history))) def sliding_window(h, keep=4): return h[-keep:] summarizer = MockClient(lambda ctx: text("【先前摘要】使用者請我依序分析 log_1～log_8，已完成；重點：log_3 有逾時、log_7 有記憶體不足。")) def summarize(h, keep=4): old, recent = h[:-keep], h[-keep:] s = summarizer.messages.create(model="mock", max_tokens=300, system="把對話濃縮成要點", messages=[{"role": "user", "content": str(old)}]).content[0].text return [{"role": "user", "content": s}, {"role": "assistant", "content": "了解，我記得先前的重點。"}] + recent def clear_old_outputs(h, keep=4): out = [] for i, m in enumerate(h): if i < len(h) - keep and m["role"] == "assistant": m = {"role": "assistant", "content": "[舊的工具輸出已清除]"} out.append(m) return out for name, fn in [("滑動視窗", sliding_window), ("摘要", summarize), ("清除舊輸出", clear_old_outputs)]: h = fn(history) print("%-6s → %2d 則，約 %5d tokens｜開頭：%s" % (name, len(h), count_tokens(h), h[0]["content"][:30])) print("\n取捨：滑動視窗最簡單但會『失憶』；摘要保留重點但可能漏細節；清除輸出保留脈絡但看不到原文。")

原始：20 則訊息，約 6408 tokens 滑動視窗 → 4 則，約 1282 tokens｜開頭：第 9 個問題：請分析 log_9 摘要 → 6 則，約 1352 tokens｜開頭：【先前摘要】使用者請我依序分析 log_1～log_8，已完 清除舊輸出 → 20 則，約 1582 tokens｜開頭：第 1 個問題：請分析 log_1 取捨：滑動視窗最簡單但會『失憶』；摘要保留重點但可能漏細節；清除輸出保留脈絡但看不到原文。
☁️ Claude API 版（換成真的 Claude，點我展開）

需要 pip install anthropic 並設定環境變數 ANTHROPIC_API_KEY；會實際呼叫 API 並計費。下載 d21_history.py

# -*- coding: utf-8 -*- """第 21 課（Claude API 版）：伺服器端壓縮（compaction，beta）。對話接近門檻時，API 自動摘要較早的內容。 重點：一定要把 response.content「整個」接回歷史，壓縮區塊才會被保留。""" import anthropic client = anthropic.Anthropic() messages = [] def chat(user_message): messages.append({"role": "user", "content": user_message}) r = client.beta.messages.create( betas=["compact-2026-01-12"], model="claude-opus-5-5", max_tokens=16000, messages=messages, context_management={"edits": [{"type": "compact_20260112"}]}, ) messages.append({"role": "assistant", "content": r.content}) # 不要只存文字！ return next(b.text for b in r.content if b.type == "text") print(chat("幫我規劃一個 Python 網路爬蟲")) print(chat("加上處理 JavaScript 動態頁面的功能"))

🧭 這一課的重點

管理過長歷史的三種策略：滑動視窗（簡單但會失憶）、摘要（保留脈絡但可能漏細節）、清除舊工具輸出（保留骨架但看不到原文），常組合使用。Claude API 提供伺服器端的 compaction 與 context editing。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
