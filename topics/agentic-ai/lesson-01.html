什麼是 Agentic AI

這一課的目標

  • 分辨聊天機器人與代理的差別
  • 理解代理的兩個要素：迴圈與工具
  • 認識這門課的地圖與範例的用法

你問聊天機器人「台北現在要帶傘嗎？」，它只能根據訓練資料猜，或者老實說不知道。代理（agent）則不同：它會判斷「我需要即時天氣」，要求程式幫它呼叫氣象 API，看到結果後再回答你。

所謂 Agentic AI，就是讓大型語言模型（LLM）在一個迴圈中，自己決定要使用哪些工具、用幾次、什麼時候停下來，以完成一個目標。Anthropic 的定義很精簡：代理是「在迴圈中，根據環境回饋使用工具的 LLM」。

聊天機器人代理
互動一問一答自己跑很多步
能力只會產生文字能查資料、讀寫檔案、執行程式
誰決定步驟使用者模型自己
例子一般聊天Claude Code、Codex、研究助理

這門課的每一個概念，都附一段 Python 範例。範例有兩個版本：離線版用一個模仿官方 SDK 介面的「假 LLM」（mockllm.py），不需要 API 金鑰就能執行，頁面上顯示的輸出就是實際執行結果；Claude API 版則把假 LLM 換成真的 Claude。兩版的程式結構幾乎一樣——差別只在模型是「規則」還是「真的在思考」。

🐍 Python 範例（離線版）　下載 a01_chat_vs_agent.py　需同資料夾的 mockllm.py

同一個問題，先用「聊天」回答，再用「代理迴圈＋工具」回答。注意代理的 while 迴圈——這就是代理的核心。

# -*- coding: utf-8 -*- """第 1 課：聊天機器人 vs 代理——差別在「有沒有迴圈和工具」。""" import json from mockllm import MockClient, text, tool_use, script # ① 聊天：問一次、答一次。模型不知道今天的天氣，只能猜或拒答。 chat = MockClient(lambda ctx: text("我無法得知即時天氣，建議你查氣象局網站。")) r = chat.messages.create(model="mock", max_tokens=200, messages=[{"role": "user", "content": "台北現在幾度？要帶傘嗎？"}]) print("【聊天】", r.content[0].text) # ② 代理：模型可以「要求」我們幫它執行工具，看到結果後再決定下一步。 def get_weather(city): # 一個真正會被執行的 Python 函式 return {"city": city, "temp_c": 27, "rain_prob": 0.7} agent = MockClient(script( tool_use("get_weather", {"city": "台北"}), # 第 1 步：先查資料 lambda ctx: text("台北現在 %d°C，降雨機率 %d%%，建議帶傘。" % ( ctx.data()["temp_c"], ctx.data()["rain_prob"] * 100)), # 第 2 步：讀工具結果再回答 )) tools = [{"name": "get_weather", "description": "查詢城市即時天氣", "input_schema": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]}}] messages = [{"role": "user", "content": "台北現在幾度？要帶傘嗎？"}] while True: # ← 這個迴圈就是「代理」的核心 r = agent.messages.create(model="mock", max_tokens=500, messages=messages, tools=tools) messages.append({"role": "assistant", "content": r.content}) if r.stop_reason != "tool_use": break for b in r.content: if b.type == "tool_use": print("【代理】模型要求執行：%s(%s)" % (b.name, b.input)) result = get_weather(**b.input) messages.append({"role": "user", "content": [ {"type": "tool_result", "tool_use_id": b.id, "content": json.dumps(result, ensure_ascii=False)}]}) print("【代理】", r.content[0].text) print("模型被呼叫了 %d 次" % agent.calls)

▶ 執行結果（這是實際執行的輸出）

【聊天】 我無法得知即時天氣，建議你查氣象局網站。 【代理】模型要求執行：get_weather({'city': '台北'}) 【代理】 台北現在 27°C，降雨機率 70%，建議帶傘。 模型被呼叫了 2 次
☁️ Claude API 版（換成真的 Claude，點我展開）

需要 pip install anthropic 並設定環境變數 ANTHROPIC_API_KEY；會實際呼叫 API 並計費。下載 a01_chat_vs_agent.py

# -*- coding: utf-8 -*- """第 1 課（Claude API 版）：同一段代理迴圈，換成真的 Claude。 執行前：pip install anthropic，並設定 ANTHROPIC_API_KEY。""" import json import anthropic client = anthropic.Anthropic() MODEL = "claude-opus-5-5" def get_weather(city): # 示範用的假資料；實務上這裡會去呼叫真正的氣象 API return {"city": city, "temp_c": 27, "rain_prob": 0.7} tools = [{"name": "get_weather", "description": "查詢城市即時天氣，回傳攝氏溫度與降雨機率（0～1）。", "input_schema": {"type": "object", "properties": {"city": {"type": "string", "description": "城市名稱，例如：台北"}}, "required": ["city"]}}] messages = [{"role": "user", "content": "台北現在幾度？要帶傘嗎？"}] while True: r = client.messages.create(model=MODEL, max_tokens=16000, tools=tools, messages=messages) messages.append({"role": "assistant", "content": r.content}) # 原封不動接回去 if r.stop_reason != "tool_use": break results = [] for b in r.content: if b.type == "tool_use": print("Claude 要求執行：", b.name, b.input) results.append({"type": "tool_result", "tool_use_id": b.id, "content": json.dumps(get_weather(**b.input), ensure_ascii=False)}) messages.append({"role": "user", "content": results}) print(next(b.text for b in r.content if b.type == "text"))

所有範例可以在 互動實驗室 頁面一次下載。想先了解 LLM 怎麼產生文字，可以參考 〈LLM 推論〉。

🧭 這一課的重點

代理是在迴圈中、根據環境回饋自己決定使用工具的 LLM；和一問一答的聊天機器人相比，它能自己跑多步、查資料、執行程式。本課程每個概念都附離線版（假 LLM）與 Claude API 版兩種 Python 範例。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
