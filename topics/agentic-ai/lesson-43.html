評估：怎麼知道代理變好了

這一課的目標

  • 建立代理的測試案例集
  • 設計自動評分
  • 用 LLM 當評審並驗證評審

改了一句提示，代理變好還是變壞？憑感覺試兩三次是不夠的——LLM 的輸出有隨機性，你修好一個案例時可能弄壞了另外三個。所以需要評估（evals）：一組固定的測試案例、自動評分、統計通過率，每次修改都重跑。

評分方式適合例子
程式規則答案明確有沒有呼叫正確的工具、輸出是否含訂單編號、測試是否通過
LLM 評審開放式、需判斷依評分標準給 1～5 分：正確、完整、語氣
人工建立基準、抽查定期抽樣檢查，也用來驗證 LLM 評審準不準

代理的評估還要看過程，不只看結果：有沒有用對工具、步數是否合理、有沒有做危險動作。案例要涵蓋常見情況、邊界情況與過去出過的錯。

🐍 Python 範例（離線版）　下載 g43_evals.py　需同資料夾的 mockllm.py

五個測試案例，比較兩個版本的代理通過率，再示範 LLM 評審的輸出格式。

# -*- coding: utf-8 -*- """第 43 課：評估（evals）——沒有量測，就不知道改了提示是變好還是變壞。 一組測試案例 + 自動評分（規則或 LLM 評審）+ 通過率；每次修改後都重跑。""" import json from mockllm import MockClient, text CASES = [ {"q": "訂單 A123 到哪了？", "expect_tool": "get_order", "must": ["A123"]}, {"q": "我要退貨", "expect_tool": "start_return", "must": []}, {"q": "你們的營業時間？", "expect_tool": None, "must": ["9"]}, {"q": "幫我把帳號刪掉", "expect_tool": "escalate", "must": []}, {"q": "訂單 B777 可以改地址嗎？", "expect_tool": "get_order", "must": ["B777"]}, ] def agent_v1(q): # 版本 1：簡單的關鍵字規則（模擬一個較弱的提示） if "訂單" in q: return {"tool": "get_order", "args": {"id": q.split("訂單 ")[1][:4]}, "reply": ""} if "退" in q: return {"tool": "start_return", "args": {}, "reply": ""} return {"tool": None, "args": {}, "reply": "請問還有什麼可以幫忙？"} def agent_v2(q): # 版本 2：改進後的提示（補上營業時間與刪帳號要轉人工） r = agent_v1(q) if "營業" in q: r["reply"] = "我們的營業時間是 9:00～18:00。" if "刪" in q: r = {"tool": "escalate", "args": {}, "reply": ""} return r def grade(case, out): ok_tool = out["tool"] == case["expect_tool"] blob = json.dumps(out, ensure_ascii=False) ok_must = all(m in blob for m in case["must"]) return ok_tool and ok_must for name, agent in [("v1", agent_v1), ("v2", agent_v2)]: res = [grade(c, agent(c["q"])) for c in CASES] print("%s 通過率 %d/%d %s" % (name, sum(res), len(res), " ".join("✓" if r else "✗" for r in res))) # LLM 當評審：適合沒有標準答案的開放題（要給明確評分標準，並抽樣人工檢查評審本身） judge = MockClient(lambda ctx: text(json.dumps({"score": 4, "reason": "有回答時間，但沒提假日"}, ensure_ascii=False))) v = judge.messages.create(model="mock", max_tokens=200, system="依 1～5 分評分：正確、完整、語氣。輸出 JSON。", messages=[{"role": "user", "content": "問：營業時間？答：我們的營業時間是 9:00～18:00。"}]) print("LLM 評審：", v.content[0].text)

▶ 執行結果（這是實際執行的輸出）

v1 通過率 3/5 ✓ ✓ ✗ ✗ ✓ v2 通過率 5/5 ✓ ✓ ✓ ✓ ✓ LLM 評審： {"score": 4, "reason": "有回答時間，但沒提假日"}

🧭 這一課的重點

評估用固定測試案例、自動評分與通過率衡量代理，每次修改都重跑。評分可用程式規則、LLM 評審（要驗證評審本身）與人工抽查；代理還要評估過程，如工具選擇、步數與危險動作。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
