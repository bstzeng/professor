防護欄

這一課的目標

  • 在三個關口設計防護欄
  • 用允許清單限制工具
  • 理解程式層防護比提示更可靠

防護欄（guardrails）是包在代理外面的檢查，分三個關口：

關口檢查什麼例子
輸入使用者訊息與外部資料偵測信用卡號、過長輸入、明顯的攻擊字串
工具呼叫模型要做的動作工具允許清單、參數格式、金額上限
輸出要給使用者的回覆遮蔽個資、攔下不當承諾、檢查是否引用來源

最重要的原則：防護欄要寫在程式裡，不能只寫在提示裡。提示中寫「不要退款超過 1000 元」是請求，模型可能被說服；程式中寫 if amount > 1000: reject 是規則，不會被說服。

防護欄也可以用另一個（較小的）模型來做分類，例如判斷輸入是否在服務範圍內。但最後的硬性限制，仍應由確定性的程式把關。

🐍 Python 範例（離線版）　下載 g39_guardrails.py　需同資料夾的 mockllm.py

三個關口各一個例子：擋下信用卡號、拒絕不在允許清單的工具與可疑參數、遮蔽輸出中的 email 和電話。

# -*- coding: utf-8 -*- """第 39 課：防護欄（guardrails）——在代理的輸入、工具呼叫、輸出三個關口設檢查。""" import re def input_guard(msg): if re.search(r"\b\d{4}-?\d{4}-?\d{4}-?\d{4}\b", msg): return "請不要在對話中貼信用卡號。" if len(msg) > 5000: return "訊息太長。" return None ALLOWED_TOOLS = {"search_orders", "get_order"} # 這個客服代理只能「讀」，不能退款或刪除 def tool_guard(name, args): if name not in ALLOWED_TOOLS: return "工具 %s 不在允許清單內" % name if name == "get_order" and not re.fullmatch(r"[A-Z]\d{5}", args.get("order_id", "")): return "訂單編號格式錯誤" return None def output_guard(reply): reply = re.sub(r"[\w.+-]+@[\w-]+\.[\w.]+", "[email 已遮蔽]", reply) # 遮蔽個資 reply = re.sub(r"09\d{2}-?\d{3}-?\d{3}", "[電話已遮蔽]", reply) if "保證獲利" in reply: return "（此回覆因含不當承諾而被攔下，已轉人工）" return reply print("輸入：", input_guard("我的卡號是 4111-1111-1111-1111，幫我查")) for call in [("get_order", {"order_id": "A12345"}), ("refund", {"order_id": "A12345"}), ("get_order", {"order_id": "1 OR 1=1"})]: print("工具 %-10s %-28s → %s" % (call[0], call[1], tool_guard(*call) or "放行 ✓")) print("輸出：", output_guard("已通知負責人 amy@shop.com，電話 0912-345-678。")) print("輸出：", output_guard("這支基金保證獲利！")) print("\n原則：防護欄放在『程式』裡，而不是只寫在提示裡拜託模型遵守——模型可能被說服，程式不會。")

▶ 執行結果（這是實際執行的輸出）

輸入： 請不要在對話中貼信用卡號。 工具 get_order {'order_id': 'A12345'} → 放行 ✓ 工具 refund {'order_id': 'A12345'} → 工具 refund 不在允許清單內 工具 get_order {'order_id': '1 OR 1=1'} → 訂單編號格式錯誤 輸出： 已通知負責人 [email 已遮蔽]，電話 [電話已遮蔽]。 輸出： （此回覆因含不當承諾而被攔下，已轉人工） 原則：防護欄放在『程式』裡，而不是只寫在提示裡拜託模型遵守——模型可能被說服，程式不會。

🧭 這一課的重點

防護欄在輸入、工具呼叫、輸出三個關口檢查：偵測敏感輸入、用允許清單與參數檢查限制動作、遮蔽個資與攔下不當內容。最重要的是把硬性限制寫在程式裡，而不只是寫在提示中。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
