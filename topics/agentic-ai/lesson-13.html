Tool Runner：讓 SDK 跑迴圈

這一課的目標

  • 理解 Tool Runner 幫你做了什麼
  • 用裝飾器定義工具
  • 知道何時改用手寫迴圈

前面幾課我們一直手寫迴圈：送出、檢查 stop_reason、執行工具、接回結果。這段程式每個代理都一樣，所以官方 SDK 把它包成 Tool Runner（目前是 beta 功能）：你只要用 @beta_tool 裝飾器寫好工具函式，SDK 會自動產生 schema、跑迴圈、執行工具、接回結果。

Tool Runner 是一個迭代器：每一輪 yield 一則模型回應，你可以在迴圈裡觀察、記錄、甚至中途修改。它仍然跑在你自己的機器上，工具也由你提供。

什麼時候還需要手寫迴圈？當你需要非常特殊的控制流程、不想依賴 beta 功能，或是想徹底理解代理怎麼運作——就像這門課做的。

🐍 Python 範例（離線版）　下載 b13_runner.py　需同資料夾的 mockllm.py

自己做一個迷你版的 @tool 裝飾器與 tool_runner() 產生器，理解 SDK 版本在背後做了什麼。

# -*- coding: utf-8 -*- """第 13 課：Tool Runner——把迴圈包起來，你只要寫工具函式。 這裡自己做一個迷你版 @tool 裝飾器與 run_tools()，理解 SDK 的 tool_runner 在做什麼。""" import inspect import json from mockllm import MockClient, text, tool_use REG = {} def tool(fn): """裝飾器：自動從簽名產生 schema，並登記到 REG。""" props = {n: {"type": {int: "integer", float: "number"}.get(p.annotation, "string")} for n, p in inspect.signature(fn).parameters.items()} fn.schema = {"name": fn.__name__, "description": inspect.getdoc(fn), "input_schema": {"type": "object", "properties": props, "required": list(props)}} REG[fn.__name__] = fn return fn @tool def add(a: float, b: float): """兩數相加""" return a + b @tool def multiply(a: float, b: float): """兩數相乘""" return a * b def tool_runner(client, messages, tools, max_iterations=10): """產生器：每一輪 yield 一則模型訊息；工具自動執行並接回。""" for _ in range(max_iterations): r = client.messages.create(model="mock", max_tokens=1000, messages=messages, tools=[t.schema for t in tools]) yield r messages.append({"role": "assistant", "content": r.content}) calls = [b for b in r.content if b.type == "tool_use"] if not calls: return messages.append({"role": "user", "content": [ {"type": "tool_result", "tool_use_id": b.id, "content": json.dumps(REG[b.name](**b.input))} for b in calls]}) def policy(ctx): if ctx.turn == 0: return tool_use("add", {"a": 17, "b": 25}) if ctx.turn == 1: return tool_use("multiply", {"a": ctx.data(), "b": 3}) return text("(17 + 25) × 3 = %s" % ctx.data()) for msg in tool_runner(MockClient(policy), [{"role": "user", "content": "(17+25)×3 = ?"}], [add, multiply]): print([("%s%s" % (b.name, b.input)) if b.type == "tool_use" else b.text for b in msg.content])

▶ 執行結果（這是實際執行的輸出）

["add{'a': 17, 'b': 25}"] ["multiply{'a': 42, 'b': 3}"] ['(17 + 25) × 3 = 126']
☁️ Claude API 版（換成真的 Claude，點我展開）

需要 pip install anthropic 並設定環境變數 ANTHROPIC_API_KEY；會實際呼叫 API 並計費。下載 b13_runner.py

# -*- coding: utf-8 -*- """第 13 課（Claude API 版）：SDK 內建的 Tool Runner（beta）。你只寫工具，迴圈交給 SDK。""" import anthropic from anthropic import beta_tool client = anthropic.Anthropic() @beta_tool def add(a: float, b: float) -> str: """兩數相加。 Args: a: 第一個數 b: 第二個數 """ return str(a + b) @beta_tool def multiply(a: float, b: float) -> str: """兩數相乘。 Args: a: 第一個數 b: 第二個數 """ return str(a * b) runner = client.beta.messages.tool_runner( model="claude-opus-5-5", max_tokens=16000, tools=[add, multiply], messages=[{"role": "user", "content": "(17+25)×3 是多少？請用工具計算。"}], ) for message in runner: # 每一輪都會 yield 一則 Claude 的回應 for b in message.content: if b.type == "tool_use": print("工具：", b.name, b.input) elif b.type == "text": print("Claude：", b.text)

🧭 這一課的重點

Tool Runner 把代理迴圈包起來：用 @beta_tool 寫工具函式，SDK 自動產生 schema、執行工具並接回結果，每輪 yield 一則回應供你觀察。需要特殊控制流程或避免依賴 beta 時，再手寫迴圈。

🤖 本課的 Python 範例分兩版：離線版用一個模仿 Anthropic SDK 介面的「假 LLM」（mockllm.py），不需 API 金鑰即可執行，頁面上的輸出就是實際執行的結果；Claude API 版使用官方 anthropic 套件，需要 API 金鑰、會產生費用。API 細節（模型名稱、beta 功能）會隨時間更新，以官方文件為準。
