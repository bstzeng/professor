Orchestrator–Worker：主控與子任務

這一課的目標

  • 了解主控-執行者模式與固定平行化的差別
  • 知道這個模式適合什麼樣的任務
  • 認識它的三個控制點：上限、驗收、彙整

前一課的平行化，前提是你事先知道要切成幾段。但有些任務 連「要做哪些子任務」都要看情況才知道—— 這時就需要一個主控步驟。

1. 結構

主控（Orchestrator）先分析輸入，決定要 產生哪些子任務；執行者（Worker）各自完成 一項；最後由彙整步驟把結果收斂成最終產出。 跟固定平行化的差別在於：子任務的數量與內容是動態決定的。

2. 適合的任務

  • 研究型：一個問題要拆成幾個子問題，取決於問題本身
  • 跨檔案修改：要改哪些檔案，要先看過程式碼才知道
  • 多來源比對：要查幾個來源，取決於初步結果

3. 三個必要的控制點

控制點做法防的是什麼
上限限制子任務數量與總成本主控拆出五十個子任務，帳單爆炸
驗收每個子任務的輸出都要結構化並驗證壞掉的結果混進彙整
彙整品質彙整步驟要能處理矛盾與重複各說各話的拼貼

4. 它已經很接近 Agent 了

主控步驟「自己決定要做什麼」，這已經是自主性的雛形。 差別在於：這個模式的結構仍然是你定的 （分析 → 派工 → 彙整，就這三段），而Agent連整體流程 的形狀都可能是動態的。這條界線正是下一個模組的主題。

檢查你的理解

  1. 說明這個模式與固定平行化的關鍵差別
  2. 列出三個必要的控制點，以及各自防止什麼問題
  3. 解釋它跟Agent的界線在哪裡
