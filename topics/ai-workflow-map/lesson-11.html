n8n：可自架的開源編排平台

這一課的目標

  • 了解n8n跟純SaaS自動化平台的三個主要差異
  • 認識「自架」在資料主權與成本結構上的意義
  • 知道n8n適合與不適合的場景

n8n 是這一類裡最常被提到的開源選項。它同樣是節點式的 流程編排工具，但有三個關鍵差異，讓它在企業與工程背景的 使用者中特別受歡迎。

1. 差異一：可以自架

你可以用 Docker 把它跑在自己的伺服器或電腦上，資料不必 經過第三方雲端。這對受規範的產業（醫療、金融、法務）或 任何處理個資的流程，往往是能不能用的分水嶺。它也提供 雲端版本，兩者流程檔案相容。

2. 差異二：計價邏輯不同

自架的成本主要是伺服器與維運人力，跟執行次數脫鉤。對於 「量很大但每次很便宜」的流程，這個結構比按次計費划算得多； 反過來，如果你一週只跑幾次，維運成本反而不值得。

3. 差異三：可以寫程式

n8n 有 Code 節點，可以直接寫 JavaScript 或 Python 處理資料。 這讓它在座標軸上處於一個微妙又實用的位置：八成的 工作用拖拉完成，剩下兩成用程式補，不必為了一個 特殊需求把整套流程改寫成程式。

比較項SaaS 自動化平台n8n（自架）
資料落點平台雲端你自己的環境
成本結構按執行次數伺服器 + 維運
整合數量更多、更成熟足夠，但長尾較少
維運負擔零你要負責升級、備份、監控
接地端模型不方便同一台機器就能接，延遲低

4. 為什麼它常跟地端模型綁在一起

最後一列是重點：如果你選擇自架的理由是資料不能外流，那麼 流程裡的AI步驟自然也不該送到外部API。n8n 加上地端模型執行 工具（模組 F 會談的 Ollama 一類），可以組成一套資料完全不 出門的AI自動化系統。本站另一門《AI工作流全紀錄》整門課 就是在做這件事，這門課只負責告訴你它在版圖上的位置。
