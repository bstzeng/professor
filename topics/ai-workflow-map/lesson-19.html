Agent SDK：Claude Agent SDK、OpenAI Agents SDK

這一課的目標

  • 了解Agent SDK 幫你處理掉的四件重複工作
  • 認識「官方SDK vs 第三方框架」的取捨：貼合度與可移植性
  • 知道評估任何Agent SDK時該問的三個問題

當Agent從研究話題變成產品形態，模型供應商開始提供自己的 開發套件。Claude Agent SDK 與 OpenAI Agents SDK 是兩個 代表，其他供應商也有對應方案。

1. 它們處理掉的四件重複工作

  • 工具呼叫的迴圈：模型要求呼叫工具 → 執行 → 把結果送回 → 再問模型，這個 loop 不用自己寫
  • 脈絡管理：對話變長時怎麼壓縮、保留什麼、丟掉什麼
  • 權限與確認：哪些工具可以自動執行、哪些必須先問人
  • 可觀測性：每一步的輸入輸出、token 用量、耗時

這四件事你自己寫都寫得出來，但都是「寫起來不難、寫對很煩」 的類型。尤其脈絡管理，是決定長任務能不能跑完的關鍵。

2. 官方 SDK 與第三方框架的取捨

面向官方 Agent SDK第三方框架
與模型的貼合度高，能第一時間用上新能力有時間差
換模型的成本較高較低，抽象層本來就在做這件事
抽象厚度通常較薄、較貼近原始 API視框架而定，可能很厚
生態工具供應商自家的追蹤與評測跨供應商的追蹤與評測

一個折衷做法是：把「呼叫模型」這件事包在自己的一層 薄介面後面，其餘程式碼只依賴這層介面。這樣你既能用 官方 SDK 的新能力，換供應商時也不必翻遍整個程式碼庫。

3. 評估任何 Agent SDK 的三個問題

第一，工具怎麼定義——好不好寫、能不能沿用 既有的函式與 API？第二，失控怎麼辦——有沒有 步數上限、成本上限、危險動作的攔截？第三， 看不看得到過程——出錯時能不能重播每一步。 第三題最常被忽略，卻是實際開發中花最多時間的地方。

檢查你的理解

  1. 說出Agent SDK 幫你處理掉的四件重複工作，並指出哪一件最關鍵
  2. 解釋「薄介面包一層」這個折衷做法解決了什麼問題
