模組 J｜互通標準：讓工具彼此連得起來 · 第 49 課

OpenAI 相容 API：模型可替換性的關鍵

這一課的目標

  • 了解相容API作為事實標準的意義
  • 認識模型路由與備援這兩個實際好處
  • 知道「介面相容」與「行為等價」之間的差距

很多工具的設定畫面上都有一欄「API Base URL」，可以填自訂 位址。這個小欄位背後，是一個影響深遠的事實標準。

1. 為什麼會形成事實標準

當大量工具依照某一家的 API 格式開發之後，其他供應商與 開源方案為了能被這些工具使用，就會提供 相容介面。結果是：地端的推論服務、 各家雲端模型、路由服務，多半都能用同一套請求格式呼叫。

2. 你得到的兩個實際好處

  • 模型路由：同一個流程裡，簡單步驟走便宜小模型、困難步驟走旗艦模型，只要換 base URL 與模型名稱
  • 備援：主要供應商故障或限流時，自動切換到備援供應商，流程不中斷

這兩件事都是成本與可靠度的直接改善，而且幾乎不用改程式碼 ——前提是你一開始就沒有把某一家的專屬功能寫死在流程裡。

3. 相容不等於等價

差異後果
工具呼叫的穩定度不同換模型後，原本可靠的工具呼叫開始出錯
結構化輸出支援程度不同JSON 格式偶爾破損，需要額外驗證
提示敏感度不同同一個提示在另一個模型上表現明顯下降
脈絡長度與計費單位不同成本估算失準

所以換模型是需要重新跑評測的變更，不是 改一行設定就沒事。這也再一次指向模組 M：沒有評測集的 流程，換模型時只能憑感覺。
