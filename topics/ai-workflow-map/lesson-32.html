模組 F｜第五類：地端與自架方案 · 第 32 課

模組總結：資料主權的代價與收益

這一課的目標

  • 把自架的收益與代價逐項列清楚
  • 掌握四個「應該自架」的明確訊號
  • 認識混合架構：不是全有或全無的選擇

地端方案常被兩種極端敘事夾殺：一種說「資料絕不能外流， 一定要自架」，另一種說「自架又貴又難，別想了」。實際上 它就是一組可以逐項計算的取捨。

1. 逐項攤開

面向收益代價
資料完全不出門，合規最單純—
成本量大時單位成本低、可預測前期投資與維運人力
可用性離線可用、不受供應商政策影響壞了自己修，沒有 SLA
能力—複雜任務仍落後旗艦模型
速度短任務延遲低（無網路往返）硬體不足時長輸出很慢
演進模型可自己選、版本自己控要自己追蹤與驗證新版本

2. 四個「應該自架」的明確訊號

  • 法規或合約明文禁止資料離境或交給第三方處理
  • 用量大到雲端 API 的月費已經超過一台伺服器的攤提
  • 流程必須在沒有網路的環境下運作
  • 需要對模型版本有完全控制（例如結果要可長期重現）

四個都不成立的話，先用雲端 API 把流程做出來，通常是更快 也更省的路徑。

3. 混合架構才是常態

最常見的成熟形態不是全地端，而是依資料敏感度與 任務難度分流：含個資的步驟走地端，去識別化後的 困難步驟走雲端；高頻的分類走小模型，低頻的複雜推理走 旗艦。這需要在流程設計時就把「這一步會看到什麼資料」 標註清楚——模組 N 會把它變成一張資料流圖。

模組 F 重點回顧

  • 執行器選有本機API的（如 Ollama），流程才接得上
  • 記憶體估算：4-bit 下約為參數量的 0.6–0.8 倍 GB
  • 多人共用要用生產級推論服務；注意吞吐與延遲的取捨
  • 自架前端是最後一哩路，好用的內部工具本身就是資安措施
  • 按任務難度分級選模型；混合架構是成熟形態

檢查你的理解

  1. 逐項說出自架的收益與代價各三項
  2. 檢查四個「應該自架」的訊號，判斷你的情況成立幾個
  3. 描述一個依資料敏感度分流的混合架構設計
