模組 A｜序幕：什麼是「AI工作流」 · 第 3 課

一組座標軸：雲端↔地端、無碼↔寫程式、固定↔自主

這一課的目標

  • 掌握三條用來定位任何AI工具的座標軸
  • 了解每條軸上的取捨：便利與控制、速度與彈性、自動化程度與可預測性
  • 能把一個沒聽過的新工具大致放到正確位置

工具太多的時候，比較的方式不該是「一個一個看功能」，而是 先建立幾條座標軸，再把工具釘上去。這門課用三條軸，之後 每一個模組都會回頭引用它們。

1. 第一條軸：雲端 ↔ 地端

往雲端走，你得到的是最強的模型、零維運、隨開隨用；付出的是 資料要離開你的環境、成本隨用量成長、以及對供應商的依賴。 往地端走，你得到的是資料主權、固定成本、離線可用；付出的是 硬體投資、維運負擔、以及模型能力上的落差。這條軸沒有正解， 只有「你的資料有多敏感、你的量有多大」。模組 F 會專門談 地端這一側。

2. 第二條軸：無碼 ↔ 寫程式

拖拉節點的平台讓你在一小時內做出可動的流程，代價是碰到平台 沒設計到的情況時會卡死，而且版本控制、測試、code review 這些 軟體工程的基本設施通常很薄弱。寫程式的框架剛好相反：起步慢， 但沒有天花板，而且可以塞進既有的開發流程裡。實務上很多團隊 是兩者混用——用無碼平台做編排與串接，把最複雜 的那一兩個步驟寫成程式再掛回去。

3. 第三條軸：固定流程 ↔ 自主 Agent

固定流程指的是「步驟是你事先寫死的，模型只負責填空」； 自主 Agent 則是「目標交給模型，步驟由它自己決定，用工具、 看結果、再決定下一步」。往自主端走，能處理的任務更開放； 代價是可預測性下降、成本更難估、除錯更困難。模組 L 會完整 討論這條軸，這裡先記一句實務原則：能用固定流程解決 的，不要用 Agent。

4. 練習：把工具釘上去

以這門課後面會談到的幾個例子來說：n8n 大致落在「可雲可地、 偏無碼、偏固定流程」；LangGraph 落在「雲端為主、寫程式、 可固定可自主」；Ollama 是純地端的模型執行層，本身不管流程； Claude Code 這類編碼代理則是「雲端模型、對使用者近乎無碼、 高度自主」。你會發現同一個象限裡的工具彼此才是真正的競爭者， 跨象限的比較常常沒有意義。

檢查你的理解

  1. 說出三條座標軸，以及每條軸兩端各自的代價
  2. 解釋「能用固定流程解決的，不要用Agent」這句話背後的理由
  3. 挑一個你正在用的AI工具，把它釘在這三條軸上
