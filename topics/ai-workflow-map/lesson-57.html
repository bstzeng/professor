模組 K｜工作流設計模式 · 第 57 課

模組總結：先選模式，再選工具

這一課的目標

  • 把五種核心模式收成一張對照表
  • 學會用「這個任務的失敗長什麼樣」來選模式
  • 了解模式如何組合成真實流程

模式層的知識之所以耐用，是因為它跟工具無關。同樣一組 模式，你可以用 n8n 的節點實作、用 LangGraph 寫、或直接 用官方 SDK 手寫。

1. 五種模式對照表

模式解決的問題主要代價
Prompt Chaining任務太複雜、無法定位錯誤延遲與成本上升
Routing輸入類型混雜、成本浪費在簡單案例多一個分類步驟，分類錯會全錯
平行化速度不夠（分段）／穩定度不夠（投票）投票是倍數成本
Orchestrator–Worker子任務無法事先決定成本難估，需要上限控制
Evaluator–Optimizer一次產出品質不穩重試成本，評估可能沒牙齒

2. 選模式的方法：從失敗長相反推

不要問「該用哪個模式」，要問「這個任務現在是怎麼 失敗的」：

  • 做對一半、漏掉步驟 → Prompt Chaining
  • 某幾類輸入特別容易錯 → Routing
  • 同樣輸入時對時錯 → 多路投票
  • 太慢 → 分段平行
  • 格式或完整度不穩 → Evaluator–Optimizer（先用程式檢查）
  • 成本太高 → Routing 分級 + 前置過濾

3. 真實流程是組合出來的

一個成熟的客服流程可能長這樣：規則過濾 → 分類 Routing → 依類別走不同的鏈 → 高風險案例走投票 → 產出後用程式與模型雙重檢查 → 不通過或低信心轉人工。 每一段都是這個模組的一個模式。當你能用模式描述自己的 流程，你就能在任何工具上重建它——這也是為什麼順序是 「先選模式，再選工具」。

模組 K 重點回顧

  • 拆步驟的價值在於製造可檢查的中間產物
  • 分流同時改善品質與成本；一定要有「不確定」類別
  • 分段平行省時間、多路投票買穩定度（倍數成本）
  • 動態派工要有上限、驗收與彙整三個控制點
  • 能用程式檢查的絕不用模型；評估要視角獨立

檢查你的理解

  1. 背出五種模式各自解決的問題與代價
  2. 用「失敗長相」反推法，為你的流程挑一個模式
  3. 把你的流程用模式語言描述一遍
