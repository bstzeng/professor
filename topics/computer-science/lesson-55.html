SQL基礎：用查詢語言操作資料

這一課的目標

  • 認識SQL是關聯式資料庫的標準查詢語言
  • 理解CRUD四個基本操作分別對應哪個SQL指令
  • 用書店範例理解JOIN如何依外鍵關係合併兩張表

第54課建立了books、authors兩張表，也講了外鍵怎麼把它們 關聯起來。但光有表格結構還不夠，還需要一種語言，讓 程式（或使用者）能實際對資料庫下指令：查資料、加資料、 改資料、刪資料。這種語言就是SQL （Structured Query Language，結構化查詢語言）——幾乎所有 主流的關聯式資料庫（MySQL、PostgreSQL、SQLite等）都用 SQL作為操作介面，語法大同小異。

1. CRUD：四個最基本的操作

不管多複雜的應用程式，對資料庫的操作最終都可以歸類成 四種基本動作，合稱CRUD：

操作SQL指令意思
Create（新增）INSERT新增一筆記錄
Read（查詢）SELECT查詢／讀取資料
Update（修改）UPDATE修改既有記錄
Delete（刪除）DELETE刪除記錄

如果你寫過操作陣列或清單的程式，這四個操作其實就對應 「新增一個元素」「讀取元素」「修改某個元素的值」 「刪除某個元素」——差別在於，SQL讓你用一句話描述「要 對哪些符合條件的記錄做什麼」，而不用自己寫迴圈去逐筆 找。這也是SQL被稱為宣告式語言的原因：你 描述「要什麼結果」，資料庫系統自己決定怎麼有效率地找到。

2. 用書店範例看SELECT的基本語法

假設要查詢books表裡所有的書名，SQL寫法大致是：

SELECT 書名 FROM books;

意思是「從books表裡，把書名欄位選出來」。如果要加 條件，例如只查書籍id為3的書，就在後面加上 WHERE 書籍id = 3。

3. 查詢「某作者的所有書」：為什麼需要JOIN

現在遇到一個更實際的問題：使用者想查「王小美寫的所有 書」，但books表裡只有作者id，沒有作者名字；作者名字存 在authors表裡。這時候單獨查books表或單獨查authors表都 不夠，需要把兩張表依照外鍵關係連起來查 ——這正是JOIN要做的事。

JOIN的基本精神是：拿books表的作者id，去跟authors表的 作者id做比對，凡是能配對上的記錄，就把兩邊的欄位合併 成一列輸出。概念上寫法會像：

SELECT books.書名, authors.作者名
FROM books
JOIN authors ON books.作者id = authors.作者id
WHERE authors.作者名 = '王小美';

這句話的意思是：「把books跟authors兩張表，依照 books.作者id等於authors.作者id的規則接起來，然後只留下 作者名是王小美的那些列，最後輸出書名跟作者名。」

INSERT、UPDATE、DELETE：一句話帶過語法精神

三者的語法邏輯跟SELECT一致：INSERT INTO books (...) VALUES (...)新增一筆書籍記錄； UPDATE books SET 書名 = '新書名' WHERE 書籍id = 3修改特定記錄；DELETE FROM books WHERE 書籍id = 3刪除特定記錄。都是「先指定要動哪張 表，再用WHERE指定條件精準命中要處理的那幾筆」，這種 「不小心忘記加WHERE會動到全部資料」的風險，也是資料庫 系統要特別小心操作的原因之一。

檢查你的理解

  1. 能說出CRUD四個操作各自對應哪個SQL指令
  2. 能解釋JOIN的基本目的：依關聯欄位合併兩張表的查詢結果
  3. 能用書店範例描述「查某作者所有書」的JOIN邏輯
