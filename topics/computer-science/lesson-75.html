RISC vs. CISC：兩種指令集設計哲學

這一課的目標

  • 能說出RISC與CISC在指令集設計哲學上的核心差異
  • 能解釋為什麼RISC風格的簡單指令特別適合搭配管線化等現代優化技巧
  • 理解現代x86處理器如何在實作層次把兩種哲學融合起來

回顧第10課介紹指令集架構（ISA）時，曾經提過一個伏筆： 指令集的設計，其實存在兩種截然不同的哲學。這一課要 把這個伏筆完整攤開——這也是為什麼這門課從頭到尾使用 的TOY-CPU，指令設計會是現在這個樣子的原因。

1. CISC：功能豐富的複雜指令

CISC（Complex Instruction Set Computer，複雜 指令集電腦）的設計哲學，是提供大量功能豐富的 指令，讓單一一條指令就能完成相對複雜的 操作（例如一條指令同時完成記憶體讀取＋運算＋寫回）。 x86架構是CISC最具代表性的例子。CISC的 優點是：組合語言或編譯器產生出來的程式碼往往比較精簡 （做同樣的事，需要的指令數量較少）；缺點是：要解碼、 執行這些功能豐富的複雜指令，硬體電路本身也必須更複雜， 設計與驗證的成本更高。

2. RISC：精簡、單純、執行時間可預期的指令

RISC（Reduced Instruction Set Computer，精簡 指令集電腦）的設計哲學完全相反：只提供少量、 單純、執行時間相對固定可預期的基本指令——這正是這門課 TOY-CPU的設計精神：LOAD、STORE、 ADD、SUB這類指令，每一條都 只做一件單純的事，複雜的操作要靠多條簡單指令組合出來。 ARM、RISC-V是RISC最具代表性的架構。 RISC的優點是：指令單純，硬體解碼與執行的電路也能設計 得更單純；缺點是：完成同樣的工作，往往需要用到更多 條指令。

回顧TOY-CPU：為什麼它的指令設計看起來像RISC

這門課從第9課開始使用的TOY-CPU，指令集刻意設計得 精簡單純——這不是巧合，而是刻意向RISC哲學靠攏的 結果：教學上，簡單、規律的指令更容易讓人看懂CPU 內部到底在做什麼，這也正是模組J管線化、超純量等 技巧可以順利用TOY-CPU示範的原因，下一節會說明兩者 之間的關聯。

3. RISC與管線化：簡單的指令，特別適合被拆解重疊

回顧第62課的管線化：指令要能順利拆成IF、ID、EX、MEM、 WB幾個階段，並且讓不同指令重疊處理，每個階段花的時間 最好整齊劃一、可預期。RISC指令天生單純、執行時間相對 固定，正好非常適合這種拆解方式；CISC指令因為功能 複雜，有些指令可能要花好幾個週期才能完成一個階段， 要設計出高效的管線就困難得多。這正是RISC哲學在講求 管線化、超純量這類現代優化技巧的年代裡，重新受到 重視的原因之一。

比較項目RISCCISC
指令數量少，只提供基本操作多，涵蓋大量複雜功能
指令複雜度單純，每條只做一件事複雜，單條可完成多步驟操作
程式碼長度較長（需要更多指令組合）較精簡（少數指令完成較多工作）
硬體解碼與執行複雜度較低，較容易做管線化較高，管線化設計較困難

4. 今天的現況：兩種哲學在實作層次逐漸靠攏

有趣的是，現代x86處理器（CISC架構的代表）內部，其實 並不是直接執行那些功能豐富的複雜指令——它們會先把 每一條CISC指令，即時翻譯成一串更單純、更接近RISC 風格的微指令（micro-ops），再交給內部 真正的執行核心（也就是模組J討論的管線化、超純量、 亂序執行等機制）去處理。換句話說，今天的x86處理器， 對外仍然保留CISC的指令集面貌，但內部運作骨子裡其實 更接近RISC的精神——兩種哲學在實作層次已經有相當程度 的融合。與此同時，ARM架構近年在行動裝置上早已是 主流，甚至在桌上型與筆記型電腦領域也快速崛起（例如 Apple Silicon系列處理器），顯示RISC哲學在今天依然 有它強勁的生命力。
