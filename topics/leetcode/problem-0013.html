Roman to Integer
羅馬數字轉整數

Easy · 簡單 雜湊表 數學 字串

Problem

Roman numerals are represented by seven different symbols: I, V, X, L, C, D and M (values 1, 5, 10, 50, 100, 500, 1000).

Usually, numerals are written largest to smallest from left to right. However, for 4 and 9, the smaller numeral is placed before the larger one and subtracted: IV, IX, XL, XC, CD, CM.

Given a Roman numeral, convert it to an integer.

中文翻譯

羅馬數字由七個符號組成：I=1, V=5, X=10, L=50, C=100, D=500, M=1000。

一般來說是由大到小、從左寫到右。但遇到 4 和 9 的時候，會把小的符號寫在大的左邊表示相減：IV=4, IX=9, XL=40, XC=90, CD=400, CM=900。

給你一個羅馬數字字串，把它轉成整數。

一句話就解完這題

從左往右掃，如果當前符號比右邊那個小，就減它；否則加它。

為什麼這一句就夠了？ 因為羅馬數字的寫法規定是「由大到小」。 唯一會出現「小的在大的左邊」的情形，就是那六個減法形式。 所以「比右邊小」這個條件， 恰好、而且只會，在減法形式的前半個字元上成立。 "MCMXCIV" M C M X C I V ^ ^ ^ ^ 這些「≥ 右邊」-> 加 ^ ^ ^ 這些「< 右邊」-> 減 你完全不需要在程式裡列出 IV、IX、XL… 這六個組合。

範例

範例 1 輸入：s = "III" 輸出：3 範例 2 輸入：s = "LVIII" 輸出：58 說明：L = 50，V = 5，III = 3 範例 3 輸入：s = "MCMXCIV" 輸出：1994 說明：M = 1000，CM = 900，XC = 90，IV = 4

限制條件

  • 1 ≤ s.length ≤ 15
  • s 只含 'I', 'V', 'X', 'L', 'C', 'D', 'M'
  • 保證 s 是 1 到 3999 範圍內的有效羅馬數字

LeetCode 原題

先看懂限制在說什麼

  • 「保證是有效的羅馬數字」是一個非常大的禮物。你不用檢查 "IIII"、"IL"、"VX" 這些非法輸入，也不用回報錯誤。所有解法都可以假設輸入完美。（如果面試官追問「那要怎麼驗證合法性」，那是另一個難度等級的問題 —— 見文末追問。）
  • 長度 ≤ 15：最長的合法羅馬數字是 3888 = "MMMDCCCLXXXVIII"，剛好 15 個字元。
  • 效率完全不是問題，所以這題的評分重點是：你的解法有多簡潔、多能說明白。

解題思路

三種寫法，本質都是同一個觀察，只是實作角度不同：往右看、成對吃、往左掃。

解法一

往右看一格，決定加還是減（最推薦）

class Solution: def romanToInt(self, s: str) -> int: VALUE = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000} total = 0 for i, ch in enumerate(s): v = VALUE[ch] # 比右邊的小 -> 這是減法形式的前半，要減；否則加 if i + 1 < len(s) and v < VALUE[s[i + 1]]: total -= v else: total += v return total

只需要一張 7 筆的表，不需要列出六個減法組合。最後一個字元一定是加（i + 1 < len(s) 不成立），這和羅馬數字「最後一個符號永遠不做減數」的規則一致。

為什麼這個判斷不會誤判？

因為合法的羅馬數字裡，「小的在大的左邊」只可能是那六個減法形式之一。例如 "XIV"（14）：X(10) ≥ I(1) → 加；I(1) < V(5) → 減；V → 加。得到 10 − 1 + 5 = 14 ✔

如果輸入不合法就不保證了："IM" 會被算成 999，但那不是合法的羅馬數字（1000−1 應寫成 "CMXCIX"）。題目保證輸入合法，所以這不是問題 —— 但要知道這個前提在哪裡。

複雜度說明
時間O(n)掃一遍
空間O(1)7 筆常數表
解法二

認出兩字元的組合，一次吃兩個

另一種直覺：既然有六個「雙字元符號」，就把它們也放進表裡，遇到就一次吃兩格。

class Solution: def romanToInt(self, s: str) -> int: VALUE = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000} PAIR = {"IV": 4, "IX": 9, "XL": 40, "XC": 90, "CD": 400, "CM": 900} total, i = 0, 0 while i < len(s): if i + 1 < len(s) and s[i:i + 2] in PAIR: total += PAIR[s[i:i + 2]] i += 2 # 兩個字元一起消化掉 else: total += VALUE[s[i]] i += 1 return total

邏輯上和第 12 題的貪婪法完全對稱（那題是查值找符號，這題是查符號找值）。

缺點是表變大了（7 + 6 = 13 筆），而且要小心 i 的前進步數。好處是意圖非常明確：讀程式碼的人一眼就看得出「CM 是一個符號」。在需要維護的真實程式裡，這種明確性往往比精簡更值錢。

複雜度說明
時間O(n)掃一遍，每格最多看兩個字元
空間O(1)13 筆常數表
解法三

從右往左掃（面試常見的變體）

換個方向：從最右邊開始，記住「目前看過的最大值」。如果當前符號比它小，就是減法形式的前半，減掉；否則加。

class Solution: def romanToInt(self, s: str) -> int: VALUE = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000} total, prev = 0, 0 for ch in reversed(s): # 從右往左掃 v = VALUE[ch] # 比「右邊已經處理過的最大值」小 -> 減，否則加 total += -v if v < prev else v prev = max(prev, v) return total

為什麼要用 max 而不是直接記上一個？

考慮 "XIV"（14），從右往左： V (5): prev = 0，5 ≥ 0 -> +5, prev = 5 I (1): prev = 5，1 < 5 -> -1, prev = max(5, 1) = 5 ← 這裡是關鍵 X (10): prev = 5，10 ≥ 5 -> +10, prev = 10 總和 = 5 - 1 + 10 = 14 ✔ 如果 prev 只記「上一個」而不取 max： I 之後 prev 會變成 1， 然後 X (10) ≥ 1 -> +10，這次剛好也對。 但看 "MCMXCIV"： V(5) +5, prev=5 I(1) -1, prev=1 ← 沒取 max，prev 退化成 1 C(100) ≥ 1 -> +100, prev=100 X(10) < 100 -> -10, prev=10 ← 又退化 M(1000) ≥ 10 -> +1000, prev=1000 C(100) < 1000 -> -100, prev=100 M(1000) ≥ 100 -> +1000 總和 = 5-1+100-10+1000-100+1000 = 1994 ✔ 碰巧也對 實際上在「合法羅馬數字」的前提下兩種寫法都對， 因為減法形式的後半永遠比前半大。 但寫 max 的版本語意更穩（「右邊出現過的最大值」）， 也比較不需要依賴輸入的合法性 —— 建議保留。

這個方向的好處是：如果題目改成「串流輸入、從尾端逐字到達」，它可以邊收邊算。

複雜度說明
時間O(n)掃一遍
空間O(1)幾個變數

邊界條件檢查清單

  • 單一字元："I" → 1，"M" → 1000。
  • 全部是減法形式："MCMXCIV" → 1994。
  • 完全沒有減法形式："MMMDCCCLXXXVIII" → 3888（最長的輸入）。
  • 六個減法形式各測一次：IV=4、IX=9、XL=40、XC=90、CD=400、CM=900。
  • 減法形式在開頭："IX" → 9。第一個字元就要減。
  • 減法形式在結尾："XIV" → 14。倒數第二個字元要減。
  • 連續三個相同符號："III" → 3、"MMM" → 3000。

常見追問

追問一：如果不保證輸入合法，要怎麼驗證？

這比轉換難得多，要檢查的規則包括：

  • 同一符號不能連寫超過三次（"IIII" 非法）
  • V、L、D 不能重複出現（"VV" 非法）
  • 只有 I、X、C 能當減數，而且只能減它的 5 倍和 10 倍（"IL"、"IC" 非法）
  • 減法形式後面不能再接更大或等大的符號（"IXI"、"CMM" 非法）

最乾淨的做法是「轉回去比對」：先用本題的解法算出數字 n，再用第 12 題的解法把 n 轉回羅馬數字，看看是不是和輸入一模一樣。因為第 12 題產生的是唯一的標準寫法，所以「轉回來一樣」等價於「輸入是合法的標準寫法」。用一個已知正確的正向函式來驗證反向輸入 —— 這個技巧在很多解析題上都很好用。

追問二：為什麼羅馬數字不適合做算術？

因為它沒有位值（positional value）也沒有零。MCMXCIV + I 沒辦法像十進位那樣「個位加一、有需要再進位」，你得先理解整個字串代表什麼數。這正是十進位位值系統（以及零這個概念）在數學史上如此重要的原因 —— 它讓算術變成可以機械化的符號操作。

追問三：處理很長的輸入（假設可以超過 3999）時，哪個解法最好？

三個都是 O(n)、O(1)，沒有差別。但解法三（從右往左）在串流場景下最有優勢，因為它不需要往後看。
