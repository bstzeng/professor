Integer to Roman
整數轉羅馬數字

Medium · 中等 雜湊表 數學 字串

Problem

Seven different symbols represent Roman numerals with the following values: I=1, V=5, X=10, L=50, C=100, D=500, M=1000.

Roman numerals are formed by appending the conversions of decimal place values from highest to lowest. If the value starts with 4 or 9, use the subtractive form (IV, IX, XL, XC, CD, CM).

Given an integer, convert it to a Roman numeral.

中文翻譯

羅馬數字用七個符號表示：I=1, V=5, X=10, L=50, C=100, D=500, M=1000。

寫法是由高位到低位依序寫出每一個位數的表示。如果某一位是 4 或 9，要用減法形式（IV=4, IX=9, XL=40, XC=90, CD=400, CM=900）。

給你一個整數，把它轉成羅馬數字。

六個減法形式，就是這題的全部規則

基本符號： I = 1 V = 5 X = 10 L = 50 C = 100 D = 500 M = 1000 減法形式（只有這六個，沒有別的）： IV = 4 IX = 9 XL = 40 XC = 90 CD = 400 CM = 900 規律：只有 I、X、C 可以放在別人左邊做減法， 而且只能放在「它的 5 倍」和「它的 10 倍」左邊。 V、L、D、M 永遠不做減數。 所以 IL（49）、IC（99）、VX 都是「不合法」的寫法。 正確的 49 是 XLIX（40 + 9），99 是 XCIX（90 + 9）。

把這六個減法形式當成「額外的六個符號」，整個問題就退化成最單純的貪婪找零錢 —— 這是解法一的全部洞察。

範例

範例 1 輸入：num = 3749 輸出："MMMDCCXLIX" 說明：3000 = MMM 700 = DCC 40 = XL 9 = IX 範例 2 輸入：num = 58 輸出："LVIII" 說明：50 = L，8 = VIII 範例 3 輸入：num = 1994 輸出："MCMXCIV" 說明：1000 = M，900 = CM，90 = XC，4 = IV

限制條件

  • 1 ≤ num ≤ 3999

LeetCode 原題

先看懂限制在說什麼

  • 上限是 3999，因為標準羅馬數字最大的符號是 M（1000），而規則不允許連寫四個 M。4000 要寫成 M̄V（上加橫線表示 ×1000），這個延伸規則題目不考。
  • 下限是 1，羅馬數字沒有 0，也沒有負數。這讓所有邊界處理都省掉了。
  • 範圍固定又小，所以查表法（解法二）是完全合理的 —— 四張表加起來只有 34 個字串。

解題思路

兩種思路，都是 O(1)：

解法想法表格大小
一、貪婪找零由大到小，能減就減；把 6 個減法形式當成獨立符號13 筆
二、位數查表千百十個各查一張表，接起來就好34 筆
解法一

貪婪：把減法形式當成獨立符號

直覺上會擔心「貪婪會不會出錯」（像找零錢問題裡某些幣值組合會讓貪婪失效）。但羅馬數字的符號值刻意設計成 1, 4, 5, 9, 10, 40, 50, 90, … 這樣的序列，每一個都能被更小的組合精確補齊，貪婪保證最優。

class Solution: def intToRoman(self, num: int) -> str: # 由大到小，並且把 6 個「減法形式」當成獨立的符號插進去 VALUES = [ (1000, "M"), (900, "CM"), (500, "D"), (400, "CD"), (100, "C"), (90, "XC"), (50, "L"), (40, "XL"), (10, "X"), (9, "IX"), (5, "V"), (4, "IV"), (1, "I"), ] out = [] for value, symbol in VALUES: if num == 0: break count, num = divmod(num, value) out.append(symbol * count) return "".join(out)

追一遍 num = 1994

num = 1994 1000 "M" : divmod(1994, 1000) = (1, 994) -> "M" num = 994 900 "CM" : divmod(994, 900) = (1, 94) -> "CM" num = 94 500 "D" : divmod(94, 500) = (0, 94) -> "" num = 94 400 "CD" : (0, 94) -> "" 100 "C" : (0, 94) -> "" 90 "XC" : divmod(94, 90) = (1, 4) -> "XC" num = 4 50 "L" : (0, 4) -> "" 40 "XL" : (0, 4) -> "" 10 "X" : (0, 4) -> "" 9 "IX" : (0, 4) -> "" 5 "V" : (0, 4) -> "" 4 "IV" : divmod(4, 4) = (1, 0) -> "IV" num = 0 break 結果："M" + "CM" + "XC" + "IV" = "MCMXCIV" ✔

為什麼 VALUES 的順序絕對不能亂？

必須嚴格由大到小。特別是 900 "CM" 一定要排在 500 "D" 前面 —— 否則 900 會先被拆成 D(500) + CCCC(400)，得到 "DCCCC"，那不是合法的羅馬數字。

count 最多是 3。因為相鄰兩個符號值的比例最多是 4（例如 1000/900、100/90），而減法形式把 4 和 9 都攔截掉了，所以 symbol * count 最多重複三次 —— 剛好符合羅馬數字「同一符號不連寫四次」的規則。這不是巧合，是那個 VALUES 表刻意設計的結果。

複雜度說明
時間O(1)固定 13 次迴圈
空間O(1)輸出最多 15 個字元（3888 = MMMDCCCLXXXVIII）
解法二

位數查表（最快，也最好讀）

既然只有四個十進位位數，而每一位只有 0–9 十種可能，那就把 4 × 10 = 40 種情況全部列出來（實際只要 34 筆，千位只到 3）。

class Solution: def intToRoman(self, num: int) -> str: # 每一位數（千、百、十、個）的寫法直接查表，完全不用算 THOUSANDS = ["", "M", "MM", "MMM"] HUNDREDS = ["", "C", "CC", "CCC", "CD", "D", "DC", "DCC", "DCCC", "CM"] TENS = ["", "X", "XX", "XXX", "XL", "L", "LX", "LXX", "LXXX", "XC"] ONES = ["", "I", "II", "III", "IV", "V", "VI", "VII", "VIII", "IX"] return (THOUSANDS[num // 1000] + HUNDREDS[num % 1000 // 100] + TENS[num % 100 // 10] + ONES[num % 10])

四張表的規律

每一張表的結構都一樣，只是換符號： 位數 1 的符號 5 的符號 10 的符號 ---- -------- -------- --------- 個位 I V X 十位 X L C 百位 C D M 千位 M - - （沒有 5000、10000 的符號，所以只到 MMM） d = 0 : "" d = 1~3 : one * d (I, II, III) d = 4 : one + five (IV) d = 5 : five (V) d = 6~8 : five + one*(d-5) (VI, VII, VIII) d = 9 : one + ten (IX) 如果覺得手寫四張表很醜，也可以用上面這個規律在程式裡生出來 —— 但既然只有 34 筆，寫死反而更清楚、更不容易錯。

這是本題最快的解法：沒有迴圈，就四次除法取模加四次陣列索引。也最不容易寫錯 —— 因為所有規則都變成了資料，而資料可以一眼看完、一眼檢查。

這體現一個很實用的原則：能用資料表達的，就不要用控制流程表達。表格可以被檢查、被測試、被生成；散落在 if-else 裡的規則不行。

複雜度說明
時間O(1)四次查表
空間O(1)34 個常數字串

邊界條件檢查清單

  • 最小值 1 → "I"。
  • 最大值 3999 → "MMMCMXCIX"。
  • 每個減法形式都要單獨測：4 → IV，9 → IX，40 → XL，90 → XC，400 → CD，900 → CM。
  • 輸出最長的情況：3888 → "MMMDCCCLXXXVIII"（15 個字元）。
  • 某些位數是 0：1000 → "M"，2020 → "MMXX"。查表法自動回空字串。
  • 49 和 99："XLIX" 和 "XCIX"，不是 "IL" 和 "IC"。最能驗證你有沒有搞錯減法規則。

常見追問

追問一：如果要支援大於 3999 呢？

標準做法是用上劃線（vinculum）表示乘以 1000：V̄ = 5000、X̄ = 10000。程式上就是在 VALUES 表前面補上這些符號。但這已經不是「標準羅馬數字」的範圍，實作前要先跟出題者確認規格。

追問二：貪婪為什麼在這裡一定對？找零錢問題不是常常會失敗嗎？

找零錢的貪婪確實會失敗 —— 經典反例是幣值 {1, 3, 4} 湊 6：貪婪拿 4+1+1 三枚，最優是 3+3 兩枚。羅馬數字之所以安全，是因為它的值序列 1,4,5,9,10,40,50,90,100,400,500,900,1000 具有一個特殊性質：每個值都整除或被下一個大值「幾乎整除」，而餘數永遠能被更小的符號在 3 個以內補完。能講出這個差別，比只說「貪婪就是對的」有說服力得多。

追問三：反過來，羅馬數字轉整數呢？

就是下一題（第 13 題）。核心技巧是：由左往右掃，如果當前符號比右邊的小就減、否則就加。反向轉換反而比正向簡單，因為不用煩惱「該用哪種寫法」。
