LeetCode 11

Container With Most Water
盛最多水的容器

Medium · 中等 陣列 雙指標 貪心

Problem

You are given an integer array height of length n. There are n vertical lines drawn such that the two endpoints of the i-th line are (i, 0) and (i, height[i]).

Find two lines that together with the x-axis form a container, such that the container contains the most water. Return the maximum amount of water a container can store.

Notice that you may not slant the container.

中文翻譯

給你一個長度為 n 的整數陣列 height。第 i 根垂直線的兩端點是 (i, 0) 和 (i, height[i])。

找出兩根線，讓它們和 x 軸圍成的容器能裝最多的水，回傳這個最大容量。

注意：容器不能傾斜。

面積公式與一個關鍵觀察

選第 i 根和第 j 根（i < j）： 面積 = 寬 × 高 = (j - i) × min(height[i], height[j]) 「高」取 min 是因為水會從比較矮的那一邊溢出來。 關鍵觀察：中間的柱子完全不影響答案。 容器就是兩片牆加底部，中間有什麼都無所謂。 （這點和第 42 題「接雨水」剛好相反 —— 那題中間的柱子會佔掉體積。）

範例

範例 1 輸入：height = [1, 8, 6, 2, 5, 4, 8, 3, 7] 輸出：49 說明：選索引 1（高 8）和索引 8（高 7）， 面積 = (8 - 1) × min(8, 7) = 7 × 7 = 49。 範例 2 輸入：height = [1, 1] 輸出：1 說明：唯一的選擇，面積 = 1 × 1 = 1。

限制條件

  • n == height.length
  • 2 ≤ n ≤ 10⁵
  • 0 ≤ height[i] ≤ 10⁴

LeetCode 原題

先看懂限制在說什麼

  • n 可以到 10⁵。O(n²) 是 10¹⁰ —— 絕對 TLE。這個數字就是在告訴你：必須找到 O(n) 或 O(n log n) 的解。
  • height[i] 可以是 0。高度 0 的柱子當牆時面積是 0，不會是答案，但也不會讓程式出錯 —— 不用特別處理。
  • n 至少是 2，所以一定存在至少一組答案，不必處理「找不到」。

解題思路

暴力法要試 C(n,2) ≈ n²/2 組。要降到 O(n)，得找到一個理由，能讓我們一口氣排除掉大量組合而不用一一驗算 —— 這就是雙指標的價值。

解法一

暴力列舉所有配對

class Solution: def maxArea(self, height: List[int]) -> int: best = 0 for i in range(len(height)): for j in range(i + 1, len(height)): best = max(best, (j - i) * min(height[i], height[j])) return best

正確但 O(n²)，在 n = 10⁵ 時穩定 TLE。還是值得寫出來 —— 它是驗證雙指標的標準答案（本篇的壓力測試就是拿它當基準）。

複雜度說明
時間O(n²)所有 C(n,2) 對
空間O(1)只有一個 best
解法二

雙指標從兩端夾（關鍵在證明）

從最寬的一組開始：lo = 0、hi = n-1。然後每一步丟掉比較矮的那一根，往中間收縮。

為什麼可以放心丟掉矮的那一根？（這是整題唯一需要證明的地方）

假設現在 height[lo] < height[hi]，也就是 lo 這根比較矮。 考慮所有「還包含 lo 這根」的組合：(lo, k)，其中 lo < k < hi。 寬度：k - lo < hi - lo （k 在 hi 左邊，一定更窄） 高度：min(height[lo], height[k]) ≤ height[lo] = min(height[lo], height[hi]) （因為 height[lo] 本來就是兩者中較小的， 不管 height[k] 多高，min 都不會超過 height[lo]） 所以：面積(lo, k) < 面積(lo, hi) 嚴格更小 結論：(lo, hi) 已經是「所有包含 lo 的組合」裡最好的那個。 既然它已經被記錄下來了，lo 就再也沒有用處 —— 安全丟棄。 同理，如果 hi 比較矮，就丟 hi。 每一步丟掉一根柱子，n 根柱子最多丟 n 次 -> O(n)。
class Solution: def maxArea(self, height: List[int]) -> int: lo, hi = 0, len(height) - 1 best = 0 while lo < hi: h = min(height[lo], height[hi]) best = max(best, (hi - lo) * h) # 移動「比較矮」的那一邊。矮的那邊是瓶頸， # 留著它只會讓寬度變小而高度不變 -> 不可能更好 if height[lo] < height[hi]: lo += 1 else: hi -= 1 return best

兩根一樣高的時候丟哪一根？

都可以。上面的程式碼寫 if height[lo] < height[hi]，相等時走 else 丟 hi。證明同樣成立（相等時兩邊的論證對稱），所以不會漏掉答案。

常見的錯誤直覺

錯誤想法：「應該移動比較高的那一邊，才能找到更高的牆」 反例： height = [2, 3, 10, 5, 7, 8, 9] lo = 0 (高 2)，hi = 6 (高 9)，面積 = 6 × 2 = 12 若移動比較高的 hi：hi = 5 (高 8)，面積 = 5 × 2 = 10 變小了 而且 lo 這根高度 2 還在，它永遠是瓶頸， 不管右邊怎麼換，高度都被鎖死在 2，寬度卻一直縮 -> 只會越來越差。 正確的做法是丟掉瓶頸（矮的那根），才有機會讓高度上升。
複雜度說明
時間O(n)兩個指標合計走 n 步
空間O(1)只用幾個變數
解法三

雙指標 + 跳過無用柱子（同複雜度的常數優化）

在移動指標時，可以一口氣跳過所有「不比目前水位高」的柱子 —— 它們當瓶頸時高度不會更好，寬度又更小，一定不是答案。

class Solution: def maxArea(self, height: List[int]) -> int: lo, hi = 0, len(height) - 1 best = 0 while lo < hi: h = min(height[lo], height[hi]) best = max(best, (hi - lo) * h) # 小優化：一路跳過所有不比 h 高的柱子 # （它們當瓶頸時高度不會變好，寬度又更小） if height[lo] < height[hi]: while lo < hi and height[lo] <= h: lo += 1 else: while lo < hi and height[hi] <= h: hi -= 1 return best

最壞情況（遞增序列）還是 O(n)，但在高度分布隨機時實測能少跑不少輪。複雜度沒變，只是常數更小。

面試時提一句就好，不必為了它把主解法寫複雜。

複雜度說明
時間O(n)最壞仍是 n 步，平均更少
空間O(1)只用幾個變數

解法對照

解法時間空間n = 10⁵ 能過？備註
一、暴力O(n²)O(1)✘當測試基準
二、雙指標O(n)O(1)✔標準解，重點是講清楚證明
三、雙指標 + 跳過O(n)O(1)✔常數優化，加分項

邊界條件檢查清單

  • 只有兩根：[1,1] → 1。while 迴圈只跑一輪。
  • 全部一樣高：[5,5,5,5] → 15（最寬的那組）。相等時的分支要能正確前進，否則死循環。
  • 遞增序列：[1,2,3,4,5] → 6（索引 1 與 4）。答案不在最寬的那組。
  • 遞減序列：[5,4,3,2,1] → 6。對稱的情況。
  • 含 0：[0,2,0] → 0。高度 0 不會讓程式出錯。
  • 最高的兩根不是答案：[2,100,3,4,5,100,2] 的答案確實是那兩根 100；但 [100,1,1,1,1,99] 的答案是 5 × 99 = 495，不是「相鄰的兩根最高」。寬度和高度要一起看。

常見追問

追問一：這題和第 42 題「接雨水」差在哪？

第 11 題（本題） 第 42 題 Trapping Rain Water ------------------------ ------------------------ 只選「兩根」當牆 每一格都要算能積多少水 中間的柱子被忽略 中間的柱子會佔掉體積 答案是一個矩形面積 答案是所有格子的總和 雙指標從兩端夾 雙指標 / 單調堆疊 / 前後綴最大值 雖然都用雙指標、都在柱狀圖上，但問的東西完全不同。 第 11 題「水會漫過中間的柱子」，第 42 題不會。 這兩題常被放在一起考，建議連著練。

追問二：如果容器可以由三片牆組成呢？

問題會變得複雜很多，雙指標的證明不再成立（丟掉一根柱子可能同時破壞好幾組候選）。通常要退回 DP 或分治。雙指標之所以能用，完全依賴「答案只由兩個端點決定」這個結構。

追問三：如果要回傳那兩根柱子的索引，而不只是面積？

在更新 best 的時候一併記下 (lo, hi) 即可，複雜度不變。唯一要注意的是：答案可能不唯一，要先問清楚「任一組」還是「字典序最小的那組」。
