LeetCode 35

Search Insert Position
搜尋插入位置

Easy · 簡單 陣列 二分搜尋

Problem

Given a sorted array of distinct integers and a target value, return the index if the target is found. If not, return the index where it would be if it were inserted in order.

You must write an algorithm with O(log n) runtime complexity.

中文翻譯

給你一個元素互不相同的升序陣列和一個目標值 target。如果 target 存在就回傳它的索引；不存在的話，回傳它應該被插入的位置（插入後陣列仍然有序）。

演算法必須是 O(log n)。

這題就是 lower_bound，沒別的

「第一個 >= target 的位置」同時回答了兩件事： target 存在 -> 那個位置就是 target 的索引 target 不存在 -> 那個位置就是該插進去的地方 nums = [1, 3, 5, 6] target=5 -> 第一個 >= 5 的是索引 2 -> 回 2（存在） target=2 -> 第一個 >= 2 的是索引 1 -> 回 1（插在 1 和 3 之間） target=7 -> 沒有 >= 7 的 -> 回 4（插在最後） target=0 -> 第一個 >= 0 的是索引 0 -> 回 0（插在最前） 所以答案的範圍是 [0, n]，一共 n+1 種可能。 這就是為什麼 hi 要初始化成 n 而不是 n-1。

這題是整個二分搜尋家族的入口。把 lower_bound 的骨架在這裡寫熟，第 34、69、74、278、875、1011 題都會受益。

範例

範例 1 輸入：nums = [1,3,5,6], target = 5 輸出：2 範例 2 輸入：nums = [1,3,5,6], target = 2 輸出：1 範例 3 輸入：nums = [1,3,5,6], target = 7 輸出：4

限制條件

  • 1 ≤ nums.length ≤ 10⁴
  • −10⁴ ≤ nums[i] ≤ 10⁴
  • nums 是嚴格遞增的（沒有重複值）
  • −10⁴ ≤ target ≤ 10⁴

LeetCode 原題

先看懂限制在說什麼

  • 沒有重複值，所以 lower_bound 和 upper_bound 的差別在這題看不出來。（有重複值時就是第 34 題。）
  • 要求 O(log n) —— 排除線性掃描（雖然 n = 10⁴ 線性也會過，但這題的重點就是二分）。
  • 答案可能是 n（插在最後面）。這是最常被漏掉的邊界。

解題思路

兩種骨架都能寫，但它們的「結束狀態」意義不同，值得一起看清楚。

解法一

lower_bound 骨架（推薦）

class Solution: def searchInsert(self, nums: List[int], target: int) -> int: lo, hi = 0, len(nums) # hi = len，答案範圍是 [0, n] while lo < hi: mid = (lo + hi) // 2 if nums[mid] < target: lo = mid + 1 # mid 確定不是答案 else: hi = mid # mid 可能就是答案，不能排除 return lo # lo == hi，就是答案

三個要點（和第 34 題一模一樣）

1. hi = len(nums) 答案範圍是 [0, n]，n 表示「插在最後」 2. while lo < hi 收斂到一點，不是「找到就 return」 3. hi = mid mid 可能是答案，不能寫 mid - 1 為什麼不會死循環？ mid = (lo + hi) // 2 向下取整，所以當 lo < hi 時一定有 mid < hi。 因此 hi = mid 一定讓 hi 嚴格變小。 而 lo = mid + 1 一定讓 lo 嚴格變大。 區間每輪都真的縮小 -> 保證終止。 不變量（loop invariant）： 答案永遠落在 [lo, hi] 裡面。 - nums[mid] < target -> mid 及其左邊都不可能是答案 -> lo = mid + 1 ✔ - nums[mid] >= target -> mid 可能是答案，右邊都不可能更好 -> hi = mid ✔ 結束時 lo == hi，區間只剩一點，那就是答案。

追一遍 nums = [1,3,5,6], target = 2：

lo=0, hi=4 mid=2: nums[2]=5 >= 2 -> hi=2 lo=0, hi=2 mid=1: nums[1]=3 >= 2 -> hi=1 lo=0, hi=1 mid=0: nums[0]=1 < 2 -> lo=1 lo=1, hi=1 -> 結束，回傳 1 ✔
複雜度說明
時間O(log n)每輪砍一半
空間O(1)只用兩個下標
解法二

經典骨架（找到就 return）

如果你比較習慣「while lo <= hi、找到就 return」的寫法，這題也能用 —— 關鍵是知道迴圈結束時 lo 是什麼。

class Solution: def searchInsert(self, nums: List[int], target: int) -> int: lo, hi = 0, len(nums) - 1 while lo <= hi: mid = (lo + hi) // 2 if nums[mid] == target: return mid if nums[mid] < target: lo = mid + 1 else: hi = mid - 1 # 迴圈結束時 lo == hi + 1，而 lo 剛好就是插入位置 return lo

為什麼結束時 lo 就是插入位置？

迴圈結束的條件是 lo > hi，而且一定是 lo == hi + 1。 此時的不變量： 所有 index < lo 的元素都 < target 所有 index > hi 的元素都 > target （而 lo == hi + 1，所以這兩個範圍剛好覆蓋全部） 所以 lo 就是「第一個 >= target 的位置」= 插入位置。 追一遍 nums = [1,3,5,6], target = 2： lo=0, hi=3, mid=1: nums[1]=3 > 2 -> hi=0 lo=0, hi=0, mid=0: nums[0]=1 < 2 -> lo=1 lo=1 > hi=0 -> 結束，回傳 lo=1 ✔ 追一遍 target = 7： lo=0, hi=3, mid=1: 3 < 7 -> lo=2 lo=2, hi=3, mid=2: 5 < 7 -> lo=3 lo=3, hi=3, mid=3: 6 < 7 -> lo=4 lo=4 > hi=3 -> 回傳 4 ✔

「結束時 lo 是插入位置」這個性質很有用，很多人寫二分只記得「找到就 return」，卻不知道找不到時 lo 和 hi 落在哪裡。這題剛好逼你搞清楚。

兩種骨架的取捨：解法一比較短、意圖更明確（「我要找邊界」）；解法二在「剛好命中」時可以提早 return（常數上稍快）。實務上建議只記一種並記熟 —— 混用是所有二分 bug 的來源。

複雜度說明
時間O(log n)每輪砍一半
空間O(1)只用兩個下標

解法對照

骨架迴圈條件結束狀態適合的問題
lower_boundlo < hilo == hi，就是答案找邊界、找插入點
經典lo <= hilo == hi + 1找特定元素

邊界條件檢查清單

  • target 比全部都大：([1,3,5,6], 7) → 4。hi 寫成 len-1 會回傳 3，錯。
  • target 比全部都小：([1,3,5,6], 0) → 0。
  • 剛好命中：([1,3,5,6], 5) → 2。
  • 插在中間：([1,3,5,6], 2) → 1。
  • 單一元素：([1], 1) → 0；([1], 0) → 0；([1], 2) → 1。
  • 空陣列：([], 1) → 0。題目保證不會，但 lower_bound 自然就對。

常見追問

追問一：如果有重複值呢？

lower_bound 會回傳「第一個等於 target 的位置」，也就是插在所有相同元素的最左邊。如果要插在最右邊，就用 upper_bound（把 < 改成 <=）。一個字元的差別。

追問二：這個骨架還能用在哪？

只要能定義一個單調的述詞 P(i)（i 小的時候是 False，超過某一點之後一直是 True），就能用同一個骨架找那個交界點：

本題： P(i) = nums[i] >= target 第 278 題： P(v) = isBadVersion(v) 第 875 題： P(speed) = 「這個速度吃得完嗎」 第 1011 題： P(cap) = 「這個載重量運得完嗎」 第 410 題： P(x) = 「最大子陣列和 <= x 時分得出 k 段嗎」 這叫「二分答案」：不是在陣列上二分，而是在「答案的值域」上二分。 一旦認出這個模式，一大票看起來很難的最佳化問題都會變成 「寫一個 check 函式 + 套這個骨架」。

追問三：mid = (lo + hi) // 2 有什麼隱患？

在 Python 裡沒有。但在 C/Java 裡，lo + hi 可能溢位（兩個都接近 INT_MAX 時）。這是 Java 的 Arrays.binarySearch 存在了九年的著名 bug（2006 年由 Joshua Bloch 公開）。安全的寫法是 mid = lo + (hi - lo) // 2。這是二分搜尋最有名的歷史教訓，面試時提到會加分。
