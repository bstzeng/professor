LeetCode 55

Jump Game
跳躍遊戲

Medium · 中等 陣列 貪心 動態規劃

Problem

You are given an integer array nums. You are initially positioned at the array's first index, and each element in the array represents your maximum jump length at that position.

Return true if you can reach the last index, or false otherwise.

中文翻譯

給你一個整數陣列 nums，你一開始站在第一個位置。nums[i] 表示從位置 i 最多能往前跳幾格。

判斷你能不能到達最後一個位置，能就回傳 true，不能就 false。

一個變數就夠了：farthest

核心洞察： 我們不需要知道「怎麼跳」，只需要知道「最遠能到哪」。 因為從位置 i 可以跳 1..nums[i] 格（不是只能跳 nums[i] 格）， 所以「能到達的位置」永遠是一段【連續的】前綴 [0, farthest]。 既然是連續的，只要記住右端點 farthest 就夠了。 演算法： 從左往右掃，沿途更新 farthest = max(farthest, i + nums[i])。 如果走到某個 i 時發現 i > farthest，表示這一格根本到不了 -> False。 nums = [3, 2, 1, 0, 4] i=0: 0 <= 0 ✔ farthest = max(0, 0+3) = 3 i=1: 1 <= 3 ✔ farthest = max(3, 1+2) = 3 i=2: 2 <= 3 ✔ farthest = max(3, 2+1) = 3 i=3: 3 <= 3 ✔ farthest = max(3, 3+0) = 3 i=4: 4 > 3 ✘ 到不了 -> False ✔ 卡在索引 3 的那個 0 上。

「可達集合是連續前綴」是這題能用單一變數解決的根本原因。如果可以往回跳（第 1306 題），這個性質就不成立了，必須寫真正的 BFS/DFS。

範例

範例 1 輸入：nums = [2,3,1,1,4] 輸出：true 說明：0 → 1 → 4，或 0 → 2 → 3 → 4。 範例 2 輸入：nums = [3,2,1,0,4] 輸出：false 說明：不管怎麼跳都會停在索引 3（值是 0），跳不出去。

限制條件

  • 1 ≤ nums.length ≤ 10⁴
  • 0 ≤ nums[i] ≤ 10⁵

LeetCode 原題

先看懂限制在說什麼

  • n 到 10⁴。O(n²) 的 DP 是 10⁸ —— 在 Python 裡會 TLE。要 O(n)。
  • nums[i] 可以是 0 —— 這就是唯一會「卡住」的原因。如果全部 ≥ 1，答案永遠是 true。
  • n 可以是 1：起點就是終點，答案 true（即使 nums = [0]）。這是最常被漏掉的邊界。
  • nums[i] 可以到 10⁵，遠大於陣列長度。i + nums[i] 可能超出陣列 —— 不影響正確性，但要記得它代表「已經能到終點」。

解題思路

三種解法，其實是同一個結構的三種視角：正著推、倒著推、或建整張可達表。

解法一

從左往右貪婪（最推薦）

class Solution: def canJump(self, nums: List[int]) -> bool: farthest = 0 # 目前能到達的最遠位置 for i, v in enumerate(nums): if i > farthest: # 連這一格都走不到 -> 卡住了 return False farthest = max(farthest, i + v) if farthest >= len(nums) - 1: return True # 已經能到終點，提早結束 return True

為什麼「發現 i > farthest 就 False」是對的？

farthest 是「從 [0, i-1] 這些格子出發，最遠能跳到哪」。 如果 i > farthest，表示沒有任何一個「到得了的格子」能跳到 i。 而 i 之後的格子都在 i 右邊，更到不了。 所以直接 False。 反過來，如果掃完整個陣列都沒觸發這個條件， 表示每一格都到得了 —— 包含最後一格 -> True。 （其實不用掃完：farthest >= n-1 就可以提早回 True。）

為什麼這是「貪婪」而不需要回溯？

因為我們不需要決定「在哪一格要跳多遠」。從位置 i 出發能到的範圍是 [i+1, i+nums[i]]，而「可達集合」是所有這些範圍的聯集 —— 而聯集永遠是一段連續前綴（因為它們都從 i+1 開始，而 i 本身可達）。所以只要追蹤右端點，不會漏掉任何可能。

和第 45 題（Jump Game II）的關係：那題問「最少幾步」，用的是同一個 farthest，只是多了一個 cur_end 來分層。兩題一起看，會發現它們是同一個掃描的兩種輸出。

複雜度說明
時間O(n)掃一遍，可提早結束
空間O(1)一個變數
解法二

從右往左倒推（另一個漂亮的視角）

換個方向：維護一個「目標」，從終點開始往左走。如果某一格能跳到目標，那它就成為新的目標。

class Solution: def canJump(self, nums: List[int]) -> bool: # 從終點往回推：維護「目前必須到得了的目標」 target = len(nums) - 1 for i in range(len(nums) - 2, -1, -1): if i + nums[i] >= target: target = i # 只要到得了 i，就到得了原本的 target return target == 0
nums = [2, 3, 1, 1, 4]，target 初值 = 4 i=3: 3 + 1 = 4 >= 4 ✔ target = 3 i=2: 2 + 1 = 3 >= 3 ✔ target = 2 i=1: 1 + 3 = 4 >= 2 ✔ target = 1 i=0: 0 + 2 = 2 >= 1 ✔ target = 0 target == 0 -> True ✔ nums = [3, 2, 1, 0, 4]，target = 4 i=3: 3 + 0 = 3 >= 4 ✘ target 不變（還是 4） i=2: 2 + 1 = 3 >= 4 ✘ target = 4 i=1: 1 + 2 = 3 >= 4 ✘ target = 4 i=0: 0 + 3 = 3 >= 4 ✘ target = 4 target == 4 != 0 -> False ✔

語意很漂亮：「要到終點，就必須先到 target；而要到 target，就必須先到新的 target…」—— 一路把需求往前推。最後如果需求推到了索引 0，表示從起點出發就能一路達成。

和解法一等價，但有時候更好想 —— 尤其當題目變成「從終點反推最少步數」或「必經的關鍵點」時。

複雜度說明
時間O(n)掃一遍
空間O(1)一個變數
解法三

可達表 DP（會 TLE 的基準線）

class Solution: def canJump(self, nums: List[int]) -> bool: n = len(nums) reach = [False] * n # reach[i] = 能不能到達位置 i reach[0] = True for i in range(n): if not reach[i]: continue for j in range(i + 1, min(i + nums[i], n - 1) + 1): reach[j] = True return reach[n - 1]

直接建一張「每一格能不能到」的表。正確，但 O(n²) —— 最壞情況（每個 nums[i] 都很大）內層迴圈要跑 O(n) 次。

它的價值是最直白，可以拿來驗證貪婪解（本篇的壓力測試就是拿它當基準）。而且它清楚地展示了「可達集合」這個概念 —— 貪婪法只是發現了「這張表永遠是 True...True False...False 的形狀」，所以只要記住分界點就夠了。

複雜度說明
時間O(n²)每格往後標記 O(n) 個
空間O(n)reach 陣列

解法對照

解法時間空間方向備註
一、貪婪 farthestO(n)O(1)左 → 右面試預設
二、倒推 targetO(n)O(1)右 → 左語意漂亮
三、可達表O(n²)O(n)左 → 右基準線，會 TLE

邊界條件檢查清單

  • 單一元素：[0] → true（起點就是終點）。最常被漏掉的邊界。
  • 第一格就是 0：[0, 1] → false。
  • 剛好卡住：[3,2,1,0,4] → false。
  • 剛好跳過去：[2,0,0] → true（從 0 直接跳到 2）。
  • 中間有 0 但跳得過：[2,5,0,0] → true。
  • 剛好每步走一格：[1,1,1,1] → true。
  • 最後一格是 0：[1,0] → true（到了就不用再跳）。

常見追問

追問一：如果要問「最少幾步」呢？

第 45 題（Jump Game II）。同一個 farthest，再加一個 cur_end 來記「這一層的邊界」。走到邊界就步數 +1。

追問二：如果可以往回跳呢？

第 1306 題（Jump Game III）：從 i 可以跳到 i + nums[i] 或 i - nums[i]，問能不能到達某個值為 0 的位置。「可達集合是連續前綴」的性質完全失效，必須寫真正的 BFS 或 DFS（O(n) 時間、O(n) 空間）。

這是一個很好的對照：多了「往回跳」這一個看似小的改動，就把一個 O(1) 空間的貪婪題，變成了一個需要顯式圖搜尋的題目。

追問三：如果每一格有不同的「成本」呢？

那就是加權最短路徑，要用 Dijkstra（O(n log n)）或 DP。貪婪之所以能用，完全依賴「每一步的代價相同」。

追問四：如果要回傳「卡在哪一格」呢？

貪婪版在 return False 之前，farthest 就是「最遠能到的位置」，而那一格必然是 nums[farthest] == 0（否則還能再往前）。一行就能加上。
