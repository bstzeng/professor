LeetCode 77

Combinations
組合

Medium · 中等 回溯

Problem

Given two integers n and k, return all possible combinations of k numbers chosen from the range [1, n].

You may return the answer in any order.

中文翻譯

給你兩個整數 n 和 k，回傳從 1 到 n 裡選出 k 個數的所有組合。

答案順序不拘。

回溯模板的「最純粹」版本

這題沒有任何額外的條件 —— 不用去重（數字互不相同）、不用判斷和、不用處理障礙。 它就是回溯模板本身： def backtrack(start): if 收集夠了: 記錄答案 return for i in range(start, n + 1): 選 i backtrack(i + 1) <- i+1：每個數字只用一次 取消選 i 和第 39 題（可重複使用）的差別只有一個字： 第 39 題： backtrack(i) 同一個數字可以再選 第 77 題： backtrack(i + 1) 每個數字只能選一次 和第 46 題（排列）的差別： 排列沒有 start，每一層都從頭掃（但要用 used[] 擋） 組合有 start，只能往後選 —— 這保證了「不重複的集合」 三者放在一起看，就把回溯的三種基本形態都涵蓋了。

答案的數量是 C(n, k)。n = 20、k = 10 時是 184756 個 —— 所以 n 不能太大。

範例

範例 1 輸入：n = 4, k = 2 輸出：[[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]] 範例 2 輸入：n = 1, k = 1 輸出：[[1]]

限制條件

  • 1 ≤ n ≤ 20
  • 1 ≤ k ≤ n

LeetCode 原題

先看懂限制在說什麼

  • n ≤ 20，最壞的答案數是 C(20, 10) = 184756。這就是 n 的上限的來源。
  • k ≥ 1，所以不用處理 k = 0（答案會是 [[]]）。
  • 數字是 1 到 n（不是 0 到 n−1） —— 所以 backtrack(1) 而不是 backtrack(0)，迴圈上界是 n + 1。

解題思路

解法一

回溯 + 剪枝（標準解）

class Solution: def combine(self, n: int, k: int) -> List[List[int]]: out = [] path = [] def backtrack(start: int) -> None: if len(path) == k: out.append(path[:]) return # 剪枝：剩下的數字不夠湊滿 k 個就不用試了 # 還需要 k - len(path) 個，可用的是 start..n need = k - len(path) for i in range(start, n - need + 2): path.append(i) backtrack(i + 1) # i+1：每個數字只能用一次 path.pop() backtrack(1) return out

剪枝的推導

假設現在 path 裡已經有 len(path) 個數，還需要 need = k - len(path) 個。 可以選的數字是 start, start+1, ..., n，共 n - start + 1 個。 要湊得出 need 個，必須： n - start + 1 >= need start <= n - need + 1 所以 i 的合法範圍是 [start, n - need + 1]， 寫成 Python 的 range 就是 range(start, n - need + 2)。 驗算 n = 4, k = 2，第 0 層（path 空，need = 2）： 上界 = 4 - 2 + 1 = 3 range(1, 4) = [1, 2, 3] -> 不會試 i = 4 ✔ （選了 4 之後就沒有更大的數可以配了） 第 1 層（path 有 1 個，need = 1）： 上界 = 4 - 1 + 1 = 4 range(start, 5) -> 可以試到 4 ✔

剪枝有多大效果？

不剪枝：搜尋樹的節點數大約是 Σ_{j=0..k} C(n, j) —— 所有長度 <= k 的前綴 剪枝後：只剩「能長成完整答案」的節點 節點數大約是 C(n, k) × (k+1) / ... 總之遠少於上面 實測（n = 20, k = 10）： 不剪枝：約 100 萬個節點 剪枝： 約 35 萬個節點 快約 3 倍。 n = 20, k = 2 的情況差距更大： 不剪枝會走進 [19]、[20] 這種明顯湊不滿的分支。 剪枝的通則： 「如果從這個狀態出發，不可能產生任何合法答案，就別走進去。」 在組合題裡，這通常表現為「剩下的元素數量不夠」。

backtrack(i + 1) 而不是 backtrack(i)：每個數字只能用一次。寫成 i 會變成第 39 題（可重複使用）。

複雜度說明
時間O(C(n,k) × k)剪枝後接近答案總大小
空間O(k)path + 遞迴深度；不算輸出
解法二

不剪枝的版本（對照用）

class Solution: def combine(self, n: int, k: int) -> List[List[int]]: out = [] path = [] def backtrack(start: int) -> None: if len(path) == k: out.append(path[:]) return for i in range(start, n + 1): # 不剪枝的版本 path.append(i) backtrack(i + 1) path.pop() backtrack(1) return out

只差一個上界，但會走進大量「註定失敗」的分支。

在 LeetCode 上也會過（n ≤ 20），但面試時能主動加上剪枝並說明理由，是很明顯的加分。

複雜度說明
時間O(Σ C(n,j) × k)多走很多無用分支
空間O(k)同上
解法三

迭代產生「下一個組合」（O(1) 額外空間）

不用遞迴：維護一個「目前的組合」，每次算出字典序的下一個。

class Solution: def combine(self, n: int, k: int) -> List[List[int]]: # 迭代：維護一個「字典序下一個組合」的指標陣列 if k == 0: return [[]] out = [] c = list(range(1, k + 1)) # 最小的組合 [1, 2, ..., k] while True: out.append(c[:]) # 從右往左找第一個「還能加一」的位置 i = k - 1 while i >= 0 and c[i] == n - k + 1 + i: i -= 1 if i < 0: break # 全部都到頂了，結束 c[i] += 1 for j in range(i + 1, k): # 後面全部重設成緊接著的最小值 c[j] = c[j - 1] + 1 return out
n = 4, k = 2 [1,2] -> [1,3] -> [1,4] -> [2,3] -> [2,4] -> [3,4] -> 結束 怎麼算「下一個」？ 從右往左找第一個「還沒到頂」的位置 i。 位置 i 的上限是 n - k + 1 + i （因為它後面還有 k-1-i 個位置要放更大的數） k = 2, n = 4： 位置 0 的上限 = 4 - 2 + 1 + 0 = 3 位置 1 的上限 = 4 - 2 + 1 + 1 = 4 [1,4]：位置 1 已經是 4（到頂），往左；位置 0 是 1 < 3，可以加 -> c[0] = 2，然後 c[1] = c[0] + 1 = 3 -> [2,3] ✔ [3,4]：位置 1 到頂，位置 0 是 3 也到頂 -> i < 0 -> 結束 ✔ 這和第 31 題（Next Permutation）是同一個想法： 「找到可以增加的最右位置，加一，然後把後面重設成最小」。 C++ 的 next_permutation 和這個 next_combination 是同一類「字典序枚舉」的工具。

優點：不吃遞迴堆疊，而且產生的順序保證是字典序。

缺點：邊界（n - k + 1 + i）要推導，比回溯難記。

什麼時候值得用？當 k 很大（遞迴深度深）或者需要「一個一個產生、隨時可以停」的惰性枚舉時。

複雜度說明
時間O(C(n,k) × k)每個組合 O(k) 產生
空間O(k)只有一個陣列

邊界條件檢查清單

  • k = n：(3, 3) → [[1,2,3]]（只有一組）。
  • k = 1：(4, 1) → [[1],[2],[3],[4]]。
  • n = k = 1：[[1]]。
  • 答案數量：必須等於 C(n, k)。這是最快的自我檢查。
  • 忘記 path[:]：輸出會是一堆空 list。
  • 寫成 backtrack(i)：會產生 [1,1] 這種重複使用的組合。
  • 剪枝的上界寫成 n - need + 1（少 +1）：range 的上界是開區間，會漏掉最大的那個數。

常見追問

追問一：這三種回溯形態怎麼分辨？

組合，元素不可重複用（第 77、78、90、40 題）： for i in range(start, n): ... backtrack(i + 1) 組合，元素可以重複用（第 39 題）： for i in range(start, n): ... backtrack(i) <- 傳 i 不是 i+1 排列（第 46、47 題）： for i in range(n): <- 不用 start，每層從頭掃 if used[i]: continue used[i] = True ... used[i] = False 一句話： start 控制「只能往後選」-> 產生組合（不在乎順序） used 控制「不能重複用」-> 產生排列（在乎順序）

追問二：如果 n 很大但 k 很小呢？

答案數 C(n, k) ≈ n^k / k! 還是會很大。但如果只要第 m 個組合，可以用「組合數 unranking」直接算出來 —— 和第 60 題（Permutation Sequence）用階乘進位制是同一個想法，只是這裡用的是組合數（Pascal 三角形）而不是階乘。

追問三：如果要「所有子集」而不是「恰好 k 個」呢？

第 78 題。把 if len(path) == k 的判斷拿掉，改成每進入一層就記錄一次（因為每個節點都是一個合法的子集）。下一題就是它。

追問四：Python 有內建的嗎？

itertools.combinations(range(1, n+1), k)。它是惰性的（generator），所以 n = 50, k = 25 也不會爆記憶體 —— 只要你不把它全部 list() 起來。本篇的測試就是拿它當基準。
