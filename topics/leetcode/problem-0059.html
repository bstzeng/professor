LeetCode 59

Spiral Matrix II
螺旋矩陣 II

Medium · 中等 陣列 矩陣 模擬

Problem

Given a positive integer n, generate an n x n matrix filled with elements from 1 to n² in spiral order.

中文翻譯

給你一個正整數 n，產生一個 n × n 的矩陣，把 1 到 n² 依螺旋順序（順時針由外往內）填進去。

和第 54 題是同一題，只是反過來

第 54 題：給你矩陣，依螺旋順序「讀」出來 第 59 題：給你 n，依螺旋順序「寫」進去 邊界邏輯一模一樣： top / bottom / left / right 四個邊界 往右 -> 往下 -> 往左 -> 往上，每走完一條邊就往內收 唯一的差別： 第 54 題： out.append(matrix[top][c]) 第 59 題： matrix[top][c] = v; v += 1 所以如果第 54 題寫熟了，這題就是把一行換掉。 一個額外的好處： 本題保證是「正方形」，而且「一定填滿」， 所以不會出現第 54 題那種「1 × n 的扁矩陣」邊界。 （n 是奇數時中間會剩一格，但那是 top == bottom 的正常情況。）

範例

範例 1 輸入：n = 3 輸出：[[1,2,3],[8,9,4],[7,6,5]] 1 2 3 8 9 4 7 6 5 範例 2 輸入：n = 1 輸出：[[1]]

限制條件

  • 1 ≤ n ≤ 20

LeetCode 原題

先看懂限制在說什麼

  • 保證是正方形，而且 n ≥ 1。比第 54 題單純很多。
  • n ≤ 20，最多 400 個格子。效率完全不是問題。
  • 驗證方法：填完之後，用第 54 題的螺旋走訪讀回來，應該剛好得到 1, 2, ..., n²。這是最可靠的自我檢查，本篇的測試就是這樣做的。

解題思路

解法一

四個邊界（和第 54 題同構）

class Solution: def generateMatrix(self, n: int) -> List[List[int]]: m = [[0] * n for _ in range(n)] top, bottom, left, right = 0, n - 1, 0, n - 1 v = 1 while top <= bottom and left <= right: for c in range(left, right + 1): m[top][c] = v; v += 1 top += 1 for r in range(top, bottom + 1): m[r][right] = v; v += 1 right -= 1 if top <= bottom: for c in range(right, left - 1, -1): m[bottom][c] = v; v += 1 bottom -= 1 if left <= right: for r in range(bottom, top - 1, -1): m[r][left] = v; v += 1 left += 1 return m

那兩個 if 還需要嗎？

本題是正方形，所以不會出現「1 × n」那種扁矩陣。 但 n 是奇數時，最後會剩下正中間一格： 此時 top == bottom 且 left == right ① 往右：填掉那一格，top 變成 bottom + 1 ② 往下：range(top, bottom+1) 空的，不做事，right 變成 left - 1 ③ 如果沒有 if top <= bottom： range(right, left-1, -1) = range(left-1, left-1, -1) 是空的 剛好也不做事 —— 所以其實不加 if 也不會錯 但這是「碰巧」而不是「設計」。 n 是偶數時，最後一圈是 2×2，四步都會執行，也沒問題。 保留那兩個 if 的理由： 1. 和第 54 題保持一致（同一套模板） 2. 意圖明確，不依賴「range 剛好是空的」這種巧合 3. 如果之後推廣到非正方形，它們就變成必要的 「不依賴巧合」是寫邊界程式碼的好習慣。

驗證的技巧

填完之後最快的檢查：矩陣裡的數字排序後應該剛好是 1..n²，一個不多一個不少。如果有重複或缺漏，表示邊界收縮的邏輯錯了。sorted(v for row in m for v in row) == list(range(1, n*n+1)) 一行就能檢查。

複雜度說明
時間O(n²)每格填一次
空間O(1)（不算輸出）只有四個邊界變數
解法二

方向陣列 + 已填標記

和第 54 題的解法二一樣：像蟲一樣爬，撞牆或撞到已填的格子就右轉。這題更方便 —— 矩陣本身就是「已填標記」（0 表示還沒填）。

class Solution: def generateMatrix(self, n: int) -> List[List[int]]: m = [[0] * n for _ in range(n)] DIRS = [(0, 1), (1, 0), (0, -1), (-1, 0)] # 右下左上 r = c = d = 0 for v in range(1, n * n + 1): m[r][c] = v nr, nc = r + DIRS[d][0], c + DIRS[d][1] # 撞牆或撞到已填的格子 -> 右轉 if not (0 <= nr < n and 0 <= nc < n and m[nr][nc] == 0): d = (d + 1) % 4 nr, nc = r + DIRS[d][0], c + DIRS[d][1] r, c = nr, nc return m

不需要額外的 seen 陣列，因為 m[nr][nc] == 0 就代表「還沒填」。（這依賴「要填的值都 ≥ 1」—— 剛好成立。）

迴圈跑 n * n 次，剛好每格一次，所以完全不需要終止條件的判斷。

優點：沒有任何邊界推導，幾乎不可能寫錯。缺點：每一步都要做一次「越界 + 已填」的檢查（常數稍大），而且依賴「0 是保留值」這個假設。

複雜度說明
時間O(n²)每格一次
空間O(1)（不算輸出）沒有額外空間

邊界條件檢查清單

  • n = 1 → [[1]]。
  • n = 2 → [[1,2],[4,3]]。最小的完整一圈。
  • n = 3 → 正中間是 9（最後一個填的）。
  • n 是偶數：最後一圈剛好是 2×2，四步都會執行。
  • n 是奇數：最後剩正中間一格，只有第 ① 步會填到它。
  • 驗證：排序後必須是 1..n²，而且螺旋讀回來要是遞增的。

常見追問

追問一：如果要從內往外填呢？

最簡單的做法：照本題填，然後把每個值 v 換成 n² + 1 − v。（由外往內填 1..n²，反轉數值就變成由內往外。）如果要「由內往外順時針」而不是「由內往外逆時針」，方向也要調整。

追問二：如果不是正方形（m × n）呢？

四邊界的邏輯完全不用改，只要把 bottom 初始化成 m - 1、right 初始化成 n - 1。但那兩個 if 就變成必要的了（會出現「只剩一列」的情況）。

追問三：這題和第 54 題為什麼值得一起練？

因為它們展示了一個重要的對稱性：「走訪」和「生成」是同一個演算法的兩面。

走訪： for 每個位置（依某個順序）: 讀出 data[位置] 生成： for 每個位置（依某個順序）: data[位置] = 下一個值 只要「順序」的邏輯寫對了，兩者共用同一份程式碼骨架。 同樣的對稱出現在： 第 6 題 Z 字形變換（走訪）vs 還原（生成） 序列化 vs 反序列化（第 297 題） 編碼 vs 解碼 寫完一個，另一個通常只要改一行。
