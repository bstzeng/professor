LeetCode 43

Multiply Strings
字串相乘

Medium · 中等 數學 字串 模擬

Problem

Given two non-negative integers num1 and num2 represented as strings, return the product of num1 and num2, also represented as a string.

Note: You must not use any built-in BigInteger library or convert the inputs to integer directly.

中文翻譯

給你兩個以字串表示的非負整數 num1 和 num2，回傳它們的乘積，同樣以字串表示。

注意：不能使用任何大整數函式庫，也不能直接把輸入轉成整數。

核心洞察：結果的位置是可以事先算出來的

num1 的第 i 位（從左數，0-indexed） num2 的第 j 位 它們相乘的結果，會落在結果的哪裡？ num1[i] 代表的數量級是 10^(m-1-i) num2[j] 代表的數量級是 10^(n-1-j) 乘積的數量級是 10^(m+n-2-i-j) 如果結果陣列 res 長度是 m+n（同樣是「從左數」）， 那麼數量級 10^k 對應的索引是 (m+n-1) - k = (m+n-1) - (m+n-2-i-j) = i + j + 1 而 num1[i] * num2[j] 最大是 9×9 = 81，是兩位數， 所以十位要放在 res[i+j]。 結論： res[i+j+1] 放個位 res[i+j] 放十位 這個公式讓我們可以「先全部乘完再統一處理進位」， 不用管乘法的順序。

為什麼結果的長度是 m + n？因為 m 位數乘 n 位數，結果最多是 m + n 位（例如 99 × 99 = 9801，2 + 2 = 4 位），最少是 m + n − 1 位（例如 10 × 10 = 100，3 位）。所以開 m + n 格一定夠，最多前面多一個 0。

範例

範例 1 輸入：num1 = "2", num2 = "3" 輸出："6" 範例 2 輸入：num1 = "123", num2 = "456" 輸出："56088"

限制條件

  • 1 ≤ num1.length, num2.length ≤ 200
  • num1 和 num2 只含數字 0–9
  • 兩者都不含前導零，除非數字本身就是 "0"

LeetCode 原題

先看懂限制在說什麼

  • 長度到 200，所以結果最多 400 位 —— 遠超任何內建整數型別（在 C/Java 裡）。Python 的整數是任意精度的，所以 str(int(a)*int(b)) 會過，但那完全違背題目的用意。
  • 沒有前導零（除了 "0" 自己）。所以輸出也不能有前導零 —— lstrip("0") 是必要的。
  • 其中一個可能是 "0"。這時候結果是 "0"，但 lstrip("0") 會把它變成空字串！必須先擋掉。
  • O(m × n) = 4 × 10⁴ —— 完全不是問題。這題考的是實作，不是效率。

解題思路

解法一

位置對應 + 統一進位（最推薦）

class Solution: def multiply(self, num1: str, num2: str) -> str: if num1 == "0" or num2 == "0": return "0" m, n = len(num1), len(num2) # 關鍵：num1[i] * num2[j] 的結果一定落在 res[i+j] 和 res[i+j+1] 這兩格 res = [0] * (m + n) for i in range(m - 1, -1, -1): d1 = int(num1[i]) for j in range(n - 1, -1, -1): d2 = int(num2[j]) total = d1 * d2 + res[i + j + 1] # 加上之前留在低位的值 res[i + j + 1] = total % 10 # 個位留下 res[i + j] += total // 10 # 進位往前推 # 去掉開頭的 0（最多只會有一個） out = "".join(map(str, res)).lstrip("0") return out

為什麼可以「邊乘邊進位」？

total = d1 * d2 + res[i+j+1] d1 * d2 最多 81 res[i+j+1] 最多 9（因為每次都取了 % 10） total 最多 90，是兩位數 ✔ res[i+j+1] = total % 10 個位留下 res[i+j] += total // 10 十位「累加」到前一格（用 += 不是 =） 注意這裡的不對稱： res[i+j+1] 用「=」（覆蓋），因為它已經被加進 total 了 res[i+j] 用「+=」（累加），因為它可能還有別的進位要加 res[i+j] 會不會爆掉（超過 9）？ 會，但沒關係 —— 因為輪到 (i-1, j) 或 (i, j-1) 時， res[i+j] 會被當成「低位」讀進 total，然後處理它的進位。 迴圈的順序（i 從右往左、j 從右往左）保證了 「低位一定先被處理完」。 最後一格 res[0] 呢？ 它不會爆，因為結果最多 m+n 位。

迴圈順序為什麼要從右往左？

因為進位是「從低位往高位傳」的。從右往左跑，可以保證處理 res[i+j] 時，所有會影響它的低位進位都已經算完了。

lstrip("0") 的陷阱

res 最多只有一個前導零（因為結果至少 m+n-1 位）。 但 lstrip 是「去掉所有開頭的 0」： "0000" -> "" 空字串！ 這在 num1 或 num2 是 "0" 時會發生。 所以最上面的 if num1 == "0" or num2 == "0": return "0" 不能省。 更保險的寫法： out = "".join(map(str, res)).lstrip("0") return out if out else "0"
複雜度說明
時間O(m·n)雙層迴圈
空間O(m+n)結果陣列
解法二

拆成「乘一位數」+「字串加法」（最像手算）

把小學的直式乘法照搬過來：num1 分別乘以 num2 的每一位，每次結果往左移一位，最後全部加起來。

class Solution: def multiply(self, num1: str, num2: str) -> str: if num1 == "0" or num2 == "0": return "0" def add(a: str, b: str) -> str: """字串直式加法""" i, j = len(a) - 1, len(b) - 1 carry = 0 out = [] while i >= 0 or j >= 0 or carry: s = carry if i >= 0: s += int(a[i]); i -= 1 if j >= 0: s += int(b[j]); j -= 1 out.append(str(s % 10)) carry = s // 10 return "".join(reversed(out)) def mul_digit(a: str, d: int) -> str: """字串乘以一位數""" if d == 0: return "0" carry = 0 out = [] for ch in reversed(a): p = int(ch) * d + carry out.append(str(p % 10)) carry = p // 10 while carry: out.append(str(carry % 10)) carry //= 10 return "".join(reversed(out)) # 就是小學的直式乘法：每一位乘一次、補零、全部加起來 result = "0" for k, ch in enumerate(reversed(num2)): partial = mul_digit(num1, int(ch)) if partial != "0": partial += "0" * k # 補 k 個零（左移 k 位） result = add(result, partial) return result
123 × 45 ------ 615 123 × 5，不補零 4920 123 × 4，補 1 個零 ------ 5535 兩者相加 程式碼裡： k = 0（num2 的個位 '5'）-> mul_digit("123", 5) = "615"，補 0 個零 k = 1（num2 的十位 '4'）-> mul_digit("123", 4) = "492"，補 1 個零 -> "4920" add("615", "4920") = "5535" ✔

優點：把問題拆成兩個獨立的、各自簡單的子程序（add 和 mul_digit），每一個都可以單獨測試。而且 add 本身就是第 415 題、mul_digit 是第 66 題的變形 —— 都是可以重複使用的元件。

缺點：中間結果要建 n 次字串，常數比解法一大，程式碼也長。

什麼時候該選它？如果你已經有一個寫好的大數加法函式庫，這個做法可以直接組合起來，不用重新推導位置公式。在實務上，「組合已知正確的元件」通常比「寫一個更聰明但更容易錯的東西」划算。

複雜度說明
時間O(m·n)n 次「乘一位 + 加法」
空間O(m+n)中間字串

邊界條件檢查清單

  • 任一個是 "0"：("0", "123") → "0"。沒有特判的話 lstrip("0") 會回傳空字串。
  • 兩個都是 "0"：("0", "0") → "0"。
  • 單一位數：("9", "9") → "81"。結果剛好 2 位（m+n）。
  • 結果少一位：("1", "1") → "1"。res 是 [0,1]，要去掉前導零。
  • 全是 9：("999", "999") → "998001"。進位最密集。
  • 結尾有 0：("100", "100") → "10000"。結尾的 0 不能被 strip 掉 —— 用 lstrip 而不是 strip。
  • 長度到上限：200 × 200 位，結果 400 位。

常見追問

追問一：有沒有比 O(m·n) 更快的乘法？

有，而且是計算機科學的一個經典主題： 長乘法（本題） O(n²) Karatsuba（1960） O(n^1.585) 把 n 位拆成兩半，用 3 次遞迴乘法而不是 4 次： (a·10^k + b)(c·10^k + d) = ac·10^2k + (ad + bc)·10^k + bd 而 ad + bc = (a+b)(c+d) - ac - bd 所以只要算 ac、bd、(a+b)(c+d) 三次 Toom-Cook O(n^1.465) 等（拆成更多份） Schönhage-Strassen（1971） O(n log n log log n) 用快速傅立葉變換（FFT） Harvey-van der Hoeven（2019） O(n log n) 理論上的最優，但常數大到實務上沒用 實務上的門檻（以 GMP 函式庫為例）： < 30 位 長乘法最快（常數最小） 30~300 位 Karatsuba > 幾千位 FFT 系列 本題 200 位，長乘法完全夠用。

追問二：Python 的大整數乘法用什麼演算法？

CPython 用長乘法 + Karatsuba：在 longobject.c 裡，當兩個數都超過 70 個「digit」（CPython 內部用 30 位元為一個 digit）時切換到 Karatsuba。它沒有實作 FFT 乘法 —— 需要超大整數運算時，Python 使用者通常會轉向 gmpy2（綁定 GMP）。

追問三：為什麼題目要禁止直接轉整數？

因為在 C、Java、Go 這些語言裡根本沒有「直接轉」這個選項 —— 200 位數遠超 64 位元。這題的本意是「實作大整數乘法」，而 Python 的任意精度整數讓這個限制變成一句人為的規定。

面試時的正確態度：主動說「Python 可以直接算，但我理解題目要的是手寫的直式乘法，所以我會實作位置對應的版本」。
