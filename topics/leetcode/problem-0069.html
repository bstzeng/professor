LeetCode 69

Sqrt(x)
x 的平方根

Easy · 簡單 數學 二分搜尋

Problem

Given a non-negative integer x, return the square root of x rounded down to the nearest integer. The returned integer should be non-negative as well.

You must not use any built-in exponent function or operator.

中文翻譯

給你一個非負整數 x，回傳它的算術平方根，向下取整。

不能使用任何內建的次方函式或運算子（例如 pow(x, 0.5) 或 x ** 0.5）。

這題就是「找邊界」型的二分搜尋

要找的是：「最大的整數 m，使得 m² <= x」 x = 8 -> 2² = 4 <= 8，3² = 9 > 8 -> 答案 2 x = 16 -> 4² = 16 <= 16 -> 答案 4 關鍵性質：述詞 P(m) = (m² <= x) 是【單調】的 m: 0 1 2 3 4 5 ... m² <= 8: ✔ ✔ ✔ ✘ ✘ ✘ 一旦變成 ✘ 就永遠是 ✘ —— 這正是二分搜尋的前提。 所以這題和第 35 題（Search Insert Position）是同一個骨架， 只是述詞從「nums[i] >= target」換成「m² > x」。 「二分答案」的通用模式： 1. 答案的範圍是什麼？ [0, x] 2. 述詞是什麼？ m² <= x 3. 它單調嗎？ ✔ 4. 套 partition_point 骨架

為什麼不能用 x ** 0.5？除了題目禁止之外，浮點數在大數時會有精度問題 —— int(2147395600 ** 0.5) 在某些平台上會得到 46339 而不是 46340。整數平方根必須用整數運算算，才能保證精確。

範例

範例 1 輸入：x = 4 輸出：2 範例 2 輸入：x = 8 輸出：2 說明：8 的平方根是 2.828...，向下取整是 2。

限制條件

  • 0 ≤ x ≤ 2³¹ − 1

LeetCode 原題

先看懂限制在說什麼

  • x 可以到 2³¹ − 1 = 2147483647，答案最大是 46340（因為 46340² = 2147395600 ≤ x，而 46341² = 2147488281 > x）。
  • 在 C/Java 裡 mid * mid 會溢位！mid 可能到 10⁹，平方是 10¹⁸ —— 超過 int。標準做法是改成 mid > x / mid（除法比較，不會溢位）或用 long。Python 沒這個問題，但面試時一定要提。
  • x 可以是 0 或 1 → 答案就是它自己。牛頓法要特判這兩個（x // r 在 r = 0 時會除以零）。

解題思路

解法想法迭代次數（x ≈ 2³¹）
一、二分搜尋在 [0, x] 上找邊界約 31 次
二、partition_point同上，換一個骨架約 31 次
三、牛頓法用切線逼近，二次收斂約 20 次
解法一

二分搜尋（經典骨架）

class Solution: def mySqrt(self, x: int) -> int: if x < 2: return x # 找「最大的 m 使得 m*m <= x」 lo, hi = 1, x // 2 # x >= 2 時，答案不會超過 x//2 while lo <= hi: mid = (lo + hi) // 2 sq = mid * mid if sq == x: return mid if sq < x: lo = mid + 1 # mid 可行，但也許還能更大 else: hi = mid - 1 return hi # 迴圈結束時 hi 就是「最大的可行值」

為什麼結束時回傳 hi？

迴圈用的是「while lo <= hi」的經典骨架。 結束時 lo == hi + 1，而且： 所有 <= hi 的 m 都滿足 m² <= x 所有 >= lo 的 m 都滿足 m² > x 所以 hi 就是「最大的可行值」= 答案 ✔ 追一遍 x = 8： lo=1, hi=4 mid=2: 4 < 8 -> lo=3 lo=3, hi=4 mid=3: 9 > 8 -> hi=2 lo=3 > hi=2 -> 結束 return hi = 2 ✔

為什麼上界可以取 x // 2？

對 x >= 4，sqrt(x) <= x/2： 等價於 4x <= x²，也就是 x >= 4 ✔ x = 2, 3 時 x//2 = 1，而答案也是 1 ✔ x = 0, 1 已經被提前 return 擋掉。 所以 hi = x // 2 對所有 x >= 2 都是安全的上界。 這只是常數優化（少一兩次迭代）， 寫 hi = x 也完全正確。

C/Java 的溢位陷阱

if (mid * mid <= x) // ✘ mid 到 10⁹ 時 mid*mid 會溢位 三種修法： 1. 用 long： if ((long)mid * mid <= x) 2. 改成除法： if (mid <= x / mid) 3. 縮小上界： hi = 46340（sqrt(INT_MAX) 的上界） 第 2 種最優雅，而且不依賴更大的型別。 mid <= x / mid <=> mid² <= x（整數除法會捨去，但不影響比較的方向） 嚴格說：x / mid 是 floor(x/mid)， 而 mid <= floor(x/mid) <=> mid * mid <= x （因為 mid 是整數）✔
複雜度說明
時間O(log x)約 31 次迭代
空間O(1)幾個變數
解法二

partition_point 骨架（更統一）

class Solution: def mySqrt(self, x: int) -> int: # partition_point 骨架：找「第一個 m 使得 m*m > x」，再減 1 lo, hi = 0, x + 1 while lo < hi: mid = (lo + hi) // 2 if mid * mid > x: hi = mid else: lo = mid + 1 return lo - 1

用第 35 題的 lower_bound 骨架：找「第一個讓 m² > x 成立的 m」，然後減 1。

述詞 P(m) = (m² > x) m: 0 1 2 3 4 P(m): ✘ ✘ ✘ ✔ ✔ （x = 8） 第一個 ✔ 是 m = 3 答案 = 3 - 1 = 2 ✔ 上界設 x + 1： 因為答案最大是 x（當 x = 0 或 1 時）， 所以「第一個 P 成立的位置」最大是 x + 1。 x = 1: lo 會收斂到 2，答案 2 - 1 = 1 ✔ x = 0: lo 會收斂到 1，答案 1 - 1 = 0 ✔ 這個版本不用任何特判（x = 0 和 1 自動處理）， 而且和第 34、35、278、875 題共用同一個骨架。 我個人偏好這個版本 —— 「只記一種二分骨架」比「記三種」不容易出錯。
複雜度說明
時間O(log x)同上
空間O(1)幾個變數
解法三

牛頓法（收斂最快）

把「求 √x」變成「求方程式 f(r) = r² − x = 0 的根」，然後用牛頓-拉弗森法（Newton-Raphson）迭代。

class Solution: def mySqrt(self, x: int) -> int: if x < 2: return x # 牛頓法：求 f(r) = r² - x = 0 的根 # 迭代式 r' = r - f(r)/f'(r) = r - (r² - x)/(2r) = (r + x/r) / 2 r = x while r * r > x: r = (r + x // r) // 2 # 整數版，會單調遞減收斂到 floor(sqrt(x)) return r

迭代式的推導

牛頓法的通式：從點 (r, f(r)) 畫切線，切線和 x 軸的交點就是下一個 r。 r' = r - f(r) / f'(r) f(r) = r² - x f'(r) = 2r r' = r - (r² - x) / (2r) = r - r/2 + x/(2r) = (r + x/r) / 2 最後這個形式有一個很直覺的解讀： 「目前的猜測 r」和「x 除以猜測 x/r」的【平均】 如果 r 太大，x/r 就會太小；反之亦然。 取平均就會往中間靠 —— 而正確答案 √x 剛好滿足 r == x/r。 這個公式在古代就被發現了，叫做【巴比倫方法】或【希羅方法】—— 比牛頓早了三千多年。

為什麼整數版的 while r * r > x 會停在正確答案？

整數版： r = (r + x // r) // 2 關鍵性質： 1. 從 r = x 開始，序列是【單調遞減】的（在 r > sqrt(x) 的範圍內） 2. 而且永遠 >= floor(sqrt(x))（不會衝過頭太多） 3. 所以當 r*r <= x 第一次成立時，r 就是 floor(sqrt(x)) 直覺：r > sqrt(x) 時，AM-GM 不等式保證 (r + x/r)/2 >= sqrt(x) 所以新的 r 不會掉到 sqrt(x) 以下。 而整數除法的捨去，剛好讓它停在 floor(sqrt(x))。 x = 8 的迭代： r = 8: 8*8 = 64 > 8 -> r = (8 + 8//8)//2 = (8+1)//2 = 4 r = 4: 16 > 8 -> r = (4 + 8//4)//2 = (4+2)//2 = 3 r = 3: 9 > 8 -> r = (3 + 8//3)//2 = (3+2)//2 = 2 r = 2: 4 <= 8 -> 停，回傳 2 ✔ x = 0 會在 x // r 那裡除以零 —— 所以要提前 return。

為什麼牛頓法比二分快？

二分是「線性收斂」：每次把誤差減半，正確的位元數每次加 1。

牛頓法是「二次收斂」：每次把誤差平方，正確的位元數大約加倍。

x ≈ 2³¹ 時： 二分： 約 31 次迭代（每次砍一半） 牛頓： 約 5-6 次就收斂到很接近， 但整數版從 r = x 開始，前幾步是「除以 2」， 所以實際約 20 次。 如果初始猜測選得好（例如用位元長度估一個接近的起點）， 牛頓法可以壓到 5-6 次。 實務上： 現代 CPU 有 sqrt 指令（硬體實作，幾個週期）。 而軟體實作（例如嵌入式系統、大數函式庫） 幾乎都用牛頓法 —— 因為二次收斂太划算了。 著名的「快速反平方根」（Quake III 的 0x5f3759df） 也是牛頓法，只是用一個位元技巧產生了極好的初始猜測。
複雜度說明
時間O(log log x) 迭代二次收斂
空間O(1)一個變數

邊界條件檢查清單

  • x = 0 → 0；x = 1 → 1。牛頓法必須特判（x // r 會除以零）。
  • 完全平方數：4 → 2、16 → 4、100 → 10。
  • 剛好差一：15 → 3、17 → 4。驗證邊界沒有差一。
  • 最大值：2147483647 → 46340。
  • 臨界點：2147395599 → 46339（因為 46340² = 2147395600 > 它）。這是 LeetCode 專門用來抓浮點精度錯誤的測資 —— int(2147395599 ** 0.5) 在某些平台會得到 46340（錯）。
  • C/Java 的 mid * mid：mid 到 10⁹ 時會溢位。

常見追問

追問一：如果要精確到小數點後 k 位呢？

兩種做法：

  • 放大再開根號：算 isqrt(x × 10^(2k))，然後在結果的小數點後 k 位插入小數點。這樣完全用整數運算，沒有浮點誤差。
  • 浮點二分：在 [0, x] 上二分，直到 hi - lo < 10^(-k)。簡單但有浮點誤差累積。

第一種在金融和密碼學裡是標準做法 —— 整數運算才能保證可重現。

追問二：Python 有內建的整數平方根嗎？

有：math.isqrt(x)（Python 3.8+）。它保證回傳 floor(sqrt(x))，而且對任意大的整數都精確。內部用的是一個基於牛頓法的「自適應精度」演算法。本篇的測試就是拿它當基準。

追問三：「快速反平方根」是什麼？

Quake III Arena 的著名程式碼（1999 年公開）： float Q_rsqrt(float number) { long i = *(long*)&number; i = 0x5f3759df - (i >> 1); // 什麼鬼？ float y = *(float*)&i; y = y * (1.5f - 0.5f * number * y * y); // 一次牛頓迭代 return y; } 它在算 1/sqrt(x)（3D 圖學裡用來正規化向量）。 那一行魔術數字在做什麼？ IEEE 754 浮點數的位元表示，本身就「近似」是 log₂(x) 的線性函數。 所以對位元做「減半再取負」，近似就是對數值做「開根號再取倒數」。 0x5f3759df 是那個近似的最佳偏移常數。 這給出約 1 位有效數字的初始猜測， 然後一次牛頓迭代就把它提升到約 6 位 —— 夠 3D 遊戲用了，而且比呼叫 sqrt() 快好幾倍。 現代 CPU 有 rsqrtss 指令，所以這個技巧已經過時， 但它是「理解浮點數位元表示」的經典教材。

追問四：為什麼「二分答案」是一個這麼通用的模式？

因為很多最佳化問題都可以改寫成「找最大／最小的可行值」，而「可行性」往往是單調的。

本題： P(m) = (m² <= x) 找最大可行 第 278 題： P(v) = isBadVersion(v) 找最小成立 第 875 題： P(speed) = 能在 h 小時內吃完 找最小可行 第 1011 題：P(cap) = 能在 d 天內運完 找最小可行 第 410 題： P(x) = 能分成 k 段且每段和 <= x 找最小可行 第 4 題： 二分「切割點」而不是值 判斷能不能用： 1. 答案在一個有界的範圍裡 2. 有一個「檢查可行性」的函式 check(m) 3. check 是單調的（一旦可行就一直可行，或反之） 三個條件都滿足 -> 套 partition_point 骨架， 複雜度 O(log(值域) × check 的複雜度)。
