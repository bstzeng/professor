LeetCode 207

Course Schedule
課程表

Medium · 中等 深度優先搜尋 廣度優先搜尋 圖 拓撲排序

Problem

There are numCourses courses labeled 0 to numCourses - 1. You are given an array prerequisites where prerequisites[i] = [ai, bi] means course bi must be completed before course ai can be taken.

Return true if it is possible to complete every course, otherwise return false.

中文翻譯

有 numCourses 門課，編號 0 到 numCourses - 1。陣列 prerequisites 中的 [ai, bi] 表示：要修課程 ai，必須先修完課程 bi。

如果有辦法修完所有課程，回傳 true；否則回傳 false。

範例

範例 1 輸入：numCourses = 2, prerequisites = [[1,0]] 輸出：true 說明：先修 0，再修 1。 範例 2 輸入：numCourses = 2, prerequisites = [[1,0],[0,1]] 輸出：false 說明：修 1 要先修 0，修 0 又要先修 1 —— 互相卡住。

限制條件

  • 1 ≤ numCourses ≤ 2000
  • 0 ≤ prerequisites.length ≤ 5000
  • prerequisites[i].length == 2
  • 0 ≤ ai, bi < numCourses
  • 所有的 [ai, bi] 都互不相同

LeetCode 原題

解題思路

【把課程看成有向圖】 [a, b]：先修 b 才能修 a -> 畫一條 b -> a 的邊 能不能修完所有課？ = 這張有向圖有沒有環？ = 能不能排出一個「拓撲排序」？ 【兩種找環的方法】 1. Kahn（BFS）：從沒有先修的課開始，一門一門修掉， 修掉一門就把它指向的課的「剩餘先修數」減 1。 最後修掉的數量 = numCourses 才代表沒有環。 2. DFS 三色標記： 白 0 = 沒走過 灰 1 = 正在目前這條遞迴路徑上 黑 2 = 已經確認從它出發不會有環 走到灰色的點 = 走回自己的路徑 = 有環。 【方向要搞清楚】 [a, b] 是「b 先、a 後」。 邊的方向畫反了，在「判斷有沒有環」這題不影響答案 （反轉所有邊，環還是環）， 但第 210 題要輸出順序時就會整個反過來 ✘
解法一

Kahn 演算法（BFS 拓撲排序）

class Solution: def canFinish(self, numCourses: int, prerequisites: List[List[int]]) -> bool: graph = [[] for _ in range(numCourses)] indeg = [0] * numCourses for a, b in prerequisites: # 先修 b 才能修 a：邊 b -> a graph[b].append(a) indeg[a] += 1 q = deque(i for i in range(numCourses) if indeg[i] == 0) taken = 0 while q: u = q.popleft() taken += 1 for v in graph[u]: indeg[v] -= 1 if indeg[v] == 0: # ★ 所有先修都修完了，可以修 q.append(v) return taken == numCourses # 有環的課永遠進不了佇列
【為什麼 taken == numCourses 就沒有環？】 環上的每一門課，都至少有一門先修也在環上。 環上的課沒有一門能先被修掉 -> 它們的入度永遠不會降到 0 -> 永遠不會進佇列 -> taken < numCourses。 【複雜度】 建圖 O(E)；每個點進出佇列一次、每條邊被處理一次 -> O(V + E)
複雜度說明
時間O(V + E)V = 課程數，E = 先修關係數
空間O(V + E)鄰接串列與入度陣列
解法二

DFS 三色標記

class Solution: def canFinish(self, numCourses: int, prerequisites: List[List[int]]) -> bool: graph = [[] for _ in range(numCourses)] for a, b in prerequisites: graph[b].append(a) # 0 = 沒看過，1 = 正在目前的 DFS 路徑上，2 = 已確認沒有環 state = [0] * numCourses def has_cycle(u: int) -> bool: state[u] = 1 for v in graph[u]: if state[v] == 1: # ★ 回到路徑上的點 = 環 return True if state[v] == 0 and has_cycle(v): return True state[u] = 2 return False return not any(state[u] == 0 and has_cycle(u) for u in range(numCourses))
【為什麼需要三種顏色，兩種不夠？】 如果只有「看過 / 沒看過」： 0 -> 1, 0 -> 2, 1 -> 3, 2 -> 3 從 0 走 1 走 3（標記看過），回來再走 2 走到 3—— 3 已經看過，但這【不是環】，只是兩條路匯合 ✘ 「灰色」專門代表「在目前這條路徑上」： 走到灰色 -> 真的繞回自己 -> 環 ✔ 走到黑色 -> 那裡早就確認安全 -> 不用再走 【遞迴深度】 最多 2000 層，超過 Python 預設的 1000。 LeetCode 有調高上限；要保險可以 sys.setrecursionlimit， 或改用解法一。
複雜度說明
時間O(V + E)
空間O(V + E)遞迴堆疊最深 V

邊界條件檢查清單

  • 沒有任何先修 → 一定修得完。
  • 課程自己指向自己（[1, 1]）→ 自環，修不完；兩種解法都能正確處理。
  • 圖不連通 → Kahn 一開始就把所有入度 0 的點放進佇列；DFS 要對每個點都嘗試出發。
  • DFS 只用兩種顏色 → 會把「匯合」誤判成「環」。

常見追問

追問一：如果要輸出修課順序？

就是第 210 題：Kahn 演算法中「出佇列的順序」就是一個合法的修課順序。 DFS 的話，是「後序（變黑的順序）」反轉過來。

追問二：如果要知道「最少要幾個學期」修完（每學期不限門數）？

Kahn 演算法一次處理「一整層」入度為 0 的課， 層數就是學期數（第 1136 題，付費題）。
