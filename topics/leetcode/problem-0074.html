Search a 2D Matrix
搜尋二維矩陣

Medium · 中等 陣列 二分搜尋 矩陣

Problem

You are given an m x n integer matrix matrix with the following two properties: each row is sorted in non-decreasing order; the first integer of each row is greater than the last integer of the previous row.

Given an integer target, return true if target is in matrix or false otherwise.

You must write a solution in O(log(m * n)) time complexity.

中文翻譯

給你一個 m × n 的整數矩陣，它有兩個性質：（1）每一列都是非遞減排序；（2）每一列的第一個數，都大於前一列的最後一個數。

給你一個 target，判斷它在不在矩陣裡。

演算法必須是 O(log(m × n))。

第二個性質是關鍵：整個矩陣「攤平」就是有序的

matrix = [[1, 3, 5, 7], [10, 11, 16, 20], [23, 30, 34, 60]] 攤平（逐列接起來）： [1, 3, 5, 7, 10, 11, 16, 20, 23, 30, 34, 60] 嚴格遞增！ 為什麼？ 性質 1 保證「同一列內」遞增 性質 2 保證「跨列的接縫」也遞增（7 < 10，20 < 23） 所以整個矩陣就是「一個折疊起來的有序陣列」。 一維索引 k <-> 二維座標 (r, c)： r, c = divmod(k, n) 一維 -> 二維 k = r * n + c 二維 -> 一維 k = 5, n = 4 -> (1, 1) -> matrix[1][1] = 11 ✔ 有了這個對應，直接對 [0, m*n-1] 做標準二分搜尋 -> O(log(mn)) ✔

如果沒有性質 2（每一列的開頭不保證比上一列的結尾大），那就是第 240 題（Search a 2D Matrix II），攤平之後不是有序的，二分搜尋失效 —— 只能用 O(m+n) 的階梯搜尋。

範例

範例 1 輸入：matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]], target = 3 輸出：true 範例 2 輸入：matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]], target = 13 輸出：false

限制條件

  • m == matrix.length，n == matrix[i].length
  • 1 ≤ m, n ≤ 100
  • −10⁴ ≤ matrix[i][j], target ≤ 10⁴

LeetCode 原題

先看懂限制在說什麼

  • 要求 O(log(mn)) —— 排除了 O(m + n) 的階梯搜尋（雖然在 100 × 100 時也很快）。
  • m, n ≥ 1，所以 matrix[0][0] 一定存在。但寫上 if not matrix or not matrix[0] 比較安全。
  • 注意 log(mn) = log m + log n —— 所以「先二分找列，再二分找行」（解法二）也符合要求。

解題思路

解法一

當成一維陣列二分（最推薦）

class Solution: def searchMatrix(self, matrix: List[List[int]], target: int) -> bool: m, n = len(matrix), len(matrix[0]) # 把二維矩陣「看成」一個長度 m*n 的有序一維陣列 lo, hi = 0, m * n - 1 while lo <= hi: mid = (lo + hi) // 2 r, c = divmod(mid, n) # 一維索引還原成 (列, 行) v = matrix[r][c] if v == target: return True if v < target: lo = mid + 1 else: hi = mid - 1 return False

divmod(mid, n) —— 注意是 n 不是 m

一維索引 k 對應 (r, c)： r = k // n （n 是「每一列有幾個元素」= 行數） c = k % n Python 的 divmod(k, n) 一次給出兩個值。 最常見的錯誤：寫成 divmod(mid, m)。 matrix 是 3 列 × 4 行（m=3, n=4） k = 5 應該對應 (1, 1) divmod(5, 4) = (1, 1) ✔ divmod(5, 3) = (1, 2) ✘ 完全錯了 記法：「除以『一列有幾個』得到列號」。 而「一列有幾個」= 行數 = n。

整個解法就是標準二分搜尋，只多了一行座標轉換。而且它明確地展示了「這個矩陣就是一個有序陣列」這個洞察 —— 面試時這個表達很有力。

複雜度 O(log(mn))，剛好符合要求。

複雜度說明
時間O(log(m·n))一次二分
空間O(1)幾個變數
解法二

兩次二分（先找列，再找行）

class Solution: def searchMatrix(self, matrix: List[List[int]], target: int) -> bool: m, n = len(matrix), len(matrix[0]) # 第 1 次二分：找出 target 可能在哪一列 lo, hi = 0, m - 1 while lo <= hi: mid = (lo + hi) // 2 if matrix[mid][0] <= target <= matrix[mid][n - 1]: row = mid break if matrix[mid][0] > target: hi = mid - 1 else: lo = mid + 1 else: return False # while 沒有 break -> 沒有任何一列涵蓋 target # 第 2 次二分：在那一列裡找 lo, hi = 0, n - 1 while lo <= hi: mid = (lo + hi) // 2 if matrix[row][mid] == target: return True if matrix[row][mid] < target: lo = mid + 1 else: hi = mid - 1 return False

複雜度 O(log m + log n) = O(log(mn))，和解法一相同。

while ... else

Python 的 while-else：else 只在「迴圈正常結束（沒 break）」時執行。這裡用來表達「沒有任何一列涵蓋 target」。但這個語法很多人沒看過，面試時建議改成明確的旗標變數。

第一次二分的判斷式

if matrix[mid][0] <= target <= matrix[mid][n-1]: 找到了「可能包含 target 的那一列」 if matrix[mid][0] > target: 這一列的開頭就太大了 -> 往上找 else: 這一列的結尾還太小 -> 往下找 要小心三個條件是互斥且窮盡的 —— 漏掉一種就會死循環或漏答案。 相較之下，解法一只有「相等／太小／太大」三種， 判斷式更簡單。

優點：不需要一維／二維的座標轉換，而且「先定位列，再定位行」的分解很自然。

缺點：程式碼長一倍，而且判斷式比較容易寫錯。

複雜度說明
時間O(log m + log n)兩次二分
空間O(1)幾個變數
解法三

從右上角出發的階梯搜尋（對第 240 題也成立）

完全不同的思路：從矩陣的「右上角」出發。往左走數字變小，往下走數字變大 —— 所以每一步都能根據比較結果，排除一整行或一整列。

class Solution: def searchMatrix(self, matrix: List[List[int]], target: int) -> bool: # 從「右上角」出發：往左變小、往下變大 # 這個解法對第 240 題（每列每行遞增，但列之間不連續）也成立 m, n = len(matrix), len(matrix[0]) r, c = 0, n - 1 while r < m and c >= 0: v = matrix[r][c] if v == target: return True if v > target: c -= 1 # 太大 -> 往左（這一行的下面只會更大） else: r += 1 # 太小 -> 往下（這一列的左邊只會更小） return False
matrix = [[1, 3, 5, 7], [10, 11, 16, 20], [23, 30, 34, 60]] target = 16 (0,3) = 7 < 16 -> 這一列（第 0 列）左邊都 <= 7，全部排除 -> r=1 (1,3) = 20 > 16 -> 這一行（第 3 行）下面都 >= 20，全部排除 -> c=2 (1,2) = 16 == 16 -> 找到 ✔ 每一步排除一整列或一整行，所以最多走 m + n 步。 為什麼一定要從「右上角」（或左下角）？ 右上角是唯一一個「往兩個方向走，值的變化方向相反」的角落： 往左 -> 變小 往下 -> 變大 左上角就不行：往右和往下「都變大」， 比較結果沒辦法告訴你該走哪邊。 右下角同理（往左和往上都變小）。 左下角也可以（往右變大、往上變小），是對稱的選擇。

為什麼這題不該用它（但值得會）

複雜度是 O(m + n)，不符合題目要求的 O(log(mn))。在 100 × 100 時 O(m+n) = 200 比 O(log(mn)) ≈ 14 慢，但都很快。

它的價值在於：它不需要「性質 2」。第 240 題（每列遞增、每行也遞增，但列之間不連續）沒辦法攤平成有序陣列，二分搜尋完全失效 —— 而階梯搜尋照樣可以用。

所以：本題寫解法一，但要知道解法三，因為它是第 240 題的唯一好解。

複雜度說明
時間O(m + n)每步排除一列或一行
空間O(1)兩個變數

解法對照

解法時間需要「性質 2」？第 240 題可用？備註
一、攤平二分O(log(mn))✔ 必須✘本題最佳
二、兩次二分O(log m + log n)✔ 必須✘同樣達標，較長
三、階梯搜尋O(m + n)✘ 不需要✔第 240 題的解

邊界條件檢查清單

  • 1 × 1：([[1]], 1) → true；([[1]], 2) → false。
  • 只有一列：([[1,3]], 3) → true。退化成一般的二分搜尋。
  • 只有一行：([[1],[3]], 3) → true。
  • target 在接縫處：target = 10（第 1 列的開頭）。驗證跨列的邏輯。
  • target 比全部都小／都大：target = 0 或 1000 → false。
  • target 剛好落在兩列之間：target = 8（7 和 10 之間）→ false。
  • divmod(mid, m) 的錯誤：在非正方形矩陣上會完全錯亂。一定要用 n。

常見追問

追問一：如果沒有「每列開頭 > 上一列結尾」這個性質呢？

那就是第 240 題。此時矩陣只保證「每列遞增、每行遞增」，攤平之後不是有序的：

[[1, 4, 7], [2, 5, 8], [3, 6, 9]] 攤平：[1,4,7, 2,5,8, 3,6,9] -> 不是有序的 ✘ 二分搜尋完全失效。 階梯搜尋照樣可用（從右上角 7 開始）： 7 > 5 -> 往左 4 < 5 -> 往下 5 == 5 ✔ O(m + n)，而且可以證明這是最優的 （對抗性論證：任何演算法在最壞情況下都必須看 Ω(m+n) 個元素）。

追問二：如果要找「第 k 小的元素」呢？

第 378 題（Kth Smallest Element in a Sorted Matrix）。在本題的條件下（攤平有序）直接取 matrix[k//n][k%n] 就好。但在第 240 題的條件下，要用二分答案：猜一個值 x，用階梯搜尋算出「有幾個元素 ≤ x」，再調整 x。複雜度 O((m+n) log(值域))。

追問三：這種「把二維當成一維」的技巧還能用在哪？

  • 矩陣的線性化儲存：C 的二維陣列本來就是這樣存的（row-major order），a[i][j] 編譯後就是 *(a + i*n + j)。
  • Union-Find 在網格上：把 (i,j) 編成 i*n+j 當節點編號。
  • 位元遮罩表示網格狀態：第 i*n+j 個位元代表 (i,j)。
  • 快取友善的走訪順序：按 row-major 走過陣列，比按 column-major 快好幾倍（因為記憶體是連續的，而 CPU 一次載入一整條快取行）。

「二維其實是一維的一種看法」是很多效能優化的起點。
