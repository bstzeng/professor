Longest Substring Without Repeating Characters
無重複字元的最長子字串

Medium · 中等 雜湊表 字串 滑動視窗

Problem

Given a string s, find the length of the longest substring that contains no repeating characters.

A substring is a contiguous, non-empty sequence of characters within the string.

中文翻譯

給你一個字串 s，請找出其中不含重複字元的 最長子字串的長度。

子字串指的是字串裡連續的一段非空字元序列。

子字串（substring）≠ 子序列（subsequence）

這是這題最常見的誤讀。

s = "pwwkew" 子字串（必須連續）： "pww"、"wke"、"kew" ✔ "pwke" ✘ （跳過了一個 w，不連續） 子序列（可以跳過）： "pwke" ✔ 本題要的是「子字串」，答案是 "wke"，長度 3。 如果是子序列，答案會是 "pwke"，長度 4 —— 那是另一題。

範例

範例 1 輸入：s = "abcabcbb" 輸出：3 說明：最長的無重複子字串是 "abc"。 範例 2 輸入：s = "bbbbb" 輸出：1 說明：最長的是 "b"。 範例 3 輸入：s = "pwwkew" 輸出：3 說明：最長的是 "wke"（不是 "pwke"，那不是子字串）。

限制條件

  • 0 ≤ s.length ≤ 5 × 10⁴
  • s 由英文字母、數字、符號與空白組成

LeetCode 原題

先看懂限制在說什麼

  • n 可以是 0：空字串要回傳 0，不能假設至少有一個字元。
  • n ≤ 5 × 10⁴：O(n²) 是 2.5 × 10⁹，一定逾時。這題必須做到 O(n)。
  • 不只有小寫字母：包含數字、符號、空白，所以不能用長度 26 的陣列。" " 是合法輸入，答案是 1。

解題思路

先想最笨的做法：檢查所有子字串，看哪個沒有重複字元、而且最長。 一個長度 n 的字串有 n(n+1)/2 個子字串，光是枚舉就已經 O(n²) 了。

優化的關鍵洞察是：

如果 s[i..j] 已經有重複字元，那麼 s[i..j+1]、 s[i..j+2]…… 全部都有重複字元，不用再檢查。

這代表對每一個起點 i，我們只要往右延伸到「第一次撞到重複」就可以停。 而且更進一步——當起點從 i 移到 i+1 時， 右邊界完全不需要退回去重來。

這就是滑動視窗：用兩個指標圈出一段區間， 右邊界只往右、左邊界也只往右，兩個都不回頭。 每個元素最多被左右指標各碰一次，所以是 O(n)。

解法一

暴力：枚舉所有子字串

class Solution: def lengthOfLongestSubstring(self, s: str) -> int: def no_repeat(sub: str) -> bool: return len(set(sub)) == len(sub) n = len(s) best = 0 for i in range(n): for j in range(i + 1, n + 1): if no_repeat(s[i:j]): best = max(best, j - i) return best

len(set(sub)) == len(sub) 是一個很 Python 的寫法： set 會去掉重複，所以只要長度沒變，就代表原本沒有重複。

複雜度說明
時間O(n³)O(n²) 個子字串 × 每個 O(n) 的切片與檢查
空間O(min(n, k))k 是字元集大小

n = 5 × 10⁴ 時這個解法會跑到天荒地老。 但它是正確的，可以拿來當「對照組」驗證後面的優化—— 後面每一種解法我都是用隨機測資跟它比對過的。

解法二

暴力改良：固定起點，撞到重複就停

用上面那個洞察的第一半：對每個起點 i， 往右延伸到第一次重複就 break。

class Solution: def lengthOfLongestSubstring(self, s: str) -> int: n = len(s) best = 0 for i in range(n): seen = set() for j in range(i, n): if s[j] in seen: break # 撞到重複，這個起點到此為止 seen.add(s[j]) best = max(best, len(seen)) return best

少了字串切片與重複檢查，從 O(n³) 降到 O(n²)。

複雜度說明
時間O(n²)最壞情況（全部字元都不同）每個起點都走到底
空間O(min(n, k))set 最多裝滿一個視窗

還是不夠。問題在於：起點從 i 換到 i+1 時， seen 被整個丟掉重建，前面掃過的工作全部作廢。 下一個解法就是要把這些工作保留下來。

解法三

滑動視窗 + 集合

不要每次都重建視窗。改成：

  • 右邊界 right 一路往右，每次把新字元加進視窗
  • 如果新字元已經在視窗裡，從左邊一個一個踢掉，直到重複消失
  • 過程中記錄看過的最大視窗長度
class Solution: def lengthOfLongestSubstring(self, s: str) -> int: window = set() left = 0 best = 0 for right, ch in enumerate(s): while ch in window: # 有重複就從左邊縮 window.remove(s[left]) left += 1 window.add(ch) best = max(best, right - left + 1) return best

為什麼有 while 迴圈還是 O(n)？

乍看之下「for 裡面包 while」像是 O(n²)，但關鍵在於： left 只會往右移，整個過程中最多移動 n 次。

所以 right 走 n 步、left 總共走 n 步， 合計最多 2n 次操作 → O(n)。

這叫攤還分析（amortized analysis）： 不看單次迴圈最壞會跑幾次，而看整體總共跑幾次。 這是所有雙指標／滑動視窗解法共通的論證方式。

複雜度說明
時間O(n)最多 2n 次操作（right 走 n、left 走 n）
空間O(min(n, k))視窗最大就是字元集大小 k

已經是 O(n) 了，但還可以更好。 注意 "abcdefga" 這種情況：撞到重複的 'a' 時， left 要一格一格從 0 移到 1，中間踢掉了 b,c,d,e,f,g—— 但我們其實一眼就知道 left 該跳到哪裡。

解法四 · 最佳解

滑動視窗 + 最後出現位置（直接跳）

把 set 換成 dict，記住每個字元最後出現的索引。 撞到重複時，left 直接跳到「那個重複字元的下一格」，不用一格一格縮。

class Solution: def lengthOfLongestSubstring(self, s: str) -> int: last = {} # 字元 -> 它最後一次出現的索引 left = 0 # 目前視窗的左邊界 best = 0 for right, ch in enumerate(s): if ch in last and last[ch] >= left: left = last[ch] + 1 # 直接跳，不用一格一格縮 last[ch] = right # 更新最後出現位置 best = max(best, right - left + 1) return best

last[ch] >= left 這個條件不能省

這是這題最容易寫錯的一行。如果寫成：

if ch in last: # ✘ 少了 >= left 的檢查 left = last[ch] + 1

那麼遇到 s = "abba" 就會出錯：

s = "abba" right=0 'a'：last={a:0}, left=0, best=1 right=1 'b'：last={a:0,b:1}, left=0, best=2 right=2 'b'：'b' 在 last，last[b]=1 >= left=0 → left=2 last={a:0,b:2}, best=2 right=3 'a'：'a' 在 last，last[a]=0 ✘ 錯誤版：left = 0+1 = 1 ← left 往左倒退了！ 視窗變成 s[1..3] = "bba"，長度 3 —— 但裡面有兩個 b ✔ 正確版：last[a]=0 < left=2，條件不成立，left 保持 2 視窗是 s[2..3] = "ba"，長度 2 ✔ 錯誤版輸出 3，正確答案是 2。

根本原因：last 裡存的是「整個字串中最後出現的位置」， 但那個位置可能已經在目前視窗的左邊了。 視窗外面的重複不算重複，所以必須用 last[ch] >= left 確認「這次重複確實發生在視窗內」。

另一組會現形的測資是 "tmmzuxt"： 正確答案 5（"mzuxt"），錯誤版會給 6。

為什麼「直接跳」是對的

當我們在位置 right 遇到重複的字元 ch， 而它上一次出現在 p = last[ch]（且 p >= left）：

  • 任何左邊界 ≤ p 的視窗，都同時包含 s[p] 和 s[right]，一定有重複 → 全部可以跳過
  • 所以最小的合法左邊界就是 p + 1

這就是解法三「一格一格縮」與解法四「一步到位」的差別： 前者不知道要縮多少所以逐格試，後者用 dict 記住的資訊算出答案。

複雜度說明
時間O(n)單趟掃描，每個字元只處理一次
空間O(min(n, k))k 是字元集大小
解法五

用固定陣列取代字典

題目說字元是「英文字母、數字、符號、空白」——都在 ASCII 範圍內。 所以可以用一個長度 128 的陣列取代 dict。

class Solution: def lengthOfLongestSubstring(self, s: str) -> int: last = [-1] * 128 # ASCII 碼 -> 最後出現的索引，-1 表示沒出現過 left = 0 best = 0 for right, ch in enumerate(s): c = ord(ch) if last[c] >= left: # -1 永遠 < left(≥0)，所以不必額外檢查存在性 left = last[c] + 1 last[c] = right best = max(best, right - left + 1) return best

用 -1 當「沒出現過」的哨兵值， 把 ch in last 的檢查也一併省掉了—— 因為 -1 >= left 在 left ≥ 0 時永遠是假。

但在 Python 裡，這個優化不一定划算

在 C++／Java 中，陣列索引比雜湊查找快很多，這是明確的優化。 在 Python 裡：

  • dict 的實作本身已經高度優化，對短字串鍵很快
  • 多了一次 ord(ch) 的函式呼叫，而 Python 的函式呼叫很貴
  • 實測兩者差距很小，有時陣列版甚至更慢

而且它犧牲了通用性：如果輸入含有非 ASCII 字元 （中文、emoji），ord(ch) 會超出 128 直接 IndexError。 這題保證 ASCII，但這個假設值得寫在註解裡。

建議：面試時寫解法四（dict 版），並口頭提到可以用陣列優化。 這樣既展示了你知道這個技巧，也展示了你知道它的取捨。

k 是字元集大小。因為視窗裡不能有重複字元， 視窗長度不會超過 k，所以空間是 O(min(n, k))—— 在 ASCII 下就是 O(1) 的常數空間。

滑動視窗的通用範本

這題是滑動視窗最經典的入門題。把它抽象出來，範本長這樣：

def sliding_window(s): window = {} # 視窗內的狀態（計數、集合、最後位置…） left = 0 answer = 初始值 for right in range(len(s)): 把 s[right] 加入 window # 擴張 while 視窗不合法: # 收縮（可能一次、可能多次、可能零次） 把 s[left] 移出 window left += 1 answer = 用 [left, right] 更新答案 # 記錄 return answer

常見追問

如果要回傳子字串本身，不只是長度呢？

多記一個起點就好：

best, start = 0, 0 for right, ch in enumerate(s): if ch in last and last[ch] >= left: left = last[ch] + 1 last[ch] = right if right - left + 1 > best: best = right - left + 1 start = left # 只在破紀錄時更新起點 return s[start:start + best]

注意 start 只在破紀錄時更新， 不能每輪都更新，否則會記到最後一個視窗而不是最長的那個。

如果允許最多 k 個重複字元呢？

那就是 340. Longest Substring with At Most K Distinct Characters 那一類。視窗狀態改成 Counter， 「不合法」的定義改成 len(counter) > k，範本其餘完全一樣。

為什麼 best = max(best, ...) 放在迴圈最後？

因為必須先把視窗調整到合法，才能用它的長度更新答案。 放在前面會把「還含有重複字元」的視窗長度算進去。
