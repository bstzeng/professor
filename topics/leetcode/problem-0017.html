LeetCode 17

Letter Combinations of a Phone Number
電話號碼的字母組合

Medium · 中等 雜湊表 字串 回溯

Problem

Given a string containing digits from 2-9 inclusive, return all possible letter combinations that the number could represent. Return the answer in any order.

A mapping of digits to letters (just like on the telephone buttons) is given below. Note that 1 does not map to any letters.

中文翻譯

給你一個只含數字 2–9 的字串，回傳它在電話按鍵上所有可能的字母組合。答案順序不拘。

對應關係就是老式手機鍵盤：2→abc、3→def、4→ghi、5→jkl、6→mno、7→pqrs、8→tuv、9→wxyz。注意 1 不對應任何字母（所以輸入裡不會出現）。

組合數學：答案有幾個？

digits = "23" -> 3 × 3 = 9 種 digits = "79" -> 4 × 4 = 16 種 digits = "234" -> 3 × 3 × 3 = 27 種 一般公式：所有位數對應字母數的乘積。 最壞情況 digits = "7777"（長度 4，每位 4 個字母）： 4⁴ = 256 種 所以答案的總量是 O(4ⁿ)，n ≤ 4。 這是一道「輸出本身就是指數大」的題目 —— 不可能有比 O(4ⁿ) 更快的演算法，因為光是印出答案就要那麼久。 換句話說：這題不考「怎麼變快」，考的是「怎麼把所有組合有系統地枚舉出來」。

範例

範例 1 輸入：digits = "23" 輸出：["ad","ae","af","bd","be","bf","cd","ce","cf"] 範例 2 輸入：digits = "" 輸出：[] 說明：空輸入回空陣列，不是 [""]。 範例 3 輸入：digits = "2" 輸出：["a","b","c"]

限制條件

  • 0 ≤ digits.length ≤ 4
  • digits[i] 是 '2' 到 '9' 之間的數字

LeetCode 原題

先看懂限制在說什麼

  • 空字串要回 []，不是 [""]。這是本題唯一的陷阱，而且會直接讓你 WA。所有「從空字串開始逐步擴充」的寫法（解法二、三）都必須在最前面擋掉它。
  • 長度最多 4，答案最多 256 個。規模小到不需要任何優化。
  • 輸入保證只有 2–9，不會有 '0'、'1' 或非數字，所以查表時不用擔心 KeyError。

解題思路

三種寫法，對應三種思考方式：深度優先（回溯）、廣度優先（逐層擴充）、數學（笛卡兒積）。三個都值得會 —— 回溯是最通用的，但另外兩個在這題更短更清楚。

解法一

回溯（backtracking）—— 最通用的模板

把它想成一棵樹：第 i 層對應第 i 個數字，每個節點的分支數 = 那個數字有幾個字母。走到葉子就收一條答案。

class Solution: def letterCombinations(self, digits: str) -> List[str]: if not digits: return [] # 空輸入回空 list，不是 [""] PAD = {"2": "abc", "3": "def", "4": "ghi", "5": "jkl", "6": "mno", "7": "pqrs", "8": "tuv", "9": "wxyz"} out = [] path = [] # 目前已經選到的字母 def backtrack(i: int) -> None: if i == len(digits): out.append("".join(path)) return for ch in PAD[digits[i]]: path.append(ch) # 選 backtrack(i + 1) # 往下一位 path.pop() # 取消選擇（回溯） backtrack(0) return out

回溯的三步驟模板

for 每個選擇: 做選擇 path.append(ch) 往下遞迴 backtrack(i + 1) 撤銷選擇 path.pop() <- 這一行是「回溯」這個名字的由來 為什麼要撤銷？ 因為 path 是共用的一份。走完 'a' 那條分支回來之後， path 裡還留著 'a'，如果不 pop 掉，接下來走 'b' 分支 就會變成 "ab..." 而不是 "b..."。 替代寫法：把 path 當成不可變的參數傳下去 def backtrack(i, path): ... backtrack(i + 1, path + ch) # 每層都建新字串，不用 pop 這樣不用手動 pop，但每層都複製一次字串。 在這題（長度 ≤ 4）完全無所謂， 但在深度大的題目上，append/pop 的版本會明顯省記憶體。

為什麼一定要學這個模板？

因為它是第 22、39、40、46、47、51、77、78、79、90、93 題的共同骨架。這題是最單純的版本（沒有剪枝、沒有去重、沒有狀態），最適合拿來把模板刻進肌肉記憶。

複雜度說明
時間O(4ⁿ · n)最多 4ⁿ 條路徑，每條組字串 O(n)
空間O(n)遞迴深度 n；不算輸出
解法二

逐層擴充（BFS / 迭代）

不用遞迴。維護一個「目前所有半成品」的清單，每處理一個數字就把每個半成品都擴充一輪。

digits = "23" 初始： [""] 處理 '2'： ["a", "b", "c"] 處理 '3'： ["ad","ae","af", "bd","be","bf", "cd","ce","cf"] 每一輪清單長度乘以「該數字的字母數」。
class Solution: def letterCombinations(self, digits: str) -> List[str]: if not digits: return [] PAD = {"2": "abc", "3": "def", "4": "ghi", "5": "jkl", "6": "mno", "7": "pqrs", "8": "tuv", "9": "wxyz"} out = [""] # 從一個空字串開始 for d in digits: out = [prefix + ch for prefix in out for ch in PAD[d]] return out

整個核心只有一行 list comprehension。out = [prefix + ch for prefix in out for ch in PAD[d]] 的兩個 for 順序不能顛倒 —— 外層是舊清單，內層是新字母。

為什麼初值是 [""] 而不是 []？因為 [] 的話第一輪的 list comprehension 產生不出任何東西，結果永遠是空的。空字串是這個「連接」運算的單位元，就像求和從 0 開始、求積從 1 開始一樣。但這也正是為什麼空輸入必須在最前面擋掉 —— 否則會回傳 [""]。

複雜度說明
時間O(4ⁿ · n)同上
空間O(4ⁿ · n)中間結果全部存在清單裡
解法三

itertools.product（Python 專用）

認出這題的本質：它就是一個笛卡兒積。

from itertools import product class Solution: def letterCombinations(self, digits: str) -> List[str]: if not digits: return [] PAD = {"2": "abc", "3": "def", "4": "ghi", "5": "jkl", "6": "mno", "7": "pqrs", "8": "tuv", "9": "wxyz"} # 笛卡兒積：product("abc", "def") -> ('a','d'), ('a','e'), ... return ["".join(t) for t in product(*(PAD[d] for d in digits))]
product("abc", "def") 產生： ('a','d') ('a','e') ('a','f') ('b','d') ('b','e') ('b','f') ('c','d') ('c','e') ('c','f') product(*(PAD[d] for d in digits)) 就是把每個數字的字母集合 當成一個維度，展開所有組合。 順序也剛好符合題目範例（最後一個維度變化最快）。

面試時可以寫，但要先講出解法一。面試官問這題通常是想看回溯模板；直接 product 秒殺會讓他沒東西可以評。正確的順序是：先寫回溯、跑通、講清楚，再補一句「Python 裡其實 itertools.product 一行就好」。

複雜度說明
時間O(4ⁿ · n)同上
空間O(4ⁿ · n)product 是惰性的，但 list comprehension 會全部展開

邊界條件檢查清單

  • 空字串 → []。不是 [""]。所有解法都要在最前面擋。
  • 單一數字："2" → ["a","b","c"]。
  • 4 個字母的按鍵："7" → ["p","q","r","s"]；"9" → ["w","x","y","z"]。這兩個最容易在打表時打錯。
  • 最長輸入："7777" → 256 個答案。
  • 重複的數字："22" → 9 個答案（aa, ab, ac, ba, ...）。數字重複不代表答案重複，這題不需要去重。

常見追問

追問一：如果要求答案必須是字典序呢？

如果 PAD 裡每個字串本身就是字典序（"abc"、"pqrs"），那回溯和 product 產生的順序天生就是字典序 —— 什麼都不用做。因為回溯是深度優先，先固定高位再變低位，這正是字典序的定義。

追問二：如果要求只回傳「是英文單字」的組合呢？

這就是加剪枝的時機。把字典建成一棵 Trie，回溯時每走一步就檢查「目前的 prefix 在 Trie 裡還有路嗎」，沒有就立刻剪掉整棵子樹。這正是 T9 輸入法的原理，也是第 212 題（Word Search II）的核心技巧。

追問三：如果數字很長（例如 20 位），要怎麼辦？

沒辦法。答案數量是 4²⁰ ≈ 10¹²，光是印出來就不可能。這時候問題一定要改：改成「回傳第 k 個組合」（可以用進位制直接算，類似第 60 題 Permutation Sequence），或「回傳前 100 個」（用產生器惰性求值）。當輸出是指數大的時候，正確的回應是質疑問題本身，而不是優化演算法。
