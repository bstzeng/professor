LeetCode 125

Valid Palindrome
驗證回文串

Easy · 簡單 雙指標 字串

Problem

A phrase is a palindrome if, after converting all uppercase letters into lowercase letters and removing all non-alphanumeric characters, it reads the same forward and backward. Alphanumeric characters include letters and numbers.

Given a string s, return true if it is a palindrome, or false otherwise.

中文翻譯

把一個字串裡的大寫全部轉成小寫、並刪掉所有非英數字元之後，如果正著讀和反著讀一樣，它就是回文。

（英數字元指的是英文字母和數字。）

給你一個字串 s，判斷它是不是回文。

三個容易忽略的細節

1. 【空字串算回文】 s = " " -> 過濾後變成 "" -> 是回文 -> True ✔ 題目的範例 2 就是這個。 2. 【數字也算「英數字元」】 s = "0P" -> 過濾後是 "0p" -> 不是回文 -> False 如果你只保留字母（漏掉數字）， "0P" 會變成 "p" -> 誤判成 True ✘ 這是 LeetCode 這題的著名陷阱測資。 3. 【底線 _ 不是英數字元】 Python 的 str.isalnum() 對 "_" 回傳 False ✔ 但如果你用正規表達式 \w，那會【包含底線】✘ \w = [a-zA-Z0-9_] ← 含底線 正確的應該是 [a-zA-Z0-9] s = "ab_a" -> 正確答案是 True（過濾後 "aba"） 用 \w 會得到 "ab_a" -> False ✘ 【這三個細節，各自都能讓一份「看起來對」的程式碼掛掉。】

範例

範例 1 輸入：s = "A man, a plan, a canal: Panama" 輸出：true 說明：過濾後是 "amanaplanacanalpanama"，正反相同。 範例 2 輸入：s = "race a car" 輸出：false 說明：過濾後是 "raceacar"，反過來是 "racaecar"，不同。 範例 3 輸入：s = " " 輸出：true 說明：過濾後是空字串 ""，空字串是回文。

限制條件

  • 1 ≤ s.length ≤ 2 × 10⁵
  • s 只包含可列印的 ASCII 字元

LeetCode 原題

解題思路

兩條路： 【A. 先過濾再比較】（解法二、三） t = 只留英數字元、全轉小寫 return t == t[::-1] 兩行，最好懂。 但要花 O(n) 額外空間存過濾後的字串。 【B. 雙指標原地比較】（解法一） i 從左邊、j 從右邊往中間走， 各自跳過非英數字元，然後比較。 O(1) 額外空間 ✔ 這是面試官想聽到的答案 —— 因為它展示你會處理「跳過不要的東西」這個模式。 【雙指標的三個細節】： 1. 內層跳過迴圈也要寫 i < j 否則全是標點的字串（例如 ".,"）會越界。 2. 比較時記得 .lower() （或者 .upper()，但兩邊要一致） 3. 比較完之後 i += 1, j -= 1 不能忘 否則無窮迴圈。
解法一

雙指標（O(1) 空間，標準答案）

class Solution: def isPalindrome(self, s: str) -> bool: i, j = 0, len(s) - 1 while i < j: while i < j and not s[i].isalnum(): i += 1 # 左邊跳過非英數字元 while i < j and not s[j].isalnum(): j -= 1 # 右邊跳過非英數字元 if s[i].lower() != s[j].lower(): return False i += 1 j -= 1 return True

★ 內層迴圈為什麼也要寫 i < j？

while i < j and not s[i].isalnum(): ^^^^^^^ 考慮 s = ".,"（全是標點）： 不寫 i < j 的話： i 會一路右移，跳過 '.'、','， 然後 i = 2 -> s[2] 索引越界 ✘ 寫了 i < j： i 移到 1 時 i < j 不成立（j 也是 1）-> 停 ✔ 外層 while i < j 也不成立 -> 回 True ✔ 【「內層迴圈也要檢查邊界」是雙指標題的通用陷阱】—— 只在外層檢查是不夠的， 因為內層可能把指標推過頭。 第 26、27、80、283 題（原地刪除） 也都有同樣的注意事項。

isalnum() 的 Unicode 行為

Python 的 str.isalnum() 是【Unicode 感知】的： "ａ".isalnum() -> True （全形 a） "三".isalnum() -> True （中文數字） "½".isalnum() -> True （分數符號） "_".isalnum() -> False ✔ 本題保證只有 ASCII，所以沒差。 但如果輸入可能有 Unicode， 「英數字元」的定義就要講清楚 —— isalnum() 可能比你想的寬鬆很多。 嚴格只要 ASCII 的話： c.isascii() and c.isalnum() 【這種「函式的行為比你以為的寬」的情況， 在字串處理裡非常常見。 用之前先想想：它對邊界輸入會怎麼反應？】

時間 O(n)、空間 O(1)。每個字元最多被 i 或 j 訪問一次。

複雜度說明
時間O(n)兩個指標各走一遍
空間O(1)沒有額外空間
解法二

先過濾再比較（最短）

class Solution: def isPalindrome(self, s: str) -> bool: # 先過濾再比較：最短，但用了 O(n) 額外空間 t = [c.lower() for c in s if c.isalnum()] return t == t[::-1]

兩行。t == t[::-1] 是 Python 判斷回文最直接的寫法。

時間 O(n)、空間 O(n)。 【面試時可以寫，但要主動說】： 「這用了 O(n) 額外空間，如果要 O(1) 我會用雙指標。」 然後寫解法一。 【為什麼用 list 而不是字串相加？】 t = "" for c in s: if c.isalnum(): t += c.lower() ✘ 每次都建立新字串 -> O(n²) Python 的字串是不可變的， 所以 += 會複製整個字串。 正確的做法是 list 生成式 + "".join()， 或者像本文一樣直接比較 list（list 也支援 [::-1] 和 ==）。 【「迴圈裡用 += 拼字串」是 Python 最常見的效能陷阱之一。】
複雜度說明
時間O(n)過濾 + 反轉
空間O(n)過濾後的副本
解法三

正規表達式（★ 注意 \w 的陷阱）

import re class Solution: def isPalindrome(self, s: str) -> bool: t = re.sub(r'[^a-z0-9]', '', s.lower()) return t == t[::-1]

★ 為什麼不能用 \w？

re.sub(r'[^a-z0-9]', '', s.lower()) ✔ 正確 re.sub(r'\W', '', s.lower()) ✘ 會保留底線！ \w 的定義是 [a-zA-Z0-9_] —— 【包含底線】。 \W 是它的補集，所以 \W 不會刪掉底線。 s = "ab_a" 正確答案：過濾成 "aba" -> True 用 \W： 過濾成 "ab_a" -> False ✘ 【而且 Python 3 的 \w 預設是 Unicode 模式】： 中文、日文、重音字母都算 \w。 要限定 ASCII 要加 re.ASCII 旗標： re.sub(r'\W', '', s, flags=re.ASCII) ——但那還是會留下底線。 【結論：這題老老實實寫 [^a-z0-9] 最安全。】 正規表達式很方便， 但它的「簡寫類別」（\w \d \s）的確切定義 在不同語言、不同旗標下都不一樣。 【在乎正確性的地方，寫出完整的字元類別。】

先 lower() 再過濾，所以只要寫 [^a-z0-9]（不用寫 A-Z）。順序反過來就要寫 [^a-zA-Z0-9]。

複雜度說明
時間O(n)正規替換 + 反轉
空間O(n)過濾後的副本

邊界條件檢查清單

  • " "（一個空格）→ True（過濾後是空字串）。
  • ".,"（全是標點）→ True。雙指標版的內層迴圈沒檢查 i < j 會索引越界。
  • "0P" → False。只保留字母（漏掉數字）會誤判成 True —— 著名陷阱測資。
  • "ab_a" → True。用 \w 會誤判成 False。
  • "a." → True。
  • 單一字元 → 永遠是 True。
  • 忘了 .lower() → "Aa" 會誤判成 False。
  • 忘了 i += 1; j -= 1 → 無窮迴圈。
  • 用 t += c 拼字串 → 2×10⁵ 時 O(n²)，會逾時。

常見追問

追問一：如果允許刪掉「最多一個字元」呢？

第 680 題（驗證回文 II）。雙指標碰到不相等時，試「跳過左邊」和「跳過右邊」兩種，只要其中一種能走完就算過。

def validPalindrome(s): def ok(i, j): while i < j: if s[i] != s[j]: return False i += 1; j -= 1 return True i, j = 0, len(s) - 1 while i < j: if s[i] != s[j]: return ok(i+1, j) or ok(i, j-1) # 只有這一次機會 i += 1; j -= 1 return True 【為什麼只要在「第一次不匹配」時分岔就夠？】 因為在那之前的所有配對都是相等的 —— 刪掉它們之中的任何一個，只會破壞已經對好的部分。 所以最優的刪除位置一定在「第一次衝突」的那兩個之中。 這是一個很漂亮的貪心論證。

追問二：如果要「最少插入幾個字元才能變成回文」呢？

第 1312 題。答案 = n - LPS(s)，其中 LPS 是最長回文子序列（第 516 題）。

而 LPS(s) = LCS(s, reverse(s)) —— 又回到第 1143 題（最長公共子序列）的二維 DP。「回文」和「和自己的反轉做 LCS」是一組很有用的等價。

追問三：isalnum() 在其他語言裡一樣嗎？

C 的 isalnum()：只看 ASCII（而且受 locale 影響） Java 的 Character.isLetterOrDigit()：Unicode 感知 JavaScript：沒有內建，通常用 /[a-z0-9]/i 或 \p{L}\p{N} Python 的 str.isalnum()：Unicode 感知 【所以「英數字元」這個概念在跨語言時完全不可移植。】 面試時如果用了 isalnum()， 主動說一句「這在 Python 裡是 Unicode 感知的， 本題只有 ASCII 所以沒差」—— 會顯示你知道自己在用什麼。

追問四：2×10⁵ 的字串，三種解法實測差多少？

通常解法二（過濾後比較）反而最快 —— 因為 [::-1] 和 == 都是 C 層實作，而雙指標的 Python 迴圈每一步都有直譯器開銷。

這是「理論複雜度相同時，常數因子由實作語言決定」的典型例子。但面試要的是 O(1) 空間的那個 —— 因為那才是他們在考的東西。
