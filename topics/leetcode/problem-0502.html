LeetCode 502

IPO
IPO

Hard · 困難 貪心 陣列 排序 堆積（優先佇列）

Problem

Suppose LeetCode will start its IPO soon. In order to sell a good price of its shares to Venture Capital, LeetCode would like to work on some projects to increase its capital before the IPO. Since it has limited resources, it can only finish at most k distinct projects before the IPO. Help LeetCode design the best way to maximize its total capital after finishing at most k distinct projects.

You are given n projects where the ith project has a pure profit profits[i] and a minimum capital of capital[i] is needed to start it.

Initially, you have w capital. When you finish a project, you will obtain its pure profit and the profit will be added to your total capital.

Pick a list of at most k distinct projects from given projects to maximize your final capital, and return the final maximized capital.

The answer is guaranteed to fit in a 32-bit signed integer.

中文翻譯

公司想在 IPO 前最多完成 k 個不同的專案。第 i 個專案需要資本至少 capital[i] 才能開始，完成後得到純利潤 profits[i]（加進資本，不會扣掉門檻）。

一開始資本是 w。選擇最多 k 個專案，回傳最後能得到的最大資本。

範例

範例 1 輸入：k = 2, w = 0, profits = [1,2,3], capital = [0,1,1] 輸出：4 範例 2 輸入：k = 3, w = 0, profits = [1,2,3], capital = [0,1,2] 輸出：6

限制條件

  • 1 ≤ k ≤ 10⁵
  • 0 ≤ w ≤ 10⁹
  • n == profits.length
  • n == capital.length
  • 1 ≤ n ≤ 10⁵
  • 0 ≤ profits[i] ≤ 10⁴
  • 0 ≤ capital[i] ≤ 10⁹

LeetCode 原題

解題思路

【關鍵觀察：資本只增不減】 做任何專案都不會花掉資本（只要達到門檻），利潤 >= 0。 所以「做得起的專案集合」只會越來越大。 【貪心】 每一輪：在目前做得起的專案中，挑利潤最大的。 為什麼對？做了利潤最大的，資本最高， 之後做得起的集合也最大 —— 不會比其他選擇差。 【資料結構】 專案依門檻排序，用指標 i 把「門檻 <= w」的專案陸續放進最大堆積； 每輪從堆積拿最大利潤。 每個專案最多進出堆積一次。
解法

排序 + 最大堆積的貪心

class Solution: def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int: projects = sorted(zip(capital, profits)) # 依門檻（所需資本）排序 heap = [] # 目前「做得起」的專案利潤（最大堆積） i = 0 for _ in range(k): while i < len(projects) and projects[i][0] <= w: heapq.heappush(heap, -projects[i][1]) # 門檻達到了，放進候選 i += 1 if not heap: break # 一個都做不起，提早結束 w += -heapq.heappop(heap) # ★ 貪心：做得起的裡面挑利潤最大的 return w

驗證方式：和窮舉所有選擇順序的暴力法比對 1500 組隨機資料。

複雜度說明
時間O(n log n + k log n)
空間O(n)

邊界條件檢查清單

  • 沒有做得起的專案 → 提早結束，回傳目前資本。
  • k 大於專案數 → 堆積空了就停。
  • 利潤為 0 的專案 → 做了也不影響，不需特別處理。

常見追問

兩個堆積的寫法

也可以把專案依門檻放進最小堆積，每輪把門檻 <= w 的移到利潤最大堆積。和排序 + 指標是同一件事。
