LeetCode 65

Valid Number
有效數字

Hard · 困難 字串

Problem

A valid number can be split up into these components (in order):

(1) A decimal number or an integer. (2) (Optional) An 'e' or 'E', followed by an integer.

A decimal number can be split up into: (optional) sign, then one of: digits followed by a dot; digits followed by a dot followed by digits; or a dot followed by digits. An integer is: (optional) sign, then digits.

Given a string s, return true if s is a valid number.

中文翻譯

一個有效數字由以下兩部分組成（依序）：

（1）一個小數或整數；（2）（可選）一個 'e' 或 'E'，後面接一個整數。

小數＝（可選的）正負號 + 下列之一：數字.、數字.數字、.數字。整數＝（可選的）正負號 + 數字。

給你一個字串 s，判斷它是不是有效數字。

先把規則攤平成一張表

合法的例子： "2" 整數 "0089" 前導零沒關係 "-0.1" 小數 "+3.14" "4." 小數點後面可以沒有數字 ✔ "-.9" 小數點前面可以沒有數字 ✔ "2e10" 科學記號 "-90E3" 大寫 E 也可以 "3e+7" 指數可以有正負號 "53.5e93" "46.e3" "46." 是合法小數，後面接 e3 ✔ 不合法的例子： "abc" 不是數字 "1a" 有雜訊 "1e" e 後面必須有數字 "e3" e 前面必須有數字 "99e2.5" 指數必須是「整數」，不能有小數點 "--6" 正負號最多一個 "-+3" "95a54e53" "." 光一個小數點不算數字 "+" 光一個正負號不算 "" 空字串不算 "4e+" e 和正負號之後還是要有數字 四條核心規則： 1. 正負號只能在「開頭」或「e/E 的正後面」 2. 小數點最多一個，而且不能在 e/E 之後 3. e/E 最多一個，而且「前面」和「後面」都必須有數字 4. 整個字串必須以數字收場（不能停在 . + - e 上） —— 但 "4." 是合法的！所以規則 4 要小心。

「4.」合法但「.」不合法 —— 這一組對照抓出了大部分錯誤的實作。關鍵在於：小數點兩邊至少要有一邊有數字。

範例

範例 1 輸入：s = "0" 輸出：true 範例 2 輸入：s = "e" 輸出：false 範例 3 輸入：s = "." 輸出：false 範例 4 輸入：s = "4." 輸出：true

限制條件

  • 1 ≤ s.length ≤ 20
  • s 由英文字母（大小寫）、數字、'+'、'-'、'.' 組成

LeetCode 原題

先看懂限制在說什麼

  • 字元集包含所有英文字母，不只是 e 和 E。所以 "1a"、"abc"、"Infinity" 都是測資，要有一個 else: return False 兜底。
  • 長度只有 20，效率完全不是問題。這題百分之百考規格的精確翻譯。
  • 不需要處理 "Infinity"、"NaN"、十六進位、底線分隔符（Python 的 float() 接受其中幾種）—— 所以不能用 try: float(s) 作弊，float("inf") 和 float("nan") 都會成功但答案應該是 false。

解題思路

三種寫法：逐字元 + 三個旗標（最好寫）、正規表示式（最短）、明確的狀態機（最能擴充）。

解法一

逐字元掃描 + 三個旗標（最推薦）

class Solution: def isNumber(self, s: str) -> bool: seen_digit = False # 看過數字了嗎 seen_dot = False # 看過小數點了嗎 seen_exp = False # 看過 e/E 了嗎 for i, ch in enumerate(s): if ch.isdigit(): seen_digit = True elif ch in "+-": # 正負號只能出現在「最開頭」或「e/E 的正後面」 if i > 0 and s[i - 1] not in "eE": return False elif ch == ".": # 小數點不能重複，也不能出現在 e/E 之後（指數必須是整數） if seen_dot or seen_exp: return False seen_dot = True elif ch in "eE": # e/E 不能重複，而且前面「必須」已經有數字 if seen_exp or not seen_digit: return False seen_exp = True seen_digit = False # 重設：e 後面也「必須」有數字 else: return False # 其他字元一律不合法 return seen_digit # 結尾必須以數字收場

四個分支，逐一對照規則

數字： seen_digit = True 沒有任何限制，數字永遠可以出現。 正負號： 只能在 i == 0 或 s[i-1] in "eE" "-1.5" i=0 ✔ "1e-5" s[1]='e' ✔ "1-5" s[0]='1' ✘ "--6" i=1，s[0]='-' ✘ 小數點： 不能重複，也不能在 e 之後 "1.2.3" 第二個點 -> seen_dot 已經是 True ✘ "1e2.5" seen_exp 已經是 True ✘（指數必須是整數） e/E： 不能重複，而且前面必須有數字 "e3" seen_digit 還是 False ✘ "1e2e3" seen_exp 已經是 True ✘ "1e5" ✔

最精妙的一行：seen_digit = False

elif ch in "eE": if seen_exp or not seen_digit: return False seen_exp = True seen_digit = False <- 這一行 為什麼要把 seen_digit 重設成 False？ 因為 e 之後「也必須」有數字。 把旗標歸零，等於說「從現在開始重新要求至少一個數字」。 然後最後一行 return seen_digit 就同時檢查了兩件事： - 沒有 e 的情況：整個字串至少有一個數字 - 有 e 的情況： e 之後至少有一個數字 "1e" -> e 之後沒數字 -> seen_digit 是 False -> False ✔ "1e5" -> e 之後有 5 -> seen_digit 是 True -> True ✔ "4." -> 有數字 4 -> True ✔ "." -> 從來沒有數字 -> False ✔ 一個變數的重複利用，同時處理了兩個「必須有數字」的要求。 這是這個解法最漂亮的地方。

只有 20 行，而且每一行都直接對應規格的一條規則 —— 這讓它很容易驗證，也很容易在面試時逐條講解。

複雜度說明
時間O(n)掃一遍
空間O(1)三個 bool
解法二

正規表示式（最短）

import re class Solution: def isNumber(self, s: str) -> bool: # 整數或小數，後面可接一個「e/E + 整數」 pattern = r"[+-]?(\d+\.?\d*|\.\d+)([eE][+-]?\d+)?" return re.fullmatch(pattern, s) is not None

pattern 逐段拆解

r"[+-]?(\d+\.?\d*|\.\d+)([eE][+-]?\d+)?" [+-]? 可選的正負號 ( 小數或整數，兩種形式擇一 \d+\.?\d* 一個以上的數字，然後可選的小數點，然後 0 個以上的數字 -> 涵蓋 "123"、"123."、"123.456" | \.\d+ 小數點 + 一個以上的數字 -> 涵蓋 ".456" ) ( 可選的指數部分 [eE] [+-]? 指數的可選正負號 \d+ 指數必須是「一個以上的數字」（不能有小數點） )? 必須用 re.fullmatch（不是 match 或 search）—— 否則 "1a" 會匹配前面的 "1" 而回傳 True ✘

為什麼要拆成兩個分支？

如果寫成 \d*\.?\d*（兩邊都用 *）， 那 "." 和 "" 都會匹配成功 ✘ 必須保證「小數點的至少一邊有數字」： \d+\.?\d* 左邊一定有數字 \.\d+ 右邊一定有數字 兩者的聯集剛好涵蓋所有合法的小數和整數， 而且排除了 "." 和 ""。 這一行就是整個 pattern 最需要想清楚的地方。

面試時可以寫，但要能逐段解釋。而且要主動說「如果不准用 regex，我會用逐字元掃描」—— 因為 regex 版本無法展示你對規格的拆解能力。

複雜度說明
時間O(n)regex 引擎掃一遍
空間O(n)編譯後的 pattern
解法三

明確的有限狀態機（最能擴充）

把狀態機畫出來，寫成一張轉移表。

class Solution: def isNumber(self, s: str) -> bool: # 明確的有限狀態機：state -> {字元類別: 下一個 state} # 字元類別：d=數字, s=正負號, .=小數點, e=指數符號 TRANSITIONS = [ {"s": 1, "d": 2, ".": 3}, # 0 起始 {"d": 2, ".": 3}, # 1 吃過正負號 {"d": 2, ".": 4, "e": 5}, # 2 整數部分（可接受狀態） {"d": 4}, # 3 「.」開頭，還沒有數字 {"d": 4, "e": 5}, # 4 小數部分（可接受狀態） {"s": 6, "d": 7}, # 5 剛吃過 e/E {"d": 7}, # 6 指數的正負號 {"d": 7}, # 7 指數數字（可接受狀態） ] ACCEPT = {2, 4, 7} def kind(ch: str) -> str: if ch.isdigit(): return "d" if ch in "+-": return "s" if ch == ".": return "." if ch in "eE": return "e" return "?" state = 0 for ch in s: k = kind(ch) if k not in TRANSITIONS[state]: return False state = TRANSITIONS[state][k] return state in ACCEPT

八個狀態的意義

狀態意義可接受？
0起始，什麼都還沒讀✘
1讀過正負號，等數字或小數點✘
2整數部分（至少一個數字）✔
3只讀到小數點（前面沒數字），等數字✘
4小數部分（小數點兩側至少一邊有數字）✔
5剛讀過 e/E，等指數✘
6指數的正負號，等數字✘
7指數數字✔

為什麼狀態 2 和 4 都可接受，3 不行？

狀態 2：讀完整數，例如 "123" -> 合法 ✔ 狀態 3：只讀到 "."（前面沒數字） -> 還不是數字 ✘ 再讀一個數字就變成狀態 4 -> ".5" ✔ 狀態 4：小數，例如 "123." 或 ".5" -> 合法 ✔ 注意狀態 2 讀到 "." 會去狀態 4（不是 3）： "123." -> 狀態 2 讀 "." -> 狀態 4（可接受）✔ 而狀態 0 或 1 讀到 "." 會去狀態 3： "." -> 狀態 3（不可接受）✘ ".5" -> 狀態 3 讀 "5" -> 狀態 4 ✔ 3 和 4 的差別，精確地編碼了 「小數點至少要有一邊有數字」這條規則。

狀態機的價值

  • 加規則 = 加狀態和轉移，不用在一堆 if 裡找地方插。例如要支援 "0x1F"，只要加幾個狀態。
  • 可以被機器產生和驗證。真正的編譯器的詞法分析器（lexer）就是這樣做的 —— 工具（lex、flex、ANTLR）從正規表示式自動產生狀態轉移表。
  • O(1) 空間，一次掃過，不回頭 —— 串流友善。

缺點：這張表要手動推導，而且推錯很難查。在面試的時間壓力下，解法一通常比較保險。

複雜度說明
時間O(n)掃一遍，每個字元一次查表
空間O(1)固定大小的轉移表

邊界條件檢查清單

  • "4." → true；"." → false。最關鍵的一組對照。
  • ".1"、"+.8" → true。小數點可以開頭。
  • "46.e3" → true。"46." 是合法小數，後面接 e3。
  • "e"、"e3"、"1e"、"4e+" → false。e 的前後都必須有數字。
  • "99e2.5"、"6e6.5" → false。指數必須是整數。
  • "--6"、"-+3"、"+" → false。
  • "1.2.3" → false。小數點只能一個。
  • "0089" → true。前導零是合法的。
  • "abc"、"95a54e53" → false。要有 else 兜底。
  • 不要用 float(s)：float("inf")、float("nan")、float("1_0") 都會成功，但這題應該回 false。

常見追問

追問一：為什麼不能用 try: float(s); return True？

Python 的 float() 接受一些這題不允許的東西： float("inf") -> inf 但題目要 false float("nan") -> nan 但題目要 false float(" 1.5 ") -> 1.5 有空白，題目要 false float("1_000") -> 1000 底線分隔符（3.6+），題目要 false 所以這個「作弊法」會 WA。 更重要的是：這題的用意就是「實作一個 parser」， 用內建函式等於什麼都沒展示。 而且在真實工作裡，你很可能是在寫一個 「和某個規格完全一致」的 parser（例如 JSON、CSV、設定檔）， 那時候內建函式的語意和你的規格幾乎不會完全吻合。

追問二：這題和第 8 題（atoi）的關係？

第 8 題：解析出一個整數，遇到非法就停（不報錯） 第 65 題：判斷整個字串是否合法（要全對） 第 8 題的狀態機只有 4 個狀態， 第 65 題有 8 個 —— 因為多了小數點和指數。 兩題一起看，就能感受到「規格變複雜時， 狀態機的擴充性為什麼比 if-else 好」。 再往上就是 JSON parser、正規表示式引擎、 以及真正的程式語言 lexer —— 狀態數會到數十個。

追問三：真正的浮點數規格有多複雜？

IEEE 754 的十進位字串表示還包括：Infinity、NaN（還分 quiet 和 signaling）、十六進位浮點數（0x1.8p3）、以及各種語言自己加的糖（Python 的底線、C++ 的 ' 分隔符）。「正確地解析一個浮點數」是一個出名地難的問題 —— 要做到「解析出的值是最接近的可表示浮點數」需要任意精度運算（著名的 Ryū 和 Grisu 演算法，以及 David Gay 的 strtod）。這題只是判斷語法，已經比那簡單太多了。
