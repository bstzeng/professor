Add Two Numbers
兩數相加

Medium · 中等 鏈結串列 數學 遞迴

Problem

You are given two non-empty linked lists representing two non-negative integers. The digits are stored in reverse order, and each node contains a single digit.

Add the two numbers and return the sum as a linked list, also in reverse order.

You may assume the two numbers do not contain any leading zero, except the number 0 itself.

中文翻譯

給你兩個非空的鏈結串列，分別代表兩個非負整數。 數字以反序儲存，每個節點存放一位數。

請把這兩個數相加，並同樣以反序的鏈結串列回傳結果。

你可以假設這兩個數除了 0 本身以外，都沒有前導零。

範例

範例 1 輸入：l1 = [2,4,3], l2 = [5,6,4] 輸出：[7,0,8] 說明：342 + 465 = 807 （反序讀：2,4,3 是 342；5,6,4 是 465；7,0,8 是 807） 範例 2 輸入：l1 = [0], l2 = [0] 輸出：[0] 範例 3 輸入：l1 = [9,9,9,9,9,9,9], l2 = [9,9,9,9] 輸出：[8,9,9,9,0,0,0,1] 說明：9999999 + 9999 = 10009998

限制條件

  • 每個串列的節點數在 [1, 100] 之間
  • 0 ≤ Node.val ≤ 9
  • 保證輸入代表的數字沒有前導零（0 本身除外）

LeetCode 原題

「反序」其實是在幫你

第一次看到「數字以反序儲存」會覺得很奇怪，但這是刻意的設計。

回想小學的直式加法：我們從個位數開始加，進位往左傳。 鏈結串列只能從頭往尾走，所以如果把個位數放在頭， 走訪的方向就剛好等於加法的方向。

342 l1: 2 → 4 → 3 （頭是個位） + 465 l2: 5 → 6 → 4 ----- --------------------- 807 結果: 7 → 0 → 8 直式加法從右往左 鏈結串列從頭往尾 ↓ ↓ 個位先算 個位在最前面 ← 方向一致

如果題目改成「正序儲存」（445 題 Add Two Numbers II）， 就必須先反轉串列、或用堆疊、或先算長度——難度會明顯提高。

解題思路

這題本質上就是把小學直式加法寫成程式。 真正要處理好的只有三件事：

  1. 進位（carry）要往下一位傳
  2. 兩個串列不一樣長，短的那個要當成 0 繼續加
  3. 最後可能還有進位（例如 5 + 5 = 10，結果比兩個輸入都長）

下面三種寫法處理的是同一件事，差別在「用什麼結構來組答案」。

解法一 · 最佳解

迭代 + 虛擬頭節點

一邊走兩個串列，一邊把結果節點接在後面。

class Solution: def addTwoNumbers(self, l1: Optional[ListNode], l2: Optional[ListNode]) -> Optional[ListNode]: dummy = ListNode() # 虛擬頭節點：只是個錨點，不放答案 cur = dummy carry = 0 while l1 or l2 or carry: # 三個條件缺一不可 s = carry if l1: s += l1.val l1 = l1.next if l2: s += l2.val l2 = l2.next carry, digit = divmod(s, 10) # 一次拿到進位與本位 cur.next = ListNode(digit) cur = cur.next return dummy.next # 跳過虛擬頭，回傳真正的第一個節點

虛擬頭節點在做什麼

如果不用 dummy，程式會長成這樣：

head = None cur = None while ...: node = ListNode(digit) if head is None: # 第一個節點要特別處理 head = node cur = node else: cur.next = node cur = cur.next

每一次迴圈都要問「這是不是第一個節點」。 虛擬頭節點的價值就是讓「第一個節點」不再是特例—— 它先占住那個位置，迴圈裡一律用 cur.next = ...， 最後回傳 dummy.next 就好。

這個技巧在幾乎所有「要建立新鏈結串列」的題目都用得上， 值得變成反射動作。

逐步追蹤

while l1 or l2 or carry ——三個條件各自防什麼

少了哪一項會在什麼測資出錯錯誤結果
l1 或 l2（改成 and）[1] + [9,9,9]只加到最短的長度就停，得到 [0]
carry[5] + [5]最高位的進位被丟掉，得到 [0] 而不是 [0,1]

divmod(s, 10) 一次回傳 (商, 餘數)， 正好就是 (進位, 本位數字)。 寫成 carry = s // 10 加 digit = s % 10 也完全一樣， divmod 只是少一行。

另外注意 s 最大是 9 + 9 + 1 = 19， 所以 carry 永遠只會是 0 或 1。

複雜度說明
時間O(max(m, n))m、n 是兩串列長度，各走一遍
空間O(max(m, n))結果串列本身；不算輸出的話是 O(1)
解法二

遞迴

同樣的邏輯可以寫成遞迴：把 carry 當成參數往下傳。

class Solution: def addTwoNumbers(self, l1: Optional[ListNode], l2: Optional[ListNode], carry: int = 0) -> Optional[ListNode]: # 終止條件：兩邊都走完，而且沒有剩下的進位 if not l1 and not l2 and not carry: return None s = carry + (l1.val if l1 else 0) + (l2.val if l2 else 0) carry, digit = divmod(s, 10) node = ListNode(digit) node.next = self.addTwoNumbers( l1.next if l1 else None, l2.next if l2 else None, carry, ) return node

這個版本讀起來很乾淨： 「結果 = 這一位的數字 + 剩下的部分相加」， 跟數學上的定義幾乎一樣。而且不需要虛擬頭節點—— 每一層自然回傳自己那一段的頭。

但遞迴有個現實限制

Python 的預設遞迴深度是 1000。 這題的限制是節點數 ≤ 100，所以絕對不會爆—— 最深也只有約 101 層。

但如果同樣的寫法用在節點數 10⁵ 的題目上， 就會直接 RecursionError。 遞迴解在鏈結串列題目上要先看清楚長度限制。

另外遞迴的空間是 O(max(m,n)) 的呼叫堆疊， 這部分是迭代版沒有的額外開銷。

複雜度說明
時間O(max(m, n))與迭代版相同
空間O(max(m, n))呼叫堆疊，比迭代版多
解法三 · 反面教材

轉成整數再相加

很多人的第一個念頭是： 「把串列轉成整數、加起來、再轉回串列不就好了？」

class Solution: def addTwoNumbers(self, l1, l2): def to_int(node): v, place = 0, 1 while node: v += node.val * place place *= 10 node = node.next return v total = to_int(l1) + to_int(l2) dummy = ListNode() cur = dummy while True: # 用 while True 才能正確處理 total == 0 total, d = divmod(total, 10) cur.next = ListNode(d) cur = cur.next if total == 0: break return dummy.next

這段程式碼在 Python 裡是會通過的， 而且在這題的資料範圍下效率也不差。 但它有三個問題，值得想清楚。

問題一：它在別的語言會直接爆掉

節點數上限 100 → 最大是一個 100 位數 Python int：沒有上限，100 位數完全沒問題 Java long：最多 19 位數 → 溢位 C++ long long：最多 19 位數 → 溢位 JavaScript Number：安全整數只到 2⁵³ ≈ 16 位數 → 精度出錯

換句話說，這個解法能過完全是因為 Python 的大整數， 不是因為你解決了題目要考的東西。 面試時寫這個版本，下一句話幾乎一定是 「那如果不能用大整數呢？」

問題二：它繞過了題目真正的考點

這題要考的是鏈結串列的走訪與建構， 以及進位的處理。 轉成整數等於把這兩件事都交給語言內建的加法， 你什麼都沒有練到。

問題三：它無法推廣

如果題目改成「兩個超長串列（10⁵ 個節點）相加」， 大整數乘法／除法的成本會變成瓶頸： place *= 10 在 100000 位數上每一次都是昂貴的大數運算， 整體會退化到遠差於 O(n)。 而解法一仍然是乾淨的 O(n)。

什麼時候「轉成整數」是好答案？

當題目明確保證數值在機器整數範圍內， 而且你要做的是乘法、取模這類在串列上很難直接做的運算時。 這題兩個條件都不成立。

三種解法對照

解法時間額外空間可讀性評價
迭代 + 虛擬頭O(max(m,n))O(1)好標準答案
遞迴O(max(m,n))O(max(m,n)) 堆疊很好可以，但注意深度限制
轉整數O(max(m,n)) 但常數大O(1)好不推薦，理由見上

「額外空間」不算輸出的結果串列—— 那是題目要求的輸出，三種解法都一樣。

邊界條件檢查清單

情況輸入正確輸出容易怎麼錯
兩邊都是 0[0] + [0][0]用 while total: 會回傳空串列
長度不同[1] + [9,9,9][0,0,0,1]迴圈條件用 and
最後有進位[5] + [5][0,1]迴圈條件漏掉 carry
連鎖進位[9,9,9,9,9,9,9] + [9,9,9,9][8,9,9,9,0,0,0,1]進位只傳一位
單節點[5] + [5][0,1]沒有虛擬頭時的第一節點處理

第一列是解法三的經典陷阱：如果寫成

while total: # ✘ total == 0 時一次都不進迴圈 total, d = divmod(total, 10) ...

那麼 0 + 0 會回傳空串列。 必須改成 while True: 加上尾端的 if total == 0: break， 確保至少產生一個節點。

常見追問

如果數字是正序儲存呢？

那就是 445. Add Two Numbers II。 加法必須從尾巴開始，但鏈結串列只能往前走。三種做法：

  • 反轉兩個串列，用本題的解法，再把結果反轉回去。簡單但修改了輸入。
  • 用兩個堆疊把數字推進去，再彈出來相加。不修改輸入，O(n) 空間。
  • 遞迴：先遞迴到底，回程時處理加法與進位。

可以原地修改 l1 來省空間嗎？

可以，把結果寫回比較長的那個串列。但這會破壞輸入， 在實務上通常不可接受，面試時要先問清楚。 而且省下的是「輸出本來就需要」的空間，收益有限。

為什麼不用 Python 的字串反轉來做？

int("".join(str(n.val) for n in walk(l1))[::-1])

可以，但這只是解法三的另一種寫法，前面講的三個問題原封不動。 而且字串轉換比直接算數還慢。
