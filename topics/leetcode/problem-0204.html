LeetCode 204

Count Primes
計數質數

Medium · 中等 陣列 數學 列舉 數論

Problem

Given an integer n, return how many prime numbers are strictly less than n.

中文翻譯

給你一個整數 n，回傳嚴格小於 n 的質數有幾個。

範例

範例 1 輸入：n = 10 輸出：4 說明：小於 10 的質數有 2、3、5、7。 範例 2 輸入：n = 0 輸出：0 範例 3 輸入：n = 1 輸出：0

限制條件

  • 0 ≤ n ≤ 5 × 10⁶

LeetCode 原題

解題思路

【逐一判斷每個數是不是質數】 每個數試除到 √x -> 總共 O(n √n) n = 5×10^6 時大約 10^10 次 ✘ 【換個方向：不要「檢查」，改成「劃掉」】 與其問「x 是不是質數」， 不如從每個質數出發，把它的倍數全部劃掉。 最後沒被劃掉的，就是質數。 這就是【埃拉托斯特尼篩法（Sieve of Eratosthenes）】。 【兩個關鍵優化】 1. 外層只需要到 √n： 大於 √n 的合數 x = a·b，一定有一個因數 ≤ √n， 早就被那個小因數劃掉了。 2. 內層從 p² 開始： p 的倍數 2p, 3p, …, (p-1)p 都有一個比 p 小的因數， 早就被劃掉了。 【複雜度】 劃掉的總次數 ≈ n/2 + n/3 + n/5 + n/7 + … ≈ n · Σ(1/p) ≈ n · ln ln n -> O(n log log n)，幾乎是線性 ✔
解法一

逐一試除（會超時）

class Solution: def countPrimes(self, n: int) -> int: def is_prime(x: int) -> bool: if x < 2: return False d = 2 while d * d <= x: # 試除到 √x if x % d == 0: return False d += 1 return True return sum(is_prime(x) for x in range(n))

每個數最多試除 √x 次，總共大約 n√n。n = 5×10⁶ 時太慢。

複雜度說明
時間O(n√n)
空間O(1)
解法二

埃氏篩（一般迴圈）

class Solution: def countPrimes(self, n: int) -> int: if n < 3: return 0 is_p = [True] * n is_p[0] = is_p[1] = False for i in range(2, int(n ** 0.5) + 1): if is_p[i]: for j in range(i * i, n, i): # 一般迴圈版，比較慢但好懂 is_p[j] = False return sum(is_p)

邏輯完全正確，但在 Python 裡內層的 for 迴圈是瓶頸，n = 5×10⁶ 時可能要好幾秒。

複雜度說明
時間O(n log log n)
空間O(n)一個長度 n 的陣列
解法三

埃氏篩 + 切片賦值（Python 最佳寫法）

class Solution: def countPrimes(self, n: int) -> int: if n < 3: return 0 # 小於 2 的沒有質數；n = 2 也是 0 is_p = bytearray([1]) * n # is_p[i]：i 是不是質數 is_p[0] = is_p[1] = 0 i = 2 while i * i < n: # ★ 只需要篩到 √n if is_p[i]: # ★ 從 i*i 開始劃掉，步長 i（用切片一次寫完） is_p[i * i::i] = bytes(len(range(i * i, n, i))) i += 1 return sum(is_p)
【is_p[i*i::i] = bytes(k) 做了什麼？】 把 is_p 從 i*i 開始、每隔 i 個的位置，全部設成 0。 bytes(k) 是 k 個 0 組成的位元組串。 這一行由 C 實作，一次處理整段 -> 比 Python 迴圈快好幾十倍 ✔ 【為什麼用 bytearray 而不是 list？】 bytearray 每個元素 1 byte， list 每個元素是一個指標（8 bytes）+ 物件。 n = 5×10^6 時，list 大約 40 MB，bytearray 只要 5 MB。 【len(range(i*i, n, i)) 是在算什麼？】 切片 is_p[i*i::i] 的長度， 右邊要給「一樣長」的 bytes，否則會報錯。
複雜度說明
時間O(n log log n)
空間O(n)n bytes

解法對照

解法時間空間n = 5×10⁶ 實測
一、逐一試除O(n√n)O(1)超時 ✘
二、篩法（迴圈）O(n log log n)O(n)數秒，邊緣
三、篩法（切片）O(n log log n)O(n)約 0.1 秒 ✔

邊界條件檢查清單

  • n = 0, 1, 2 → 答案都是 0（「嚴格小於」2 的質數不存在）。
  • n = 3 → 只有 2，答案 1。
  • 「小於 n」而不是「小於等於 n」 → n 本身是質數也不算。
  • 外層條件寫成 i * i <= n → 也對，只是多跑一輪；寫成 i < n 會慢很多。

常見追問

追問一：有沒有 O(n) 的篩法？

【線性篩（歐拉篩）】：讓每個合數只被它的「最小質因數」劃掉一次。 primes = [] is_p = [True] * n for i in range(2, n): if is_p[i]: primes.append(i) for p in primes: if i * p >= n: break is_p[i * p] = False if i % p == 0: break # ★ p 是 i 的最小質因數，停 理論上是 O(n)，但在 Python 裡因為沒辦法用切片， 實際上比「埃氏篩 + 切片」慢。

追問二：如果要回答很多次「小於 n 的質數個數」？

先篩一次到最大的 n，再做前綴和： cnt[i] = 小於等於 i 的質數個數 每次查詢 O(1)。
