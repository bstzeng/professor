LeetCode 61

Rotate List
旋轉串列

Medium · 中等 鏈結串列 雙指標

Problem

Given the head of a linked list, rotate the list to the right by k places.

中文翻譯

給你一個鏈結串列的頭節點 head，把串列向右旋轉 k 格。

「向右旋轉 1 格」的意思是：把最後一個節點搬到最前面。

兩個關鍵：取模，以及接成環

關鍵 1：k 要先對 n 取模 轉 n 次等於沒轉（繞了一圈回到原點）。 題目說 k 可以到 2×10⁹，而串列最多 500 個節點 —— 不取模的話會做幾十億次無謂的旋轉。 k %= n 取模之後 k 一定在 [0, n-1]，最多只轉不到一圈。 關鍵 2：把串列接成環，再在正確的位置剪開 向右轉 k 格 <=> 新的頭是「原本的倒數第 k 個」 <=> 新的尾是「原本的倒數第 k+1 個」 <=> 新的尾是「原本的第 n-k 個」（1-indexed） 1 -> 2 -> 3 -> 4 -> 5，k = 2，n = 5 新頭 = 倒數第 2 個 = 4 新尾 = 倒數第 3 個 = 3 結果 4 -> 5 -> 1 -> 2 -> 3 ✔ 做法：先 tail.next = head 接成環， 再從 head 走 n-k-1 步到新尾， 記下 new_head = new_tail.next， 然後 new_tail.next = None 剪開。

「接成環再剪開」比「找到兩段再拼起來」乾淨 —— 因為接環之後，所有節點的相對位置都還在，只要決定「從哪裡剪」就好。

範例

範例 1 輸入：head = [1,2,3,4,5], k = 2 輸出：[4,5,1,2,3] 說明： 轉 1 次：[5,1,2,3,4] 轉 2 次：[4,5,1,2,3] 範例 2 輸入：head = [0,1,2], k = 4 輸出：[2,0,1] 說明：4 % 3 = 1，等於只轉 1 次。

限制條件

  • 串列節點數在 [0, 500] 範圍內（可以是空的）
  • −100 ≤ Node.val ≤ 100
  • 0 ≤ k ≤ 2 × 10⁹

LeetCode 原題

先看懂限制在說什麼

  • 串列可以是空的 → 直接回傳 None。而且不能對空串列取模（k % 0 會 ZeroDivisionError）—— 所以 if not head 一定要在取模之前。
  • k 可以到 2 × 10⁹，而節點最多 500 個。不取模的話會 TLE。這就是題目給這麼大的 k 的理由。
  • k 可以是 0 → 原樣回傳。

解題思路

解法一

接成環，再剪開（最推薦）

class Solution: def rotateRight(self, head: Optional[ListNode], k: int) -> Optional[ListNode]: if not head or not head.next or k == 0: return head # 第 1 步：數出長度，並找到尾節點 n = 1 tail = head while tail.next: tail = tail.next n += 1 k %= n # 轉 n 次等於沒轉 if k == 0: return head # 第 2 步：接成環 tail.next = head # 第 3 步：走到新的尾節點（原本的第 n-k 個），在那裡斷開 new_tail = head for _ in range(n - k - 1): new_tail = new_tail.next new_head = new_tail.next new_tail.next = None return new_head

為什麼走 n - k - 1 步？

從 head 出發（head 是第 0 個）： 走 0 步 -> 第 0 個 走 m 步 -> 第 m 個 我們要停在「新的尾巴」= 原本的第 (n-k-1) 個（0-indexed）。 驗算 n=5, k=2： n-k-1 = 2 走 2 步 -> 第 2 個節點（值 3）✔ 它的 next（值 4）就是新的頭 ✔ 換個角度： 新頭是「倒數第 k 個」= 第 (n-k) 個（0-indexed） 新尾是它的前一個 = 第 (n-k-1) 個 ✔

三個提前 return，缺一不可

if not head: 空串列 -> 不能取模（除以零），也不能走 if not head.next: 只有一個節點 -> 怎麼轉都一樣 if k == 0: 不用轉 第三個（k % n == 0）在取模之後還要再檢查一次： k = 5, n = 5 -> k %= n -> k = 0 這時候如果繼續走，n-k-1 = 4， 會走到最後一個節點，new_head = tail.next = head（環！） 然後 new_tail.next = None 剛好切回原樣 —— 其實結果是對的，但多做了一圈無謂的操作。 而且更重要的是：語意上「不用轉」就該直接回傳， 讓讀程式的人一眼看懂。

為什麼「接成環」是安全的？

因為我們立刻就會把它剪開。環只存在於函式內部的幾行之間，回傳前一定會有 new_tail.next = None。

但這是一個要小心的操作：如果中間的邏輯出錯（例如 n - k - 1 算錯），就會回傳一個有環的串列，導致呼叫端無窮迴圈。測試時一定要檢查「走訪回傳的串列會不會停」 —— 本篇的 from_list 就內建了環偵測。

複雜度說明
時間O(n)走兩趟（數長度 + 找新尾）
空間O(1)只用幾個指標
解法二

不接環，直接斷開再拼接

有些人不喜歡「製造環」這個中間狀態（因為出錯時很難 debug）。那就先斷開，再把原本的尾巴接到原本的頭。

class Solution: def rotateRight(self, head: Optional[ListNode], k: int) -> Optional[ListNode]: if not head or not head.next: return head n = 1 tail = head while tail.next: tail = tail.next n += 1 k %= n if k == 0: return head # 不接環的版本：用快慢指標找出「倒數第 k+1 個」節點 slow = head for _ in range(n - k - 1): slow = slow.next new_head = slow.next slow.next = None # 先斷開 tail.next = head # 再把原本的尾巴接到原本的頭 return new_head
1 -> 2 -> 3 -> 4 -> 5，k = 2 slow 走到節點 3（n-k-1 = 2 步） new_head = slow.next = 節點 4 slow.next = None -> 1 -> 2 -> 3 | 4 -> 5 tail.next = head -> 4 -> 5 -> 1 -> 2 -> 3 ✔ 順序很重要： 要先 slow.next = None（斷開），再 tail.next = head（接起來）。 反過來的話，串列在中間會有一瞬間是環， 而 slow.next = None 剛好把它剪對 —— 結果也對， 但「先斷再接」的中間狀態比較安全（永遠不是環）。

兩個版本完全等價，選你覺得比較不容易出錯的那個。我個人偏好這個 —— 因為它在任何時刻都不會產生環，即使中途出錯，也只會得到「斷掉的串列」而不是「無窮迴圈」。

複雜度說明
時間O(n)走兩趟
空間O(1)只用幾個指標

解法對照

解法中間狀態順序要求備註
一、接環再剪會有環先接環，再找新尾最常見的寫法
二、先斷再接永遠不是環先斷開，再接尾巴出錯時比較安全

邊界條件檢查清單

  • 空串列：([], 5) → []。k % 0 會 ZeroDivisionError，所以 if not head 必須在取模之前。
  • 單一節點：([1], 99) → [1]。
  • k = 0：原樣。
  • k = n：([1,2,3], 3) → 原樣（取模後 k = 0）。
  • k > n：([0,1,2], 4) → [2,0,1]（4 % 3 = 1）。
  • k = n − 1：([1,2], 1) → [2,1]。
  • k 極大：k = 2×10⁹。不取模的話會跑幾十億次迴圈。

常見追問

追問一：向「左」旋轉呢？

向左轉 k 格 = 向右轉 (n − k) 格。所以只要 k = (n - k) % n，其餘完全一樣。

追問二：陣列版呢？

第 189 題（Rotate Array）。有一個很漂亮的 O(1) 空間解法：反轉三次。

nums = [1,2,3,4,5]，k = 2 1. 整個反轉： [5,4,3,2,1] 2. 反轉前 k 個： [4,5,3,2,1] 3. 反轉後 n-k 個： [4,5,1,2,3] ✔ 為什麼對？ 設原陣列是 A + B（A 是前 n-k 個，B 是後 k 個） 目標是 B + A 整個反轉 -> reverse(A+B) = reverse(B) + reverse(A) 反轉前 k 個 -> B + reverse(A) 反轉後 n-k 個 -> B + A ✔ 這個「三次反轉」的技巧在字串旋轉、 以及 C++ 的 std::rotate 實作裡都會用到。 串列版不適合這個做法（反轉串列要改一堆指標）， 所以串列用「接環再剪」，陣列用「反轉三次」。

追問三：如果要旋轉很多次（不同的 k）呢？

每次都 O(n) 的話總共 O(qn)。更好的做法是用循環串列（circular linked list）：只維護一個「當前頭」的指標，旋轉就是移動那個指標，O(k mod n)。如果再配上雙向循環串列，還能選擇往左或往右走比較近的方向，變成 O(min(k, n-k))。這正是 Python 的 collections.deque 的 rotate() 的做法。
