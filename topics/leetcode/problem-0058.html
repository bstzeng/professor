LeetCode 58

Length of Last Word
最後一個單詞的長度

Easy · 簡單 字串

Problem

Given a string s consisting of words and spaces, return the length of the last word in the string.

A word is a maximal substring consisting of non-space characters only.

中文翻譯

給你一個由單字和空白組成的字串 s，回傳最後一個單字的長度。

單字指的是連續的非空白字元組成的最長子字串。

唯一的陷阱：結尾的空白

s = "Hello World " 天真的做法：從最後一個字元往前數 最後一個字元是空白 -> 數出 0 ✘ 正確答案是 5（"World"） 所以流程一定是兩步： 1. 先跳過「結尾的空白」 2. 再往左數字母 除此之外，這題沒有別的難度。 它在 LeetCode 上的意義比較像是「確認你會處理邊界」。

範例

範例 1 輸入：s = "Hello World" 輸出：5 範例 2 輸入：s = " fly me to the moon " 輸出：4 說明：最後一個單字是 "moon"。 範例 3 輸入：s = "luffy is still joyboy" 輸出：6

限制條件

  • 1 ≤ s.length ≤ 10⁴
  • s 只含英文字母和空白 ' '
  • s 裡至少有一個單字

LeetCode 原題

先看懂限制在說什麼

  • 保證至少有一個單字 —— 所以不用處理「全是空白」的情況，s.split()[-1] 不會 IndexError。（但寫成能處理比較安全。）
  • 只有半形空格，沒有 tab 或換行。所以 s[i] == " " 的判斷是精確的。
  • 可能有連續空白、開頭空白、結尾空白 —— 三種都要能處理。

解題思路

三種寫法都是 O(n)，但從後往前掃的版本實際上是 O(最後一個單字的長度 + 結尾空白數)，通常遠小於 n。

解法一

從後往前掃（最推薦）

class Solution: def lengthOfLastWord(self, s: str) -> int: i = len(s) - 1 # 先跳過結尾的空白 while i >= 0 and s[i] == " ": i -= 1 # 再往左數字母，數到空白或開頭為止 length = 0 while i >= 0 and s[i] != " ": length += 1 i -= 1 return length

兩個 while 對應兩個步驟，語意非常清楚。

複雜度其實優於 O(n)：它只會碰到「結尾的空白 + 最後一個單字」這些字元，前面的內容完全不看。對一個 10⁴ 字元、最後一個單字只有 3 個字母的輸入，它只跑幾步。

而且 O(1) 空間 —— 不建任何新字串。

兩個 while 的邊界 i >= 0

第一個 while 的 i >= 0 防的是「全是空白」（題目保證不會，但別讓程式炸掉）。第二個 while 的 i >= 0 防的是「整個字串只有一個單字」（例如 "day"，會一路數到索引 −1 之前停下）。

複雜度說明
時間O(結尾空白 + 最後單字長)通常遠小於 n
空間O(1)只用兩個變數
解法二

split()（最短）

class Solution: def lengthOfLastWord(self, s: str) -> int: # split() 不帶參數時，會自動忽略所有連續空白與首尾空白 return len(s.split()[-1])

split() 不帶參數 vs 帶參數，差很多

s = " a b " s.split() -> ['a', 'b'] 不帶參數時： - 以「任意連續空白」為分隔 - 自動忽略首尾的空白 - 不會產生空字串 s.split(" ") -> ['', '', 'a', '', 'b', '', ''] 帶參數時： - 嚴格以「單一個空格」為分隔 - 連續空白會產生空字串 - 首尾空白也會產生空字串 所以這題一定要用 s.split()（不帶參數）。 寫成 s.split(" ")[-1] 會在 "Hello World " 上回傳 0 ✘ 這是 Python 字串處理最常見的一個坑。

缺點：它把整個字串切成一個 list，空間是 O(n)，而且一定要掃完整個字串。對這題（n ≤ 10⁴）完全無所謂，但在「只要最後一個單字」的場景下是浪費。

實務上就寫這一行。面試時可以先寫它，再說「如果要 O(1) 空間，可以從後往前掃」。

複雜度說明
時間O(n)切出整個 list
空間O(n)list 本身
解法三

rstrip + rfind

class Solution: def lengthOfLastWord(self, s: str) -> int: s = s.rstrip() # 去掉結尾空白 return len(s) - s.rfind(" ") - 1 # 找不到時 rfind 回 -1，剛好是整串長度
s = "Hello World " s.rstrip() -> "Hello World" 長度 11 s.rfind(" ") -> 5 最後一個空格的位置 11 - 5 - 1 = 5 ✔ s = "day"（沒有空格） s.rstrip() -> "day" 長度 3 s.rfind(" ") -> -1 找不到 3 - (-1) - 1 = 3 ✔ 「找不到回 -1」這個慣例，在這裡剛好讓公式統一 —— 不用寫 if。這種「讓邊界自然落在公式裡」的設計很值得學。

介於解法一和二之間：比 split 省記憶體（rstrip 還是會建一個新字串，但只有一份），比手寫掃描短。

複雜度說明
時間O(n)rstrip 建新字串
空間O(n)一份字串複本

解法對照

解法時間空間行數備註
一、從後往前掃O(尾端)O(1)10最優，面試預設
二、split()O(n)O(n)1最短，實務首選
三、rstrip + rfindO(n)O(n)2公式統一，不用 if

邊界條件檢查清單

  • 結尾有空白："Hello World " → 5。本題的核心陷阱。
  • 開頭有空白：" a" → 1。
  • 連續空白：" fly me to the moon " → 4。
  • 只有一個單字："day" → 3。掃描版會數到 i == -1。
  • 只有一個字元："a" → 1；"a " → 1。
  • 用 split(" ") 的錯誤："Hello World " 會回傳 0（最後一個元素是空字串）。

常見追問

追問一：如果要回傳「第 k 個單字」的長度呢？

從後往前掃的優勢就消失了（可能要掃到開頭）。這時 split() 反而是最好的選擇，或者用一個計數器邊掃邊數單字。

追問二：如果分隔符不只是空格（tab、換行、全形空白）呢？

手寫掃描要改成 s[i].isspace()，或者定義一個明確的分隔字元集合。split()（不帶參數）已經處理了所有 Unicode 空白，這是它的優勢。

但要注意：str.isspace() 對全形空白 '\u3000' 也回傳 True —— 這通常是你要的，但如果規格明確只說「半形空格」，就會不符。「哪些字元算空白」永遠應該由規格決定，不是由語言的預設值決定。

追問三：為什麼「從後往前」在這題特別划算？

因為我們只要「最後一個單字」—— 需要的資訊全部集中在字串的尾端。從前往後掃會讀完整個字串，只為了拿到最後那幾個字元。

這是一個很通用的判斷：問自己「答案依賴哪一部分的資料？」然後只去讀那一部分。同樣的想法出現在：從後往前的字串比對（Boyer-Moore）、從尾端讀取日誌檔（tail）、以及本題。
