LeetCode 201

Bitwise AND of Numbers Range
數字範圍按位與

Medium · 中等 位元運算

Problem

You are given two integers left and right that describe the inclusive range [left, right]. Return the result of applying bitwise AND to every integer in that range.

中文翻譯

給你兩個整數 left 和 right，代表閉區間 [left, right]。請回傳把區間內所有整數做位元 AND 之後的結果。

★ 這題的陷阱：直接迴圈會超時

區間最長可以是 [0, 2^31 - 1]，大約 21 億個數字。 一個一個 AND 下去 -> 最多 21 億次運算 ✘ 【真正要問的是】： AND 一路做下去，哪些位元能活下來？ 【答案】： 只有 left 和 right 的「共同二進位前綴」能活下來， 其餘位元一定都變成 0。 所以這題不是迴圈題，是【找共同前綴】的題目。

範例

範例 1 輸入：left = 5, right = 7 輸出：4 說明：5 = 101、6 = 110、7 = 111，全部 AND 起來是 100 = 4。 範例 2 輸入：left = 0, right = 0 輸出：0 範例 3 輸入：left = 1, right = 2147483647 輸出：0

限制條件

  • 0 ≤ left ≤ right ≤ 2³¹ − 1

LeetCode 原題

解題思路

【為什麼共同前綴之後的位元全部會變 0？】 假設 left 和 right 的共同前綴是 P， 在 P 之後的第一個位置上： left 的那一位是 0 right 的那一位是 1 （因為 left ≤ right，而且這是第一個不同的位） 從 left 數到 right 的途中，一定會經過這個數： M = P 1 000...0 （那一位是 1，後面全 0） 以及它的前一個數： M - 1 = P 0 111...1 這兩個數 AND 起來： P 1 000...0 & P 0 111...1 = P 0 000...0 【從那一位開始到最右邊，全部都被清成 0 了】 而共同前綴 P 在區間內每個數都一樣，所以保留。 【結論】： 答案 = left 和 right 的共同前綴，後面補 0 ✔ 【怎麼找共同前綴？】兩種常見寫法： 1. 兩者一起右移，直到相等；再左移回去。 2. 不斷把 right 最低位的 1 拿掉，直到 right ≤ left。
解法一

暴力 AND（會超時，但有助理解）

class Solution: def rangeBitwiseAnd(self, left: int, right: int) -> int: ans = left for x in range(left + 1, right + 1): ans &= x if ans == 0: # 小優化：已經是 0 就不會再變 break return ans

最壞情況 21 億次迴圈——即使加了「變成 0 就提早結束」的優化，像 left = 2³⁰, right = 2³¹ − 1 這種區間，答案是 2³⁰ 從不變 0，還是要跑完十億次。

複雜度說明
時間O(right − left)區間長度
空間O(1)
解法二

同步右移找共同前綴

class Solution: def rangeBitwiseAnd(self, left: int, right: int) -> int: shift = 0 while left < right: # ★ 兩者不同，代表最低位一定會出現 0 left >>= 1 right >>= 1 shift += 1 return left << shift # 共同前綴補回右邊的 0
【模擬】left = 26 (11010)、right = 30 (11110) shift = 0：11010 vs 11110 不同 shift = 1： 1101 vs 1111 不同 shift = 2： 110 vs 111 不同 shift = 3： 11 vs 11 相同 -> 停 答案 = 11 << 3 = 11000 = 24 ✔ 【迴圈最多跑幾次？】 每次右移一位，最多 31 位 -> O(log right) ✔
複雜度說明
時間O(log right)最多 31 次右移
空間O(1)
解法三

Brian Kernighan：一直拿掉最低位的 1

class Solution: def rangeBitwiseAnd(self, left: int, right: int) -> int: while left < right: right &= right - 1 # ★ 拿掉 right 最低位的 1 return right
【right & (right - 1) 做了什麼？】 right = 1 1 1 1 0 right - 1 = 1 1 1 0 1 AND = 1 1 1 0 0 <- 最低位的 1 被拿掉了 【為什麼可以這樣做？】 只要 right > left，right 的最低位的 1 一定不在共同前綴裡（否則 right 就會 ≤ left）， 所以它在答案裡一定是 0，可以直接拿掉。 一直拿到 right ≤ left 為止，剩下的就是共同前綴 ✔ 【模擬】left = 26、right = 30 30 = 11110 -> 11100 = 28 仍 > 26 28 = 11100 -> 11000 = 24 ≤ 26，停 答案 24 ✔ 【注意回傳 right 而不是 left】 迴圈結束時 right ≤ left，right 才是被清乾淨的共同前綴。
複雜度說明
時間O(log right)迴圈次數 = 要拿掉的 1 的個數
空間O(1)

解法對照

解法時間空間備註
一、暴力O(right − left)O(1)區間大時超時 ✘
二、同步右移O(log right)O(1)最直觀 ✔
三、Brian KernighanO(log right)O(1)通常迴圈次數更少

邊界條件檢查清單

  • left == right → 答案就是它本身。
  • left = 0 → 任何數 AND 0 都是 0。
  • 區間跨過 2 的冪次（例如 [3, 4]）→ 最高位不同，答案是 0。
  • 最大值 2³¹ − 1 → Python 沒有溢位問題；其他語言要注意 right - 1 不會溢位，但別寫成 right + 1。
  • 解法三回傳 left → 錯，要回傳 right。

常見追問

追問一：如果改成 OR 呢？

【區間 OR】剛好反過來： 共同前綴保留， 共同前綴之後的位元，全部變成 1。 理由相同：區間內一定有 P 0 111...1 這個數， 它把後面所有位都填成 1。 def rangeBitwiseOr(left, right): shift = 0 while left < right: left >>= 1; right >>= 1; shift += 1 return (left << shift) | ((1 << shift) - 1) if shift else left

追問二：同樣的「最低位的 1」技巧還能做什麼？

  • 第 191 題 位元 1 的個數：n &= n - 1 每次拿掉一個 1，計數即可。
  • 第 231 題 2 的冪：n > 0 and n & (n - 1) == 0。
  • 第 338 題 位元計數：bits[i] = bits[i & (i - 1)] + 1。

延伸題目

  • 第 231 題 2 的冪 —— n & (n - 1)
  • 第 338 題 位元計數 —— 同樣的技巧用在 DP
