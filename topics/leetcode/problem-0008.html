LeetCode 8

String to Integer (atoi)
字串轉換整數

Medium · 中等 字串

Problem

Implement the myAtoi(string s) function, which converts a string to a 32-bit signed integer.

The algorithm is as follows: (1) skip any leading whitespace; (2) read an optional '+' or '-' sign; (3) read digits until a non-digit character or the end of input; (4) if no digits were read, the result is 0; (5) clamp the result to the range [-2³¹, 2³¹ - 1].

中文翻譯

實作 myAtoi(string s)，把字串轉換成 32 位元有號整數（類似 C/C++ 的 atoi）。

規則依序是：（1）跳過開頭的空白；（2）讀一個可有可無的 '+' 或 '-'；（3）一直讀數字，直到遇到非數字或字串結束；（4）如果一個數字都沒讀到，結果是 0；（5）超出 [-2³¹, 2³¹ − 1] 就夾（clamp）到邊界值，不是回傳 0。

這題不難，但規則多到一定會漏掉一條

第 7 題溢位回 0，這題溢位回 邊界值。光這一條就淘汰掉一半的人。把五條規則抄下來、一條一條對照著寫，是最有效率的做法。

五條規則，缺一不可： 1. 只跳「開頭」的空白，而且只跳半形空格 ' ' → " 42" -> 42 → " 4 2" -> 4 （中間的空白就是終止符） 2. 符號最多一個 → "+-12" -> 0 （第二個符號不是數字，直接結束） → "--1" -> 0 3. 遇到非數字立刻停，不報錯 → "4193 with words" -> 4193 → "words and 987" -> 0 （開頭就不是數字） 4. 一個數字都沒讀到 -> 0 → "", " ", "+", "abc" 都是 0 5. 溢位要 clamp，不是回 0 → "-91283472332" -> -2147483648 （不是 0！） → "21474836460" -> 2147483647

範例

範例 1 輸入：s = "42" 輸出：42 範例 2 輸入：s = " -42" 輸出：-42 說明：跳過三個空白，讀到 '-'，然後讀 42。 範例 3 輸入：s = "4193 with words" 輸出：4193 說明：讀到空白就停了。 範例 4 輸入：s = "words and 987" 輸出：0 說明：第一個非空白字元是 'w'，不是數字也不是符號，直接結束。 範例 5 輸入：s = "-91283472332" 輸出：-2147483648 說明：超出下界，夾到 INT_MIN（不是回傳 0）。

限制條件

  • 0 ≤ s.length ≤ 200（可以是空字串）
  • s 由英文字母、數字、' '、'+'、'-'、'.' 組成

LeetCode 原題

先看懂限制在說什麼

  • 字串可以是空的，所以每個 s[i] 之前都要先確認 i < n。
  • 字元集裡有 '.' —— 這是在提醒你 "3.14" 的答案是 3，不是 3.14，也不是 0。小數點就只是一個普通的終止符。
  • 只有半形空格 ' '，沒有 \t 或 \n。所以千萬不要用 s.strip() 或 str.isspace() —— 它們會把 tab、換行、甚至全形空白都吃掉，在某些測資上會與規格不符。
  • n ≤ 200，效率完全不是問題。這題考的是把規格翻譯成程式碼的精準度。

解題思路

把它當成一台有限狀態機來看，五條規則就變成四個狀態之間的轉移，一條都不會漏。

解法一

照著規則一步一步走（面試標準答案）

四個步驟對應四段程式碼，順序不能換：吃空白 → 吃符號 → 吃數字 → 夾範圍。

class Solution: def myAtoi(self, s: str) -> int: INT_MIN, INT_MAX = -2**31, 2**31 - 1 i, n = 0, len(s) # 第 1 步：跳過開頭的空白（只有 ' '，不含 \t \n） while i < n and s[i] == " ": i += 1 if i == n: return 0 # 第 2 步：讀符號，最多一個 sign = 1 if s[i] in "+-": if s[i] == "-": sign = -1 i += 1 # 第 3 步：讀連續的數字，遇到非數字立刻停 num = 0 while i < n and s[i].isdigit(): num = num * 10 + int(s[i]) i += 1 # 第 4 步：邊讀邊夾住範圍（讀完才判斷也行，但這樣不會累積大數） if sign == 1 and num > INT_MAX: return INT_MAX if sign == -1 and -num < INT_MIN: return INT_MIN return sign * num

為什麼溢位檢查要放在迴圈裡面？

放在迴圈外面（讀完整個數字再夾）在 Python 裡也會對，但有兩個問題：

  • 字串長度 200 時，累積出來的整數會有 200 位數 —— Python 撐得住，C/Java 早就爆了。把檢查放在迴圈裡，同一份邏輯可以直接翻譯成 C。
  • 提前 return 也比較快，雖然在這個規模下無所謂。

為什麼負數要寫 -num < INT_MIN 而不是 num > 2**31？

兩者等價（-num < -2**31 ⟺ num > 2**31），但寫成前者的好處是：判斷式直接對應題目的規格文字「結果小於 INT_MIN」，讀程式碼的人不用自己在心裡做一次移項。規格題寫得越像規格越好。

那個常見的錯誤：用 strip()

錯誤寫法： s = s.strip() # ✘ 會把結尾的空白也吃掉，還會吃掉 \t \n s = s.lstrip() # ✘ 同樣會吃 \t \n 規格只說「跳過開頭的『空白字元』」，而測資裡只會出現半形空格。 用 while s[i] == " " 才是精確對應規格的寫法。 實務上這個差別很重要：如果你在寫一個真的 parser， 「哪些字元算 whitespace」必須由規格決定，不能由語言的預設值決定。
複雜度說明
時間O(n)每個字元最多看一次
空間O(1)只用幾個變數
解法二

正規表示式（簡潔但要小心）

import re class Solution: def myAtoi(self, s: str) -> int: INT_MIN, INT_MAX = -2**31, 2**31 - 1 m = re.match(r"[ ]*([+-]?\d+)", s) if not m: return 0 return max(INT_MIN, min(INT_MAX, int(m.group(1))))

這個 pattern 逐字拆解

r"[ ]*([+-]?\d+)" [ ]* 開頭 0 個以上的半形空格 （寫 [ ] 而不是 \s 是故意的：\s 會吃 \t \n \r \f \v） ( 開始擷取 [+-]? 可有可無的一個符號 \d+ 一個以上的數字（+ 而不是 * ，沒數字就整個不匹配） ) 結束擷取 re.match 只從字串開頭比對（不是 re.search）， 所以 "words and 987" 匹配失敗 → 回傳 0 ✔

三個容易出錯的地方

  • 必須用 re.match 而不是 re.search。search 會在整個字串裡找，"words and 987" 就會錯誤地回傳 987。
  • 必須用 \d+ 而不是 \d*。用 * 的話 "+" 會匹配成功但 group 是 "+"，int("+") 會拋例外。
  • 不要用 \s*。理由同上：規格只允許半形空格。

面試時該不該用？可以寫，但要主動說明每個部分在做什麼 —— 面試官想確認你是理解規格後寫出 regex，而不是從網路上背了一條。被追問「如果不准用 regex 呢」的機率很高，所以解法一還是要會。

複雜度說明
時間O(n)regex 引擎掃一遍
空間O(n)編譯後的 pattern 與擷取到的子字串

邊界條件檢查清單

  • 空字串 / 全空白：""、" " → 0。不能對空字串取 s[0]。
  • 只有符號："+"、"-"、"+-12"、"--1" → 都是 0。
  • 開頭不是數字也不是符號："words and 987"、".1" → 0。
  • 數字後面接垃圾："4193 with words" → 4193；"3.14" → 3；"00000-42a1234" → 0。
  • 前導零："0032" → 32；"-000000000000001" → −1。
  • 正溢位："2147483648" → 2147483647（不是 0）。
  • 負溢位："-2147483649" → −2147483648（不是 0）。
  • 剛好在邊界："2147483647"、"-2147483648" → 原值，不能被誤夾。
  • 空白在中間：" +0 123" → 0（讀完 0 之後遇到空白就停）。

常見追問

追問一：要支援小數或科學記號呢？

那就變成第 65 題（Valid Number），狀態機會從 4 個狀態擴張到 9 個左右。這正是為什麼一開始就用狀態機的角度思考很划算 —— 加規則等於加狀態和轉移，而不是在一堆 if 裡面到處補洞。

追問二：要支援不同進位（像 strtol 的 base 參數）呢？

把 s[i].isdigit() 換成「這個字元在 base 進位下的值」，把 num * 10 換成 num * base，再處理 0x／0b 前綴即可。溢位檢查的移項技巧完全一樣，只是把 10 換成 base。

追問三：為什麼真實世界的 atoi 被認為是壞 API？

因為它無法區分「解析失敗」和「答案真的是 0」 —— atoi("abc") 和 atoi("0") 都回 0，呼叫端無從得知發生了什麼。這也是 C 標準後來推薦 strtol（會回傳「停在哪裡」和設定 errno）的原因，而 Rust 的 str::parse 直接回傳 Result。這是一個很好的 API 設計話題，面試時提到會加分。
