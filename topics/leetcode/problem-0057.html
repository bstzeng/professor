LeetCode 57

Insert Interval
插入區間

Medium · 中等 陣列

Problem

You are given an array of non-overlapping intervals intervals where intervals[i] = [start_i, end_i] represent the start and the end of the i-th interval and intervals is sorted in ascending order by start_i. You are also given an interval newInterval.

Insert newInterval into intervals such that intervals is still sorted in ascending order by start_i and intervals still does not have any overlapping intervals (merge overlapping intervals if necessary).

中文翻譯

給你一個已依起點排序、而且互不重疊的區間陣列 intervals，以及一個新區間 newInterval。

把新區間插進去，並且讓結果仍然是「依起點排序、互不重疊」（必要時要合併重疊的區間）。

把原陣列切成三段

設新區間是 [s, e]。原本的區間可以分成三類： ① 完全在左邊： interval[1] < s 它的結束比新區間的開始還早 -> 不重疊，原封不動 ② 有重疊： interval[0] <= e 且 interval[1] >= s 要被吞併進新區間 ③ 完全在右邊： interval[0] > e 它的開始比新區間的結束還晚 -> 不重疊，原封不動 而因為原陣列「已排序且不重疊」， 這三類在陣列裡剛好是【連續的三段】： [①①①][②②②][③③③] 所以只要找出兩個分界點，就能一趟做完。 吞併的規則： s = min(s, 所有重疊區間的最小起點) e = max(e, 所有重疊區間的最大終點)

「已排序且不重疊」這個前提，讓這題從 O(n log n) 降到 O(n) —— 如果沒有這個前提，就只能套用第 56 題的做法（先加進去再全部重排合併）。

範例

範例 1 輸入：intervals = [[1,3],[6,9]], newInterval = [2,5] 輸出：[[1,5],[6,9]] 說明：[2,5] 和 [1,3] 重疊，合併成 [1,5]。 範例 2 輸入：intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]], newInterval = [4,8] 輸出：[[1,2],[3,10],[12,16]] 說明：[4,8] 和 [3,5]、[6,7]、[8,10] 都重疊，一起合併成 [3,10]。

限制條件

  • 0 ≤ intervals.length ≤ 10⁴（可以是空的）
  • intervals[i].length == 2
  • 0 ≤ startᵢ ≤ endᵢ ≤ 10⁵
  • intervals 已依 startᵢ 升序排列且互不重疊
  • newInterval.length == 2，0 ≤ start ≤ end ≤ 10⁵

LeetCode 原題

先看懂限制在說什麼

  • intervals 可以是空的 → 答案就是 [newInterval]。三段式寫法自然處理（前兩個 while 都不跑，直接 append）。
  • 已排序且不重疊 —— 這是 O(n) 解法的全部基礎。面試時務必確認這個前提（如果沒有，就是第 56 題）。
  • 端點相碰算重疊：[[1,5]] 插入 [5,7] → [[1,7]]。所以判斷式用 < 和 <= 而不是反過來。
  • n 到 10⁴，O(n) 輕鬆過。二分搜尋（O(log n) 定位）是加分項而不是必需。

解題思路

解法一

三段式一趟掃描（標準解）

class Solution: def insert(self, intervals: List[List[int]], newInterval: List[int]) -> List[List[int]]: out = [] s, e = newInterval i, n = 0, len(intervals) # 第 1 段：完全在新區間「左邊」的，原封不動放進去 while i < n and intervals[i][1] < s: out.append(intervals[i]) i += 1 # 第 2 段：所有和新區間重疊的，吞併成一個大區間 while i < n and intervals[i][0] <= e: s = min(s, intervals[i][0]) e = max(e, intervals[i][1]) i += 1 out.append([s, e]) # 第 3 段：完全在右邊的，原封不動放進去 while i < n: out.append(intervals[i]) i += 1 return out

兩個 while 的條件，一個字都不能錯

第 1 段（左邊）： intervals[i][1] < s 「這個區間的結束，比新區間的開始還早」 用嚴格 < ：如果 intervals[i][1] == s，端點相碰，算重疊，不能放進第 1 段。 第 2 段（重疊）： intervals[i][0] <= e 「這個區間的開始，不超過新區間的結束」 用 <= ：端點相碰算重疊。 為什麼不用同時檢查 intervals[i][1] >= s？ 因為第 1 段的 while 已經把「結束 < s」的全部消化掉了， 所以走到第 2 段時，剩下的都保證 intervals[i][1] >= s。 這是「三段式」的優雅之處： 每一段的條件都靠前一段的結束來簡化。 第 3 段： 剩下全部原封不動。

追一遍範例 2

intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]]，new = [4,8] s, e = 4, 8 第 1 段： i=0: [1,2] 的 2 < 4 ✔ 放進 out，i=1 i=1: [3,5] 的 5 < 4 ✘ 停 第 2 段： i=1: [3,5] 的 3 <= 8 ✔ s=min(4,3)=3, e=max(8,5)=8，i=2 i=2: [6,7] 的 6 <= 8 ✔ s=3, e=max(8,7)=8，i=3 i=3: [8,10] 的 8 <= 8 ✔ s=3, e=max(8,10)=10，i=4 i=4: [12,16] 的 12 <= 10 ✘ 停 out.append([3, 10]) 第 3 段： i=4: 放進 [12,16] 結果 [[1,2],[3,10],[12,16]] ✔

注意 e 在第 2 段會「一邊擴大一邊被用來判斷」 —— 這是對的，因為吞併之後新區間變大，可能又碰到更右邊的區間。例子裡 [8,10] 就是靠 e 從 8 沒變（8 <= 8）才被吞進來的。

複雜度說明
時間O(n)每個區間看一次
空間O(n)輸出陣列
解法二

二分搜尋定位（在區間很多時更快）

既然陣列已排序，兩個分界點可以用二分搜尋找出來，而不是線性掃過去。

import bisect class Solution: def insert(self, intervals: List[List[int]], newInterval: List[int]) -> List[List[int]]: starts = [x[0] for x in intervals] ends = [x[1] for x in intervals] s, e = newInterval # 第一個「結束 >= s」的區間 —— 從它開始可能有重疊 lo = bisect.bisect_left(ends, s) # 第一個「開始 > e」的區間 —— 從它開始不可能重疊 hi = bisect.bisect_right(starts, e) if lo < hi: # 有區間要被吞併 s = min(s, intervals[lo][0]) e = max(e, intervals[hi - 1][1]) return intervals[:lo] + [[s, e]] + intervals[hi:]
lo = bisect_left(ends, s) ends 是所有區間的「結束」，它也是遞增的（因為不重疊）。 找「第一個 end >= s」的位置 —— 從它開始才可能重疊。 hi = bisect_right(starts, e) starts 是所有區間的「開始」，遞增。 找「第一個 start > e」的位置 —— 從它開始不可能重疊。 所以 intervals[lo : hi] 就是所有和新區間重疊的區間。 if lo < hi: 表示真的有重疊 s = min(s, intervals[lo][0]) 最左邊那個的起點 e = max(e, intervals[hi-1][1]) 最右邊那個的終點 （不用掃過中間所有的，因為已排序且不重疊， 最小起點一定在 lo，最大終點一定在 hi-1。） 最後拼起來： intervals[:lo] + [[s, e]] + intervals[hi:]

為什麼 ends 也是遞增的？

因為題目保證「已排序且不重疊」。不重疊表示 intervals[i][1] < intervals[i+1][0] ≤ intervals[i+1][1]，所以 ends 必然也遞增 —— 才能對它做二分搜尋。如果區間可能重疊（例如 [[1,10],[2,3]]），ends 就不是遞增的，這個解法會錯。

複雜度真的比較好嗎？

定位： O(log n) 切片： intervals[:lo] 和 intervals[hi:] 是 O(n) 的複製 所以總複雜度還是 O(n)。 真正的差別在「常數」： 解法一：n 次迴圈（Python 層） 解法二：兩次 bisect（C 層）+ 兩次切片（C 層的 memcpy） 在 n = 10⁴ 時，解法二通常快 5–10 倍 —— 不是因為複雜度，而是因為工作都在 C 層做。 如果輸出可以用「回傳索引範圍」而不是「新陣列」， 解法二才能真正做到 O(log n)。

面試時：先寫解法一（它展示了對問題結構的理解），再提「因為已排序，兩個分界點可以二分搜尋」。

邊界條件檢查清單

  • 空陣列：([], [5,7]) → [[5,7]]。
  • 新區間在最前面：([[1,5]], [0,0]) → [[0,0],[1,5]]。
  • 新區間在最後面：([[1,5]], [6,8]) → [[1,5],[6,8]]。
  • 新區間被完全包含：([[1,5]], [2,3]) → [[1,5]]。min 和 max 都不能省。
  • 新區間包含所有：([[1,2],[3,4]], [0,10]) → [[0,10]]。
  • 端點相碰：([[1,5]], [5,7]) → [[1,7]]；([[3,5],[12,15]], [6,6]) → [[3,5],[6,6],[12,15]]。
  • 點區間插在縫隙：驗證「不重疊」時不會被誤吞。

常見追問

追問一：如果要插入很多個區間呢？

一個一個插是 O(k · n)。更好的做法：把 k 個新區間全部加進去，再套第 56 題的「排序 + 合併」，O((n+k) log(n+k))。當 k 接近 n 時後者明顯更好。

追問二：如果是「刪除一個區間」呢？

第 1272 題（Remove Interval）。結構很像，也是三段式，但重疊的部分要「切掉中間」而不是「合併」：

對每個重疊的區間 [a, b] 和要刪除的 [s, e]： 左邊殘留： [a, s] 若 a < s 右邊殘留： [e, b] 若 e < b 一個區間可能被切成兩段（當 [s,e] 完全在 [a,b] 內部時）。 刪除比插入麻煩，因為區間數量可能「變多」。

追問三：如果要支援「動態插入 + 查詢某點是否被覆蓋」呢？

第 715 題（Range Module）。用 平衡二元搜尋樹（Python 的 sortedcontainers.SortedList）維護不重疊的區間集合，每次操作 O(log n + 受影響的區間數)。或者用線段樹 + 座標壓縮。

追問四：這題的「三段式」在哪裡還會出現？

任何「有序資料 + 一個範圍操作」的問題：

  • 陣列的區間刪除／替換（list[a:b] = [...] 就是三段式）
  • 版本控制的 diff / patch：未變、變更、未變
  • 資料庫的範圍更新
  • 文字編輯器的區塊選取與替換

「把序列切成『不受影響的前段 + 受影響的中段 + 不受影響的後段』」是處理有序資料的通用模式。
