LeetCode 16

3Sum Closest
最接近的三數之和

Medium · 中等 陣列 雙指標 排序

Problem

Given an integer array nums of length n and an integer target, find three integers in nums such that the sum is closest to target.

Return the sum of the three integers. You may assume that each input would have exactly one solution.

中文翻譯

給你一個長度為 n 的整數陣列 nums 和一個整數 target，找出三個數，讓它們的和最接近 target。

回傳這三個數的和（不是三個數本身）。可以假設每筆輸入恰好只有一個答案。

和第 15 題的三個差異

第 15 題 3Sum 第 16 題 3Sum Closest ------------------------ ------------------------ 和要「等於」0 和要「最接近」target 回傳所有三元組 只回傳一個整數（那個和） 必須去重 不必去重（答案是數字，不是組合） 差異的後果： 1. 找到 total == target 可以立刻 return（不可能更好了） 2. 雙指標的移動邏輯從「三分支」變成「一樣是三分支，但中間那支是提前結束」 3. 去重從「必要」降級成「純優化」

「恰好只有一個答案」是什麼意思？指的是「最接近的那個和」唯一，不是「三元組」唯一。例如 target = 1、可能的和有 0 和 2 時，兩者距離都是 1 —— 題目保證這種情況不會出現，所以你不用煩惱平手時要回哪一個。

範例

範例 1 輸入：nums = [-1, 2, 1, -4], target = 1 輸出：2 說明：最接近的和是 (-1) + 2 + 1 = 2。 範例 2 輸入：nums = [0, 0, 0], target = 1 輸出：0 說明：只有一種選法。

限制條件

  • 3 ≤ nums.length ≤ 500
  • −1000 ≤ nums[i] ≤ 1000
  • −10⁴ ≤ target ≤ 10⁴

LeetCode 原題

先看懂限制在說什麼

  • n ≤ 500。O(n³) 是 1.25 × 10⁸ —— 在 Python 裡會很吃力（可能 TLE），在 C++ 裡勉強能過。O(n²) 是 2.5 × 10⁵ —— 瞬間完成。
  • target 的範圍比「三個數能湊出的最大值」（3000）還大。所以可能出現「怎麼湊都差很遠」的情況，例如 target = 10000。這時答案就是最大的三個數之和 —— 你的程式要能正確處理，不能因為「差太多」而出錯。
  • 陣列至少 3 個元素，所以 nums[0]+nums[1]+nums[2] 當初值一定安全。

解題思路

骨架和第 15 題一模一樣：排序 → 固定一個 → 雙指標。唯一要換的是「判斷式」：從「等於 0 才收」改成「比目前更近就更新」。

雙指標的移動邏輯為什麼還是對的？ 排序後，固定 nums[i]，我們要在 [lo, hi] 裡找一對，使總和最接近 target。 total < target -> 和太小，需要更大的數 左指標右移（nums[lo] 變大）是唯一能變大的方向 （右移 hi 只會讓和更小，離 target 更遠） total > target -> 和太大，需要更小的數 右指標左移 total == target -> 距離 0，不可能更好，直接 return 每一步都排除掉一個指標位置，所以是 O(n)。
解法一

三重迴圈（基準線）

class Solution: def threeSumClosest(self, nums: List[int], target: int) -> int: n = len(nums) best = nums[0] + nums[1] + nums[2] for i in range(n): for j in range(i + 1, n): for k in range(j + 1, n): s = nums[i] + nums[j] + nums[k] if abs(s - target) < abs(best - target): best = s return best

best 的初值要用一組真實存在的和，不能用 float("inf") —— 因為我們最後要回傳的是「某三個數的和」，不是距離。用 inf 當初值的話，如果所有比較都沒通過（不會發生，但邏輯上要乾淨），會回傳一個不存在的值。

複雜度說明
時間O(n³)n = 500 時約 2 × 10⁷ 組
空間O(1)只有一個 best
解法二

排序 + 雙指標（標準解）

class Solution: def threeSumClosest(self, nums: List[int], target: int) -> int: nums.sort() n = len(nums) best = nums[0] + nums[1] + nums[2] # 先拿任意一組當初值 for i in range(n - 2): if i > 0 and nums[i] == nums[i - 1]: continue # 相同的 i 不會給出新結果 lo, hi = i + 1, n - 1 while lo < hi: total = nums[i] + nums[lo] + nums[hi] if abs(total - target) < abs(best - target): best = total if total == target: # 不可能更接近了 return target if total < target: lo += 1 # 想要更大 -> 左指標右移 else: hi -= 1 # 想要更小 -> 右指標左移 return best

追一遍 nums = [-4, -1, 1, 2]（已排序），target = 1

best 初值 = (-4) + (-1) + 1 = -4 |best - 1| = 5 i = 0（-4）： lo=1(-1), hi=3(2)：total = -4-1+2 = -3 |−3−1| = 4 < 5 -> best = -3 -3 < 1 -> lo++ lo=2(1), hi=3(2)：total = -4+1+2 = -1 |−1−1| = 2 < 4 -> best = -1 -1 < 1 -> lo++ lo=3, hi=3 -> 結束 i = 1（-1）： lo=2(1), hi=3(2)：total = -1+1+2 = 2 |2−1| = 1 < 2 -> best = 2 2 > 1 -> hi-- lo=2, hi=2 -> 結束 回傳 2 ✔

if total == target: return target 值得寫嗎？

值得。距離 0 是絕對最小值，不可能更好，直接結束可以省下剩餘所有迴圈。在「答案剛好命中」的測資上，這一行可能把執行時間砍掉九成。

去重那一行還需要嗎？

不是必需的（答案是一個數字，重複計算同樣的 i 只會得到同樣的結果），但保留它是純粹的優化：相同的 nums[i] 走第二遍會得到完全相同的搜尋過程。在有大量重複值的測資上能省不少時間。

複雜度說明
時間O(n²)排序 + 雙層
空間O(log n)排序本身的空間
解法三

加上區間剪枝（面試加分）

固定 i 之後，這一層能產生的和的範圍是固定的：

最小值：nums[i] + nums[i+1] + nums[i+2] （配最左邊兩個） 最大值：nums[i] + nums[n-2] + nums[n-1] （配最右邊兩個） 情況 A：最小值已經 > target 這一層所有的和都 > target，最接近的就是最小值本身。 而且因為 nums 已排序，之後的 i 只會讓最小值更大、離 target 更遠 -> 記錄之後直接 break，整個迴圈結束。 情況 B：最大值還 < target 這一層所有的和都 < target，最接近的就是最大值本身。 但之後的 i 還可能更接近 -> 記錄之後 continue，跳過雙指標。 情況 C：target 落在 [最小值, 最大值] 之間 才真的需要跑雙指標。
class Solution: def threeSumClosest(self, nums: List[int], target: int) -> int: nums.sort() n = len(nums) best = nums[0] + nums[1] + nums[2] for i in range(n - 2): if i > 0 and nums[i] == nums[i - 1]: continue # 這一層能達到的最小值：nums[i] 配最左邊兩個 lo_sum = nums[i] + nums[i + 1] + nums[i + 2] if lo_sum > target: # 連最小值都已經超過 target，之後的 i 只會更大 -> 收工 if abs(lo_sum - target) < abs(best - target): best = lo_sum break # 這一層能達到的最大值：nums[i] 配最右邊兩個 hi_sum = nums[i] + nums[n - 2] + nums[n - 1] if hi_sum < target: # 連最大值都還不到 target，這一層最好的就是 hi_sum if abs(hi_sum - target) < abs(best - target): best = hi_sum continue lo, hi = i + 1, n - 1 while lo < hi: total = nums[i] + nums[lo] + nums[hi] if abs(total - target) < abs(best - target): best = total if total == target: return target if total < target: lo += 1 else: hi -= 1 return best

複雜度還是 O(n²)（最壞情況每一層都落在情況 C），但在 target 極大或極小的測資上，這個剪枝能把大部分層直接跳掉。

面試時的正確做法：先寫解法二，跑通之後再說「還可以加上區間剪枝」。一開始就寫解法三容易把自己繞暈，而且三個分支都要寫對才不會出錯。

複雜度說明
時間O(n²) 最壞多數情況遠低於 n²
空間O(log n)排序本身的空間

邊界條件檢查清單

  • 剛好三個元素：([0,0,0], 1) → 0。沒有選擇餘地。
  • target 遠大於所有可能的和：([1,1,1,0], 100) → 3。答案是最大的三個之和。
  • target 遠小於所有可能的和：([1,1,1,0], -100) → 1。答案是最小的三個之和。
  • 剛好命中：([0,2,1,-3], 0) → 0。驗證提前 return。
  • 全部相同：([5,5,5,5], 1) → 15。去重的 continue 要能正確跳過。
  • 負數與正數混合：([4,0,5,-5,3,3,0,-4,-5], -2) → −2。
  • best 初值：不能用 0 或 inf，必須是一組真實的和。用 0 的話 ([1,1,1], 100) 會錯誤地回傳 0。

常見追問

追問一：如果要回傳那三個數，而不是它們的和？

在更新 best 時一併記下 (nums[i], nums[lo], nums[hi]) 即可。但要先問清楚：如果有多組三元組達到同樣的最佳和，要回哪一組？題目目前只保證「和」唯一，沒保證三元組唯一。

追問二：如果平手時要回傳比較小的那個和呢？

把更新條件從 < 改成「距離更小，或距離相同但和更小」：

d_new, d_old = abs(total - target), abs(best - target) if d_new < d_old or (d_new == d_old and total < best): best = total 這種「主要鍵 + 次要鍵」的比較在實務上很常見， 寫成 tuple 比較會更清楚： if (d_new, total) < (d_old, best): best = total

追問三：kSum Closest 呢？

一樣可以遞迴降維：固定一個數，遞迴解 (k−1)Sum Closest，k == 2 時用雙指標。複雜度 O(n^(k−1))。但要注意「最接近」沒有 3Sum 那種「剪掉就不會漏」的性質 —— 區間剪枝要小心寫，不能像 3Sum 那樣看到 nums[i] > 0 就直接 break。
