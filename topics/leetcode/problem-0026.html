Remove Duplicates from Sorted Array
刪除有序陣列中的重複項

Easy · 簡單 陣列 雙指標

Problem

Given an integer array nums sorted in non-decreasing order, remove the duplicates in-place such that each unique element appears only once. The relative order of the elements should be kept the same.

Return k after placing the final result in the first k slots of nums. It does not matter what you leave beyond the first k elements.

中文翻譯

給你一個非遞減排序的整數陣列 nums，請原地刪除重複的元素，讓每個不同的值只出現一次，並保持原本的相對順序。

回傳去重後的長度 k，而且 nums 的前 k 個位置必須存放最終結果。第 k 個之後的內容是什麼都無所謂。

「原地」和「前 k 個」是兩個獨立的要求

輸入： nums = [0,0,1,1,1,2,2,3,3,4] 輸出： k = 5 nums 的前 5 格必須是 [0,1,2,3,4] 第 6 格之後是什麼都不檢查（通常標記成 _） nums = [0,1,2,3,4,_,_,_,_,_] ✔ 常見誤解： ✘ 以為要回傳新陣列 -> 不行，必須原地改 nums ✘ 以為要把後面清空 -> 不用，後面是什麼都不檢查 ✘ 用 nums = [...] 重新綁定 -> 沒用！那只改了區域變數， 呼叫端拿到的還是原本的 list 在 Python 裡要真的「原地」修改，只能用 nums[i] = x （逐格賦值） nums[:] = [...] （切片賦值，會改動原物件） 不能寫 nums = [...]。這是 Python 特有的陷阱。

因為陣列已經排序，所有相同的值一定相鄰 —— 所以只要和「前一個保留下來的值」比較就夠了，不需要 set，也不需要 O(n) 額外空間。

範例

範例 1 輸入：nums = [1,1,2] 輸出：k = 2，nums = [1,2,_] 範例 2 輸入：nums = [0,0,1,1,1,2,2,3,3,4] 輸出：k = 5，nums = [0,1,2,3,4,_,_,_,_,_]

限制條件

  • 1 ≤ nums.length ≤ 3 × 10⁴
  • −100 ≤ nums[i] ≤ 100
  • nums 已經依非遞減順序排好

LeetCode 原題

先看懂限制在說什麼

  • 已經排序 —— 這是整題的關鍵。相同的值一定相鄰，所以「去重」退化成「和前一個比」。如果沒有排序，就得用 set 或先排序，複雜度和空間都會變。
  • 長度至少 1，但寫成能處理空陣列比較安全。
  • 值域是 −100 到 100，所以不能用 0 或 −1 當哨兵。解法二用 None 就是為了這個。

解題思路

快慢雙指標：一個負責「讀」（掃過每個元素），一個負責「寫」（記錄下一個要放的位置）。這是所有「原地過濾」題目的共同模板。

nums = [0,0,1,1,1,2,2,3,3,4] k 指向「下一個要寫入的位置」 i=1: nums[1]=0 == nums[k-1]=nums[0]=0 -> 跳過 k=1 i=2: nums[2]=1 != nums[0]=0 -> nums[1]=1 k=2 i=3: nums[3]=1 == nums[1]=1 -> 跳過 k=2 i=4: nums[4]=1 == nums[1]=1 -> 跳過 k=2 i=5: nums[5]=2 != nums[1]=1 -> nums[2]=2 k=3 i=6: nums[6]=2 == nums[2]=2 -> 跳過 k=3 i=7: nums[7]=3 != nums[2]=2 -> nums[3]=3 k=4 i=8: nums[8]=3 == nums[3]=3 -> 跳過 k=4 i=9: nums[9]=4 != nums[3]=3 -> nums[4]=4 k=5 結果 nums = [0,1,2,3,4,2,3,3,4] 前 5 格正確，回傳 5 ✔ （第 6 格之後是垃圾，但題目不檢查） 注意「寫」永遠不會超前「讀」（k <= i）， 所以不會覆蓋掉還沒讀到的資料 —— 這是原地演算法安全的關鍵。
解法一

快慢指標，和「最後寫入的值」比較

class Solution: def removeDuplicates(self, nums: List[int]) -> int: if not nums: return 0 k = 1 # 下一個「要寫入」的位置；nums[0] 一定保留 for i in range(1, len(nums)): if nums[i] != nums[k - 1]: # 和「最後寫進去的那個」不同才寫 nums[k] = nums[i] k += 1 return k

為什麼是 nums[k-1] 而不是 nums[i-1]？

兩者在這一題「剛好」都對，但意義不同，而且推廣時會分家。 nums[i-1]：和「原陣列的前一個」比 nums[k-1]：和「已經保留下來的最後一個」比 因為輸入是排序的，兩者等價。 但如果輸入沒有排序，nums[k-1] 的語意才是對的 （「我已經收了哪些」而不是「原本前面是誰」）。 更重要的是第 80 題（每個值最多保留兩次）： 那題的條件是 nums[i] != nums[k-2]， 也就是「和已保留的『倒數第二個』比」。 這時候就完全不能用 i 了。 所以養成用 k 的習慣，推廣時會順很多。

k 從 1 開始，因為第一個元素一定要保留 —— 它沒有「前一個」可以比。

「寫」永遠不超前「讀」（k ≤ i 恆成立），所以 nums[k] = nums[i] 絕不會覆蓋掉還沒讀到的資料。這個不變量是所有原地雙指標演算法的安全保證，值得每次都確認一次。

複雜度說明
時間O(n)掃一遍
空間O(1)只用一個下標
解法二

記住上一個值（更容易推廣）

class Solution: def removeDuplicates(self, nums: List[int]) -> int: k = 0 prev = None # 值域是 -100..100，所以用 None 當「還沒有」 for x in nums: if x != prev: nums[k] = x k += 1 prev = x return k

語意上更直白：「掃過每個元素，和上一個不同就收下來」。而且不需要 if not nums 的特判 —— 空陣列的迴圈跑 0 次，直接回 0。

用 None 而不是某個數字當初值，是刻意的。值域包含 −100 到 100，任何具體數字都可能是真實資料。在 C/Java 裡沒有 None，常見做法是多一個 bool 旗標，或是像解法一那樣從第二個元素開始跑。

這個版本很容易改成「去重但不要求排序、保留首次出現順序」—— 把 prev 換成一個 set 即可（但那樣就是 O(n) 空間了）。

複雜度說明
時間O(n)掃一遍
空間O(1)兩個變數

邊界條件檢查清單

  • 空陣列：[] → 0。題目保證不會有，但別讓程式崩潰。
  • 只有一個：[1] → 1。
  • 全部相同：[1,1,1] → 1，前 1 格是 [1]。
  • 完全沒有重複：[1,2,3] → 3。每一格都會被寫入（寫到自己身上，無害）。
  • 負數：[-100,-100,100] → 2。哨兵不能用 0 或 −1。
  • Python 陷阱：寫 nums = [...] 不會改到呼叫端的 list。要用 nums[i] = x 或 nums[:] = [...]。

常見追問

追問一：如果每個值最多保留兩次呢？

第 80 題。只要把條件從 nums[i] != nums[k-1] 改成 k < 2 or nums[i] != nums[k-2]。一般化成「最多保留 m 次」就是 k < m or nums[i] != nums[k-m] —— 同一個模板改一個數字。

追問二：如果陣列沒有排序呢？

「保留首次出現順序」的話要用 set 記錄看過的值，空間變 O(n)。或者先排序（O(n log n)）再用本題的方法 —— 但那樣會破壞原本的順序。「已排序」這個前提值多少，從這裡就看得出來。

追問三：Python 裡怎麼真的「原地」修改？

def f(nums): nums = [1, 2, 3] # ✘ 只改了區域變數，呼叫端看不到 def f(nums): nums[:] = [1, 2, 3] # ✔ 切片賦值，改的是原物件 def f(nums): nums[0] = 1 # ✔ 逐格賦值 這個區別在所有「原地」的 LeetCode 題都會遇到 （第 27、80、75、88、189 題…）。 背後是 Python 的「名字綁定 vs 物件變異」—— 賦值 (=) 是重新綁定名字，索引賦值 ([i]=) 才是改物件。
