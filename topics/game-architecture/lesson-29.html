資料驅動設計

這一課的目標

  • 理解資料驅動的意義
  • 認識常見的資料格式
  • 知道資料驅動的好處與風險

如果怪物的血量寫在程式碼裡，企劃每調一次數值都要請程式設計師重新編譯。資料驅動的做法是：程式只寫「規則」，數值放在資料檔。

// monsters.json { "slime": { "hp": 30, "speed": 1.5, "drops": ["gel"] }, "dragon": { "hp": 900, "speed": 4.0, "drops": ["scale", "gold"] } }
// 程式碼：讀資料生成怪物，不認識任何具體怪物 Entity Spawn(const std::string& id) { const auto& d = db.monsters[id]; auto e = world.Create(); world.Add<Health>(e, d.hp); world.Add<Speed>(e, d.speed); return e; }
  • 好處：企劃自己調整、可以熱重載、方便做模組（Mod）。
  • 風險：資料錯了在執行時才會發現 → 需要驗證工具與預設值。

🧭 這一課的重點

資料驅動把「內容」從「程式」中分離，讓非程式人員能直接調整遊戲。

🎮 本課以通用的遊戲引擎架構說明概念，程式碼為教學用的簡化片段（類 C++／C# 虛擬碼），不是特定引擎的實際原始碼；各引擎的實作細節以官方文件為準。
