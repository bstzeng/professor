繼承地獄

這一課的目標

  • 理解傳統繼承設計
  • 看見繼承樹的問題
  • 知道「組合優於繼承」
class Character : public GameObject { /* 移動、血量 */ }; class Enemy : public Character { /* AI */ }; class FlyingEnemy : public Enemy { /* 飛行 */ }; // 會飛又會游泳的敵人？會游泳的寶箱？ // 結果：功能被往上搬到基底類別，GameObject 越來越肥

症狀

  • 基底類別塞滿不是每個子類都需要的欄位。
  • 想重用某個功能，卻被迫繼承一大串不需要的東西。
  • 企劃想要新組合時，必須請程式設計師新增類別。

軟體設計的老格言「組合優於繼承」在遊戲裡特別明顯，下一課就來看組合式的做法。

🧭 這一課的重點

遊戲物件的功能組合太多，深層繼承會變得又肥又脆；組合是更好的方向。

🎮 本課以通用的遊戲引擎架構說明概念，程式碼為教學用的簡化片段（類 C++／C# 虛擬碼），不是特定引擎的實際原始碼；各引擎的實作細節以官方文件為準。
