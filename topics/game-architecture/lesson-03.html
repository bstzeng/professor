引擎的分層架構

這一課的目標

  • 認識引擎的典型分層
  • 理解平台抽象層
  • 知道依賴方向的規則

平台抽象層

同一款遊戲要上 PC、PlayStation、Switch、手機。引擎把「開檔案」「建立視窗」「讀手把」這些各平台不同的事包成統一介面：

// 平台抽象層：介面 class IFileSystem { public: virtual File* Open(const char* path) = 0; }; // 各平台各寫一份實作 class WindowsFileSystem : public IFileSystem { ... }; class SwitchFileSystem : public IFileSystem { ... };

上層程式只認識 IFileSystem，所以移植時只需要補一份新的實作。

🧭 這一課的重點

引擎分層：平台抽象 → 核心 → 子系統 → 框架 → 遊戲邏輯；上層只依賴下層。

🎮 本課以通用的遊戲引擎架構說明概念，程式碼為教學用的簡化片段（類 C++／C# 虛擬碼），不是特定引擎的實際原始碼；各引擎的實作細節以官方文件為準。

  2. 為什麼下層不能呼叫上層？
