UI 系統

這一課的目標

  • 理解 UI 的分層
  • 認識即時模式與保留模式 UI
  • 知道 UI 與遊戲狀態的連接方式
模式做法常見用途
保留模式建立元件樹，框架負責版面與事件遊戲內選單、HUD（Unity UI、UMG）
即時模式每畫格用程式碼「畫」出 UI除錯工具、編輯器（Dear ImGui）
// 即時模式 UI：每畫格呼叫一次，沒有元件物件 if (ImGui::Button("重生")) player.Respawn(); ImGui::SliderFloat("重力", &gravity, 0, 30);

UI 通常透過事件或資料繫結得知「血量變了」，而不是每畫格去讀玩家物件，這部分在 〈套裝應用程式的架構〉第 8 課 有更詳細的討論。

🧭 這一課的重點

UI 獨立成一層；保留模式適合正式介面，即時模式適合工具與除錯。

🎮 本課以通用的遊戲引擎架構說明概念，程式碼為教學用的簡化片段（類 C++／C# 虛擬碼），不是特定引擎的實際原始碼；各引擎的實作細節以官方文件為準。

  2. 為什麼 UI 不應該直接持有遊戲物件？
  3. Dear ImGui 常用在哪裡？
