遊戲迴圈

這一課的目標

  • 認識遊戲迴圈的結構
  • 寫出最簡單的遊戲迴圈
  • 理解每個階段的責任
while (running) { ProcessInput(); // 讀鍵盤、手把，轉成「動作」 Update(dt); // 推進世界：移動、碰撞、AI、計時 Render(); // 把目前的世界畫出來 }

三個階段的分工

  • 輸入：只收集狀態，不直接改世界（見 第 17 課）。
  • 更新：唯一可以修改遊戲狀態的地方。
  • 繪製：只讀取狀態，不修改——同一個狀態畫兩次應該得到同樣的畫面。

把「改狀態」和「畫狀態」分開，是很多進階技巧（多執行緒繪圖、重播、連線同步）的基礎。

🧭 這一課的重點

遊戲迴圈每畫格做輸入、更新、繪製；只有更新可以改變遊戲狀態。

🎮 本課以通用的遊戲引擎架構說明概念，程式碼為教學用的簡化片段（類 C++／C# 虛擬碼），不是特定引擎的實際原始碼；各引擎的實作細節以官方文件為準。

  2. 為什麼繪製不應該修改狀態？
  3. dt 代表什麼？
