資料導向設計

這一課的目標

  • 理解快取與記憶體延遲
  • 比較 AoS 與 SoA
  • 知道為什麼 ECS 快

CPU 從主記憶體讀資料比做運算慢上百倍，所以它一次會把一整塊（快取列，常見 64 位元組）讀進快取。如果接下來要用的資料剛好就在那一塊裡，速度就很快。

// AoS：物件導向的自然寫法 struct Monster { Vec2 pos; Vec2 vel; int hp; char name[32]; ... }; Monster monsters[10000]; // SoA：資料導向 struct Monsters { Vec2 pos[10000]; Vec2 vel[10000]; int hp[10000]; };

移動系統只需要 pos 與 vel。用 SoA 排列時，讀進快取的每個位元組都有用；用 AoS 時，name 等無關資料佔掉了大部分快取。數萬個物件時差距可達數倍。這種「以資料怎麼被使用來設計結構」的思考，就叫資料導向設計。

快取與記憶體階層的原理，見 〈計算機概論〉。

🧭 這一課的重點

資料導向設計依照資料的使用方式排列記憶體，讓快取命中率最高；這是 ECS 快的原因。

🎮 本課以通用的遊戲引擎架構說明概念，程式碼為教學用的簡化片段（類 C++／C# 虛擬碼），不是特定引擎的實際原始碼；各引擎的實作細節以官方文件為準。
