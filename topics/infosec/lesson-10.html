Session、Cookie 與 Token

這一課的目標

  • 理解 HTTP 無狀態與 Session
  • 認識 Cookie 的安全屬性
  • 理解 JWT 的結構與常見錯誤

HTTP 是健忘的

HTTP 協定本身是無狀態的：每一個請求都是獨立的，伺服器不記得你上一秒做了什麼。為了讓你登入一次就能持續使用，網站在你登入成功後，給你一個識別碼，之後每個請求都帶著它。

Session

  1. 登入成功後，伺服器產生一個隨機、很長的 Session ID，並在伺服器端記下「這個 ID = 使用者 alice」。
  2. Session ID 存在你瀏覽器的 Cookie 中，之後每個請求自動帶上。
  3. 誰拿到這個 ID，誰就是 alice——所以 Session ID 就是臨時的通行證。

Cookie 的安全屬性

屬性作用
HttpOnlyJavaScript 讀不到這個 Cookie，即使網頁被注入惡意程式（XSS，第 14 課）也偷不走
Secure只透過 HTTPS 傳送
SameSite限制從其他網站發出的請求是否帶上 Cookie，防禦 CSRF（第 15 課）
有效期限Session 應該有合理的逾時，登出時伺服器要讓它失效

Token 與 JWT

另一種做法是把使用者資訊直接放進一個簽章過的 Token，伺服器不需要記住任何東西，只要驗證簽章。最常見的格式是 JWT，由三段以「.」相連：

標頭（演算法）. 內容（使用者 ID、角色、到期時間）. 簽章

前兩段只是 Base64 編碼，任何人都能讀——不要把機密資料放進去。安全性完全依賴第三段的簽章。

常見的錯誤

  • 不驗證簽章，或接受標頭寫著「alg: none」（不簽章）的 Token——攻擊者可以把自己改成管理員。
  • 簽章用的金鑰太弱，被暴力破解。
  • Token 沒有到期時間，或無法撤銷：員工離職、手機遺失，Token 依然有效。
  • 把 Token 存在 JavaScript 讀得到的地方，一旦有 XSS 就被偷走。

Session 劫持

不論是 Session ID 還是 Token，被偷走就等於帳號被盜，而且不需要密碼，也繞過了多因素驗證。近年許多 YouTube 頻道被盜，就是資訊竊取程式偷走了瀏覽器中的 Cookie（第 22 課）。

🧭 這一課的重點

HTTP 是無狀態的，網站登入後給你識別碼並在每個請求中帶上。Session 是伺服器產生隨機長 ID 並記錄對應使用者，ID 存在 Cookie，誰拿到誰就是你。Cookie 安全屬性包括讓 JavaScript 讀不到的 HttpOnly、只走 HTTPS 的 Secure、防 CSRF 的 SameSite 與合理的有效期限。Token 把使用者資訊放進簽章過的字串，JWT 由標頭、內容、簽章三段組成，前兩段只是 Base64 誰都能讀，安全依賴簽章。常見錯誤有不驗簽章或接受 alg none、金鑰太弱、沒有到期或無法撤銷、存在 JS 可讀處。Session 劫持不需密碼並繞過 MFA，許多頻道被盜就是 Cookie 被資訊竊取程式偷走。
