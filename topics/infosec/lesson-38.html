模組 F｜防禦 · 第 38 課

安全的軟體開發

這一課的目標

  • 理解「安全左移」的概念
  • 認識開發流程中的資安工具
  • 避免把祕密寫進程式碼

越早修越便宜

在設計階段發現一個安全問題，可能只要改幾行規格；上線後才發現，可能要緊急修補、通報、賠償。安全左移（shift left）的意思是：把安全的工作移到開發流程的前面。

開發流程中的資安

階段做法
需求與設計威脅建模（第 2 課）：資料怎麼流、誰能存取、哪裡可能被攻擊
撰寫程式安全的程式設計規範、使用安全預設的框架、程式碼審查
建置SAST（靜態分析：掃描原始碼）、依賴套件掃描、祕密掃描
測試DAST（動態分析：對執行中的網站做測試）、模糊測試（餵大量隨機輸入找當機）
部署基礎設施即程式碼的設定檢查、最小權限的雲端角色
營運監控、漏洞獎勵計畫、定期滲透測試

把這些自動化地放進 CI/CD 流程，稱為 DevSecOps。

不要把祕密寫進程式碼

  • API 金鑰、資料庫密碼、雲端憑證，一旦推上 GitHub，自動化的掃描機器人可能在幾分鐘內就找到並濫用——例如用你的雲端帳號挖礦，帳單暴增。
  • 刪掉最新的 commit 沒有用，祕密還在 Git 的歷史紀錄中；必須立刻撤銷並更換那把金鑰。
  • 使用環境變數或專門的祕密管理服務；在 Git 設定中忽略 .env 等檔案；開啟 GitHub 的祕密掃描。

安全的預設

好的框架與工具，讓「正確的做法」成為「最容易的做法」：預設自動跳脫輸出（第 14 課）、預設使用參數化查詢（第 13 課）、預設 HttpOnly 與 SameSite 的 Cookie（第 10 課）。開發者不需要記住每一條規則，系統就預設安全。

AI 寫的程式碼

用 AI 助手寫程式越來越普遍。研究發現，AI 產生的程式碼也可能含有注入、弱加密等漏洞，甚至「發明」不存在的套件名稱，被攻擊者搶先註冊。AI 寫的程式碼，仍然需要審查與測試。

🧭 這一課的重點

設計階段發現安全問題成本最低，上線後才發現則需緊急修補與賠償，安全左移是把安全工作移到開發流程前面。各階段做法：需求設計做威脅建模、撰寫時用安全規範與框架並審查、建置時做 SAST、依賴與祕密掃描、測試時做 DAST 與模糊測試、部署時檢查設定與最小權限、營運時監控與漏洞獎勵，自動化放入 CI/CD 稱為 DevSecOps。API 金鑰推上 GitHub 可能幾分鐘內被掃描濫用，刪 commit 無用必須撤銷更換，應使用環境變數或祕密管理服務。好的框架讓正確做法成為最容易的做法。AI 產生的程式碼也可能有漏洞或虛構套件名，仍需審查。

🛡️ 本課程只介紹攻擊的原理與防禦方法，所有示範都是在瀏覽器內的模擬，不會連線到任何系統。未經授權入侵他人系統是違法行為（刑法第 358～363 條妨害電腦使用罪）；想練習請使用合法的靶場與 CTF。
