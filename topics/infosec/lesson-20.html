記憶體漏洞與緩衝區溢位

這一課的目標

  • 理解緩衝區溢位的原理
  • 認識現代的緩解機制
  • 理解記憶體安全語言的意義

原理

C 與 C++ 讓程式直接操作記憶體，效率很高，但不會自動檢查邊界。如果程式準備了一塊 64 位元組的空間（緩衝區）存放使用者輸入，卻沒有檢查輸入的長度，多出來的資料就會覆蓋到相鄰的記憶體。

堆疊溢位：改寫返回位址

函式被呼叫時，電腦會在「堆疊」上記下函式結束後要回到哪裡（返回位址），緊鄰著區域變數。攻擊者精心構造過長的輸入，就能把返回位址改成自己想要的位置——讓程式在函式結束時，跳去執行攻擊者準備的程式碼。

[ 緩衝區 64 bytes ][ 其他資料 ][ 返回位址 ] [ AAAA…（過長的輸入）…AAAA ][ 被覆蓋 ][ 攻擊者的位址 ]

1988 年的莫里斯蠕蟲，就利用了 fingerd 程式中的緩衝區溢位（第 4 課）。

其他記憶體漏洞

  • 釋放後使用（use-after-free）：記憶體已經被釋放，程式卻還在使用它，攻擊者趁機在那裡放入自己的資料。瀏覽器的漏洞很多是這一類。
  • 整數溢位：長度計算溢位，導致配置了過小的緩衝區。
  • 越界讀取：讀到不該讀的記憶體，例如 2014 年的 Heartbleed 讓伺服器洩漏記憶體中的私鑰與密碼。

緩解機制

機制做法
堆疊保護值（canary）在返回位址前放一個隨機值，函式結束時檢查有沒有被改
不可執行記憶體（DEP／NX）存放資料的區域不能當作程式碼執行
位址空間隨機化（ASLR）每次執行時，程式與函式庫的位置都不同，攻擊者難以猜到要跳去哪裡
控制流程完整性（CFI）限制程式只能跳到合法的位置

這些機制讓攻擊變難，但攻擊者也發展出串接既有程式片段（ROP）等繞過技巧——這是一場持續的軍備競賽。

記憶體安全語言

微軟與 Google 都曾統計，他們產品中約七成的嚴重漏洞屬於記憶體安全問題。因此業界開始轉向 Rust、Go、Java 等會自動檢查邊界或管理記憶體的語言；美國政府機關也建議新專案優先採用記憶體安全語言。

🧭 這一課的重點

C 與 C++ 不自動檢查邊界，輸入超過緩衝區時會覆蓋相鄰記憶體。堆疊溢位改寫緊鄰區域變數的返回位址，讓程式跳去執行攻擊者的程式碼，莫里斯蠕蟲即利用 fingerd 的溢位。其他記憶體漏洞有釋放後使用、整數溢位與越界讀取，如 2014 年 Heartbleed 洩漏私鑰。緩解機制有堆疊保護值、不可執行記憶體、位址空間隨機化與控制流程完整性，但攻擊者發展出 ROP 等繞過技巧。微軟與 Google 統計約七成嚴重漏洞屬記憶體安全問題，業界轉向 Rust 等記憶體安全語言。
