API 安全

這一課的目標

  • 理解 API 為什麼成為主要的攻擊面
  • 認識常見的 API 漏洞
  • 掌握 API 的基本防護

API 無所不在

手機 App、單頁網站、物聯網裝置、企業之間的系統串接，背後都是 API（應用程式介面）：程式之間用固定的格式（多半是 JSON）互相請求資料。使用者看不到 API，但攻擊者可以輕易地攔截 App 的流量，看到每一個 API 的網址與參數。

常見的 API 漏洞

漏洞說明
物件層級授權失效API 版的 IDOR（第 17 課）：改 ID 就能拿到別人的資料，是 API 最常見的漏洞
過度回傳資料API 回傳整筆資料（含電話、地址、內部欄位），讓前端「自己挑要顯示的」——但攻擊者看得到全部
批量指派API 把請求中的所有欄位直接寫進資料庫，攻擊者多送一個 isAdmin: true 就變成管理員
缺乏限速沒有限制請求次數，可以暴力猜驗證碼、大量爬取資料
失控的舊版 API新版加了保護，舊版的 /v1/ 卻還開著
認證失效API 金鑰寫死在 App 裡、Token 不會過期

爬取與資料外洩

許多「外洩」事件其實沒有入侵任何伺服器，而是攻擊者利用設計不良的 API，大量爬取原本就「公開」的資料——例如用電話號碼查詢使用者的功能，搭配沒有限速，就能把整個平台的電話與帳號對應起來。

基本防護

  1. 每個端點都要認證與授權，檢查物件的擁有權。
  2. 只回傳前端需要的欄位（回應結構白名單）。
  3. 只接受允許的欄位（請求結構白名單）。
  4. 限速與異常偵測。
  5. 維護 API 清冊，下架不用的舊版本。
  6. 不要把金鑰與祕密放在 App 或前端程式碼中——它們一定會被找到。

🧭 這一課的重點

手機 App、單頁網站、物聯網與企業串接背後都是以 JSON 互相請求的 API，攻擊者能攔截流量看到每個 API。常見漏洞有物件層級授權失效（API 版 IDOR）、過度回傳資料、把所有欄位直接寫入的批量指派、缺乏限速、失控的舊版 API 與認證失效。許多外洩其實是利用設計不良的 API 大量爬取公開資料，如電話查詢加上無限速。防護包括每個端點認證授權並檢查擁有權、回應與請求欄位白名單、限速與異常偵測、維護 API 清冊下架舊版，以及不把金鑰放在 App 或前端。

🛡️ 本課程只介紹攻擊的原理與防禦方法，所有示範都是在瀏覽器內的模擬，不會連線到任何系統。未經授權入侵他人系統是違法行為（刑法第 358～363 條妨害電腦使用罪）；想練習請使用合法的靶場與 CTF。
