重大事件（二）：SolarWinds、Log4Shell 與 xz 後門

這一課的目標

  • 了解 SolarWinds 事件的經過
  • 理解 Log4Shell 為什麼影響如此廣泛
  • 了解 xz 後門被發現的過程

SolarWinds（2020）

  1. 攻擊者入侵了美國網管軟體公司 SolarWinds 的建置系統，在 Orion 產品的正式更新中植入後門。
  2. 這個帶有數位簽章的「正式更新」，被約 18,000 個客戶下載安裝。
  3. 攻擊者再從中挑選高價值的目標深入，包括美國多個聯邦機關與大型科技公司。
  4. 事件在 2020 年 12 月由資安公司 FireEye 發現——它自己也是受害者。美國政府將其歸因於俄羅斯對外情報局。

教訓：「可信的更新」本身也可能是攻擊管道；建置系統需要和正式產品一樣的保護。

Log4Shell（2021）

  • Log4j 是 Java 世界中極為普遍的記錄（日誌）函式庫，藏在無數的企業系統、雲端服務、遊戲伺服器中。
  • 漏洞 CVE-2021-44228：只要讓程式記錄一段特殊的字串（例如在聊天訊息、瀏覽器標頭中），Log4j 就會去連線外部伺服器並載入程式碼——遠端執行任意程式。
  • CVSS 評分 10 分（滿分）。最早的案例之一，是在《Minecraft》的聊天室中打一行字就能控制伺服器。
  • 最困難的是：許多公司根本不知道自己哪裡用了 Log4j——它常常是依賴的依賴（第 18 課的 SBOM 就是為此）。

xz utils 後門（2024）

  1. xz 是 Linux 上普遍使用的壓縮工具，由一位志工獨自維護。
  2. 一個化名「Jia Tan」的帳號，花了大約兩年熱心貢獻程式碼；同時有其他帳號在郵件列表上施壓，抱怨維護者進度太慢。
  3. Jia Tan 逐漸成為共同維護者，接著在發布的版本中，用極為隱密的方式藏入後門，目標是透過 SSH 遠端登入系統。
  4. 2024 年 3 月，微軟的工程師 Andres Freund 在做效能測試時，發現 SSH 登入慢了約半秒，追查之下發現了後門——當時它還沒進入主要 Linux 發行版的穩定版本。

開源的脆弱與強韌

xz 事件暴露了開源世界的脆弱：全球依賴的關鍵元件，可能只由一位疲憊的志工維護。但它也展現了開源的強韌：因為程式碼是公開的，一位好奇的工程師就能發現並阻止它。這也促使業界更重視資助與支持開源維護者。

🧭 這一課的重點

2020 年 SolarWinds 的建置系統被入侵，Orion 正式更新中植入後門，約 18,000 個客戶安裝，攻擊者再挑選美國聯邦機關與大型科技公司深入，FireEye 於 12 月發現，美國歸因於俄羅斯對外情報局，教訓是可信更新也可能是攻擊管道。2021 年 Log4Shell（CVE-2021-44228）讓普遍使用的 Java 日誌函式庫在記錄特殊字串時連外載入程式碼，可遠端執行任意程式，CVSS 10 分，最早案例之一是 Minecraft 聊天室，許多公司不知道自己哪裡用了它。2024 年化名 Jia Tan 的帳號花約兩年取得 xz 維護權並藏入 SSH 後門，微軟工程師 Andres Freund 因 SSH 登入慢約半秒而發現。開源既脆弱也強韌。
