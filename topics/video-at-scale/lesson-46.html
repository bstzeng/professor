模組 I｜轉碼：最貴的那道工 · 第 46 課

轉碼要多少算力

這一課的目標

  • 理解實時倍率這個單位
  • 算出一支影片的轉碼成本
  • 知道各編碼器的算力差距

1. 實時倍率

實時倍率 = 影片長度 / 編碼所需時間 2× 實時：一小時影片編 30 分鐘（比播放快） 1× 實時：一小時影片編一小時（剛好跟得上直播） 0.1× 實時：一小時影片要編 10 小時

直播要求至少 1× 實時（而且要有餘裕）， 點播則可以慢慢來。這是兩者的根本差異（第 16 課）。

2. 單核心的實時倍率（示意）

設定1080p30720p30360p30
H.264 極快3–6×10–20×40–80×
H.264 中等1–2×4–8×15–30×
H.264 高品質0.3–0.6×1–2×5–10×
VP9 高品質0.1–0.2×0.4–0.8×2–4×
AV1 高品質0.03–0.1×0.1–0.3×0.5–1.5×

（實際值依編碼器實作、CPU 世代與參數差異很大，這裡看的是量級關係。）

關鍵觀察：畫質每降一階，速度快 3–4 倍。 所以整個階梯的成本主要由最高畫質決定。

3. 一支影片的全階梯成本

一小時影片，H.264 中等品質，六階梯： 1080p @ 1.5× → 0.67 核心小時 720p @ 6× → 0.17 480p @ 12× → 0.08 360p @ 20× → 0.05 240p @ 35× → 0.03 144p @ 60× → 0.02 ───────── 合計約 1.0 核心小時 → 全階梯的成本約等於「1080p 單獨編一次」的 1.5 倍

這是個有用的經驗法則： 算全階梯時，用最高畫質的成本乘 1.5 就差不多了。

4. 加上其他編碼器

同一支影片： H.264 全階梯 約 1.0 核心小時 + VP9 全階梯 約 8 核心小時 + AV1 全階梯 約 25 核心小時 ────────────── 全部都編 約 34 核心小時

加上 AV1 讓成本變成 34 倍。 這就是為什麼不能每支影片都編 AV1， 必須分級（第 48 課）。

5. 其他處理的成本

工作相對成本
探測與驗證很低
縮圖與精靈圖低（只要解碼取樣）
語音辨識字幕中（一小時影片約 0.1–0.5 核心小時，用 GPU 更快）
自動翻譯低（按需產生）
版權指紋比對中（要與龐大資料庫比對）
內容分析（推薦用特徵）中至高（可能要跑視覺模型）

近年這些「非轉碼」的處理成本成長很快， 因為平台加入越來越多的自動化分析。 在某些情況下它們加起來已經可以與轉碼相比。

6. 為什麼不用 GPU 就好

GPU 有硬體編碼器，速度很快，但有取捨：

CPU 軟體編碼GPU 硬體編碼專用 ASIC
速度慢快最快
同位元率的畫質最好較差接近軟體（專門優化過）
彈性最高受硬體限制最低
每瓦效率差好最好
單位成本高中低（量夠大時）

GPU 編碼器是為了遊戲直播設計的， 重視速度勝於壓縮效率。對平台來說， 壓縮效率差 20% 意味著頻寬成本多 20%—— 那個數字太大，所以他們寧可自己做 ASIC。下一課處理。
