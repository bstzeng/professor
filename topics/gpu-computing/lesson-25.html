CUDA 的護城河

這一課的目標

  • 理解軟體生態的重要
  • 了解 CUDA 生態的組成
  • 思考開放與封閉的取捨

硬體容易複製，生態很難

其他公司也能做出峰值運算相近的晶片，但 NVIDIA 最大的優勢不只是硬體，而是近二十年累積的軟體生態：

  • 函式庫：cuBLAS（線性代數）、cuDNN（深度學習）、cuFFT、NCCL（通訊）、TensorRT（推論）……每一個都針對每一代硬體精心調校。
  • 框架：PyTorch、TensorFlow、JAX 最早、最完整地支援 CUDA。
  • 開發者：數百萬名熟悉 CUDA 的工程師與研究者，大學課程與教科書。
  • 相容性：十多年前寫的 CUDA 程式，仍能在新的 GPU 上執行。

一個研究者想嘗試新的想法，在 NVIDIA 的 GPU 上「就是能跑」；換到其他平台，可能要花數週處理相容性問題。這種轉換成本，就是所謂的「護城河」。

挑戰者

  • AMD ROCm／HIP：與 CUDA 相似的程式模型，提供工具把 CUDA 程式轉換過去。
  • Triton、MLIR 等編譯器：讓開發者寫高階的程式，由編譯器產生各種硬體的程式碼，降低對 CUDA 的依賴。
  • PyTorch 的硬體抽象：讓大部分使用者不必直接接觸 CUDA。

開放的標準能促進競爭與降低成本；但一個由單一公司主導、緊密整合的生態，也常常更穩定、更快速。這是科技產業中反覆出現的取捨。

🧭 這一課的重點

其他公司能做出峰值相近的晶片，但 NVIDIA 最大優勢是近二十年累積的軟體生態：cuBLAS cuDNN cuFFT NCCL TensorRT 針對每代調校的函式庫、PyTorch TensorFlow JAX 最早最完整支援、數百萬熟悉 CUDA 的開發者與課程教科書、十多年前的程式仍能在新 GPU 執行；研究者在 NVIDIA 上就是能跑，換平台要花數週處理相容性，這轉換成本就是護城河；挑戰者有 AMD ROCm HIP 提供轉換工具、Triton MLIR 等編譯器降低依賴、PyTorch 硬體抽象；開放標準促進競爭降成本，單一公司緊密整合常更穩定快速，是反覆出現的取捨。
