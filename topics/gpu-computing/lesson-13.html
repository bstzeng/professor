第一個 kernel

這一課的目標

  • 認識 CUDA 程式的結構
  • 理解 kernel 與 host 的分工
  • 寫出第一個 GPU 程式

主機與裝置

CUDA 程式分成兩部分：在 CPU 上執行的主機（host）程式，以及在 GPU 上執行的裝置（device）程式。在 GPU 上平行執行的函式叫做 kernel，用 __global__ 標記。

// 每個執行緒負責一個元素 __global__ void vecAdd(const float* a, const float* b, float* c, int n) { int i = blockIdx.x * blockDim.x + threadIdx.x; // 我是第幾號執行緒？ if (i < n) c[i] = a[i] + b[i]; // 超出範圍的執行緒不做事 } int main() { int n = 1 << 20; // 約一百萬個元素 size_t bytes = n * sizeof(float); float *a, *b, *c; // 指向 GPU 記憶體的指標 cudaMalloc(&a, bytes); cudaMalloc(&b, bytes); cudaMalloc(&c, bytes); // ……用 cudaMemcpy 把資料從 CPU 複製到 GPU…… int threads = 256; int blocks = (n + threads - 1) / threads; // 無條件進位 vecAdd<<<blocks, threads>>>(a, b, c, n); // 啟動約一百萬個執行緒 // ……用 cudaMemcpy 把結果複製回 CPU，最後 cudaFree…… }

重點

  • 沒有迴圈：CPU 版本會寫 for (i = 0; i < n; i++)；GPU 版本把迴圈「攤開」，每一圈由一個執行緒負責。
  • <<<blocks, threads>>>：啟動 kernel 的特殊語法，指定要多少個區塊、每個區塊多少執行緒。
  • 邊界檢查：執行緒的總數會被進位成區塊大小的倍數，多出來的執行緒必須什麼都不做。
  • 記憶體的配置與複製：cudaMalloc、cudaMemcpy——資料必須先搬到 GPU。

這個 kernel 的運算強度很低（第 11 課），它的速度幾乎完全由記憶體頻寬決定。但它展示了 CUDA 最基本的模式：一個執行緒處理一筆資料。

🧭 這一課的重點

CUDA 程式分在 CPU 執行的主機程式與在 GPU 執行的裝置程式，GPU 上平行執行的函式叫 kernel 用 __global__ 標記；向量相加 kernel 用 blockIdx.x*blockDim.x＋threadIdx.x 算出自己的編號，i < n 才計算；重點是沒有迴圈把迴圈攤開每圈一個執行緒、<<<blocks, threads>>> 指定區塊數與每區塊執行緒數、執行緒總數進位成區塊倍數多的要什麼都不做、cudaMalloc cudaMemcpy 先把資料搬到 GPU；這 kernel 運算強度低速度由頻寬決定，但展示了一個執行緒處理一筆資料的基本模式。
