同步與原子操作

這一課的目標

  • 理解區塊內的同步
  • 理解競爭條件與原子操作
  • 學會平行歸約

__syncthreads()

同一個區塊的執行緒，可以用 __syncthreads() 設下一道「柵欄」：所有執行緒都到達這裡，才一起往下走。上一課的 tiling 就需要它：必須等所有人都把資料載入共享記憶體，才能開始計算。

注意：如果 __syncthreads() 放在只有部分執行緒會進入的 if 裡面，其他執行緒永遠到不了柵欄，程式就會卡住或出錯。

競爭條件

如果一百萬個執行緒都執行 count = count + 1，結果幾乎不會是一百萬。因為「讀取—加一—寫回」不是一個不可分割的動作：兩個執行緒可能同時讀到 5，各自加一，都寫回 6——一次加法就消失了。這叫做競爭條件。

原子操作

atomicAdd(&count, 1) 保證「讀取—加一—寫回」不會被打斷。但如果大量執行緒同時對同一個位址做原子操作，它們必須排隊，效能會很差。

平行歸約

要加總 n 個數，更好的方法是樹狀歸約：第一輪，一半的執行緒各把兩個數相加；第二輪，再兩兩相加……經過 log₂n 輪就得到總和。在一個區塊內用共享記憶體完成，每個區塊得到一個部分和，最後再把各區塊的部分和加起來。

for (int s = blockDim.x / 2; s > 0; s >>= 1) { if (tid < s) sdata[tid] += sdata[tid + s]; __syncthreads(); } // 迴圈結束後，sdata[0] 就是這個區塊的總和

注意：浮點數的加法不滿足結合律，平行歸約的結果可能和依序相加略有不同——這是平行計算中「結果不完全可重現」的來源之一。

🧭 這一課的重點

同區塊執行緒用 __syncthreads() 設柵欄，全部到達才一起往下，tiling 需要它，放在只有部分執行緒進入的 if 內會卡住；一百萬執行緒執行 count＝count＋1 結果幾乎不會是一百萬，讀取加一寫回可分割，兩執行緒同時讀 5 都寫回 6 叫競爭條件；atomicAdd 保證不被打斷，但大量執行緒對同位址原子操作要排隊效能差；加總用樹狀歸約，每輪一半執行緒兩兩相加 log₂n 輪得總和，區塊內用共享記憶體得部分和再合併；浮點加法不滿足結合律平行歸約結果可能與依序相加略不同，是不完全可重現的來源。
