執行緒、區塊與網格

這一課的目標

  • 理解執行緒的階層
  • 學會計算全域索引
  • 理解區塊如何對應到硬體

三層結構

  • 執行緒（thread）：最小的執行單位。
  • 區塊（block）：一群執行緒（最多 1,024 個），被分配到同一個 SM 上執行，可以使用共享記憶體與同步。
  • 網格（grid）：一次 kernel 啟動的所有區塊。

區塊與網格都可以是一維、二維或三維的，方便對應影像（二維）或體積資料（三維）。例如處理一張 1920×1080 的影像，可以用 16×16 的區塊，網格大小 120×68。

__global__ void brighten(unsigned char* img, int W, int H) { int x = blockIdx.x * blockDim.x + threadIdx.x; int y = blockIdx.y * blockDim.y + threadIdx.y; if (x < W && y < H) { int v = img[y * W + x] + 40; img[y * W + x] = v > 255 ? 255 : v; } } // 啟動：dim3 block(16, 16); dim3 grid((W + 15) / 16, (H + 15) / 16);

區塊之間是獨立的

一個重要的規則：區塊之間不能假設執行的順序，也不能互相等待。GPU 會依照自己的 SM 數量，把區塊分批送上去執行。這讓同一個程式可以在只有幾個 SM 的筆電 GPU 上執行，也可以在有一百多個 SM 的資料中心 GPU 上執行——只是快慢不同。這叫做透明的可擴展性。

如果需要所有區塊都完成某一步，才能進行下一步，通常的做法是把它拆成兩次 kernel 啟動。

🧭 這一課的重點

三層結構：執行緒是最小單位、區塊是一群執行緒最多 1,024 個分配到同一 SM 可用共享記憶體與同步、網格是一次啟動的所有區塊；區塊與網格可一二三維方便對應影像體積，1920×1080 影像用 16×16 區塊網格 120×68，二維 kernel 用 x y 兩個索引並檢查邊界；區塊之間不能假設執行順序也不能互相等待，GPU 依 SM 數分批執行，同程式能在少 SM 的筆電與一百多 SM 的資料中心 GPU 執行只是快慢不同叫透明可擴展性；需全部區塊完成才能下一步就拆成兩次 kernel 啟動。
