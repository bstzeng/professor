串流與非同步

這一課的目標

  • 理解 kernel 的非同步啟動
  • 理解 CUDA 串流
  • 學會重疊資料傳輸與計算

非同步

CPU 啟動一個 kernel 後，不會等它算完，而是立刻繼續執行下一行。GPU 在背景工作。只有在需要結果（例如把資料複製回來）或明確呼叫同步函式時，CPU 才會等待。

串流

串流（stream）是一個工作佇列：同一個串流中的工作依序執行，不同串流中的工作可以同時進行。

重疊傳輸與計算

假設要處理一大批資料：傳上 GPU、計算、傳回。依序做的話，GPU 在傳輸時閒著，傳輸線在計算時閒著。把資料切成幾份，放在不同的串流：

時間 →12345
串流 1上傳計算下載
串流 2上傳計算下載
串流 3上傳計算下載

像工廠的生產線一樣，各階段同時進行，總時間大幅縮短。這需要 CPU 端使用「鎖定頁面」的記憶體（pinned memory），讓 GPU 能直接存取。

CUDA Graphs

對於重複執行、由許多小 kernel 組成的工作（例如神經網路的每一步），每次啟動 kernel 的開銷（數微秒）會累積起來。CUDA Graphs 把整串工作錄製成一張圖，之後一次啟動，大幅減少開銷——LLM 推論引擎常用這個技巧。

效能分析

最佳化之前，先測量：NVIDIA 的 Nsight Systems 可以畫出 CPU 與 GPU 的時間軸，看出哪裡在等待；Nsight Compute 可以分析單一 kernel 的記憶體與運算使用率。「不要猜，要量」是效能工程的第一原則。

🧭 這一課的重點

CPU 啟動 kernel 後不等它算完立刻往下，GPU 背景工作，需要結果或明確同步時才等；串流是工作佇列，同串流依序不同串流可同時；處理大批資料依序做 GPU 傳輸時閒著，切成幾份放不同串流讓上傳計算下載像生產線同時進行大幅縮短時間，需 CPU 端鎖定頁面記憶體；CUDA Graphs 把許多小 kernel 錄製成一張圖一次啟動減少數微秒的啟動開銷，LLM 推論引擎常用；最佳化前先測量，Nsight Systems 畫時間軸、Nsight Compute 分析單一 kernel，不要猜要量。
