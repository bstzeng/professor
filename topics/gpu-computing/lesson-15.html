合併存取

這一課的目標

  • 理解記憶體交易
  • 理解合併存取
  • 認識常見的存取模式

記憶體一次搬一段

全域記憶體不是一個位元組一個位元組地讀取，而是以一段連續的區塊（例如 32 或 128 位元組）為單位。當一個 warp 的 32 個執行緒發出讀取請求，硬體會看它們要的位址落在幾段裡：

  • 合併存取：32 個執行緒讀取連續的 32 個 float（共 128 位元組）——只需要一次記憶體交易。
  • 跨步存取：執行緒 i 讀取第 i × 32 個元素——32 個請求落在 32 個不同的段，需要 32 次交易，頻寬利用率只剩約 1/32。

矩陣的列與行

C 語言的二維陣列是以列為主儲存的：同一列的元素在記憶體中相鄰。如果相鄰的執行緒處理同一列的相鄰元素，存取是合併的；如果相鄰的執行緒處理同一行（往下）的元素，就變成跨步存取。所以矩陣轉置是 GPU 程式設計的經典練習：要讀得合併、寫得也合併，必須借助共享記憶體（下一課）。

結構陣列與陣列結構

// 結構陣列（AoS）：x 之間隔著 y、z——跨步存取 struct P { float x, y, z; }; P pts[N]; // 陣列結構（SoA）：所有的 x 連在一起——合併存取 struct Ps { float x[N], y[N], z[N]; };

在 CPU 上，結構陣列很自然；在 GPU 上，陣列結構往往快得多。這是一個「資料布局決定效能」的好例子。

🧭 這一課的重點

全域記憶體以一段連續區塊（32 或 128 位元組）為單位讀取，硬體看一個 warp 的 32 個請求落在幾段；合併存取 32 執行緒讀連續 32 個 float 共 128 位元組只需一次交易，跨步存取 i×32 落在 32 段需 32 次交易頻寬利用約 1/32；C 二維陣列以列為主，相鄰執行緒處理同列相鄰元素是合併，處理同行往下是跨步，矩陣轉置是經典練習須借助共享記憶體；結構陣列 AoS 的 x 隔著 y z 是跨步，陣列結構 SoA 所有 x 連在一起是合併，GPU 上 SoA 往往快得多，資料布局決定效能。
