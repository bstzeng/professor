讓模型思考

這一課的目標

  • 理解「先思考再回答」的作用
  • 認識內建思考功能與 effort
  • 知道何時需要、何時不需要思考

複雜的問題——數學、邏輯、多步驟分析——讓模型先想再答，正確率會明顯提高。早期的做法是在提示中加上「請一步一步思考」，並要求把推理寫在 <thinking> 標籤裡。

現在的主流模型大多有內建的思考功能：模型在回答前自行推理，推理過程與最終回答分開。以 Claude 最新的模型為例，思考是自適應的——模型自己判斷需要想多少；開發者用 effort 參數（low、medium、high 等）控制整體的深度與花費。

任務建議
簡單問答、分類、格式轉換低 effort，快又省
一般寫作與分析中等
困難的程式、數學、長時間的代理任務高 effort
  • 思考也要付費：思考的 token 算在輸出中。
  • 給思考方向，而不是步驟：「先列出可能的原因，再逐一排除」這種引導有幫助；但把每一步都寫死，常常不如讓模型自己想。
  • 要求驗證：「回答前，用一個例子檢查你的答案」是很有效的指示。

☁️ Claude API 範例（需要 pip install anthropic 與 API 金鑰）　開啟思考並調整 effort

import anthropic client = anthropic.Anthropic() r = client.messages.create( model="claude-opus-5-5", max_tokens=16000, thinking={"type": "adaptive", "display": "summarized"}, # 回傳可讀的思考摘要 output_config={"effort": "high"}, # low / medium / high / xhigh / max messages=[{"role": "user", "content": "球棒和球共 110 元，球棒比球貴 100 元，球多少錢？回答前先驗算。"}], ) for b in r.content: print(b.type, getattr(b, "thinking", "") or getattr(b, "text", ""))

🧭 這一課的重點

讓模型先思考可提升複雜問題的正確率。現代模型多有內建自適應思考，用 effort 控制深度與花費：簡單任務低、困難程式與代理任務高。思考 token 要付費；給方向而非寫死步驟，並要求回答前驗證。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

  3. 為什麼「給方向」比「寫死每一步」更好？
