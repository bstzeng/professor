錯誤恢復

這一課的目標

  • 設計幫助代理恢復的提示
  • 避免代理重複同樣的錯誤
  • 知道何時應該放棄並求助

代理一定會遇到失敗：指令出錯、測試不過、工具回傳錯誤。提示要告訴它失敗時怎麼做：

  1. 先理解錯誤：讀完錯誤訊息，找出原因，而不是立刻換一個方法亂試。
  2. 不要重複：同樣的方法失敗兩次，就換方向。
  3. 不要繞過：例如不要為了讓測試通過而修改或刪除測試。
  4. 知道何時停：試了幾種方法都不行時，停下來回報，說明試過什麼、可能的原因。
✗ 改寫前
如果出錯就再試一次。
✓ 改寫後
遇到錯誤時： 1. 先完整閱讀錯誤訊息，判斷原因 2. 根據原因修正；同一個方法失敗兩次就換一種思路 3. 不要修改測試或刪除檢查來「通過」 4. 嘗試三種不同方法仍失敗時，停下來向使用者說明：試過的方法、各自的結果、你認為的根本原因
  • 把「再試一次」改成有步驟的恢復策略
  • 明確禁止常見的「作弊」行為
  • 給出放棄並求助的條件

錯誤恢復也需要好的工具錯誤訊息（第 24 課）：錯誤訊息越清楚，模型越能正確修正。

🧭 這一課的重點

錯誤恢復的提示要指示代理：先完整理解錯誤再修正、同方法失敗兩次就換方向、不以修改測試等方式繞過、多次嘗試仍失敗時停下回報試過的方法與可能原因。清楚的工具錯誤訊息也是錯誤恢復的基礎。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。
