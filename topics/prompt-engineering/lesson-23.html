工具呼叫（一）：工具說明就是提示

這一課的目標

  • 理解工具說明對模型行為的影響
  • 寫出清楚的工具說明
  • 知道何時該用、何時不該用的描述

讓模型使用工具（查資料、計算、呼叫 API）時，模型決定「要不要用、用哪個、填什麼參數」的依據，只有工具的名稱、說明與參數描述。這些文字就是提示。

✗ 改寫前
name: search description: 搜尋 parameters: q: string
✓ 改寫後
name: search_orders description: 依客戶 email 搜尋訂單，回傳最近 20 筆的訂單編號、日期、金額與狀態。 客戶詢問訂單狀況、配送進度、退款進度時使用。 若客戶只提供訂單編號，請改用 get_order。 parameters: email: 客戶的 email（必填） status: 篩選狀態，可選 pending / shipped / delivered（選填）
  • 名稱具體：動詞＋名詞
  • 說明做什麼、回傳什麼、何時用
  • 說明何時不該用、該改用哪個工具
  • 參數附說明與可選值
  • 工具之間的邊界：兩個工具功能相近時，說明清楚各自的使用時機，避免模型選錯。
  • 工具數量：太多工具會讓模型難以選擇；把常一起使用的功能合併，或按需載入。
  • 在系統提示中補充策略：例如「回答價格問題前，一定先用 get_price 查最新價格」。

🧭 這一課的重點

模型決定是否用工具、用哪個、填什麼參數，依據只有工具名稱、說明與參數描述，這些就是提示。好的說明包括具體名稱、做什麼回傳什麼、何時用與何時不該用、參數說明與可選值；功能相近的工具要劃清邊界，控制工具數量並在系統提示補充使用策略。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

檢查你的理解

  1. 模型依據什麼決定使用哪個工具？
  2. 好的工具說明應包含哪些內容？
  3. 為什麼要說明「何時不該用」？
