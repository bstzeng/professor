換模型時的提示遷移

這一課的目標

  • 理解換模型時提示可能失效的原因
  • 規劃提示遷移的步驟
  • 清理過時的提示寫法

模型升級時，舊提示不一定會自動變好。常見的情況：

現象原因處理
變得過度謹慎或過度積極為舊模型寫的「全部大寫」「一定要」等強調語氣，新模型會過度執行降低強調語氣，用平實的說明
不再需要的技巧舊模型需要的「逐步思考」咒語，新模型已內建思考移除，改用 API 的思考設定
API 參數改變例如新模型不支援預填回覆、某些取樣參數改用結構化輸出、系統提示指令
行為細節不同長度、格式、語氣的預設值不同用測試集找出差異再調整
  1. 用舊模型跑測試集，記錄基準分數
  2. 不改提示，直接用新模型跑，比較差異
  3. 針對差異修改提示（一次一件事）
  4. 清理過時的技巧，確認分數沒有下降
  5. 小流量上線、觀察後再全面切換

刪除也是優化

很多提示累積了為舊模型寫的補丁。遷移是清理的好時機：刪掉一條規則後如果測試分數不變，它就不需要存在。

🧭 這一課的重點

換模型時舊提示可能失效：強調語氣被過度執行、內建思考讓舊咒語多餘、API 參數改變、預設行為不同。遷移步驟是先用舊模型建立基準、直接換模型比較、針對差異逐一修改、清理過時技巧並確認分數、小流量上線。刪除不再需要的規則也是優化。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。
