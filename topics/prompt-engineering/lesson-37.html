長任務的提示

這一課的目標

  • 處理長任務特有的問題
  • 讓代理有預算意識
  • 避免過早宣告完成

跑幾十步、甚至數小時的任務，會出現短任務沒有的問題：

問題表現提示對策
過早宣告完成做了一半就說「完成了」明確的完成條件＋要求列出驗證證據
範圍蔓延越做越多，改了不需要改的重申範圍；額外發現記下來但不處理
忘記目標上下文太長，偏離原始要求在待辦清單中保留原始目標；定期回顧
預算耗盡做到一半用完 token 或時間告知預算；接近時優先收尾、記錄進度
在宣告完成之前，逐項確認並列出證據： - 原始需求的每一點是否都已處理？（逐條對照） - 相關測試的執行結果（貼上摘要） - 有沒有尚未處理、需要使用者知道的事項 如果工作量超出這次能完成的範圍，優先把已完成的部分整理好，並在 progress.md 寫下剩下的工作，而不是匆忙完成所有事情。

有些 API 提供「任務預算」功能，讓模型知道整個任務還剩多少 token，模型會據此調整節奏、在預算內優雅收尾。提示中也可以直接說明時間或步數的限制。

🧭 這一課的重點

長任務常見過早宣告完成、範圍蔓延、忘記目標與預算耗盡。對策是明確完成條件並要求列出驗證證據、重申範圍並記錄但不處理額外發現、在待辦中保留原始目標、告知預算並在接近時優先收尾與記錄進度。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。
