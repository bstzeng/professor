Level 0｜先理解模型怎麼「讀」提示 · 第 2 課

system、user、assistant

這一課的目標

  • 理解三種角色的分工
  • 知道什麼內容該放在 system
  • 了解對話歷史對行為的影響
角色放什麼例子
system整段對話都適用的設定：身分、背景、規則、語氣、輸出慣例「你在協助一家寵物用品店回覆客服信件，回覆使用繁體中文……」
user這一次的任務與資料；在工具使用中，也是工具結果的位置「這是客人的來信：……」
assistant模型先前的回應之前的回答會影響之後的風格與決定
  • 穩定的放 system，變動的放 user：每次都一樣的規則放在 system；這次才有的資料放在 user。這也有利於提示快取（第 25 課）。
  • 對話歷史會「教」模型：如果前面的回答都很長，模型往後也傾向寫長；前面犯的錯如果沒糾正，可能會延續。
  • 預填已不適用：過去常見的技巧是先替模型寫好回答的開頭（例如先寫一個「{」逼它輸出 JSON）。在最新一代的 Claude 模型上，這種「預填」已不被支援；要控制格式，改用結構化輸出（第 12 課）或在指令中說明。

🧭 這一課的重點

system 放整段對話都適用的身分、背景、規則與輸出慣例，user 放這次的任務與資料（也是工具結果的位置），assistant 是模型回應且會影響後續風格。穩定內容放 system、變動放 user；新一代 Claude 已不支援預填，格式改用結構化輸出控制。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

  2. 為什麼對話歷史會影響模型之後的行為？
  3. 預填技巧在新模型上有什麼變化？
