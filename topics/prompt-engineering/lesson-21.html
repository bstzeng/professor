RAG（二）：讓模型老實回答

這一課的目標

  • 寫出有據可查的 RAG 提示
  • 要求引用來源
  • 讓模型在資料不足時承認不知道

檢索到資料之後，提示要確保模型根據資料回答，而不是憑記憶或想像。三個關鍵指令：

  1. 只根據提供的資料：明確說明資料以外的知識不能用（或要分開標示）。
  2. 標註出處：每個說法附上來源編號，方便檢查。
  3. 允許說不知道：資料不足時，說「資料中沒有提到」比編造好。這一句非常重要——沒有它，模型傾向硬擠出答案。

🐍 Python 範例（離線可執行，已實際執行）　組出一個嚴格的 RAG 提示

# 組出一個 RAG 提示：檢索結果 + 嚴格的回答規則 hits = [ ("退貨政策.pdf", "商品到貨 7 天內可申請退貨，需保持包裝完整。"), ("FAQ", "退款會在退貨審核通過後 5 個工作天內退回原付款方式。"), ] question = "退貨後多久會拿到錢？運費誰出？" docs = "\n".join( '<document index="%d" source="%s">%s</document>' % (i, src, text) for i, (src, text) in enumerate(hits, 1)) prompt = """<documents> %s </documents> 只根據上面的文件回答問題，每個說法後面用 [編號] 標註來源。 文件沒有提到的部分，請明確寫「文件中沒有提到」，不要自行推測。 問題：%s""" % (docs, question) print(prompt)

▶ 執行結果

<documents> <document index="1" source="退貨政策.pdf">商品到貨 7 天內可申請退貨，需保持包裝完整。</document> <document index="2" source="FAQ">退款會在退貨審核通過後 5 個工作天內退回原付款方式。</document> </documents> 只根據上面的文件回答問題，每個說法後面用 [編號] 標註來源。 文件沒有提到的部分，請明確寫「文件中沒有提到」，不要自行推測。 問題：退貨後多久會拿到錢？運費誰出？

注意這個問題的設計：「運費誰出」在文件中找不到。好的提示會讓模型回答前半題、並老實說後半題文件沒有提到——這正是要測試的行為（第 40 課）。

🧭 這一課的重點

RAG 提示要確保模型根據資料回答：明確只用提供的資料、每個說法標註來源編號、資料不足時允許並要求說「文件中沒有提到」。最後一點非常重要，否則模型傾向硬擠出答案；測試時應刻意包含資料中找不到的問題。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。
