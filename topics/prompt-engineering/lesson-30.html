規劃者與執行者

這一課的目標

  • 理解規劃者與執行者的分工
  • 寫出規劃者與執行者的提示
  • 設計兩者之間的交接格式

複雜任務常分成兩種角色：規劃者看全局、拆解任務；執行者專心完成一個子任務。兩者的提示重點完全不同：

規劃者提示執行者提示
重點怎麼拆、順序、相依關係怎麼把一件事做好
需要的上下文整體目標、限制、可用資源只需要這個子任務的資訊
輸出結構化的計畫（JSON 清單）子任務結果＋簡短回報
常用模型較強的模型可以用較快、較便宜的模型
（規劃者） 把使用者的目標拆成 3–6 個子任務。每個子任務要能獨立完成，並寫清楚： - goal：要完成什麼（一句話） - inputs：需要哪些資訊 - done_when：怎樣算完成 子任務之間若有先後順序，用 depends_on 標示。以 JSON 陣列輸出。
（執行者） 你負責一個子任務，不需要考慮整體計畫。 <task>{goal}</task> <inputs>{inputs}</inputs> <done_when>{done_when}</done_when> 完成後回報：結果、遇到的問題、你不確定的地方。不確定的地方不要猜，直接說明。

關鍵是交接格式：規劃者給執行者的資訊要足夠完整（執行者看不到全局），執行者回報要包含「不確定之處」，讓規劃者能調整計畫。

🧭 這一課的重點

規劃者看全局拆解任務，執行者專注完成一個子任務。規劃者提示著重拆法、順序與相依，輸出結構化計畫，常用強模型；執行者提示只給子任務所需資訊，回報結果、問題與不確定之處，可用較便宜模型。關鍵在交接格式要完整。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

檢查你的理解

  1. 規劃者與執行者的提示重點有什麼不同？
  2. 為什麼執行者要回報「不確定的地方」？
  3. 每個子任務應該包含哪些資訊？
