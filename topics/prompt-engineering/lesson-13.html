限制條件

這一課的目標

  • 寫出有效的限制條件
  • 用正面描述取代禁止
  • 處理限制之間的衝突

限制條件讓輸出符合實際需求：字數、語氣、要避開的內容、必須遵守的規則。寫限制條件時有幾個原則：

  1. 說要什麼，而不是不要什麼：「不要用艱深的字」→「用國中生看得懂的詞」。
  2. 給數字：「簡短」→「100 字以內」。
  3. 說明理由（第 6 課）：讓模型知道限制的目的。
  4. 標明優先順序：限制衝突時哪一條優先。
✗ 改寫前
不要太長、不要太正式、不要用條列、不要提到競爭對手、不要太推銷。
✓ 改寫後
寫一段 120 字左右的產品介紹，語氣像店員跟熟客聊天。 重點放在我們產品本身的優點；不比較其他品牌，因為我們的品牌規範不允許。 用一段流暢的文字，最後一句自然地提到週末有試用活動。
  • 五個「不要」改成正面描述與具體數字
  • 保留一個必要的禁止事項，並附上理由

字數的注意事項

模型對「精確字數」的控制並不完美，特別是中文。需要嚴格上限時，在程式中檢查並要求重寫；用「三句話」「兩段」這種結構性的限制，通常比精確字數可靠。

🧭 這一課的重點

有效的限制條件：說要什麼而非不要什麼、給具體數字、說明理由、標明衝突時的優先順序。必要的禁止事項要附理由；模型對精確字數控制不完美，嚴格上限要用程式檢查，結構性限制（幾句、幾段）較可靠。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

檢查你的理解

  1. 寫限制條件有哪四個原則？
  2. 把「不要太長、不要太正式」改寫成正面描述。
  3. 為什麼「三句話」比「87 字」可靠？
