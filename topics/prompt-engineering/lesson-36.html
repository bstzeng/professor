自主程度的控制

這一課的目標

  • 在提示中設定代理的自主程度
  • 依風險決定是否需要確認
  • 避免過度詢問與過度自主

代理太常問人，使用者會覺得煩；太少問人，可能做出無法挽回的事。提示要清楚劃出界線，最好的依據是可逆性與影響範圍：

動作類型例子建議
唯讀、可逆讀檔、搜尋、跑測試直接做
本地修改、容易回復修改專案檔案（有版本控制）直接做，完成後說明
影響他人或難以回復推送程式碼、寄信、發布先問
不可逆或高風險刪除資料、付款、修改正式環境一律先問
✗ 改寫前
重要的事情要先問我。
✓ 改寫後
可以直接進行：讀取檔案、執行測試、修改專案內的程式碼（都有 git 可以回復）。 需要先詢問：推送到遠端、刪除檔案、安裝新套件、任何會影響專案以外的動作。 需求不明確時：如果有一個明顯合理的做法，直接採用並在最後說明你的假設；如果有多種同樣合理但結果差很多的做法，先問。
  • 把「重要」換成具體的動作清單
  • 依可逆性分級
  • 說明需求不明確時的處理原則

🧭 這一課的重點

代理自主程度要依可逆性與影響範圍劃界：唯讀可逆的直接做、本地可回復的修改直接做並說明、影響他人或難回復的先問、不可逆高風險的一律先問。把「重要的事先問」改成具體動作清單，並說明需求不明確時何時自行假設、何時詢問。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

檢查你的理解

  1. 決定是否需要先詢問的兩個依據是什麼？
  2. 舉出一個應該直接做和一個應該先問的動作。
  3. 需求不明確時，提示可以怎麼指示？
