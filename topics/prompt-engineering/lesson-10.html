Zero-shot 還是 Few-shot

這一課的目標

  • 判斷何時需要範例
  • 了解範例的成本
  • 學會用描述取代範例

範例很強大，但不一定需要。現代模型的zero-shot（沒有範例）能力很強，許多常見任務只要說清楚就夠了。

情況建議
常見任務：摘要、翻譯、一般寫作先試 zero-shot，說清楚要求
特殊的格式或風格給範例
分類標準很主觀給範例，特別是邊界案例
希望輸出有創意、多樣少給或不給範例，避免模型只會模仿
成本敏感、提示很長用描述取代範例，或只給一個最典型的
✗ 改寫前
<example>好</example> <example>非常好</example> <example>極好</example> 請用類似的方式評價這部電影。
✓ 改寫後
請用一到兩個詞評價這部電影的整體觀感，從「很差、普通、不錯、很好、傑作」中選一個。
  • 簡單的任務，直接描述比給範例更清楚，也更省 token

實務上的順序：先用 zero-shot 試，看輸出哪裡不對，再針對那些地方加範例。這比一開始就塞滿範例更有效率。

🧭 這一課的重點

現代模型 zero-shot 能力強，常見任務說清楚就夠；特殊格式、主觀分類標準適合給範例，追求創意多樣時少給範例，成本敏感時用描述取代。實務上先試 zero-shot，再針對錯誤處補範例。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

檢查你的理解

  1. 什麼情況適合用 zero-shot？
  2. 為什麼想要創意時要少給範例？
  3. 建議的「先 zero-shot、後補範例」流程是什麼？
