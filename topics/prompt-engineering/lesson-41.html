評估（二）：怎麼評分

這一課的目標

  • 比較三種評分方式
  • 寫出 LLM 評審的提示
  • 用計分板比較提示版本
評分方式適合優點缺點
規則／程式格式、關鍵字、數值、分類標籤快、便宜、完全一致無法判斷語意與品質
LLM 評審語氣、是否回答問題、是否根據資料可規模化、能判斷語意本身也會出錯，要校準
人工最終品質、細微判斷最可靠慢、貴、不同人標準不一

實務上三者並用：能用規則的就用規則，其他用 LLM 評審，再抽樣人工檢查 LLM 評審是否可信。

🐍 Python 範例（離線可執行，已實際執行）　規則評分

# 規則評分：用測試集的條件自動檢查輸出 def grade(output, expect): for s in expect.get("must_contain", []): if s not in output: return "失敗：缺少「%s」" % s for s in expect.get("must_not_contain", []): if s in output: return "失敗：不應出現「%s」" % s return "通過" runs = [ ("退貨期限是幾天？", "商品到貨 7 天內可申請退貨。", {"must_contain": ["7 天"]}), ("你們有賣貓砂嗎？", "有賣喔！", {"must_contain": ["客服"], "must_not_contain": ["有賣"]}), ("你們有賣貓砂嗎？", "目前查不到這項商品，我幫您轉給客服確認。", {"must_contain": ["客服"], "must_not_contain": ["有賣"]}), ] for q, out, exp in runs: print("%-10s → %s" % (q, grade(out, exp)))

▶ 執行結果

退貨期限是幾天？ → 通過 你們有賣貓砂嗎？ → 失敗：缺少「客服」 你們有賣貓砂嗎？ → 通過

LLM 評審的提示要像一份評分規準：給出明確的評分標準與每個分數的定義，並要求先寫理由、再給分數。

☁️ Claude API 範例（需要 pip install anthropic 與 API 金鑰）　LLM 評審（示意）

JUDGE = """你是客服回覆的評審。根據 <documents> 判斷 <answer> 是否符合規準： 1. 只使用文件中的資訊（沒有編造） 2. 文件沒有答案時，有明確說明並轉人工 先在 <reason> 中逐條說明，再在 <verdict> 中輸出 PASS 或 FAIL。""" r = client.messages.create( model="claude-opus-5-5", max_tokens=2000, system=JUDGE, messages=[{"role": "user", "content": f"<documents>{docs}</documents>\n<question>{q}</question>\n<answer>{answer}</answer>"}], )

🧭 這一課的重點

評分方式有規則程式（快、一致但不懂語意）、LLM 評審（可規模化能判斷語意但需校準）與人工（最可靠但慢貴）。實務上能用規則就用規則，其他用 LLM 評審並抽樣人工驗證；評審提示要有明確規準並先寫理由再給分。比較版本時也要注意個別案例的退步。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。
