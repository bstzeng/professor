Level 3｜Agent：讓模型自己跑很多步 · 第 38 課

實作：拆解一個程式代理的系統提示

這一課的目標

  • 分析真實代理系統提示的結構
  • 對應 Level 3 的各項技巧
  • 寫出自己的代理提示

Claude Code、Codex 這類程式代理的系統提示很長，但結構可以拆解成我們學過的部分。以下是一個簡化、示意性的整理：

區塊內容（示意）對應課程
身分與目標在使用者的專案中協助軟體開發第 29 課
工具使用原則讀檔用專用工具而非 shell、搜尋先用 grep、多個獨立操作可平行第 23 課
做事方式修改前先閱讀、遵循現有慣例、改完要驗證第 29、33 課
任務管理多步驟任務先列待辦清單並持續更新第 31 課
安全與邊界破壞性操作先確認、不推送除非被要求、不洩漏機密第 36 課
溝通風格簡潔、完成後說明改了什麼第 11 課
專案記憶自動讀入專案說明檔（如 CLAUDE.md、AGENTS.md）第 22 課

值得學習的幾個特點：

  • 原則多於步驟：大多數內容是判斷準則，而不是固定流程。
  • 解釋理由：例如「用專用工具讀檔，因為使用者比較容易審閱」。
  • 專案說明檔是使用者可以改的提示：把專案慣例寫進 CLAUDE.md，等於延伸了系統提示——這是你最容易上手的代理提示工程。
# CLAUDE.md（專案說明檔範例） ## 專案 電商後台，Node.js 20 + PostgreSQL。 ## 指令 - 測試：npm test（修改後必跑） - 型別檢查：npm run typecheck ## 慣例 - 新 API 放在 src/routes/，參考 orders.ts 的寫法 - 資料庫變更一律透過 migrations/，不要直接改 schema ## 注意 - payments/ 底下的程式涉及金流，修改前先告訴我

🧭 這一課的重點

程式代理的系統提示可拆解為身分目標、工具使用原則、做事方式、任務管理、安全邊界、溝通風格與專案記憶。值得學習的是原則多於步驟、解釋理由，而 CLAUDE.md 等專案說明檔是使用者可直接編寫的提示延伸。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。
