RAG（一）：檢索

這一課的目標

  • 理解 RAG 中檢索的角色
  • 認識切塊、檢索與重排序
  • 知道檢索失敗時的症狀

RAG（檢索增強生成）是先從知識庫找出相關段落，再放進提示讓模型回答。它的品質有一大半取決於檢索：段落沒找到，模型就不可能答對。

環節要做的決定常見問題
切塊每段多長？在哪裡切？切太碎失去脈絡；切太大混入雜訊
檢索關鍵字、語意向量，或兩者並用同義詞找不到、專有名詞被誤判
重排序用更精準的模型重新排序前幾十筆省略這步時，最相關的段落可能排不進前幾名
放入提示放幾段？怎麼標示來源？放太多稀釋重點

提示工程也能幫助檢索：例如先讓模型把使用者口語化的問題改寫成適合搜尋的查詢，或拆成幾個子問題分別搜尋。

✗ 改寫前
（直接拿使用者的話去搜尋） 「上次買的那個藍色的可以換嗎」
✓ 改寫後
把使用者的問題改寫成 1–3 個適合搜尋客服知識庫的查詢，每行一個。 使用者問題：上次買的那個藍色的可以換嗎 → 換貨政策 顏色 → 退換貨 期限 條件
  • 口語化、帶指代的問題不適合直接搜尋
  • 讓模型先改寫查詢，檢索命中率更高

🧭 這一課的重點

RAG 的品質大半取決於檢索：切塊大小、關鍵字與語意檢索、重排序、放入提示的數量都影響能否找到對的段落。提示工程也能幫助檢索，例如先讓模型把口語化問題改寫成適合搜尋的查詢或拆成子問題。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

  2. 重排序的作用是什麼？
  3. 為什麼要先改寫使用者的問題再搜尋？
