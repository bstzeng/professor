結構化提示

這一課的目標

  • 使用 XML 標籤組織提示
  • 理解分隔資料與指令的重要性
  • 建立可重複使用的提示範本

提示一長，指令、背景、範例、資料混在一起，模型就可能分不清楚。用標籤（例如 XML 風格的 <document>）把不同的部分包起來，有幾個好處：

  • 清楚：模型知道哪段是要處理的資料、哪段是要遵守的指令。
  • 安全：文件裡如果剛好有「請忽略上述指示」之類的句子，模型比較不會把它當命令（第 27、44 課）。
  • 好引用：可以說「根據 <contract> 中的第三條」。
  • 好維護：變成範本，每次只替換標籤內的內容。
<instructions> 根據合約內容，回答使用者的問題。只根據合約回答；合約沒寫的，就說「合約中未提及」。 回答時引用相關條文的編號。 </instructions> <contract> {合約全文} </contract> <question> {使用者問題} </question>

標籤名稱沒有固定的規定，取有意義的名字、前後一致即可。Markdown 標題也可以達到類似的效果。

🧭 這一課的重點

用 XML 風格標籤分隔指令、背景、範例與資料，讓模型清楚區分命令與素材、較不易把文件中的句子當指令、方便引用與維護成範本。標籤名稱沒有固定規定，取有意義的名字並前後一致即可。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

  2. 為什麼分隔資料能提高安全性？
  3. 把一個你常用的提示改寫成有標籤的範本。
