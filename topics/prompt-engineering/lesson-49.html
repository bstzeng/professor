成本與延遲

這一課的目標

  • 估算提示的成本
  • 認識降低成本與延遲的方法
  • 在品質、成本與速度間取捨

成本大致等於輸入 token × 輸入單價＋輸出 token × 輸出單價；延遲則主要受輸出長度與模型大小影響。

🐍 Python 範例（離線可執行，已實際執行）　估算每月成本

# 估算每月成本（單價為示意，實際請查官方價目表） PRICE_IN, PRICE_OUT = 5.0, 25.0 # 美元 / 百萬 token（示意） CACHE_READ = 0.1 # 快取讀取約為一般輸入的 1/10（示意） def monthly(calls, sys_tok, user_tok, out_tok, cached=False): ins = (sys_tok * (CACHE_READ if cached else 1) + user_tok) * PRICE_IN return calls * (ins + out_tok * PRICE_OUT) / 1e6 base = monthly(100000, 6000, 300, 400) print("原始： $%7.0f / 月" % base) print("系統提示快取： $%7.0f / 月" % monthly(100000, 6000, 300, 400, cached=True)) print("快取＋輸出減半： $%7.0f / 月" % monthly(100000, 6000, 300, 200, cached=True))

▶ 執行結果

原始： $ 4150 / 月 系統提示快取： $ 1450 / 月 快取＋輸出減半： $ 950 / 月
方法效果代價
提示快取重複的前綴大幅降價、加速要調整提示順序
精簡上下文減少輸入可能漏掉資訊，要評估
控制輸出長度減少輸出（通常最貴）太短可能不完整
模型路由簡單請求用小模型需要可靠的分類
調整 effort簡單任務用較低的思考量困難任務品質可能下降
批次處理不急的任務用批次 API，通常有折扣結果不會即時回來
串流輸出首字更快出現，體感延遲降低總時間不變

每一項優化都要用測試集確認品質沒有下降。省錢的方法很多，但用一個更差的答案換來的節省通常不值得。

🧭 這一課的重點

成本約為輸入與輸出 token 乘以各自單價，延遲主要受輸出長度與模型大小影響。降低方法包括提示快取、精簡上下文、控制輸出長度、模型路由、調整 effort、批次處理與串流輸出；每項優化都要用測試集確認品質沒有下降。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。
