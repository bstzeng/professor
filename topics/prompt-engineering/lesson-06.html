說明「為什麼」

這一課的目標

  • 理解說明理由的效果
  • 把規則改寫成帶理由的說明
  • 知道理由如何幫助模型處理例外

比起單純下命令，告訴模型為什麼要這樣做，效果通常更好。因為模型能從理由推論出你沒寫到的情況該怎麼處理。

✗ 改寫前
不要用刪節號。
✓ 改寫後
這段文字會用語音朗讀軟體唸出來，軟體不知道刪節號該怎麼唸，所以請不要使用刪節號。
  • 有了理由，模型也會自動避開其他朗讀軟體唸不好的符號（例如表情符號、特殊括號）
✗ 改寫前
回答要簡短。
✓ 改寫後
使用者是在手機上用 LINE 跟我們的客服機器人對話，訊息太長會被折疊，所以每則回覆請控制在三句話內；需要詳細步驟時，改成提供說明頁連結。
  • 理由讓模型知道「簡短」的真正目的，也告訴它例外時該怎麼做

說明理由也是一種優先順序的溝通：當兩條規則衝突時，模型可以根據背後的目的判斷哪一條更重要。

🧭 這一課的重點

告訴模型規則背後的理由，比單純下命令有效：模型能從理由推論未寫到的情況（例如朗讀軟體唸不好的其他符號），也能在規則衝突時依目的判斷優先順序，並知道例外時該怎麼做。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

檢查你的理解

  1. 為什麼說明理由能幫助模型處理沒寫到的情況？
  2. 把「不要用專業術語」改寫成帶理由的說明。
  3. 理由如何幫助模型處理規則衝突？
