記憶

這一課的目標

  • 區分不同類型的記憶
  • 設計記憶的寫入與讀取提示
  • 避免記憶帶來的問題

模型本身不會記得上一次對話。所謂「記憶」，其實是由程式把重要資訊存下來，下次再放進上下文。提示工程要處理兩件事：記什麼和怎麼用。

記憶類型例子放入方式
對話摘要「前面已討論過預算上限 3 萬元」取代冗長的舊對話
使用者偏好「偏好簡短回答、素食」放在 system 或對話開頭
事實與決定「專案使用 PostgreSQL」專案說明檔、筆記
任務進度「已完成 1–3 步，下一步是測試」進度檔（第 31 課）
✗ 改寫前
把對話重點記下來。
✓ 改寫後
從這段對話中，找出之後的對話也會用到的使用者資訊（偏好、限制、已做的決定），用條列寫下。 只記錄使用者明確說出的事，不要推測；一次性的問題（例如今天的天氣）不用記。 如果與既有記憶衝突，以最新的說法為準，並標註「更新」。
  • 說明什麼值得記、什麼不用記
  • 禁止推測（避免把猜測當成事實存下來）
  • 處理新舊衝突

記憶的風險

錯誤的記憶會一直被重複使用；惡意內容也可能被寫進記憶（記憶污染）。所以要讓使用者能查看、修改與刪除記憶，敏感資訊（密碼、身分證號）不該被記錄。

🧭 這一課的重點

模型的記憶是程式把重要資訊存下並在下次放入上下文，包括對話摘要、使用者偏好、事實與決定、任務進度。寫入記憶的提示要說明記什麼、禁止推測並處理新舊衝突；要防範錯誤記憶與記憶污染，讓使用者可查看刪改，不記錄敏感資訊。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。
