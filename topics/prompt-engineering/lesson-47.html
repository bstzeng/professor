版本管理

這一課的目標

  • 用版本控制管理提示
  • 把提示與程式碼分開管理
  • 記錄提示與模型的對應

上線的提示是產品的一部分，應該像程式碼一樣管理：

  • 放進版本控制：每次修改都有紀錄、可以回復、可以審查（code review）。
  • 與程式分開存放：提示放在獨立的檔案或範本中，而不是散落在程式碼的字串裡。
  • 記錄搭配的模型與參數：同一個提示換模型，表現可能完全不同。
  • 修改要跑評估：把評估加入 CI，分數下降就不讓合併。
  • 上線紀錄：每則回覆記下用的是哪個提示版本，方便追查問題。
prompts/ customer_service/ system.md ← 系統提示本文 config.yaml ← 模型、effort、max_tokens、版本號 CHANGELOG.md ← v4：移除過度的帳號限制（通過率 85%→88%） evals/ customer_service.jsonl ← 測試集 holdout.jsonl ← 保留集

變數與範本

提示中會變動的部分（客戶名稱、文件、日期）用範本變數表示，例如 {customer_name}。這讓提示本身保持穩定，也方便提示快取（第 25 課）。

🧭 這一課的重點

上線的提示應像程式碼一樣管理：放進版本控制並審查、與程式分開存放、記錄搭配的模型與參數、把評估加入 CI 防止退步、記錄每則回覆使用的提示版本；變動部分用範本變數，讓提示穩定並利於快取。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。
