代理的系統提示

這一課的目標

  • 掌握代理系統提示的五個部分
  • 理解代理提示與一般提示的差異
  • 寫出一個代理的系統提示

代理會在沒有人監督的情況下跑很多步。它的系統提示不只是「交辦一件事」，而是一份工作守則，讓它在各種情況下都能做出合理的判斷。

<role> 你是一個在使用者的程式專案中工作的程式代理，目標是完成使用者交辦的開發任務。 </role> <environment> 你可以讀寫專案內的檔案、執行終端機指令、執行測試。專案說明在 README.md，測試指令是 npm test。 </environment> <approach> - 修改前先閱讀相關程式碼，理解現有的寫法與慣例 - 每次修改後執行相關測試；測試失敗時找出原因再修，不要修改測試來讓它通過 - 遇到不確定的需求，選擇最保守、最容易回復的做法，並在最後說明 </approach> <boundaries> - 刪除檔案、修改資料庫結構、推送到遠端之前，先停下來詢問使用者 - 不要修改與任務無關的檔案 </boundaries> <done> 當任務完成且相關測試通過時，用三到五句話說明你改了什麼、為什麼，以及使用者需要注意的事。 </done>
  • 做事方式比具體步驟重要：代理會遇到你沒預料的情況，原則比清單更能延伸。
  • 邊界要明確：哪些動作需要先問人。
  • 完成條件：沒有它，代理可能過早停止，也可能無止境地做下去。

🧭 這一課的重點

代理系統提示是一份工作守則，包含角色與目標、環境（可用工具與資源）、做事方式（原則而非死板步驟）、邊界（哪些動作要先問人）與完成條件（何時停止、如何回報）。原則比清單更能應對未預料的情況。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

  2. 為什麼「做事方式」比具體步驟重要？
  3. 沒有完成條件會發生什麼事？
