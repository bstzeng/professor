輸出格式

這一課的目標

  • 指定適當的輸出格式
  • 讓格式配合使用情境
  • 用正面描述控制格式

同樣的內容，用在不同地方需要不同格式：網頁需要 Markdown、程式需要 JSON、簡報需要條列、朗讀需要純文字。輸出格式要配合輸出會被怎麼使用。

使用情境適合的格式提示寫法
直接顯示給人看Markdown：標題、條列、粗體「以 Markdown 輸出，含標題與小標」
程式要讀取JSON用結構化輸出功能（第 12 課）
貼進聊天軟體純文字、短段落「不要使用 Markdown 符號，用空行分段」
比較多個項目表格「用表格比較，欄位為……」
文章、報告流暢的段落「用完整的段落書寫，不要條列」
✗ 改寫前
不要用 Markdown，不要條列，不要粗體。
✓ 改寫後
請用流暢的散文段落回答，就像一封寫給朋友的信。
  • 說「要什麼」比列出一堆「不要」有效——模型更清楚目標長什麼樣子

另一個實用技巧：提示本身的風格會影響輸出的風格。如果你的提示寫滿了條列與粗體，模型也傾向條列與粗體；想要散文，提示也用散文寫。

🧭 這一課的重點

輸出格式要配合使用情境：給人看用 Markdown、程式讀取用 JSON、聊天軟體用純文字、比較用表格、報告用段落。用正面描述說明要什麼比列出不要什麼有效；提示本身的風格也會影響輸出風格。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

檢查你的理解

  1. 為什麼輸出格式要配合使用情境？
  2. 把「不要條列」改寫成正面描述。
  3. 提示的風格如何影響輸出的風格？
