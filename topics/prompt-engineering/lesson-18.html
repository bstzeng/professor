上下文的預算

這一課的目標

  • 理解上下文過多與過少的問題
  • 學會精簡上下文
  • 知道如何取捨
問題症狀對策
太少模型憑常識亂猜、編造細節補上必要背景與資料
太多忽略關鍵細節、成本與延遲上升只放相關段落；摘要舊內容
放錯用了過時或錯誤的資料標明日期與來源；刪除過時內容
互相矛盾回答搖擺、自相矛盾說明以哪一份資料為準

一個實用的原則：每一段上下文都要「付租金」——它要嘛提供模型需要的資訊，要嘛就不該在那裡。特別注意這些常見的浪費：

  • 把整份 50 頁的手冊放進去，只為了回答其中一段的問題
  • 工具回傳了完整的原始 JSON，其實只需要三個欄位
  • 對話歷史中保留了早已解決、與目前任務無關的討論
  • 重複出現的相同規則

不只是成本問題

即使上下文視窗夠大、成本可以接受，塞入大量不相關的內容仍會降低回答品質。上下文越精準，模型越聚焦。

🧭 這一課的重點

上下文太少會讓模型亂猜，太多會忽略重點並增加成本延遲，放錯會用到過時資料，矛盾會讓回答搖擺。每段上下文都要「付租金」；避免整份手冊、完整原始 JSON、無關歷史與重複規則。即使視窗夠大，不相關內容仍會降低品質。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

檢查你的理解

  1. 上下文太少與太多各有什麼症狀？
  2. 「每一段上下文都要付租金」是什麼意思？
  3. 舉出兩個常見的上下文浪費。
