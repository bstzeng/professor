Level 3｜Agent：讓模型自己跑很多步 · 第 33 課

自我檢查與反思

這一課的目標

  • 設計讓模型檢查自己工作的提示
  • 區分外部驗證與自我評論
  • 避免無效的自我檢查

要求模型「檢查一下你的答案」有時有效，但模型常常看不出自己的錯誤——它用同樣的思路犯錯，也用同樣的思路檢查。更可靠的是外部驗證：

驗證方式可靠度例子
執行與測試高跑程式、跑測試、實際計算
對照來源高把每個說法對回引用的原文
具體的檢查清單中「逐項確認：是否回答了每個子問題？數字是否與資料一致？」
「再檢查一次」低模型常直接說「看起來沒問題」
✗ 改寫前
寫完後檢查一下有沒有錯。
✓ 改寫後
完成後，依序確認： 1. 使用者問了三個問題，每一個都回答了嗎？ 2. 回答中的每個數字，都能在 <data> 中找到嗎？逐一列出對照 3. 有沒有說了資料中沒有的事？有的話刪除或標註為推測
  • 把模糊的「檢查」變成具體、可執行的檢查項目
  • 要求對照來源，而不是憑感覺

🧭 這一課的重點

模型常看不出自己的錯誤，因為用同樣思路犯錯與檢查。外部驗證（執行測試、對照來源）最可靠，具體檢查清單次之，單純「再檢查一次」最弱。把模糊的檢查改成逐項、可執行、對照來源的具體檢查。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。

檢查你的理解

  1. 為什麼模型常看不出自己的錯誤？
  2. 哪些驗證方式比較可靠？
  3. 把「檢查一下有沒有錯」改寫成具體的檢查清單。
