拆解任務

這一課的目標

  • 判斷何時應拆解任務
  • 設計提示串接（prompt chaining）
  • 理解拆解的好處與代價

當一個任務包含好幾個不同性質的步驟——例如「讀財報、找出異常、寫成給董事會的報告、再檢查一遍」——一次全部交給模型，結果常常顧此失彼。另一種做法是提示串接：每一步一個提示，前一步的輸出成為下一步的輸入。

一個大提示串接多個小提示
適合簡單、步驟緊密相關複雜、步驟性質不同
除錯難：不知道哪一步出錯易：每一步可單獨檢查
成本與延遲較低較高（多次呼叫）
彈性低高：每一步可用不同模型、可插入程式檢查

☁️ Claude API 範例（需要 pip install anthropic 與 API 金鑰）　三步驟的提示串接

import anthropic client = anthropic.Anthropic() def ask(system, content): r = client.messages.create(model="claude-opus-5-5", max_tokens=16000, system=system, messages=[{"role": "user", "content": content}]) return next(b.text for b in r.content if b.type == "text") report = open("q3_report.txt", encoding="utf-8").read() numbers = ask("從財報中擷取營收、毛利、營業費用的本季與去年同期數字，用表格列出。", report) # 步驟一 analysis = ask("根據數字表格，指出變化超過 10% 的項目，並推測可能原因。", numbers) # 步驟二 memo = ask("把分析寫成給董事會的一頁備忘錄：先結論，再三個重點，最後建議。", analysis) # 步驟三 print(memo)

拆解也有代價：步驟之間的資訊可能遺失。每一步的輸出要包含下一步需要的所有資訊；必要時把原始資料也一起傳下去。

🧭 這一課的重點

複雜任務可用提示串接：每步一個提示、前一步輸出作為下一步輸入。串接較易除錯、每步可換模型或插入程式檢查，但成本與延遲較高，且步驟間可能遺失資訊，需確保傳遞足夠內容。

✍️ 提示工程的最佳做法會隨模型世代改變；本課以目前主流模型（特別是 Claude）的實際行為為例，原則大多通用。Python 範例中標示「已執行」的為離線程式，輸出是實際結果；呼叫 API 的範例需要金鑰，模型名稱與參數以官方文件為準。
