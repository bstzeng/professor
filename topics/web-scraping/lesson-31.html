模組 E｜爬蟲實戰橋接：從瀏覽器知識到 Python 工具 · 第 31 課

常見反爬蟲機制與應對思路：User-Agent、速率限制、驗證碼

學習目標

  • 認識網站常見的反爬蟲機制，理解它們存在的正當理由
  • 學會用速率限制、合理間隔等方式，寫出「有禮貌」的爬蟲
  • 建立正確心態：遇到驗證碼等強機制時該怎麼看待

網站設置反爬蟲機制，通常不是針對個人惡意刁難， 而是為了保護伺服器資源、防止資料被大量濫用、 或維護服務品質。這一課的重點，不是教你怎麼 「繞過」這些機制，而是幫助你認識它們、 理解存在的理由，並用負責任的方式應對。

1. 為什麼網站要防範爬蟲

  • 保護伺服器資源——大量、 高頻的自動化請求，會消耗原本要服務真實 使用者的運算與頻寬資源。
  • 防止資料被大量複製—— 許多網站的內容資料本身有商業價值， 希望控制被大量、系統性複製的程度。
  • 維持服務公平性—— 確保少數自動化程式不會擠占原本該分配給 真實使用者的服務容量。

2. 速率限制（Rate Limiting）：最常見也最合理的機制

伺服器限制「同一個來源，在一段時間內最多能 發送幾次請求」，超過限制通常回傳狀態碼 429（Too Many Requests）。 這是最普遍、也最合理的機制——面對它， 負責任的做法很直接：放慢速度。

import time import requests for page in range(1, 11): response = requests.get(url, params={"page": page}, headers=headers) if response.status_code == 429: # 有些伺服器會告訴你要等多久才能再試 wait = int(response.headers.get("Retry-After", 5)) time.sleep(wait) continue # 正常處理... time.sleep(1) # 主動放慢速度，禮貌地間隔請求，即使沒被限速也養成習慣

主動在每次請求之間加入延遲（time.sleep()）， 是負責任爬蟲最基本的禮貌——即使目標網站 沒有明確要求，也應該視為預設的良好習慣， 而不是把伺服器容忍度當成挑戰的上限。

3. IP封鎖：更嚴格的手段

持續違反速率限制、或行為模式明顯異於正常 使用者，網站可能會直接封鎖來源IP位址一段 時間，甚至永久封鎖。遇到IP被封鎖，最負責任 的反應是把它當成明確的訊號：這個網站 不歡迎目前這種存取方式——應該重新 檢視自己的爬取頻率是否過高，而不是尋求繞過 封鎖的方式。如果有正當的資料需求，更好的做法 是查詢該網站是否提供官方API，或直接聯繫網站 方說明需求。

4. 驗證碼（CAPTCHA）：一個需要尊重的邊界

遇到驗證碼，代表什麼

驗證碼是網站用來區分真人與自動化程式最直接 的工具。這門課不會教怎麼繞過或破解 驗證碼——遇到驗證碼，應該把它理解為 網站明確表達「這個操作希望由真人完成」的 訊號，合理的回應是尊重這個邊界：如果是 你自己需要存取的資料，手動完成驗證碼、 改用官方提供的API或資料下載功能，或聯繫 網站方詢問是否有合作或授權存取的管道， 而不是尋求技術手段自動突破它。

5. 其他常見機制：認識即可

  • 檢查User-Agent與其他headers是否合理—— 第 26、30 課提過，設定合理的headers是 基本禮貌，跟惡意偽裝是兩回事。
  • 蜜罐連結（Honeypot）—— 頁面裡藏著肉眼看不到、只有自動化程式才會 誤觸的連結，誤觸會被判定為機器人。 這提醒我們：只選取畫面上真正看得到的內容 （呼應第 3 課挑選穩定屬性的原則）， 不要無差別地爬取頁面裡的所有連結。
  • 需要JS挑戰驗證（例如某些防護服務 要求瀏覽器先執行一段JS運算才放行）—— 這類機制通常代表網站對自動化存取的防護 意願很強，遇到時應該優先考慮：這個網站 是否真的希望被大量爬取？是否有更正當的 資料取得管道？

6. 整體原則：把這些機制當成溝通訊號

這一課想建立的核心心態是：反爬蟲機制不是 單純的技術障礙，而是網站方在跟你溝通「這裡的 存取規則是什麼」。負責任的爬蟲行為，是根據 這些訊號調整自己的行為（放慢速度、降低頻率、 尊重明確的拒絕），而不是把每一個機制都當成 必須突破的關卡。下一課會更完整地談這個原則 背後的法律與道德邊界。

檢查你的理解

  1. 能說出網站設置反爬蟲機制的正當理由
  2. 能寫出處理429狀態碼、主動放慢速度的程式碼
  3. 能說明遇到IP封鎖時，負責任的反應是什麼
  4. 能說明遇到驗證碼時，這門課建議的正確心態
