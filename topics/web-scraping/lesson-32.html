模組 E｜爬蟲實戰橋接：從瀏覽器知識到 Python 工具 · 第 32 課

爬蟲的合法與道德邊界：robots.txt、服務條款、資料使用的分寸

學習目標

  • 學會讀懂並尊重robots.txt的規則
  • 理解服務條款（Terms of Service）對爬蟲行為的約束
  • 認識個人資料、著作權在爬蟲情境下需要特別注意的地方

這一課要談的不是程式技巧，而是該不該做、 該怎麼做才恰當——技術上做得到， 不代表法律上或道德上就沒有問題。這是負責任地 使用這門課教的技能，很重要的一課。

1. robots.txt：網站主動說明的存取規則

幾乎所有網站根目錄下都有一個 /robots.txt檔案，用來聲明 「哪些自動化程式（依User-Agent識別）可以爬取 哪些路徑、不能爬取哪些路徑」。這是網站方 主動、公開表達意願的方式，業界公認的基本 禮貌是先檢查、並尊重這份聲明：

# 直接在瀏覽器打開查看，或用Python讀取解析 # https://example.com/robots.txt User-agent: * Disallow: /admin/ Disallow: /api/private/ Allow: / # Python可以用內建的urllib.robotparser解析判斷 from urllib.robotparser import RobotFileParser rp = RobotFileParser() rp.set_url("https://example.com/robots.txt") rp.read() can_fetch = rp.can_fetch("*", "https://example.com/admin/dashboard") print(can_fetch) # False：robots.txt明確表示不希望這裡被爬

需要澄清：robots.txt本身沒有技術上的強制力 （它不是一道無法穿越的鎖），但業界的共識與 許多司法管轄區的法律實務，都把「無視 robots.txt的明確聲明」視為對網站方意願的 直接違反，是需要嚴肅看待的紅線。

2. 服務條款（Terms of Service）

許多網站的服務條款裡，會明文規定是否允許 自動化存取、爬取資料。這些條款具有法律上的 約束力（使用該服務，某種意義上等同同意 這些條款）。實務上的建議：如果打算對某個 網站進行有規模、持續性的爬取（尤其是商業用途）， 應該先花時間閱讀該網站的服務條款， 必要時直接聯繫網站方確認，而不是假設 「技術上做得到就代表允許」。

3. 個人資料：需要特別謹慎的類別

爬取個人資料的額外考量

如果爬取目標涉及使用者的個人資料 （姓名、聯絡方式、位置資訊等）， 除了前面提到的robots.txt跟服務條款， 還需要考慮個資保護相關法規（不同地區 規範不同，例如歐盟GDPR、台灣個資法等）。 大量蒐集、儲存、甚至再利用他人的個人資料， 可能涉及法律責任，不只是網站服務條款的 問題。這是一個需要格外謹慎、 必要時諮詢法律專業意見的領域，這門課 的技術教學不能取代專業法律諮詢。

4. 著作權：爬到的內容不代表可以任意使用

網站上的文字、圖片、影片等內容，通常受著作權 保護。能夠技術上抓取這些內容， 跟能不能合法地重新發布、商業使用 這些內容，是兩件不同的事。如果爬蟲的目的是 為了個人分析、學術研究，風險相對較低； 如果打算把爬到的內容重新包裝、公開發布甚至 商業化，需要額外評估著作權問題， 必要時尋求授權或法律意見。

5. 一個實用的自我檢查清單

  1. 檢查過robots.txt了嗎？有沒有違反明確的 Disallow規則？
  2. 讀過服務條款裡跟自動化存取相關的段落嗎？
  3. 爬取的內容是否涉及個人資料？有沒有評估 相關法規？
  4. 打算怎麼使用爬到的資料？個人分析、 還是要重新發布或商業使用？後者是否需要 額外的授權或法律意見？
  5. 請求頻率是否合理（第 31 課的速率限制 原則）？

這份清單不能取代正式的法律諮詢，但養成 每次開始一個新的爬蟲專案前，先過一遍這份 清單的習慣，能大幅降低誤觸紅線的風險。

檢查你的理解

  1. 能說明robots.txt的作用，並寫出用Python檢查它的程式碼
  2. 能說明服務條款對爬蟲行為的法律意義
  3. 能說出爬取個人資料時需要額外考量的問題
  4. 能複述開始新爬蟲專案前的自我檢查清單
