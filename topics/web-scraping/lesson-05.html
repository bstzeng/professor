XPath 入門：另一套定位元素的語言，跟CSS選擇器互補

學習目標

  • 認識XPath的基本語法，理解它跟CSS選擇器的定位不同
  • 學會用XPath做CSS選擇器做不到的事：文字比對、往上找父節點
  • 知道Selenium、Scrapy裡怎麼使用XPath

第 4 課的CSS選擇器已經能應付大多數情況， 但有兩種常見需求它天生做不到： 「找出文字內容是某段字的元素」跟 「從一個元素往上找它的父節點」—— 這正是XPath補足的地方。

1. XPath 的基本語法

  • 絕對路徑——/html/body/div 從根節點開始，一層一層寫死路徑（很脆弱， 網站結構稍微變動就失效，不建議常用）。
  • 任意位置（//）—— //div 選出頁面裡任何位置 的所有div，最常用的寫法，效果類似CSS的 標籤選擇器。
  • 屬性條件（[@attr]）—— //div[@class='sp-product'] 相當於CSS的 div.sp-product。
  • 文字比對（text()）—— //span[text()='特價'] 選出文字 內容完全等於「特價」的span； //span[contains(text(),'特')] 則是包含「特」這個字即可， 這是CSS選擇器完全沒有對應寫法的能力。

3. XPath 獨有的能力：往上找父節點

CSS選擇器只能往下（從父找子）或平行（兄弟）找， 沒有辦法「往上」。XPath用 ..（父節點）或 parent:: 軸（axis）可以做到：

# 先找到文字是「特價」的span，再往上找它的父層 div //span[text()='特價']/.. # 或用更明確的軸寫法，效果相同 //span[text()='特價']/parent::div

這種「先找到我認得的東西，再往上找到我真正要的 容器」的策略，在真實爬蟲情境裡很實用——有時候 最好辨認的線索是內層的一小段文字，但你真正要的 資料（例如整張商品卡片）在更外層。

4. 在 Python 爬蟲工具裡使用 XPath

# lxml（BeautifulSoup常見的底層解析器之一，也能獨立用） from lxml import html as lxml_html tree = lxml_html.fromstring(html) titles = tree.xpath("//h3[@class='sp-product-title']/text()") # Selenium from selenium.webdriver.common.by import By el = driver.find_element(By.XPATH, "//span[text()='特價']") # Scrapy（框架內建的response物件直接支援） response.xpath("//h3[@class='sp-product-title']/text()").getall()

注意 BeautifulSoup 本身不支援XPath （它的 .select()只吃CSS選擇器）—— 需要XPath時，通常改用同樣以lxml為底層的工具， 或直接用 lxml.html。這也是為什麼 「CSS選擇器跟XPath都要會」：不同工具支援的 語法不一樣，多會一套，遇到限制時才有退路。

5. 該選CSS選擇器還是XPath？

沒有絕對的對錯，實務上的建議是：能用CSS選擇器 解決的，優先用CSS選擇器（語法更簡潔、幾乎所有 工具都支援）；只有遇到CSS選擇器做不到的情況 （文字比對、往上找父節點、找「第n個符合特定 條件」的複雜邏輯）才切換成XPath。

檢查你的理解

  1. 能寫出「任何位置」跟「屬性條件」兩種基本XPath語法
  2. 能用XPath寫出「文字包含某段字」的選擇器
  3. 能說明XPath怎麼往上找父節點，CSS選擇器為什麼做不到
  4. 能說出BeautifulSoup本身支援CSS選擇器還是XPath
