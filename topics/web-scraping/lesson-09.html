函式與箭頭函式：對照 def 與 lambda

學習目標

  • 認識JS宣告函式的三種寫法
  • 掌握箭頭函式的簡寫規則，這是網頁JS裡最常見的寫法
  • 能讀懂真實程式碼裡常見的函式呼叫寫法

JS的函式寫法比Python多樣，尤其是「箭頭函式」 這種簡寫，在真實網頁的JS程式碼裡出現頻率 非常高——這一課的目標是讓你看到任何一種寫法， 都能立刻反應過來它在做什麼。

2. 箭頭函式：JS最常見的簡寫

      

        箭頭函式（arrow function）用 =>
        符號取代 function 關鍵字，
        寫法上比較接近Python的lambda，
        但功能更完整（可以有多行程式碼、可以有名字）：
      


      

        

          箭頭函式的三種寫法，由完整到最簡
          
        

        
        

      


      

        
對照 Python lambda

        

          const addTax = price => price * 1.05;
          最接近的Python寫法是
          add_tax = lambda price: price * 1.05——
          但箭頭函式在JS裡不只用在「一行搞定」的簡單
          情況，複雜、多行的函式邏輯也經常寫成箭頭函式
          （用完整寫法、帶大括號跟return），這點跟
          Python的lambda明確被限制只能寫單一運算式
          不太一樣。
        

      


      
3. 函式當作參數傳遞：JS裡極度常見的寫法

      

        JS裡把函式當作另一個函式的參數傳進去，
        是家常便飯——這在Python裡也做得到（函式是
        一級公民），但JS用得更頻繁，尤其是在陣列方法
        （第 11 課）跟事件處理（第 15 課）裡：
      


      

        

          陣列的 map 方法，接收一個函式當參數
          
        

        
        

      


      

        這正是為什麼看到真實網頁的JS程式碼裡，
        經常滿滿都是 => 符號——
        大部分處理陣列、處理事件、處理非同步結果
        （模組D）的程式碼，習慣上都用箭頭函式當參數
        直接寫在呼叫的地方，而不是先另外定義好一個
        具名函式再傳進去。
      


      
4. 讀懂比會寫更重要

      

        回顧第 7 課設定的目標：這門課不要求你能流利地
        寫出JS函式，但一定要能讀懂——
        看到一段陌生的JS程式碼，能認出「這是一個函式
        定義」「這個函式接收什麼參數」「它回傳什麼」。
        這個能力，是後面模組D追蹤API、模組D進階課
        追蹤參數計算邏輯時，最基本的前提。
