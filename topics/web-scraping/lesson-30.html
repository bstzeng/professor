模仿瀏覽器發送請求：headers、cookies、session 的角色

學習目標

  • 理解headers在請求裡扮演的角色，學會從DevTools複製
  • 理解cookies怎麼讓伺服器「記得」你是誰
  • 學會用requests.Session()維持跨請求的登入狀態

找到API網址、算出正確的參數（第 23、29 課） 之後，很多時候還差一步：把請求偽裝得 像瀏覽器發出的一樣，這一課要處理的 正是這件事。

1. Headers：請求的「自我介紹」

每個HTTP請求都會夾帶一組headers，向伺服器 說明「我是誰、我想要什麼格式的回應」。 除了第 26 課提過的User-Agent，還有幾個 常見的關鍵headers：

  • Referer——告訴伺服器 「這個請求是從哪一個頁面點過來的」， 有些API會檢查這個欄位，拒絕Referer不是 自己網站的請求。
  • Accept——告訴伺服器 「我想要什麼格式的回應」（例如 application/json）。
  • Authorization——夾帶 身分驗證資訊（例如API金鑰、登入token）， 第 22 課的Headers分頁裡如果看到這個欄位， 代表這個API需要驗證身分才能存取。

最快取得完整、正確headers組合的方式，是回顧 第 22 課提過的「Copy as cURL」功能——複製出來 的內容包含瀏覽器實際送出的所有headers， 可以直接參考、挑出必要的欄位加進Python的 請求裡。

2. Cookies：伺服器記住你的方式

HTTP本身是無狀態的協定——每個請求彼此獨立， 伺服器預設不會記得「這個請求跟上一個請求 是不是同一個人發的」。Cookies就是解決這個 問題的機制：伺服器第一次回應時，在headers裡 夾帶一組cookie（一小段文字資料），瀏覽器會 自動把這組cookie存起來，之後每次對同一個 網站發送請求，都自動附上這組cookie—— 伺服器藉此辨認「這是同一個瀏覽器、同一個 使用者session」。登入狀態、購物車內容， 很多都是靠cookies維持的。

3. requests.Session()：讓Python自動處理cookies

如果每次請求都用requests.get() 單獨呼叫，cookies不會在請求之間自動保留—— 需要登入狀態才能存取的頁面，會因此一直被當成 「新的訪客」。解法是用 requests.Session()：

import requests session = requests.Session() # 第一次請求（例如登入），伺服器回應會夾帶cookie session.post("https://example.com/login", data={ "username": "myuser", "password": "mypassword" }) # 後續用同一個session物件發送請求，cookies會自動帶上 response = session.get("https://example.com/my-account") print(response.text)

session物件會自動記住伺服器回傳的 所有cookies，並在後續每次請求時自動附上—— 這正是瀏覽器本身自動在做的事， requests.Session()幫你在Python裡 重現了同樣的行為。

4. 組合起來：完整重現一個瀏覽器請求

import requests session = requests.Session() session.headers.update({ "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) " "AppleWebKit/537.36 (KHTML, like Gecko) " "Chrome/124.0.0.0 Safari/537.36", "Referer": "https://example.com/products", "Accept": "application/json" }) response = session.get("https://example.com/api/products", params={"page": 1}) data = response.json()

這正是模組D到模組E一路建立的完整流程的終點： 從DevTools觀察到的請求（第 22 課）、追蹤出的 神秘參數（第 23、29 課），加上這一課的 headers跟cookies，組成一個Python requests可以正確重現、伺服器 會正常回應的完整請求。

檢查你的理解

  2. 能解釋為什麼HTTP需要cookies來維持登入狀態
  3. 能寫出用requests.Session()維持跨請求cookies的程式碼
  4. 能組合headers、cookies、正確參數，寫出一個完整的模擬請求
