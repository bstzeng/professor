模組 D｜非同步與網路請求：現代網頁資料流動的核心 · 第 22 課

用 DevTools 的 Network 分頁找到隱藏的API

學習目標

  • 學會操作Network分頁：篩選、排序、搜尋請求
  • 學會檢查一個請求的完整細節：Headers、Payload、Response
  • 能從眾多請求裡，快速鎖定真正裝著你要的資料的那一個

前三課建立了fetch、Promise、async/await的 程式碼知識；這一課要用這些知識，實際去 DevTools裡「看」一個真實網站到底送出了 什麼請求——這是找到隱藏API最直接的方法。

1. 打開 Network 分頁的正確方式

按F12（或右鍵→檢查）打開DevTools，切到 Network分頁。重要：先打開這個 分頁，再重新整理頁面（或觸發你 想觀察的動作），Network分頁只會記錄「分頁 開著之後」發生的請求，錯過的請求不會補記錄。

2. 篩選：只看 XHR / Fetch 類型

一個網頁載入時會同時發出很多請求（圖片、 CSS、字體、JS檔案本身），真正裝著資料的 通常是類型標示為Fetch/XHR的請求—— Network分頁上方有類型篩選按鈕，點選 「Fetch/XHR」可以過濾掉圖片、樣式表等雜訊， 只看真正的資料請求，這是最實用的第一步。

3. 點開一個請求：四個關鍵子分頁

  • Headers——請求網址、方法 （GET/POST）、狀態碼，以及完整的請求標頭 （headers，第 30 課會深入這部分怎麼在 Python重現）跟查詢參數（Query String Parameters，分頁跟篩選常見的 page、limit參數 會出現在這裡）。
  • Payload——如果是POST等 會夾帶請求內容的方法，這裡顯示送出去的 資料內容。
  • Preview / Response—— 伺服器回傳的內容，Preview通常會把JSON 格式化成可以展開收合的樹狀結構，方便 瀏覽；Response顯示未格式化的原始內容。
  • Timing——這個請求各階段 花費的時間，除錯效能問題時才會用到， 爬蟲情境比較少需要看這裡。

4. 實用技巧：用網址關鍵字過濾

Network分頁的篩選欄位除了選類型，也可以直接 打字篩選網址——例如輸入api， 只會顯示網址包含這個字的請求。很多網站的 資料API網址習慣包含/api/、 /graphql、或某個服務名稱 （例如/v1/products）， 用這個技巧可以快速從一大堆請求裡縮小範圍。

5. 從觀察到重現：這是接下來要走的路

找到裝著資料的請求之後，右鍵點它通常有 「Copy → Copy as cURL」的選項——這會複製出 一段完整重現這個請求所需要的所有資訊（網址、 方法、headers、body），這是後面第 30 課教 怎麼用Python requests重現同一個 請求時，最快的起點。但在那之前，第 23 課 要先處理一個更棘手的問題：如果請求網址裡 帶著一段看起來像亂碼的參數（例如UUID）， 該怎麼追出它是怎麼被算出來的。

檢查你的理解

  1. 能說明打開Network分頁時，正確的操作順序（先開再重整）
  2. 能說出Fetch/XHR篩選的作用
  3. 能說出Headers、Payload、Response三個子分頁各自顯示什麼
  4. 能說明「Copy as cURL」這個功能的用途
