陣列與物件：對照 list 與 dict，重點在存取語法差異

學習目標

  • 掌握JS陣列的常用方法，對照Python list的操作
  • 掌握JS物件的語法，理解它跟JSON資料格式的關係
  • 認識const宣告的陣列／物件，內容其實仍然可以修改

這一課的內容，對你之後讀懂API回傳的資料格式 特別重要——因為JS的物件語法，跟JSON資料格式 幾乎是同一件事，這不是巧合（JSON全名就是 「JavaScript Object Notation」）。

1. 陣列：對照 Python 的 list

陣列的基本操作 

      


      

        
    
          
  • .length（屬性，沒有括號）——
            對照 Python 的 len(list)。
    • 
          
  • .push(x)——對照
            list.append(x)。
    • 
          
  • .map(fn)——對照
            [fn(x) for x in list]。
    • 
          
  • .filter(fn)——對照
            [x for x in list if fn(x)]。
    • 
          
  • .reduce(fn, init)——對照
            functools.reduce(fn, list, init)。
    • 
        

      


      
2. 物件：對照 Python 的 dict

      

        

          物件的基本操作
          
        

        
        

      


      

        物件用點記法（product.name）存取，
        是JS跟Python dict最直觀的語法差異——Python
        的dict只能用中括號product["name"]。
        JS兩種寫法都可以，但遇到鍵名不是合法變數名稱
        時（例如鍵名是"product-id"，
        中間有連字號），就只能用中括號寫法。
      


      
3. JS物件語法＝JSON，這件事非常重要

      

        
為什麼這對爬蟲特別關鍵

        

          模組D會教你怎麼直接呼叫網站背後的API，
          這些API幾乎都是回傳JSON格式的資料。
          JSON的語法規則，幾乎完全照搬JS物件跟陣列的
          寫法——這不是設計上的巧合，JSON本來就是從
          JS物件字面量（object literal）語法簡化而來的
          資料交換格式。這代表：只要你看得懂這一課的
          物件跟陣列語法，你就已經看得懂絕大多數API
          回傳的JSON資料長什麼樣子，完全不需要另外
          學一套「JSON語法」。

      


      

        

          JS物件字面量 vs. Python的json.loads()結果，長得幾乎一樣
          
        

        
        

      


      
4. 陷阱：const 宣告的陣列／物件，內容還是能改

      

        回顧第 8 課：const宣告後不能重新賦值。
        但如果const存的是陣列或物件，裡面的內容
        仍然可以修改（像上面例子的
        product.price = 259就是對const宣告的
        product物件做修改，完全合法）——const禁止的是
        「把product整個換成另一個東西」，不是禁止
        「修改product內部的欄位」。這是很多JS新手
        會搞混的地方，值得特別記住。
