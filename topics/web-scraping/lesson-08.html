變數與資料型態：對照 Python，注意 let/const 與動態型別的坑

學習目標

  • 認識 let、const、var 三種變數宣告方式的差異
  • 認識JS的基本資料型態，對照Python的對應型態
  • 知道 == 跟 === 的差異，以及為什麼要優先用 ===

Python裡宣告變數很單純：x = 5就結束了。 JS多了一層「用什麼關鍵字宣告」的選擇—— 這一課把這幾個容易讓Python工程師困惑的地方 一次講清楚。

1. 三種宣告變數的關鍵字

  • let——可以重新賦值的變數， 現代JS最常用的宣告方式，行為最接近Python的 一般變數。
  • const——宣告後不能重新賦值 （但如果是物件或陣列，內容本身還是可以改， 第 11 課會解釋這個細節）。實務上的慣例是： 預設優先用const，只有真的需要重新賦值時才 改用let。
  • var——最古老的宣告方式， 作用域規則比較容易出錯（第 10 課會提到）， 現代JS程式碼已經很少用它，看到舊程式碼裡 出現var，知道它大致等同let即可，不需要 自己寫新程式碼時採用。

2. 基本資料型態對照

      

        
    
          
  • 字串——JS的 string，
            對應Python的 str；JS可以用單引號、
            雙引號，還有反引號模板字串
            `哈囉 ${name}`（對應Python的
            f-string f"哈囉 {name}"）。
    • 
          
  • 數字——JS只有一種
            number型態，不像Python分
            int跟float——
            所有數字（整數、小數）都是同一種型態。
    • 
          
  • 布林值——true／
            false（注意JS是全小寫，
            Python的True／False
            是大寫開頭）。
    • 
          
  • undefined——變數宣告了但
            沒有賦值，大致對應Python的概念上「還沒有值」，
            但Python沒有真正對應的內建值。
    • 
          
  • null——明確表示「這裡故意
            是空的」，比較接近Python的None；
            undefined跟null都
            表示「沒有值」，但意義上有微妙差異
            （undefined通常是「還沒設定」，null是
            「刻意設為空」）。

        這叫動態型別（dynamic typing）。但JS在做

        + 運算子如果任一邊是字串，會把另一邊
        轉成字串做字串連接；但
        -、*、/

養成習慣：永遠用 === 而不是 ==

        

          ==（寬鬆相等）在比較前會先自動轉型，
          容易產生反直覺的結果（例如
          0 == "0"是true，
          0 == ""也是true，
          但"0" == ""卻是false）。
          ===（嚴格相等）不做任何自動轉型，
          型態不同直接視為不相等，行為可預期得多。
          業界慣例是：永遠用===，不要用==，
          這條規則沒有例外，養成習慣就不用逐一記憶
          那些反直覺的轉型規則。
