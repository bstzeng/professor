模組 A｜HTML 深化：從爬蟲視角重新認識網頁結構 · 第 1 課

View Source vs. DOM：原始碼跟瀏覽器實際解析結果的關鍵差異

學習目標

  • 理解「View Source」跟「DOM（Inspect Element）」是兩種不同的東西
  • 知道 requests.get() 抓到的內容，對應的是哪一種
  • 學會用這個觀念，快速判斷一個新網站該用什麼策略爬

你已經會用 Python 的 requests 抓網頁、 用 BeautifulSoup 解析——但一定遇過這種情況： 明明瀏覽器裡看得到的資料，requests.get(url).text 印出來卻找不到。這一課要解決這個困惑， 而且是整門課最重要的一個觀念，值得花時間搞懂。

1. 兩種「看網頁原始碼」的方式

瀏覽器提供兩種完全不同的方式讓你看網頁的 「原始碼」：

  • View Source（檢視原始碼）—— 快捷鍵通常是 Ctrl+U（Windows）或 Cmd+Option+U（Mac）。這顯示的是瀏覽器 從伺服器收到的原始 HTML 文字， 一個字都沒有被改過。這正是 requests.get(url).text 拿到的東西—— 兩者是同一份資料。
  • Inspect Element（檢查／開發者工具）—— 右鍵點某個元素選「檢查」，或按 F12。 這顯示的是瀏覽器執行完所有 JavaScript 之後，目前實際存在的 DOM 樹—— 這是你「肉眼在畫面上看到」的東西所對應的 結構。

2. 為什麼這兩者常常不一樣

現代網頁很少是「後端把完整HTML組好、一次性 送給瀏覽器」這麼單純了。常見的情況是： 伺服器先送一份骨架HTML（可能只有 少數幾個空的 <div>），瀏覽器收到後執行 裡面夾帶的 JavaScript，這段JS再另外發送請求 去要真正的資料（模組D的主題），拿到資料後 用JS把內容動態插入到那些原本空的 <div> 裡——這整個動態插入的過程， View Source 完全看不到，因為 View Source 顯示 的是「JS執行之前」那一瞬間的原始文字； Inspect Element 顯示的則是「JS執行之後」的 最終結果。

3. 一個三秒鐘就能做的診斷測試

遇到新網站，先做這個測試

打開想爬的頁面，按 Ctrl+U（或 Cmd+Option+U） 看 View Source，用瀏覽器內建搜尋（Ctrl+F） 找你想要的資料文字（例如商品名稱、價格）—— 找得到：代表資料本來就在原始HTML裡， requests + BeautifulSoup 就能直接 抓到，不需要處理JS。找不到： 代表資料是JS動態插入的，你需要模組D教的方法 （找出背後的API直接呼叫），或模組E會介紹的 Selenium／Playwright（真的跑一次JS再抓結果）。

4. 這個觀念會貫穿整門課

接下來模組A剩下幾課，會先建立正確理解DOM結構、 選擇器的能力（這兩者都是針對DOM， 也就是Inspect Element看到的東西，因為你平常在 DevTools裡練習選擇器，操作的就是DOM）； 模組B、C會補上JS基礎，讓你看懂JS怎麼把資料 插進DOM裡；模組D會教你怎麼跳過「等JS跑完」 這個步驟，直接找到JS背後在打的API—— 這通常是效率最高的爬蟲策略。

檢查你的理解

  1. 能說出 View Source 跟 Inspect Element 分別對應網頁的哪個時間點
  2. 能說出 requests.get().text 拿到的是哪一種內容
  3. 能複述遇到新網站時的三秒鐘診斷測試
  4. 能說明為什麼「肉眼看得到但requests抓不到」是常見現象
