封包的路徑與 IP 位址

這一課的目標

  • 理解手機封包經過的路徑
  • 理解隧道的概念
  • 理解手機的 IP 位址與 NAT

封包的路徑

  1. 手機把封包透過無線電送到基地台。
  2. 基地台把封包包裝在一條「隧道」裡，送到核心網路的閘道。
  3. 閘道拆開隧道，把原始的封包送到網際網路。
  4. 回來的封包，沿著相反的方向送回手機。

為什麼要用隧道

手機在移動、換手，基地台一直在改變；但對網際網路來說，手機的 IP 位址必須保持不變，連線才不會中斷。隧道讓閘道成為一個固定的「錨點」：不論手機換到哪一個基地台，只要更新隧道的另一端，網際網路看到的仍然是同一個 IP 位址。

手機的 IP 位址

  • 手機的 IP 位址由核心網路的閘道分配。
  • 由於 IPv4 位址不足，許多業者讓大量的手機共用少數的公開位址（大規模 NAT）。
  • 越來越多的業者提供 IPv6，讓每支手機都有自己的位址（見〈網際網路的骨幹〉）。

延遲從哪裡來

無線電的排程與重傳、隧道的處理、閘道的位置，以及之後在網際網路上的距離，都會增加延遲。5G 的低延遲，有一部分來自把閘道與運算（邊緣運算）放得更靠近基地台。

🧭 這一課的重點

封包路徑：手機透過無線電送基地台、基地台把封包包在隧道送核心網路閘道、閘道拆開送網際網路、回來沿反方向；用隧道因手機移動換手基地台一直改變但 IP 須保持不變，隧道讓閘道成固定錨點換基地台只更新隧道另一端；手機 IP 由閘道分配，IPv4 不足許多業者讓大量手機共用少數公開位址大規模 NAT，越來越多提供 IPv6；延遲來自無線電排程重傳隧道處理閘道位置網際網路距離，5G 低延遲部分來自把閘道與邊緣運算放更靠近基地台。
