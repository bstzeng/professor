DNS 的安全

這一課的目標

  • 理解 DNS 的主要安全威脅
  • 理解 DNSSEC 的原理
  • 了解加密的 DNS 查詢

DNS 原本沒有安全設計

DNS 誕生於 1980 年代，當時沒有考慮到惡意的攻擊者：查詢與回答都是明文，而且沒有驗證回答的真偽。

快取下毒

攻擊者偽造 DNS 回答，搶在真正的回答之前送到解析器。如果解析器相信了，就會把假的答案存進快取，之後所有使用這個解析器的人，都會被導到攻擊者的網站。2008 年，安全研究員卡明斯基揭露了一種能大幅提高下毒成功率的方法，全球的 DNS 軟體緊急修補（例如隨機化查詢的來源連接埠）。

DNSSEC

DNS 安全擴充（DNSSEC）為 DNS 紀錄加上數位簽章：每一層用自己的金鑰簽署紀錄，並由上一層為下一層的金鑰背書，形成從根開始的「信任鏈」。解析器可以驗證答案沒有被竄改。

  • DNSSEC 保證的是真實性，不是隱私：查詢內容仍然可以被看見。
  • 部署較複雜，金鑰管理錯誤可能讓網域無法解析，所以普及的速度較慢。

加密的 DNS

透過 HTTPS 或 TLS 傳送的 DNS 查詢（DoH、DoT），能防止網路上的第三者看到或竄改你的查詢。它保護的是隱私，但也引發爭議：企業與政府較難監控或過濾 DNS，而查詢集中到少數的大型公共 DNS 服務商。

🧭 這一課的重點

DNS 1980 年代誕生沒考慮惡意攻擊者查詢回答明文沒驗證真偽；快取下毒攻擊者偽造回答搶在真回答前送到解析器存進快取所有使用者被導到攻擊者網站，2008 年卡明斯基揭露大幅提高成功率方法全球緊急修補如隨機化來源連接埠；DNSSEC 為紀錄加數位簽章每層用金鑰簽署上層為下層金鑰背書形成從根開始的信任鏈可驗證未被竄改，保證真實性不是隱私，部署複雜金鑰錯誤可能無法解析普及慢；加密 DNS DoH DoT 防第三者看到或竄改保護隱私，爭議企業政府難監控過濾查詢集中到少數大型公共服務商。
