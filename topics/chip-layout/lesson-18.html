高階合成（HLS）：C 語言怎麼變成電路

這一課的目標

  • 理解高階合成的流程：排程、配置、綁定
  • 認識 HLS 指示（pragma）如何影響硬體結構
  • 知道 HLS 適合與不適合的場合

RTL 必須精確描述每一個時脈週期發生什麼事，寫起來費時又容易出錯。高階合成（High-Level Synthesis，HLS）讓工程師用 C／C++ 等高階語言描述演算法，由工具自動產生 RTL。常見的工具包括 AMD（Xilinx）的 Vitis HLS、Siemens 的 Catapult、Cadence 的 Stratus。

1. HLS 在做什麼

步驟要回答的問題
排程（scheduling）每一個運算在第幾個時脈週期執行？
配置（allocation）需要幾個乘法器、加法器、記憶體埠？
綁定（binding）每一個運算交給哪一個硬體單元？變數放在哪個暫存器或記憶體？
控制產生產生一個狀態機，依序指揮資料路徑

2. 同一段 C，不同的硬體

for (int i = 0; i < 64; i++) { #pragma HLS PIPELINE II=1 y[i] = a * x[i] + b; }

不加任何指示，工具可能只放一個乘法器，一筆一筆慢慢算；加上 PIPELINE，工具會把運算切成管線，每個週期處理一筆新資料；改用 UNROLL，則會複製 64 份硬體同時計算。程式碼幾乎一樣，產生的電路在速度與面積上可以相差數十倍。

3. HLS 的限制

  • 不是任何 C 程式都能轉：動態記憶體配置、遞迴、指標的任意操作、系統呼叫通常不支援
  • 硬體思維仍然必要：要寫出好的 HLS 程式碼，必須了解它會產生什麼樣的硬體
  • 品質差距：在最講究效能與面積的地方，手寫 RTL 通常仍然更好
  • 驗證更方便：好處是可以直接用 C 的測試程式驗證演算法，速度比 RTL 模擬快得多

4. 適合的場合

HLS 特別適合資料密集、規則的運算：影像與訊號處理、濾波器、AI 推論加速器、加密運算，以及在 FPGA 上快速開發加速器（下一課）。控制邏輯複雜、需要精確時序的部分，則通常仍用 RTL 撰寫。

產業現場

越來越多 AI 加速器與影像處理晶片的部分區塊採用 HLS 開發，因為演算法變化快，用 C++ 修改與驗證比改 RTL 快得多。但產出的 RTL 最後仍要走完一般的合成與後端流程。
