在晶片上實作

這一課的目標

  • 了解濾波器的實作平台
  • 學會規劃即時處理的預算
  • 了解從設計到部署的流程

平台的選擇

平台特色適合
一般 MCU（Cortex-M4/M7）有單週期乘加指令與 SIMD，CMSIS-DSP 函式庫感測器、音訊、馬達控制（見〈嵌入式系統〉）
DSP 晶片針對乘加與資料搬移最佳化，平行的記憶體存取專業音訊、通訊
FPGA硬體平行、每個時脈處理一個樣本雷達、高速通訊、超低延遲
GPU大量平行影像、大批次的頻譜分析（見〈GPU 運算〉）
一般電腦NumPy／SciPy設計、模擬、離線分析

乘加運算

濾波的核心運算是乘加（MAC）：累加器 += 係數 × 樣本。DSP 架構為此特別設計：單一週期完成一次乘加、硬體迴圈、環形定址（自動處理延遲線的繞回）、較寬的累加器避免溢位（第 17 課）。

即時的預算

以 48 kHz 的音訊為例，每個樣本只有約 20.8 μs。如果 MCU 以 200 MHz 運作，大約只有 4,000 個時脈週期，要完成所有的濾波、等化、效果。一個 64 抽頭的 FIR 約需 64 次乘加，一個二階節約 5 次——算一算就知道能放多少個濾波器。實務上通常以區塊（例如每次 64 個樣本）處理，用 DMA 雙緩衝搬資料，降低每個樣本的額外負擔，代價是增加延遲。

從設計到部署

  1. 在 Python 或 MATLAB 中設計濾波器，檢查頻率響應、相位與穩定性。
  2. 用真實的錄音資料模擬，確認效果。
  3. 量化係數（例如 Q15），重新檢查頻率響應與穩定性（第 17 課）。
  4. 在目標平台上實作（例如 CMSIS-DSP 的 arm_biquad_cascade 函式）。
  5. 用已知的輸入（脈衝、正弦掃頻）測試，和模擬結果逐點比較。
  6. 量測執行時間，確認在預算之內。

延遲

即時系統還要注意總延遲：線性相位 FIR 的群延遲、區塊處理的緩衝、ADC 與 DAC 本身的延遲。樂手監聽、助聽器、主動降噪對延遲非常敏感（降噪可能需要微秒等級），通常要 IIR 或非常短的區塊。

🧭 這一課的重點

平台有 Cortex-M4/M7 有單週期乘加與 SIMD 用 CMSIS-DSP、DSP 晶片針對乘加最佳化、FPGA 硬體平行超低延遲、GPU 大量平行、電腦 NumPy SciPy 設計模擬；核心運算是乘加 MAC，DSP 有單週期 MAC、硬體迴圈、環形定址、寬累加器；48 kHz 每樣本約 20.8 μs，200 MHz 約 4,000 週期，64 抽頭 FIR 約 64 次、二階節約 5 次，常以區塊與 DMA 雙緩衝處理但增加延遲；流程為設計檢查、真實資料模擬、量化重查、平台實作、已知輸入比較、量測執行時間；樂手監聽助聽器主動降噪對延遲敏感。
