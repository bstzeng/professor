視覺 token 的推論成本

這一課的目標

  • 推導預填階段的計算量
  • 估算圖片對延遲的影響
  • 理解視覺 token 的計價

推導：預填的 FLOP

Transformer 每處理一個 token，每個參數大約參與一次乘法與一次加法，所以前向計算約 \(2P\) FLOP（\(P\) 為參數量，忽略注意力的 \(N^2\) 項）。預填（prefill）一次處理 \(N\) 個輸入 token：

\[C_{\text{prefill}} \approx 2 P N \;\text{FLOP}\]

7B 模型、一張 576 token 的圖：\(2\times7\times10^9\times576 \approx 8\times10^{12}\) FLOP。在有效算力每秒 \(10^{14}\) FLOP 的 GPU 上約 80 毫秒。十張高解析度圖（每張 2,880 token）就是 \(4\times10^{14}\)，約 4 秒——使用者會明顯感覺到「首 token 延遲」。

預填 vs. 解碼

預填是計算受限（大量 token 並行，GPU 算力被充分利用）；逐 token 解碼是記憶體頻寬受限（每步都要讀完全部權重與 KV 快取，但只算一個 token）。視覺 token 主要增加預填成本與 KV 快取，對之後每一步解碼的速度影響較小（只透過 KV 快取的讀取量）。

為什麼按 token 計價

API 通常把圖片換算成 token 計價，因為成本確實和 token 數成正比（預填 FLOP 與 KV 記憶體都是線性）。實務上的省錢方法：上傳前縮小或裁切到需要的區域、使用「低解析度」選項、純文字 PDF 直接抽文字。詳見 〈多模態與生成式 AI〉第 30 課。

🧭 這一課的重點

前向計算約每 token 2P FLOP，預填 N 個 token 約 2PN FLOP：7B 模型一張 576 token 的圖約 8×10¹² FLOP，在 10¹⁴ FLOP/s 的 GPU 上約 80 毫秒，十張高解析度圖約 4 秒。預填是計算受限、解碼是記憶體頻寬受限；視覺 token 主要增加預填與 KV 快取。API 按 token 計價因為成本與 token 數成正比，可縮小裁切、用低解析度選項或抽文字省錢。
