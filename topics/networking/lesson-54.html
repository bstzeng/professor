Docker指令與常用工作流程

這一課的目標

  • 熟悉build、run、ps、logs、exec、stop、rm這一整套日常會用到的Docker指令
  • 能精確拆解docker run -d -p 8080:80裡每一個參數的語法與意義
  • 能把這些指令串成一個從建置到除錯、清除的完整工作流程

第53課建立了映像檔、容器、Dockerfile的概念圖像，這一課 要把這些概念落實成實際會敲進終端機的指令。這些指令 會反覆出現在接下來模組L實際架站的過程中，值得先熟悉 一輪。

1. 建置與檢視映像檔

在含有Dockerfile的目錄下，用以下指令建置映像檔：

docker build -t myapp:latest .

-t myapp:latest是幫這個映像檔取一個好記的 名稱（name）與標籤（tag），格式是名稱:標籤 ——標籤常用來標示版本，省略時預設是latest。 最後的.指定建置情境（build context）為目前 目錄，也就是Dockerfile裡COPY指令複製檔案 時的基準目錄。建置完成後，可以用以下指令列出本機所有 已經下載或建置好的映像檔：

docker images

2. 啟動容器：docker run，拆解每個參數

有了映像檔，就能啟動容器：

docker run -d -p 8080:80 --name mysite myapp:latest

簡單來說：-d（detached）讓容器在背景執行， 指令會立刻返回、不會卡住目前的終端機；-p 主機埠: 容器埠把主機上的一個連接埠，對應到容器內部監聽 的連接埠——容器有自己獨立的網路命名空間（第52課）， 外界預設連不到容器內部的埠，必須靠-p明確 建立這條轉送路徑；--name則是幫容器取一個 好記的名字，之後下指令時可以用名字取代一長串容器ID。

3. 查看容器狀態：docker ps

docker ps docker ps -a

docker ps列出目前正在執行中 的容器；加上-a（all）則會列出所有 容器，包括已經停止、還沒被刪除的容器——想確認 一個容器是不是還活著，或是想找出之前跑過但已經停掉的 容器，都會用到這個指令。

4. 除錯利器：logs 與 exec

容器跑起來之後，如果行為不如預期，最常用的兩個除錯 指令是：

docker logs mysite docker exec -it mysite sh

docker logs顯示容器的輸出內容（標準輸出／ 標準錯誤），是排查「容器到底發生了什麼事」最基本也最 重要的一步；docker exec -it mysite sh則是 直接打開一個互動式的shell，「鑽進」正在執行中的容器 內部查看——-i（interactive）讓標準輸入保持 開啟，-t（tty）配置一個虛擬終端機，兩者合 起來才能得到一個像平常在終端機打字一樣的互動環境。

5. 停止與清理：stop 與 rm

docker stop mysite docker rm mysite

docker stop優雅地停止一個正在執行的容器； docker rm則是把一個已經停止的容器徹底刪除 （容器停止後並不會自動消失，仍會留在docker ps -a 的清單裡，直到被明確刪除）。

6. 下載與上傳：pull 與 push

映像檔除了自己建置，也可以直接從映像檔倉庫 （registry）下載——最知名的公開倉庫是 Docker Hub。下載別人已經建置好的映像檔用 docker pull，把自己建置的映像檔上傳分享則 用docker push：

docker pull nginx:alpine docker push myaccount/myapp:latest

這也是為什麼實際部署時，很多基礎映像檔（例如官方的 node、nginx、postgres） 不需要自己從零建置，直接docker pull下來 當作Dockerfile裡FROM的起點即可——這個概念 會在第58課實際架站時用上。

7. 串成一個完整工作流程

把上面這些指令串起來，一個典型的開發、除錯循環大致是 這樣：先建置映像檔，接著背景啟動容器並映射連接埠， 用logs確認服務有沒有正常啟動，如果行為 怪異就exec進容器內部檢查檔案或環境變數， 確認沒問題後，如果要停用這個版本，就依序停止並刪除 容器：

docker build -t myapp:latest . docker run -d -p 3000:3000 --name myapp-container myapp:latest docker logs myapp-container docker exec -it myapp-container sh docker stop myapp-container docker rm myapp-container

檢查你的理解

  1. 寫出一個正確的docker run指令，用背景模式啟動一個叫做myapp的映像檔，並把主機3000埠對應到容器3000埠
  2. 能說出docker ps與docker ps -a的差異
  3. 能說出docker exec -it裡-i與-t各自的作用
