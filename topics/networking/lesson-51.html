模組 K｜虛擬化與容器技術：Docker基礎 · 第 51 課

為什麼需要虛擬化：從實體機到虛擬機

這一課的目標

  • 理解「一台實體伺服器只跑一個服務」在資源利用率與擴充速度上的兩個根本問題
  • 理解虛擬機（VM）與Hypervisor如何讓一台實體機安全地分身成多台獨立的虛擬機器
  • 能分辨Type 1（裸機型）與Type 2（託管型）兩種Hypervisor的差異與典型使用場景

模組J把三層式架構講完了：網頁伺服器、應用程式伺服器、 資料庫，各自負責一部分工作，合作把一個網站服務起來。 但這些「伺服器」實際上要跑在什麼樣的機器上？模組F 介紹過資料中心裡塞滿了機櫃與伺服器主機，但如果每一個 服務都要對應一台實體機器，很快就會撞上兩個很實際的 問題——這正是模組K要從頭講起的地方：虛擬化技術， 以及它最終如何演變成今天幾乎無所不在的Docker容器。

1. 一台實體機，一個服務：資源被閒置的年代

在虛擬化技術普及之前，一個很常見的做法是「一台實體 伺服器對應一個服務」——網頁伺服器一台、資料庫一台、 內部某個小工具再一台，圖的是簡單、乾淨，服務之間 彼此不會互相干擾。問題是，現代伺服器的運算能力 （CPU核心數、記憶體容量）通常遠遠超過大多數應用程式 實際會用到的量。一個中小型網站的應用程式伺服器， 平常可能只用掉這台機器百分之十幾的CPU運算能力， 絕大部分時間，剩下的運算資源就只是閒置在那裡，沒有 任何服務在使用——買了昂貴的硬體，卻只發揮一小部分 的價值。

2. 提供新服務的痛：採購、上架、設定，動輒好幾週

第二個問題跟「速度」有關。如果每一個新服務都需要一台 新的實體機器，那麼公司想要上線一個新功能、或是既有 服務需要更多運算容量時，流程往往是：申請採購、等待 硬體到貨、送到資料中心上架安裝、接電源與網路線 （呼應模組F機櫃與配線的畫面）、安裝作業系統、逐步 設定好整套環境——這整個流程動輒需要好幾天甚至好幾週。 在網路服務的世界裡，這樣的速度往往跟不上業務成長或 流量突然暴增的需求。

換個角度看這兩個問題

資源利用率低落，跟提供新容量太慢，其實是同一件事的 兩面：實體硬體的「顆粒度」太粗——你沒辦法只買半台 伺服器給某個小服務用，也沒辦法在十分鐘內生出一台 新機器。虛擬化技術的核心構想，就是想辦法把 一台實體機器「切」得更細，讓資源可以被更靈活地 分配跟重複利用。

3. 虛擬機（VM）：讓一台實體機分身成好幾台

虛擬機（Virtual Machine, VM）是稱霸資料 中心架構將近二十年的解法。核心構想是在一台實體主機 （host）上，安裝一層叫做Hypervisor（虛擬機 監視器）的軟體，由它負責建立、管理好幾台 互相隔離的「虛擬」機器——每一台虛擬機器都擁有自己 完整、獨立的作業系統，感覺起來就像一台真正獨立的 電腦，但實際上，這些虛擬機共享著同一台實體主機底下 真正的CPU、記憶體、儲存空間，由Hypervisor負責在背後 排程、分配這些實體資源。

這帶來一個關鍵好處：好幾個虛擬機——甚至可以是完全 不同的作業系統——可以安全地共用同一台實體伺服器， 每一台都以為自己獨佔了一整套硬體。原本閒置的運算 資源，現在可以被好幾個虛擬機分著用，大幅提升硬體 利用率；而提供新的運算容量，也從「買一台新機器」 變成「在既有硬體上建立一台新的虛擬機」——通常幾分鐘 內就能完成，不再需要等待硬體採購與上架。

4. Type 1 vs Type 2：兩種Hypervisor

Hypervisor依照運作方式，通常分成兩大類：

類型運作方式典型代表常見場景
Type 1（裸機型）直接安裝在實體硬體上運作，本身就是一層精簡的系統，不需要先裝一套通用作業系統VMware ESXi、KVM、Microsoft Hyper-V資料中心、雲端服務供應商，追求最高效能與穩定性
Type 2（託管型）以一般應用程式的身分，安裝、執行在一套已經裝好的主機作業系統之上VirtualBox、VMware Workstation個人電腦、開發者的桌機或筆電，用來測試不同作業系統

Type 1 Hypervisor因為少了「先跑一套完整主機作業系統」 這一層，效能損耗更小、也更適合大規模、高密度地部署 虛擬機，因此是資料中心與雲端服務供應商的主流選擇； Type 2 Hypervisor則因為安裝、使用都跟裝一套一般軟體 差不多方便，常被用在個人電腦上，例如開發者想在自己的 Mac或Windows筆電裡，順手開一台Linux虛擬機測試程式。

  2. 能解釋Hypervisor在虛擬機架構裡扮演的角色
