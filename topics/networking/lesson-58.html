用Docker部署一個簡單網站

這一課的目標

  • 能寫出一份正確的Dockerfile，把一個靜態網站包成映像檔
  • 能在伺服器上完成建置、啟動容器、對外開放連接埠這一整套部署流程
  • 能透過伺服器的公網IP驗證部署是否成功，並知道基本的疑難排解方向

第57課選定了VPS作為新手友善的起點，這一課假設你已經 有一台裝好Docker的VPS（大多數主機供應商都提供已預裝 Docker的作業系統映像檔，或是可以依照Docker官方文件 安裝），要動手把一個最簡單的靜態網站，用Docker實際 部署上線。

1. 撰寫Dockerfile：把靜態網站包進nginx映像檔

假設專案目錄裡已經有一個index.html（以及 可能的CSS、圖片等靜態檔案），最直接的做法是使用官方 的nginx映像檔，把這些靜態檔案複製進nginx 預設會讀取的網頁目錄：

FROM nginx:alpine COPY . /usr/share/nginx/html

FROM nginx:alpine選用一個體積精簡、已經 內建設定好nginx的基礎映像檔（呼應模組J第47課nginx作為 網頁伺服器角色的介紹）；COPY . /usr/share/nginx/ html把目前目錄下的所有檔案，複製進nginx預設會 當作網站根目錄讀取的路徑。這個基礎映像檔本身已經內建 了容器啟動時要執行的指令（啟動nginx伺服器本身）， 所以不需要額外再寫CMD。

2. 在伺服器上建置映像檔

把專案檔案（Dockerfile、index.html等）上傳到伺服器後， 在該目錄下執行：

docker build -t mysite .

這一步會依照Dockerfile的內容，建置出一個叫做 mysite的映像檔（回顧第53、54課的建置流程）。

3. 啟動容器，開放對外的連接埠

docker run -d -p 80:80 --name mysite mysite

這裡把主機的80埠對應到容器內nginx監聽的80埠——80正是 HTTP的標準埠（回顧模組E第20課well-known port的概念）， 瀏覽器造訪一個網址而沒有特別指定埠號時，預設就是連往 80埠。把容器對應到主機的80埠，代表訪客只要輸入伺服器 的IP位址（暫時還沒有網域名稱，會在第59課設定），就能 直接連上這個網站，不需要額外輸入埠號。

小提醒：80埠通常需要較高權限

在Linux上，1024以下的連接埠屬於「特權埠」，執行 docker run時如果目前使用者不在docker 群組或沒有足夠權限，可能需要在指令前加上 sudo才能成功綁定主機的80埠。

4. 驗證部署成功：直接用IP位址造訪

容器啟動後，在瀏覽器網址列直接輸入伺服器的公網IP位址 （例如http://203.0.113.10，這裡用的是保留 給文件示範用的範例IP），如果一切順利，應該就能看到 index.html的內容——此時網站已經是公開 可連線的狀態了，只是還沒有一個好記的網域名稱（下一課 的主題）。

5. 常見疑難排解

如果造訪IP位址沒有反應，依序檢查幾個常見原因：

  • 先確認容器真的在跑——執行 docker ps確認mysite容器 狀態是執行中，而不是啟動後立刻結束
  • 查看容器日誌——執行docker logs mysite（第54課介紹過），檢查nginx啟動 過程有沒有噴出錯誤訊息
  • 檢查伺服器的防火牆規則——很多VPS 或雲端主機預設會擋掉大部分的對外連入流量，需要 明確開放80埠，例如Ubuntu常見的ufw防火牆 可以用sudo ufw allow 80/tcp開放，雲端 主機則常常需要額外到主控台設定「安全群組」或 「防火牆規則」，允許外部連入80埠

檢查你的理解

  1. 寫出把一個靜態網站包成映像檔所需的Dockerfile，以及啟動它並開放80埠所需的docker run指令
  2. 能說明在設定網域名稱之前，要怎麼確認部署已經成功
  3. 能列出網站連不上時，依序該檢查哪幾個可能的原因
