CAN 與 USB

這一課的目標

  • 了解 CAN 匯流排的特性與仲裁
  • 了解 USB 的基本架構
  • 認識其他工業匯流排

汽車裡的網路

1980 年代，汽車裡的電子控制單元越來越多，點對點的配線又重又複雜。德國的博世公司開發了 CAN（控制器區域網路），1986 年發表，讓引擎、變速箱、煞車、儀表板等數十個單元共用一對雙絞線溝通。今天幾乎所有汽車、許多工業設備與醫療器材都使用 CAN。

CAN 的特點

  • 差動訊號：兩條線 CAN_H 與 CAN_L 的電壓差代表 0 或 1，抗雜訊能力強；匯流排兩端要接 120 Ω 的終端電阻。
  • 以訊息為中心：沒有「傳給誰」的位址，而是每則訊息有一個 ID（代表內容，例如「車速」），所有節點都收得到，各自決定要不要處理。
  • 非破壞性仲裁：多個節點同時發送時，邊送邊聽；「0」（顯性）會蓋過「1」（隱性），ID 數值較小的訊息會勝出並繼續傳送，輸的節點自動退出、稍後再送——優先權最高的訊息不會延遲，也不會浪費頻寬。
  • 錯誤處理：CRC 檢查、確認，以及錯誤計數：一直出錯的節點會自動離開匯流排，避免拖垮整個網路。
  • 速度：傳統 CAN 最高 1 Mbps；CAN FD 可以在資料段提高速度並加大資料量。

汽車維修用的 OBD-II 接頭，就可以讀到車上 CAN 匯流排的部分資料。也因為 CAN 沒有內建的認證，研究者曾展示透過入侵車上的資訊娛樂系統來發送偽造的 CAN 訊息（見〈資訊安全〉、第 24 課）。

USB

  • 主從架構：一個主機（電腦）管理所有的裝置，裝置只能在主機詢問時回應。
  • 列舉：裝置插上後，主機讀取它的描述元（我是誰、我需要什麼驅動），再分配位址。
  • 類別：HID（鍵盤滑鼠）、CDC（虛擬序列埠）、MSC（隨身碟）、Audio 等標準類別，電腦有內建的驅動，不必另外安裝。
  • 傳輸類型：控制、中斷、大量、等時（音訊、視訊）。

許多 MCU 內建 USB 週邊，配合廠商或開源的 USB 協定堆疊（例如 TinyUSB），就能讓 MCU 變成鍵盤、虛擬序列埠或隨身碟。

其他工業匯流排

工業自動化中還有 Modbus（常跑在 RS-485 上，第 13 課）、PROFIBUS、EtherCAT、PROFINET 等；汽車裡也有低成本的 LIN 與高速的車用乙太網路。

🧭 這一課的重點

博世開發 CAN 1986 年發表讓汽車數十個 ECU 共用一對雙絞線，今用於汽車工業醫療；CAN_H CAN_L 差動訊號兩端 120 Ω 終端電阻、以訊息 ID 為中心所有節點都收到、非破壞性仲裁顯性 0 蓋過隱性 1 使 ID 小者勝出、CRC 確認與錯誤計數使故障節點離線、傳統最高 1 Mbps 與 CAN FD；OBD-II 可讀部分資料，CAN 無認證曾被展示入侵；USB 為主從架構、插上後列舉讀描述元分配位址、HID CDC MSC Audio 標準類別、控制中斷大量等時四種傳輸，MCU 配 TinyUSB 可成鍵盤或虛擬序列埠；其他有 Modbus、PROFIBUS、EtherCAT、LIN、車用乙太網路。

🔌 本課以 ARM Cortex-M 等常見的 32 位元微控制器為主要例子；暫存器名稱與細節依晶片與廠商而異，實作時請以晶片的資料手冊與參考手冊為準。
