開發流程與工具鏈

這一課的目標

  • 了解交叉編譯
  • 認識工具鏈的組成
  • 了解燒錄與開機流程

交叉編譯

在電腦（x86 或 ARM 的筆電）上寫程式，編譯出另一種處理器（例如 Cortex-M）可以執行的機器碼，叫做交叉編譯。常用的工具鏈是 GCC（arm-none-eabi-gcc）、Clang/LLVM，或廠商的商業編譯器（見〈編譯器〉）。

從原始碼到映像檔

  1. 編譯：每個 .c 檔變成目的檔（.o）。
  2. 連結：依照連結腳本（linker script），把程式碼放到 Flash 的位址、變數放到 RAM 的位址。
  3. 產生映像檔：.elf（含除錯資訊）、.bin 或 .hex（純粹要燒進 Flash 的內容）。
  4. 燒錄：透過 SWD／JTAG 除錯器（例如 ST-Link、J-Link），或透過 USB、UART 的 Bootloader（第 22 課）。

開機時發生了什麼

  1. 上電或重置後，Cortex-M 從 Flash 開頭的向量表讀出初始的堆疊指標與重置處理函式的位址。
  2. 啟動程式碼（startup）把 .data 區段的初始值從 Flash 複製到 RAM，把 .bss 區段清為 0。
  3. 設定時脈（SystemInit）。
  4. 呼叫 main()——在嵌入式系統中，main() 通常是一個永遠不會結束的迴圈。

這和電腦上執行一個 .exe 的過程有許多相似之處，但沒有作業系統替你準備環境（見〈程式是怎麼跑起來的〉）。

開發環境

  • Arduino IDE：最容易入門，隱藏了大部分的細節。
  • 廠商 IDE：例如 STM32CubeIDE、MPLAB，提供圖形化的腳位與時脈設定、自動產生初始化程式碼。
  • PlatformIO、VS Code 加 CMake：跨平台、適合專業的專案。
  • Rust、MicroPython：新的選擇，前者強調記憶體安全，後者適合快速原型。

HAL 與暫存器

廠商提供硬體抽象層（HAL）函式庫，例如 HAL_GPIO_WritePin()，讓程式容易移植、開發快速；但它可能比較大、比較慢，也隱藏了硬體在做什麼。直接操作暫存器（第 4 課）最有效率，也最能理解晶片。實務上兩者常常混用。

🧭 這一課的重點

在電腦上編譯另一種處理器的機器碼為交叉編譯，常用 arm-none-eabi-gcc、Clang 或商業編譯器；流程為編譯成 .o、依連結腳本把程式放 Flash 變數放 RAM、產生 .elf .bin .hex、透過 SWD JTAG 除錯器或 Bootloader 燒錄；Cortex-M 開機從向量表讀堆疊指標與重置函式位址，啟動程式把 .data 複製到 RAM 並清 .bss，設定時脈後呼叫不會結束的 main；開發環境有 Arduino IDE、STM32CubeIDE 等廠商 IDE、PlatformIO VS Code CMake、Rust 與 MicroPython；HAL 易移植但較大較慢，暫存器最有效率，實務常混用。

🔌 本課以 ARM Cortex-M 等常見的 32 位元微控制器為主要例子；暫存器名稱與細節依晶片與廠商而異，實作時請以晶片的資料手冊與參考手冊為準。
