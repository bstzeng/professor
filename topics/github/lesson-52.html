實戰：從零到第一個 PR

這一課的目標

  • 獨立完成一次完整的協作流程
  • 把指令與 GitHub 操作連起來
  • 建立自己的工作習慣

把整門課串成一次完整的練習。建議找一個朋友，或用兩個帳號自己扮演兩個角色。

第一階段：建立專案（維護者）

$ gh repo create todo-app --public --clone --add-readme --license mit $ cd todo-app $ printf 'tasks = []\n' > todo.py $ printf '__pycache__/\n.env\n' > .gitignore $ git add . && git commit -m "feat: 建立待辦清單骨架" $ git push

在 GitHub 設定：Settings → Rules → 新增規則集保護 main（要求 PR、至少 1 人核准）；新增一個 CI workflow（第 39 課）。開一個 Issue：「新增『加入待辦』功能」，加上 good first issue 標籤。

第二階段：貢獻（貢獻者）

$ gh repo fork ming/todo-app --clone $ cd todo-app $ git switch -c feat/add-task # ……編輯 todo.py，加入 add_task 函式與測試…… $ git add todo.py test_todo.py $ git commit -m "feat: 新增 add_task 函式" -m "Fixes #1" $ git push -u origin feat/add-task $ gh pr create --fill

第三階段：審查與合併

  1. 維護者在 Files changed 留言，用 Suggest changes 提出修改。
  2. 貢獻者修改後再 commit、push，PR 自動更新。
  3. CI 綠燈、維護者 Approve。
  4. 維護者選擇 Squash and merge，Issue #1 自動關閉。
  5. 貢獻者同步：git switch main、git pull upstream main（或在 GitHub 按 Sync fork）、git branch -D feat/add-task。

第四階段：發布

$ git switch main && git pull $ git tag -a v0.1.0 -m "第一個版本" $ git push origin v0.1.0 $ gh release create v0.1.0 --generate-notes

走完一次，你就用過了本課程大部分的技能：設定、commit、分支、push、fork、PR、審查、CI、規則、合併、同步、標籤與發布。

🧭 這一課的重點

完整練習分四階段：維護者用 gh repo create 建立專案、加 .gitignore 並 push，設定 main 保護規則、CI 與 good first issue；貢獻者 fork、開分支、commit（Fixes #1）、push、gh pr create；維護者留言、貢獻者修改再 push、CI 綠燈並核准後 Squash and merge，Issue 自動關閉，貢獻者同步並刪分支；最後打 tag、推送、gh release create 發布。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。

檢查你的理解

  1. 在這個練習中，Issue 是怎麼自動關閉的？
  2. 貢獻者合併後要做哪些清理？
  3. 發布 v0.1.0 需要哪幾個指令？
