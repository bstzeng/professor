大型檔案：Git LFS

這一課的目標

  • 知道 GitHub 的檔案大小限制
  • 使用 Git LFS 管理大型檔案
  • 了解 LFS 的取捨

Git 為文字檔設計。把大型二進位檔（影片、PSD、遊戲素材、資料集、模型權重）直接放進 Git，每改一次就多存一整份，倉庫很快膨脹到幾 GB，每個人 clone 都要下載全部歷史版本。

GitHub 的限制：單一檔案超過 50 MB 會警告，超過 100 MB 會直接拒絕 push。建議倉庫整體保持在 1 GB 以下（詳細數字以官方文件為準）。

Git LFS（Large File Storage）的做法是：Git 裡只存一個幾行的「指標檔」，真正的大檔案放在另外的 LFS 伺服器，checkout 時才下載你需要的版本。

$ git lfs install # 每台電腦執行一次 $ git lfs track "*.psd" # 指定要用 LFS 管理的檔案類型 $ git add .gitattributes # 追蹤規則存在這個檔案，要 commit $ git add design.psd $ git commit -m "加入設計稿" $ git push $ git lfs ls-files # 列出由 LFS 管理的檔案

Git 裡存的指標檔長這樣：

version https://git-lfs.github.com/spec/v1 oid sha256:4d7a214614ab2935c943f9e0ff69d22eadbb8f32b1258daaa5e2ca24d17e2393 size 12345678
  • git lfs track 要在加入檔案之前設定；已經 commit 進一般 Git 的大檔案，要用 git lfs migrate 轉換（會改寫歷史）。
  • GitHub 的 LFS 有免費的儲存與流量額度，超過要購買。
  • 不是所有大檔都該進版本控制：可以重新產生的（編譯結果）或很少變動的大型資料集，放在雲端儲存並在 README 說明下載方式也很好。

🧭 這一課的重點

大型二進位檔直接放 Git 會讓每個版本都存一整份、倉庫膨脹。GitHub 對超過 50 MB 的檔案警告、超過 100 MB 拒絕 push。Git LFS 只在 Git 中存放指標檔，實際檔案放在 LFS 伺服器：git lfs install、git lfs track "*.psd"、commit .gitattributes。track 要在加入檔案前設定，已存在的要用 lfs migrate；LFS 有額度限制，也可考慮雲端儲存。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
