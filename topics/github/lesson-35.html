Projects 看板

這一課的目標

  • 建立 Projects 看板
  • 使用自訂欄位與檢視
  • 設定自動化

GitHub Projects 是一個可以放 Issue 與 PR 的看板／表格，像 Trello 或 Jira 的簡化版。它屬於使用者或組織，可以跨好幾個倉庫。

檢視方式適合
Board（看板）把卡片在「Todo → In Progress → Done」欄之間拖曳
Table（表格）像試算表一樣一次編輯很多項目的欄位
Roadmap（時間軸）依日期排列，看專案進度
  • 自訂欄位：Status、優先度、預估時間、迭代（Iteration，例如兩週一個 Sprint）。
  • 篩選與分組：例如「只看指派給我的」「依優先度分組」，可以存成不同的檢視。
  • 內建自動化：Issue 關閉時自動移到 Done、PR 合併時自動更新狀態、新 Issue 自動加入看板。
  • 草稿項目：還沒成形的想法可以先寫成草稿，之後再轉成正式 Issue。

一個實用的小團隊做法：每週開會時打開 Board 檢視，從左到右看一遍；每個人只從 Todo 拿最上面的卡片，PR 合併後卡片自動到 Done。

🧭 這一課的重點

GitHub Projects 是可放入 Issue 與 PR 的看板／表格，屬於使用者或組織、可跨倉庫。有 Board、Table、Roadmap 三種檢視；可加自訂欄位（狀態、優先度、迭代）、篩選分組並存成檢視；內建自動化可在 Issue 關閉或 PR 合併時更新狀態；也可先建草稿項目。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
