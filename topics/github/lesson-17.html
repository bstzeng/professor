stash：暫時收起來

這一課的目標

  • 用 stash 暫存修改
  • 查看與取回 stash
  • 知道 stash 的使用時機

你正在寫新功能，寫到一半，老闆說「線上有 bug，馬上修！」。現在的修改還不能 commit，但切換分支又會帶著這些修改走。這時用 stash：

▶ 動手做　實際執行的輸出

$ printf 'print("寫到一半")\n' >> app.py $ git stash push -m "功能寫到一半" Saved working directory and index state On main: 功能寫到一半 $ git status --short $ git stash list stash@{0}: On main: 功能寫到一半 $ git stash pop On branch main Changes not staged for commit: (use "git add <file>..." to update what will be committed) (use "git restore <file>..." to discard changes in working directory) modified: app.py no changes added to commit (use "git add" and/or "git commit -a") Dropped refs/stash@{0} (3292789d1a91a15575bb3a1bd43a32be343938ce) $ git status --short M app.py
指令作用
git stash push -m "說明"把未 commit 的修改收起來，工作目錄回到乾淨狀態（舊寫法 git stash）
git stash list列出所有收起來的東西
git stash pop取回最新的一個，並從清單移除
git stash apply取回但保留在清單中
git stash drop丟掉一個
git stash -u連未追蹤的新檔案也一起收

stash 就像一個「抽屜」：先把桌上的東西掃進去，處理完急事再拿出來。但抽屜放久了會忘記裡面有什麼——如果一件工作要擱置很久，不如開一個分支 commit 起來。

🧭 這一課的重點

git stash push -m 把未 commit 的修改收起來讓工作目錄變乾淨，stash list 列出、pop 取回並移除、apply 取回但保留、drop 丟掉、-u 連未追蹤檔一起收。適合臨時切去處理急事；要擱置很久的工作則應開分支 commit。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。

  2. pop 和 apply 有什麼不同？
  3. 新建立的檔案預設會被 stash 收起來嗎？
