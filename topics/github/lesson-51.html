開源禮儀與授權

這一課的目標

  • 比較常見的開源授權
  • 知道沒有授權條款的意義
  • 成為受歡迎的貢獻者

公開倉庫不等於開源。沒有 LICENSE 檔的程式碼，預設是「保留所有權利」——別人可以看，但法律上不能使用、修改或散布。想讓別人使用，就要選一個授權條款：

授權大意常見於
MIT幾乎什麼都能做，只要保留版權聲明；不提供任何擔保React、Rails 等大量專案
Apache 2.0類似 MIT，另外明確授予專利權、要求標示修改Kubernetes、Android 許多元件
GPL-3.0可自由使用修改，但散布衍生作品時必須以 GPL 開放原始碼（copyleft）許多 GNU 軟體
BSD與 MIT 類似的寬鬆授權FreeBSD 等
CC BY 4.0給文章、圖片等非程式內容；需標示作者文件、教材

不知道怎麼選，可以參考 choosealicense.com。本課提供的是一般性介紹，不構成法律意見；商業用途請諮詢專業人士。

當個受歡迎的貢獻者

  1. 先讀 README 與 CONTRIBUTING.md：很多專案規定了程式風格、測試方式、commit 格式。
  2. 先搜尋 Issue：你的問題可能已經有人回報過。
  3. 大改動先開 Issue 討論，維護者同意方向再動手，免得白做。
  4. 從 good first issue 標籤開始。
  5. PR 保持小而專注，附上測試；被要求修改時保持耐心。
  6. 維護者多半是志工，回覆慢是正常的。

CODE_OF_CONDUCT.md（行為準則）規範社群中的互動方式——尊重他人、不騷擾、不歧視，以及違反時如何處理。最常用的範本是 Contributor Covenant。

🧭 這一課的重點

沒有 LICENSE 的公開程式碼預設保留所有權利，別人不能合法使用。常見授權：MIT（寬鬆，保留版權聲明）、Apache 2.0（另授予專利權）、GPL-3.0（散布衍生作品須以 GPL 開源）、BSD、CC BY（非程式內容）；可參考 choosealicense.com（本課非法律意見）。貢獻前先讀 README 與 CONTRIBUTING、搜尋 Issue、大改動先討論、從 good first issue 開始、PR 小而專注並有耐心。CODE_OF_CONDUCT 規範社群互動。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
