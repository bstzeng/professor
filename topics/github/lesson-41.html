Secrets 與環境變數

這一課的目標

  • 在 Actions 中使用 Secrets
  • 區分 secrets 與 variables
  • 理解 GITHUB_TOKEN 與權限

部署時常需要密碼、API 金鑰。它們絕對不能寫在 workflow 檔或程式碼中（任何能看倉庫的人都看得到）。正確做法是存成 Secret：Settings → Secrets and variables → Actions → New repository secret。

steps: - run: ./deploy.sh env: API_KEY: ${{ secrets.API_KEY }} REGION: ${{ vars.REGION }}

用途密碼、金鑰、token不機密的設定，如區域、網址

語法${{ secrets.名稱 }}${{ vars.名稱 }}
  • 層級：可以設在倉庫、組織（多個倉庫共用）、或 Environment（例如 production 環境，可以要求有人核准才部署）。
  • GITHUB_TOKEN：每次執行自動產生的臨時 token，用來操作本倉庫（例如留言、發布）。用 permissions: 把它的權限縮到最小。
  • fork 來的 PR 拿不到 secrets：這是安全設計，避免陌生人開 PR 把你的金鑰印出來。
  • 能連到雲端服務時，優先用 OIDC（無需長期金鑰的短期憑證）取代存放雲端金鑰。

本機開發時，機密放在 .env 檔並加入 .gitignore（第 14 課），在 README 裡附一個沒有真實值的 .env.example 告訴別人需要哪些變數。

🧭 這一課的重點

金鑰不能寫在程式碼或 workflow 中，應存為 Secret，用 ${{ secrets.名稱 }} 取用；Secrets 寫入後不可讀、log 中自動遮蔽，不機密的設定用 Variables（${{ vars.名稱 }}）。可設在倉庫、組織或 Environment（可要求核准）。GITHUB_TOKEN 是自動產生的臨時 token，用 permissions 縮小權限；fork 的 PR 拿不到 secrets；雲端可用 OIDC。本機用 .env 加 .gitignore 與 .env.example。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
