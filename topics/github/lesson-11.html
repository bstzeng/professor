add 與 commit

這一課的目標

  • 用 git status 觀察狀態
  • 用 add 與 commit 建立版本
  • 寫出好的 commit 訊息

建立一個檔案，看看 Git 怎麼看待它：

▶ 動手做　實際執行的輸出

$ printf '# 我的專案\n' > README.md $ git status On branch main No commits yet Untracked files: (use "git add <file>..." to include in what will be committed) README.md nothing added to commit but untracked files present (use "git add" to track) $ git add README.md $ git status On branch main No commits yet Changes to be committed: (use "git rm --cached <file>..." to unstage) new file: README.md $ git commit -m "初始提交：加入 README" [main (root-commit) 0f345f7] 初始提交：加入 README 1 file changed, 1 insertion(+) create mode 100644 README.md $ git log commit 0f345f7d802ecdf6192599755baf6c6452e76be2 Author: Ming Chen <ming@example.com> Date: Sun Mar 1 10:05:00 2026 +0800 初始提交：加入 README

逐行解讀：

  • Untracked files：Git 看到了新檔案，但還沒在管理它。
  • git add 之後變成 Changes to be committed：已經放進暫存區。
  • git commit -m "訊息"：建立 commit。(root-commit) 表示這是第一個 commit，0f345f7 是它的雜湊。
  • git log 列出歷史。

好的 commit 訊息

✗ 不好✓ 好
update修正登入時密碼含空白會失敗的問題
改東西首頁加上聯絡表單
asdf將圖片壓縮，首頁載入時間從 3 秒降到 1 秒
  • 第一行是摘要，簡短（約 50 字元內）說明「這個 commit 做了什麼」。
  • 需要的話空一行，再寫詳細說明：為什麼要這樣改。
  • 一個 commit 只做一件事。半年後的你（或同事）會感謝你。
  • 很多團隊採用 Conventional Commits 格式：feat: 加入登入、fix: 修正…、docs: 更新 README。

小技巧：git add . 會加入目前資料夾下所有變更；git commit -am "訊息" 可以一次把已追蹤檔案的修改 add 加 commit（新檔案仍要先 add）。

🧭 這一課的重點

新檔案先是 Untracked；git add 後進入暫存區（Changes to be committed）；git commit -m 建立 commit，第一個標示 root-commit；git log 查看歷史。好的 commit 訊息第一行簡述做了什麼、內文說明為什麼，一個 commit 只做一件事，可採用 Conventional Commits。git add . 加入全部，commit -am 只適用已追蹤檔。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
