為什麼需要版本控制

這一課的目標

  • 說出不用版本控制的痛點
  • 知道版本控制解決的四件事
  • 理解為什麼不只工程師需要它

你一定看過這種資料夾：

報告.docx 報告_v2.docx 報告_v2_老師改過.docx 報告_最終版.docx 報告_最終版_真的最終版.docx 報告_最終版_真的最終版(1).docx

問題是：哪個才是最新的？v2 和最終版差在哪？三天前刪掉的那段，還找得回來嗎？兩個人同時改，誰的版本算數？

版本控制系統（Version Control System）就是為了解決這些問題：

  • 完整歷史：每次存檔（commit）都記錄「誰、什麼時候、改了什麼、為什麼」，可以隨時回到任何一個版本。
  • 比較差異：精確看出兩個版本之間哪幾行變了。
  • 平行開發：用「分支」同時嘗試好幾個方向，互不干擾，最後再合併。
  • 多人協作：大家各自修改，系統幫你合併；真的衝突時會明確告訴你。

Git 最擅長處理純文字檔案：程式碼、Markdown、設定檔、LaTeX 論文、網頁。Word、Excel、圖片這類二進位檔也能放，但 Git 看不懂它們的內容，只能整個檔案存一份。

🧭 這一課的重點

不用版本控制時，檔案會變成一堆「最終版」副本，搞不清楚差異、找不回刪掉的內容、多人修改互相覆蓋。版本控制提供完整歷史、比較差異、用分支平行開發與多人協作。Git 最擅長純文字檔，二進位檔只能整份存。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。

  2. 為什麼 Git 比較適合純文字檔？
  3. 除了程式碼，還有哪些東西適合用 Git 管理？
