Issue

這一課的目標

  • 建立與管理 Issue
  • 使用標籤、指派、里程碑
  • 在 commit 與 PR 中連結 Issue

Issue 是 GitHub 的「待辦事項＋討論串」：回報 bug、提議新功能、提問、記錄任務。每個 Issue 有一個編號（與 PR 共用編號序列），例如 #42。

功能用途
Labels 標籤分類：bug、enhancement、good first issue（適合新手）、help wanted
Assignees 指派誰負責處理
Milestone 里程碑歸到某個版本或期限，如「v2.0」，可看完成百分比
Issue 範本在 .github/ISSUE_TEMPLATE/ 放範本，要求回報者填寫重現步驟、環境等
Sub-issues把大任務拆成子任務

好的 bug 回報

## 發生了什麼 按下「匯出 PDF」後頁面一片空白。 ## 重現步驟 1. 登入後進入「報表」 2. 選擇 2025 年 3. 按「匯出 PDF」 ## 預期結果 下載 PDF 檔。 ## 環境 Windows 11、Chrome 130、版本 v2.3.1

自動連結

  • 在任何留言、commit 訊息中寫 #42，會自動變成連到 Issue 42 的連結。
  • 在 PR 說明或 commit 訊息中寫 Fixes #42、Closes #42、Resolves #42，合併到預設分支時自動關閉 Issue。
  • 寫 @使用者名稱 會通知那個人。

另外還有 Discussions：適合開放式的問答與交流，不像 Issue 那樣代表「一件要完成的事」。

🧭 這一課的重點

Issue 是 GitHub 的待辦與討論串，編號與 PR 共用。可用 Labels 分類（bug、enhancement、good first issue）、Assignees 指派、Milestone 歸到版本、Issue 範本規範回報內容、Sub-issues 拆分任務。好的 bug 回報包含現象、重現步驟、預期結果、環境。寫 #42 自動連結、Fixes #42 合併時自動關閉、@名稱 通知人。開放式問答可用 Discussions。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
