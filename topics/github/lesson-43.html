安全性功能

這一課的目標

  • 認識 GitHub 的安全工具
  • 處理 Dependabot 的警告與 PR
  • 了解 push protection

倉庫的 Security 分頁集中了幾個自動化安全工具（公開倉庫大多免費）：

工具做什麼
Dependabot alerts你用的套件出現已知漏洞時發出警告
Dependabot security updates自動開 PR 把有漏洞的套件升級到修補版本
Dependabot version updates定期開 PR 把套件升到最新版（用 .github/dependabot.yml 設定頻率）
Secret scanning掃描倉庫中是否有外洩的 token、金鑰
Push protection在你 push 時就擋下含有已知格式金鑰的 commit
Code scanning（CodeQL）靜態分析程式碼中的安全漏洞，例如 SQL 注入
# .github/dependabot.yml version: 2 updates: - package-ecosystem: "pip" directory: "/" schedule: interval: "weekly" - package-ecosystem: "github-actions" directory: "/" schedule: interval: "monthly"

收到 Dependabot 的 PR 時：看 CI 是否通過、讀一下套件的更新說明（尤其是主版號升級），沒問題就合併。不要讓這些 PR 堆積——越晚升級，一次要跨的版本越多。

如果 push protection 擋下了你的 push，不要選擇略過：把金鑰從 commit 中移除（amend 或 reset），改用 Secret 或 .env。萬一金鑰真的上去了，要立刻到服務商那裡撤銷並換一把新的——刪掉 commit 不夠，它可能已經被複製走了（第 49 課）。

另外可以在倉庫放一個 SECURITY.md，告訴別人發現漏洞時該私下怎麼聯絡你，而不是公開開 Issue。

🧭 這一課的重點

Security 分頁有 Dependabot（漏洞警告、自動開修補 PR、用 dependabot.yml 定期升級）、Secret scanning 與 Push protection（push 時就擋下含金鑰的 commit）、Code scanning（CodeQL 靜態分析）。Dependabot PR 要看 CI 與更新說明後盡快合併。金鑰外洩時要立刻撤銷並更換，刪 commit 不夠。SECURITY.md 說明漏洞的私下回報方式。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。

  2. push protection 擋下金鑰時該怎麼處理？
  3. 金鑰已經推上 GitHub，只刪掉 commit 夠嗎？
