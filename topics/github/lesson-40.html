GitHub Pages：免費架網站

這一課的目標

  • 用 GitHub Pages 發布靜態網站
  • 了解兩種發布來源
  • 知道 Pages 的限制

GitHub Pages 可以把倉庫裡的 HTML、CSS、JavaScript 直接變成一個公開的網站，網址是 https://使用者名稱.github.io/倉庫名稱/。個人作品集、專案文件、部落格都很適合。

發布來源設定適合
Deploy from a branchSettings → Pages → 選分支（如 main）與資料夾（/ 或 /docs）純 HTML 網站，什麼都不用建置
GitHub ActionsSettings → Pages → Source 選 GitHub Actions，用 workflow 建置後發布需要建置的網站（React、Vue、Hugo、Astro 等）

最簡單的做法：建立倉庫 ming.github.io（倉庫名稱等於「使用者名稱.github.io」），放一個 index.html，幾分鐘後打開 https://ming.github.io 就看得到了。

# 用 Actions 部署的 workflow 核心 permissions: pages: write id-token: write jobs: deploy: runs-on: ubuntu-latest environment: github-pages steps: - uses: actions/checkout@v4 - run: npm ci && npm run build - uses: actions/upload-pages-artifact@v3 with: path: dist - uses: actions/deploy-pages@v4
  • 只能放靜態網站：沒有伺服器端程式、沒有資料庫。
  • 可以設定自訂網域，並免費啟用 HTTPS。
  • 免費方案下，公開倉庫才能使用 Pages。不要拿來架商業網店或放機密資料。
  • 網站有容量與流量的使用限制，詳見官方文件。

🧭 這一課的重點

GitHub Pages 把倉庫中的靜態檔案發布成網站（使用者名稱.github.io/倉庫名稱）。發布來源可選分支（純 HTML，設定分支與 / 或 /docs）或 GitHub Actions（先建置再用 upload-pages-artifact 與 deploy-pages 發布）。名為「使用者名稱.github.io」的倉庫會成為根網址。只支援靜態網站，可設自訂網域與免費 HTTPS，免費方案需公開倉庫，有容量流量限制。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
