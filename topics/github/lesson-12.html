push 與 pull

這一課的目標

  • 把 commit 推上 GitHub
  • 把別人的修改拉下來
  • 把本機現有專案推上新的 GitHub 倉庫

在 clone 下來的倉庫裡做一個 commit，然後 push：

▶ 動手做　實際執行的輸出

$ printf 'print("hello")\n' > app.py $ git add app.py && git commit -q -m "加入 app.py" $ git status On branch main Your branch is ahead of 'origin/main' by 1 commit. (use "git push" to publish your local commits) nothing to commit, working tree clean $ git push To /home/ming/github/ming/demo.git 562cf03..576b207 main -> main $ git status On branch main Your branch is up to date with 'origin/main'. nothing to commit, working tree clean

注意 git status 的變化：commit 之後是 ahead of 'origin/main' by 1 commit（你比 GitHub 多一個），push 之後變成 up to date。origin/main 是 Git 記住的「上次看到 GitHub 上的 main 在哪」。

把別人的修改拉下來

假設你在桌機 push 了一個 commit，現在回到筆電：

▶ 動手做　實際執行的輸出

$ git fetch From /home/ming/github/ming/demo 562cf03..e336dc9 main -> origin/main $ git status On branch main Your branch is behind 'origin/main' by 1 commit, and can be fast-forwarded. (use "git pull" to update your local branch) nothing to commit, working tree clean $ git log --oneline --all e336dc9 桌機：加入 app.py 562cf03 Initial commit $ git pull Updating 562cf03..e336dc9 Fast-forward app.py | 1 + 1 file changed, 1 insertion(+) create mode 100644 app.py $ git log --oneline e336dc9 桌機：加入 app.py 562cf03 Initial commit

git fetch 只更新 origin/main，不碰你的檔案；git pull 則是 fetch 之後再合併。養成習慣：開始工作前先 pull。

本機已有專案，推到新的 GitHub 倉庫

# 先在 GitHub 建立一個「空的」倉庫（不要勾 README） $ git remote add origin https://github.com/ming/demo.git $ git push -u origin main

-u（--set-upstream）讓本機的 main 記住「對應 origin 的 main」，之後只要打 git push、git pull 就好。

🧭 這一課的重點

commit 後 git status 顯示 ahead of origin/main，push 後變成 up to date；origin/main 是 Git 記住的遠端分支位置。git fetch 只更新 origin/main，git pull 是 fetch 加合併，開始工作前應先 pull。本機專案推到新倉庫：git remote add origin 網址，再 git push -u origin main。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
