merge：合併分支

這一課的目標

  • 理解快轉合併
  • 理解三方合併與合併 commit
  • 合併後刪除分支

功能做完了，要把 feature 分支合併回 main：先切到 main，再 git merge feature。合併有兩種情況。

情況一：快轉（fast-forward）

如果 main 在你開分支之後沒有新的 commit，Git 只要把 main 的標籤往前移就好，不需要新的 commit：

▶ 動手做　實際執行的輸出

$ git merge feature-login Updating edad20f..ea55c3c Fast-forward login.py | 1 + 1 file changed, 1 insertion(+) create mode 100644 login.py $ git log --oneline --graph * ea55c3c 加入登入功能 * edad20f 加入 app.py * 582091b 初始提交：加入 README $ git branch -d feature-login Deleted branch feature-login (was ea55c3c).

情況二：三方合併（three-way merge）

如果 main 在這段期間也有了新 commit，兩條線分岔了。Git 會比較三個版本——兩個分支的最新 commit，加上它們的共同祖先——自動合併，並產生一個有兩個父 commit 的「合併 commit」：

▶ 動手做　實際執行的輸出

$ git log --oneline --graph --all * 03ce36c README 加上說明 | * ea55c3c 加入登入功能 |/ * edad20f 加入 app.py * 582091b 初始提交：加入 README $ git merge --no-edit feature-login Merge made by the 'ort' strategy. login.py | 1 + 1 file changed, 1 insertion(+) create mode 100644 login.py $ git log --oneline --graph * 1867a44 Merge branch 'feature-login' |\ | * ea55c3c 加入登入功能 * | 03ce36c README 加上說明 |/ * edad20f 加入 app.py * 582091b 初始提交：加入 README

'ort' 是 Git 目前預設的合併策略名稱。只要兩邊改的是不同的地方（這裡一邊改 README、一邊加 login.py），Git 都能自動合併。兩邊改到同一行，就會發生衝突（下一課）。

合併完成的分支可以用 git branch -d 刪除——刪的只是標籤，commit 都還在 main 的歷史裡。

🧭 這一課的重點

合併時先切到目標分支再 git merge 來源分支。若目標分支沒有新 commit，Git 只把標籤往前移（快轉，Fast-forward）；若兩邊都有新 commit，Git 以兩個分支與共同祖先進行三方合併，產生有兩個父 commit 的合併 commit（預設策略 ort）。改到不同地方可自動合併，改同一行則會衝突。合併後可刪除分支。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
