amend：修改上一個 commit

這一課的目標

  • 用 --amend 修改 commit 訊息
  • 用 --amend 補上漏掉的檔案
  • 理解 amend 會改變雜湊

剛 commit 完發現訊息打錯字：

▶ 動手做　實際執行的輸出

$ printf 'MIT\n' > LICENSE $ git add LICENSE && git commit -q -m "加入授全條款" $ git log --oneline -1 541711b 加入授全條款 $ git commit --amend -m "加入授權條款" [main 098731a] 加入授權條款 Date: Sun Mar 1 10:07:00 2026 +0800 1 file changed, 1 insertion(+) create mode 100644 LICENSE $ git log --oneline 098731a 加入授權條款 edad20f 加入 app.py 582091b 初始提交：加入 README

注意雜湊從 541711b 變成了 098731a：amend 並不是「修改」舊 commit，而是做一個新的 commit 取代它（舊的仍在 reflog 裡，第 28 課）。

漏了檔案也一樣：先 git add 漏掉的檔案，再 git commit --amend --no-edit（--no-edit 表示沿用原本的訊息）。

⚠️ 跟 reset 一樣，只對還沒 push 的 commit 使用。如果已經 push，amend 之後本機和 GitHub 的歷史就分岔了，必須強制推送（git push --force-with-lease）——在自己一個人的分支上可以，在共用分支上會給別人帶來麻煩。

想修改更早之前的 commit，可以用互動式 rebase：git rebase -i HEAD~3，在打開的清單中把 pick 改成 reword（改訊息）、squash（合併到前一個）、drop（刪除）等。

🧭 這一課的重點

git commit --amend -m 可修改上一個 commit 的訊息；漏了檔案先 add 再 commit --amend --no-edit。amend 是做新 commit 取代舊的，雜湊會改變，只應用在未 push 的 commit；已 push 則需強制推送（--force-with-lease），共用分支應避免。更早的 commit 可用 git rebase -i 改寫。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
