分散式版本控制

這一課的目標

  • 理解集中式與分散式的差別
  • 認識遠端倉庫（remote）
  • 知道 push 與 pull 的方向

早期的版本控制（例如 SVN）是集中式的：歷史只存在一台伺服器上，每次查歷史、存檔都要連線。伺服器壞了，大家都不能工作。

Git 是分散式的：每個人 clone 下來的，都是完整的歷史。你在飛機上也能 commit、查 log、開分支；GitHub 只是大家約定好的「中央集合點」。

動作方向說明
git cloneGitHub → 你第一次把整個倉庫複製下來
git push你 → GitHub把你的新 commit 送上去
git fetchGitHub → 你把別人的新 commit 拿下來，但不動你的檔案
git pullGitHub → 你fetch ＋ 合併到你目前的分支

記住：commit 只存在你的電腦上，直到你 push。很多新手以為 commit 就「上傳」了，其實沒有。

🧭 這一課的重點

集中式版本控制的歷史只在一台伺服器上；Git 是分散式的，每個 clone 都有完整歷史，可離線 commit 與查詢，GitHub 只是大家同步的集合點。clone 第一次複製、push 送出、fetch 取回不合併、pull 取回並合併。commit 在 push 之前只存在本機。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。

檢查你的理解

  1. 集中式與分散式版本控制有什麼差別？
  2. fetch 和 pull 有什麼不同？
  3. commit 之後，GitHub 上就有了嗎？
