團隊與權限

這一課的目標

  • 認識個人帳號與組織
  • 了解倉庫的權限等級
  • 安全地管理成員

倉庫可以屬於個人帳號或組織（Organization）。個人倉庫可以邀請 Collaborator（協作者）；公司或社群專案則建議建立組織，把成員分成 Teams，再把團隊指派到倉庫。

角色能做什麼
Read看程式碼、開 Issue 和留言、clone
TriageRead ＋ 管理 Issue 與 PR（標籤、指派、關閉），不能 push
WriteTriage ＋ push、合併 PR
MaintainWrite ＋ 管理部分倉庫設定（不含敏感與破壞性操作）
Admin完全控制，包括刪除倉庫、變更可見性、管理權限
  • 最小權限原則：只給完成工作所需的權限。大部分開發者 Write 就夠了，Admin 留給少數人。
  • 組織可以要求所有成員啟用兩步驟驗證。
  • 成員離職時從組織移除，他就失去所有倉庫的權限——這是用組織而不是個人帳號管理公司專案的主要理由。
  • Outside collaborator：不是組織成員、但被允許存取特定倉庫的外部人員（例如外包）。

公開倉庫的可見性設定（Settings → General → Danger Zone）可以把私有轉公開或反之；轉公開前務必確認歷史中沒有密碼與金鑰（第 49 課）。

🧭 這一課的重點

倉庫可屬於個人（邀請 Collaborator）或組織（以 Teams 管理成員）。權限由低到高：Read、Triage（管理 Issue／PR）、Write（push、合併）、Maintain、Admin（刪除、可見性、權限）。應遵循最小權限原則、要求 2FA；組織讓離職者一次失去所有權限；Outside collaborator 是外部協作者。私有轉公開前要確認歷史中沒有機密。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
