Releases 與套件發布

這一課的目標

  • 在 GitHub 建立 Release
  • 自動產生更新說明
  • 用 Actions 在打 tag 時自動發布

Release 是建立在 tag（第 18 課）之上的「發布頁面」：版本號、更新說明、可下載的檔案（例如編譯好的安裝程式）。在倉庫右側 Releases → Draft a new release：

  1. 選擇或建立一個 tag（如 v1.2.0）。
  2. 按 Generate release notes：GitHub 會自動列出上次發布以來合併的所有 PR 與貢獻者。
  3. 拖曳上傳附件（binaries）。
  4. 勾選 Set as a pre-release 表示測試版，或直接發布。

使用者可以按倉庫的 Watch → Custom → Releases，只在有新版本時收到通知。

打 tag 自動發布

on: push: tags: ["v*"] permissions: contents: write jobs: release: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - run: make build - run: gh release create "$GITHUB_REF_NAME" dist/* --generate-notes env: GH_TOKEN: ${{ github.token }}

這樣只要 git tag -a v1.2.0 -m ... && git push origin v1.2.0，Actions 就會自動建置並建立 Release。

GitHub Packages 則可以存放 npm、Maven、NuGet 套件與 Docker 映像檔（ghcr.io）。不過 Python 與 JavaScript 的公開套件通常還是發布到 PyPI、npmjs.com，也能用 Actions 自動完成。

🧭 這一課的重點

Release 建立在 tag 之上，包含版本號、更新說明與可下載附件；Generate release notes 自動列出合併的 PR 與貢獻者，可標為 pre-release。使用者可 Watch 只訂閱 Releases。用 on: push: tags: v* 的 workflow 搭配 gh release create 可在推送 tag 時自動發布。GitHub Packages 存放 npm、Maven、Docker（ghcr.io）等套件。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
