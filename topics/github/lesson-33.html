讓 fork 跟上原專案

這一課的目標

  • 加入 upstream 遠端
  • 把原專案的新 commit 同步到 fork
  • 使用 GitHub 的 Sync fork 按鈕

fork 之後，原專案持續有人更新，你的 fork 卻停在 fork 那一刻。要同步，先把原專案加成第二個遠端，慣例叫 upstream：

▶ 動手做　實際執行的輸出

$ git remote -v origin /home/ming/github/ming/tool.git (fetch) origin /home/ming/github/ming/tool.git (push) $ git remote add upstream ../github/torvalds/tool.git $ git fetch upstream From ../github/torvalds/tool * [new branch] main -> upstream/main $ git merge upstream/main Updating 5c76f07..310b1e9 Fast-forward VERSION | 1 + 1 file changed, 1 insertion(+) create mode 100644 VERSION $ git push origin main To /home/ming/github/ming/tool.git 5c76f07..310b1e9 main -> main
  • origin：你的 fork（你可以 push）。
  • upstream：原專案（只讀取）。
  • git fetch upstream 把原專案的新 commit 拿下來，成為 upstream/main。
  • git merge upstream/main 合併到你本機的 main，再 git push origin main 更新你的 fork。

更簡單的方法：在 GitHub 上你的 fork 頁面，按 Sync fork → Update branch，GitHub 直接幫你同步，之後本機 git pull 即可。

開新 PR 前先同步，能大幅減少衝突。如果你的 PR 分支已經落後很多，可以 git rebase upstream/main 再 git push --force-with-lease（這是你自己的分支，可以這樣做）。

🧭 這一課的重點

fork 不會自動跟上原專案。git remote add upstream 原專案網址 加入第二個遠端；git fetch upstream 取得原專案更新成為 upstream/main；git merge upstream/main 合併後 git push origin main 更新 fork。也可在 GitHub 按 Sync fork。開 PR 前先同步可減少衝突，落後的 PR 分支可 rebase upstream/main 後 --force-with-lease。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
