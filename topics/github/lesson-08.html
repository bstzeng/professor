登入驗證：HTTPS 與 SSH

這一課的目標

  • 知道 GitHub 不接受密碼推送
  • 設定 Personal Access Token 或 Git Credential Manager
  • 建立並登記 SSH 金鑰

push 到 GitHub 時，GitHub 要確認你有權限。自 2021 年 8 月起，GitHub 不再接受用帳號密碼做 Git 操作，你需要以下其中一種方式：

方式網址長相適合
HTTPS ＋ 憑證管理員https://github.com/ming/demo.git新手；Windows 的 Git 已內建 Git Credential Manager，第一次 push 會跳出瀏覽器登入
HTTPS ＋ Personal Access Token同上沒有憑證管理員時；把 token 當密碼貼上
SSH 金鑰git@github.com:ming/demo.git常用終端機的人；設定一次就不用再輸入

方法一：Personal Access Token

GitHub 右上角頭像 → Settings → Developer settings → Personal access tokens。建議用 Fine-grained token：可以限定只能存取某幾個倉庫、只給需要的權限（例如 Contents 讀寫），並設定到期日。token 只顯示一次，要像密碼一樣保管。

方法二：SSH 金鑰

$ ssh-keygen -t ed25519 -C "ming@example.com" # 一路按 Enter（可以設定密語保護私鑰） $ cat ~/.ssh/id_ed25519.pub # 複製輸出的整行，貼到 GitHub → Settings → SSH and GPG keys → New SSH key $ ssh -T git@github.com

最後一行成功時會看到 Hi ming! You've successfully authenticated。.pub 是公鑰，可以給別人；沒有 .pub 的 id_ed25519 是私鑰，絕對不能外流。

另一個簡單的選擇是 GitHub 官方的命令列工具 gh：執行 gh auth login，它會引導你用瀏覽器登入並設定好 Git 的驗證（第 45 課）。

🧭 這一課的重點

GitHub 自 2021 年 8 月起不接受密碼做 Git 操作。可用 HTTPS 搭配憑證管理員（Windows 內建，第一次會跳瀏覽器登入）或 Personal Access Token（建議 Fine-grained、限定倉庫與期限），或用 ssh-keygen 建立 ed25519 金鑰並把公鑰貼到 GitHub。私鑰絕不外流；gh auth login 也能一次設定好。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
