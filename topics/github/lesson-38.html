GitHub Actions 入門

這一課的目標

  • 理解 GitHub Actions 的用途
  • 讀懂 workflow 檔的結構
  • 認識觸發事件與 runner

GitHub Actions 讓你在發生某些事情時（push、開 PR、排程、手動按按鈕）自動執行工作：跑測試、檢查格式、建置、部署、發布⋯⋯。設定寫在倉庫的 .github/workflows/*.yml，用 YAML 格式。

name: CI on: push: branches: [main] pull_request: jobs: test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-python@v5 with: python-version: "3.12" - run: pip install -r requirements.txt - run: pytest
名詞意思上例
workflow一個 yml 檔就是一個工作流程CI
on（event）什麼時候觸發push 到 main，或任何 PR
job一組步驟，在一台機器上執行；多個 job 預設平行執行test
runs-on（runner）在哪種機器上跑GitHub 提供的 Ubuntu 虛擬機
step一個步驟：uses 使用別人寫好的 action，run 執行指令checkout、安裝 Python、裝套件、跑 pytest
  • actions/checkout 把你的倉庫程式碼抓到 runner 上——幾乎每個 workflow 第一步都是它。
  • @v4 是 action 的版本；為了安全，重要專案常改成固定到完整的 commit 雜湊。
  • YAML 用縮排表示層級，只能用空白不能用 Tab，縮排錯誤是最常見的錯。

執行結果在倉庫的 Actions 分頁，點進去可以看每個 step 的輸出。公開倉庫使用 GitHub 提供的 runner 免費；私有倉庫每月有免費額度，超過要付費。

🧭 這一課的重點

GitHub Actions 在 push、PR、排程或手動觸發時自動執行工作，設定寫在 .github/workflows/*.yml。workflow 是一個檔、on 是觸發事件、job 是在一台 runner 上執行的步驟組（預設平行）、runs-on 指定機器、step 用 uses 引用 action 或用 run 執行指令。checkout 幾乎是第一步；YAML 以空白縮排。公開倉庫免費、私有倉庫有每月額度。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
