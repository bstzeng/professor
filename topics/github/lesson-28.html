cherry-pick 與 reflog

這一課的目標

  • 用 cherry-pick 複製單一 commit
  • 用 reflog 找回被 reset 掉的 commit
  • 理解 reflog 的期限

cherry-pick：只拿我要的那一個

experiment 分支有兩個 commit，你只想要其中「加入 util.py 小工具」那一個，不要實驗性修改：

▶ 動手做　實際執行的輸出

$ git log --oneline experiment 5c28245 實驗性修改 aec5ad2 加入 util.py 小工具 edad20f 加入 app.py 582091b 初始提交：加入 README $ git cherry-pick experiment~1 [main 21aeb91] 加入 util.py 小工具 Date: Sun Mar 1 10:08:00 2026 +0800 1 file changed, 1 insertion(+) create mode 100644 util.py $ git log --oneline 21aeb91 加入 util.py 小工具 edad20f 加入 app.py 582091b 初始提交：加入 README

cherry-pick 把那個 commit 的修改複製一份到目前分支，產生新雜湊（aec5ad2 → 21aeb91）。常見用途：把 main 上的 bug 修正搬到舊版本的維護分支。

reflog：Git 的「黑盒子」

不小心 reset --hard 掉了重要的 commit？別慌：

▶ 動手做　實際執行的輸出

$ git reset --hard HEAD~1 HEAD is now at edad20f 加入 app.py $ git log --oneline edad20f 加入 app.py 582091b 初始提交：加入 README $ git reflog edad20f HEAD@{0}: reset: moving to HEAD~1 830b714 HEAD@{1}: commit: 重要的工作 edad20f HEAD@{2}: commit: 加入 app.py 582091b HEAD@{3}: commit (initial): 初始提交：加入 README $ git reset --hard HEAD@{1} HEAD is now at 830b714 重要的工作 $ git log --oneline 830b714 重要的工作 edad20f 加入 app.py 582091b 初始提交：加入 README

git reflog 記錄了 HEAD 在你這台電腦上走過的每一步，即使 commit 已經沒有任何分支指著它。找到它（HEAD@{1}），reset 回去或開一個新分支指向它（git branch rescue 830b714）就救回來了。

限制：reflog 只存在本機、不會 push；沒有分支指向的 commit 大約 30 天到 90 天後會被清理（依設定）。另外，從來沒有 commit 過的修改（例如被 git restore 丟掉的）不在 reflog 裡，救不回來——所以多 commit 永遠是好習慣。

🧭 這一課的重點

git cherry-pick 雜湊 把指定 commit 的修改複製到目前分支（產生新雜湊），常用於把 bug 修正搬到維護分支。git reflog 記錄 HEAD 在本機走過的每一步，可找回被 reset 掉的 commit 並 reset 回去或開新分支指向它。reflog 只在本機、無人指向的 commit 約 30～90 天後清理；從未 commit 的修改救不回來。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
