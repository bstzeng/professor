CI：每次 push 自動測試

這一課的目標

  • 理解 CI 的意義
  • 在 PR 上看懂檢查結果
  • 用矩陣在多個版本上測試

CI（持續整合）的想法是：每次有人 push 或開 PR，就自動跑一次完整的測試。問題在剛出現時就被發現，而不是上線後才爆炸。

上一課的 workflow 就是 CI。PR 頁面下方會顯示檢查結果：🟡 執行中、✅ 通過、❌ 失敗。點 Details 看失敗的 log；搭配分支保護的「Require status checks」（第 36 課），測試沒過就無法合併。

矩陣：一次測好幾種環境

jobs: test: strategy: matrix: os: [ubuntu-latest, windows-latest, macos-latest] python: ["3.11", "3.12", "3.13"] runs-on: ${{ matrix.os }} steps: - uses: actions/checkout@v4 - uses: actions/setup-python@v5 with: python-version: ${{ matrix.python }} - run: pip install -r requirements.txt - run: pytest

這會產生 3 × 3 = 9 個 job 平行執行，確保你的程式在三種作業系統、三個 Python 版本上都能跑。${{ }} 是 Actions 的運算式語法。

  • 快取：actions/setup-python、actions/setup-node 都有 cache 選項，可以快取下載的套件，加快每次執行。
  • Lint：除了測試，CI 也常跑格式檢查（如 ruff、eslint、prettier），讓程式風格一致。
  • 徽章：在 README 放上 workflow 的狀態徽章，大家一眼就知道 main 是不是綠燈。

🧭 這一課的重點

CI 持續整合在每次 push 或開 PR 時自動跑完整測試，讓問題及早發現。PR 下方顯示執行中、通過或失敗，Details 看 log，搭配分支保護可讓測試失敗時無法合併。strategy.matrix 可一次在多種作業系統與版本上測試（3×3 產生 9 個 job），${{ }} 是運算式語法；還可加入快取、lint 與狀態徽章。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
