參照：HEAD 與分支的真面目

這一課的目標

  • 認識 .git 資料夾的結構
  • 看見分支只是檔案
  • 理解 HEAD 的兩種狀態

▶ 動手做　實際執行的輸出

$ ls .git COMMIT_EDITMSG HEAD branches config description hooks index info logs objects refs $ cat .git/HEAD ref: refs/heads/main $ ls .git/refs/heads dev main $ cat .git/refs/heads/main edad20f121e019738a20f1cf7b2026fc83cbc709 $ git rev-parse main dev HEAD edad20f121e019738a20f1cf7b2026fc83cbc709 edad20f121e019738a20f1cf7b2026fc83cbc709 edad20f121e019738a20f1cf7b2026fc83cbc709 $ git switch -q dev && cat .git/HEAD ref: refs/heads/dev

真相大白：

  • 分支 main 就是 .git/refs/heads/main 這個檔案，內容只有一行 40 字元的 commit 雜湊。這就是為什麼開分支幾乎不花時間。
  • .git/HEAD 的內容是 ref: refs/heads/main——「我現在在 main 上」。切到 dev，它就變成 ref: refs/heads/dev。
  • 遠端分支在 .git/refs/remotes/origin/，標籤在 .git/refs/tags/。（分支很多時，Git 會把它們打包進 .git/packed-refs 一個檔案裡。）
.git 中的項目用途
objects/所有物件（blob、tree、commit、tag）
refs/分支、標籤、遠端分支
HEAD目前所在的分支
index暫存區（一個二進位檔）
config這個倉庫的設定（遠端網址等）
logs/reflog 的紀錄
hooks/在 commit、push 等時機自動執行的腳本範例

分離的 HEAD（detached HEAD）

如果你 git switch --detach 雜湊（或 git checkout 雜湊）切到某個 commit 而不是分支，HEAD 的內容會直接是一個雜湊，稱為 detached HEAD。這時可以看、可以實驗，但新 commit 不屬於任何分支，切走就會「迷路」（只能靠 reflog 找）。想保留的話：git switch -c 新分支名稱。

🧭 這一課的重點

分支 main 就是 .git/refs/heads/main 檔案，內容是一行 commit 雜湊；.git/HEAD 寫著 ref: refs/heads/main 表示目前所在分支。遠端分支在 refs/remotes、標籤在 refs/tags，也可能打包進 packed-refs。.git 中還有 objects、index（暫存區）、config、logs（reflog）、hooks。直接切到某個 commit 會成為 detached HEAD，新 commit 不屬於任何分支，要用 switch -c 保存。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
