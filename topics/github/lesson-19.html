在 GitHub 網頁上操作

這一課的目標

  • 在網頁上編輯與上傳檔案
  • 瀏覽歷史與差異
  • 認識 github.dev 與鍵盤快捷鍵

很多小事可以直接在 GitHub 網站完成：

想做的事怎麼做
編輯一個檔案打開檔案 → 右上角鉛筆圖示 → 修改 → Commit changes，可選擇直接 commit 到 main 或開新分支並建立 Pull Request
上傳檔案倉庫首頁 Add file → Upload files，拖曳檔案進去（單檔有大小限制）
新增檔案Add file → Create new file，檔名中打 / 會自動建立資料夾
看歷史檔案頁面的 History，或倉庫首頁的 commits 數字
看是誰改的檔案頁面的 Blame：每一行最後由哪個 commit 修改
比較兩個版本網址 /compare/v1.0.0...main

在倉庫頁面按鍵盤上的 .（句點），或把網址的 github.com 改成 github.dev，會在瀏覽器中打開一個網頁版的 VS Code，可以同時編輯多個檔案再一次 commit。按 t 可以快速搜尋檔案、? 列出所有快捷鍵。

Blame 對應的指令是 git blame：

▶ 動手做　實際執行的輸出

$ git blame app.py edad20f1 (Ming Chen 2026-03-01 10:05:00 +0800 1) print("hello") 44f2b99b (Hua Lin 2026-03-01 10:06:00 +0800 2) print("world")

網頁操作很方便，但它沒有本機的完整歷史與工具，也不能執行程式測試。小修改（改錯字、更新 README）用網頁，真正的開發還是在本機。

🧭 這一課的重點

GitHub 網頁可以直接編輯（鉛筆圖示後 Commit changes，可選 commit 到 main 或開分支 PR）、上傳與新增檔案、看 History 與 Blame、用 /compare 比較版本。按 . 或改用 github.dev 可開啟網頁版 VS Code，t 搜尋檔案、? 列出快捷鍵。git blame 對應 Blame 功能。真正開發仍在本機。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
