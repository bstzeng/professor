常見災難與解法

這一課的目標

  • 處理上傳了機密的情況
  • 修正在錯的分支 commit
  • 用 bisect 找出出錯的 commit

災難一：把 .env 上傳了

▶ 動手做　實際執行的輸出

$ git log --oneline --stat -1 c9de246 加入設定 .env | 1 + 1 file changed, 1 insertion(+) $ git rm --cached .env rm '.env' $ printf '.env\n' >> .gitignore $ git add .gitignore && git commit -q -m "停止追蹤 .env" $ git status --short --ignored !! .env $ git log --oneline --all -- .env 5053070 停止追蹤 .env c9de246 加入設定

git rm --cached 讓 Git 停止追蹤（檔案還在你的硬碟上），加入 .gitignore 後狀態變成 !!（已忽略）。但注意最後一行：舊的 commit 裡仍然有 .env。如果已經 push 到公開倉庫，第一件事是撤銷那把金鑰。

災難二：在 main 上 commit 了本該在功能分支的東西

▶ 動手做　實際執行的輸出

$ printf 'def pay(): pass\n' > pay.py && git add pay.py && git commit -q -m "加入付款功能" $ git branch feature-pay $ git reset --hard HEAD~1 HEAD is now at edad20f 加入 app.py $ git switch feature-pay Switched to branch 'feature-pay' $ git log --oneline --graph --all * 94e21eb 加入付款功能 * edad20f 加入 app.py * 582091b 初始提交：加入 README

先用 git branch 在目前位置建立分支「保存」那個 commit，再把 main 退回去，最後切到新分支——commit 就搬家了。

災難三：程式壞了，不知道是哪個 commit

▶ 動手做　實際執行的輸出

$ git log --oneline a815385 第 6 版 b3606b1 第 5 版 0066adc 第 4 版 49f2453 第 3 版 8cd7188 第 2 版 feb7711 第 1 版 edad20f 加入 app.py 582091b 初始提交：加入 README $ git bisect start HEAD HEAD~6 Bisecting: 2 revisions left to test after this (roughly 2 steps) [49f245380ef841728a0fc43d88ebe563286b06a2] 第 3 版 $ git bisect run python3 app.py running 'python3' 'app.py' hello Bisecting: 0 revisions left to test after this (roughly 1 step) [b3606b1b0fc703739eabf85474a24dccb16dcd3d] 第 5 版 running 'python3' 'app.py' hello Traceback (most recent call last): File "/home/ming/demo/app.py", line 5, in <module> print(1/0) ~^~ ZeroDivisionError: division by zero Bisecting: 0 revisions left to test after this (roughly 0 steps) [0066adc1c8cf0e26630e40ad68a1f533d019fcc0] 第 4 版 running 'python3' 'app.py' hello Traceback (most recent call last): File "/home/ming/demo/app.py", line 5, in <module> print(1/0) ~^~ ZeroDivisionError: division by zero 0066adc1c8cf0e26630e40ad68a1f533d019fcc0 is the first bad commit commit 0066adc1c8cf0e26630e40ad68a1f533d019fcc0 Author: Ming Chen <ming@example.com> Date: Sun Mar 1 10:09:00 2026 +0800 第 4 版 app.py | 1 + 1 file changed, 1 insertion(+) bisect found first bad commit $ git bisect reset Previous HEAD position was 0066adc 第 4 版 Switched to branch 'main'

git bisect 用二分搜尋：告訴它一個壞的（HEAD）和一個好的（HEAD~6）commit，它會切到中間讓你測試。用 git bisect run 指令，指令成功（結束碼 0）表示好、失敗表示壞，Git 自動找到「第 4 版」是第一個壞掉的 commit。1000 個 commit 也只要測大約 10 次。

🧭 這一課的重點

上傳 .env：git rm --cached 停止追蹤並加入 .gitignore，但舊 commit 仍有它，已 push 就要先撤銷金鑰（必要時用 git filter-repo 重寫歷史）。在錯的分支 commit：git branch 新分支保存、reset --hard HEAD~1 退回、switch 過去。找出出錯的 commit：git bisect start 壞 好，加 bisect run 自動以結束碼判斷，二分搜尋只需約 log2(N) 次。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
