tag 與版本號

這一課的目標

  • 建立附註標籤
  • 理解語意化版本 SemVer
  • 推送標籤到 GitHub

commit 的雜湊不好記。發布正式版時，可以給那個 commit 貼一個標籤（tag）：

▶ 動手做　實際執行的輸出

$ git tag -a v1.0.0 -m "第一個正式版" $ printf 'print("v1.1")\n' > app.py && git commit -q -am "小修正" $ git tag v1.0.0 $ git describe --tags v1.0.0-1-g6b6b9eb $ git show v1.0.0 --stat tag v1.0.0 Tagger: Ming Chen <ming@example.com> Date: Sun Mar 1 10:06:00 2026 +0800 第一個正式版 commit edad20f121e019738a20f1cf7b2026fc83cbc709 Author: Ming Chen <ming@example.com> Date: Sun Mar 1 10:05:00 2026 +0800 加入 app.py app.py | 1 + 1 file changed, 1 insertion(+)

-a 建立附註標籤（annotated tag），會記錄建立者、時間和說明，正式發布建議用它；不加 -a 是輕量標籤，只是一個名字。git describe 的 v1.0.0-1-g6b6b9eb 表示「v1.0.0 之後又多了 1 個 commit，目前在 6b6b9eb」。

語意化版本（SemVer）

版本號 主版號.次版號.修訂號，例如 2.4.1：

哪個數字加 1時機例子
主版號 MAJOR不相容的改變（舊的用法會壞）1.9.3 → 2.0.0
次版號 MINOR新增功能，向下相容1.9.3 → 1.10.0
修訂號 PATCH修 bug，向下相容1.9.3 → 1.9.4

標籤預設不會隨 git push 上傳，要另外推送：

$ git push origin v1.0.0 # 或一次推送所有標籤 $ git push --tags

在 GitHub 上，標籤可以進一步做成 Release，附上更新說明與下載檔（第 42 課）。

🧭 這一課的重點

git tag -a v1.0.0 -m 建立附註標籤（記錄建立者、時間、說明），適合正式發布；git describe 顯示距離最近標籤多少 commit。語意化版本 MAJOR.MINOR.PATCH：不相容改變加主版號、新功能加次版號、修 bug 加修訂號。標籤需 git push origin 標籤 或 --tags 另外推送，在 GitHub 可做成 Release。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
