打包與垃圾回收

這一課的目標

  • 理解鬆散物件與 packfile
  • 認識 git gc
  • 了解 Git 用 SHA-1 的安全議題

每個新物件一開始都是 .git/objects/ 下的一個壓縮檔（鬆散物件，loose object）。修改一個大檔案的一行，就會多一個幾乎一樣的 blob——看起來很浪費。所以 Git 會定期打包：

▶ 動手做　實際執行的輸出

$ git count-objects -v count: 30 size: 120 in-pack: 0 packs: 0 size-pack: 0 prune-packable: 0 garbage: 0 size-garbage: 0 $ git gc --quiet $ git count-objects -v count: 0 size: 0 in-pack: 30 packs: 1 size-pack: 4 prune-packable: 0 garbage: 0 size-garbage: 0 $ ls .git/objects/pack pack-b837483a8f924c27b75f3840c303b55e481a798c.idx pack-b837483a8f924c27b75f3840c303b55e481a798c.pack pack-b837483a8f924c27b75f3840c303b55e481a798c.rev

git gc（garbage collection）把 30 個鬆散物件打包成一個 packfile（.pack 存資料，.idx 是索引）。在 pack 裡，相似的物件會存成「基底＋差異（delta）」，所以 10 個版本的大檔案只占一點點空間。同時，沒有任何分支或 reflog 指向的過期物件會被刪除。

  • Git 會在適當時機自動執行 gc，平常不用手動。
  • git clone 與 git push 時，傳輸的也是 packfile，所以速度很快。
  • 這套機制對文字檔效果極好；對已經壓縮過的二進位檔（影片、zip、jpg）幾乎無效——這是大型二進位檔該用 Git LFS 的原因（第 50 課）。

SHA-1 安全嗎？

2017 年研究者首次做出兩個不同但 SHA-1 相同的 PDF。Git 之後改用能偵測這類攻擊的強化版 SHA-1，並已支援以 SHA-256 建立倉庫（git init --object-format=sha256）。不過 SHA-256 倉庫與 GitHub 等平台的相容性仍在推進中，目前絕大多數倉庫仍使用 SHA-1。

🧭 這一課的重點

新物件先是 .git/objects 下的鬆散物件；git gc 把它們打包成 packfile（.pack 與 .idx），相似物件以基底加差異儲存，並刪除無人指向的過期物件。gc 會自動執行，clone 與 push 也傳輸 packfile。差異壓縮對文字檔有效、對已壓縮的二進位檔幾乎無效，所以大型二進位檔應用 Git LFS。SHA-1 在 2017 年被證實可碰撞，Git 採用偵測碰撞的強化版並支援 SHA-256 倉庫。

🐙 本課程的 Git 指令範例都在 Git 2.43 實際執行過，畫面上的輸出就是當時的結果（日期固定，所以雜湊值可重現）；範例中的「GitHub 遠端」是用本機的裸倉庫模擬的，指令與真正連到 GitHub 時相同，只有網址不同。GitHub 網站的按鈕位置與名稱偶爾會改版，以官方說明為準。
