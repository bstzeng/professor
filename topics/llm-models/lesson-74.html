模組 N｜評測與選型 · 第 74 課

為什麼 benchmark 分數會騙人

這一課的目標

  • 理解資料污染的機制
  • 認識榜單過擬合
  • 學會辨識可疑的宣稱

1. 資料污染

評測題目散布在網路上——論文、GitHub、教學文章、討論串。 預訓練抓取網頁時，這些內容必然會進去。 於是模型不是在推理，而是在回憶。

污染形式難度
原題直接出現可用 n-gram 比對清除
改寫版本難清
翻譯版本很難清
討論串裡的片段解說幾乎清不掉
刻意加進訓練集清不掉，且是作弊

所以「我們做了去污染」這句話， 頂多代表第一種被清掉了。

2. 榜單過擬合

即使沒有直接污染，只要團隊反覆用某個榜單當開發指標 （調配方、選 checkpoint、挑超參數）， 模型就會慢慢往那個榜單的分布靠攏。

這在統計上叫多重比較問題： 測試集被當成驗證集用了幾百次之後，它就不再是測試集。

3. 飽和

當前沿模型都拿到 90% 以上，剩下的 10% 多半是 題目本身的錯誤、標註爭議、或極端邊緣案例。 此時分數的差異沒有統計意義。

  • MMLU 早已飽和，MMLU-Pro 也在逼近
  • HumanEval 對前沿模型已無區分力
  • GPQA Diamond 對最強的模型也開始飽和

看到「90.1% vs 89.8%」這種比較，可以直接忽略—— 誤差範圍比差距大。

4. 辨識可疑宣稱

紅旗為什麼可疑
小模型宣稱勝過大它十倍的模型通常是針對榜單優化
只貼一兩個 benchmark可能只有那個好
沒說計分方式可能是 pass@k 或用了工具
合併模型（merge）刷榜典型的榜單過擬合（第 63 課）
分數與實際體驗落差大相信你的體驗
沒有與基座模型對比無法判斷微調到底有沒有幫助

5. 比較可信的指標

  1. 持續更新的動態評測：題目定期換新，模型來不及污染
  2. 人類偏好競技場：真人盲測，難以直接優化（第 75 課）
  3. 真實任務評測：SWE-bench 這類建立在真實 repo 上的
  4. 三角驗證：靜態學術評測 + 人類偏好 + agent 任務， 三者一致才可信
  5. 你自己的評測集：最可信，因為只有你有（第 76 課）

6. 一個實際做法

不要問「哪個模型分數最高」，改問 「哪幾個模型在我在乎的指標上都排在前面」， 取出三到五個候選，然後用自己的任務實測。

榜單的正確用途是縮小候選範圍， 不是做最終決定。

重點回顧

  • 污染幾乎不可能完全清除
  • 反覆用同一榜單開發會造成過擬合
  • 飽和的榜單上，小數點的差距沒有意義
  • 榜單用來縮小候選，不用來做決定

檢查你的理解

  1. 列出四種資料污染形式
  2. 說明榜單過擬合的統計原因
  3. 說出三個可疑宣稱的紅旗
