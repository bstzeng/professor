模組 C｜Transformer 骨架 · 第 12 課

FFN／MLP：大部分參數其實在這裡

這一課的目標

  • 理解 FFN 的結構與作用
  • 算出它的參數量
  • 知道為何它佔掉三分之二的參數

1. 結構

每層 Transformer block 有兩個部分：注意力負責在 token 之間交換資訊， FFN 負責在每個 token 內部做處理。 FFN 是逐 token 獨立的——它不看別的位置。

傳統 FFN 是兩層：

h = X · W_up [d_model → d_ff] h = GELU(h) y = h · W_down [d_ff → d_model] 參數 = 2 × d_model × d_ff

現代模型（Llama、Qwen、Mistral 等）用 SwiGLU，變成三個矩陣：

gate = X · W_gate [d_model → d_ff] up = X · W_up [d_model → d_ff] h = SiLU(gate) ⊙ up ⊙ 是逐元素相乘 y = h · W_down [d_ff → d_model] 參數 = 3 × d_model × d_ff

2. 參數量

Llama 2 7B：d_model=4096、d_ff=11008

3 × 4096 × 11008 = 135,266,304

Llama 3 8B：d_model=4096、d_ff=14336

3 × 4096 × 14336 = 176,160,768

和上一課的注意力層比較：

模型注意力FFNFFN 佔比
Llama 2 7B67.1 M135.3 M66.8%
Llama 3 8B41.9 M176.2 M80.8%

所以「Transformer 的參數大部分在注意力」是個常見的錯誤印象。 實際上三分之二以上在 FFN， 用了 GQA 的模型甚至到八成。

3. 擴張比例

d_ff / d_model 這個比例叫擴張比（expansion ratio）。

年代／類型比例說明
原始 Transformer4.0兩矩陣 GELU
SwiGLU 慣例約 2.67（= 4 × 2/3）多一個矩陣，所以把寬度縮小以維持總參數
Llama 2 7B11008/4096 = 2.69再對齊到 256 的倍數
Llama 3 8B14336/4096 = 3.5刻意加寬

那個 2/3 的由來很直白：SwiGLU 從兩個矩陣變三個， 為了讓參數量與原本的 4 倍擴張持平，就把寬度乘 2/3。 這也是為什麼你會看到 11008 這種怪數字—— 它是 4096 × 8/3 再向上對齊到 256 的倍數。

4. FFN 在做什麼

一個廣為接受的解釋是：FFN 是鍵值記憶體。 W_up 的每一列可以看成一個「偵測器」， 當輸入向量與它方向接近時被啟動； W_down 的對應列則是「被啟動時要寫回什麼」。

所以模型記住的事實知識（巴黎是法國首都）， 大多存在 FFN 層而不是注意力層。 這也是知識編輯（model editing）研究會去改 FFN 權重的原因。

5. 對量化的意義

既然 FFN 佔了七八成參數，量化策略自然會針對它：

  • GGUF 的 K-quant 會把 ffn_down 保留在較高位元，因為它對誤差最敏感
  • MoE 把 FFN 換成多個專家，所以 MoE 的參數幾乎全在專家層（第 46 課）
  • 要壓縮模型，動 FFN 的效益最大

重點回顧

  • FFN 逐 token 獨立處理，不跨位置
  • SwiGLU 有三個矩陣，參數 = 3 × d_model × d_ff
  • FFN 佔一層參數的 67%–81%，比注意力多得多
  • 擴張比的 2/3 是為了補償 SwiGLU 多出來的矩陣

檢查你的理解

  1. 算出 d_model=8192、d_ff=28672 的 SwiGLU FFN 參數量
  2. 解釋 11008 這個數字怎麼來的
  3. 說明為何量化要特別保護 ffn_down
