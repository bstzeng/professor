adapter、merged 與多 LoRA 切換

這一課的目標

  • 知道 adapter 檔案裡有什麼
  • 理解合併與不合併的取捨
  • 掌握多 LoRA 切換的用法

1. Adapter 檔案

訓練完 LoRA，產出的資料夾長這樣：

my-lora/ ├── adapter_config.json # r、alpha、target_modules、基座模型名稱 ├── adapter_model.safetensors # 只有 A 與 B 矩陣，通常 10–500 MB └── README.md

關鍵是 adapter_config.json 裡的 base_model_name_or_path—— adapter 只對那一個特定基座有效。 把 Llama 的 adapter 掛到 Qwen 上不會報錯，但輸出會是垃圾。

2. 兩種使用方式

不合併（動態掛載）合併（merge）
做法載入基座 + 載入 adapterW ← W + (α/r)·B·A，存成新模型
檔案基座 + 小檔案完整的新模型（GB 級）
推論速度略慢（多一次小矩陣乘法）與原模型相同
可切換可以，隨時換不行，固定了
可量化成 GGUF不行可以

3. 什麼時候該合併

  • 要轉成 GGUF 給 llama.cpp／Ollama 用 → 必須合併
  • 要部署到 vLLM 當單一模型 → 合併比較單純
  • 要發佈到 HF 給別人下載 → 合併版比較好用
  • 要在同一個服務裡支援多個客戶的客製模型 → 不要合併

4. 合併的正確做法

from transformers import AutoModelForCausalLM from peft import PeftModel # 注意：載入原始 16-bit 基座，不是 4-bit base = AutoModelForCausalLM.from_pretrained( "Qwen/Qwen2.5-7B-Instruct", torch_dtype="bfloat16", device_map="cpu") model = PeftModel.from_pretrained(base, "./my-lora") model = model.merge_and_unload() model.save_pretrained("./merged-model") # tokenizer 也要一起複製過去 from transformers import AutoTokenizer AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B-Instruct").save_pretrained("./merged-model")

最常見的錯誤：用 QLoRA 訓練後， 把 adapter 合併回 4-bit 的基座。 這會疊加量化誤差。正確做法是像上面那樣載入原始 BF16 基座再合併。

5. 多 LoRA 切換

一個基座掛多個 adapter，是 LoRA 在生產環境最有價值的用法：

顯存中只有一份 7B 基座（14 GB） ├── adapter-客戶A （50 MB） ├── adapter-客戶B （50 MB） ├── adapter-摘要任務（50 MB） └── adapter-分類任務（50 MB） 依請求動態選用，總成本 ≈ 14.2 GB

如果每個都合併成獨立模型，就要 4 × 14 = 56 GB。 vLLM 與 TGI 都內建這種多 adapter 的服務能力。

6. LoRA 的加減運算

因為 ΔW 是加上去的，adapter 之間可以做算術：

  • 相加：合併兩個能力（風格 + 領域知識）
  • 加權：W + 0.7·ΔW₁ + 0.3·ΔW₂
  • 相減：移除某種行為（效果不穩定）

效果不保證——兩個 adapter 可能互相干擾。 但它便宜到值得試，這也是模型合併（第 63 課）的基礎之一。
