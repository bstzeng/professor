模組 I｜MoE：AxB 到底什麼意思 · 第 44 課

稀疏模型的想法：不是每個 token 都要全部參數

這一課的目標

  • 理解稀疏模型的基本動機
  • 知道條件計算是什麼
  • 建立總參數與活躍參數的區分

1. Dense 模型的浪費

一般（dense）模型處理每個 token 時，所有參數都會被用到。 不管你問的是「1+1 等於幾」還是「解釋量子糾纏」， 都要把全部 70B 參數算過一遍。

但直覺上，回答不同問題應該用到不同的知識。 如果能只啟動相關的那部分參數， 就能在不增加計算量的前提下擴大模型的知識容量。

2. 條件計算

MoE 的做法是把 FFN 層換成多個並列的 FFN（稱為專家）， 再加一個小小的路由器決定這次要用哪幾個。

Dense 的一層： x ──► Attention ──► FFN ──► y MoE 的一層： ┌─► Expert 1 ─┐ x ──► Attention ──┼─► Expert 2 ─┼─► 加權合併 ──► y ├─► Expert 3 ─┤ └─► ... ───┘ ▲ Router（決定啟動哪 2 個）

注意力層通常不做 MoE，維持共享。 因為注意力的參數佔比小（第 12 課），而且它的功能是通用的。

3. 兩個參數量

名詞意義決定什麼
總參數（total）模型裡所有的參數記憶體需求、檔案大小、知識容量
活躍參數（active）處理一個 token 實際用到的參數計算量、推論速度

Dense 模型的這兩個數字相同。MoE 則可以差很多倍。 這就是為什麼 MoE 的命名需要兩個數字——一個數字不足以描述它。

4. 為什麼這是好交易

回到第 25 課的成本模型：

  • 訓練算力與活躍參數成正比 → MoE 便宜
  • 推論算力與活躍參數成正比 → MoE 便宜
  • 記憶體與總參數成正比 → MoE 昂貴
  • 知識容量與總參數相關 → MoE 划算

所以 MoE 的本質是：用記憶體換算力。 對有大顯存但算力吃緊的服務端來說非常划算； 對顯存不足的個人使用者則不一定。

5. 一個常見誤解

「專家會分別負責不同的領域，例如一個管數學、一個管程式。」

這是錯的。實際觀察到的分工非常零碎且難以解釋—— 可能某個專家對標點符號反應強烈，某個對特定語法結構反應強烈。 路由是在 token 層級做的，不是在「問題領域」層級。 同一個句子裡，不同的 token 可能被送到完全不同的專家。

重點回顧

  • MoE 把 FFN 換成多個專家，每次只啟動幾個
  • 注意力層通常保持共享
  • 總參數決定記憶體，活躍參數決定速度
  • MoE 的本質是用記憶體換算力
  • 專家不對應人類可理解的領域分工
