模組 D｜參數量是怎麼決定的 · 第 18 課

寬 vs 深：同參數量下的取捨

這一課的目標

  • 理解深寬比的取捨
  • 知道太深或太寬各自的問題
  • 掌握深度對推論延遲的影響

1. 兩種做法

要達到同樣的參數量，可以選擇「少層但很寬」或「多層但較窄」。 以 7B 為例：

方案d_modellayers特徵
寬而淺6,14416每層很肥，路徑短
標準4,09632業界慣例
窄而深2,56080路徑長，每層瘦

2. 深度帶來什麼

深度對應「連續推理的步數」。 每一層只能做有限的變換，多步推理需要多層來串接。 實證上，需要組合多個事實的任務（多跳問答、數學） 對深度比對寬度敏感。

代價是：層是序列的，不能平行。 產生一個 token 必須依序通過全部層。 80 層模型的單 token 延遲，天生就比 32 層高。

3. 寬度帶來什麼

寬度對應「每一步能處理多少資訊」， 也直接決定知識容量（FFN 寬度與 d_model 成正比）。

寬度的好處是硬體友善： 大矩陣乘法能把 GPU 餵飽，小矩陣則會卡在記憶體頻寬上。 同樣參數量，寬模型的實際吞吐量通常比深模型高。

4. 為何收斂到 100–150

d_model / n_layers 這個比值，現代模型大致落在 100–150 之間：

模型量級d_modellayers比值
1.5B1,5362855
8B4,09632128
14B5,12048107
32B5,1206480
70B8,19280102

兩端的問題都很實際：

  • 太深：訓練不穩（殘差流的尺度累積）、推論延遲高、張量平行難切
  • 太寬：參數浪費在寬度上，推理深度不足；而且 d_model 平方成長，很快就超預算

5. 一個實務觀察

小模型傾向做得相對深（比值低）， 因為它們的 d_model 已經小到不能再小， 只能靠層數補推理能力。 大模型則可以兩邊一起長。

另外要注意：推論延遲與層數成正比，與寬度成正比但可被平行化。 所以做端側部署（手機、邊緣裝置）時， 寧可選寬一點淺一點的配置。

重點回顧

  • 深度 ≈ 推理步數，寬度 ≈ 每步的資訊量與知識容量
  • 層是序列的，深模型單 token 延遲天生較高
  • d_model / layers 慣例落在 100–150
  • 小模型偏深，端側部署偏寬

檢查你的理解

  1. 說明為何深度影響延遲而寬度影響較小
  2. 解釋小模型為何傾向做得比較深
  3. 說出太深與太寬各自的兩個問題
