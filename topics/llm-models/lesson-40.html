LoRA：低秩分解在做什麼

這一課的目標

  • 理解低秩分解的想法
  • 掌握 rank 與 alpha 的意義
  • 知道該掛在哪些層

1. 核心想法

微調做的事是把權重 W 改成 W + ΔW。 LoRA 的假設是：這個 ΔW 的「本質維度」很低， 可以用兩個瘦長矩陣的乘積表示。

原本：W 形狀 [d, k]，凍結不動 新增：ΔW = B·A 其中 A 是 [r, k]，B 是 [d, r]，r ≪ min(d,k) 前向：y = xW + (α/r)·x·A·B

參數量對照（以 d=k=4096 為例）：

參數量相對
原始 W16,777,216100%
LoRA r=82 × 4096 × 8 = 65,5360.39%
LoRA r=642 × 4096 × 64 = 524,2883.1%

2. 初始化的巧思

A ~ 隨機高斯初始化 B = 全零

因為 B 是零，訓練開始的瞬間 ΔW = B·A = 0， 模型的行為與原始模型完全相同。 這保證了訓練起點是穩定的，不會一開始就把模型打壞。

3. rank 與 alpha

參數意義典型值
r（rank）旁路的容量，決定能學多複雜的改動8–64，常用 16 或 32
α（alpha）縮放係數，實際倍率是 α/r常設為 r 或 2r
dropoutLoRA 層的 dropout0–0.1

α/r 這個設計的用意是：改變 r 時不用重調學習率。 社群慣例是 α = 2r（例如 r=16, α=32）， 這樣有效倍率固定為 2。

rank 怎麼選：

  • r=8–16：風格、格式、語氣調整，資料量小（幾百到幾千筆）
  • r=32–64：任務能力訓練，資料量中等（上萬筆）
  • r=128+：接近全參數微調的效果，但也接近它的成本，多半不划算

常見錯誤是把 r 開得很大以為效果會更好。 實際上 r 過大容易過擬合，而且失去了 LoRA 的意義。 資料量不夠時，加大 r 只會學到雜訊。

4. 掛在哪些層

目標模組效果成本
只有 q_proj, v_proj原始論文的設定，夠用最省
全部注意力（q,k,v,o）略好中等
注意力 + FFN（gate,up,down）明顯較好，現在的主流較高
再加 embed 與 lm_head擴充詞表時才需要高

現在的共識是掛全部線性層。理由回到第 12 課： 七成以上的參數在 FFN，只調注意力等於放棄大部分容量。

5. 實際設定範例

from peft import LoraConfig config = LoraConfig( r=32, lora_alpha=64, lora_dropout=0.05, target_modules=["q_proj","k_proj","v_proj","o_proj", "gate_proj","up_proj","down_proj"], task_type="CAUSAL_LM", )

訓練完只會產出一個幾十 MB 的 adapter 檔案（adapter_model.safetensors）， 而不是完整的模型。這是 LoRA 另一個大優點： 一個基座模型可以掛很多個 adapter（第 42 課）。
