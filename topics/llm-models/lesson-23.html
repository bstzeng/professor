模組 E｜Scaling Law：該練多大、餵多少 · 第 23 課

Kaplan 2020 與 Chinchilla 2022

這一課的目標

  • 理解 Kaplan 與 Chinchilla 兩篇論文的差異
  • 掌握 20 tokens/param 的來源
  • 知道這個結論的適用範圍

1. 問題設定

假設你有固定的算力預算 C。既然 C ≈ 6ND， 那麼 N 與 D 就是一組此消彼長的選擇：

  • 大模型 + 少資料
  • 小模型 + 多資料

哪一種的最終 loss 比較低？這就是 scaling law 要回答的問題。

2. Kaplan 2020：偏大模型

OpenAI 的研究結論是：算力增加時，大部分應該投在模型尺寸上。 大致的建議是 N 隨 C 的 0.73 次方成長、D 只隨 0.27 次方成長。

GPT-3 就是照這個結論做的：175B 參數，只餵了約 300B tokens， 比值不到 2 tokens/param。

3. Chinchilla 2022：兩者同步

DeepMind 重做了這個實驗，訓練超過 400 個不同配置的模型， 得到相反的結論：N 與 D 應該以相同速率成長， 各自隨 C 的 0.5 次方。

模型參數訓練 tokens比值
Gopher280 B300 B1.1
GPT-3175 B300 B1.7
Chinchilla70 B1.4 T20

關鍵結果是：Chinchilla 用了和 Gopher 相同的算力， 模型小了四倍，但表現全面勝出。 這意味著在此之前的大模型全部「訓練不足」—— 它們的參數沒有被餵飽。

4. 為什麼 Kaplan 會錯

後續分析指出幾個原因：

  • Kaplan 的實驗中，learning rate schedule 沒有隨訓練長度調整， 使長訓練的效果被低估
  • 實驗的模型尺寸範圍較窄，外推誤差大
  • 沒有把嵌入參數與非嵌入參數分開處理

這是一個值得記住的案例：scaling law 是經驗擬合，不是物理定律。 它會隨著訓練技術改進而移動。

5. 怎麼用這個結論

給定算力 C，Chinchilla 最適配置： C = 6 × N × D 且 D = 20N C = 120 N² N = √(C / 120) D = 20N 例：C = 1e23 FLOPs N = √(1e23/120) ≈ 2.9e10 = 29 B D = 5.8e11 = 580 B tokens

6. 適用範圍與限制

限制說明
只管訓練成本完全沒考慮推論成本，而那才是長期的大宗（第 25 課）
假設資料無限高品質資料其實有限，重複使用效果會遞減
只看預訓練 loss不等於下游任務表現，更不等於後訓練後的可用性
不含 MoE稀疏模型有自己的 scaling 行為
擬合有爭議後續有研究重做並指出原論文部分參數估計有誤

所以 20 這個數字要當成參考點，不是目標。 現在業界的實際做法遠遠超過它——下一課處理。
