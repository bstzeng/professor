QLoRA：4-bit 基底加 LoRA

這一課的目標

  • 理解 QLoRA 的三項技術
  • 知道 NF4 為何比一般 INT4 好
  • 算出實際的記憶體需求

1. 想法

LoRA 已經把可訓練參數降到 1% 以下， 但凍結的基底權重還是要放進顯存—— 70B 模型的 BF16 權重就是 140 GB。

QLoRA 的答案：既然基底是凍結的，不需要精確梯度， 那就把它壓成 4-bit，只有 LoRA 那一小部分保持高精度。

2. 三項技術

技術做什麼省下什麼
NF44-bit NormalFloat 資料型別權重從 16-bit 降到 4-bit
雙重量化把量化用的縮放常數本身也量化每參數再省約 0.37 bit
分頁優化器顯存不足時把優化器狀態暫存到主記憶體避免長序列時的 OOM 崩潰

3. NF4 為何比 INT4 好

一般的 INT4 量化把數值範圍均勻切成 16 格。 但神經網路的權重不是均勻分布的——它們大致呈常態分布， 集中在零附近。

INT4（均勻） : |---|---|---|---|---|---|---|---| 每格一樣寬，但兩端幾乎沒有權重落在那裡 NF4（依常態） : |-|-|--|---|----|----|---|--|-|-| 零附近切得細，兩端切得粗

NF4 讓每一格包含大致相同數量的權重（資訊理論上最優）。 同樣 4 bit，量化誤差明顯較小。

4. 記憶體帳

微調一個 7B 模型：

方法基底權重可訓練部分合計（不含啟動值）
全參數14 GB98 GB112 GB
LoRA（BF16 基底）14 GB約 0.6 GB約 15 GB
QLoRA（NF4 基底）約 3.8 GB約 0.6 GB約 4.5 GB

加上啟動值與 KV，實務上 7B 的 QLoRA 微調在 8–12 GB 顯卡上可行。 這就是 QLoRA 論文標題說「在單張消費級顯卡上微調」的意思。

5. 代價

  • 速度較慢：每次前向都要把 4-bit 權重解量化回 BF16 計算，約慢 20–40%
  • 品質略降：論文宣稱與 16-bit LoRA 相當，但在困難任務上仍有可測量的差距
  • 合併時要小心：把 LoRA 合併回 4-bit 基底會有額外誤差， 正確做法是合併到原始的 16-bit 基底

6. 實際指令

from transformers import AutoModelForCausalLM, BitsAndBytesConfig import torch bnb = BitsAndBytesConfig( load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_use_double_quant=True, bnb_4bit_compute_dtype=torch.bfloat16, ) model = AutoModelForCausalLM.from_pretrained( "Qwen/Qwen2.5-7B-Instruct", quantization_config=bnb, device_map="auto", ) # 接著套用第 40 課的 LoraConfig 即可

bnb_4bit_compute_dtype 要特別注意： 它指的是計算時解量化成什麼精度，設 BF16 才不會有溢位問題。
