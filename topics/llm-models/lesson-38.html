蒸餾：R1-Distill-Qwen-7B 這種名字是什麼意思

這一課的目標

  • 理解蒸餾的兩種做法
  • 看懂 R1-Distill-Qwen-7B 這種命名
  • 知道蒸餾模型的限制

1. 兩種蒸餾

類型做法需要什麼
logit 蒸餾（白盒）讓學生模型匹配教師模型的完整機率分布教師模型的權重
資料蒸餾（黑盒）用教師模型生成大量輸出，當成 SFT 資料訓練學生只要能呼叫教師模型

開源社群看到的幾乎都是第二種——因為第一種需要教師模型的權重， 而最強的模型通常不開放。

2. 為什麼有效

關鍵不在「壓縮參數」，而在資料品質。 教師模型生成的回答，比網路上抓來的資料乾淨、一致、格式統一， 而且可以針對特定能力大量生成。

對推理能力尤其有效：教師模型的思考鏈是 展示了完整推導過程的高品質資料， 這種資料在自然語料裡幾乎不存在。 讓小模型模仿這些思考鏈，它就學會了推理的形式。

3. 讀懂命名

DeepSeek-R1-Distill-Qwen-7B └──── 教師 ────┘ │ └─ 學生基座 ─┘ 蒸餾
部分意義
DeepSeek-R1提供訓練資料的教師模型
Distill用教師的輸出做 SFT
Qwen-7B學生的基座——架構、tokenizer、預訓練知識都來自這裡

再強調一次第 3 課的重點： 這是一個 Qwen 模型，不是 DeepSeek 模型。 它的 config.json 是 Qwen 架構、詞表是 Qwen 詞表、 底層知識是 Qwen 預訓練來的。DeepSeek 只提供了訓練資料。

4. 蒸餾模型的限制

  • 學形式不學能力：模型會模仿思考鏈的樣子， 但如果基座本身缺乏相關知識，思考過程會「看起來對但結論錯」
  • 上限受基座限制：7B 的基座不會因為蒸餾就變成 70B
  • 繼承教師的錯誤：教師答錯的題目，學生會學到錯誤答案
  • 領域外表現差：蒸餾資料集中在數學與程式，其他領域可能沒有提升甚至退步
  • 授權問題：用某些商用 API 的輸出訓練競爭模型，多半違反其服務條款

5. 怎麼判斷一個蒸餾模型好不好

  1. 看基座是什麼——基座決定天花板
  2. 看蒸餾資料的規模與領域——model card 有寫的通常比較可信
  3. 用你自己的任務測，不要只看它宣稱的數學分數
  4. 注意輸出長度——蒸餾出來的推理模型很會寫，成本要先算

重點回顧

  • 開源看到的蒸餾幾乎都是「用教師輸出當 SFT 資料」
  • 有效的原因是資料品質，不是參數壓縮
  • 命名中最後的家族才是真正的架構與基座
  • 上限受基座限制，且會繼承教師的錯誤
