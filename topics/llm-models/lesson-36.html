模組 G｜後訓練：從會接話到會做事 · 第 36 課

DPO 家族：ORPO、KTO、SimPO

這一課的目標

  • 理解 DPO 為何能跳過 reward model
  • 認識幾個主要變體的差異
  • 知道在 model card 上看到這些後綴代表什麼

1. DPO 的核心洞見

RLHF 的流程是：偏好資料 → 訓練 RM → 用 RL 最大化 RM。 DPO 的論文證明了一件事：這兩步可以合併成一個監督式損失函數。

DPO loss = − log σ( β·[ log π(chosen)/π_ref(chosen) − log π(rejected)/π_ref(rejected) ] ) π = 正在訓練的模型 π_ref = 凍結的參考模型（通常就是 SFT 模型） β = 控制偏離參考模型的強度

直覺是：提高好回答的相對機率，降低壞回答的相對機率， 而「相對」是相對於參考模型。 這隱含地做了 RLHF 在做的事，但不需要 RM，也不需要 RL 迴圈。

2. 對照

RLHF (PPO)DPO
需要載入的模型4 個2 個
訓練形式線上 RL，要一邊生成離線監督學習
穩定度難調，容易崩穩定，像一般微調
算力高約為 SFT 的 1–2 倍
上限調得好時仍較高略低，但差距不大

DPO 出現後，開源社群的偏好優化幾乎全面倒向它—— 因為它把一個「需要 RL 專家」的工作，變成「會跑微調就會做」。

3. 幾個變體

方法改了什麼好處
ORPO把 SFT 與偏好優化合成一步，不需要參考模型只載入一個模型，最省
KTO不需要成對資料，單則「好／壞」標註就能用資料收集容易得多
SimPO去掉參考模型，改用長度正規化的機率省記憶體，緩解長度偏誤
IPO修改損失以避免過度擬合偏好減少過擬合

這些差異在實務上不大。挑選原則很簡單：

  • 有成對資料、記憶體夠 → DPO
  • 記憶體很緊 → ORPO 或 SimPO
  • 只有單則標註（讚／倒讚） → KTO

4. 在 model card 上看到它們

你會看到 Xxx-7B-DPO、Xxx-7B-ORPO 這種名字。 它們的意思是「在某個 SFT 模型上做過偏好優化」。 實務上的判讀：

看到推測
官方模型沒標，只寫 Instruct通常做過完整的 SFT + 偏好優化，只是不細分
社群模型標 -DPO在別人的 SFT 模型上，用公開偏好資料集再調過
標 -SFT 但沒有 DPO半成品，語氣可能生硬

5. DPO 的已知缺點

  • 離線資料的侷限：偏好資料是對「某個模型的輸出」標的， 訓練中模型已經改變，資料就漸漸不匹配
  • 容易降低多樣性：模型會收斂到少數安全句式
  • 長度偏誤仍在：偏好資料裡長回答較受歡迎，這個偏誤會被學走
  • 對資料品質極度敏感：偏好標註不一致時，效果會直接崩

所以近年又出現「迭代式 DPO」：訓練幾輪就重新生成資料、重新標註， 某種程度上把線上 RL 的好處補回來。
