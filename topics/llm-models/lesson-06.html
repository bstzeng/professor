模組 B｜文字怎麼變成數字 · 第 6 課

Embedding：把 token 變成向量

這一課的目標

  • 理解 embedding 矩陣的形狀與作用
  • 算出它佔多少參數
  • 知道 tied embedding 的取捨

1. 查表，就這樣

Tokenizer 把文字變成一串整數，例如 [128000, 9906, 1917]。 Embedding 層做的事只有一件：拿這個整數去查一張表， 取出對應的那一列向量。

嵌入矩陣 E 的形狀 = [vocab_size, d_model] Llama 3 8B: [128256, 4096] token 9906 → E[9906] → 一個 4096 維的向量

沒有乘法、沒有啟動函數，純粹是索引。 但這張表本身是學出來的——訓練過程中， 每個 token 的向量會被調整到能反映它的語意與用法。

2. 它佔多少參數

參數量就是矩陣元素個數：

嵌入層參數 = vocab_size × d_model Llama 3 8B : 128,256 × 4,096 = 525,336,576 ≈ 5.25 億 Llama 2 7B : 32,000 × 4,096 = 131,072,000 ≈ 1.31 億

同樣是 4096 維，Llama 3 因為詞表大了四倍， 嵌入層就多了近四億參數。這還只是輸入端。

3. 輸出端：lm_head

模型算完最後一層之後，要把 4096 維向量變回「詞表上每個 token 的分數」， 這需要另一個 [d_model, vocab_size] 的矩陣，叫 lm_head （也叫 unembedding、output projection）。

所以詞表相關的參數其實要算兩次：

模型嵌入層lm_head合計佔總參數
Llama 3 8B5.25 億5.25 億10.5 億約 13%
Llama 2 7B1.31 億1.31 億2.62 億約 3.9%

4. Tied embedding

既然兩個矩陣形狀互為轉置，能不能共用同一份權重？可以，這叫 權重綁定（weight tying），config.json 裡的欄位是 tie_word_embeddings。

綁定不綁定
參數量省下一份（8B 模型可省 5 億）多一份
效果小模型影響不大，甚至更好大模型通常略優
典型用例Gemma、Qwen 的小尺寸、多數 3B 以下模型Llama 系列、多數 7B 以上

這個欄位很重要：算參數量時如果忽略它， 小模型會算多一大截。第 21 課的計算會把它考慮進去。

5. 一個常見誤解

很多人以為 embedding 就是「詞向量」，像 word2vec 那樣有固定語意。 在 Transformer 裡不是這樣：

  • 嵌入層給的是沒有上下文的初始向量
  • 真正有意義的表示，是經過 32 層 attention 之後的中間狀態
  • 同一個 token 在不同句子裡，經過網路後的向量完全不同

所以「bank」這個 token 的嵌入向量只有一個， 但「河岸的 bank」與「銀行的 bank」在第 20 層的表示會差很遠。

重點回顧

  • Embedding 是查表，矩陣形狀 [vocab, d_model]
  • 輸入端與輸出端各一份，除非 tie_word_embeddings 為真
  • 詞表大的小模型，嵌入層會吃掉異常高比例的參數
  • 嵌入向量沒有上下文，真正的語意在深層才形成
