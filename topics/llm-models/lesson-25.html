模組 E｜Scaling Law：該練多大、餵多少 · 第 25 課

推理成本進入公式：訓練一次、跑一億次

這一課的目標

  • 把推論成本納入 scaling 決策
  • 理解「訓練一次、跑一億次」的量級
  • 知道什麼情況下該選大模型

1. 總成本模型

總成本 ∝ 6ND + 2N·R 第一項：訓練，一次性 第二項：推論，R 是預期的總輸出 token 數

在固定的目標品質下，N 與 D 可以互換（over-train 讓小 N 追上）。 於是問題變成：R 多大時，該犧牲訓練成本去換更小的 N？

2. 量級感

情境R（總輸出 token）推論成本佔比
研究實驗，跑幾千次評測約 1e8可忽略
企業內部工具，百人使用一年約 1e10與訓練同量級
消費級產品，千萬用戶1e13 以上完全主導

用 8B 模型算一下第三種情境：

訓練：6 × 8e9 × 15e12 = 7.2e23 FLOPs 推論：2 × 8e9 × 1e13 = 1.6e23 FLOPs 比值約 4.5 : 1

即使是 15T tokens 的重度 over-train， 當推論量到達 1e13 token 時，推論已經是同一個量級。 再往上，推論就完全壓過訓練。

3. 這解釋了幾個現象

  • 為何小模型被瘋狂 over-train：推論便宜是可以攤提幾十億次的優勢
  • 為何 MoE 流行：推論成本只跟活躍參數有關，於是可以「訓練時很大、推論時很小」（模組 I）
  • 為何蒸餾這麼常見：用大模型的品質，換小模型的推論成本
  • 為何推理模型很貴：長思考鏈讓 R 暴增，一題可能輸出上萬 token

4. 什麼時候該選大模型

情境建議理由
一次性的大批次分析大模型推論量固定且不大，品質優先
高價值低頻任務（合約審查、研究）大模型每次的價值遠高於運算成本
高頻低價值（分類、抽取、改寫）小模型推論成本主導
端側、離線小模型硬體是硬限制
需要極低延遲小模型延遲與參數量正相關

5. 一個常被忽略的變數

推論成本不只跟 N 有關，也跟輸出長度有關。 推理模型（會先輸出思考過程）的實際成本可能是同尺寸一般模型的五到二十倍， 因為它為了回答一題會先產出幾千個思考 token。

所以選型時要問的不是「幾 B」，而是 「這個任務每次要燒多少 token」。 一個 32B 的非推理模型，總成本可能低於 8B 的推理模型。

重點回顧

  • 總成本 = 6ND + 2N·R，R 夠大時推論主導
  • 消費級產品的 R 讓推論成本壓過訓練
  • 這是 over-train、MoE、蒸餾三件事共同的動機
  • 推理模型的輸出長度會讓實際成本翻好幾倍
