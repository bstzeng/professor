模組 C｜Transformer 骨架 · 第 15 課

Decoder-only 為什麼贏了

這一課的目標

  • 比較三種 Transformer 架構
  • 理解 decoder-only 勝出的原因
  • 知道 encoder 模型今天還用在哪

1. 三種架構

類型代表注意力擅長
Encoder-onlyBERT雙向，看得到全文分類、抽取、嵌入
Encoder-decoderT5、BART編碼端雙向，解碼端因果翻譯、摘要
Decoder-onlyGPT、Llama、Qwen全程因果生成，以及幾乎所有事

2. Decoder-only 為何勝出

  • 訓練訊號最密：每個位置都在預測下一個 token，一段 1000 token 的文字提供 1000 個學習訊號。 BERT 的遮罩式訓練只遮掉 15%，訊號密度差了六倍多。
  • 任務統一：翻譯、摘要、問答、分類，全部可以寫成「續寫」。 不需要為每個任務設計不同的頭。
  • 推論可快取：因果遮罩讓前面的 K、V 永遠不變， 於是有了 KV cache。雙向注意力做不到——新增一個 token 會改變所有位置的表示。
  • Scaling 表現好：實證上同樣算力下，decoder-only 的 loss 下降得最漂亮。

3. 代價

因果遮罩意味著每個 token 只看得到左邊。 對「理解整句再判斷」的任務，這在理論上是劣勢。 但實務上被兩件事補償掉了：

  1. 模型夠大時，從左到右的表示已經足夠好
  2. 可以把問題放在前面、答案放在後面，用 prompt 繞過

4. Encoder 模型今天在哪

BERT 系列沒有消失，只是換了位置——它們現在是基礎設施：

用途為何用 encoder
向量檢索（RAG 的 embedding）雙向表示品質好，模型小、跑得快
重排序（reranker）同上，而且一次只要輸出一個分數
內容分類與過濾0.1B 的模型就夠，成本是 LLM 的千分之一
預訓練資料品質評分要處理數兆 token，只能用小模型

所以一套完整的 RAG 系統裡，通常同時有 decoder-only 的生成模型 與 encoder-only 的嵌入模型。它們不是競爭關係。
