模組 L｜讀懂一張 Model Card · 第 62 課

變體後綴全表：Base、Instruct、Chat、it、Thinking

這一課的目標

  • 認識所有官方變體後綴
  • 知道各自的使用方式
  • 避免選錯版本

1. 基本三分

類型常見後綴怎麼用
基座（無後綴）、-Base、-pt續寫、few-shot、當微調起點
指令-Instruct、-Chat、-it、-sft套 chat template 對話
推理-Thinking、-Reasoning、R1、-QwQ 類同上，但會先輸出思考段落

各家用詞不同但意思一樣： Meta 用 Instruct，Google 用 it（instruction-tuned）， 早期常見 Chat。

2. 能力導向的後綴

後綴意思注意
-Coder程式碼特化通用能力可能略降
-Math數學特化同上
-VL / -Vision視覺多模態需要支援多模態的引擎
-Audio / -Omni語音或全模態引擎支援更少
-Embedding向量嵌入模型不能拿來對話
-Reranker重排序模型同上
-Guard內容安全分類輸出是分類標籤不是對話

最後三個特別容易搞錯：它們是不同用途的模型， 不是聊天模型的變體。拿 embedding 模型去對話只會得到亂碼。

3. 規模與版本標記

標記意思
v0.1、v0.3同一模型的修訂版，通常修 bug 或改進 tokenizer
-2507 類數字發布年月（2025 年 7 月）
-Preview預覽版，可能不穩定
-Mini / -Small / -Large同一家族的尺寸分級
-Flash / -Turbo速度最佳化版

4. Thinking 模式的實務差異

推理模型在使用上有幾個要注意的地方：

  • 輸出結構：通常用 <think>...</think> 包住思考段落， 應用端要記得把它濾掉再顯示給使用者
  • token 用量：思考段落常佔輸出的八成以上
  • 取樣參數：推理模型通常建議較高的 temperature（0.6 左右）， 設 0 反而容易陷入重複
  • 可關閉：有些模型支援在 prompt 或參數中關掉思考模式
  • 不要用 few-shot：推理模型通常在 zero-shot 下表現最好， 範例反而會干擾它的思考

5. 怎麼確認你拿到的是哪一種

# 1. 看 tokenizer_config.json 有沒有 chat_template # 有 → instruct 類；沒有 → base # 2. 看特殊 token 有沒有 # 有 → 推理模型 # 3. 直接試 # 輸入「你好」，base 會亂續寫，instruct 會打招呼

重點回顧

  • Instruct／Chat／it 是同一件事，各家用詞不同
  • Embedding／Reranker／Guard 是不同用途的模型，不能對話
  • 推理模型的輸出要濾掉思考段，且不建議用 few-shot
  • 有沒有 chat_template 是判斷 base／instruct 最快的方法
