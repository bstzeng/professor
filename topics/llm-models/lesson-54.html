校準資料與 imatrix 在做什麼

這一課的目標

  • 理解校準資料的作用
  • 掌握 imatrix 的原理
  • 知道校準資料的選擇會影響什麼

1. 為什麼量化需要資料

第 51 課的量化只看權重本身的分布。 但有個更重要的問題沒被考慮：哪些權重比較重要？

一個權重的重要性，不只取決於它的大小， 還取決於它乘上的輸入通常有多大。 如果某個輸入維度的啟動值總是很大， 那麼對應權重的一點點誤差就會被放大。

輸出誤差 ≈ Σ (權重誤差 × 輸入啟動值) 權重誤差小但啟動值大 → 輸出誤差大 權重誤差大但啟動值≈0 → 輸出誤差可忽略

要知道啟動值的分布，就必須真的餵資料跑一遍。 這就是校準資料的用途。

2. imatrix

llama.cpp 的 importance matrix 做法很直接：

  1. 拿一份校準文本，用 FP16 模型跑一遍
  2. 記錄每一層每個輸入維度的啟動值平方和
  3. 存成一個 .imatrix 檔案
  4. 量化時用它加權——重要的維度分配更多位元或更細的 scale
# 產生 imatrix ./llama-imatrix -m model-F16.gguf -f calibration.txt -o model.imatrix # 用它量化 ./llama-quantize --imatrix model.imatrix model-F16.gguf out-IQ4_XS.gguf IQ4_XS

3. 效果

量化等級無 imatrix有 imatrix
Q6_K 以上幾乎無差幾乎無差
Q4_K_M可用略好
Q3_K_M明顯劣化改善明顯
IQ 系列（2–4 bit）不可用可用

關鍵結論：位元數越低，imatrix 越重要。 IQ 系列的設計本身就假設有 imatrix，沒有它品質會很差。

4. 校準資料怎麼選

這是有爭議的部分。兩派做法：

做法主張風險
用通用文本（維基、隨機語料）不偏向任何用途，保持通用能力特定領域表現未最佳化
用多樣化混合（含程式碼、多語言、對話）涵蓋各種啟動模式需要精心設計
用目標領域資料該領域表現最好其他領域可能退步

社群的主流是第二種。知名量化發佈者通常會在 model card 上 寫明用了什麼校準資料——這是判斷量化品質的重要線索。 沒寫的通常是用預設值，品質未必差，但你無從得知。

5. 一個實際的注意事項

如果你主要用中文，而 imatrix 是用純英文語料產生的， 理論上中文的表現會略差——因為中文 token 對應的啟動模式 沒有被校準資料涵蓋到。

實測上這個差異通常不大（1% 量級），但在低位元量化時會放大。 如果你很在意，可以：

  • 選用校準資料含多語言的量化版本
  • 或自己用中文語料產生 imatrix 再量化

6. 其他方法的校準

不只 GGUF。GPTQ 與 AWQ 也都需要校準資料：

  • GPTQ：用校準資料計算 Hessian，決定誤差補償方向
  • AWQ：用校準資料找出「重要通道」加以保護
  • bitsandbytes：不需要，它是即時量化（品質也因此較差）

重點回顧

  • 權重的重要性取決於它乘上的啟動值大小
  • imatrix 記錄啟動值統計，指導量化分配
  • 位元數越低，imatrix 越關鍵；IQ 系列沒它不能用
  • 校準資料的語言與領域會影響結果
