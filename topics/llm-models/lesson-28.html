模組 F｜預訓練：資料與過程 · 第 28 課

資料清洗：去重、品質分類、過濾

這一課的目標

  • 掌握資料清洗的完整管線
  • 理解去重為何是最重要的一步
  • 知道過度過濾的風險

1. 管線

步驟做什麼剩下比例
1. 抽取正文從 HTML 拿掉導覽列、廣告、頁尾—
2. 語言辨識依目標語言篩選依配方而定
3. 規則過濾去掉太短、符號比例太高、重複行太多的文件約 30–50%
4. 去重精確去重 + 近似去重約 10–30%
5. 品質分類用小模型評分，留高分的約 5–20%
6. 安全過濾去掉個資、極端內容略減
7. 評測去污染移除與評測集重疊的內容略減

整條管線下來，原始資料通常只剩百分之幾。 所謂「數十 TB 的 Common Crawl」，能用的可能只有幾 TB。

2. 去重為何最重要

網路上充滿重複：轉載、鏡像站、模板頁、法律聲明。 不去重的後果非常實際：

  • 記憶而非泛化：重複幾百次的內容會被逐字背下來， 包括別人的個資與版權內容
  • 算力浪費：重複的 token 貢獻的學習訊號趨近於零
  • 評測污染：評測題目常散布在多個網站，不去重就會洩題

兩層做法：

層次方法抓到什麼
精確去重整份文件雜湊比對完全相同的複本
近似去重MinHash + LSH，比對 n-gram 集合的重疊度改了標題、加了幾句話的轉載
子字串去重後綴陣列找長重複片段文件不同但段落相同

3. 品質分類

近年最有效的一招是：用一個小型分類器（例如 fastText 或小 BERT） 替每份文件打分，判斷它「像不像維基百科／教科書」，只留高分的。

訓練這個分類器的方式很取巧：把維基百科當正例、 隨機網頁當負例，訓一個二元分類器就好。 FineWeb-Edu 這類資料集就是這樣做出來的， 實證顯示用更少但更乾淨的資料，反而訓出更好的模型。

4. 過度過濾的風險

過濾太狠會有三個問題：

  • 多樣性喪失：全部留下教科書式文本，模型會不懂口語、俚語、對話
  • 偏見放大：品質分類器本身有偏好，可能系統性排除某些方言、地區、族群的內容
  • 資料不夠：過濾到只剩 1%，就湊不到需要的 token 數

所以實務上是分級的：高品質資料在訓練後期加重權重， 一般資料在前期用量取勝。這就是下一課的「資料配方」。

5. 評測去污染

這一步關係到你能不能相信 benchmark 分數（第 74 課）。 標準做法是把所有評測集的題目做成 n-gram 指紋， 在訓練資料中搜尋並移除命中的文件。

問題是：沒有人能保證做乾淨。 題目的改寫版本、翻譯版本、討論串裡的片段都很難完全清掉。 這是所有 benchmark 分數都要打折看待的根本原因。

重點回顧

  • 清洗管線七步，原始資料通常只剩百分之幾
  • 去重是最重要的一步，影響記憶、算力與評測可信度
  • 品質分類器用維基百科當正例訓練，效果顯著
  • 過度過濾會損失多樣性並放大偏見

檢查你的理解

  1. 說出清洗管線的七個步驟
  2. 解釋近似去重與精確去重各抓到什麼
  3. 說明過度過濾的三個風險
