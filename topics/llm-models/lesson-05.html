Token 與 tokenizer：BPE 與 SentencePiece

這一課的目標

  • 理解 token 不是字也不是詞
  • 掌握 BPE 的合併演算法
  • 知道 vocab 是怎麼訓練出來的

1. 模型看不到文字

神經網路只能處理數字。所以在任何運算之前， 必須先把字串切成一個個單位，再把每個單位換成一個整數編號。 這個單位叫 token，做這件事的元件叫 tokenizer。

Token 不是字元，也不是單詞。它是統計上劃算的切法： 常見的字串給一個獨立編號，罕見的字串拆成幾段。

"unbelievable" → ["un", "bel", "iev", "able"] 4 tokens "the" → ["the"] 1 token "Hugging Face" → ["Hug", "ging", " Face"] 3 tokens

注意第三個例子裡的 " Face" 前面有空格—— 現代 tokenizer 把空格併進 token，所以「字首有沒有空格」是兩個不同的 token。 這是很多 prompt 行為異常的隱藏原因。

2. BPE：合併最常出現的一對

Byte-Pair Encoding 的訓練流程非常單純：

  1. 初始詞表 = 所有單一位元組（256 個），任何文字都切得開
  2. 統計整個語料中，相鄰兩個 token 出現最多次的組合
  3. 把這一對合併成新 token，加進詞表
  4. 重複 2–3，直到詞表達到目標大小（例如 128,256）

手算一個小例子。語料是 low low lower lowest：

回合最高頻的一對新 token
1l+o（4 次）lo
2lo+w（4 次）low
3e+r 或 e+ser

幾萬回合之後，常用詞會變成單一 token， 罕見詞仍會被拆開，而任何位元組序列都保證切得開—— 這是 byte-level BPE 的重要保證：不會有「未知字元」。

3. BPE 與 SentencePiece

Byte-level BPESentencePiece（Unigram）
用的人GPT 系列、Llama 3、QwenLlama 1/2、Gemma、T5
基本單位位元組Unicode 字元
空格處理併進 token（Ġ 或空白字元）用 ▁ 標記
建構方式由下往上合併由上往下裁剪（機率模型）
檔案tokenizer.jsontokenizer.model

4. 特殊 token

除了一般文字，詞表裡還保留一批控制用的編號：

類型例子用途
序列邊界<s>、</s>、<|endoftext|>標示開始與結束
對話角色<|im_start|>、<|start_header_id|>區隔 system／user／assistant
填充<pad>批次對齊
工具呼叫<tool_call>結構化輸出
思考標記<think>推理模型的思考段落

這些 token 在 tokenizer_config.json 裡定義。 用錯特殊 token 是本機部署最常見的問題之一—— 模型會不知道什麼時候該停，一直講下去。

5. 動手看

pip install transformers python - <<'PY' from transformers import AutoTokenizer tok = AutoTokenizer.from_pretrained("meta-llama/Llama-3.1-8B") s = "Hugging Face 是一個模型平台" ids = tok.encode(s) print(len(ids), ids) print([tok.decode([i]) for i in ids]) PY

重點回顧

  • Token 是統計上劃算的切法，不是字也不是詞
  • BPE 靠反覆合併最高頻的相鄰配對建出詞表
  • 空格通常併進 token，前導空格會改變 token
  • 特殊 token 控制對話格式，用錯會導致模型停不下來
