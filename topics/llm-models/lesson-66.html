誰做的量化：發佈者的差異

這一課的目標

  • 知道同一個模型的不同量化版差在哪
  • 建立挑選發佈者的判準
  • 學會看量化版的 model card

1. 為什麼會有很多版本

官方發 BF16 權重之後，社群會在幾小時內產出各種量化版。 同一個模型可能有十幾個人各發一套。它們的差異來自：

變數影響
有沒有用 imatrix低位元品質差很多（第 54 課）
校準資料是什麼影響特定語言與領域的表現
llama.cpp 的版本新版可能修了該架構的轉換 bug
提供的等級有人只發 Q4_K_M，有人發十幾種
chat template 有無正確帶入直接影響能不能正常對話
是否處理了特殊架構MoE、多模態容易轉錯

2. 判斷發佈者的五個指標

  1. 有沒有寫明 llama.cpp 版本或 commit——代表他知道版本會影響結果
  2. 有沒有說明校準資料——imatrix 量化尤其重要
  3. 有沒有完整的等級表——附檔案大小與簡短建議的最好
  4. 更新頻率——架構有 bug 修正時會不會重發
  5. Community 頁有沒有互動——有人回報問題並得到回應

3. 常見的標記慣例

標記意思
i1-用 imatrix 量化（相對於同一人發的靜態量化版）
-imat / -imatrix同上，不同人的寫法
-static沒有用 imatrix
-GGUF 無其他標記要看 model card 才知道有沒有 imatrix

4. 一個典型的好 model card 會有什麼

## Llamacpp imatrix Quantizations of SomeModel-7B Using llama.cpp release b4500 for quantization. Original model: https://huggingface.co/org/SomeModel-7B All quants made using imatrix option with dataset from [連結] | Filename | Quant | Size | Description | |-------------------|---------|--------|--------------------------------| | ...-Q8_0.gguf | Q8_0 | 8.1GB | Extremely high quality | | ...-Q6_K.gguf | Q6_K | 6.3GB | Very high quality, recommended | | ...-Q4_K_M.gguf | Q4_K_M | 4.7GB | Good quality, default | | ...-IQ4_XS.gguf | IQ4_XS | 4.2GB | Decent, smaller than Q4_K_S | ## Which file should I choose? [依 RAM/VRAM 給的選擇建議]

看到這種結構化的 card，通常品質可以信任。 反過來，只有一行「quantized version of X」的， 你完全不知道它用了什麼方法。

5. 官方量化版

越來越多官方會自己發 GGUF 或官方 QAT 版本。優先順序建議：

  1. 官方 QAT 量化版（第 52 課）——品質最好
  2. 官方 GGUF——保證架構與 template 正確
  3. 知名社群發佈者的 imatrix 版
  4. 其他社群版

6. 模組 L 總結

  • 模型名可拆成：發佈者／家族－尺寸－能力－變體－再製－量化
  • 官方後綴 Instruct／Chat／it 是同一件事；Embedding／Reranker 不能對話
  • 社群標記中 abliterated 與 merge 的風險最高
  • GGUF repo 只要下載一個檔案
  • 授權要看原模型，不是量化版 repo
  • 挑量化版要看有沒有 imatrix 與說明是否完整

檢查你的理解

  1. 說出同一模型不同量化版差異的四個來源
  2. 解釋 i1- 標記的意思
  3. 列出挑選量化版的優先順序
