開源權重與商用 API：什麼時候用哪邊

這一課的目標

  • 建立四個面向的比較框架
  • 算出成本的損益兩平點
  • 知道什麼情況該用哪一邊

本課資訊查證於 2026-09

這個領域變動極快，價格與模型名稱請以各家官方定價頁為準。

1. 四個面向

面向開源權重（自架）商用 API
成本固定成本高（硬體），邊際成本趨近零零固定成本，按 token 計費
隱私資料完全不出門資料送到第三方

2. 成本的損益兩平計算

商用 API 以每百萬 token 計價，分輸入與輸出兩種費率。 以 Anthropic 的第一方 API 為例（2026-06 資料）：

模型context輸入 $/百萬 token輸出 $/百萬 token
Claude Opus 51M5.0025.00
Claude Sonnet 51M2.0010.00
Claude Haiku 4.5200K1.005.00

可以看到同一家的不同層級就差了五倍，跨廠商的差距更大。 比較時務必先確認是哪個層級的模型。

用一個具體情境算損益兩平：

情境：每天處理 1000 份文件，每份輸入 2000 token、輸出 500 token 每天 token：輸入 2,000,000、輸出 500,000 用中階 API（輸入 $2 / 輸出 $10 每百萬）： 每天 = 2.0 × $2 + 0.5 × $10 = $9 每年 = $3,285 自架： 一次性硬體（24 GB 顯卡的整機）約 $2,000 電費每年約 $200（假設半天運轉） 第一年 $2,200，之後每年 $200 損益兩平：約在第 8 個月

所以這個量級的用量，自架大約八個月回本。 用量再高十倍，兩三週就回本；用量只有十分之一， 就永遠不會回本。

3. 別忘了算進去的成本

自架的隱藏成本API 的隱藏成本
建置與維護的人力時間用量暴增時的帳單風險
硬體折舊與故障價格調整（通常是降價，但服務可能停用）
模型更新要重新測試模型版本汰換，要重新調 prompt
高峰時的容量不足速率限制
沒有 SLA依賴外部服務的可用性

人力成本常常被低估。一個工程師花兩週把自架服務調穩， 那兩週的薪資可能就超過一年的 API 費用。

4. 隱私與法規

這往往是決定性因素，而且不是成本能換的：

  • 必須自架：病歷、個資、營業秘密、法規禁止出境的資料
  • 可考慮 API：對方提供資料不用於訓練的保證、 零資料保留選項、或地區內推論的承諾
  • 混合：敏感資料在本機用小模型處理， 去識別化後再送 API 做複雜推理

混合架構在實務上很常見，而且通常是最划算的： 用本機模型做過濾、分類、去識別化這些高頻低價值的工作， 只把真正需要強能力的請求送出去。

5. 能力差距

開源與商用前沿的差距一直在縮小，但兩者的性質不同：

能力差距
一般對話、改寫、摘要幾乎沒有差距
中文等非英語能力視模型而定，部分開源模型反而更好
複雜推理、長任務仍有明顯差距
工具使用與 agent差距較大，且與模型的後訓練品質高度相關
超長 context 的可靠度商用通常較好

所以判斷原則不是「開源夠不夠好」，而是 「開源在我的任務上夠不夠好」—— 這要靠第 76 課的自製評測回答。

6. 決策表

情況建議
資料不能外流自架，沒有第二個選項
用量很小或不穩定API
用量大且穩定自架（算損益兩平）

兩者都有的情況混合：本機處理敏感與高頻，API 處理困難的
