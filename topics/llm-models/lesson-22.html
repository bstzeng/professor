算力預算：C ≈ 6ND 這個公式

這一課的目標

  • 理解 C ≈ 6ND 的由來
  • 能用它估算訓練所需的算力
  • 知道推論的成本公式是 2N

1. 公式

C ≈ 6 × N × D C = 訓練總計算量（FLOPs） N = 參數量（通常指非嵌入參數） D = 訓練 token 數

2. 那個 6 是怎麼來的

每個參數在處理每個 token 時會被用到幾次乘加運算：

階段倍數說明
前向傳播2一次乘、一次加（矩陣乘法的 MAC）
反向：對輸入求梯度2同樣規模的矩陣運算
反向：對權重求梯度2同上
合計6

所以推論時只有前向，成本是 2N FLOPs 每 token； 訓練是它的三倍，6N。 這是整個領域最常用的估算式。

3. 它忽略了什麼

  • 注意力的平方項：seq×seq 的計算沒有計入。序列短時可忽略， 但 context 很長時會變顯著（大致是 12·L·d·seq² 這一項）
  • 啟動函數與正規化：相對矩陣乘法小很多
  • 重算（activation checkpointing）：省記憶體的代價是多一次前向， 會把 6 推到 8

所以 6ND 是下界估計。實務估算常用 6–8 之間。

4. 實際估算：Llama 3 8B

N = 8.0e9，D = 15e12 tokens C = 6 × 8.0e9 × 15e12 = 7.2e23 FLOPs

換算成 GPU 時間。H100 的 BF16 密集算力約 989 TFLOPS，但實際利用率（MFU）只有三到四成：

有效算力 = 989e12 × 0.35 ≈ 3.46e14 FLOP/s 時間 = 7.2e23 / 3.46e14 = 2.08e9 秒 = 578,000 GPU 小時 ≈ 1,000 張 H100 跑 24 天

Meta 公布 Llama 3 8B 的訓練用了約 130 萬 H100 小時， 比這個估算高一倍多。差距來自：實際 MFU 更低、失敗重跑、 資料載入與檢查點的額外開銷。 把估算值乘以 2 當作現實值，是合理的做法。

5. 反過來用：預算換模型

如果你有固定的 GPU 預算，可以反推能練多大的模型：

已知：100 張 H100 跑 30 天，MFU 0.35 C = 100 × 30 × 24 × 3600 × 3.46e14 = 8.97e22 FLOPs 若照 Chinchilla 的 D = 20N： C = 6 × N × 20N = 120 N² N = √(8.97e22 / 120) ≈ 2.7e10 → 約 27 B 但這是物理下界。算入失敗重跑與實際 MFU，把 C 打對折： N = √(4.49e22 / 120) ≈ 1.9e10 → 約 19 B

這種「先算再打折」的習慣很重要。 公式給的是物理下界，現實永遠更貴。

6. 推論端

每個輸出 token 的計算量 ≈ 2N FLOPs 8B 模型：2 × 8e9 = 1.6e10 FLOPs／token 但實際瓶頸通常不是算力，而是記憶體頻寬： 每產生一個 token 要把「全部權重」從顯存讀一遍。 8B 模型 Q4 量化 ≈ 4.5 GB 顯卡頻寬 1 TB/s → 上限約 220 tokens/秒

這是單次推論（batch=1）速度的估算法， 實測值通常落在理論值的 60–80%。第 70 課會再用到。

重點回顧

  • 訓練 C ≈ 6ND，推論每 token ≈ 2N
  • 6 = 前向 2 + 反向 4
  • 公式是下界，現實成本約為估算的兩倍
  • 單次推論的瓶頸是記憶體頻寬不是算力

檢查你的理解

  1. 推導 6 這個係數
  2. 估算 70B 模型用 15T tokens 訓練需要多少 FLOPs
  3. 用頻寬法估算 32B 模型 Q4 在 1 TB/s 顯卡上的生成速度上限
