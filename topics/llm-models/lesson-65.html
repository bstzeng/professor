授權與 gated repo

這一課的目標

  • 區分主要授權類型
  • 理解「開放權重」與「開源」的差別
  • 知道 gated repo 怎麼處理

1. 開放權重 ≠ 開源

幾乎所有「開源模型」嚴格說都只是開放權重：

開放權重真正的開源
權重可下載✓✓
訓練程式碼通常沒有✓
訓練資料幾乎不公開✓
可重現訓練✗✓

完全開源（權重 + 資料 + 程式碼 + 訓練細節）的模型存在， 但數量很少，通常出自學術機構。 商業發布的幾乎都只給權重。

2. 主要授權類型

授權商用主要限制
Apache 2.0✓ 自由要保留授權聲明；有專利條款
MIT✓ 自由幾乎沒有限制
Llama 社群授權✓ 有條件月活躍用戶超過門檻要另外談；要標示「Built with Llama」
Gemma 條款✓ 有條件使用政策限制特定用途
CC-BY-NC✗禁止商業使用
研究專用✗僅限研究，常見於實驗性模型

3. 幾個實務問題

Q：用模型生成的內容，版權歸誰？

多數授權不主張輸出的版權。但有些條款會限制 「不得用其輸出訓練競爭模型」——這條在蒸餾（第 38 課）時要特別注意。

Q：微調後的模型算誰的？

通常你擁有自己的微調成果，但衍生模型仍受原授權約束。 Llama 系列還要求衍生模型的名稱要以 Llama 開頭。

Q：社群量化版的授權是什麼？

繼承原模型。有些量化者會漏寫授權欄位， 這不代表它變成公共領域——要回去看原模型。

4. Gated repo

有些 repo 需要先同意條款才能下載，網頁上會顯示一個同意按鈕。 常見於 Llama、Gemma 等系列。

# 1. 在網頁上登入並按同意 # 2. 建立 access token（Settings → Access Tokens） # 3. 在本機登入 huggingface-cli login # 4. 正常下載 huggingface-cli download meta-llama/Llama-3.1-8B-Instruct --local-dir ./m

沒登入會得到 401 或 403。 這也是第 21 課提到抓 config.json 會失敗的原因。

繞過方式：社群通常會有非 gated 的鏡像或量化版本。 使用它們在技術上可行，但你仍然受原授權約束—— 同意條款這件事只是形式，授權本身還是有效的。

5. 一個檢查習慣

要拿模型做商業用途時，至少確認三件事：

  1. 原始模型的授權（不是量化版 repo 上寫的）
  2. 有沒有使用者規模的門檻條款
  3. 有沒有「不得用於訓練其他模型」的限制

Apache 2.0 與 MIT 是最安全的。看到這兩個基本上不用擔心。

重點回顧

  • 絕大多數「開源模型」只是開放權重
  • Apache 2.0 與 MIT 最寬鬆，Llama 與 Gemma 有附加條款
  • 量化版的授權繼承原模型
  • Gated repo 需要登入 token

檢查你的理解

  1. 說明開放權重與開源的四項差異
  2. 說出 Llama 授權的兩個附加要求
  3. 列出商用前要確認的三件事
