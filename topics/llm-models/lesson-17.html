模組 D｜參數量是怎麼決定的 · 第 17 課

參數量公式：手算一個 7B 模型

這一課的目標

  • 從目標參數量反推架構配置
  • 完成一次完整的設計計算
  • 理解設計時的取捨

1. 題目

要設計一個約 70 億參數的模型， 詞表 128,000、不綁定權重、使用 GQA（8 個 KV 頭）、SwiGLU。 請決定 d_model、layers、d_ff。

2. 步驟一：扣掉詞表

詞表相關 = 2 × 128,000 × d_model 先猜 d_model = 4096: 詞表相關 = 2 × 128,000 × 4,096 = 1,048,576,000 ≈ 1.05 B Transformer 層可用預算 = 7.0 B − 1.05 B ≈ 5.95 B

3. 步驟二：定深寬比

依第 16 課的慣例，d_model / n_layers ≈ 128， 取 d_model=4096 則 layers ≈ 32。

每層預算 = 5,950,000,000 / 32 ≈ 185,900,000

4. 步驟三：拆成注意力與 FFN

注意力（head_dim=128, heads=32, kv=8）: = 4096 × 128 × (2×32 + 2×8) = 4096 × 128 × 80 = 41,943,040 FFN 可用 = 185,900,000 − 41,943,040 − 8,192 ≈ 143,948,768 d_ff = 143,948,768 / (3 × 4096) ≈ 11,715

5. 步驟四：對齊

11,715 要對齊到 256 的倍數。11,715 / 256 = 45.76， 取 45 → 11,520，或取 46 → 11,776。選 11,776 試算：

FFN = 3 × 4096 × 11,776 = 144,703,488 注意力 = 41,943,040 norms = 8,192 每層 = 186,654,720 × 32 = 5,972,951,040 嵌入 = 128,000 × 4,096 = 524,288,000 lm_head = 524,288,000 final norm = 4,096 ────────────────────────────────────── 總計 = 7,021,531,136 ≈ 7.02 B

目標 7.0 B，結果 7.02 B，誤差 0.3%。設計完成。

6. 如果要調整

想要怎麼改後果
推論更快層數 32 → 28，d_ff 補寬延遲下降，但深度不足可能影響推理能力
長 context 更省kv 頭 8 → 4KV cache 減半，品質略降
知識容量更大d_ff 加寬參數上升，但推論成本也上升
小裝置可跑綁定權重省 0.52 B，小模型划算

7. 一個現實提醒

以上是架構設計。真正決定模型好壞的是 資料、訓練 token 數與後訓練品質。 同樣 7B 的架構，用 1T tokens 練與用 15T tokens 練， 差距遠大於架構上的任何微調。模組 E 與 F 處理這件事。
