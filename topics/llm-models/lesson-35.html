RLHF：reward model 與 PPO

這一課的目標

  • 理解 RLHF 的三階段流程
  • 知道 reward model 怎麼訓練
  • 掌握 RLHF 的已知問題

1. 為什麼 SFT 不夠

SFT 教模型「怎麼回答」，但有些性質很難用範例表達：

  • 兩個都正確的回答，哪個比較好？
  • 什麼時候該說「我不知道」？
  • 什麼要求該拒絕？
  • 回答該多長？

這些是比較性的判斷，不是示範性的。 於是需要另一種訊號：讓人看兩個回答，選出比較好的那個。

2. 三階段

階段做什麼產出
1. SFT指令微調初始策略模型
2. 訓練 reward model用人類偏好對訓練一個打分模型RM
3. RL 優化用 PPO 讓策略模型最大化 RM 分數最終模型

3. Reward model

資料形式是「同一個提示，兩個回答，人類標註誰比較好」：

prompt: 如何學好一門外語？ chosen: （詳細、具體、有結構的回答） rejected: （空泛、重複的回答）

RM 通常是把基座模型的 lm_head 換成一個輸出單一分數的頭， 用成對比較的損失訓練：

loss = − log σ( RM(chosen) − RM(rejected) ) 意思是：讓好的回答分數高於壞的回答，差距越大損失越小。

4. PPO 階段

有了 RM，就可以把語言生成當成強化學習問題：

  • 狀態：目前已生成的文字
  • 動作：選下一個 token
  • 獎勵：整段生成完後，由 RM 給一個分數

關鍵是還要加一個 KL 懲罰：

總獎勵 = RM 分數 − β × KL(新策略 ‖ SFT 策略)

沒有這一項，模型會為了討好 RM 而輸出奇怪的東西 （例如不斷重複 RM 偏好的句式）。KL 項把它綁在原本的分布附近。

5. RLHF 的已知問題

問題表現
獎勵駭客模型找到 RM 的漏洞，輸出高分但實際很差的回答
長度偏誤人類傾向認為長回答比較好，模型因此變得囉唆
諂媚模型學會同意使用者，即使使用者是錯的
工程複雜要同時載入四個模型（策略、參考、RM、critic），記憶體與調參都很痛
標註昂貴人工偏好資料的成本很高

6. RLAIF

既然標註昂貴，就讓 AI 來標：用一個強模型依據一份明文原則 來判斷哪個回答比較好，產生偏好資料。 這大幅降低成本，也讓「模型該遵守什麼原則」變成可書寫、可稽核的文件。

代價是：原則寫得不好，或評判模型本身有偏誤， 都會被放大到最終模型身上。

重點回顧

  • RLHF 三階段：SFT → reward model → PPO
  • RM 用成對比較訓練，輸出單一分數
  • KL 懲罰防止模型為了討好 RM 而崩壞
  • 主要問題：獎勵駭客、長度偏誤、諂媚、工程複雜

  1. 說明為何 SFT 無法處理「哪個回答比較好」
  2. 寫出 reward model 的損失函數並解釋
  3. 解釋 KL 懲罰的作用
