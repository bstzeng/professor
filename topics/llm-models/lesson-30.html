模組 F｜預訓練：資料與過程 · 第 30 課

訓練迴圈：loss、learning rate schedule、warmup

這一課的目標

  • 理解交叉熵損失與 perplexity 的關係
  • 掌握 learning rate schedule 的形狀與理由
  • 知道正常的 loss 曲線該長什麼樣

1. 損失函數

預訓練的目標是最大化正確 token 的機率，等價於最小化交叉熵：

loss = − (1/T) Σ log P(正確的下一個 token | 前面的內容)

Perplexity（困惑度）就是它的指數： ppl = e^loss。 直覺意義是「模型在每一步大概在幾個選項之間猶豫」。

lossppl意義
11.5約 100,000隨機亂猜（詞表大小）
4.0約 55學到基本文法
2.5約 12一般小模型的水準
1.8約 6大模型在乾淨語料上的水準

注意 ppl 只能在同一份測試資料、同一個 tokenizer 下比較。 不同 tokenizer 的 ppl 完全不可比——這是第 53 課評估量化品質時的重要前提。

2. Learning rate schedule

lr │ ╱▔▔▔╲___ │ ╱ ╲___ │ ╱ ╲___ │ ╱ ╲__ └──┴────────────────────────────▶ steps warmup cosine decay
階段做什麼為什麼
Warmup從 0 線性升到最大 lr，佔總步數 0.1–2%初期梯度方向很亂，直接用大 lr 會炸掉
主階段餘弦衰減到最大值的 10% 或更低前期大步探索，後期小步收斂
退火降到接近零，配合高品質資料第 29 課提到的技巧

近年也流行 WSD（warmup-stable-decay）：中間維持固定 lr， 最後才快速衰減。好處是可以隨時決定停在哪—— 不必像餘弦那樣一開始就得決定總步數。

3. 正常的 loss 曲線

  • 前幾百步：從 11 附近急速下降到 4–5（學會詞頻分布）
  • 接下來：緩慢下降，在對數座標上接近直線
  • 整體形狀：冪次律，token 加倍帶來固定的 loss 減量
  • 沒有平台期：如果卡住不動，通常是 lr 設錯或資料有問題

4. 幾種異常

現象可能原因處理
loss 突然衝到 NaNFP16 溢位、lr 太大換 BF16、降 lr、回到上一個 checkpoint
loss spike 後自己恢復遇到異常資料批次通常可忽略，或跳過該批次
loss 下降但評測沒進步資料重複導致記憶檢查去重
loss 異常低評測資料混進訓練集檢查去污染

最後一項特別值得警惕：loss 太好看通常是壞消息。

5. 其他關鍵超參數

參數典型值作用
batch size（token 數）百萬至千萬 token越大梯度越穩，但報酬遞減
最大 lr1e-4 至 3e-4（大模型更小）與 batch size 相關
優化器AdamW每個參數要存兩個動量，是記憶體大戶
weight decay0.1正則化
gradient clipping1.0防止單次異常梯度炸掉訓練

注意 AdamW 的記憶體代價：每個參數除了權重本身， 還要存一階動量與二階動量。以 BF16 權重 + FP32 優化器狀態計算， 每個參數約需 12–16 bytes—— 這是全參數微調記憶體需求的主因（第 39 課）。
