SFT：指令微調與 chat template

這一課的目標

  • 理解 SFT 的資料形式與訓練方式
  • 看懂 chat template
  • 知道套錯模板的後果

1. SFT 的資料

監督式微調的資料是「指令－回應」對，通常還加上 system prompt：

{ "messages": [ {"role": "system", "content": "你是一個有幫助的助理。"}, {"role": "user", "content": "用一句話解釋光合作用"}, {"role": "assistant", "content": "植物利用陽光把二氧化碳與水轉成醣類與氧氣。"} ] }

訓練方式與預訓練完全相同——還是預測下一個 token。 唯一的差別是只對 assistant 的內容計算 loss， user 與 system 的部分被遮掉。 模型因此學會「看到這種格式時，該產出什麼」。

2. 資料量與品質

做法資料量備註
早期（Alpaca 時代）約 5 萬筆多為 GPT 生成，品質參差
LIMA 論文1,000 筆證明少量高品質就夠
現代開源模型數十萬至數百萬筆涵蓋多語言、程式、工具呼叫

LIMA 的結論影響深遠：知識在預訓練時就學完了， SFT 只是在教「怎麼表達」。 所以 SFT 資料的品質遠比數量重要， 一千筆精心撰寫的樣本可能勝過十萬筆機器生成的。

3. Chat template

訊息列表要變成一串 token 才能餵給模型。 怎麼變？由 chat template 決定，它寫在 tokenizer_config.json 裡（Jinja2 格式）。

ChatML 風格（Qwen 等）：

<|im_start|>system 你是一個有幫助的助理。<|im_end|> <|im_start|>user 用一句話解釋光合作用<|im_end|> <|im_start|>assistant 植物利用陽光...<|im_end|>

Llama 3 風格：

<|begin_of_text|><|start_header_id|>system<|end_header_id|> 你是一個有幫助的助理。<|eot_id|><|start_header_id|>user<|end_header_id|> 用一句話解釋光合作用<|eot_id|><|start_header_id|>assistant<|end_header_id|>

兩者完全不相容。同一段對話，用錯模板就是用錯語言。

4. 套錯模板的症狀

症狀可能原因
模型不停講話，不會結束結束 token 不對，模型沒看到熟悉的 EOS
模型自問自答，模擬整段對話沒有正確標示 assistant 的起點
輸出裡混進 <|im_end|> 這類字串特殊 token 被當成普通文字編碼
忽略 system prompt模板沒有 system 區塊，或位置錯誤
品質明顯低於預期模板細節（換行、空格）與訓練時不一致

5. 正確做法

from transformers import AutoTokenizer tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B-Instruct") msgs = [{"role": "user", "content": "你好"}] text = tok.apply_chat_template(msgs, tokenize=False, add_generation_prompt=True) print(repr(text))

永遠用 apply_chat_template，不要自己拼字串。 連換行與空格都要完全一致。

用 llama.cpp／Ollama 時，模板通常已經內嵌在 GGUF 檔案的 metadata 裡， 引擎會自動套用。但如果是自己轉換的 GGUF，就要確認模板有沒有被正確帶過去—— 這是本機部署最常見的問題之一。
