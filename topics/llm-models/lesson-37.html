GRPO 與可驗證獎勵：推理模型怎麼練出來的

這一課的目標

  • 理解可驗證獎勵（RLVR）的想法
  • 掌握 GRPO 的機制
  • 知道推理模型的代價

1. 問題：獎勵從哪來

RLHF 的獎勵來自人類偏好，而人類偏好是主觀的、昂貴的、 而且對「這個數學解法對不對」這種問題並不可靠。

但有些任務的答案可以自動驗證：

任務驗證方式
數學題比對最終答案
程式題跑單元測試
邏輯謎題檢查約束是否滿足
格式要求用規則檢查

這類任務不需要 reward model——驗證器就是獎勵函數， 而且它不會被駭客攻擊（答案對就是對）。 這條路線叫 RLVR（Reinforcement Learning with Verifiable Rewards）。

2. GRPO

PPO 需要一個 critic 模型來估計「這個狀態有多好」， 那是額外的一整個模型。GRPO 的做法是用同組樣本的平均值取代 critic：

對同一個問題，取樣 G 個答案（例如 G=8） 分別驗證，得到獎勵 r_1 ... r_G 優勢 A_i = (r_i − mean(r)) / std(r) 然後照這個優勢更新策略，加上 KL 懲罰綁住參考模型。

直覺是：比同一題的其他嘗試好，就強化；比較差，就抑制。 不需要絕對的價值估計，只需要組內相對比較。 省下一整個 critic 模型，記憶體與工程複雜度都大幅下降。

3. 長思考鏈是怎麼「長出來」的

這是最反直覺的部分：沒有人教模型要想很久。

訓練時只獎勵「答案正確」。模型在探索過程中發現： 多寫一些推導步驟、檢查一下、換個方法再試， 答對的機率比較高。於是它自己把回答越寫越長。

訓練曲線上會看到平均輸出長度隨訓練步數持續上升， 同時準確率也上升。「先想再答」是湧現出來的策略， 不是被指定的格式。

4. 代價

代價說明
輸出 token 暴增一題可能先產出數千 token 的思考，成本翻好幾倍
延遲高使用者要等思考跑完才看到答案
過度思考簡單問題也要想半天
只在可驗證領域有效寫作、對話這類任務沒有自動驗證器
可讀性純 RL 訓出來的思考鏈可能語言混雜、難以閱讀

最後一項是實務上的重要發現： 純粹靠 RL 訓練會產出「能用但人看不懂」的思考過程， 所以正式版通常會先用一批人工整理過的思考鏈做冷啟動 SFT， 再進 RL。

5. 在 model card 上的樣子

  • -Thinking、-Reasoning、R1 之類的標記
  • 輸出裡會有 <think>...</think> 包起來的段落
  • 有些模型提供「開關」，可以在 prompt 或參數中關掉思考
  • 評測分數在數學與程式上明顯高，在一般對話上未必

選型提醒：如果你的任務是摘要、改寫、分類， 推理模型通常是浪費——你會付五倍的 token 成本買一個不需要的能力。
