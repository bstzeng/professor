模組 O｜總結 · 第 79 課

從零到一：把一個模型跑起來的完整清單

這一課的目標

  • 提供一份可照做的完整清單
  • 把整門課的知識變成操作步驟
  • 知道每一步出錯時該查哪一課

步驟 1：確認硬體

# NVIDIA nvidia-smi --query-gpu=name,memory.total --format=csv # Apple Silicon system_profiler SPHardwareDataType | grep Memory # 一般記憶體 free -h # Linux

記下可用顯存／記憶體，扣掉 2 GB。→ 第 67、72 課

步驟 2：選模型

  1. 依記憶體決定尺寸上限（第 72 課的對照表）
  2. 依任務類型篩選（推理／程式／中文／一般）
  3. 挑 3–5 個候選
  4. 確認授權（第 65 課）

步驟 3：選量化等級

從 Q4_K_M 開始。檔案大小 × 1.2 要小於可用記憶體。→ 第 56 課

步驟 4：安裝引擎

# 最簡單：Ollama curl -fsSL https://ollama.com/install.sh | sh ollama run qwen2.5:7b # 圖形介面：下載 LM Studio # 最大控制權：llama.cpp git clone https://github.com/ggml-org/llama.cpp cd llama.cpp && cmake -B build && cmake --build build -j

→ 第 70 課

步驟 5：下載模型

pip install huggingface_hub huggingface-cli download bartowski/SomeModel-7B-Instruct-GGUF \ SomeModel-7B-Instruct-Q4_K_M.gguf \ --local-dir ./models

GGUF repo 只要下載一個檔案。→ 第 64 課

步驟 6：跑起來

# llama.cpp：開一個 OpenAI 相容 server ./build/bin/llama-server \ -m ./models/SomeModel-7B-Instruct-Q4_K_M.gguf \ -c 8192 \ -ngl 99 \ --port 8080 # 測試 curl http://localhost:8080/v1/chat/completions \ -H "Content-Type: application/json" \ -d '{"messages":[{"role":"user","content":"你好"}]}'

步驟 7：驗證與調整

症狀處理參考
OOM降 -c、降 -ngl、換小模型第 71 課
講不停檢查 chat template 與 EOS token第 34、55 課
輸出亂碼tokenizer 不匹配，或量化檔案損毀第 1 課
速度太慢確認是否全部在 GPU（看啟動日誌的層數）第 71 課
長對話後變笨超過原生 context，檢查 rope_scaling第 69 課
品質不如預期先確認不是 base 版；再試高一級量化第 33、53 課

步驟 8：建立評測

寫三十題你自己的任務，跑過所有候選模型，選出最好的。 這一步不能跳。→ 第 76 課

步驟 9：長期維護

  • llama.cpp 定期更新（新架構支援與 bug 修正）
  • 有新模型時用同一份評測集重測，換不換一目瞭然
  • 把評測腳本與模型設定放進版本控制
  • 記錄每個模型的速度與品質，累積成自己的對照表

一頁式速查

記憶體 → 尺寸 → Q4_K_M → GGUF → llama.cpp/Ollama → 測三十題 → 決定 常用檢查： 檔案大小 × 1.2 < 可用記憶體 KV cache = 2 × 層 × n_kv × head_dim × ctx × 2 bytes 速度上限 ≈ 記憶體頻寬 ÷ 檔案大小 參數量 = L×(d·hd·(2h+2kv) + 3·d·ff + 2d) + V·d×(1或2) + d

檢查你的理解

  1. 照這份清單實際跑起來一個模型
  2. 說出遇到 OOM 時的三個處理順序
  3. 寫出速度上限的估算公式
