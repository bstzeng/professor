IQ 系列與 imatrix 量化

這一課的目標

  • 理解 i-quant 與 k-quant 的差異
  • 知道 IQ 的速度代價
  • 判斷什麼時候該用 IQ

1. 核心差異

K-quant（Q*_K）i-quant（IQ*）
基本方法分塊量化 + 混合精度基於碼書（codebook）的向量量化
需要 imatrix可選，有更好幾乎必須
同位元品質基準較好，尤其在低位元
解碼速度快較慢（要查表）
CPU 推論好明顯較慢

2. 碼書量化的想法

K-quant 是把每個權重獨立映射到一個整數。 i-quant 則是把一組權重當成一個向量， 在預先定義的碼書中找最接近的那一個，只存索引。

K-quant: 每個權重 → 4 bit 整數 + 共用 scale i-quant: 每 8 個權重 → 查碼書 → 存一個 16 bit 索引 平均 2 bit/權重，但因為碼書設計得好，誤差比 2-bit 整數小很多

這個做法在極低位元時優勢明顯： 2-bit 的整數量化只有 4 個可能值，幾乎不可用； 而碼書可以讓 8 個權重的組合有數萬種可能， 分布貼合得多。

3. 速度代價

查表是隨機記憶體存取，對 GPU 與 CPU 的快取都不友善。 實測上：

  • GPU：IQ 比同 bpw 的 K-quant 慢約 10–30%
  • CPU：慢更多，有時超過 50%
  • Apple Silicon：介於兩者之間

所以在記憶體夠的情況下， K-quant 是比較好的選擇——品質相當但更快。

4. 什麼時候該用 IQ

情境建議
記憶體剛好差一點點IQ4_XS 通常能救（比 Q4_K_S 小但品質相當）
要跑 3-bit 以下一定用 IQ，K-quant 在這個區間很差
純 CPU 推論避免 IQ，速度損失太大
記憶體充裕用 Q5_K_M 或 Q6_K，不要用 IQ

5. IQ 的完整系列

代號約 bpw用途
IQ4_NL4.5非線性 4-bit，品質好
IQ4_XS4.3最常用的 IQ，Q4_K_S 的更小替代
IQ3_M / IQ3_S / IQ3_XS / IQ3_XXS3.1–3.73-bit 區間的首選
IQ2_M / IQ2_S / IQ2_XS / IQ2_XXS2.1–2.8極端壓縮
IQ1_S / IQ1_M1.6–1.8實驗性質，品質很差

XXS < XS < S < M < NL，字母越多越小。 這套命名與 K-quant 的 _S/_M/_L 不同，別搞混。

6. 一個實用組合

很多量化發佈者會同時提供兩套，並在 model card 上放對照表。 挑選流程：

  1. 先看你的記憶體能吃多大的檔案
  2. 在能吃下的檔案裡，挑 bpw 最高的那個
  3. 如果 K-quant 與 IQ 檔案大小相近，優先選 K-quant（比較快）
  4. 只有在 K-quant 塞不下、IQ 剛好塞得下時，才選 IQ
