模組 A｜導論：一個模型從無到有 · 第 3 課

為什麼 Hugging Face 上的名字這麼亂

這一課的目標

  • 理解模型命名混亂的三個來源
  • 學會把任何一個長名字拆成有意義的段落
  • 建立「先看發佈者，再看名字」的習慣

你在 Hugging Face 上會看到這種東西：

bartowski/Meta-Llama-3.1-8B-Instruct-GGUF TheBloke/Mixtral-8x7B-Instruct-v0.1-AWQ unsloth/DeepSeek-R1-Distill-Qwen-14B-unsloth-bnb-4bit mradermacher/Qwen2.5-32B-abliterated-i1-GGUF

看起來像亂碼，其實每一段都有意義。這一課教你怎麼讀。

1. 混亂的三個來源

來源造成的現象
官方各家慣例不同Meta 用 -Instruct、Google 用 -it、有些用 -Chat，指的是同一件事
社群再製微調、合併、移除拒答，每一層都在原名後面再加字
量化發佈者同一個模型被十幾個人量化成十幾種格式，各自再加自己的標記

2. 標準拆解法

任何一個模型名都可以拆成五段，順序大致固定：

發佈者 / 家族 - 版本 - 尺寸 - 變體 - 量化 bartowski / Meta-Llama-3.1 - 8B - Instruct - GGUF ① ② ③ ④ ⑤
段內容要看什麼
① 發佈者斜線前面的組織或個人是官方還是社群？這決定可信度
② 家族與版本Llama、Qwen、Mistral、Gemma…架構、授權、tokenizer 都由它決定
③ 尺寸8B、70B、8x7B、30B-A3B含 x 或 A 的是 MoE，見模組 I
④ 變體Base／Instruct／Thinking／Coder／abliterated決定怎麼用它，見模組 L
⑤ 量化GGUF／AWQ／GPTQ／bnb-4bit／EXL2決定用什麼引擎跑，見模組 K

3. 三個實例

例一：bartowski/Meta-Llama-3.1-8B-Instruct-GGUF

  • bartowski 是社群裡最活躍的量化發佈者之一
  • 原始模型是 Meta 的 Llama 3.1，80 億參數（dense）
  • Instruct 版，可以直接對話
  • 被量化成 GGUF，用 llama.cpp / Ollama / LM Studio 跑
  • 進到 repo 裡會看到十幾個檔案：Q4_K_M、Q6_K、Q8_0…那才是實際要選的

例二：mistralai/Mixtral-8x7B-Instruct-v0.1

  • mistralai 是官方
  • 8x7B：MoE 模型，八個專家。注意它不是 56B，實際約 46.7B——第 46 課會逐項算給你看
  • 沒有量化後綴，所以是原始 BF16 權重，約 93 GB

例三：unsloth/DeepSeek-R1-Distill-Qwen-14B-unsloth-bnb-4bit

  • 這是一個三層加工的模型，要從裡往外讀
  • 底層是 Qwen 14B（架構與 tokenizer 來自 Qwen）
  • DeepSeek-R1-Distill：用 DeepSeek R1 的輸出蒸餾出來的推理能力
  • unsloth-bnb-4bit：unsloth 用 bitsandbytes 量化成 4-bit，供微調用

例三特別值得記住：名字裡同時出現兩個家族時， 後面那個才是真正的架構。 「DeepSeek-R1-Distill-Qwen-14B」是一個 Qwen 模型，不是 DeepSeek 模型。

4. 先看發佈者

名字可以隨便取，發佈者不行。養成先看斜線前面的習慣：

類型例子意義
官方組織meta-llama、Qwen、mistralai、google、deepseek-ai原始權重，最可信
知名量化者bartowski、mradermacher、unsloth量化品質穩定，會寫清楚用什麼校準資料
個人再製各種帳號品質參差，要看 model card 寫得夠不夠清楚

重點回顧

  • 模型名可拆成：發佈者／家族－版本－尺寸－變體－量化
  • 尺寸欄位出現 x 或 A 代表 MoE
  • 名字裡有兩個家族時，後面那個才是真正的架構
  • 先看發佈者，再看名字

檢查你的理解

  1. 把 mradermacher/Qwen2.5-32B-abliterated-i1-GGUF 拆成五段
  2. 說明為什麼 DeepSeek-R1-Distill-Qwen-14B 是 Qwen 架構
  3. 說出 8x7B 與 8B 在尺寸欄位上的根本差異
