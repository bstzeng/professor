模組 A｜導論：一個模型從無到有 · 第 1 課

什麼是「一個模型」：權重、架構、tokenizer 三件套

這一課的目標

  • 知道「一個模型」實際上是哪幾個檔案
  • 理解權重、架構、tokenizer 三者的分工
  • 看懂一個 Hugging Face repo 的檔案清單

很多人說「我下載了一個模型」，但模型不是一個檔案，而是一組互相依賴的東西。 少了任何一個，剩下的都跑不起來。先把這件事弄清楚，後面所有名詞才有地方掛。

1. 三件套

組成是什麼典型檔案大小
權重訓練出來的數十億個浮點數model-00001-of-00004.safetensorsGB 級，佔 99.9%
架構這些數字要怎麼接線、怎麼算config.json幾 KB
Tokenizer文字與數字之間的字典tokenizer.json幾 MB

用一個比喻：權重是零件，架構是組裝圖，tokenizer 是說明書的語言。 三者必須配套——把 Llama 的權重配上 Qwen 的 tokenizer，模型會輸出亂碼， 因為同一個編號在兩邊代表不同的字。

2. 權重到底是什麼

一個 80 億參數的模型，就是80 億個數字。 這些數字被組織成幾百個矩陣，每個矩陣有名字（例如 model.layers.0.self_attn.q_proj.weight）， 形狀由架構決定。推論時做的事就是：把你的輸入變成向量， 依序與這些矩陣相乘、加上非線性運算，最後得到下一個 token 的機率分布。

「參數量」就是這些數字的總數。它決定三件事：

  • 檔案大小：80 億參數 × 2 bytes（BF16）≈ 16 GB
  • 記憶體需求：至少要放得下權重，才跑得動
  • 計算量：每產生一個 token，大約要做 2N 次浮點運算（N 為參數量）

3. config.json 裡有什麼

這是整個模型的規格書。以 Llama 架構為例，關鍵欄位是：

{ "hidden_size": 4096, // d_model，每個 token 的向量維度 "num_hidden_layers": 32, // 幾層 Transformer block "num_attention_heads": 32, // 注意力頭數 "num_key_value_heads": 8, // KV 頭數（GQA） "intermediate_size": 14336, // FFN 中間層維度 "vocab_size": 128256, // 詞表大小 "max_position_embeddings": 8192,// 訓練時的 context 長度 "torch_dtype": "bfloat16", // 權重的數值格式 "rope_theta": 500000.0 // RoPE 的基底頻率 }

這九個數字幾乎決定了一切：參數量、記憶體需求、能吃多長的輸入。 第 21 課我們會用它們反推任何模型的精確參數量。

4. 一個 repo 的完整檔案清單

檔案用途缺了會怎樣
*.safetensors權重本體，大模型會分片沒東西可跑
model.safetensors.index.json告訴載入器哪個張量在哪一片分片模型載不起來
config.json架構規格不知道怎麼組裝
tokenizer.json / tokenizer.model切詞規則與詞表輸入輸出全是亂碼
tokenizer_config.json特殊 token 與 chat template對話格式錯誤，模型行為異常
generation_config.json預設的生成參數用內建預設，通常還好
README.mdModel card，人看的說明只是沒說明，不影響執行

GGUF 是例外：它把上面前五項全部打包進一個檔案。 這是它在本機部署上最大的優勢，第 55 課會詳細處理。

5. safetensors 與 .bin 的差別

早期的權重檔是 pytorch_model.bin，本質是 Python 的 pickle 序列化—— 載入時會執行程式碼，所以下載來路不明的 .bin 等於執行陌生程式。 safetensors 是為了解決這件事設計的：純資料、沒有程式碼、可以記憶體映射（mmap）快速載入。 現在幾乎所有新模型都只發 safetensors。

重點回顧

  • 模型 = 權重 + 架構（config.json）+ tokenizer，三者必須配套
  • 參數量決定檔案大小、記憶體需求與每個 token 的計算量
  • config.json 的九個欄位幾乎決定一切
  • GGUF 把所有東西打包成單檔；safetensors 取代了有安全疑慮的 .bin
