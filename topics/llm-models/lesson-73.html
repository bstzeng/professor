常見 benchmark 各測什麼

這一課的目標

  • 認識主要 benchmark 各測什麼
  • 知道各自的形式與計分
  • 建立「哪個分數對我有意義」的判斷

1. 分類

類型代表測什麼
知識與理解MMLU、MMLU-Pro、GPQA事實知識與學科推理
數學GSM8K、MATH、AIME算術到競賽級數學
程式HumanEval、MBPP、LiveCodeBench函式級的程式撰寫
軟體工程SWE-bench在真實 repo 上修 issue
指令遵循IFEval能不能照約束輸出
長文本大海撈針、RULER長 context 的實際可用性
人類偏好LMArena真人盲測投票
agent 能力Terminal-Bench 類多步驟工具使用

2. 幾個重要的

MMLU / MMLU-Pro

  • MMLU：57 個學科的四選一選擇題，約 1.4 萬題
  • MMLU-Pro：十選一、題目更難，約 1.2 萬題，為了解決 MMLU 飽和
  • 問題：選擇題可以靠刪去法；且已嚴重污染

GPQA（Diamond 子集）

  • 研究所等級的生物、物理、化學問答，Diamond 子集約 448 題
  • 設計成「Google 不到」——就算給網路搜尋，非專家也答不出來
  • 目前前沿模型已逼近飽和

HumanEval 與 SWE-bench

  • HumanEval：164 題函式撰寫，跑單元測試判對錯。已經太簡單且污染嚴重
  • SWE-bench：給真實 GitHub repo 與一個 issue，要模型產出能通過測試的 patch。 這個難得多，也更接近實際工作

IFEval

  • 測「用兩段話回答」「不要用逗號」「以 JSON 輸出」這類可程式驗證的約束
  • 這個分數對實際應用很有意義——它直接對應「模型聽不聽話」
  • 常被忽略，但比 MMLU 更能預測你的使用體驗

3. 計分方式的陷阱

方式意思注意
pass@1一次就答對的比例最嚴格，也最接近實際使用
pass@kk 次裡有一次對就算對數字會漂亮很多，要看清楚 k
maj@k取 k 次的多數答案等於花 k 倍成本
with tools允許用計算機、執行程式碼與不用工具的分數不可比

看到一個亮眼的分數，先確認它是 pass@1 還是 pass@64。 這兩者可能差 20 個百分點以上。

4. 哪些分數對你有意義

你的用途該看可忽略
一般問答助理LMArena、IFEvalAIME、SWE-bench
寫程式LiveCodeBench、SWE-benchMMLU
資料抽取／分類IFEval、自建評測幾乎全部
長文件處理RULER、大海撈針數學類
中文應用中文專用評測、自建評測英文為主的榜單

最後一列很重要：多數榜單是英文的， 英文表現好不代表中文表現好。

檢查你的理解

  1. 說出 MMLU 與 GPQA 的差異
  2. 解釋 pass@1 與 pass@64 為何不可比
  3. 替「做中文客服機器人」挑出該看的兩個指標
