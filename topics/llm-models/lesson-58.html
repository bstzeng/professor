GPTQ：逐層最小化誤差

這一課的目標

  • 理解 GPTQ 的誤差補償想法
  • 掌握 group size 與 act-order 的意義
  • 知道它的適用場景

1. 核心想法：補償

一般量化是逐個權重獨立處理，誤差就這樣留著。 GPTQ 多做一件事：量化完一個權重後， 調整同一層還沒處理的權重，把誤差補回來。

for 每一欄權重 w_i: q_i = quantize(w_i) 量化 err = w_i − dequantize(q_i) 算出誤差 調整剩下的欄位 w_{i+1:} 以補償 err

怎麼知道該調多少？用二階資訊（Hessian）： 它描述「改動某個權重會讓輸出誤差變多少」。 Hessian 由校準資料的啟動值統計算出來。

2. 為什麼有效

單一權重的量化誤差無法避免，但一層的輸出誤差可以減小—— 用其他權重的微調來抵消。 這就像四捨五入一串數字時，把每次的捨去誤差累加到下一個數字上， 總和的誤差會小很多。

GPTQ 的貢獻是把這個想法做到能在幾十分鐘內處理完一個大模型 （原始的最優解法計算量太大）。

3. 主要參數

參數意義典型值
bits目標位元數4（也有 3、8）
group_size幾個權重共用一組 scale128（或 32、64）
desc_act / act-order是否依啟動值重要性排序後再量化建議開啟
damp_percentHessian 的阻尼，避免數值不穩0.01

act-order 值得多說：開啟後會先處理最重要的權重欄， 讓它們的誤差最小，剩下的誤差推給不重要的欄位。 品質明顯提升，代價是推論時的記憶體存取變得不規則，速度略降。 現在多數發佈者都會開。

group_size 越小品質越好但檔案越大。 128 是預設；32 在小模型上值得考慮。

4. 檔案樣貌

GPTQ 不是獨立的容器格式，它存在標準的 HF 結構裡：

model-GPTQ/ ├── config.json # 多了 quantization_config 區塊 ├── model.safetensors # 量化後的權重（qweight、qzeros、scales） ├── tokenizer.json └── ... config.json 裡： "quantization_config": { "bits": 4, "group_size": 128, "desc_act": true, "quant_method": "gptq" }

5. 怎麼用

# 推論（transformers 會自動偵測 quantization_config） from transformers import AutoModelForCausalLM, AutoTokenizer m = AutoModelForCausalLM.from_pretrained("someone/Model-GPTQ", device_map="auto") # 或用 vLLM 服務 vllm serve someone/Model-GPTQ --quantization gptq

6. 適用場景

情境GPTQ 是否合適
NVIDIA GPU 上的批次服務✓ 合適
與 vLLM／TGI 搭配✓ 支援良好
CPU 推論✗ 不支援
Apple Silicon✗ 不支援
單人本機使用△ GGUF 通常更方便

簡單的判斷：你在跑 NVIDIA 伺服器就考慮 GPTQ／AWQ， 你在自己電腦上玩就用 GGUF。
