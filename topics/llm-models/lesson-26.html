模組 E｜Scaling Law：該練多大、餵多少 · 第 26 課

決策表：給定預算怎麼選 N 與 D

這一課的目標

  • 把 scaling 的結論整理成可操作的表
  • 看三個真實案例的決策邏輯
  • 建立自己估算的能力

1. 決策流程

  1. 估算預期推論量 R（每天 token 數 × 天數）
  2. 決定品質目標（要贏過哪個現有模型）
  3. 由硬體限制決定 N 的上限（第 67 課的顯存公式）
  4. 在 N 上限內，把算力全部投進 D
  5. 用 C ≈ 6ND 反推所需 GPU 時數，再乘 2 當現實值

2. 速查表

3. 三個案例

案例一：把 8B 模型做到極致

  • 目標：能在 8 GB 顯卡跑，品質盡量高
  • N 被硬體鎖死在 8B 左右（Q4 約 5 GB）
  • 剩下的自由度只有 D，於是餵 15T tokens
  • 結論：這就是 Llama 3 8B 的邏輯

案例二：MoE 繞開取捨

  • 目標：品質接近 70B dense，但推論成本接近 10B
  • 做法：總參數 200B+、活躍參數 20B 左右的 MoE
  • 代價：顯存需求仍以總參數計，要多卡或大記憶體
  • 結論：用顯存換算力，適合有硬體的服務端

案例三：不要自己預訓練

  • 從零訓練 8B 模型：約 60–130 萬 H100 小時，數百萬美元
  • 在現成 8B 上做 LoRA 微調：幾十到幾百 GPU 小時，數十美元
  • 差距是四到五個數量級
  • 結論：除非你要的能力是基座模型完全沒有的（例如全新語言、 全新模態），否則答案永遠是微調

4. 一個自我檢查

很多人問「我要不要自己訓練一個模型」。用這三個問題篩：

  1. 你有沒有現成模型完全做不到的能力需求？（多半沒有）
  2. 你有沒有數千億 token 的獨佔資料？（多半沒有）
  3. 你有沒有數百萬美元的預算？（多半沒有）

三個都是「是」才需要預訓練。 三個有一個是「否」，答案就是微調或 RAG（第 43 課）。

5. 模組 E 總結

  • C ≈ 6ND 是估算的基礎，推論是 2N
  • Chinchilla 的 20 tokens/param 只最適化訓練成本
  • 加入推論成本後，最適解往「小模型多資料」大幅移動
  • 實務上 N 常由硬體決定，D 才是可調的那一個

檢查你的理解

  1. 用決策流程替一個端側應用選出 N 與 D
  2. 說明 MoE 如何繞開 N 的取捨
  3. 回答三個自我檢查問題，判斷你該不該預訓練
