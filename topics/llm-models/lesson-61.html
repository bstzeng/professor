模組 L｜讀懂一張 Model Card · 第 61 課

命名結構拆解：組織／家族－尺寸－變體－量化

這一課的目標

  • 完整拆解長模型名
  • 建立由外而內的閱讀順序
  • 練習幾個真實案例

1. 完整結構

發佈者 / 家族 - 版本 - 尺寸 - 能力 - 變體 - 再製 - 量化 - 等級 實例拆解： bartowski / Meta-Llama-3.1 - 8B - Instruct - GGUF / Q4_K_M.gguf mradermacher / Qwen2.5 - 32B - abliterated - i1-GGUF unsloth / DeepSeek-R1-Distill-Qwen - 14B - unsloth-bnb-4bit Qwen / Qwen3 - 30B - A3B - Instruct mistralai / Mixtral - 8x7B - Instruct - v0.1

2. 由外而內的讀法

  1. 斜線前：誰發的？官方還是社群？
  2. 最後一段：什麼格式？決定用什麼引擎跑
  3. 尺寸欄：多大？有 x 或 A 就是 MoE
  4. 最靠近尺寸的家族名：真正的架構是誰
  5. 中間的修飾詞：做過什麼加工

3. 尺寸欄的三種寫法

寫法意思記憶體看速度看
8BDense，80 億參數8B8B
8x7BMoE，8 專家要自己算（約 47B）要自己算（約 13B）
30B-A3BMoE，總 30B 活躍 3B30B3B

4. 五個案例

案例一：Qwen/Qwen3-30B-A3B-Instruct

  • 官方發佈（Qwen 組織）
  • MoE：總 30B、活躍 3B
  • Instruct 版，可直接對話
  • 沒有量化後綴 → 原始 BF16，約 60 GB

案例二：bartowski/Qwen3-30B-A3B-Instruct-GGUF

  • 社群量化者 bartowski
  • 同上的模型，轉成 GGUF
  • 進 repo 後還要選檔案：...-Q4_K_M.gguf 等

案例三：mradermacher/SomeModel-32B-i1-GGUF

  • i1 是 mradermacher 的標記，代表用 imatrix 量化
  • 同一個人通常會發兩套：不帶 i1（靜態量化）與帶 i1（imatrix 量化）
  • 低位元時選 i1 版

案例四：TheBloke/Mixtral-8x7B-Instruct-v0.1-AWQ

  • TheBloke 是早期最大的量化發佈者
  • AWQ 格式 → 需要 NVIDIA GPU + vLLM/transformers
  • v0.1 是原模型的版本號

案例五：unsloth/Llama-3.3-70B-Instruct-bnb-4bit

  • unsloth 專做微調工具
  • bnb-4bit → 這是給微調用的，不是給部署用的
  • 要部署的話應該找 GGUF 或 AWQ 版本
