位置編碼：從絕對位置到 RoPE

這一課的目標

  • 理解為什麼 Transformer 需要位置編碼
  • 掌握 RoPE 的基本想法
  • 知道 rope_theta 這個欄位在控制什麼

1. 注意力本身看不到順序

注意力機制是對所有 token 做加權平均。 如果不做任何處理，「狗咬人」與「人咬狗」算出來會一模一樣—— 因為集合沒有順序。所以必須額外把位置資訊注入進去。

2. 三代做法

做法怎麼做問題
學習式絕對位置每個位置學一個向量，加到嵌入上超過訓練長度就沒有向量可用
正弦絕對位置用 sin/cos 算出位置向量可外推但效果差，模型難以掌握相對距離
RoPE（現行標準）把 Q 與 K 向量依位置旋轉一個角度外推仍有限，但可用 scaling 緩解

3. RoPE 的想法

把向量的維度兩兩配成一組，每組當成平面上的一個二維向量， 然後依照 token 的位置 m 把它旋轉 mθ 度。

位置 m 的向量 q，維度 (2i, 2i+1) 這一對： [ q_2i ] [ cos(mθ_i) -sin(mθ_i) ] [ q_2i ] [ q_2i+1 ] → [ sin(mθ_i) cos(mθ_i) ] [ q_2i+1 ] 其中 θ_i = base^(-2i/d)，base 就是 config 裡的 rope_theta

精妙之處在於：兩個旋轉過的向量做內積時， 結果只跟它們的位置差有關，跟絕對位置無關。 於是模型自動獲得「相對位置」的感知，而且不需要額外參數—— RoPE 的參數量是零，它是純粹的數學變換。

4. rope_theta 在控制什麼

不同維度用不同的旋轉頻率 θ_i：低維度轉得快（管短距離）， 高維度轉得慢（管長距離）。base 越大，整體轉得越慢， 能區分的距離範圍就越長。

模型rope_theta訓練 context
Llama 210,0004K
Llama 3500,0008K
長 context 模型常見 1,000,000 以上128K 以上

看到一個模型宣稱支援很長的 context， 第一件事就是去 config.json 看 rope_theta—— 如果它還停在 10,000，那個長 context 多半是靠推論時的 scaling 硬撐的， 品質會打折。第 69 課會處理這件事。

5. 為什麼 RoPE 贏了

  • 零參數：不佔模型容量
  • 相對位置：內積只依賴距離差，符合語言的直覺
  • 可調：改 base 就能改變有效範圍，方便事後延長 context
  • 與 KV cache 相容：旋轉可以在寫入 cache 前做完

重點回顧

  • 注意力本身無序，位置資訊必須另外注入
  • RoPE 用旋轉把位置編進 Q 與 K，內積只依賴相對距離
  • RoPE 不佔任何參數
  • rope_theta 決定可區分的距離範圍，是判斷長 context 真偽的線索
