社群後綴：distill、abliterated、uncensored、merge

這一課的目標

  • 認識社群再製模型的常見標記
  • 知道每種加工實際做了什麼
  • 建立判斷品質的方法

1. 常見標記一覽

標記做了什麼風險
-Distill用大模型輸出做 SFT（第 38 課）能力受基座限制
-abliterated用權重編輯移除拒答方向可能傷及一般能力
-uncensored用去除拒答的資料重新微調同上，且可能引入偏誤
-merge / 各種怪名合併多個模型的權重結果不可預測
-RP / -Roleplay角色扮演特化微調通用能力常下降
-DPO / -ORPO做過偏好優化（第 36 課）視資料品質
-128k / -1M延長 context宣稱長度未必可用（第 69 課）

2. abliteration 是什麼

這個技術的想法是：模型的「拒絕」行為， 在殘差流裡對應一個特定方向的向量。

  1. 準備兩組提示：會被拒絕的、不會被拒絕的
  2. 各跑一遍，記錄中間層的啟動值
  3. 兩組的平均差，就是「拒絕方向」
  4. 把這個方向從權重中投影掉

它不需要重新訓練，只是線性代數操作，幾分鐘就能做完。 代價是：那個方向可能也承載了其他資訊， 移除後模型在某些任務上會變笨， 而且會失去對真正危險請求的判斷力。

3. 模型合併

用 mergekit 之類的工具，把多個模型的權重混在一起。主要方法：

方法做法
線性平均直接加權平均權重
SLERP球面線性插值，在兩個模型之間平滑過渡
TIES解決參數衝突：只保留變化量大的，符號衝突的取多數
DARE隨機丟棄大部分差異再放大剩下的
passthrough / frankenmerge把不同模型的層串起來，做出更深的模型

合併的前提是兩個模型來自同一個基座—— 權重才在同一個空間裡。合併不同家族的模型不會有意義。

合併模型在榜單上曾經很風光，因為它常常能刷高 benchmark 分數。 但這通常是過擬合榜單而非真的變強， 實際使用時常有不穩定、重複、語言混雜的問題。

4. 怎麼判斷一個社群模型值不值得用

檢查項好的徵兆壞的徵兆
Model card寫明基座、方法、資料、參數只有一句話或全是自動生成
訓練細節有 loss 曲線、超參數沒有
評測有在多個 benchmark 上的結果，且與基座對比只貼一個分數
已知限制誠實說明退步的地方宣稱全面超越
下載量與討論有人在 Community 頁討論實際體驗零討論

5. 一個務實的建議

社群再製模型的品質分布非常廣。 除非你有特定需求（例如角色扮演、特定語言強化）， 官方的 Instruct 版通常是最安全的選擇。

要用社群模型時，至少做一件事： 拿你自己的十個真實任務跑一遍， 跟官方版本並排比較。花十分鐘，能避免很多後悔。
