注意力機制：Q、K、V 在算什麼

這一課的目標

  • 理解 Q、K、V 各自代表什麼
  • 看懂注意力的完整計算式
  • 知道因果遮罩在做什麼

1. 一個比喻

把注意力想成查資料庫：

符號名稱比喻
QQuery，查詢我想找什麼
KKey，鍵每筆資料的標籤
VValue，值每筆資料的內容

差別在於：資料庫是精確比對，取出一筆； 注意力是模糊比對，取出所有筆的加權平均。 權重由 Q 與 K 的相似度決定。

2. 完整計算

輸入 X 形狀 [seq_len, d_model] Q = X · W_q [seq, d_head] K = X · W_k [seq, d_head] V = X · W_v [seq, d_head] scores = Q · Kᵀ / √d_head [seq, seq] scores += causal_mask 上三角設為 -∞ weights = softmax(scores) 每列加總為 1 output = weights · V [seq, d_head]

逐行說明：

  • Q·Kᵀ：每個 token 對每個 token 算一個分數，得到 seq×seq 的方陣。這就是注意力計算量隨長度平方成長的原因。
  • ÷√d_head：維度越高內積越大，除以 √d 讓 softmax 不會過度尖銳（梯度消失）。
  • causal_mask：把「看未來」的位置設成 -∞，softmax 之後變成 0。
  • weights·V：按權重把各 token 的內容混合起來。

3. 因果遮罩

語言模型訓練時，一次餵進整個序列，同時預測每一個位置的下一個字。 如果不遮，第 3 個位置就能看到第 5 個字的答案——等於作弊。

看得到 → t1 t2 t3 t4 預測 t2 時 ✓ ✗ ✗ ✗ 預測 t3 時 ✓ ✓ ✗ ✗ 預測 t4 時 ✓ ✓ ✓ ✗ 預測 t5 時 ✓ ✓ ✓ ✓

這個下三角結構也是 KV cache 能成立的原因： 既然每個位置只看得到自己與前面， 那前面算過的 K 與 V 就永遠不會變，可以存起來重用（第 68 課）。

4. 為什麼這個設計有效

  • 任意距離一步到位：第 1 個字與第 1000 個字之間只隔一次矩陣乘法，不像 RNN 要傳 999 步
  • 完全平行：訓練時所有位置同時算，GPU 吃得飽
  • 權重由內容決定：不是固定的連接，而是每次依輸入動態算出來的

代價就是那個 seq×seq 的矩陣：序列翻倍，注意力計算量變四倍。 這是長 context 昂貴的根本原因。

5. FlashAttention 在解什麼

seq×seq 的分數矩陣如果真的整個寫進顯存， 32K 序列就是 10 億個數字。FlashAttention 的做法是 分塊計算、不落地——把中間矩陣留在 GPU 的高速 SRAM 裡分批處理。 它不改變數學結果，只改變記憶體存取方式，但實際效果是 長 context 從跑不動變成跑得動。

重點回顧

  • 注意力 = 用 Q 與 K 的相似度，對 V 做加權平均
  • ÷√d_head 是為了穩定 softmax 的梯度
  • 因果遮罩讓模型看不到未來，也讓 KV cache 成立
  • 計算量與序列長度成平方，FlashAttention 解的是記憶體不是數學
