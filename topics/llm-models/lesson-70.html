模組 M｜跑起來：硬體與記憶體帳 · 第 70 課

推理引擎：llama.cpp、Ollama、LM Studio、vLLM、SGLang

這一課的目標

  • 掌握五種主要推理引擎的定位
  • 知道各自吃什麼格式
  • 理解單人與多人場景的差異

1. 兩種完全不同的目標

單人推論（batch=1）批次服務
瓶頸記憶體頻寬算力與 KV cache
指標單次 tokens/秒、首 token 延遲總吞吐量、併發數
最佳化重點量化、減少權重讀取批次排程、KV cache 管理
代表引擎llama.cpp、ExLlama、MLXvLLM、SGLang、TensorRT-LLM

這個區分很重要：為批次服務設計的引擎，在單人使用時未必快。 反之亦然。

2. 五種引擎

引擎格式硬體定位
llama.cppGGUFCPU / CUDA / Metal / ROCm / Vulkan最通用，硬體覆蓋最廣
OllamaGGUF同上llama.cpp 的易用封裝，有模型庫與 API
LM StudioGGUF / MLX同上圖形介面，適合不想碰指令列的人
vLLMsafetensors / AWQ / GPTQ / FP8NVIDIA（AMD 部分支援）生產級服務，高吞吐
SGLang同 vLLMNVIDIA同類，在複雜工作流與結構化輸出上有優勢

另外還有 ExLlamaV2/V3（EXL2 格式，單人速度極快）與 MLX（Mac 專用）。

3. 選擇決策

你的情況？ ├── 自己用，Windows/Linux/Mac │ ├── 不想碰指令列 → LM Studio │ ├── 想要簡單的本機 API → Ollama │ └── 想要最大控制權 → llama.cpp ├── Mac 且追求速度 → MLX 或 LM Studio 的 MLX 後端 ├── NVIDIA 顯卡，只有自己用 → ExLlamaV2 或 llama.cpp └── 要服務多人／做產品 ├── 標準需求 → vLLM └── 複雜工作流／結構化 → SGLang

4. 速度估算

單人推論的速度上限由記憶體頻寬決定（第 22 課）：

上限 tokens/秒 ≈ 記憶體頻寬 / 模型檔案大小 例： RTX 4090（約 1008 GB/s），8B Q4_K_M（4.85 GB） → 1008 / 4.85 ≈ 208 tokens/秒（理論上限） → 實測通常落在 100–150 RTX 4090，32B Q4_K_M（19.4 GB） → 1008 / 19.4 ≈ 52 tokens/秒（理論） → 實測約 30–40

這個公式非常實用：換一張頻寬兩倍的卡，速度就約兩倍； 模型檔案小一半，速度就約兩倍。 算力（TFLOPS）在單人推論時幾乎不重要。

5. 兩個延遲指標

指標意思受什麼影響
TTFT（首 token 延遲）送出請求到看到第一個字prompt 長度、算力（這階段是算力密集）
TPS（每秒 token）之後的生成速度記憶體頻寬

長 prompt 會讓 TTFT 明顯變長——因為要先把整個 prompt 跑一遍（prefill 階段）。這階段是算力密集的， 與生成階段的瓶頸完全不同。

6. 常用啟動指令

# llama.cpp：開一個 OpenAI 相容的 server ./llama-server -m model-Q4_K_M.gguf -c 8192 -ngl 99 --host 0.0.0.0 --port 8080 # Ollama ollama run qwen2.5:7b # vLLM vllm serve Qwen/Qwen2.5-7B-Instruct --max-model-len 8192 --gpu-memory-utilization 0.9

-ngl 99 代表「盡量把所有層放 GPU」。 顯存不夠時調低這個數字，讓部分層留在 CPU（第 71 課）。
