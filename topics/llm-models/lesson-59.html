AWQ：保護最重要的那些權重

這一課的目標

  • 理解 AWQ 的「保護重要通道」想法
  • 比較 AWQ 與 GPTQ
  • 知道該選哪一個

1. 觀察：不是所有權重一樣重要

AWQ 的論文指出一個實驗結果： 如果把模型裡約 1% 的權重保持在 FP16 不量化， 其餘全部量化到 4-bit，品質幾乎不會掉。

關鍵是怎麼挑那 1%。AWQ 的答案是： 不要看權重本身的大小，要看它對應的啟動值大小。 這與第 54 課的 imatrix 是同一個洞見。

2. 問題：混合精度很難實作

真的把 1% 的權重存成 FP16、其餘存成 INT4， 會讓記憶體布局變得破碎，GPU kernel 難寫、速度也差。

AWQ 的巧思是改用縮放取代混合精度：

對重要通道 i： W[:, i] × s 把權重放大 s 倍再量化（相對誤差變小） X[:, i] / s 對應的輸入縮小 s 倍 因為 (W·s)·(X/s) = W·X，數學上完全等價， 但量化誤差變小了，而且全部權重仍是統一的 INT4。

放大後的權重在量化時佔據更多有效位元， 相對誤差就降低了。而輸入的縮放可以事先融進上一層， 推論時零成本。

3. 與 GPTQ 的比較

GPTQAWQ
核心想法量化後補償剩餘權重量化前縮放重要通道
用到的資訊Hessian（二階）啟動值幅度（一階）
校準需求需要，較多需要，較少
量化速度較慢較快
同位元品質好通常略優
推論速度act-order 開啟時略慢較快（記憶體存取規則）
對校準資料的敏感度較高較低（作者主張泛化較好）

4. 實務結論

  • 要在 vLLM／SGLang 上做高吞吐服務 → AWQ 通常是較好的預設， 推論 kernel 成熟且快
  • 已經有現成的 GPTQ 權重 → 直接用，差距不足以讓你重做
  • 要壓到 3-bit 以下 → 兩者都不理想，考慮 GGUF 的 IQ 系列
  • 本機單人使用 → GGUF 更方便

5. 使用方式

# 推論 from transformers import AutoModelForCausalLM m = AutoModelForCausalLM.from_pretrained("someone/Model-AWQ", device_map="auto") # vLLM vllm serve someone/Model-AWQ --quantization awq # 自己量化（autoawq） from awq import AutoAWQForCausalLM model = AutoAWQForCausalLM.from_pretrained("原始模型") model.quantize(tokenizer, quant_config={ "w_bit": 4, "q_group_size": 128, "zero_point": True, "version": "GEMM" }) model.save_quantized("./out-awq")

version 有 GEMM 與 GEMV 兩種 kernel： GEMM 適合批次大的服務，GEMV 適合 batch=1 的單人推論。
