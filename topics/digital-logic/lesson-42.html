跨時脈域與同步器

這一課的目標

  • 說明跨時脈域的問題
  • 設計兩級正反器同步器
  • 理解多位元資料要用握手或非同步 FIFO

真實系統有很多時脈：CPU 核心、記憶體控制器、USB、PCIe 各自有自己的時脈，還有來自外界的按鈕與感測器根本沒有時脈。訊號從一個時脈域進入另一個時脈域時，它相對於接收端時脈的時間是任意的，遲早會落在 setup／hold 視窗裡，造成亞穩態（第 33 課）。

兩級同步器

讓第一個正反器去「承擔」亞穩態的風險，給它一整個時脈週期安定下來，再由第二個正反器取樣。下游只使用第二級的輸出。

📄 sync.v　下載

// sync.v：兩級正反器同步器——把來自另一個時脈域的訊號安全地帶進來 module sync2(input clk, input async_in, output reg sync_out); reg meta; // 第一級可能進入亞穩態 always @(posedge clk) begin meta <= async_in; sync_out <= meta; // 第二級給第一級一整個週期去「安定下來」 end endmodule

可用的恢復時間 \(t_r \approx T_{clk} - t_{cq} - t_{setup}\)，MTBF 隨 \(t_r\) 指數成長。在 1 GHz 的時脈下，一級幾乎肯定不夠，兩級通常可以達到數千年以上；超高速或高可靠度系統（航太、醫療）用三級。兩個同步器正反器之間不能有任何邏輯，佈局時也要放得很近，以留下最多的恢復時間。

多位元資料：不能各自同步

把一個 8 位元的計數值每一位各接一個同步器是錯的：如果值從 0111 變 1000，各位元可能在不同的週期被同步過去，接收端可能看到 0000、1111 或任何組合。解法有三：

  1. 格雷碼：每次只變一位，同步後不是舊值就是新值（第 3 課）。只適用於依序遞增的值，例如計數器、FIFO 指標。
  2. 握手：發送端把資料放好、保持不動，再送一個「資料有效」的單一位元控制訊號；接收端同步這一位元，看到後才去讀資料，讀完回一個確認訊號。慢但簡單可靠。
  3. 非同步 FIFO：一塊雙埠記憶體，寫入端用寫時脈、讀取端用讀時脈；讀寫指標以格雷碼表示，各自同步到對方的時脈域來判斷滿與空。這是高頻寬跨時脈域的標準做法。

其他注意事項

  • 脈衝可能被漏掉：從快時脈域送一個一拍寬的脈衝到慢時脈域，慢時脈可能根本沒取樣到。要先轉成電位翻轉（toggle）再同步，接收端用邊緣偵測還原。
  • 重置的放開也是跨時脈域：見第 34 課的「非同步觸發、同步放開」。
  • 商業 EDA 有專門的 CDC 檢查工具，找出所有未同步的跨域路徑。

到這裡，循序邏輯的工具都齊了。下一個模組系統地介紹本課程一直在用的 Verilog。

🧭 這一課的重點

跨時脈域的訊號相對於接收時脈的時間是任意的，必然會違反 setup／hold 而產生亞穩態。兩級正反器同步器給第一級一整個週期恢復，MTBF 指數提升；兩級之間不可有邏輯。多位元資料不可逐位同步，須用格雷碼（遞增值）、握手協定或以格雷碼指標實作的非同步 FIFO。快到慢的脈衝要先轉成翻轉訊號，重置放開也需同步。
