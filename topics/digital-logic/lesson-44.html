Verilog：組合邏輯

這一課的目標

  • 用 assign 與 always @(*) 描述組合邏輯
  • 掌握位元寬度、串接與運算子
  • 避免意外產生閂鎖器

模組與連接埠

module mux2 #(parameter W = 8) ( // 參數：寬度可調 input [W-1:0] a, b, input s, output [W-1:0] y ); assign y = s ? b : a; // 連續賦值：y 永遠等於右邊 endmodule

assign 描述的是一條永遠成立的關係，不是一次性的動作：右邊任何訊號改變，y 就跟著變。它對應的硬體就是一團組合邏輯。

常用語法

語法意義例子
8'b1010_0011、8'hA3、8'd163寬度 + 進位 + 值底線只是分隔
a[3:0]、a[7]取部分位元
{a, b}串接{4'b0, x} 補零
{8{a[7]}}複製符號延伸（第 52 課）
& | ^ ~逐位元運算
&a、|a、^a縮減運算：所有位元 AND／OR／XOR 成一位^a 就是同位元
&& || !邏輯運算（結果一位）
+ - * << >> >>>算術與移位合成成加法器、乘法器、移位器
? :條件運算子多工器

位元寬度要特別小心：兩個 8 位元相加的結果要 9 位元才裝得下進位；把 32 位元的值指定給 8 位元的訊號會被默默截斷。模擬器頂多給警告。

always @(*)

較複雜的組合邏輯（case、多層 if）寫在 always @(*) 裡，被賦值的訊號要宣告成 reg（名稱的歷史包袱：它不一定是暫存器）。第 18 課的 mux4_case 與第 23 課的 ALU 都是這種寫法。

閂鎖器陷阱

always @(*) begin if (en) y = d; // en = 0 時呢？沒有寫！ end

組合邏輯的定義是「輸出只依賴目前的輸入」。en = 0 時沒有給 y 新值，語意上 y 要保持舊值——這需要記憶，合成工具只好推論出一個閂鎖器（第 29 課）。這幾乎總是錯誤。避免方法：

  • 每個 if 都有 else，每個 case 都有 default。
  • 更保險：在 always 開頭先給所有輸出一個預設值，再用 if/case 覆蓋。第 19 課的優先權編碼器就是這樣寫的（code = 0; valid = 0;）。
  • SystemVerilog 的 always_comb 會讓工具檢查並報錯。

敏感列表

舊式寫法 always @(a or b) 如果漏寫一個訊號，模擬時那個訊號改變不會觸發重新計算（看起來像有記憶），合成卻會忽略敏感列表產生正確的組合邏輯——典型的模擬與合成不一致。一律使用 @(*)。

🧭 這一課的重點

組合邏輯用 assign（永遠成立的連續賦值）或 always @(*)（內部用 = 阻塞賦值）描述。要掌握位元寬度、串接 {}、複製、縮減運算與條件運算子；寬度不符會默默截斷。always @(*) 中若某條件下未給輸出賦值，會推論出閂鎖器；以完整的 else、default 或開頭預設值避免。敏感列表一律用 @(*) 以免模擬與合成不一致。

🔌 本課程的 Verilog 範例都用 Icarus Verilog 12 實際編譯、模擬過，頁面上的「模擬結果」就是當時的輸出；所有範例可以整包下載。時間單位與延遲數字是教學用的假設值，真實晶片的閘延遲在皮秒等級。
