暫存器與暫存器檔

這一課的目標

  • 由正反器組成 N 位元暫存器
  • 設計多讀埠、單寫埠的暫存器檔
  • 理解 RISC-V x0 恆為 0 的實作

N 個共用時脈（與致能、重置）的 D 正反器就是一個 N 位元暫存器。在 Verilog 中只是把 reg 宣告成向量：reg [31:0] q; always @(posedge clk) q <= d;。

暫存器檔

CPU 需要一組可以用編號存取的暫存器。RISC-V 有 32 個 32 位元的整數暫存器 x0～x31。一條像 add x5, x6, x7 的指令需要同時讀兩個暫存器、寫一個，所以暫存器檔要有兩個讀埠、一個寫埠：

  • 讀埠：5 位元的位址選出 32 個暫存器之一——就是一個 32 選 1 的多工器（每個位元一個，共 32 個）。讀取是組合邏輯，位址一給就有結果。
  • 寫埠：5 位元位址經過 5 對 32 解碼器，再 AND 上寫入致能 we，產生每個暫存器的致能；在時脈邊緣寫入。

🔧 範例：regfile　執行：iverilog -g2012 -o regfile regfile.v tb_regfile.v && vvp regfile

📄 regfile.v　下載

// regfile.v：RISC-V 的 32 個 32 位元暫存器，兩個讀埠、一個寫埠，x0 永遠是 0 module regfile(input clk, input we, input [4:0] ra1, input [4:0] ra2, input [4:0] wa, input [31:0] wd, output [31:0] rd1, output [31:0] rd2); reg [31:0] r [1:31]; assign rd1 = (ra1 == 0) ? 32'd0 : r[ra1]; // 讀取是組合邏輯：立刻得到 assign rd2 = (ra2 == 0) ? 32'd0 : r[ra2]; always @(posedge clk) // 寫入在時脈邊緣 if (we && wa != 0) r[wa] <= wd; endmodule

📄 tb_regfile.v　下載

module tb_regfile; reg clk = 0, we = 0; reg [4:0] ra1, ra2, wa; reg [31:0] wd; wire [31:0] rd1, rd2; regfile rf(clk, we, ra1, ra2, wa, wd, rd1, rd2); always #5 clk = ~clk; initial begin we = 1; wa = 5; wd = 32'd123; @(posedge clk); #1; wa = 6; wd = 32'd456; @(posedge clk); #1; wa = 0; wd = 32'd999; @(posedge clk); #1; // 寫 x0 會被忽略 we = 0; ra1 = 5; ra2 = 6; #1 $display("x5 = %0d, x6 = %0d", rd1, rd2); ra1 = 0; #1 $display("x0 = %0d (writes to x0 are ignored)", rd1); $finish; end endmodule

▶ 模擬結果（實際執行的輸出）

x5 = 123, x6 = 456 x0 = 0 (writes to x0 are ignored)

注意兩個細節：

  1. reg [31:0] r [1:31] 只宣告 31 個暫存器：x0 根本不存在。讀到位址 0 時直接回傳 0，寫入位址 0 時被忽略。RISC-V 用這個恆為 0 的暫存器實作很多「假指令」：mv a, b 是 addi a, b, 0，nop 是 addi x0, x0, 0，無條件跳躍 j 是 jal x0, …。
  2. 讀是組合、寫是同步：在單週期 CPU 中，一條指令在同一個週期內讀暫存器、算出結果，到時脈邊緣才寫回，下一條指令就看得到新值。

真實的暫存器檔

用正反器加多工器做暫存器檔在 FPGA 與小型設計中很普遍。高效能 CPU 的暫存器檔是客製化的 SRAM 陣列（第 47 課），有 6～12 個讀埠、3～6 個寫埠，供多條指令同時使用；因為暫存器重新命名，實體暫存器數量也遠多於 32 個（例如 180～300 個）。每多一個埠，每個儲存格就要多一條字線與位元線，面積大約隨埠數的平方成長。

🧭 這一課的重點

N 個共用時脈的 D 正反器組成暫存器。RISC-V 暫存器檔有 32 個 32 位元暫存器、兩個讀埠（32 選 1 多工器，組合讀取）與一個寫埠（解碼器 + we，在時脈邊緣寫入）。x0 不存在實體儲存，讀回 0、寫入被忽略，讓 mv、nop、j 等假指令得以實作。高效能 CPU 的暫存器檔是多埠 SRAM，面積隨埠數約平方成長。

🔌 本課程的 Verilog 範例都用 Icarus Verilog 12 實際編譯、模擬過，頁面上的「模擬結果」就是當時的輸出；所有範例可以整包下載。時間單位與延遲數字是教學用的假設值，真實晶片的閘延遲在皮秒等級。
