Verilog：循序邏輯與狀態機

這一課的目標

  • 用 always @(posedge clk) 描述正反器
  • 理解阻塞與非阻塞賦值的差別
  • 撰寫測試平台驗證設計

正反器的寫法

always @(posedge clk) begin if (rst) q <= 0; else if (en) q <= d; end

posedge clk 表示只在時脈上升時執行；這段描述合成成帶同步重置與致能的 D 正反器（第 34 課）。在 always @(posedge clk) 裡被賦值的訊號一定變成正反器。

阻塞與非阻塞

<=（非阻塞）的語意是：先把所有右邊的值讀出來，等到這個時間點的所有區塊都執行完，再一起更新左邊。這正好模擬「所有正反器在同一個邊緣同時取樣」。看第 36 課的移位暫存器：如果改用 = 逐級寫 q1 = q0; q2 = q1;，q2 會在同一個邊緣拿到新的 q1——資料一次穿過兩級，而且結果取決於敘述的順序。

規則很簡單，絕不例外：

  1. 循序邏輯（posedge）用 <=。
  2. 組合邏輯（@(*)）用 =。
  3. 同一個訊號只在一個 always 區塊中賦值。

三段式 FSM

第 39 課的 fsm_seq.v 是標準範本：一行 always @(posedge clk) state <= rst ? S0 : next; 是狀態暫存器；一個 always @(*) 用 case 算 next；一個 assign 算輸出。把時序和組合分開，閂鎖器、阻塞非阻塞的錯誤都不容易發生。

測試平台

測試平台是一個沒有連接埠的模組，實例化待測設計、產生時脈與輸入、檢查輸出：

module tb; reg clk = 0, rst = 1; wire [3:0] q; counter4 dut(clk, rst, 1'b1, q); // 待測設計 always #5 clk = ~clk; // 週期 10 的時脈 initial begin @(posedge clk); #1 rst = 0; // 一拍後放開重置 repeat (20) begin @(posedge clk); #1; if (q !== expected) $display("錯！"); // 自動比對 end $finish; end endmodule

好的測試平台會自動比對結果，而不是讓人看波形：本課程的 mux、adders、alu 範例都是窮舉或亂數比對、最後印出錯誤數。!== 是「四值」比較，會把未知值 x 當成不相等。輸入在時脈邊緣之後 #1 才改變，是為了避免與正反器取樣發生競爭。

業界的驗證遠比這複雜：SystemVerilog 的 UVM 方法學、限制式隨機、功能覆蓋率、形式驗證。驗證工程師的人數往往比設計工程師多（〈晶片 Layout 設計〉第 16 課）。

🧭 這一課的重點

always @(posedge clk) 中被賦值的訊號會成為正反器。非阻塞賦值 <= 先讀完所有右邊再同時更新，正確模擬同一邊緣的取樣；阻塞賦值 = 依序執行。規則：循序用 <=、組合用 =、每個訊號只在一個 always 中賦值。三段式 FSM 分離時序與組合。測試平台產生時脈與輸入並自動比對輸出，輸入在邊緣後稍晚改變以避免競爭。

🔌 本課程的 Verilog 範例都用 Icarus Verilog 12 實際編譯、模擬過，頁面上的「模擬結果」就是當時的輸出；所有範例可以整包下載。時間單位與延遲數字是教學用的假設值，真實晶片的閘延遲在皮秒等級。
