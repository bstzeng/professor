多週期 CPU 與微程式

這一課的目標

  • 說明多週期 CPU 如何縮短時脈週期
  • 把控制單元設計成狀態機
  • 理解微程式控制與 CPI

單週期的問題是所有指令都要等最慢的那一個。多週期 CPU 把五個步驟分到不同的週期，每個週期只做一步；步驟之間加上暫存器（指令暫存器 IR、讀出的 A、B、ALU 結果、記憶體資料暫存器）保存中間結果。

指令需要的週期經過的步驟
lw5IF ID EX MEM WB
sw4IF ID EX MEM
R、I 型4IF ID EX WB
分支3IF ID EX
jal3IF ID EX（同時寫回）

時脈週期只要容納最慢的一步（通常是記憶體存取），而不是最慢的一整條指令。每條指令用幾個週期就是幾個，不必都等 5 個。

效能分析

\[ \text{執行時間} = \text{指令數} \times \text{CPI} \times T_{clk} \]

假設單週期 \(T = 800\) ps、CPI = 1；多週期 \(T = 200\) ps，指令組合為 lw 25%、sw 10%、R/I 型 45%、分支 20%，平均 CPI = 0.25×5 + 0.10×4 + 0.45×4 + 0.20×3 = 4.05，每條指令平均 810 ps——反而差不多，因為每個步驟的時間不平均，加上中間暫存器的 \(t_{cq} + t_{setup}\) 開銷。多週期的真正好處是硬體可以重複使用：同一個 ALU 在不同週期算 PC + 4、分支目標與運算結果；指令和資料可以共用一個記憶體。在 1970～80 年代電晶體昂貴的時候，這非常重要。

控制單元變成狀態機

多週期的控制單元是一個 FSM（模組 F）：狀態 IF → ID → 依 opcode 分岔到不同的 EX 狀態 → MEM → WB → 回到 IF。每個狀態輸出一組控制訊號（Moore 機）。

微程式

指令很多、很複雜時（例如 x86），這個 FSM 變得極大。1951 年威爾克斯提出微程式：把每個狀態的控制訊號存在一個 ROM（控制儲存，第 26 課）裡，每一列是一條微指令，下一個狀態也由 ROM 中的欄位決定。設計控制單元就變成「寫微程式」。IBM System/360（1964）用微程式讓同一個 ISA 在快慢不同的機器上實作。

RISC 運動（1980 年代，包括柏克萊的 RISC-I——RISC-V 的「V」就是第五代）認為：與其用微程式實作複雜指令，不如用簡單、固定格式、可以直接硬接線解碼的指令，然後把力氣花在管線化上。今天的 x86 處理器在前端把複雜指令翻譯成類似 RISC 的微操作，只有極少數複雜指令還走微碼。

🧭 這一課的重點

多週期 CPU 把五個步驟分到不同週期，步驟間以暫存器保存中間結果，時脈只需容納最慢的一步，各指令用 3～5 個週期。執行時間 = 指令數 × CPI × T；由於步驟時間不均與暫存器開銷，多週期未必更快，主要好處是共用 ALU 與記憶體。控制單元成為狀態機，複雜時可用微程式（控制訊號存在 ROM）實作。RISC 主張簡單硬接線指令加管線化，現代 x86 則把指令翻譯成微操作。

🔌 本課程的 Verilog 範例都用 Icarus Verilog 12 實際編譯、模擬過，頁面上的「模擬結果」就是當時的輸出；所有範例可以整包下載。時間單位與延遲數字是教學用的假設值，真實晶片的閘延遲在皮秒等級。
