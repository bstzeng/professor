Problem

You are given an m x n integer array grid. There is a robot initially located at the top-left corner. The robot tries to move to the bottom-right corner. The robot can only move either down or right.

An obstacle and space are marked as 1 or 0 respectively in grid. A path that the robot takes cannot include any square that is an obstacle.

Return the number of possible unique paths.

中文翻譯

給你一個 m × n 的二維陣列 obstacleGrid，機器人從左上角出發，要走到右下角，每一步只能往下或往右。

格子裡的 1 表示障礙物，0 表示空地。路徑上不能經過任何障礙物。

回傳總共有幾種不同的走法。

和第 62 題只差一行

第 62 題：dp[i][j] = dp[i-1][j] + dp[i][j-1] 第 63 題：if 是障礙物: dp[i][j] = 0 else: dp[i][j] = dp[i-1][j] + dp[i][j-1] 「障礙物 = 0 種走法」這個設定非常漂亮： 走不到它（0 種）， 而且它也不會把任何走法「傳」給右邊和下面的格子（加 0 等於沒加）。 所以我們不需要特別處理「繞過障礙物」—— 只要把它的值設成 0，整張表就會自動正確。 而組合公式（C(m+n-2, m-1)）在這裡完全失效 —— 因為「哪些路徑會被擋住」沒有簡單的封閉形式。 這就是 DP 相對於數學公式的價值：它能吸收任意的局部限制。

範例

範例 1 輸入：obstacleGrid = [[0,0,0],[0,1,0],[0,0,0]] 輸出：2 說明：3×3 的網格正中間有一個障礙物。 1. 右 → 右 → 下 → 下 2. 下 → 下 → 右 → 右 範例 2 輸入：obstacleGrid = [[0,1],[0,0]] 輸出：1

限制條件

  • m == obstacleGrid.length，n == obstacleGrid[i].length
  • 1 ≤ m, n ≤ 100
  • obstacleGrid[i][j] 是 0 或 1

LeetCode 原題

三個容易踩的邊界

  • 起點就是障礙物：[[1]] → 0。如果直接寫 dp[0][0] = 1 而不檢查，答案會錯。
  • 終點是障礙物：答案 0。這個會被主迴圈自然處理（dp[m-1][n-1] 被設成 0）。
  • 第一列或第一行中間有障礙物：[[0,1,0]] → 0。障礙物「後面」的格子全部走不到 —— 所以第一列／第一行不能無腦初始化成 1，必須讓 DP 自然算出來。

解題思路

第 62 題的 DP 骨架完全不變，只加上「障礙物歸零」。但初始化要小心：第 62 題可以把第一列和第一行都設成 1，這題不行。

解法一

二維 DP（把邊界也交給迴圈處理）

class Solution: def uniquePathsWithObstacles(self, obstacleGrid: List[List[int]]) -> int: m, n = len(obstacleGrid), len(obstacleGrid[0]) if obstacleGrid[0][0] == 1: return 0 # 起點就被擋住 dp = [[0] * n for _ in range(m)] dp[0][0] = 1 for i in range(m): for j in range(n): if obstacleGrid[i][j] == 1: dp[i][j] = 0 # 障礙物：走不到，也不能往外傳 continue if i > 0: dp[i][j] += dp[i - 1][j] if j > 0: dp[i][j] += dp[i][j - 1] return dp[m - 1][n - 1]

為什麼不預先初始化第一列和第一行？

第 62 題可以寫 dp = [[1] * n for _ in range(m)] （第一列和第一行都是 1）。 這題不行，因為障礙物會「切斷」它們： grid = [[0, 1, 0]] dp[0][0] = 1 dp[0][1] = 0（障礙物） dp[0][2] = dp[0][1] = 0 ← 走不到！ 如果無腦設成 1，dp[0][2] 會是 1 ✘ 所以正確的做法是： 只設 dp[0][0] = 1（起點）， 其餘全部交給主迴圈的 if i > 0 / if j > 0 去累加。 i == 0 時只會累加 dp[0][j-1]（左邊） j == 0 時只會累加 dp[i-1][0]（上面） 邊界自然就對了，而且障礙物的 0 會正確地往後傳播。 「讓邊界由一般規則自然產生，而不是特別初始化」 是減少 bug 的好習慣。

起點被擋住的特判

if obstacleGrid[0][0] == 1: return 0。其實主迴圈也會處理（dp[0][0] 被 continue 前的 dp[i][j] = 0 蓋掉）—— 但我們在迴圈前就寫了 dp[0][0] = 1，而迴圈的第一輪 i=0, j=0 會把它改回 0。所以其實不特判也對，但寫出來讓意圖更清楚。

時間O(m·n)填滿整張表
空間O(m·n)dp 表
解法二

一維 DP（滾動陣列，最推薦）

class Solution: def uniquePathsWithObstacles(self, obstacleGrid: List[List[int]]) -> int: n = len(obstacleGrid[0]) dp = [0] * n dp[0] = 1 # 起點（若被擋，下面第一輪就會歸零） for row in obstacleGrid: for j in range(n): if row[j] == 1: dp[j] = 0 # 障礙物：這一格歸零 elif j > 0: dp[j] += dp[j - 1] # 否則：上面(舊 dp[j]) + 左邊(新 dp[j-1]) return dp[n - 1]

初始化 dp[0] = 1 的巧妙之處

dp = [0] * n dp[0] = 1 這個 dp 代表「第 -1 列」的狀態 —— 一個虛擬的、在網格上方的列， 只有第 0 欄有 1 條路徑（代表「起點可達」）。 然後第一輪迴圈（處理第 0 列）： j=0: row[0] == 0 -> j > 0 不成立 -> dp[0] 保持 1 ✔ （或 row[0] == 1 -> dp[0] = 0，處理了「起點被擋」） j=1: dp[1] += dp[0] = 1 ... 所以「起點被擋住」這個邊界，被第一輪迴圈自動處理了 —— 不需要任何特判。 這就是為什麼一維版比二維版還短。

三個分支的順序

if row[j] == 1: dp[j] = 0 障礙物優先，直接歸零 elif j > 0: dp[j] += dp[j-1] 非障礙物且不在第一欄：累加左邊 （else: j == 0 且非障礙物 -> dp[0] 保持不變 = 上一列的值） 第三種情況（j == 0）為什麼「保持不變」就對？ 第 0 欄只能從上面來， 而 dp[0] 此刻正好是「上一列第 0 欄」的值 ✔ 不用寫任何程式碼 —— 這是滾動陣列的自然結果。

O(n) 空間，而且程式碼比二維版還短。面試時寫這個版本，並且說明「dp 在迴圈中途同時混合了新舊兩列的值」。

複雜度說明
時間O(m·n)同上
空間O(n)一條長度 n 的陣列

邊界條件檢查清單

  • 起點是障礙物：[[1]]、[[1,0]] → 0。
  • 終點是障礙物：[[0,0],[0,1]] → 0。
  • 第一列被切斷：[[0,1,0]] → 0。無腦初始化第一列為 1 會錯。
  • 整列被擋住：[[0,0],[1,1],[0,0]] → 0。
  • 沒有障礙物：退化成第 62 題。
  • 1×1 空網格：[[0]] → 1。
  • 繞得過的障礙：[[0,0,0],[1,1,0],[0,0,0]] → 1（只能從上面繞）。

常見追問

追問一：為什麼組合公式在這裡失效？

因為「有幾條路徑被障礙物擋住」沒有簡單的封閉形式。理論上可以用容斥原理（扣掉經過障礙物 A 的、扣掉經過 B 的、加回同時經過 A 和 B 的…），但障礙物有 k 個時要算 2ᵏ 項 —— 遠不如 DP 的 O(mn)。

這是一個很好的例子：封閉公式很美，但 DP 更能「吸收」局部的限制。

追問二：如果要原地做（不用額外空間）呢？

可以直接把 obstacleGrid 當成 dp 表用 —— 把障礙物的 1 改成 0，空地填上路徑數。但這會破壞輸入，而且「1 同時代表障礙物和路徑數 1」很容易混淆。一維滾動陣列的 O(n) 已經夠好了，不值得為了 O(1) 犧牲可讀性。

追問三：如果障礙物很少呢？

可以用容斥 + 組合數：先算總路徑 C(m+n-2, m-1)，再依序扣掉「第一個碰到的障礙物是第 i 個」的路徑數。把障礙物排序後，用 f[i] = C(到 i 的路徑) − Σ f[j] × C(從 j 到 i 的路徑) 遞推。複雜度 O(k²)，k 是障礙物數量。當 k ≪ mn 時（例如 10⁹ × 10⁹ 的網格只有 100 個障礙物），這是唯一可行的做法。
