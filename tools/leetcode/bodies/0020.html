Problem

Given a string s containing just the characters '(', ')', '{', '}', '[' and ']', determine if the input string is valid.

An input string is valid if: open brackets are closed by the same type of brackets, open brackets are closed in the correct order, and every close bracket has a corresponding open bracket of the same type.

中文翻譯

給你一個只含 '('、')'、'{'、'}'、'['、']' 的字串 s，判斷它是否有效。

有效的定義：（1）左括號必須用相同類型的右括號關閉；（2）左括號必須以正確的順序關閉；（3）每個右括號都要有對應的左括號。

為什麼一定是堆疊？

括號匹配的結構是後進先出（LIFO）：最後打開的括號，必須最先關閉。這正是堆疊的定義。

"{[()]}" 合法 最內層的 () 先關，然後 []，最後 {} "([)]" 不合法 ( 比 [ 早開，卻比 [ 晚關 —— 交錯了 如果不用堆疊，你必須同時追蹤「所有還沒關的括號以及它們的順序」 —— 那就是在手工實作一個堆疊。 反過來說，如果只有一種括號（例如只有小括號）， 那用一個「計數器」就夠了（+1 開、-1 關、不能變負、結束時要是 0）。 是「多種括號」讓計數器失效、逼出堆疊。

範例

範例 1 輸入：s = "()" 輸出：true 範例 2 輸入：s = "()[]{}" 輸出：true 範例 3 輸入：s = "(]" 輸出：false 說明：類型對不上。 範例 4 輸入：s = "([)]" 輸出：false 說明：順序不對（交錯了）。 範例 5 輸入：s = "([])" 輸出：true

限制條件

  • 1 ≤ s.length ≤ 10⁴
  • s 只由 '()[]{}' 這六個字元組成

LeetCode 原題

先看懂限制在說什麼

  • 只有六種字元，沒有其他雜訊。所以「不是右括號的就是左括號」這個判斷是安全的 —— 不用第三個分支。
  • 長度到 10⁴。O(n) 的堆疊解法輕鬆過；但 O(n²) 的「反覆 replace」解法（解法二）在最壞情況下會明顯變慢。
  • 長度至少 1，不過空字串在數學上是合法的（堆疊為空），我們的程式也自然會回 true —— 不用特判。
  • 奇數長度必定不合法。可以加一行 if len(s) % 2: return False 提前退出，但這只是常數優化。

解題思路

解法一

堆疊（唯一正解）

class Solution: def isValid(self, s: str) -> bool: PAIR = {")": "(", "]": "[", "}": "{"} # 右括號 -> 對應的左括號 stack = [] for ch in s: if ch in PAIR: # 是右括號 # 堆疊空了，或頂端不是配對的左括號 -> 失敗 if not stack or stack.pop() != PAIR[ch]: return False else: # 是左括號 stack.append(ch) return not stack # 必須剛好清空；還有剩表示有左括號沒關

三個必須同時成立的條件

1. 遇到右括號時，堆疊不能是空的 ")" 或 "]" 開頭 -> 沒有對應的左括號 -> False 2. 遇到右括號時，堆疊頂端必須是「同類型」的左括號 "(]" -> pop 出 "("，但 "]" 需要的是 "[" -> False 3. 全部處理完之後，堆疊必須是空的 "(()" -> 結束時堆疊還剩一個 "(" -> False 漏掉第 3 條是最常見的 bug： "(((" 會一路 push 而不觸發任何檢查， 如果最後直接 return True 就錯了。

為什麼用「右括號 → 左括號」的映射，而不是反過來？

PAIR = {")": "(", "]": "[", "}": "{"} 這樣寫的好處：判斷「這是不是右括號」只要 ch in PAIR， 一個字典同時當「分類器」和「對照表」用。 如果反過來寫 {"(": ")", ...}， 判斷右括號就要另外寫 ch in ")]}" 或 ch in PAIR.values()， 多一個資料結構，也多一個出錯的地方。 小細節，但它讓程式碼從 8 行變 6 行，而且更不容易錯。

stack.pop() != PAIR[ch] 這一行同時做了兩件事：取出頂端、並且比對。因為 Python 的 and 短路求值，not stack 為真時就不會執行 pop()，所以不會 IndexError。順序不能顛倒。

複雜度說明
時間O(n)每個字元處理一次
空間O(n)最壞情況（全是左括號）堆疊有 n 個元素
解法二

反覆消除（有趣但很慢）

另一種思路：合法的字串一定能靠「不斷消掉相鄰的一對」化簡成空字串。

class Solution: def isValid(self, s: str) -> bool: # 反覆把最內層的一對消掉，直到消不動為止 while "()" in s or "[]" in s or "{}" in s: s = s.replace("()", "").replace("[]", "").replace("{}", "") return s == ""
"{[()]}" -> replace("()", "") -> "{[]}" -> replace("[]", "") -> "{}" -> replace("{}", "") -> "" -> 空字串，合法 ✔ "([)]" -> 三種 replace 都找不到東西可消 -> while 條件不成立，跳出 -> s != ""，不合法 ✔

正確，但複雜度是 O(n²)：最壞情況（例如 "((((...))))"）每輪只能消掉最內層的一對，要跑 n/2 輪，每輪的 replace 又要掃過整個字串。n = 10⁴ 時大約 5 × 10⁷ 次字元操作 —— 能過，但比堆疊慢一兩個數量級。

為什麼還要講它？因為它揭示了一件事：堆疊本質上就是在做同一件事，只是一趟做完。堆疊的 push/pop 就是「延後的消除」—— 理解這個對應關係，之後看到單調堆疊、運算式求值這類題目會更有感覺。

複雜度說明
時間O(n²)最壞 n/2 輪 × 每輪 O(n)
空間O(n)字串的複本

邊界條件檢查清單

  • 右括號開頭：")"、"]" → false。堆疊是空的就 pop 會炸。
  • 左括號沒關："("、"(()" → false。忘記最後檢查堆疊為空的話會錯。
  • 類型錯配："(]"、"{)" → false。
  • 順序交錯："([)]" → false。這是堆疊存在的理由。
  • 正確巢狀："([{}])"、"{[]}" → true。
  • 並列："()[]{}" → true。每一對獨立開關。
  • 深層巢狀："(((((((((())))))))))" → true。堆疊會長到 10 層。
  • 奇數長度：一定 false，可以提前退出。

常見追問

追問一：如果還有其他字元（例如 "a(b)c"）呢？

把 else: stack.append(ch) 改成只在 ch in "([{" 時才 push，其他字元直接忽略。一行的差別，但如果不改，字母也會被推進堆疊，結果全錯。

追問二：如果要回傳「最長的合法子字串長度」呢？

那是第 32 題（Longest Valid Parentheses），難度跳到 Hard。堆疊還是主角，但要改成存索引而不是存字元，而且要在堆疊底部放一個「上一個不合法位置」的哨兵。

追問三：如果允許用 '*' 當萬用字元（可以是 '('、')' 或空）呢？

那是第 678 題（Valid Parenthesis String）。堆疊不夠用了，因為 '*' 有三種可能。標準解法是維護「可能的左括號數量」的區間 [lo, hi]：遇到 '(' 兩者都 +1，')' 都 −1，'*' 則 lo −1、hi +1。過程中 hi 不能變負，lo 要夾在 0 以上，結束時 lo 必須是 0。「用區間代替列舉所有可能」是一個很強大的技巧。

追問四：這題和編譯器有什麼關係？

括號匹配是語法分析（parsing）的最小範例。「合法的括號序列」是一個典型的上下文無關語言，而它不是正規語言 —— 這就是為什麼你不能用正規表示式檢查括號配對（有限狀態機沒有記憶體記住巢狀深度，但堆疊有）。這個觀察是計算理論裡的經典結果（用 pumping lemma 可以證明）。
