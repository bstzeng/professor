Problem

Given an integer rowIndex, return the rowIndexth (0-indexed) row of the Pascal's triangle.

In Pascal's triangle, each number is the sum of the two numbers directly above it.

Follow up: Could you optimize your algorithm to use only O(rowIndex) extra space?

中文翻譯

給你一個整數 rowIndex，回傳楊輝三角的第 rowIndex 列（從 0 開始算）。

進階：你能只用 O(rowIndex) 額外空間嗎？

★ 這題的唯一考點：倒著更新

如果照第 118 題那樣做，要存整個三角形 -> O(k²) 空間。 進階要求只用 O(k) —— 也就是【只保留一列，原地更新】。 【但原地更新有陷阱】： row[j] = row[j-1] + row[j] ^^^^^^^^ ^^^^^^ 需要「上一列」的值 正著走（j 從小到大）： 更新 row[1] 時用 row[0] -> row[0] 永遠是 1，沒問題 更新 row[2] 時用 row[1] -> row[1] 【已經被這一輪改掉了】✘ row = [1,1,1]，要變成 [1,2,1] 正著走：row[1] += row[0] -> [1,2,1] row[2] += row[1] -> [1,2,3] ✘ 應該是 [1,2,1] 倒著走（j 從大到小）： 更新 row[2] 時用 row[1] -> 還沒改 ✔ 更新 row[1] 時用 row[0] -> 還沒改 ✔ row = [1,1,1] 倒著走：row[2] += row[1] -> [1,1,2] row[1] += row[0] -> [1,2,2] 咦，這也不對？ ...因為 row 一開始就全填 1 了， 而第 2 列（i=2）只需要改 row[1]： for j in range(i-1, 0, -1) -> i=2 時 range(1,0,-1) = [1] row[1] += row[0] -> [1,2,1] ✔ 【內層迴圈的上界是 i-1，不是 len(row)-1。】 因為第 i 列只有前 i+1 個是有效的， 而其中只有索引 1..i-1 需要更新。 【這個「倒著走」和第 115 題（不同子序列）、 01 背包是完全同一件事。】

範例

範例 1 輸入：rowIndex = 3 輸出：[1,3,3,1] 範例 2 輸入：rowIndex = 0 輸出：[1] 範例 3 輸入：rowIndex = 1 輸出：[1,1]

限制條件

  • 0 ≤ rowIndex ≤ 33

LeetCode 原題

為什麼上限是 33？

第 33 列的最大值是 C(33, 16) = 1166803110 C(34, 17) = 2333606220 > 2^31 - 1 = 2147483647 溢位！ 所以 rowIndex <= 33 是為了讓所有數字都裝得進 32 位元有號整數。 【和第 96 題的 n <= 19、第 70 題的 n <= 45 是同一種考量。】 看到這種「奇怪的上限」， 反射動作應該是「這大概是為了不溢位」。 Python 的整數無限大，所以不受影響 —— 但解法三（乘除法）在其他語言裡要特別小心： 【必須先乘後除】，而且中間值可能接近上限。

解題思路

三條路： 【A. 原地倒著更新】（解法一） 只用一個長度 k+1 的陣列，倒著走避免覆蓋。 O(k²) 時間、O(k) 空間 ✔ 滿足進階。 【B. 移位相加】（解法二） 每次造一條新的 list（第 118 題的解法二）。 O(k²) 時間，但空間嚴格說是 O(k) —— 因為同時只有兩條 list 存在（舊的會被回收）。 【C. 直接用組合數遞推】（解法三） C(n, k) = C(n, k-1) × (n - k + 1) / k 一路乘除算過去，O(k) 時間、O(k) 空間（就是輸出）。 【這是唯一一個 O(k) 時間的解法】—— 比要求的 O(k²) 還快一個數量級。
解法一

原地倒著更新（滿足進階要求）

class Solution: def getRow(self, rowIndex: int) -> List[int]: row = [1] * (rowIndex + 1) for i in range(2, rowIndex + 1): # 【倒著走】：row[j] 要用到 row[j-1] 的「上一列」的值 for j in range(i - 1, 0, -1): row[j] += row[j - 1] return row

兩個迴圈的邊界

for i in range(2, rowIndex + 1): # 從第 2 列開始 for j in range(i - 1, 0, -1): # j 從 i-1 倒數到 1 為什麼 i 從 2 開始？ 第 0 列 [1]、第 1 列 [1,1] 都不用改 （全 1 就是答案）。 為什麼 j 的上界是 i-1？ 第 i 列有 i+1 個元素（索引 0..i）， 兩端是 1 不用改，所以要改的是 1..i-1。 為什麼 j 的下界是 1（不含 0）？ row[0] 永遠是 1。 驗算 rowIndex = 3： 初始 row = [1,1,1,1] i=2: j=1 -> row[1] += row[0] -> [1,2,1,1] i=3: j=2 -> row[2] += row[1] -> [1,2,3,1] j=1 -> row[1] += row[0] -> [1,3,3,1] ✔

O(k²) 時間、O(k) 空間（除了輸出之外是 O(1)）。這就是進階要求的答案。

複雜度說明
時間O(k²)兩層迴圈
空間O(k)只有一列
解法二

移位相加（最短）

class Solution: def getRow(self, rowIndex: int) -> List[int]: row = [1] for _ in range(rowIndex): row = [a + b for a, b in zip([0] + row, row + [0])] return row

四行。和第 118 題的解法二完全一樣，只是不收集中間結果。

注意初始值是 row = [1] 而不是 [] —— 同樣的邊界陷阱。

迴圈跑 rowIndex 次（不是 rowIndex + 1）—— 因為初始的 [1] 就已經是第 0 列了。

空間嚴格說是多少？ 每一輪都建立一條新的 list， 但舊的立刻失去參考、會被回收。 所以【同時存在的記憶體】是 O(k) ✔ 不過它確實比解法一多了「配置 + 回收」的成本， 在極端在意效能的場合（k 很大）會有差別。 對 k <= 33 來說完全無所謂。
複雜度說明
時間O(k²)每輪建一條新 list
空間O(k)同時兩條列
解法三

組合數遞推（O(k) 時間，最快）

class Solution: def getRow(self, rowIndex: int) -> List[int]: # C(n, k) = C(n, k-1) * (n - k + 1) / k，一路乘除算過去 row = [1] n = rowIndex for k in range(1, n + 1): row.append(row[-1] * (n - k + 1) // k) return row

推導 C(n,k) = C(n,k-1) × (n-k+1) / k

C(n, k) = n! / (k! (n-k)!) C(n, k-1) = n! / ((k-1)! (n-k+1)!) C(n,k) / C(n,k-1) = [(k-1)! (n-k+1)!] / [k! (n-k)!] = (n-k+1) / k ✔ 驗算 n = 4： C(4,0) = 1 C(4,1) = 1 × (4-1+1)/1 = 4/1 = 4 ✔ C(4,2) = 4 × (4-2+1)/2 = 4×3/2 = 6 ✔ C(4,3) = 6 × (4-3+1)/3 = 6×2/3 = 4 ✔ C(4,4) = 4 × (4-4+1)/4 = 4×1/4 = 1 ✔ 【★ 必須先乘後除】： row[-1] * (n - k + 1) // k ✔ row[-1] // k * (n - k + 1) ✘ 餘數會被丟掉 為什麼先乘後除一定整除？ 因為 C(n,k-1) × (n-k+1) = C(n,k) × k， 而 C(n,k) 是整數 -> 左邊一定被 k 整除 ✔ 【這和第 96 題（卡塔蘭數遞推）、 第 62 題（手算組合數）的注意事項一模一樣。】

O(k) 時間 —— 只跑一個迴圈。比進階要求的 O(k²) 還快。

但要注意中間值：row[-1] * (n-k+1) 可能比最終答案大一個因子 k。在 C++ / Java 裡 rowIndex = 33 時這個中間值會超過 int，必須用 long long。

複雜度說明
時間O(k)一個迴圈
空間O(k)輸出本身

邊界條件檢查清單

  • rowIndex = 0 → [1]。三種解法的迴圈都一次都不跑。
  • rowIndex = 1 → [1,1]。
  • rowIndex = 33 → 最大值 1166803110，剛好在 INT_MAX 內。
  • 解法一正著走 j → 答案全錯（用到被改過的值）—— 本題第一名的 bug。
  • 解法一的 j 上界寫成 rowIndex 而不是 i-1 → 會提前把後面的格子加進去。
  • 解法二初始值寫成 [] → 得到 [0]。
  • 解法三先除後乘 → 餘數損失，答案錯。

常見追問

追問一：如果只要「第 n 列的第 k 項」呢？

直接 math.comb(n, k)，或用解法三的遞推算 k 步 —— O(k) 時間、O(1) 空間。

不需要算出整列。「只要一個值」時，永遠先問「能不能跳過中間過程」。

追問二：如果 rowIndex 很大（例如 10⁶）且要對質數取模呢？

C(n, k) mod p （p 是質數）： 方法 A：預處理階乘和反元素 fact[i] = i! mod p inv_fact[i] = (i!)^(-1) mod p 用費馬小定理算 C(n,k) = fact[n] × inv_fact[k] × inv_fact[n-k] mod p 預處理 O(n)，之後每次查詢 O(1)。 方法 B：Lucas 定理（n 很大、p 很小時） C(n,k) mod p = Π C(n_i, k_i) mod p （n_i, k_i 是 n, k 在 p 進位下的每一位） O(log_p n) 時間。 【競賽裡幾乎所有組合數題目都長這樣】—— 「對 10^9 + 7 取模」是標準設定， 因為 10^9+7 是質數，而且 2^31 裝得下它的平方的一半。

追問三：解法三為什麼不會有精度問題？

因為全程都是整數運算（// 而不是 /）。

如果用浮點數（/），C(33,16) 這種九位數會開始累積誤差，最後可能差個 1。「組合數一律用整數運算」是鐵律。

追問四：能不能 O(1) 空間？

如果「輸出」不算，那解法三已經是 O(1) 了（只需要記住上一項）。

但輸出本身有 k+1 個數字，所以總空間至少 O(k) —— 這是輸出規模的下界，無法突破。
