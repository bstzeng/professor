Problem

Given the roots of two binary trees p and q, write a function to check if they are the same or not.

Two binary trees are considered the same if they are structurally identical, and the nodes have the same value.

中文翻譯

給你兩棵二元樹的根節點 p 和 q，判斷它們是否相同。

兩棵二元樹相同的條件是：結構完全一致，而且對應位置的節點值也相同。

第 100 題，一個里程碑

恭喜你走到第 100 題。這題是樹的遞迴最乾淨的起點 —— 五行程式碼，卻包含了所有樹題目的共同骨架。

如果你能把這題的三個 base case 說清楚，後面幾百道樹的題目都只是它的變形。

「相同」的兩個條件，缺一不可

1. 結構一致（每個位置有沒有節點，完全一樣） 2. 對應位置的值一樣 只滿足 2 不算 —— 1 1 / \ 2 2 兩棵樹的「值」都是 {1, 2}，但一個掛左邊、一個掛右邊。 【不同。】 只滿足 1 也不算 —— 1 1 / \ / \ 2 3 2 4 結構一模一樣，但 3 != 4。 【不同。】 【這兩個條件在遞迴裡剛好對應到「檢查 None」和「檢查 val」。】

範例

範例 1 輸入：p = [1,2,3], q = [1,2,3] 1 1 / \ / \ 2 3 2 3 輸出：true 範例 2 輸入：p = [1,2], q = [1,null,2] 1 1 / \ 2 2 輸出：false （結構不同） 範例 3 輸入：p = [1,2,1], q = [1,1,2] 1 1 / \ / \ 2 1 1 2 輸出：false （對應位置的值不同）

限制條件

  • 兩棵樹的節點數都在 [0, 100] 之間
  • −10⁴ ≤ Node.val ≤ 10⁴

LeetCode 原題

注意：節點數可以是 0

所以 p 和 q 都可能是 None。

isSameTree(None, None) 必須回 True（兩棵空樹是相同的）。這是最容易被漏掉的測資。

解題思路

把定義直接翻成遞迴： 「p 和 q 相同」 ⟺ 根節點相同 且 左子樹相同 且 右子樹相同 三個 base case，【順序很重要】： 1. not p and not q -> True 兩邊都空，相同 2. not p or not q -> False 只有一邊空，結構就不一樣了 3. p.val != q.val -> False 都存在但值不同 然後遞迴： isSame(p.left, q.left) and isSame(p.right, q.right) 【為什麼 1 一定要在 2 前面？】 如果先寫 2（not p or not q -> False）， 那麼 p 和 q 都是 None 時也會進到這一條 -> 回 False ✘ 但兩棵空樹明明是相同的。 正確的順序是： 先排除「都空」（True），再排除「只有一邊空」（False）。 【這是本題唯一的陷阱，也是它值得被當成第 100 題的原因 —— 它逼你把 base case 的順序想清楚。】 【為什麼 3 要在遞迴之前？】 這只是效率問題（提早發現不同就不用往下走）， 不影響正確性。但寫在前面更自然。

遞迴、BFS、DFS 迭代、序列化 —— 四種寫法都很短，差別只在「用什麼方式同步走訪兩棵樹」。

解法一

遞迴（標準答案，五行）

class Solution: def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool: if not p and not q: return True # 兩邊都空 -> 相同 if not p or not q: return False # 只有一邊空 -> 不同 if p.val != q.val: return False # 值不同 -> 不同 return (self.isSameTree(p.left, q.left) and self.isSameTree(p.right, q.right))

三個 if 加一行遞迴，就是全部。這是樹題目最標準的形狀，值得背下來當模板。

手動走一遍範例 2

p = [1,2] q = [1,null,2] 1 1 / \ 2 2 isSame(p=1, q=1) 兩個都不是 None ✔ 1 == 1 ✔ -> isSame(p.left=2, q.left=None) and isSame(p.right=None, q.right=2) isSame(2, None) not p and not q ？ p 存在 -> 否 not p or not q ？ q 是 None -> 【是】 -> return False ✔ 短路，右邊不用算了 -> False ✔

複雜度

時間 O(min(m, n)) 注意【不是 O(m + n)】—— 因為只要有一邊走完（或發現不同）就會停， 最多只會訪問「兩棵樹的共同部分」。 實務上常寫成 O(n)，但說得出 min(m, n) 會加分。 空間 O(min(m, n)) 最壞情況 遞迴堆疊的深度 = min(兩棵樹的高度)。 平衡樹是 O(log n)，退化成鏈時是 O(n)。 本題 n <= 100，完全不用擔心。
複雜度說明
時間O(min(m, n))只走共同部分
空間O(min(h₁, h₂))遞迴堆疊
解法二

遞迴（更精簡的寫法）

class Solution: def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool: if not p or not q: return p is q # 至少一邊是 None：只有都是 None 才相同 return (p.val == q.val and self.isSameTree(p.left, q.left) and self.isSameTree(p.right, q.right))

return p is q 這一手

if not p or not q: return p is q 走到這一行時，代表【至少有一邊是 None】。 如果兩邊都是 None -> p is q 為 True ✔ 如果只有一邊是 None -> 一個是 None、一個是節點物件 -> p is q 為 False ✔ 一行取代了原本的兩個 if。 【為什麼用 is 而不是 ==？】 is 比較的是「同一個物件」， 而 None 在 Python 裡是單例（只有一個 None 物件）。 用 == 在這裡也會對，但 == 可能觸發 __eq__， 語意上不夠精確。 【比較 None 一律用 is，這是 Python 的慣例（PEP 8）。】

精簡不等於比較好 —— 面試時解法一更容易讓面試官跟上你的思路。這個版本適合在寫完解法一之後說「也可以壓成這樣」。

複雜度說明
時間O(min(m, n))同解法一
空間O(min(h₁, h₂))遞迴堆疊
解法三

BFS 迭代（用佇列同步走訪）

from collections import deque class Solution: def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool: dq = deque([(p, q)]) # 一次比一「對」節點 while dq: a, b = dq.popleft() if not a and not b: continue # 兩邊都空，這一對沒問題 if not a or not b or a.val != b.val: return False dq.append((a.left, b.left)) # 左對左 dq.append((a.right, b.right)) # 右對右 return True

核心：佇列裡放的是「一對節點」

dq = deque([(p, q)]) 每次取出一「對」要比較的節點， 然後把它們的 (左, 左) 和 (右, 右) 再放進去。 【關鍵是「成對」地走 —— 兩棵樹用同一個節奏往下推進。】 如果一對都是 None -> continue（這一對沒問題，不用往下） 如果只有一邊 None 或值不同 -> 立刻 return False 這個「成對推進」的想法，在下面這些題目裡會一再出現： 101 Symmetric Tree -> 放 (左.left, 右.right) 和 (左.right, 右.left) 572 Subtree of Another -> 對每個節點呼叫一次 isSameTree 951 Flip Equivalent BT -> 兩種配對方式都試 1367 Linked List in BT -> 樹和鏈結串列成對推進

沒有遞迴深度限制。本題 n ≤ 100 用不到，但面試官問「能不能不用遞迴」時就是它。

空間 O(w)（w 是樹的最大寬度）—— 完全二元樹時是 O(n/2) = O(n)，其實比遞迴版差。BFS 換掉的是「深度風險」，不是空間。

複雜度說明
時間O(min(m, n))每對節點一次
空間O(w)佇列最大寬度
解法四

DFS 迭代（把 deque 換成 stack）

class Solution: def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool: stack = [(p, q)] while stack: a, b = stack.pop() if not a and not b: continue if not a or not b or a.val != b.val: return False stack.append((a.left, b.left)) stack.append((a.right, b.right)) return True

和解法三只差一個字：popleft()（佇列，BFS）改成 pop()（堆疊，DFS）。

【這是一個很值得注意的現象】： BFS 和 DFS 的迭代版，程式碼結構完全一樣， 差別只在「從哪一端取出元素」。 popleft() -> 先進先出 -> BFS（一層一層） pop() -> 後進先出 -> DFS（一路走到底） 對「判斷是否相同」這件事來說， 【走訪順序完全不影響答案】—— 因為我們要檢查「每一對」，順序無所謂。 所以兩個版本都對，挑順手的寫。 （但如果題目問「最先發現的不同在哪裡」， 那順序就有意義了。）

空間 O(h) —— 對深而窄的樹，這比 BFS 省。

複雜度說明
時間O(min(m, n))每對節點一次
空間O(h)堆疊深度
解法五

序列化後比較字串（有陷阱，但概念重要）

class Solution: def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool: def ser(node) -> str: if not node: return "#" # 空節點一定要留下記號 return "(%s,%d,%s)" % (ser(node.left), node.val, ser(node.right)) return ser(p) == ser(q)

空節點的記號 # 絕對不能省

如果序列化時忽略空節點： 1 1 / \ 2 2 前序（跳過空節點）： "1,2" 和 "1,2" -> 誤判成相同 ✘ 加上空節點的記號之後： "(( #,2,# ),1,#)" 和 "(#,1,( #,2,# ))" -> 不同 ✔ 【一個序列化方式要能「唯一決定」一棵樹， 就必須記錄空節點的位置。】 這在第 297 題（序列化與反序列化二元樹）是核心考點。 另一個等價的做法是「前序 + 中序」兩條序列 —— 但那需要值互不重複才成立，限制更多。

為什麼這個解法「不推薦」？

  • 時間和空間都是 O(n)，而且常數大（字串拼接）。
  • 沒有提早結束 —— 就算第一個節點就不同，也得把兩棵樹整個序列化完。
  • 字串比較本身是 O(n)，等於多走了一遍。

但它的概念很有用：當你要「把一棵樹當成雜湊表的鍵」或「找出所有重複的子樹」（第 652 題）時，序列化就是標準做法。

複雜度說明
時間O(m + n)一定走完整棵樹
空間O(m + n)兩條字串

這題是「樹的遞迴模板」的最小範例

幾乎所有樹的遞迴題目都長這樣： def go(node): if <base case>: # 1. 空節點怎麼辦 return <base 值> <對 node 本身做檢查> # 2. 當前節點的邏輯 left = go(node.left) # 3. 交給子問題 right = go(node.right) return <合併 left 和 right> # 4. 把子答案合起來 本題只是把它從「一棵樹」擴展成「兩棵樹同步走」。 def go(a, b): if not a and not b: return True if not a or not b: return False if a.val != b.val: return False return go(a.left, b.left) and go(a.right, b.right) 【一旦你掌握這個形狀，下面這些題目都是同一招換皮】： 101 Symmetric Tree go(a.left, b.right) and go(a.right, b.left) 226 Invert Binary Tree 交換左右再遞迴 104 Maximum Depth 1 + max(左, 右) 110 Balanced Binary Tree 回傳 (高度, 是否平衡) 543 Diameter of Binary Tree 在遞迴中順便更新全域最大值 124 Max Path Sum 同上，但值可能是負的 【第 100 題是這一整片森林的入口。】

邊界條件檢查清單

  • p = None, q = None → True。把 base case 順序寫反就會錯，這是本題第一名的 bug。
  • p = None, q = [1] → False。
  • p = [1], q = [1] → True。
  • p = [1,2], q = [1,null,2] → False（結構不同）。
  • p = [1,2,1], q = [1,1,2] → False（值不對位）。
  • 節點值是 0 → 如果你用 if not node.val 之類的寫法會爆炸。檢查節點存在請用 if not node，不要碰 val 的真假值。
  • 把遞迴寫成 go(p.left, q.right) → 那是第 101 題（對稱樹），不是這題。
  • 序列化版忘了寫空節點記號 → [1,2] 和 [1,null,2] 會誤判成相同。

常見追問

追問一：如果要判斷「兩棵樹是否對稱」呢？

第 101 題。只要把遞迴的配對方式改掉：

相同（第 100 題）： go(a.left, b.left) and go(a.right, b.right) 對稱（第 101 題）： go(a.left, b.right) and go(a.right, b.left) ^^^^^^^^^^^^^^^ ^^^^^^^^^^^^^^^ 左對右 右對左 然後對單棵樹呼叫 go(root.left, root.right)。 【一模一樣的骨架，只改了兩個字。】

追問二：如果要判斷「q 是不是 p 的子樹」呢？

第 572 題。最直接的做法：對 p 的每個節點呼叫一次 isSameTree(節點, q)。時間 O(m × n)。

更快的做法：把兩棵樹都序列化（含空節點記號），然後用 KMP 檢查 q 的序列是不是 p 的子字串 —— O(m + n)。

但要小心：序列化時每個值前面要加分隔符（例如 ,12），否則 12 會錯誤地匹配到 112 的一部分。這是「把樹題轉成字串題」最經典的坑。

追問三：如果節點可以有任意多個孩子（N 元樹）呢？

def isSame(p, q): if not p and not q: return True if not p or not q: return False if p.val != q.val: return False if len(p.children) != len(q.children): return False # 新增的檢查 return all(isSame(a, b) for a, b in zip(p.children, q.children)) 【多了一個「孩子數量要相同」的檢查。】 如果孩子的【順序不重要】（無序樹），問題就難很多 —— 要做「樹的同構判定」， 標準做法是 AHU 演算法（把每棵子樹的簽章排序後往上合併）， 時間仍是 O(n)，但實作複雜得多。

追問四：如果兩棵樹超大，放不進單一台機器呢？

用「樹的雜湊（Merkle tree）」：每個節點的雜湊值 = hash(值, 左子樹雜湊, 右子樹雜湊)。

比較兩棵樹只要比較根的雜湊值 —— 而且可以只傳 32 bytes 就判斷完。

如果不同，還能沿著雜湊不同的路徑往下找，快速定位差異在哪 —— Git、IPFS、區塊鏈用的就是這一招。

代價：雜湊碰撞的機率（理論上可能誤判成相同），以及要先把整棵樹算過一遍。
