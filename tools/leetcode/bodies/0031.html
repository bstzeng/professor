Problem

A permutation of an array of integers is an arrangement of its members into a sequence or linear order.

The next permutation of an array of integers is the next lexicographically greater permutation of its integer. If such an arrangement is not possible, the array must be rearranged as the lowest possible order (i.e., sorted in ascending order).

Given an array of integers nums, find the next permutation of nums. The replacement must be in place and use only constant extra memory.

中文翻譯

一個整數陣列的排列，就是把它的元素排成某個順序。

下一個排列指的是：在所有排列按字典序排好之後，緊接在目前這個排列後面的那一個。如果目前已經是最大的排列（完全遞減），就把它變成最小的排列（升序）。

請原地修改 nums，而且只能用常數額外空間。

先用小例子建立直覺

[1,2,3] 的所有排列按字典序排： 123 -> 132 -> 213 -> 231 -> 312 -> 321 -> (回到 123) 觀察每一次「進位」發生了什麼： 123 -> 132 ：最後兩位交換（3 和 2） 132 -> 213 ：從右邊找不到可以小幅調整的了， 只好動第 0 位：1 換成 2，後面補最小 -> 213 231 -> 312 ：同理，2 換成 3，後面補最小 -> 312 321 -> 123 ：已經是最大，整個重來 這很像十進位數字加一： 從個位開始往上找「還能變大的那一位」， 把它變大一點點，然後後面全部歸零（變成最小）。 差別在於：這裡不能隨便填，只能用手上現有的數字重排。

範例

範例 1 輸入：nums = [1,2,3] 輸出：[1,3,2] 範例 2 輸入：nums = [3,2,1] 輸出：[1,2,3] 說明：已經是最大的排列，回到最小。 範例 3 輸入：nums = [1,1,5] 輸出：[1,5,1]

限制條件

  • 1 ≤ nums.length ≤ 100
  • 0 ≤ nums[i] ≤ 100

LeetCode 原題

先看懂限制在說什麼

  • 值可以重複（[1,1,5]）。這會影響第 2 步的比較要用 <= 還是 < —— 見下面的說明。
  • 必須原地、常數空間。所以不能「生成所有排列再找下一個」（那是 O(n!)），也不能複製一份陣列出來排序。
  • 長度可以是 1。此時只有一種排列，答案就是它自己。程式要能正確處理（第 1 步找不到下降點，第 3 步反轉長度 1 的區段，等於沒動）。

解題思路

三個步驟，每一步都有明確的理由。

解法

找下降點 → 交換 → 反轉尾段（唯一解）

class Solution: def nextPermutation(self, nums: List[int]) -> None: n = len(nums) # 第 1 步：從右往左找第一個「下降點」i，滿足 nums[i] < nums[i+1] i = n - 2 while i >= 0 and nums[i] >= nums[i + 1]: i -= 1 # 第 2 步：若找到了，在 i 右邊找「剛好比 nums[i] 大」的最小值，交換 if i >= 0: # i 右邊是非遞增的，所以從右往左第一個 > nums[i] 的就是答案 j = n - 1 while nums[j] <= nums[i]: j -= 1 nums[i], nums[j] = nums[j], nums[i] # 第 3 步：把 i 右邊反轉（從非遞增變成非遞減 = 最小） # 若第 1 步沒找到（i == -1），整個反轉 -> 回到最小的排列 left, right = i + 1, n - 1 while left < right: nums[left], nums[right] = nums[right], nums[left] left += 1 right -= 1

步驟 1：為什麼要找「從右往左第一個下降點」？

設 i 是「最右邊」滿足 nums[i] < nums[i+1] 的位置。 這表示 nums[i+1..n-1] 這一段是「非遞增」的 （否則會有更右邊的下降點）。 非遞增 = 這一段已經是它自己所有排列裡「最大」的那個 = 光動這一段沒辦法變得更大 所以「要變大」就一定得動到 nums[i] 或更左邊。 而我們要的是「下一個」（最小的變大）， 所以動到的位置要「越右邊越好」-> 就是 i。 例：[1,5,4,7,6,5,3,1] 從右往左：1<3? 否。3<5? 否。5<6? 否。6<7? 否。7>4 -> i 指向 4 所以 i = 2（值 4），右邊 [7,6,5,3,1] 是非遞增的 ✔

步驟 2：為什麼從右往左找第一個 > nums[i] 的？

我們要把 nums[i] 換成「右邊比它大的數裡，最小的那一個」。 因為 nums[i+1..] 是「非遞增」的， 從右往左掃的時候數字是「非遞減」的， 所以第一個碰到的 > nums[i] 的，就是「大於 nums[i] 的最小值」。 [7, 6, 5, 3, 1]，要找 > 4 的最小值 從右往左：1 ✘ 3 ✘ 5 ✔ -> 就是 5 不需要排序，也不需要二分 —— 單調性已經送給我們了。 為什麼條件寫 nums[j] <= nums[i] 而不是 <？ 因為要找「嚴格大於」nums[i] 的。 遇到相等的要繼續往左走。 [1, 5, 1]：i = 0（1 < 5）， 從右往左找 > 1 的：nums[2]=1 <= 1 跳過，nums[1]=5 > 1 ✔ 交換 -> [5, 1, 1]，反轉後面 -> [5, 1, 1] 如果誤寫成 <，j 會停在 nums[2]=1， 交換後還是 [1,5,1]，完全沒變。

步驟 3：為什麼交換之後直接反轉就對了？

關鍵引理：交換之後，nums[i+1..] 仍然是「非遞增」的。 為什麼？ 原本 nums[i+1..] 非遞增，而 nums[j] 是「> nums[i] 的最小值」。 換進去的 nums[i]（舊值）滿足： nums[j-1] >= nums[j] > nums[i] >= nums[j+1] （最後一個不等式：因為 j 是從右往左「第一個」> nums[i] 的， 所以 j 右邊的全都 <= nums[i]） 把 nums[i] 放到位置 j，剛好塞在正確的位置上， 非遞增的性質完好無損。 既然它是非遞增（= 最大的排法）， 我們要「後面補最小」， 反轉一下就變成非遞減（= 最小的排法）。 不需要排序！反轉是 O(n)，排序是 O(n log n)。

步驟 1 找不到下降點的情況

表示整個陣列是非遞增的（例如 [3,2,1]），已經是最大的排列。此時 i == -1，第 2 步被 if i >= 0 跳過，第 3 步的 left = i + 1 = 0 —— 整個陣列反轉，剛好變成最小的排列。一個變數同時處理了正常情況和邊界情況，非常漂亮。

複雜度說明
時間O(n)最多掃三遍
空間O(1)只用幾個下標

解法對照

步驟做什麼為什麼複雜度
1. 找下降點 i從右往左找 nums[i] < nums[i+1]i 右邊非遞增 = 已是最大，必須動 iO(n)
2. 找 j 並交換從右往左找第一個 > nums[i]非遞增保證它是「大於 nums[i] 的最小值」O(n)
3. 反轉 i 右邊頭尾對調把非遞增變成非遞減 = 最小O(n)

這就是 C++ 的 std::next_permutation

C++ 標準庫的 std::next_permutation 就是這個演算法，而且它回傳一個 bool 表示「有沒有繞回最小」。

// C++ 的標準用法：列出所有排列 std::sort(v.begin(), v.end()); // 先排成最小 do { process(v); } while (std::next_permutation(v.begin(), v.end())); 先排序很重要 —— 否則會從中間開始，繞一圈就停， 漏掉字典序比初始值小的那些排列。 Python 沒有內建的 next_permutation， itertools.permutations 是「一次全部生成」， 在 n 大的時候會爆記憶體（除非用它的惰性特性）。

邊界條件檢查清單

  • 已經是最大：[3,2,1] → [1,2,3]。i == -1 的路徑。
  • 單一元素：[1] → [1]。
  • 兩個元素：[1,2] → [2,1]；[2,1] → [1,2]。
  • 有重複值：[1,1,5] → [1,5,1]；[1,5,1] → [5,1,1]。步驟 2 的 <= 寫成 < 會在這裡出錯。
  • 全部相同：[2,2,2] → [2,2,2]。找不到下降點，反轉後還是一樣。
  • 只有最後兩個要換：[1,2,3] → [1,3,2]。i 在倒數第二格。
  • 複雜的情況：[5,4,7,5,3,2] → [5,5,2,3,4,7]。

常見追問

追問一：怎麼求「上一個排列」？

把所有比較反過來就好：

  • 步驟 1 找 nums[i] > nums[i+1]（上升點變下降點）
  • 步驟 2 找從右往左第一個 < nums[i] 的
  • 步驟 3 一樣反轉

這就是 C++ 的 std::prev_permutation。

追問二：怎麼求「第 k 個排列」？

不需要跑 k 次 next_permutation（那是 O(k·n)）。用階乘進位制（factorial number system）可以 O(n²) 直接算出來：第一位是 k // (n-1)! 個候選，然後 k %= (n-1)!，遞迴下去。這是第 60 題（Permutation Sequence）。

追問三：這個演算法的名字和歷史？

一般叫做 Narayana Pandita 演算法，最早記載於 14 世紀印度數學家 Narayana Pandita 的著作。同樣的想法在 17 世紀被歐洲的變位鐘（change ringing）傳統重新發現。它是最古老、仍在標準庫裡日日運行的演算法之一。
