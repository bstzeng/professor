Problem

You are given a large integer represented as an integer array digits, where each digits[i] is the i-th digit of the integer. The digits are ordered from most significant to least significant in left-to-right order.

Increment the large integer by one and return the resulting array of digits.

中文翻譯

給你一個用整數陣列表示的大整數 digits，陣列由高位到低位排列（最左邊是最高位）。

把這個大整數加一，回傳加完之後的陣列。

唯一的難點：進位

加一的三種情況： ① 個位不是 9 [1,2,3] -> [1,2,4] 直接加，收工。 ② 尾巴有一串 9 [1,9,9] -> [2,0,0] 把那串 9 變成 0，然後前面那一位加一。 ③ 全部都是 9 [9,9,9] -> [1,0,0,0] 全部變 0，而且要在最前面補一個 1 —— 陣列變長了！ 情況 ③ 是唯一會改變陣列長度的情況， 也是這題最常被漏掉的地方。 而且它只會發生一次（加一最多讓位數增加 1 位）， 所以不需要迴圈處理。

為什麼不直接轉成整數再加一？因為題目說「大整數」—— 在 C/Java 裡，100 位數遠超任何整數型別。Python 可以（int("".join(...)) + 1），但那完全繞過了題目的用意。

範例

範例 1 輸入：digits = [1,2,3] 輸出：[1,2,4] 說明：123 + 1 = 124 範例 2 輸入：digits = [4,3,2,1] 輸出：[4,3,2,2] 範例 3 輸入：digits = [9] 輸出：[1,0] 說明：9 + 1 = 10，陣列變長了。

限制條件

  • 1 ≤ digits.length ≤ 100
  • 0 ≤ digits[i] ≤ 9
  • digits 不含前導零，除了數字本身就是 0

LeetCode 原題

先看懂限制在說什麼

  • 長度到 100 —— 100 位數，遠超 64 位元整數（約 19 位）。這就是「不能轉成整數」的理由。
  • 沒有前導零（除了 [0] 本身）。所以輸出也不該有前導零 —— 只有情況 ③ 會在最前面加 1，那不是前導零。
  • [0] 是合法輸入 → 輸出 [1]。

解題思路

從最低位往前掃，遇到 9 就變 0 繼續，遇到非 9 就加一收工。如果掃完了還在進位，表示全是 9，在最前面補 1。

解法一

從後往前掃，提早退出（最短）

class Solution: def plusOne(self, digits: List[int]) -> List[int]: # 從個位往前掃：不是 9 就加一收工，是 9 就變 0 繼續進位 for i in range(len(digits) - 1, -1, -1): if digits[i] < 9: digits[i] += 1 return digits digits[i] = 0 # 走到這裡表示全部都是 9（例如 999 -> 000） return [1] + digits

為什麼「不是 9 就可以直接 return」？

因為加一最多只產生一個進位。 如果 digits[i] < 9，那 digits[i] + 1 <= 9， 不會產生新的進位 —— 所以前面的位數完全不受影響，直接收工。 這讓大部分情況只跑一次迴圈： [1,2,3] -> i = 2，3 < 9，加一，return （只跑 1 次） [1,9,9] -> i=2 是 9、i=1 是 9、i=0 是 1 < 9 （跑 3 次） 平均來說，有 90% 的機率個位不是 9， 所以這個解法的期望執行次數大約是 1.11 次 —— 非常接近 O(1)。

最後那一行 return [1] + digits

走到這裡表示迴圈跑完了都沒有 return，也就是每一位都是 9，而且都已經被設成 0。此時只要在最前面補一個 1 就對了。

[9,9,9] i=2: 9 -> 0 i=1: 9 -> 0 i=0: 9 -> 0 迴圈結束，digits = [0,0,0] return [1] + [0,0,0] = [1,0,0,0] ✔ 注意 [1] + digits 會建一個新 list（O(n)）。 如果要「原地」做，可以用 digits.insert(0, 1)， 但那在 Python 裡也是 O(n)（要搬移所有元素）。 C++ 的 vector 也一樣 —— 在前面插入是 O(n)。 如果這個操作很頻繁，應該考慮用 deque 或「反著存」。
複雜度說明
時間O(n) 最壞，平均 O(1)90% 的情況只跑一次
空間O(1)原地修改；只有全 9 時才建新陣列
解法二

標準進位寫法（更容易推廣）

class Solution: def plusOne(self, digits: List[int]) -> List[int]: # 標準的「進位」寫法，比較容易推廣到「加上任意數」 carry = 1 for i in range(len(digits) - 1, -1, -1): total = digits[i] + carry digits[i] = total % 10 carry = total // 10 if carry == 0: break if carry: digits.insert(0, carry) return digits

這是大數加法的標準骨架：total = 這一位 + 進位、這一位 = total % 10、進位 = total // 10。

優點：把 carry = 1 換成任意值，就變成「加上任意數」；再加一個迴圈變數就變成「兩個大數相加」（第 415 題）。可重用性遠高於解法一。

if carry == 0: break 是效能優化 —— 沒有它也對，只是會白跑完剩下的位數。

缺點：比解法一長。在只做「加一」的場合是過度設計。

複雜度說明
時間O(n)同上
空間O(1)原地修改

邊界條件檢查清單

  • 不進位：[1,2,3] → [1,2,4]。
  • 單一個 9：[9] → [1,0]。
  • 全是 9：[9,9] → [1,0,0]。陣列變長。
  • 尾巴有 9：[1,9] → [2,0]。
  • 中間有 9：[9,8,9] → [9,9,0]。只進一位。
  • 零：[0] → [1]。
  • 最長：100 個 9 → 101 位。

常見追問

追問一：如果要加上任意一個數 k 呢？

把 carry = 1 換成 carry = k。其餘完全不用改 —— 因為 total // 10 會自動處理多位數的進位。

[9, 9] 加上 123： carry = 123 i=1: total = 9 + 123 = 132 -> digits[1] = 2, carry = 13 i=0: total = 9 + 13 = 22 -> digits[0] = 2, carry = 2 迴圈結束，carry = 2 -> insert(0, 2) 結果 [2, 2, 2] = 222 ✔（99 + 123 = 222） 但如果 carry 是多位數，insert(0, carry) 就不對了 —— 要把 carry 拆成多位再插入。 所以「加上任意數」的完整版還要多幾行。

追問二：如果是「減一」呢？

對稱的邏輯：從後往前掃，不是 0 就減一收工，是 0 就變 9 繼續借位。但多一個麻煩：結果可能有前導零（[1,0,0] - 1 = [0,9,9]，應該輸出 [9,9]），所以最後要去掉前導零。減法通常比加法麻煩，因為它會「縮短」而加法只會「變長」。

追問三：為什麼陣列要「高位在前」？

因為那是人類閱讀的順序（123 就是 [1,2,3]）。但對運算來說，「低位在前」比較方便 —— 進位是往高位傳的，如果低位在前，進位就是往陣列的後面傳，而且「變長」變成 append（O(1)）而不是 insert(0, ...)（O(n)）。

所以真正的大數函式庫（GMP、Python 的 int）內部都是「低位在前」存的，只在輸出時才反轉。「內部表示」和「外部表示」可以不同 —— 這是一個很重要的設計觀念。
