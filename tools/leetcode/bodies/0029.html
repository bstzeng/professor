Problem

Given two integers dividend and divisor, divide two integers without using multiplication, division, and mod operator.

The integer division should truncate toward zero, which means losing its fractional part. For example, 8.345 would be truncated to 8, and -2.7335 would be truncated to -2.

Return the quotient. If the quotient is strictly greater than 2³¹ - 1, return 2³¹ - 1; if less than -2³¹, return -2³¹.

中文翻譯

給你兩個整數 dividend（被除數）和 divisor（除數），在不使用乘法、除法和取餘運算子的前提下做整數除法。

結果要向零取整（截斷小數部分）。例如 8.345 截斷成 8，-2.7335 截斷成 -2（不是 −3）。

回傳商。如果商大於 2³¹ − 1 就回 2³¹ − 1，小於 −2³¹ 就回 −2³¹。

三個陷阱，一個比一個隱蔽

陷阱 1：溢位。而且只有「一種」情況會溢位。 -2³¹ / -1 = 2³¹ = 2147483648 > INT_MAX = 2147483647 其他所有組合的商都在範圍內： 任何數除以 |divisor| >= 1 只會變小或不變， 而 dividend 本身一定在範圍內。 唯一的例外就是「最負的數 ÷ -1」，因為正負兩側不對稱。 陷阱 2：向零取整，不是向下取整。 -7 / 3 -> -2 （不是 -3！） 7 / -3 -> -2 Python 的 // 是「向下取整（floor）」： -7 // 3 == -3 ✘ 和題目要的不一樣 Python 的 int() 對浮點數是向零截斷，但不能用除法。 正確做法：取絕對值算、最後補上符號。 abs(-7) // abs(3) = 2，異號 -> -2 ✔ 陷阱 3：Python 沒有 32 位元整數。 在 C/Java 裡，abs(INT_MIN) 本身就會溢位。 標準做法是「全程用負數算」，因為負數那一側範圍比較大。 Python 沒這個問題，但面試官可能會問。

範例

範例 1 輸入：dividend = 10, divisor = 3 輸出：3 說明：10 / 3 = 3.333... 截斷成 3。 範例 2 輸入：dividend = 7, divisor = -3 輸出：-2 說明：7 / -3 = -2.333... 向零截斷成 -2（不是 -3）。

限制條件

  • −2³¹ ≤ dividend, divisor ≤ 2³¹ − 1
  • divisor != 0（不用處理除以零）

LeetCode 原題

先看懂限制在說什麼

  • 保證 divisor 不是 0，省掉一個邊界。
  • 只有 INT_MIN / -1 會溢位。所以「clamp 到範圍內」實際上只要寫一個 if。很多人會寫一大串 min/max，那是沒想清楚。
  • 不能用 *、/、%。但可以用位移 << >>、加減、比較 —— 而位移就是乘除 2 的冪次。這就是這題的解法方向。

解題思路

除法的本質是「減多少次」。一次減一個太慢，所以改成一次減掉「除數的 2 的冪次倍」 —— 這正是我們小學學的直式除法，只是換成二進位。

解法一

一次減一個（會 TLE 的基準線）

class Solution: def divide(self, dividend: int, divisor: int) -> int: INT_MIN, INT_MAX = -2**31, 2**31 - 1 # 唯一會溢位的情況：-2^31 / -1 = 2^31，超過 INT_MAX if dividend == INT_MIN and divisor == -1: return INT_MAX negative = (dividend < 0) != (divisor < 0) # 異號才是負的 a, b = abs(dividend), abs(divisor) quotient = 0 while a >= b: # 一次減一個 b —— 正確但會 TLE a -= b quotient += 1 return -quotient if negative else quotient

邏輯完全正確，但當 dividend = 2³¹ − 1、divisor = 1 時，要跑 21 億次迴圈 —— 必定 TLE。

但它的前兩行（溢位檢查、符號處理）在後面兩個解法裡完全一樣，所以先把它寫對是有價值的。

複雜度說明
時間O(dividend / divisor)最壞 2³¹ 次
空間O(1)幾個變數
解法二

倍增：每次減掉「盡可能大」的一塊

既然一次減一個太慢，那就一次減掉 divisor 的 2 的冪次倍。而 b × 2ᵏ 用位移就能算出來，不算乘法。

class Solution: def divide(self, dividend: int, divisor: int) -> int: INT_MIN, INT_MAX = -2**31, 2**31 - 1 if dividend == INT_MIN and divisor == -1: return INT_MAX negative = (dividend < 0) != (divisor < 0) a, b = abs(dividend), abs(divisor) quotient = 0 while a >= b: # 找出最大的 k，使得 b << k 仍然 <= a temp, multiple = b, 1 while a >= (temp << 1): temp <<= 1 # temp 翻倍 multiple <<= 1 # 對應的商也翻倍 a -= temp quotient += multiple return -quotient if negative else quotient
43 ÷ 3 外層第 1 輪（a = 43）： temp = 3, multiple = 1 43 >= 6? ✔ -> temp = 6, multiple = 2 43 >= 12? ✔ -> temp = 12, multiple = 4 43 >= 24? ✔ -> temp = 24, multiple = 8 43 >= 48? ✘ 停 a = 43 - 24 = 19，quotient = 8 外層第 2 輪（a = 19）： temp = 3, multiple = 1 19 >= 6? ✔ -> temp = 6, multiple = 2 19 >= 12? ✔ -> temp = 12, multiple = 4 19 >= 24? ✘ 停 a = 19 - 12 = 7，quotient = 12 外層第 3 輪（a = 7）： 7 >= 6? ✔ -> temp = 6, multiple = 2 7 >= 12? ✘ 停 a = 7 - 6 = 1，quotient = 14 a = 1 < 3，結束。答案 14 ✔

為什麼是 O(log²n)？

外層每輪至少把 a 砍掉一半（因為減掉的 temp 至少是 a 的一半），所以外層最多 32 輪；內層的倍增也最多 32 次。總共 O(log² n) —— 大約 1024 次運算，瞬間完成。

注意內層條件是 a >= (temp << 1) 而不是 a >= temp。我們要找的是「翻倍之後還不會超過」的最大值，所以要先試探翻倍後的結果。寫錯的話 temp 會超過 a，減出負數。

複雜度說明
時間O(log²n)外層 log n 輪 × 內層 log n
空間O(1)幾個變數
解法三

二進位長除法（最乾淨）

把解法二的兩層迴圈攤平成一層：直接從第 31 位往下問「這一位的商能不能是 1？」

class Solution: def divide(self, dividend: int, divisor: int) -> int: INT_MIN, INT_MAX = -2**31, 2**31 - 1 if dividend == INT_MIN and divisor == -1: return INT_MAX negative = (dividend < 0) != (divisor < 0) a, b = abs(dividend), abs(divisor) # 從高位往低位試：這一位能不能填 1？ # 就是長除法（直式除法）的二進位版本 quotient = 0 for k in range(31, -1, -1): if (b << k) <= a: a -= b << k quotient |= 1 << k return -quotient if negative else quotient

這就是我們小學學的直式除法，只是基底從 10 換成 2。十進位的直式除法每一位要試 0–9（十選一），二進位每一位只要試 0 或 1（能減就是 1，不能就是 0）—— 這正是為什麼電腦用二進位做除法比較簡單。

43 ÷ 3，從 k = 31 開始（前面全是 0，略過） k=5: 3<<5 = 96 > 43 -> 商的第 5 位 = 0 k=4: 3<<4 = 48 > 43 -> 第 4 位 = 0 k=3: 3<<3 = 24 <= 43 -> 第 3 位 = 1，a = 43-24 = 19 k=2: 3<<2 = 12 <= 19 -> 第 2 位 = 1，a = 19-12 = 7 k=1: 3<<1 = 6 <= 7 -> 第 1 位 = 1，a = 7-6 = 1 k=0: 3<<0 = 3 > 1 -> 第 0 位 = 0 商 = 0b001110 = 14，餘 = 1 驗算：14 × 3 + 1 = 43 ✔

固定 32 輪，不管數字多大 —— 複雜度是 O(32) = O(1)。而且沒有巢狀迴圈，最好讀也最好記。

在 C/Java 裡要注意什麼？

b << k 在 32 位元裡可能溢位！ C/Java 的正確寫法是反過來比： if ((a >>> k) >= b) // 無號右移，避免符號位問題 a -= b << k; 或者全程用 long（64 位元）來算 b << k。 Python 沒有這個問題（整數任意精度）， 但如果面試官問「這段翻成 C 會怎樣」， 要能指出這一行。
複雜度說明
時間O(32) = O(1)固定 32 輪
空間O(1)幾個變數

邊界條件檢查清單

  • INT_MIN / -1 → INT_MAX。唯一會溢位的組合，一定要單獨擋。
  • INT_MIN / 1 → INT_MIN。不溢位，不能被上面那個 if 誤攔。
  • 被除數是 0：(0, 5) → 0。while 一次都不跑。
  • 除數比被除數大：(1, 2) → 0。
  • 剛好整除：(6, 3) → 2。
  • 負數的向零取整：(7, -3) → −2（不是 −3）；(-7, 3) → −2；(-7, -3) → 2。四種符號組合都要測。
  • 除以 1 和 −1：(2147483647, 1) → 2147483647。這是解法一 TLE 的測資。

常見追問

追問一：如果還要回傳餘數呢？

解法三跑完之後，a 裡剩下的就是餘數（絕對值）。符號依照語言慣例：C99 和 Java 的 % 結果跟被除數同號，Python 的 % 跟除數同號。-7 % 3 在 C 裡是 −1，在 Python 裡是 2。這個差別在跨語言移植時害過很多人。

追問二：CPU 是怎麼做除法的？

本質上就是解法三 —— 硬體版的「回復餘數法（restoring division）」或它的改良版「不回復餘數法（non-restoring division）」，一個時脈週期算一位。這也是為什麼整數除法比乘法慢很多（在現代 x86 上，乘法約 3–5 個週期，除法約 20–40 個）。

編譯器知道這一點，所以看到「除以常數」時會把它改寫成乘法 + 位移。例如 x / 3 會被編譯成大約 (x * 0xAAAAAAAB) >> 33 —— 用一個「魔術數字」（1/3 的定點數近似）的乘法取代除法。這個技巧叫做 Barrett reduction / magic number division。

追問三：如果不准用減法呢？

那就只剩位元運算了。加法可以用 XOR（不進位加）和 AND + 左移（進位）遞迴實作；減法是「加上二補數」。這就是第 371 題（Sum of Two Integers）。把那題和這題組合起來，就能在只用位元運算的前提下做除法。
