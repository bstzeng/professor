Problem

Given an absolute path for a Unix-style file system, which begins with a slash '/', transform this path into its simplified canonical path.

The rules are: a single period '.' represents the current directory; a double period '..' represents the previous directory (going one level up); multiple consecutive slashes are treated as a single slash. Any sequence of periods that is not '.' or '..' (e.g. '...') is treated as a valid directory name.

The canonical path must start with '/', have directories separated by a single '/', and must not end with '/' (unless it is the root).

中文翻譯

給你一個 Unix 風格的絕對路徑（以 '/' 開頭），把它化簡成標準路徑（canonical path）。

規則：'.' 表示當前目錄；'..' 表示回上一層；連續的多個 '/' 視為一個；任何「不是 . 也不是 ..」的點序列（例如 '...'）都是合法的目錄名。

標準路徑必須以 '/' 開頭、目錄之間只用一個 '/' 分隔、而且結尾不能有 '/'（除非它就是根目錄）。

為什麼是堆疊？

路徑是一個「進入／退出」的巢狀結構： 進入一個目錄 -> push 回到上一層 -> pop 這正是堆疊的定義。 四種路徑片段的處理： "" 連續斜線或開頭／結尾的斜線 -> 忽略 "." 當前目錄 -> 忽略 ".." 上一層 -> pop（堆疊空了就什麼都不做） 其他 目錄名 -> push 第四種要特別注意： "..." 是合法的目錄名！（不是 ".." 也不是 "."） "...." 也是 "..a" 也是 只有「剛好兩個點」才是「上一層」。 很多人用 startswith("..") 判斷，那會把 "..." 誤判 ✘

「根目錄的 .. 停在根目錄」是 Unix 的實際行為 —— cd /.. 之後你還在 /。所以 pop 之前要檢查堆疊是不是空的。

範例

範例 1 輸入：path = "/home/" 輸出："/home" 說明：結尾的斜線要去掉。 範例 2 輸入：path = "/../" 輸出："/" 說明：根目錄的上一層還是根目錄。 範例 3 輸入：path = "/home//foo/" 輸出："/home/foo" 說明：連續的斜線視為一個。 範例 4 輸入：path = "/a/./b/../../c/" 輸出："/c" 範例 5 輸入：path = "/..." 輸出："/..." 說明："..." 是合法的目錄名，不是「上兩層」。

限制條件

  • 1 ≤ path.length ≤ 3000
  • path 只含英文字母、數字、'.'、'/'、'_'
  • path 是一個有效的絕對 Unix 路徑（一定以 '/' 開頭）

LeetCode 原題

五個容易踩的坑

  • "..." 是目錄名，不是「上兩層」。只有剛好兩個點才是 ..。
  • 根目錄的 .. 要停住："/../../../" → "/"，不能 pop 空堆疊。
  • 結果為空時要輸出 "/"。"/" + "/".join([]) = "/" + "" = "/" ✔ —— 這個公式自然就對了，不用特判。
  • 結尾不能有斜線："/home/" → "/home"。用 "/".join 天然不會產生尾隨斜線。
  • 連續斜線：split("/") 會產生空字串，要過濾掉。

解題思路

解法一

split + 堆疊（最推薦）

class Solution: def simplifyPath(self, path: str) -> str: stack = [] # split("/") 會自動把 "a//b" 切成 ['a', '', 'b']，空字串代表連續斜線 for part in path.split("/"): if part == "" or part == ".": continue # 空的或「當前目錄」-> 忽略 if part == "..": if stack: stack.pop() # 回上一層；已經在根目錄就什麼都不做 else: stack.append(part) # 一般的目錄名（含 "..." 這種） return "/" + "/".join(stack)

path.split("/") 的行為

"/a/./b/../../c/".split("/") -> ['', 'a', '.', 'b', '..', '..', 'c', ''] 注意： - 開頭的 "/" 產生一個空字串 - 結尾的 "/" 也產生一個空字串 - 連續的 "//" 會產生中間的空字串 "/home//foo/".split("/") -> ['', 'home', '', 'foo', ''] 所以「忽略空字串」這一條，同時處理了 「開頭斜線」「結尾斜線」「連續斜線」三件事。 （注意這裡用的是 split("/")，帶參數版本。 和第 58 題不同 —— 那題要用不帶參數的 split() 來忽略連續空白。 兩種 split 的語意不同，要看清楚需求。）

最後一行的巧妙之處

return "/" + "/".join(stack) stack = ["home", "foo"] -> "/" + "home/foo" = "/home/foo" ✔ stack = ["c"] -> "/" + "c" = "/c" ✔ stack = [] -> "/" + "" = "/" ✔ 三種情況（多層、單層、根目錄）都被同一個公式涵蓋， 而且天然不會產生尾隨斜線。 不用任何 if —— 這是「讓邊界自然落在公式裡」的好例子。

複雜度 O(n)：split 是 O(n)，迴圈是 O(片段數)，join 是 O(n)。

複雜度說明
時間O(n)掃一遍
空間O(n)堆疊 + 切出來的片段
解法二

手動掃描（不用 split）

如果語言沒有好用的 split（例如 C），或者想避免建那個中間 list，就手動掃描。

class Solution: def simplifyPath(self, path: str) -> str: # 不用 split，手動掃描（在沒有 split 的語言裡就得這樣寫） stack = [] i, n = 0, len(path) while i < n: while i < n and path[i] == "/": i += 1 # 跳過連續的斜線 j = i while j < n and path[j] != "/": j += 1 # 取出一段名稱 part = path[i:j] i = j if part == "" or part == ".": continue if part == "..": if stack: stack.pop() else: stack.append(part) return "/" + "/".join(stack)

雙指標分段的骨架

while i < n: while i < n and path[i] == "/": # 跳過所有斜線 i += 1 j = i while j < n and path[j] != "/": # 取出一段名稱 j += 1 part = path[i:j] i = j ...處理 part... 這個「跳過分隔符 + 取出一段」的骨架， 就是手寫 tokenizer 的最基本形式。 它自然處理了連續斜線（第一個 while 會一路跳過）， 所以 part 永遠不會是空字串 （除非 i == n，此時 part 是空的，被 continue 擋掉）。 好處：不建中間的 list，空間只有堆疊。 壞處：長很多，而且兩個 while 的邊界要小心。

在 Python 裡沒有理由用這個版本，但如果面試官問「不用內建函式呢」，這就是答案。

複雜度說明
時間O(n)掃一遍
空間O(n)只有堆疊

邊界條件檢查清單

  • 根目錄："/" → "/"。
  • 結尾斜線："/home/" → "/home"。
  • 根目錄的上一層："/../"、"/../../../" → "/"。
  • 連續斜線："/home//foo/" → "/home/foo"。
  • 三個點："/..." → "/..."。用 startswith("..") 判斷會錯。
  • 以點開頭的隱藏檔："/..hidden" → "/..hidden"。同上。
  • 全部被抵銷："/a/../../b/../c//.//" → "/c"。
  • 複雜的混合："/a//b////c/d//././/.." → "/a/b/c"。

常見追問

追問一：如果是相對路徑（不以 / 開頭）呢？

麻煩得多。相對路徑開頭的 .. 不能被丟掉 —— "../a" 化簡後還是 "../a"。

做法：用一個計數器記「有幾個還沒被抵銷的 ..」 for part in path.split("/"): if part in ("", "."): continue if part == "..": if stack and stack[-1] != "..": stack.pop() else: stack.append("..") # 相對路徑才需要這一行 else: stack.append(part) return "/".join(stack) or "." "a/../../b" -> ["..", "b"] -> "../b" ✔ "a/.." -> [] -> "." ✔（空路徑要輸出 "."） Python 的 os.path.normpath 就是這樣做的。

追問二：真實的 realpath 和這題有什麼不同？

本題（以及 Python 的 os.path.normpath）是【純字串操作】—— 它不碰檔案系統。 真實的 realpath(3) 會： 1. 解析【符號連結（symlink）】 這是關鍵差異！如果 /a/b 是一個指向 /x/y 的 symlink， 那 /a/b/.. 的答案是 /x（不是 /a）。 所以純字串的化簡「在有 symlink 時是錯的」。 2. 檢查每一層是否真的存在、是否有權限 3. 處理掛載點、/proc 這類特殊檔案系統 這就是為什麼 shell 裡 cd .. 的行為 和 pwd -P（物理路徑）可能不一樣： cd 預設用「邏輯路徑」（純字串化簡）， pwd -P 會真的去解析 symlink。 本題考的是「邏輯路徑」的化簡。

追問三：這題的安全意義是什麼？

路徑穿越（path traversal）攻擊。如果一個網站讓使用者指定檔名，而沒有做路徑化簡，攻擊者就能用 ../../../etc/passwd 讀到不該讀的檔案。

正確的防禦：

  • 先化簡，再檢查是否還在允許的目錄底下（而不是「先檢查有沒有 ..」—— 那會被 URL 編碼、Unicode 正規化、或 ....// 這類技巧繞過）
  • 用作業系統提供的 realpath（會解析 symlink），而不是純字串化簡
  • 最後再確認一次結果的前綴是允許的根目錄

「先正規化，再驗證」是所有輸入驗證的通則 —— 反過來（先驗證再正規化）幾乎總是可以被繞過。
