Problem

Given an integer array nums, find the subarray with the largest sum, and return its sum.

A subarray is a contiguous non-empty sequence of elements within an array.

Follow up: If you have figured out the O(n) solution, try coding another solution using the divide and conquer approach.

中文翻譯

給你一個整數陣列 nums，找出和最大的連續子陣列，回傳它的和。

子陣列指的是陣列裡連續且非空的一段。

進階：如果你已經想出 O(n) 的解，試著再用分治法寫一個。

「非空」這兩個字很重要

如果允許空子陣列，全負的輸入答案就是 0（什麼都不選）。 題目說「非空」，所以： nums = [-2, -1] -> 答案是 -1（選最大的那個），不是 0 這就是為什麼 best 的初值要是 nums[0]，不能是 0。 best = 0 的寫法在 [-2, -1] 上會回傳 0 ✘ best = nums[0] 的寫法回傳 -1 ✔ 這是本題第一名的 bug，而且「全正數」的測資抓不出來。

核心洞察（Kadane 演算法）：走到位置 i 時，「以 i 結尾的最大子陣列」只有兩種可能 —— 接上前面那一段，或從 i 自己重新開始。而「什麼時候該重新開始？」的答案是：當前面那一段的和是負的時候（負數只會拖累，不如丟掉）。

範例

範例 1 輸入：nums = [-2,1,-3,4,-1,2,1,-5,4] 輸出：6 說明：子陣列 [4,-1,2,1] 的和是 6，最大。 範例 2 輸入：nums = [1] 輸出：1 範例 3 輸入：nums = [5,4,-1,7,8] 輸出：23 說明：整個陣列。

限制條件

  • 1 ≤ nums.length ≤ 10⁵
  • −10⁴ ≤ nums[i] ≤ 10⁴

LeetCode 原題

先看懂限制在說什麼

  • n 到 10⁵。O(n²) 是 10¹⁰ —— 必定 TLE。要 O(n)。
  • 陣列至少有一個元素，所以 nums[0] 一定存在，可以安全地當初值。
  • 有負數，而且可能全是負數。配上「非空」的要求，就是這題最大的陷阱。
  • 總和最大 10⁵ × 10⁴ = 10⁹，在 32 位元整數範圍內（剛好），但在 C/Java 裡值得留意。

解題思路

解法一

Kadane 演算法（標準解）

class Solution: def maxSubArray(self, nums: List[int]) -> int: best = cur = nums[0] for x in nums[1:]: # 關鍵抉擇：是「接上前面那一段」還是「從自己重新開始」？ cur = max(x, cur + x) best = max(best, cur) return best

一行轉移式的三種讀法

cur = max(x, cur + x) 讀法 1（選擇）： 「以 x 結尾的最大和」= max(只要 x 自己, 接上前面那一段) 讀法 2（丟棄）： 等價於 cur = x + max(0, cur) 「前面那段如果是負的，就當它不存在」 讀法 3（重啟）： if cur < 0: cur = 0 # 重新開始 cur += x 三種寫法完全等價，挑一個你覺得最直覺的記。 為什麼「前面那段是負的就丟掉」是對的？ 設前面那段的和是 S。 - S >= 0：帶著它只會讓總和變大（或不變），留著。 - S < 0：帶著它一定讓總和變小，不如從 x 重新開始。 這是一個「局部決定就足夠」的貪婪 —— 而它之所以正確，是因為子陣列必須「連續」： 要接上前面，就必須把「整段」都接上，不能挑著接。

為什麼 best 和 cur 要分開？

cur 是「以目前這一格結尾的最大和」，best 是「到目前為止看過的所有子陣列裡最大的和」。cur 會上上下下，best 只增不減。只用一個變數是這題第二名的 bug。

Kadane 演算法由 Jay Kadane 在 1984 年提出，當時是為了回應 Ulf Grenander 提出的一個影像處理問題（在二維的圖裡找「最大和的矩形區域」）。一維的情況被 Kadane 在幾分鐘內解決 —— 這個故事被 Jon Bentley 寫進了《Programming Pearls》。

複雜度說明
時間O(n)掃一遍
空間O(1)兩個變數
解法二

明確寫成 DP（同一件事，換個說法）

class Solution: def maxSubArray(self, nums: List[int]) -> int: n = len(nums) # dp[i] = 「以 nums[i] 結尾」的最大子陣列和 dp = [0] * n dp[0] = nums[0] for i in range(1, n): dp[i] = max(nums[i], dp[i - 1] + nums[i]) return max(dp)

dp[i] 的定義是「以 nums[i] 結尾的最大子陣列和」—— 不是「前 i 個元素裡的最大子陣列和」。這個「以 i 結尾」的定義是關鍵：它讓轉移只依賴 dp[i-1]。

如果定義成「前 i 個元素裡的最大子陣列和」會怎樣？ 那 dp[i] = max(dp[i-1], 某個以 i 結尾的子陣列和) 但「某個以 i 結尾的子陣列和」本身又要重新算 —— 轉移式不封閉，DP 做不下去。 「以 i 結尾」這個限制，讓子問題之間產生了遞推關係。 這是設計 DP 狀態時最常見的技巧： 加一個「必須用到第 i 個元素」的限制， 讓子問題變得可遞推，最後再對所有 i 取 max。 同樣的手法出現在： 第 300 題 最長遞增子序列（以 i 結尾的最長遞增子序列） 第 152 題 乘積最大子陣列 第 918 題 環形子陣列的最大和

Kadane 就是這個 DP 的滾動陣列版（只留 dp[i-1]），所以空間從 O(n) 降到 O(1)。

複雜度說明
時間O(n)掃一遍
空間O(n)dp 陣列（可壓到 O(1)）
解法三

前綴和的視角

子陣列 nums[i..j] 的和 = prefix[j] − prefix[i-1]。所以「最大子陣列和」= 「對每個 j，找出最小的 prefix[i-1]」。

class Solution: def maxSubArray(self, nums: List[int]) -> int: # 子陣列和 = prefix[j] - prefix[i] # 要讓它最大 -> 對每個 j，減掉「目前為止最小的 prefix」 best = float("-inf") prefix = 0 min_prefix = 0 # prefix[-1] = 0（空前綴） for x in nums: prefix += x best = max(best, prefix - min_prefix) min_prefix = min(min_prefix, prefix) return best
nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4] prefix = [-2, -1, -4, 0, -1, 1, 2, -3, 1] （prefix[-1] = 0，代表空前綴） 對每個 j，答案候選 = prefix[j] - min(prefix[-1..j-1]) j=0: -2 - 0 = -2 min_prefix = min(0, -2) = -2 j=1: -1 - (-2) = 1 min_prefix = -2 j=2: -4 - (-2) = -2 min_prefix = -4 j=3: 0 - (-4) = 4 min_prefix = -4 j=4: -1 - (-4) = 3 min_prefix = -4 j=5: 1 - (-4) = 5 min_prefix = -4 j=6: 2 - (-4) = 6 ✔ min_prefix = -4 j=7: -3 - (-4) = 1 min_prefix = -4 j=8: 1 - (-4) = 5 min_prefix = -4 最大 6 ✔

注意 min_prefix 的初值是 0 而不是 inf。0 代表「空前綴」，也就是「子陣列從索引 0 開始」的情況。而且更新 min_prefix 必須在計算答案之後 —— 否則 prefix[j] - prefix[j] = 0 會變成一個候選答案，對應「空子陣列」，違反「非空」的要求。

這個視角的價值：它能直接推廣到「和最接近 k 的子陣列」（用有序集合找最接近的 prefix）、「和為 k 的子陣列個數」（第 560 題，用雜湊表）、「和至少為 k 的最短子陣列」（第 862 題，用單調佇列）。Kadane 推廣不了這些，前綴和可以。

時間O(n)掃一遍
空間O(1)三個變數
解法四

分治法（題目的進階要求）

把陣列從中間切開。最大子陣列只有三種可能：完全在左半、完全在右半、或跨過中線。

class Solution: def maxSubArray(self, nums: List[int]) -> int: def solve(lo: int, hi: int): """回傳 (區間總和, 最大前綴和, 最大後綴和, 最大子陣列和)""" if lo == hi: v = nums[lo] return (v, v, v, v) mid = (lo + hi) // 2 ls, lpre, lsuf, lbest = solve(lo, mid) rs, rpre, rsuf, rbest = solve(mid + 1, hi) total = ls + rs pre = max(lpre, ls + rpre) # 最大前綴：只在左邊，或跨過整個左邊 suf = max(rsuf, rs + lsuf) # 最大後綴：只在右邊，或跨過整個右邊 best = max(lbest, rbest, lsuf + rpre) # 三種：全左、全右、跨中線 return (total, pre, suf, best) return solve(0, len(nums) - 1)[3]

為什麼要回傳四個值？

只回傳「最大子陣列和」是不夠的 —— 因為「跨中線」的情況需要「左半的最大後綴」和「右半的最大前綴」。 而「最大前綴／後綴」在合併時又需要「區間總和」。 所以一次回傳四個值： total 區間總和 合併：ls + rs pre 最大前綴和 合併：max(lpre, ls + rpre) suf 最大後綴和 合併：max(rsuf, rs + lsuf) best 最大子陣列和 合併：max(lbest, rbest, lsuf + rpre) ^^^^^^^^^^^^^ 跨中線 「最大前綴」的兩種可能： 只在左半裡（lpre）， 或者「吃掉整個左半」再加上右半的最大前綴（ls + rpre）。 這種「為了能合併，多回傳幾個輔助值」的技巧， 在線段樹（segment tree）裡非常常見 —— 事實上，這四個值構成的就是一個可以放進線段樹的「幺半群（monoid）」。

複雜度

T(n) = 2T(n/2) + O(1)，由主定理得 O(n)… 等等，其實是 O(n) 沒錯 —— 因為合併只花 O(1)（不像 merge sort 要 O(n)）。但遞迴本身有 O(n) 個節點，所以總共 O(n) 時間、O(log n) 空間（遞迴堆疊）。

比 Kadane 慢（常數大很多），而且更難寫。為什麼還要學？

  • 它可以放進線段樹，支援「查詢任意區間的最大子陣列和」和「單點修改」，各 O(log n)。Kadane 做不到 —— 它只能算整個陣列，而且不支援修改。
  • 它可以平行化：左右兩半完全獨立。
  • 它是題目明確要求的進階。

時間O(n)合併只要 O(1)

邊界條件檢查清單

  • 全是負數：[-2,-1] → −1；[-5,-4,-3] → −3。best = 0 的寫法會錯。
  • 單一元素：[1] → 1；[-1] → −1。
  • 全是正數：[1,2,3] → 6（整個陣列）。
  • 含 0：[0] → 0；[-1,0,-1] → 0。
  • 答案在中間：[-2,1,-3,4,-1,2,1,-5,4] → 6。
  • 答案是整個陣列：[5,4,-1,7,8] → 23。
  • 前綴和版更新 min_prefix 的順序：如果先更新再算答案，[-1] 會回傳 0 而不是 −1。

常見追問

追問一：如果要回傳那個子陣列的起訖位置呢？

在 Kadane 裡多記兩個變數： best = cur = nums[0] start = end = tmp_start = 0 for i in range(1, len(nums)): if cur + nums[i] < nums[i]: cur = nums[i] tmp_start = i # 從這裡重新開始 else: cur += nums[i] if cur > best: best = cur start, end = tmp_start, i 複雜度不變。 但要先問清楚：如果有多組答案，要回哪一組？

追問二：環形陣列呢？

第 918 題。答案是以下兩者的較大值：

  • 不跨越邊界：就是本題的 Kadane 結果
  • 跨越邊界：總和 − 最小子陣列和（把中間「不要的那一段」挖掉）

但要小心一個邊界：如果全是負數，「總和 − 最小子陣列和」會是 0（挖掉全部），違反「非空」。這時候直接回傳 Kadane 的結果。

追問三：乘積最大子陣列呢？

第 152 題。Kadane 的直接推廣行不通，因為「負數乘負數會變正數」—— 目前最小的乘積可能在下一步變成最大的。解法是同時維護最大和最小兩個值：

cur_max, cur_min = max(x, cur_max * x, cur_min * x), \ min(x, cur_max * x, cur_min * x) （要用舊的 cur_max 算新的 cur_min，所以要同時賦值或先存起來。） 這是一個很好的提醒： 「加法」和「乘法」的結構不同， 加法只需要追蹤一個極值，乘法需要兩個。

追問四：二維版（最大和的子矩形）呢？

第 363 題的變形。標準做法是：枚舉「上邊界」和「下邊界」（O(m²) 對），把那幾列壓縮成一維陣列，再對它跑 Kadane。總共 O(m² · n)。這正是 Grenander 當年提出的原始問題 —— Kadane 的一維解法就是為了它。
