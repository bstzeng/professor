Problem

Given an integer array nums and an integer val, remove all occurrences of val in nums in-place. The order of the elements may be changed.

Return the number of elements in nums which are not equal to val. The first k elements of nums should hold the final result.

中文翻譯

給你一個陣列 nums 和一個值 val，請原地移除所有等於 val 的元素。元素的順序可以改變。

回傳移除後剩下的元素個數 k，而且 nums 的前 k 格要存放結果。

和第 26 題差一個字：「順序可以改變」

第 26 題：要保持相對順序 -> 只能用「讀寫指標」往前搬 第 27 題：順序可以改變 -> 多了一個「拿最後一個來填坑」的選項 為什麼這個差別重要？ nums = [1, 2, 3, 3, 3, 3, 3, 4]，val = 3 讀寫指標：要走完 8 格，寫 3 次 填坑法： 遇到 3 就從尾巴搬一個過來，只搬 2 次就結束 （因為 4 被搬到前面之後，後面的 3 直接被「縮掉」） 當「要刪的元素很多」時，填坑法的寫入次數明顯少很多。 當「要刪的元素很少」時，兩者差不多。 這是一個很典型的「放寬一個條件，換來一個更快的演算法」的例子。

範例

範例 1 輸入：nums = [3,2,2,3], val = 3 輸出：k = 2，nums 的前 2 格是 [2,2] 範例 2 輸入：nums = [0,1,2,2,3,0,4,2], val = 2 輸出：k = 5，nums 的前 5 格包含 [0,0,1,3,4]（順序不拘）

限制條件

  • 0 ≤ nums.length ≤ 100
  • 0 ≤ nums[i] ≤ 50
  • 0 ≤ val ≤ 100

LeetCode 原題

先看懂限制在說什麼

  • 陣列可以是空的（長度 0）。兩種解法都自然處理（迴圈跑 0 次）。
  • val 的範圍（0–100）比 nums[i] 的範圍（0–50）大。所以 val 可能根本不在陣列裡 —— 這時什麼都不用刪，回傳原長度。
  • 「順序可以改變」是這題和第 26 題最大的差別，也是評分的重點：面試官會想看你有沒有注意到這句話、並且利用它。

解題思路

兩種解法，都是 O(n) 時間、O(1) 空間，差別在寫入次數。

解法一

讀寫指標（保持順序，最通用）

class Solution: def removeElement(self, nums: List[int], val: int) -> int: k = 0 # 下一個要寫入的位置 for x in nums: if x != val: nums[k] = x k += 1 return k

和第 26 題完全一樣的模板：一個指標讀、一個指標寫，只有「該保留」的元素才寫下去。

nums = [0,1,2,2,3,0,4,2]，val = 2 x=0 != 2 -> nums[0]=0 k=1 x=1 != 2 -> nums[1]=1 k=2 x=2 == 2 -> 跳過 k=2 x=2 == 2 -> 跳過 k=2 x=3 != 2 -> nums[2]=3 k=3 x=0 != 2 -> nums[3]=0 k=4 x=4 != 2 -> nums[4]=4 k=5 x=2 == 2 -> 跳過 k=5 nums = [0,1,3,0,4,0,4,2]，前 5 格 [0,1,3,0,4] ✔ 回傳 5

順序被保留了（雖然題目不要求）。這是它的優點 —— 同一份程式碼可以直接用在「要求保持順序」的題目上。

寫入次數 = 保留的元素個數。如果幾乎沒東西要刪，那就是幾乎每一格都寫一次（寫到自己身上）。

解法二

從尾巴搬過來填坑（寫入次數最少）

既然順序無所謂，遇到要刪的元素時，就把最後一個有效元素搬過來蓋掉它，然後把有效範圍縮小一格。

class Solution: def removeElement(self, nums: List[int], val: int) -> int: i, n = 0, len(nums) while i < n: if nums[i] == val: nums[i] = nums[n - 1] # 把最後一個搬過來填坑 n -= 1 # 縮小有效範圍；i 不動，要重新檢查搬過來的值 else: i += 1 return n
nums = [3,2,2,3]，val = 3，n = 4 i=0: nums[0]=3 == 3 nums[0] = nums[3] = 3，n=3 i 不動（搬過來的 3 還沒檢查！） nums = [3,2,2,|3] i=0: nums[0]=3 == 3 nums[0] = nums[2] = 2，n=2 i 不動 nums = [2,2,|2,3] i=0: nums[0]=2 != 3 -> i=1 i=1: nums[1]=2 != 3 -> i=2 i=2 == n=2 -> 結束 回傳 2，前 2 格是 [2,2] ✔

為什麼搬完之後 i 不能前進？

因為從尾巴搬過來的那個值還沒被檢查 —— 它自己也可能等於 val。如果搬完就 i += 1，那個值會被漏掉。

錯誤寫法： if nums[i] == val: nums[i] = nums[n-1] n -= 1 i += 1 # ✘ 漏檢查搬過來的值 nums = [3, 3]，val = 3 i=0: nums[0]=3 -> nums[0]=nums[1]=3, n=1, i=1 i=1 == n=1 -> 結束，回傳 1 錯了！應該回傳 0。前 1 格是 [3]，但 3 應該被刪掉。 這是這個解法唯一的陷阱，也是面試時最常被抓到的 bug。

什麼時候該用這個？

當要刪的元素很多而且順序真的無所謂時。極端例子：[1] + [2]*100000、val = 2 —— 解法一要寫 1 次但走 100001 格；解法二只要 1 次搬移就把 i 推到界外。（實際上兩者都是 O(n)，差的是寫入次數而不是總步數。在「寫入很貴」的場景，例如寫到 SSD 或需要同步到遠端，這個差別才真的重要。）

邊界條件檢查清單

  • 空陣列：([], 0) → 0。
  • 全部都要刪：([4,4,4,4], 4) → 0。解法二的「i 不前進」在這裡至關重要。
  • 一個都不用刪：([1], 2) → 1。
  • 只有一個且要刪：([1], 1) → 0。
  • 要刪的在最後：([1,2,3], 3) → 2。解法二會把 nums[2] 搬到自己身上，無害。
  • val 不在陣列裡：([1,2,3], 99) → 3。

常見追問

追問一：如果要刪的是「滿足某個條件」的元素呢？

把 x != val 換成 not predicate(x) 即可，模板完全一樣。這個模板的本質是「原地過濾（in-place filter）」，和 Python 的 [x for x in nums if ...] 做同一件事，但不配置新記憶體。

追問二：這個模板還能用在哪？

  • 第 26／80 題：條件變成「和前面保留的不重複」
  • 第 283 題 Move Zeroes：先把非零的往前搬，再把後面補 0
  • 第 75 題 Sort Colors：三個指標的版本（荷蘭國旗）
  • C++ 的 std::remove：標準庫就是這個演算法，而且它也只回傳新的結尾迭代器、不真的縮短容器 —— 所以標準用法是 v.erase(std::remove(v.begin(), v.end(), val), v.end())，俗稱 erase-remove idiom。LeetCode 這題其實就是在考 std::remove 的實作。

追問三：為什麼題目不要求把後面清空？

因為那會是額外的 O(n) 寫入，而且對「回傳長度 + 前 k 格」這個介面來說沒有意義。在真實的容器實作裡，「邏輯長度」和「實體容量」本來就是分開的 —— vector::erase 也只是改 size，不會去清理後面的記憶體。
