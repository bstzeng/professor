Problem

Given an array of distinct integers candidates and a target integer target, return a list of all unique combinations of candidates where the chosen numbers sum to target.

The same number may be chosen from candidates an unlimited number of times. Two combinations are unique if the frequency of at least one of the chosen numbers is different.

中文翻譯

給你一個元素互不相同的整數陣列 candidates 和一個目標值 target，找出所有能讓總和等於 target 的不重複組合。

同一個數字可以無限次重複使用。兩個組合只要有任何一個數字的使用次數不同，就算不同的組合。

三句話決定整題的寫法

1. 「元素互不相同」 -> 不用處理候選陣列裡的重複 2. 「可以無限重複用」 -> 遞迴時傳 i 而不是 i+1 3. 「組合不能重複」 -> 用 start 限制「只能往後選」 第 3 點最重要，值得展開： 如果每一層都從 0 開始選，target=4、candidates=[2]： [2,2] 會被生成一次（沒問題） 但 candidates=[2,3]、target=5： [2,3] 和 [3,2] 都會被生成 -> 重複！ 用 start 限制之後，每一層只能選「>= 上一次選的」， 所以產生的組合永遠是「非遞減」的： [2,3] ✔ [3,2] ✘（不會被生成） 「強制一個固定的順序」是組合類問題去重的標準手法 —— 它讓每個「多重集合」只有唯一一種生成路徑。

範例

範例 1 輸入：candidates = [2,3,6,7], target = 7 輸出：[[2,2,3],[7]] 說明：2+2+3 = 7，7 = 7。 範例 2 輸入：candidates = [2,3,5], target = 8 輸出：[[2,2,2,2],[2,3,3],[3,5]] 範例 3 輸入：candidates = [2], target = 1 輸出：[]

限制條件

  • 1 ≤ candidates.length ≤ 30
  • 2 ≤ candidates[i] ≤ 40
  • candidates 的所有元素互不相同
  • 1 ≤ target ≤ 40

LeetCode 原題

先看懂限制在說什麼

  • candidates[i] ≥ 2 —— 沒有 0 也沒有 1。如果允許 0，遞迴會無限深（一直選 0，remain 永遠不變）。這一條保證每選一個數 remain 至少減 2，遞迴深度最多 target/2 = 20。
  • target ≤ 40，所以答案的數量有限（題目說「不超過 150 個組合」）。這是在告訴你：直接枚舉就好，不需要擔心爆炸。
  • 元素互不相同 —— 這是和第 40 題最大的差別。那題候選可以重複，去重會麻煩很多。

解題思路

解法一

回溯（標準解）

class Solution: def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]: candidates.sort() # 排序讓剪枝成立（也讓輸出比較整齊） out = [] path = [] def backtrack(start: int, remain: int) -> None: if remain == 0: out.append(path[:]) # 一定要複製！path 之後還會被改 return for i in range(start, len(candidates)): if candidates[i] > remain: break # 排序後，後面只會更大 -> 整層剪掉 path.append(candidates[i]) # 傳 i 而不是 i+1：同一個數字可以重複使用 backtrack(i, remain - candidates[i]) path.pop() backtrack(0, target) return out

三個關鍵，缺一不可

① backtrack(i, ...) 而不是 backtrack(i + 1, ...) -> 允許同一個數字再選一次 -> 這是「無限重複」的實作方式 ② for i in range(start, len(...)) 而不是 range(len(...)) -> 只能往後選，保證組合非遞減 -> 這是「去重」的實作方式 ③ out.append(path[:]) 而不是 out.append(path) -> path 是共用的 list，之後還會被 pop 和 append -> 不複製的話，out 裡全部都會變成同一個（而且最後是空的） -> 這是 Python 回溯題第一名的 bug

剪枝：if candidates[i] > remain: break

因為 candidates 已經排序， 如果 candidates[i] 已經超過 remain， 那 candidates[i+1], candidates[i+2], ... 只會更大 —— 整個 for 迴圈剩下的部分都不可能有答案。 所以是 break（跳出整層），不是 continue（只跳過這一個）。 沒有排序的話只能寫 continue，效率差很多： candidates = [7, 2, 3]，remain = 1 不排序：檢查 7 ✘、2 ✘、3 ✘ 三次 有排序：檢查 2 ✘ -> break 一次

為什麼不用檢查 remain < 0？

因為剪枝已經保證了 candidates[i] <= remain，所以 remain - candidates[i] >= 0，永遠不會變成負數。剪枝同時扮演了「邊界檢查」的角色 —— 這是好設計的副產品。

複雜度

回溯類問題的複雜度很難給出緊的上界。粗略地說，搜尋樹的深度是 O(target / min(candidates))，每個節點的分支數最多 len(candidates)，所以最壞是 O(n^(target/min))。但實際上剪枝讓它遠低於這個數字 —— 而且輸出本身就有 O(答案數 × 平均長度) 那麼大，這是無法避免的下界。

複雜度說明
時間O(n^(T/m))T = target，m = 最小候選；剪枝後遠低於上界
空間O(T/m)遞迴深度；不算輸出
解法二

動態規劃（完全背包的組合列舉版）

這題本質上是完全背包問題（每種物品可以拿無限個）。如果只問「有幾種組合」，DP 是標準答案；要「列出所有組合」，DP 也能做，只是要存下所有組合。

class Solution: def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]: # dp[t] = 湊出金額 t 的所有組合 dp = [[] for _ in range(target + 1)] dp[0] = [[]] # 湊出 0 只有一種方法：什麼都不拿 # 外層跑「候選」、內層跑「金額」-> 每個組合只會被「非遞減」地生成一次 for c in sorted(candidates): for t in range(c, target + 1): for combo in dp[t - c]: dp[t].append(combo + [c]) return dp[target]

迴圈順序決定了「組合」還是「排列」

外層跑候選、內層跑金額 -> 組合（本題要的） for c in candidates: for t in range(c, target+1): dp[t] += dp[t-c] 加上 c 因為每個候選只被「處理一次」， 生成的組合裡的數字順序一定是「候選被處理的順序」—— 也就是排序後的非遞減順序。 [2,3] 會出現，[3,2] 不會。 外層跑金額、內層跑候選 -> 排列（第 377 題要的） for t in range(1, target+1): for c in candidates: dp[t] += dp[t-c] 加上 c 每個金額都把所有候選試一遍， [2,3] 和 [3,2] 都會被生成。 這兩個迴圈只是交換順序，語意卻完全不同。 這是背包問題裡最容易搞混、也最值得記住的一點。

優點：沒有遞迴，而且 dp 陣列裡有「湊出每個金額」的所有答案 —— 如果題目要問多個 target，這個解法只要算一次。

缺點：記憶體大很多。它把所有中間金額的組合都存起來，而回溯只需要當前路徑。在這題（target ≤ 40）沒問題，但 target 大一點就會爆。

所以：只問「有幾種」用 DP（只存數量，O(target) 空間）；要「列出來」用回溯。

複雜度說明
時間O(target × n × 答案數)每個金額存所有組合
空間O(target × 答案總大小)所有中間結果

解法對照

解法時間空間適合備註
一、回溯O(n^(T/m))O(T/m)列出所有組合面試標準解
二、DP較大大多次查詢、只問數量完全背包

邊界條件檢查清單

  • 湊不出來：([2], 1) → []。
  • 剛好一個數字就是答案：([2,3,6,7], 7) 裡的 [7]。
  • 需要重複很多次：([2], 40) → [[2]×20]。遞迴深度 20。
  • 候選沒排序：([7,3,2], 18)。不先排序的話 break 剪枝會錯剪。
  • 忘記 path[:]：輸出會是一堆空 list（或全部相同）。先寫 path[:] 再想別的。
  • 傳 i+1 而不是 i：([2,3,6,7], 7) 會少掉 [2,2,3]，只剩 [7]。
  • 從 0 而不是 start 開始：會產生 [2,2,3]、[2,3,2]、[3,2,2] 三份重複。

常見追問

追問一：如果候選裡有重複、而且每個只能用一次呢？

那就是第 40 題（Combination Sum II）。兩個改動：

  • 遞迴傳 i + 1（每個只能用一次）
  • 加上「同一層跳過重複值」：if i > start and candidates[i] == candidates[i-1]: continue

注意是 i > start 不是 i > 0 —— 同一層不能重複選同一個值，但不同層可以（那是「用了兩個相同的數」，是合法的）。

追問二：如果只問「有幾種組合」呢？

完全背包的標準 DP，O(target) 空間：

dp = [0] * (target + 1) dp[0] = 1 for c in candidates: # 外層候選 -> 算「組合」 for t in range(c, target + 1): dp[t] += dp[t - c] return dp[target] 如果把兩層迴圈交換，算出來的是「排列」數（第 377 題）。 這是背包問題最經典的一組對照。

追問三：如果 target 很大（例如 10⁹）呢？

列出所有組合是不可能的（答案數量爆炸）。如果只問「有沒有解」，那是硬幣問題（Frobenius 問題）：當所有候選的最大公因數是 1 時，存在一個「Frobenius 數」，超過它的所有金額都湊得出來。兩個數 a、b 互質時，這個數是 ab − a − b（Chicken McNugget 定理）。三個以上就沒有簡單公式了。

追問四：這個回溯模板還能用在哪？

start 參數控制「能選哪些」，是組合類回溯的核心： 傳 i + start -> 可重複、組合 （第 39 題） 傳 i+1 + start -> 不可重複、組合 （第 40、77、78、90 題） 不用 start，用 used[] 標記 -> 排列 （第 46、47 題） 三種變化涵蓋了 LeetCode 上絕大多數的枚舉題。
