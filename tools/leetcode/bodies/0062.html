Problem

There is a robot on an m x n grid. The robot is initially located at the top-left corner. The robot tries to move to the bottom-right corner. The robot can only move either down or right at any point in time.

Given the two integers m and n, return the number of possible unique paths that the robot can take to reach the bottom-right corner.

中文翻譯

一個機器人位於 m × n 網格的左上角，想要走到右下角。它每一步只能往下或往右。

給你 m 和 n，回傳總共有幾種不同的走法。

兩種完全不同的思路，答案一樣

思路 A：動態規劃 要到達 (i, j)，最後一步只可能是 從 (i-1, j) 往下走，或 從 (i, j-1) 往右走 所以 dp[i][j] = dp[i-1][j] + dp[i][j-1] 邊界：第一列和第一行都是 1（只有一條路） 思路 B：組合數學 從左上走到右下，總共要走 (m-1) 次「下」 + (n-1) 次「右」 = m+n-2 步 這 m+n-2 步的順序決定了路徑。 所以問題等價於： 「在 m+n-2 個位置裡，選 m-1 個放『下』，有幾種選法？」 答案 = C(m+n-2, m-1) m=3, n=7：C(8, 2) = 28 ✔ 思路 B 是 O(min(m,n)) 的，比 DP 的 O(mn) 快得多。 但思路 A 能推廣到「有障礙物」（第 63 題）和「有權重」（第 64 題）， 思路 B 不行。

範例

範例 1 輸入：m = 3, n = 7 輸出：28 範例 2 輸入：m = 3, n = 2 輸出：3 說明： 1. 下 → 下 → 右 2. 下 → 右 → 下 3. 右 → 下 → 下

限制條件

  • 1 ≤ m, n ≤ 100
  • 題目保證答案不超過 2 × 10⁹

LeetCode 原題

先看懂限制在說什麼

  • m, n ≤ 100，所以 DP 的 O(mn) = 10⁴ —— 瞬間完成。這題不考效率，考的是你能不能看出它是 DP，以及能不能看出它其實是組合數。
  • 答案不超過 2 × 10⁹ —— 剛好超過 32 位元有號整數（2¹⁵ ≈ 2.1 × 10⁹）。在 Java 裡用 int 剛好夠（因為題目保證了上界），但很危險。而組合數的中間計算很容易溢位 —— 見解法四。
  • m 或 n 可以是 1 → 答案是 1（只能一直走）。

解題思路

解法一

二維 DP（最直白）

class Solution: def uniquePaths(self, m: int, n: int) -> int: # dp[i][j] = 從左上角走到 (i, j) 有幾種走法 dp = [[1] * n for _ in range(m)] # 第一列和第一行都只有一種走法 for i in range(1, m): for j in range(1, n): dp[i][j] = dp[i - 1][j] + dp[i][j - 1] return dp[m - 1][n - 1]

初始化的 [[1] * n for _ in range(m)] 一次搞定了第一列和第一行 —— 它們都只有一種走法。

注意不能寫 [[1] * n] * m！那樣 m 個列會是同一個 list 物件，改一個就全部都改。這是 Python 建二維陣列最經典的陷阱。

O(mn) 時間、O(mn) 空間。清楚，而且可以直接推廣到第 63、64 題。

複雜度說明
時間O(m·n)填滿整張表
空間O(m·n)dp 表
解法二

一維 DP（滾動陣列）

dp[i][j] 只依賴上一列同欄和同一列左邊一欄，所以一條長度 n 的陣列就夠。

class Solution: def uniquePaths(self, m: int, n: int) -> int: # 只需要「上一列」的資料，所以一條陣列滾動就夠 dp = [1] * n for _ in range(1, m): for j in range(1, n): dp[j] += dp[j - 1] # 右邊 = 上面(舊的 dp[j]) + 左邊(新的 dp[j-1]) return dp[n - 1]

dp[j] += dp[j-1] 這一行為什麼是對的？

在處理第 i 列、第 j 欄的時候： dp[j] 還沒更新 -> 它是「上一列」的值 = dp[i-1][j] dp[j-1] 已經更新 -> 它是「這一列」的值 = dp[i][j-1] dp[j] = dp[j] + dp[j-1] = dp[i-1][j] + dp[i][j-1] ✔ 正是轉移式 關鍵：j 必須「從左往右」跑。 這樣 dp[j-1] 才會是「已經更新的新值」， 而 dp[j] 還是「還沒更新的舊值」。 如果從右往左跑，dp[j-1] 會是舊值（上一列的），就錯了。 「滾動陣列的迴圈方向」是所有 DP 空間優化的核心問題： 需要「上一列」的舊值 -> 某些方向 需要「這一列」的新值 -> 另一些方向 有時候還得倒著跑（例如 0/1 背包）。 判斷方法：把轉移式攤開，看每一項需要新的還是舊的。

O(n) 空間。在 m, n ≤ 100 時沒差，但如果 n 到 10⁵，這個優化就是必要的。

複雜度說明
時間O(m·n)同上
空間O(n)一條長度 n 的陣列
解法三

直接算組合數（最快）

import math class Solution: def uniquePaths(self, m: int, n: int) -> int: # 總共要走 (m-1) 次下 + (n-1) 次右，共 m+n-2 步 # 從這 m+n-2 步裡選 m-1 步當「下」-> C(m+n-2, m-1) return math.comb(m + n - 2, m - 1)

一行。Python 3.8+ 有 math.comb，它的實作是高度優化的 C 程式碼。

為什麼是 C(m+n-2, m-1)？ 任何一條路徑，都可以寫成一串「下」和「右」： m=3, n=7 -> "下下右右右右右右"（2 個下、6 個右） 不同的路徑 <=> 不同的排列 而這種「只有兩種符號」的排列數，就是組合數： C(總步數, 下的次數) = C(8, 2) = 28 也可以寫成 C(m+n-2, n-1)，兩者相等 （C(8,2) == C(8,6)）。 驗證小例子 m=3, n=2： C(3+2-2, 3-1) = C(3, 2) = 3 ✔

複雜度是 O(min(m,n))（math.comb 的實作），遠優於 DP 的 O(mn)。

但它完全無法推廣 —— 一旦有障礙物或權重，組合公式就失效了。面試時建議：先講 DP（展示你會建模），再說「其實這是組合數，可以 O(min(m,n))」。

複雜度說明
時間O(min(m,n))組合數的計算
空間O(1)幾個變數
解法四

手算組合數（不用內建函式，避免溢位）

如果不能用 math.comb（或在 C/Java 裡），就要自己算 —— 而且要小心不要先算階乘再相除。

class Solution: def uniquePaths(self, m: int, n: int) -> int: # 手算 C(m+n-2, m-1)，邊乘邊除避免中間數字太大 total = m + n - 2 k = min(m - 1, n - 1) # 取小的那個，乘法次數較少 result = 1 for i in range(1, k + 1): # 每一步都整除：result 累積的是 C(total-k+i, i)，一定是整數 result = result * (total - k + i) // i return result

為什麼要「邊乘邊除」？

錯誤寫法： return factorial(m+n-2) // (factorial(m-1) * factorial(n-1)) m = n = 100 時，(m+n-2)! = 198! ≈ 10^372 在 Python 裡算得出來（但很慢）， 在 C/Java 裡早就溢位了。 正確寫法： C(N, k) = (N-k+1)/1 × (N-k+2)/2 × ... × N/k for i in 1..k: result = result * (N-k+i) // i 每一步的 result 都是 C(N-k+i, i)， 是一個組合數，所以「一定是整數」—— 整數除法不會有誤差。 而中間值最大就是答案本身（2×10⁹），不會溢位。 為什麼每一步都整除？ result_i = C(N-k+i, i) result_{i} = result_{i-1} × (N-k+i) / i = C(N-k+i-1, i-1) × (N-k+i) / i 由組合數的遞推恆等式，這確實等於 C(N-k+i, i)， 而組合數一定是整數 ✔ 但注意：「result × (N-k+i)」這一步之後才除以 i， 順序不能顛倒（先除會有餘數損失）。

k = min(m-1, n-1)：利用 C(N,k) == C(N,N-k)，取小的那個可以少跑一半的迴圈，中間值也更小。

複雜度說明
時間O(min(m,n))min(m,n) 次乘除
空間O(1)一個變數

邊界條件檢查清單

  • m = 1 或 n = 1：答案是 1。DP 的初始化直接回傳 1；組合數是 C(k, 0) = 1。
  • m = n = 1：答案 1（起點就是終點，走 0 步）。
  • m = 3, n = 2：3。最小的非平凡例子。
  • m = n = 100：答案是 C(198, 99)，約 2.25 × 10⁵⁸ —— 遠超題目說的 2 × 10⁹！所以題目的「保證不超過 2 × 10⁹」暗示測資不會給到 100 × 100。（實際上 LeetCode 的測資最大大約是 m = 3, n = 28 這種等級。）
  • Python 建二維陣列：[[1] * n] * m 是錯的，要用 [[1] * n for _ in range(m)]。
  • 先算階乘再除：在 C/Java 裡會溢位。

常見追問

追問一：如果有障礙物呢？

第 63 題。DP 幾乎不用改：障礙物那一格的 dp 設成 0。但組合公式完全失效 —— 這就是為什麼 DP 值得先學。

追問二：如果每一格有「成本」，要求最小成本路徑呢？

第 64 題。轉移式從「相加」變成「取 min 再加上自己」：dp[i][j] = min(dp[i-1][j], dp[i][j-1]) + grid[i][j]。同一張 DP 表，換一個運算，答案完全不同。

追問三：這張 DP 表和巴斯卡三角形是什麼關係？

dp[i][j] = dp[i-1][j] + dp[i][j-1] 這和巴斯卡三角形的遞推式 C(n, k) = C(n-1, k-1) + C(n-1, k) 是同一個式子，只是座標系旋轉了 45 度。 事實上 dp[i][j] = C(i+j, i)。 dp[2][6] = C(8, 2) = 28 ✔ 所以這張表「就是」巴斯卡三角形，斜著擺而已。 這也解釋了為什麼組合公式會出現 —— 不是巧合，是同一個遞推結構的兩種計算方式： DP 是「自底向上填表」， 組合公式是「直接套封閉形式」。

追問四：如果可以往上下左右四個方向走呢？

路徑數會變成無限大（可以繞圈）。所以題目必須限制方向（或限制「不能重複經過同一格」，那就變成計算自迴避路徑（self-avoiding walk）—— 一個著名的難題，連 n × n 網格的路徑數都沒有封閉公式）。

「只能往下或往右」這個限制，正是讓這題有優雅解答的原因。
