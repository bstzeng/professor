Problem

Given a string s, return the longest palindromic substring in s.

A string is a palindrome when it reads the same backward as forward.

中文翻譯

給你一個字串 s，找出 s 中最長的回文子字串並回傳。

回文的意思是：從左讀到右和從右讀到左完全一樣。

回文的「奇偶」問題，是這題所有麻煩的來源

奇數長度的回文： r a c e c a r ↑ 正中間是「一個字元」 偶數長度的回文： a b b a ↑ 正中間是「兩個字元的縫隙」，沒有中心字元 只想到奇數的人，會在 "cbbd" 這種測資上得到 "b"（正確答案是 "bb"）。 這是本題第一名的錯誤。

範例

範例 1 輸入：s = "babad" 輸出："bab" 說明："aba" 也是正確答案（題目說任一個都可以）。 範例 2 輸入：s = "cbbd" 輸出："bb" 說明：偶數長度的回文。 範例 3 輸入：s = "a" 輸出："a"

限制條件

  • 1 ≤ s.length ≤ 1000
  • s 只由數字和英文字母組成（大小寫有分，'A' ≠ 'a'）

LeetCode 原題

先看懂限制在說什麼

  • n ≤ 1000 是一個關鍵訊號。O(n²) 是 10⁶ 次運算 —— 穩過。O(n³) 是 10⁹ —— 一定超時。所以題目在說：做到 O(n²) 就及格了，O(n) 的 Manacher 是加分題而不是必需品。
  • 長度至少 1，所以不必處理空字串（但我們的程式碼還是會擋，因為寫成通用的比較安全）。
  • 大小寫有分："Aa" 的答案是 "A"，不是 "Aa"。這題沒有「忽略大小寫與標點」的要求 —— 那是第 125 題。

解題思路

所有解法都在回答同一個問題：怎麼避免把 O(n²) 個子字串每一個都花 O(n) 去驗證？

解法怎麼避免重複驗證時間空間
一、暴力法不避免（基準線）O(n³)O(n)
二、區間 DP用「內層是回文」的結果推「外層是回文」O(n²)O(n²)
三、中心擴散從中心往外長，天然就是遞增驗證O(n²)O(1)
四、Manacher用已知回文的對稱性，直接抄鏡像的答案O(n)O(n)
解法一

暴力列舉所有子字串

枚舉左右端點共 O(n²) 對，每一對花 O(n) 檢查是不是回文。總共 O(n³)。

class Solution: def longestPalindrome(self, s: str) -> str: best = "" for i in range(len(s)): for j in range(i, len(s)): sub = s[i:j + 1] if sub == sub[::-1] and len(sub) > len(best): best = sub return best

n = 1000 時大約 10⁹ 次字元比較，LeetCode 上會 TLE。但它只有 8 行、絕對正確，是後面三種解法的對照組 —— 這篇的所有測試都拿它當標準答案。

複雜度說明
時間O(n³)O(n²) 個子字串 × O(n) 驗證
空間O(n)切片 s[i:j+1] 本身就是 O(n) 記憶體
解法二

區間 DP：把驗證的 O(n) 省掉

暴力法的浪費在於：驗證 "abcba" 是回文時，其實剛剛已經驗證過 "bcb" 是回文了，卻沒有留下來用。

定義 dp[i][j]＝s[i..j]（閉區間）是不是回文。轉移只有一行：

dp[i][j] = (s[i] == s[j]) and dp[i+1][j-1] 白話：頭尾一樣，而且「去掉頭尾之後」也是回文。 邊界： 長度 1： dp[i][i] = True （單一字元必是回文） 長度 2： dp[i][i+1] = (s[i] == s[i+1]) （沒有「內層」可以問）

迴圈順序是這題唯一的陷阱

dp[i][j] 依賴 dp[i+1][j-1] —— 一個更短的區間。所以必須按區間長度由短到長填表。如果照著直覺寫 for i in range(n): for j in range(n):，在算 dp[0][4] 的時候 dp[1][3] 還是 False，答案就錯了。

填表順序（n = 5）：先填 ln=1 的對角線，再一層一層往右上角推 j=0 j=1 j=2 j=3 j=4 i=0 1 2 3 4 5 ← 數字是填的順序（第幾輪） i=1 1 2 3 4 i=2 1 2 3 i=3 1 2 i=4 1 只有右上三角（i ≤ j）有意義，左下三角永遠用不到。
class Solution: def longestPalindrome(self, s: str) -> str: n = len(s) if n < 2: return s # dp[i][j] = s[i..j] 是不是回文 dp = [[False] * n for _ in range(n)] start, length = 0, 1 for i in range(n): # 長度 1 一定是回文 dp[i][i] = True # 一定要「按長度由短到長」跑，因為 dp[i][j] 依賴 dp[i+1][j-1] for ln in range(2, n + 1): for i in range(n - ln + 1): j = i + ln - 1 if s[i] != s[j]: continue if ln == 2 or dp[i + 1][j - 1]: dp[i][j] = True if ln > length: start, length = i, ln return s[start:start + length]

為什麼還是 O(n²) 空間？因為要存整張表。雖然可以用滾動陣列壓到 O(n)，但既然解法三能做到 O(1)，這個優化就沒什麼意義了。區間 DP 真正的價值在於：它能推廣到「最長回文子序列」（第 516 題）和「回文分割」（第 131、132 題），而中心擴散不行。

複雜度說明
時間O(n²)填滿半張 n×n 的表
空間O(n²)整張 dp 表
解法三

中心擴散（最推薦的寫法）

換個方向想：與其問「這段是不是回文」，不如從中心開始長出回文。

每個回文都有唯一的中心。長度 n 的字串總共有 2n − 1 個可能的中心：n 個字元（奇數長度的回文）加上 n − 1 個縫隙（偶數長度的回文）。每個中心往外撐最多 O(n) 步，總共 O(n²) —— 和 DP 一樣，但不需要任何額外空間。

class Solution: def longestPalindrome(self, s: str) -> str: if not s: return "" def expand(l: int, r: int) -> tuple: """從 (l, r) 往兩邊撐開，回傳撐到最大時的閉區間。""" while l >= 0 and r < len(s) and s[l] == s[r]: l -= 1 r += 1 return l + 1, r - 1 # 多跑了一步，收回來 start, end = 0, 0 for i in range(len(s)): for l, r in (expand(i, i), # 奇數長度，中心是一個字元 expand(i, i + 1)): # 偶數長度，中心是兩字元的縫隙 if r - l > end - start: start, end = l, r return s[start:end + 1]

為什麼 expand 回傳 (l+1, r-1)？

因為 while 迴圈是在「撐不動了」才停下來，此時 l 和 r 已經各多走了一步（要嘛出界、要嘛字元不同）。收回一步才是真正的回文邊界。這個 off-by-one 是這個解法唯一容易寫錯的地方 —— 驗證方法：拿 "a" 試，expand(0,0) 應該回傳 (0,0)，長度 1。

為什麼偶數中心用 expand(i, i+1) 就好，不用擋越界？

當 i 是最後一個字元時 i+1 == len(s)，while 的條件 r < len(s) 第一次就不成立，直接回傳 (i+1, i) —— 一個「長度 −1」的空區間，自然不會贏過任何真實答案。用區間長度為負來表示「不存在」，省掉一個 if，是很實用的小技巧。

複雜度說明
時間O(n²)2n−1 個中心 × 最多 n 步
空間O(1)只用幾個下標；回傳的切片不算
解法四

Manacher：O(n) 的完整解

中心擴散還有浪費：算 "aaaaaaa" 時，每個中心都從頭撐一次，總步數是 O(n²)。但這些回文彼此高度重疊 —— Manacher 就是把重疊的部分「抄」過來。

第一步：用 # 消滅奇偶之分

s = "abba" t = "#a#b#b#a#" （長度變成 2n+1，永遠是奇數） s = "aba" t = "#a#b#a#" 好處： 1. 所有回文在 t 裡都是奇數長度，只要處理「以某字元為中心」一種情況。 2. pal[i]（t 裡的半徑）剛好等於「原字串裡對應回文的長度」。 例如 t = "#a#b#b#a#"，中心在正中央的 # 上，半徑 4， 原字串的回文 "abba" 長度就是 4。不用換算，直接相等。

第二步：利用對稱性抄答案

維護目前右端最靠右的那個回文，記下它的中心 center 和右端 right。當我們要算位置 i（且 i < right）時，它在這個大回文裡有一個鏡像位置 mirror = 2*center − i。

center | ... [ # a # a # a # ] ... ^ ^ ^ mirror i right 因為 [left..right] 整段是回文，mirror 附近和 i 附近長得一模一樣， 所以 pal[i] 至少可以直接抄 pal[mirror]。 但有一個限制：抄的部分不能超出 right， 因為 right 外面的字元還沒被這個大回文保證過。 pal[i] = min(right - i, pal[mirror]) 抄完之後再從這個起點繼續往外撐 —— 撐成功的每一步都會把 right 往右推。

為什麼總複雜度是 O(n)？

關鍵在最後一句：while 迴圈每成功跑一次，right 就 +1。而 right 從 0 單調遞增到 n，最多只能被推 n 次。所以所有 while 的總執行次數是 O(n)，不是 O(n²)。這是「攤還分析（amortized analysis）」的經典例子 —— 單看一次迴圈可能跑很久，但整體加起來有上界。

class Solution: def longestPalindrome(self, s: str) -> str: if not s: return "" # 插入分隔符，讓奇偶長度統一成奇數 t = "#" + "#".join(s) + "#" n = len(t) pal = [0] * n # pal[i] = 以 t[i] 為中心的回文「半徑」 center = right = 0 # 目前最靠右的回文的中心與右端 for i in range(n): if i < right: mirror = 2 * center - i pal[i] = min(right - i, pal[mirror]) # 先抄鏡像，最多抄到 right # 從已知的半徑繼續往外撐 while (i - pal[i] - 1 >= 0 and i + pal[i] + 1 < n and t[i - pal[i] - 1] == t[i + pal[i] + 1]): pal[i] += 1 if i + pal[i] > right: center, right = i, i + pal[i] k = max(range(n), key=lambda i: pal[i]) length = pal[k] # 半徑剛好等於原字串裡的長度 start = (k - length) // 2 # 映射回原字串的下標 return s[start:start + length]

下標換算：start = (k − length) // 2

t = "#b#a#b#a#d#" （s = "babad"） 下標 0123456789… 最佳中心 k = 3（字元 'a'），半徑 pal[3] = 3 → 在 t 裡的回文是 t[0..6] = "#b#a#b#" → 對應 s 裡的 "bab"，起點 0，長度 3 驗算：start = (3 - 3) // 2 = 0 ✔ length = pal[3] = 3 ✔

實務上要不要寫 Manacher？老實說：n ≤ 1000 的話完全不需要。面試時能把中心擴散寫對、再口頭說明「有 O(n) 的 Manacher，原理是利用已知回文的對稱性省掉重複比較」，通常就足夠了。硬寫 Manacher 寫錯，比不寫還扣分。

複雜度說明
時間O(n)攤還分析：right 單調遞增
空間O(n)t 和 pal 兩個陣列

邊界條件檢查清單

  • 偶數回文："cbbd" → "bb"。只寫奇數中心的話會得到 "b"。
  • 全部相同："aaaa" → "aaaa"。這是中心擴散的最壞情況（真的跑滿 O(n²)）。
  • 完全沒有長度 > 1 的回文："abcd" → 任一個單字元。不能回傳空字串。
  • 長度 1："a" → "a"。DP 解法的 n < 2 提前 return 就是為了它。
  • 整個字串就是回文："racecar"。撐開會一路撐到出界，檢查 l >= 0 和 r < len(s) 不能漏。
  • 答案不唯一："babad" 回 "bab" 或 "aba" 都算對，但你的程式要穩定回其中一個 —— 用 > 而不是 >= 比長度，會回傳最早出現的那個。

常見追問

追問一：要的是最長回文「子序列」呢？

完全不同的題（第 516 題）。子序列可以跳過字元，中心擴散整個失效，只能用區間 DP：dp[i][j] = dp[i+1][j-1] + 2（若 s[i]==s[j]）否則 max(dp[i+1][j], dp[i][j-1])。這就是為什麼解法二值得學 —— 它的骨架可以直接搬過去。

追問二：要回傳「有幾個回文子字串」呢？

第 647 題。中心擴散幾乎不用改：每成功撐開一次就 count += 1，因為每一次成功的撐開都對應一個不同的回文子字串。三行改完。

追問三：要把字串補成回文，最少在前面加幾個字元？

第 214 題（Shortest Palindrome）。等價於「找出從 0 開始的最長回文前綴」，可以用 KMP 在 O(n) 解決 —— 把 s + "#" + reversed(s) 做一次 failure function 即可。

延伸題目

  • 第 516 題 Longest Palindromic Subsequence —— 區間 DP 的直接應用
  • 第 647 題 Palindromic Substrings —— 中心擴散改三行
  • 第 131／132 題 Palindrome Partitioning —— 需要 dp 表當預處理
  • 第 125 題 Valid Palindrome —— 忽略大小寫與標點的版本
