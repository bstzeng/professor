Problem

You are given the root of a binary search tree (BST), where the values of exactly two nodes of the tree were swapped by mistake. Recover the tree without changing its structure.

Follow up: A solution using O(n) space is pretty straight-forward. Could you devise a constant O(1) space solution?

中文翻譯

給你一棵二元搜尋樹（BST）的根節點 root，其中剛好有兩個節點的值被不小心交換了。

請在不改變樹的結構的前提下，把它復原。

進階：用 O(n) 空間很直接，你能做到 O(1) 嗎？

先確認題目到底在說什麼

「兩個節點的值被交換」的意思是： 原本是一棵合法的 BST， 然後有人把【其中兩個節點裡存的數字】對調了。 樹的【形狀完全沒變】，只有兩個位置的數字換了位子。 你要做的是：把那兩個數字換回來。 【注意：是改 val，不是搬節點。】 題目明確說「不改變結構」—— 所以不能重建樹、不能改 left/right 指標， 只能修改節點裡的 val。 （實務上兩者等價，但面試官會看你有沒有讀清楚題目。） 前一題（98）教你「怎麼判斷是不是 BST」， 這一題教你「壞掉了要怎麼修」—— 兩題用的是【同一把鑰匙】。

這把鑰匙：BST ⟺ 中序走訪嚴格遞增

把 BST 中序走訪一遍，會得到一條【嚴格遞增】的序列。 現在有兩個值被交換了， 那條序列上就會出現【逆序】。 原本： 1 2 3 4 5 6 7 交換 2 和 6： 1 6 3 4 5 2 7 ^ ^ 【問題從「樹」變成了「一條幾乎排好序的陣列裡， 找出被交換的那兩個元素」。】 這是一個非常標準的化簡： 樹的問題 --中序--> 陣列的問題

範例

範例 1 輸入：root = [1,3,null,null,2] 1 / 3 \ 2 中序走訪：3, 2, 1 （應該要是 1, 2, 3） 輸出：[3,1,null,null,2] 3 / 1 \ 2 說明：1 和 3 被交換了，換回來即可。 範例 2 輸入：root = [3,1,4,null,null,2] 3 / \ 1 4 / 2 中序走訪：1, 3, 2, 4 （應該要是 1, 2, 3, 4） 輸出：[2,1,4,null,null,3] 說明：2 和 3 被交換了。

限制條件

  • 樹的節點數在 [2, 1000] 之間
  • −2³¹ ≤ Node.val ≤ 2³¹ − 1

LeetCode 原題

注意：節點數至少是 2

所以一定存在兩個被交換的節點，不需要處理「樹本來就是對的」這種情況。

但寫防呆比較安全：如果 first is None（沒找到逆序），就直接 return。面試時主動加上這行會加分。

解題思路

在中序序列上找「逆序點」（相鄰兩項 prev > cur 的位置）。 【情況 A：被交換的兩個位置不相鄰】 1 6 3 4 5 2 7 ^逆序1 ^逆序2 逆序1：6 > 3 -> 要換的「大值」是 6（前者） 逆序2：5 > 2 -> 要換的「小值」是 2（後者） 出現【兩個】逆序點。 【情況 B：被交換的兩個位置相鄰】 1 2 4 3 5 6 ^逆序 只有【一個】逆序點：4 > 3 要換的就是 4（前者）和 3（後者）。 【怎麼用一段程式碼同時處理兩種情況？】 每遇到一次逆序 (prev, cur)： if first is None: first = prev # 只記第一次的前者 second = cur # 每次都更新成後者 情況 A： 第一次逆序 -> first = 6, second = 3 第二次逆序 -> first 不動, second = 2 ✔ 最終 (6, 2) 情況 B： 唯一一次逆序 -> first = 4, second = 3 ✔ 【first 只設一次、second 每次都覆蓋】—— 這六個字就是本題的全部技巧。 最後 swap(first.val, second.val) 即可。

為什麼「最多只會有兩個逆序點」？

把中序序列想成一個排序好的陣列，然後交換位置 i < j 的兩個元素。 ... a[i-1] a[j] a[i+1] ... a[j-1] a[i] a[j+1] ... ^ ^ 變大了 變小了 a[j] 原本比 a[i] 大，現在被放到前面 -> 和右鄰居產生逆序 a[i] 原本比 a[j] 小，現在被放到後面 -> 和左鄰居產生逆序 中間那一段 a[i+1] ... a[j-1] 內部仍然遞增（沒被動到）。 所以【恰好兩個逆序點】—— 除非 j = i + 1（相鄰），此時兩個逆序點重疊成一個。 【這個推理是本題的正確性證明，面試時值得講一遍。】
解法一

中序收集 + 排序（最笨但最保險）

class Solution: def recoverTree(self, root: Optional[TreeNode]) -> None: # 先把中序走訪的「節點」收集起來 nodes = [] def go(node): if not node: return go(node.left) nodes.append(node) go(node.right) go(root) # 正確的中序應該是值排序後的結果，直接填回去 for node, v in zip(nodes, sorted(n.val for n in nodes)): node.val = v

先把中序的節點收集起來，再把「排序後的值」依序填回去。完全不用思考逆序點，絕對不會錯。

為什麼這樣一定對？ 中序的第 k 個節點，就該放「第 k 小的值」—— 這是 BST 的定義。 所以把所有值排序後依序填回中序位置， 結果必然是合法的 BST，而且形狀沒變 ✔ 而且它甚至比題目要求的更強： 【就算被交換的不只兩個節點，它也能修好。】 代價： 時間 O(n log n)（排序） 空間 O(n)（存節點） 題目 n <= 1000，這個成本完全可以接受。

面試時可以先講這個當「保底解」，說「這一定對，但我可以做得更好」，然後再講解法二。先給出一個正確解、再優化，是很好的節奏。

複雜度說明
時間O(n log n)排序主導
空間O(n)存所有節點
解法二

中序找逆序點（面試預設答案）

class Solution: def recoverTree(self, root: Optional[TreeNode]) -> None: self.first = self.second = self.prev = None def go(node): if not node: return go(node.left) # 中序走訪裡，prev 應該永遠 < node。違反了就是逆序點 if self.prev and self.prev.val > node.val: if self.first is None: self.first = self.prev # 第一次：記「大的那個」 self.second = node # 每次都更新「小的那個」 self.prev = node go(node.right) go(root) self.first.val, self.second.val = self.second.val, self.first.val

三個變數的分工

prev 中序走訪裡「上一個節點」（注意存的是節點，不是值） first 要交換的兩個節點中，【比較大】的那個（先出現） second 要交換的兩個節點中，【比較小】的那個（後出現） if prev and prev.val > node.val: if first is None: first = prev # 只在第一次逆序時設定 second = node # 每次逆序都更新 最後 swap(first.val, second.val) 【為什麼 first 只設一次？】 因為在情況 A 裡，第一個逆序點的「前者」才是被錯放的大值； 第二個逆序點的前者只是個無辜的路人。 【為什麼 second 每次都更新？】 因為在情況 A 裡，被錯放的小值出現在【第二個】逆序點的後者。 在情況 B 裡只有一次逆序，所以「每次都更新」也等於「設一次」。 兩種情況共用同一段程式碼 ✔

為什麼 prev 存節點而不是值？

因為最後要交換的是節點裡的 val，所以必須抓得到那個節點物件。

只存值的話，你知道「要換 6 和 2」，卻不知道它們在哪兩個節點上 —— 而且樹裡可能有同值節點（雖然 BST 不該有，但壞掉的樹什麼都可能）。

if self.prev 這裡為什麼可以不用 is not None？

因為 prev 是 TreeNode 物件，而自訂類別的實例永遠是 truthy（除非定義了 __bool__ 或 __len__）。

對照第 98 題：那裡的 prev 存的是整數值，值可能是 0，所以那裡非得寫 is not None 不可。同一個符號、不同的型別，安全性完全不同 —— 這是很好的對照練習。

空間 O(h)（遞迴堆疊）。還不是 O(1)，所以進階要求還沒滿足。

複雜度說明
時間O(n)每個節點看一次
空間O(h)遞迴堆疊
解法三

中序迭代版（把遞迴堆疊變成顯式堆疊）

class Solution: def recoverTree(self, root: Optional[TreeNode]) -> None: stack, prev = [], None first = second = None node = root while stack or node: while node: stack.append(node) node = node.left node = stack.pop() if prev and prev.val > node.val: if first is None: first = prev second = node prev = node node = node.right first.val, second.val = second.val, first.val

和解法二完全等價，只是把遞迴改成 while + stack。

好處：沒有遞迴深度限制（本題 n ≤ 1000 其實不會爆，但養成習慣總是好的），而且可以用區域變數，不用 self. 或 nonlocal。

這個骨架（第 94、98、99、173、230 題共用）： stack, node = [], root while stack or node: while node: stack.append(node) node = node.left node = stack.pop() # ★★★ 中序輸出的時機，你的邏輯寫在這裡 ★★★ node = node.right 【把它背起來。】 只要換掉星號那一行，就能解一整排 BST 題目。

空間仍然是 O(h) —— 堆疊沒消失，只是換了地方住。

複雜度說明
時間O(n)每個節點進出堆疊一次
空間O(h)顯式堆疊
解法四

Morris 中序走訪（真正的 O(1) 空間，滿足進階）

class Solution: def recoverTree(self, root: Optional[TreeNode]) -> None: first = second = prev = None node = root while node: if not node.left: if prev and prev.val > node.val: if first is None: first = prev second = node prev = node node = node.right else: pre = node.left # 找中序前驅 while pre.right and pre.right is not node: pre = pre.right if not pre.right: # 第一次：架線，往左 pre.right = node node = node.left else: # 第二次：拆線，輸出 pre.right = None if prev and prev.val > node.val: if first is None: first = prev second = node prev = node node = node.right first.val, second.val = second.val, first.val

Morris 的核心：借用空指標當「回家的線」

一棵 n 個節點的二元樹有 n+1 個空指標， Morris 把它們臨時借來記錄「走完左子樹之後要回到誰身上」。 對每個有左子樹的 node： pre = node.left while pre.right and pre.right is not node: pre = pre.right # pre 走到左子樹的最右邊 = node 的中序前驅 if not pre.right: # 【第一次】造訪 node pre.right = node # 架線：走完左子樹會自動回到 node node = node.left # 往左下去 else: # 【第二次】造訪 node（沿著線回來的） pre.right = None # 拆線，把樹恢復原狀 <輸出 node> # 左子樹已經走完了，現在輪到自己 node = node.right # 往右子樹 如果 node 沒有左子樹，直接輸出自己然後往右走。 【pre.right is not node 這個判斷，就是在區分「第一次」和「第二次」。】

為什麼總時間還是 O(n)？

看起來「找前驅」是個內層迴圈，會不會變成 O(n²)？ 不會。 關鍵：每一條「右邊緣」（right spine）最多被走過【兩次】—— 一次是架線時，一次是拆線時。 而所有右邊緣的總長度是 O(n)（每條邊只屬於一條右邊緣）。 所以總成本是 O(n) ✔ 這個分析叫做【攤還分析（amortized analysis）】—— 單次操作可能很貴，但總量有上界。

本題用 Morris 的注意事項

和第 98 題不同，這裡沒有「提早結束」的誘惑 —— 本來就要走完整棵樹才能確定 second，所以 Morris 在這題用起來反而比第 98 題順。

但仍然要注意：中途絕對不能 return，否則樹上會留下沒拆的線，變成有環的結構。

空間真的是 O(1)（只有 first、second、prev、node、pre 五個指標）—— 這才是進階要求的答案。

代價：程式碼長了三倍、暫時修改樹（不可用於唯讀樹或多執行緒）、實際執行常常比解法三慢（找前驅的常數不小）。

複雜度說明
時間O(n)攤還每條邊常數次
空間O(1)只用五個指標

面試時的講法建議

1. 先說出那把鑰匙： 「BST 的中序走訪是嚴格遞增的， 所以交換兩個值，就會在中序序列上留下逆序點。」 2. 給保底解（收集 + 排序），說「這一定對，O(n log n)」。 3. 升級到「找逆序點」，講清楚【兩個逆序點 vs 一個逆序點】 這兩種情況，以及 first / second 的更新規則。 ★ 這一步是本題的核心，講不清楚就等於沒解出來。 4. 被問到 O(1) 空間，再端出 Morris。 【第 3 步的「兩種情況」是面試官真正在看的東西。】 很多人寫出程式碼卻說不出「為什麼 second 要每次覆蓋」—— 那代表是背來的，不是想出來的。

邊界條件檢查清單

  • [1,3,null,null,2] → 換 1 和 3（官方範例 1）。
  • [3,1,4,null,null,2] → 換 2 和 3（官方範例 2）。
  • 被交換的兩個節點在中序裡相鄰（情況 B）→ 只有一個逆序點。沒處理這個情況的話，second 會是 None，直接 crash —— 這是本題第一名的 bug。
  • 被交換的是根節點和某個葉子 → 一樣用同一套邏輯處理。
  • 只有兩個節點 [2,3]（3 是左孩子）→ 中序是 3, 2，一個逆序點，換回來變 [3,2]。
  • first 寫成「每次都更新」 → 情況 A 會抓到錯的節點（抓到第二個逆序點的前者）。
  • second 寫成「只設一次」 → 情況 A 會抓到錯的節點（抓到第一個逆序點的後者）。
  • prev 存值而不是節點 → 最後不知道要改哪個節點的 val。
  • Morris 版中途 return → 樹上留下沒拆的線，變成有環。

常見追問

追問一：如果有 k 個節點被交換（k > 2）呢？

「找逆序點」的邏輯就不夠用了 —— k 個錯位可能產生任意數量的逆序點，而且對應關係不再單純。

解法一（收集 + 排序）卻完全不受影響，因為它根本不管「錯了幾個」，直接把正確的值填回正確的位置。這就是「笨解法」的價值 —— 它的正確性不依賴題目的特殊假設。

如果只想找出「哪些節點被動過」：把中序序列和它的排序版逐項比對，不相等的位置就是被動過的節點。O(n log n) 時間、O(n) 空間。

追問二：如果是「兩個節點的位置被交換」（連同子樹一起搬）呢？

那就是完全不同的題目了 —— 樹的形狀變了，中序序列不再只是「兩個元素互換」，而是「兩段子序列互換」。

本題明確說「不改變結構」，所以只有 val 被動過。讀題時要抓住這個關鍵字。

追問三：Morris 走訪還能做什麼？

  • 第 94 題：中序走訪，O(1) 空間
  • 第 98 題：驗證 BST，O(1) 空間
  • 本題：復原 BST，O(1) 空間
  • 第 114 題：把二元樹攤平成鏈結串列（Morris 的變形）
  • 前序版：只要把「輸出的時機」從「拆線時」改成「架線時」

後序版也存在但複雜很多（需要「反轉右邊緣」的技巧），面試幾乎不會考。

追問四：能不能一趟就知道「有沒有被交換」？

可以 —— 那就是第 98 題。本題和第 98 題的差別只在：第 98 題發現逆序就回 False，本題發現逆序要記下來繼續走。

98 題： if prev.val > node.val: return False 99 題： if prev.val > node.val: if first is None: first = prev second = node 【同一個骨架，不同的動作。】 這種「一個模板解一整類題」的感覺， 正是刷題的真正收穫 —— 不是記住 100 個解法，而是記住 10 個骨架。
