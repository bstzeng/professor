Problem

Given the head of a linked list and a value x, partition it such that all nodes less than x come before nodes greater than or equal to x.

You should preserve the original relative order of the nodes in each of the two partitions.

中文翻譯

給你一個鏈結串列的頭節點 head 和一個值 x，請重新排列，讓所有小於 x 的節點，都排在大於或等於 x 的節點前面。

而且要保留兩個部分各自原本的相對順序（也就是「穩定」）。

「保留相對順序」= 這是一個穩定的分割

1 -> 4 -> 3 -> 2 -> 5 -> 2，x = 3 小於 3 的（依原順序）： 1, 2, 2 大於等於 3 的（依原順序）： 4, 3, 5 答案： 1 -> 2 -> 2 -> 4 -> 3 -> 5 注意：不是排序！4 還是排在 3 前面（原本的順序）。 「穩定」這個要求排除了很多解法： - 快速排序的分割（不穩定） - 從尾巴往前搬（會反轉順序） 最乾淨的做法： 【開兩條新串列，掃一遍，各自 append，最後接起來】 因為 append 天然保持順序，所以穩定性是免費的。

這個「分成兩堆再接起來」的模式，在鏈結串列上特別漂亮 —— 因為串列的「接起來」是 O(1)（改一個指標），而陣列要 O(n) 的複製。

範例

範例 1 輸入：head = [1,4,3,2,5,2], x = 3 輸出：[1,2,2,4,3,5] 範例 2 輸入：head = [2,1], x = 2 輸出：[1,2]

限制條件

  • 串列節點數在 [0, 200] 範圍內（可以是空的）
  • −100 ≤ Node.val ≤ 100
  • −200 ≤ x ≤ 200

LeetCode 原題

先看懂限制在說什麼

  • x 的範圍比節點值大（−200 到 200 vs −100 到 100）—— 所以可能出現「全部都小於 x」或「全部都大於等於 x」的情況。那時候其中一條串列會是空的。
  • 串列可以是空的 → 回傳 None。
  • 是「小於」而不是「小於等於」：等於 x 的節點要放在後半段。

解題思路

解法一

兩條串列 + 兩個 dummy（標準解）

class Solution: def partition(self, head: Optional[ListNode], x: int) -> Optional[ListNode]: # 開兩條新串列：小的放一邊、大的放一邊，最後接起來 small_head = small = ListNode() large_head = large = ListNode() while head: if head.val < x: small.next = head small = small.next else: large.next = head large = large.next head = head.next large.next = None # 切斷！否則可能留下環 small.next = large_head.next # 把「大的那條」接到「小的那條」後面 return small_head.next

為什麼需要兩個 dummy？

small_head 和 large_head 是兩個虛擬頭節點。 它們的作用和第 21、19 題一樣： 「讓第一個節點不再是特例」。 沒有 dummy 的話，每次 append 都要判斷 「這是這條串列的第一個嗎？如果是就設 head，否則接在尾巴後面」。 有了 dummy，兩種情況變成同一行： small.next = head small = small.next 最後回傳 small_head.next（跳過虛擬節點）。 而且 dummy 順便處理了「其中一條是空的」： 如果沒有任何節點 < x，small_head.next 就是 None， small 還是 small_head， small.next = large_head.next 直接把大的接上 ✔

large.next = None —— 最容易漏的一行

如果不寫這一行，會發生什麼？ 1 -> 4 -> 3 -> 2 -> 5 -> 2，x = 3 掃完之後： small 這條：dummy -> 1 -> 2 -> 2 large 這條：dummy -> 4 -> 3 -> 5 但注意！這些是【原本的節點】，指標還沒被完全重設。 最後一個被放進 small 的節點是 2（原本的最後一個）， 它的 next 本來就是 None ✔ 但最後一個被放進 large 的節點是 5， 而 5.next 原本指向 2（最後那個節點）—— 而 2 現在在 small 這條裡！ 接起來之後： 1 -> 2 -> 2 -> 4 -> 3 -> 5 -> 2 -> ... ^ ^ └────────────────────┘ 環！ from_list 會無限迴圈，或 LeetCode 會回報 「Found cycle in the ListNode」。 所以 large.next = None 是【必須】的。 為什麼 small 那條不用？ 因為 small 的尾巴接下來就會被 small.next = large_head.next 覆寫掉。 寫了也不會錯，但沒必要。

為什麼是「穩定」的？

因為我們按照原本的順序掃過一遍，每個節點都 append 到對應的串列尾端。append 保持插入順序，所以兩段內部的相對順序都不變 ✔

複雜度 O(n) 時間、O(1) 額外空間（兩個 dummy 是常數，節點本身是重用的，沒有建新節點）。

複雜度說明
時間O(n)掃一遍
空間O(1)兩個 dummy + 幾個指標
解法二

原地搬移（不開新串列，但難寫很多）

有些人會想「能不能不開兩條串列？」—— 可以，把每個小於 x 的節點摘下來，插到「小的區段」的尾端。

class Solution: def partition(self, head: Optional[ListNode], x: int) -> Optional[ListNode]: # 不開新串列的版本：把「小的」一個一個搬到前面 # （比較難寫，而且不穩定，這裡只當對照） dummy = ListNode(0, head) prev_small = dummy # 「小的區段」的最後一個 prev = dummy while prev.next: cur = prev.next if cur.val < x and prev is not prev_small: # 把 cur 從目前的位置摘下來，插到 prev_small 後面 prev.next = cur.next cur.next = prev_small.next prev_small.next = cur prev_small = cur # prev 不動（因為 cur 被摘走了，prev.next 換人了） else: if cur.val < x: prev_small = cur prev = cur return dummy.next

但它明顯更難寫：

  • 要同時維護 prev（目前掃到哪）和 prev_small（小段的尾巴）
  • 摘除節點之後 prev 不能前進（因為 prev.next 換人了）
  • 要小心「節點已經在正確位置」的情況（prev is prev_small），否則會把它摘下來再插回原位，造成無窮迴圈

而且空間複雜度完全一樣（都是 O(1)） —— 解法一的兩個 dummy 只是兩個節點，不是 O(n)。

所以這個版本沒有任何優勢，只是為了展示「另一條路存在」。面試時寫解法一。

複雜度說明
時間O(n)掃一遍
空間O(1)幾個指標

邊界條件檢查清單

  • 空串列：([], 1) → []。
  • 全部小於 x：([1,2,3], 10) → 原樣。large_head.next 是 None，接上去剛好。
  • 全部大於等於 x：([1,2,3], 0) → 原樣。small_head.next 是 None，small 還是 small_head，接上大的那條 ✔
  • 剛好等於 x：([1], 1) → [1]（1 不小於 1，所以歸在後半段）。
  • 只需要交換兩個：([2,1], 2) → [1,2]。
  • 忘記 large.next = None：([1,4,3,2,5,2], 3) 會產生一個環。這是本題唯一真正的陷阱。

常見追問

追問一：如果要分成三段（< x、== x、> x）呢？

開三條串列，最後接起來。這就是荷蘭國旗問題（第 75 題）的串列版 —— 但串列版反而更簡單，因為不需要交換，只要 append。

small = mid = large = 三個 dummy while head: if head.val < x: 接到 small elif head.val == x: 接到 mid else: 接到 large head = head.next large.next = None mid_tail.next = large_head.next small_tail.next = mid_head.next return small_head.next 陣列版（第 75 題）需要三個指標和小心的交換邏輯， 串列版只要三條串列 —— 這是串列的優勢。

追問二：這和快速排序有什麼關係？

這就是 quicksort 的 partition 步驟（在串列上）。把它和遞迴組合起來，就是串列的快速排序：

def quicksort_list(head): if not head or not head.next: return head pivot = head.val 分成 < pivot、== pivot、> pivot 三條 return concat(quicksort_list(小的), 等於的, quicksort_list(大的)) 但實務上串列排序幾乎都用【merge sort】而不是 quicksort， 因為： - merge sort 在串列上是 O(1) 額外空間（陣列版要 O(n)） - merge sort 穩定 - quicksort 需要隨機存取來選 pivot（串列做不到）， 而「取第一個當 pivot」在已排序的輸入上會退化成 O(n²) 這就是為什麼 Python 的 sort、Java 的 Collections.sort， 以及第 148 題的標準解，都是 merge sort。

追問三：陣列版呢？

陣列版的「穩定分割」需要 O(n) 額外空間（或一個 O(n log n) 的就地穩定分割演算法 —— 相當複雜）。串列版的 O(1) 空間是免費的，因為「接起來」不用搬資料。

這是鏈結串列相對於陣列最明顯的優勢場景之一。
