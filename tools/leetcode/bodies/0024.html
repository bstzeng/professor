Problem

Given a linked list, swap every two adjacent nodes and return its head.

You must solve the problem without modifying the values in the list's nodes (i.e., only nodes themselves may be changed).

中文翻譯

給你一條鏈結串列，兩兩交換相鄰的節點，回傳交換後的頭節點。

你不能修改節點的值，只能改變節點之間的連接（也就是必須真的動指標）。

「不能改值」這句話就是全題的重點

如果可以改值，這題兩行就結束了（見解法三）。題目特別禁止，是因為它想考指標重接。

為什麼真實世界會在意這個限制？ 在很多場景裡，「節點」不只是一個值： - 節點可能很大（裡面有一整筆記錄），複製成本高 - 可能有外部指標指向某個節點，交換值會讓那些指標指錯東西 - 節點可能是不可變的（immutable） 所以「重接指標」是 O(1) 的操作， 「複製整個節點的內容」可能是 O(節點大小)。 這個區別在資料庫的 B-tree、作業系統的 free list 裡都很關鍵。

範例

範例 1 輸入：head = [1,2,3,4] 輸出：[2,1,4,3] 範例 2 輸入：head = [] 輸出：[] 範例 3 輸入：head = [1] 輸出：[1] 說明：只有一個節點，沒有對象可以交換。 範例 4 輸入：head = [1,2,3] 輸出：[2,1,3] 說明：最後落單的 3 保持原位。

限制條件

  • 節點數在 [0, 100] 範圍內（可以是空串列）
  • 0 ≤ Node.val ≤ 100

LeetCode 原題

先看懂限制在說什麼

  • 節點數可以是 0，所以不能無條件存取 head.val。
  • 節點數可以是奇數，最後那個落單的節點保持原位，不動它。
  • 規模只有 100，效率完全不是重點。這題純粹考指標操作。

解題思路

迴圈版和遞迴版都很短。遞迴版只有 6 行，但迴圈版是 O(1) 空間 —— 兩個都該會。

解法一

迴圈 + dummy（標準解）

class Solution: def swapPairs(self, head: Optional[ListNode]) -> Optional[ListNode]: dummy = ListNode(0, head) prev = dummy # 只要還有「兩個」節點可以交換 while prev.next and prev.next.next: first = prev.next second = first.next # 三條線重接：prev -> second -> first -> (second 原本的下一個) first.next = second.next second.next = first prev.next = second prev = first # first 現在在後面，它是下一對的「前一個」 return dummy.next

三條線的重接順序

交換前： prev -> first -> second -> rest ① first.next = second.next first -> rest （先保住 rest） ② second.next = first second -> first ③ prev.next = second prev -> second 交換後： prev -> second -> first -> rest ✔ 為什麼順序不能亂？ 如果先做 ③（prev.next = second）， 那 prev 就不再指向 first 了 —— 但我們已經把 first 存在區域變數裡，其實還找得到。 真正致命的是：如果先做 ②（second.next = first）， 就會蓋掉 second 原本指向的 rest， ① 再去讀 second.next 就會拿到 first，形成一個環！ first -> first -> first -> ... 無限迴圈 實務上的安全做法：先把所有「等下會用到的指標」存進區域變數， 再開始改。上面的程式碼就是這樣寫的（first、second 都先存好）。

為什麼結束後 prev = first 而不是 prev = second？

因為交換之後 first 跑到了後面。下一對的「前一個節點」是 first，不是 second。這是最容易寫錯的一行 —— 寫成 second 的話 prev 沒有前進，會變成無限迴圈。

while 條件為什麼要檢查兩個？

prev.next：還有節點嗎？prev.next.next：還有第二個節點嗎？少了任一個，奇數長度的串列或空串列就會崩潰。而且順序不能顛倒 —— Python 的 and 短路求值保證了prev.next 是 None 時不會去讀 .next。

複雜度說明
時間O(n)每個節點處理一次
空間O(1)只用幾個指標
解法二

遞迴（最短）

class Solution: def swapPairs(self, head: Optional[ListNode]) -> Optional[ListNode]: # 不足兩個就不用換 if not head or not head.next: return head second = head.next head.next = self.swapPairs(second.next) # 後面的先換好，再接上來 second.next = head return second # 換完之後 second 變成這一段的頭

語意非常清楚：「換掉前兩個，然後把『後面換好的結果』接到第一個節點後面。」

swapPairs([1,2,3,4]) second = 2 head(1).next = swapPairs([3,4]) second = 4 head(3).next = swapPairs([]) = None 4.next = 3 return 4 -> [4,3] 所以 1.next = [4,3] 的頭，也就是 4 2.next = 1 return 2 -> [2,1,4,3] ✔

終止條件 not head or not head.next 同時處理了「空串列」和「只剩一個節點」，回傳 head 本身 —— 不足兩個就原封不動。

不需要 dummy，因為「這一段的新頭是誰」就是回傳值。

缺點一樣是 O(n) 的堆疊深度。n = 100 沒問題。

複雜度說明
時間O(n)每對一層遞迴
空間O(n)遞迴堆疊
解法三

只交換值（題目禁止，列出來當對照）

class Solution: def swapPairs(self, head: Optional[ListNode]) -> Optional[ListNode]: # 只交換「值」而不動指標 —— 題目通常不允許，這裡列出來當對照 node = head while node and node.next: node.val, node.next.val = node.next.val, node.val node = node.next.next return head

兩行就結束。邏輯上「輸出」完全正確，但它違反了題目的要求，而且在真實場景下可能有嚴重問題（見最上面的說明）。

為什麼還要看它？因為它讓你清楚看出：這題的難度完全來自那條限制。拿掉限制，問題是 Easy；加上限制，才需要練指標重接。面試時值得主動說一句「如果可以改值的話兩行就好，但題目不允許」—— 這顯示你理解了限制存在的理由。

複雜度說明
時間O(n)掃一遍
空間O(1)只用一個指標

邊界條件檢查清單

  • 空串列：[] → []。
  • 只有一個：[1] → [1]。
  • 剛好兩個：[1,2] → [2,1]。
  • 奇數長度：[1,2,3] → [2,1,3]。最後一個不動。
  • 偶數長度：[1,2,3,4] → [2,1,4,3]。
  • prev = second 的錯誤：會造成無限迴圈（prev 沒前進）。
  • 重接順序錯誤：先寫 second.next = first 會製造出自環，from_list 之類的檢查會卡死。

常見追問

追問一：如果是每 k 個一組反轉呢？

那就是第 25 題（Reverse Nodes in k-Group），Hard。這題是 k = 2 的特例。一般化之後不能再用「三條線」硬寫，要先數夠 k 個，再反轉那一段，然後把前後接回去。建議把這兩題連著練。

追問二：如果最後不足 k 個要反轉呢？

第 25 題的變體。差別只在「數不夠 k 個」時是 return 還是照樣反轉。面試時一定要先問清楚這一點。

追問三：為什麼題目要禁止交換值？

除了前面說的「節點可能很大／可能有外部參照」之外，還有一個教學上的理由：指標重接是鏈結串列的核心技能，而交換值會讓你完全繞過它。第 25、92、206 這些題都在練同一件事 —— 在只能往前走的結構上，安全地改變連接順序。
