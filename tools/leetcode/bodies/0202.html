Problem

Decide whether a positive integer n is happy.

Starting from n, repeatedly replace the number with the sum of the squares of its decimal digits. If this process eventually reaches 1, the number is happy. If it instead falls into a loop that never contains 1, it is not happy.

Return true if n is happy, otherwise false.

中文翻譯

判斷正整數 n 是不是快樂數。

從 n 開始，反覆把數字換成「它每一位數字的平方和」。如果最後能變成 1，它就是快樂數；如果掉進一個不含 1 的無限循環，就不是。

是快樂數就回傳 true，否則回傳 false。

範例

範例 1 輸入：n = 19 輸出：true 說明：1² + 9² = 82 8² + 2² = 68 6² + 8² = 100 1² + 0² + 0² = 1 範例 2 輸入：n = 2 輸出：false 說明：2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → …（循環）

限制條件

  • 1 ≤ n ≤ 2³¹ − 1

LeetCode 原題

解題思路

【這個過程只有兩種結局】 1. 走到 1（1 → 1 → 1 …，也是一種「循環」，但它是好的） 2. 走進一個不含 1 的循環 【會不會無限變大、永遠不重複？】不會。 一個 d 位數，它的「位數平方和」最多是 81 × d。 10 位數 最多 81 × 10 = 810 所以不管 n 多大，一步之後就掉到 810 以下， 之後永遠在 [1, 810] 裡打轉。 有限的範圍 + 確定性的規則 -> 一定會重複 -> 一定有循環 ✔ 【所以問題變成】： 「這條序列最後會停在 1，還是停在別的循環？」 = 鏈結串列找環（第 141 題）的換皮版本。
解法一

雜湊集合記錄走過的數

class Solution: def isHappy(self, n: int) -> bool: def nxt(x: int) -> int: s = 0 while x: x, d = divmod(x, 10) s += d * d return s seen = set() while n != 1 and n not in seen: # ★ 重複出現 = 進入循環 seen.add(n) n = nxt(n) return n == 1
【為什麼用 divmod 而不是 str(n)？】 兩者都可以。divmod 避免建立字串， 在其他語言裡也是標準寫法。 【集合最多會存多少個數？】 第一步之後就 ≤ 810，所以集合大小是常數等級。
複雜度說明
時間O(log n)第一步處理 log n 位數，之後在常數範圍內
空間O(log n)集合大小有上界
解法二

Floyd 快慢指標（O(1) 空間）

class Solution: def isHappy(self, n: int) -> bool: def nxt(x: int) -> int: s = 0 while x: x, d = divmod(x, 10) s += d * d return s slow, fast = n, nxt(n) while fast != 1 and slow != fast: slow = nxt(slow) # 走一步 fast = nxt(nxt(fast)) # 走兩步 return fast == 1
【把 nxt() 想成鏈結串列的 .next】 slow 每次走一步，fast 每次走兩步。 - 如果會走到 1：fast 先到 1，而 1 的下一個還是 1。 - 如果有環：fast 一定會在環裡追上 slow。 【結束條件】 fast == 1 -> 快樂 ✔ slow == fast != 1 -> 在不含 1 的環裡相遇 ✘ 【為什麼 fast 初始是 nxt(n) 而不是 n？】 如果兩者都從 n 開始，while 條件 slow != fast 一開始就不成立，迴圈根本不會執行。
複雜度說明
時間O(log n)同解法一
空間O(1)只有兩個變數
解法三

數學：唯一的不快樂循環

class Solution: def isHappy(self, n: int) -> bool: cycle = {4, 16, 37, 58, 89, 145, 42, 20} # ★ 唯一的非 1 循環 while n != 1 and n not in cycle: n = sum(int(d) ** 2 for d in str(n)) return n == 1

數學上可以證明，所有不快樂數最後都會掉進 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 這個循環。所以只要看到其中任何一個數，就可以判定不快樂。

這個解法最快，但它依賴一個「背下來的事實」——面試時可以提，但要說明它的根據（範圍有限，可以暴力驗證 1–810 的所有數）。

複雜度說明
時間O(log n)
空間O(1)集合是常數大小

邊界條件檢查清單

  • n = 1 → 直接是快樂數。
  • n = 7 → 7 → 49 → 97 → 130 → 10 → 1，是快樂數（個位數裡只有 1 和 7）。
  • 很大的 n → 一步之後就 ≤ 810，不需要擔心。
  • 快慢指標兩者都從 n 開始 → 迴圈不會執行，永遠回傳 false（除非 n = 1）。

常見追問

追問一：怎麼證明序列一定會進入循環？

1. d 位數的位數平方和 ≤ 81d。 2. 當 d ≥ 4 時，81d < 10^(d-1)，也就是「下一個數的位數會變少」。 3. 所以序列最後一定落在 ≤ 3 位數（≤ 243）的範圍內。 4. 有限狀態 + 確定性的轉移 -> 鴿籠原理：一定會重複。

追問二：這個「函數迭代找環」的模式還出現在哪？

  • 第 141 / 142 題 環狀鏈結串列：最原始的版本。
  • 第 287 題 尋找重複數：把陣列看成 i → nums[i] 的函數，用 Floyd 找環的入口。
  • 偽隨機數產生器的週期偵測：同樣是 Floyd 或 Brent 演算法。
