Problem

Given the head of a singly linked list and two integers left and right where left <= right, reverse the nodes of the list from position left to position right, and return the reversed list.

Follow up: Could you do it in one pass?

中文翻譯

給你一個單向鏈結串列的頭節點 head，以及兩個整數 left 和 right（left ≤ right），請把第 left 到第 right 個節點反轉，回傳處理後的串列。（位置從 1 開始算。）

進階：能不能只走一趟？

三段式：前、中（要反轉）、後

1 -> 2 -> 3 -> 4 -> 5，left = 2, right = 4 [1] [2 -> 3 -> 4] [5] 前 中 後 反轉中段： 4 -> 3 -> 2 接回去： 1 -> 4 -> 3 -> 2 -> 5 需要記住四個位置： prev = 前段的最後一個（節點 1） start = 中段的第一個（節點 2）—— 反轉後會變成中段的尾巴 中段反轉後的新頭（節點 4） cur = 後段的第一個（節點 5） 三個接點： prev.next = 新頭 (1 -> 4) start.next = 後段 (2 -> 5) 為什麼要 dummy node？ 因為 left 可以是 1 —— 那時候「前段」是空的， prev 就是 dummy。 沒有 dummy 的話，「反轉包含頭節點」要另外寫一套 ✘

兩種實作方式：頭插法（一趟，邊走邊反轉）或切開 → 反轉 → 接回（概念最清楚）。

範例

範例 1 輸入：head = [1,2,3,4,5], left = 2, right = 4 輸出：[1,4,3,2,5] 範例 2 輸入：head = [5], left = 1, right = 1 輸出：[5]

限制條件

  • 串列節點數是 n，1 ≤ n ≤ 500
  • −500 ≤ Node.val ≤ 500
  • 1 ≤ left ≤ right ≤ n

LeetCode 原題

先看懂限制在說什麼

  • 位置從 1 開始（不是 0）。所以要走到「第 left 個的前一個」，從 dummy 出發要走 left - 1 步。
  • left 可以等於 1 —— 反轉包含頭節點。這是必須用 dummy 的理由。
  • left 可以等於 right —— 什麼都不用做。兩種解法都自然處理（迴圈跑 0 次），但提前 return 更清楚。
  • 保證 right ≤ n，所以不用檢查越界。

解題思路

解法一

頭插法（一趟，符合進階要求）

class Solution: def reverseBetween(self, head: Optional[ListNode], left: int, right: int) -> Optional[ListNode]: if not head or left == right: return head dummy = ListNode(0, head) # 走到「要反轉的那一段」的前一個節點 prev = dummy for _ in range(left - 1): prev = prev.next # 頭插法：把 cur 後面的節點一個一個「摘下來、插到 prev 後面」 cur = prev.next for _ in range(right - left): nxt = cur.next # 要被搬走的節點 cur.next = nxt.next # 把它從原位摘掉 nxt.next = prev.next # 插到 prev 後面 prev.next = nxt return dummy.next

三行重接，順序絕對不能亂

nxt = cur.next # 記住要搬的那個節點 cur.next = nxt.next # 把 nxt 從原位摘掉（cur 直接連到 nxt 的下一個） nxt.next = prev.next # nxt 接到「目前 prev 後面的那個」 prev.next = nxt # prev 指向 nxt 為什麼是這個順序？ 每一步都只依賴「還沒被改掉」的指標。 如果先做 prev.next = nxt， 那 nxt.next = prev.next 就會變成 nxt.next = nxt（自環）✘ 驗證（1 -> 2 -> 3 -> 4 -> 5，prev=1, cur=2）： 第 1 輪： nxt = 3 cur.next = nxt.next -> 2 -> 4 （3 被摘掉） nxt.next = prev.next -> 3 -> 2 prev.next = nxt -> 1 -> 3 結果：1 -> 3 -> 2 -> 4 -> 5 ✔ 第 2 輪： nxt = cur.next = 4 （cur 還是 2！） cur.next = nxt.next -> 2 -> 5 nxt.next = prev.next -> 4 -> 3 prev.next = nxt -> 1 -> 4 結果：1 -> 4 -> 3 -> 2 -> 5 ✔

cur 為什麼從頭到尾都不動？

因為 cur 指的是「中段原本的第一個節點」，而它反轉後會變成中段的最後一個 —— 它的位置在邏輯上是固定的（尾巴）。我們一直在把它「後面」的節點搬到前面去，所以它會一路被擠到最後。

迴圈跑 right - left 次（不是 +1）—— 因為有 right - left + 1 個節點，但第一個（cur）不用搬。

一趟、O(1) 空間，符合進階要求。但三行重接的順序很容易寫錯 —— 建議在紙上畫一遍再下筆。

解法二

切開 → 反轉 → 接回（概念最清楚）

class Solution: def reverseBetween(self, head: Optional[ListNode], left: int, right: int) -> Optional[ListNode]: if not head or left == right: return head dummy = ListNode(0, head) # 1. 找到那一段的「前一個」和「第一個」 prev = dummy for _ in range(left - 1): prev = prev.next start = prev.next # 反轉後會變成這一段的「尾巴」 # 2. 標準的串列反轉，做 (right - left + 1) 次 p, cur = None, start for _ in range(right - left + 1): nxt = cur.next cur.next = p p = cur cur = nxt # 此時 p 是反轉後的「新頭」，cur 是這一段後面的第一個節點 # 3. 把三段接回去 prev.next = p start.next = cur return dummy.next

三個步驟，各自對應一個已知的技巧

1. 定位 從 dummy 走 left-1 步 -> prev start = prev.next 2. 反轉（就是第 206 題的標準寫法） p, cur = None, start 重複 (right - left + 1) 次： nxt = cur.next; cur.next = p; p = cur; cur = nxt 跑完之後： p = 反轉後的新頭（原本的第 right 個） cur = 後段的第一個（原本的第 right+1 個，或 None） start = 反轉後的尾巴（它的 next 現在指向 p 的前一個，是錯的） 3. 接回 prev.next = p 前段接到新頭 start.next = cur 反轉後的尾巴接到後段 為什麼 start 一定是「反轉後的尾巴」？ 反轉會把順序整個顛倒， 原本的第一個自然變成最後一個 ✔

優點：每一步都是「已知正確的元件」—— 定位、第 206 題的反轉、接回。如果第 206 題已經寫熟，這個版本幾乎不可能寫錯。

「一趟」嗎？嚴格說它走了 left-1 + (right-left+1) = right 步，只碰到每個節點一次 —— 也算一趟。兩種解法的實際步數是一樣的。

面試建議：先寫這個版本（好解釋），如果面試官特別問「有沒有更精簡的」，再提頭插法。

邊界條件檢查清單

  • left == right：([5], 1, 1) → 原樣。迴圈跑 0 次，自然正確。
  • 反轉整條：([1,2,3], 1, 3) → [3,2,1]。
  • left == 1：([1,2], 1, 2) → [2,1]。沒有 dummy 會在這裡出錯。
  • right == n：([1,2,3], 2, 3) → [1,3,2]。後段是空的，start.next = None。
  • 單一節點：([5], 1, 1) → [5]。
  • 兩個節點：([3,5], 1, 2) → [5,3]。
  • 重接順序寫錯：會產生自環，走訪時無限迴圈。測試時一定要檢查回傳的串列會不會停。

常見追問

追問一：如果要「每 k 個一組反轉」呢？

第 25 題（Reverse Nodes in k-Group）。本質上是「重複做這一題」 —— 每一組都是一次區間反轉，只是要先數夠 k 個。

三題的關係：

第 206 題 反轉整條串列 最基本 第 92 題 反轉中間一段 [left, right] 本題 第 25 題 每 k 個一組反轉 重複做第 92 題 建議的學習順序：206 -> 92 -> 25 每一題都建立在前一題之上。

追問二：頭插法還能用在哪？

「頭插法」的本質是「把後面的元素一個一個搬到前面」 —— 它天然產生「反轉」的效果。

  • 建立一個反序的串列：讀入時每個都插在頭部
  • LRU 快取（第 146 題）：把剛使用的節點移到最前面
  • 第 25 題：每一組都用頭插法

追問三：如果是雙向串列呢？

反轉一段雙向串列時，每個節點的 prev 和 next 都要交換，而且接回去時要處理四個指標（前段的 next、新頭的 prev、新尾的 next、後段的 prev）。更容易寫錯，但邏輯上是一樣的三段式。

追問四：這類題目的除錯建議？

  • 在紙上畫出「改動前」和「改動後」的圖，標出每個指標
  • 用最小的例子驗證（[1,2]、left=1, right=2）
  • 檢查有沒有自環：走訪回傳的串列，如果不會停就是有環
  • 檢查節點總數：反轉前後的節點數必須相同

本篇的 from_list 就內建了環偵測 —— 這是測試串列題最有價值的一行程式碼。
