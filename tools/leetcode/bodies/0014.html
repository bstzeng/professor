Problem

Write a function to find the longest common prefix string amongst an array of strings.

If there is no common prefix, return an empty string "".

中文翻譯

寫一個函式，找出一組字串裡最長的共同前綴。

如果沒有共同前綴，回傳空字串 ""。

前綴的兩個性質，決定了所有解法

性質 1：答案的長度不會超過「最短的那個字串」 ["abcdef", "ab"] -> 最多只能是 "ab" 性質 2：共同前綴具有「傳遞收斂」的性質 LCP(a, b, c) = LCP(LCP(a, b), c) 也就是可以一個一個併進去，不必同時看全部。 性質 3（最漂亮的一個）： 把所有字串照「字典序」排好之後， LCP(全部) == LCP(最小的那個, 最大的那個) 因為字典序最小和最大的兩個字串「差最多」， 它們都同意的前綴，中間的字串一定也同意。

範例

範例 1 輸入：strs = ["flower", "flow", "flight"] 輸出："fl" 範例 2 輸入：strs = ["dog", "racecar", "car"] 輸出："" 說明：連第一個字元都不一樣。

限制條件

  • 1 ≤ strs.length ≤ 200
  • 0 ≤ strs[i].length ≤ 200（字串可以是空的）
  • strs[i] 只含小寫英文字母

LeetCode 原題

先看懂限制在說什麼

  • 字串可以是空的。["", "b"] 的答案是 ""。任何對 s[0] 的存取都要先確認長度 —— 這是本題最常見的 IndexError 來源。
  • 陣列至少有一個元素（strs.length ≥ 1），所以理論上不用檢查空陣列。但寫上 if not strs 只要一行，而且讓函式在別的情境下也安全 —— 建議保留。
  • 只有一個字串時，答案就是它自己。["a"] → "a"。
  • 規模很小（200 × 200 = 40000 個字元），任何解法都會過。這題考的是邊界處理的乾淨程度。

解題思路

解法怎麼掃時間特點
一、垂直掃描一欄一欄往下比O(S)最早退出，最直覺
二、水平掃描把 prefix 和下一個字串合併O(S)體現 LCP 的結合律
三、排序取頭尾只比 min 和 maxO(n·m)最少的比較次數
四、zipPython 的一行流O(S)最短，但要懂 zip 的行為

S 是所有字元的總數。四種都是線性等級，差別在提早退出的時機和可讀性。

解法一

垂直掃描：一欄一欄比（最推薦）

把所有字串上下對齊排好，一次比一「欄」。只要有任何一個字串在這一欄對不上（或已經沒字元了），就結束。

strs = ["flower", "flow", "flight"] 欄位: 0 1 2 3 4 5 f l o w e r f l o w f l i g h t ─ ─ ✘ ✔ ✔ 第 2 欄：o vs o vs i -> 不一致，停 答案 = first[:2] = "fl"
class Solution: def longestCommonPrefix(self, strs: List[str]) -> str: if not strs: return "" first = strs[0] for i, ch in enumerate(first): # 一欄一欄往下比 for other in strs[1:]: if i >= len(other) or other[i] != ch: return first[:i] # 這一欄對不上，前 i 個字元就是答案 return first # 第一個字串本身就是共同前綴

最壞情況只會比到「最短字串的長度」次，因為 i >= len(other) 會在最短的字串用完時立刻 return。

這是四種解法裡最早退出的：只要第一欄就不一致（像範例 2），只做 n−1 次比較就結束了。

複雜度說明
時間O(S)S = 所有字元總數；不一致時提早退出
空間O(1)只回傳切片
解法二

水平掃描：把答案一個一個併進去

利用 LCP(a,b,c) = LCP(LCP(a,b), c)：先拿第一個當候選前綴，然後每遇到一個新字串就把候選砍短，直到它是新字串的前綴為止。

prefix = "flower" vs "flow": "flow".startswith("flower") ✘ -> prefix = "flowe" "flow".startswith("flowe") ✘ -> prefix = "flow" "flow".startswith("flow") ✔ 停 vs "flight": "flight".startswith("flow") ✘ -> prefix = "flo" "flight".startswith("flo") ✘ -> prefix = "fl" "flight".startswith("fl") ✔ 停 答案 = "fl"
class Solution: def longestCommonPrefix(self, strs: List[str]) -> str: if not strs: return "" prefix = strs[0] for s in strs[1:]: # 一直砍 prefix 的尾巴，直到它是 s 的前綴 while not s.startswith(prefix): prefix = prefix[:-1] if not prefix: return "" return prefix

if not prefix: return "" 這行不能省 —— 否則 prefix[:-1] 在空字串上會一直是空字串，"".startswith("") 是 True，所以其實不會死循環，但加上這行可以提早結束，也讓意圖更清楚。

這個解法的價值在於它體現了「結合律」，可以直接推廣成 map-reduce：把字串分成幾組平行算出各組的 LCP，再把結果兩兩合併。

複雜度說明
時間O(S)m = 最短字串長度
空間O(m)prefix 的切片
解法三

排序後只比頭尾（最少的字元比較）

字典序排序後，只需要比最小和最大這兩個字串。

為什麼只比頭尾就夠？

設排序後是 s₁ ≤ s₂ ≤ ... ≤ sₙ（字典序） 宣稱：LCP(全部) = LCP(s₁, sₙ) 證明的直覺： 設 p = LCP(s₁, sₙ)，也就是 s₁ 和 sₙ 的前 |p| 個字元都一樣。 對於中間任何一個 sₖ，我們有 s₁ ≤ sₖ ≤ sₙ。 字典序比較是「從左到右逐字元比，第一個不同的決定大小」。 既然 s₁ 和 sₙ 的前 |p| 個字元完全相同， 而 sₖ 被夾在它們中間， sₖ 的前 |p| 個字元也只能是同一串 —— 否則它會跑到 s₁ 之前或 sₙ 之後。 所以 p 是所有字串的共同前綴。 又因為 LCP(全部) ⊆ LCP(s₁, sₙ)（子集的 LCP 一定不比全集短）， 兩邊相等。
class Solution: def longestCommonPrefix(self, strs: List[str]) -> str: if not strs: return "" # 字典序排序後，只有頭尾兩個需要比 lo, hi = min(strs), max(strs) for i, ch in enumerate(lo): if i >= len(hi) or hi[i] != ch: return lo[:i] return lo

用 min() 和 max() 只要 O(n·m) 就能找出頭尾，不必真的做 O(n·m·log n) 的完整排序。

字元比較次數最少（只比兩個字串），但因為 min／max 本身要掃過所有字串，總複雜度沒有變好。面試時提出來會是很好的加分點 —— 它展示了你會從「資料的序關係」找結構。

複雜度說明
時間O(n·m)n 個字串各比較一次求 min/max
空間O(1)只回傳切片
解法四

Python 的 zip 一行流

class Solution: def longestCommonPrefix(self, strs: List[str]) -> str: if not strs: return "" out = [] for chars in zip(*strs): # zip 在最短的字串用完時自動停 if len(set(chars)) > 1: # 這一欄有人不一樣 break out.append(chars[0]) return "".join(out)

zip(*strs) 在做什麼？

strs = ["flower", "flow", "flight"] zip(*strs) 等於 zip("flower", "flow", "flight") -> ('f', 'f', 'f') ('l', 'l', 'l') ('o', 'o', 'i') <- set 大小 3 > 1，break ... 關鍵：zip 會在「最短的那個」用完時自動停止。 "flow" 只有 4 個字元，所以最多只會產生 4 組。 這剛好就是我們要的「答案不超過最短字串」的性質 —— 連檢查都不用寫。 len(set(chars)) > 1 就是「這一欄有人不一樣」。

如果 strs 裡有空字串會怎樣？zip 會立刻停（最短長度是 0），迴圈一次都不跑，回傳 "" —— 正確。

很 Pythonic，寫起來很爽。但面試時建議先寫解法一，再說「Python 可以這樣一行寫」，因為面試官想確認你懂演算法，而不是懂語言特性。

複雜度說明
時間O(S)每一欄建一次 set
空間O(m)輸出的 list

解法時間空間最早退出？備註

二、水平掃描O(S)O(m)普通可平行化（結合律）

邊界條件檢查清單

  • 完全沒有共同前綴：["dog","racecar","car"] → ""。
  • 含空字串：[""]、["","b"]、["b",""] → 全部是 ""。
  • 其中一個是另一個的前綴：["ab","a"] → "a"。垂直掃描要靠 i >= len(other) 這個檢查擋住。
  • 全部一樣：["abc","abc","abc"] → "abc"。第一個字串會被完整走完，迴圈正常結束。
  • 只有一個字串：["a"] → "a"。
  • 第一個字串最短：["c","acc","ccc"] → ""。

常見追問

追問一：如果字串陣列很大，而且會反覆查詢不同的子集合呢？

建一棵 Trie（字典樹）。所有字串插進去之後，從根節點往下走，只要當前節點只有一個子節點而且不是某個字串的結尾，就繼續往下。建樹 O(S)，之後每次查詢 O(答案長度)。但如果只查一次，建 Trie 是浪費 —— 建樹本身就已經 O(S) 了。

追問二：要找最長共同「後綴」呢？

把每個字串反轉，套用同一套解法，答案再反轉回來。一行 [s[::-1] for s in strs] 就解決。

追問三：這個問題可以平行化嗎？

可以，而且很漂亮。因為 LCP 滿足結合律（LCP(LCP(a,b), c) = LCP(a, LCP(b,c))）而且有單位元（任意長字串），它是一個 monoid。所以可以把陣列切成 k 塊，各自算出局部 LCP，再把 k 個結果兩兩合併 —— 這正是 map-reduce 的標準形式。
