Problem

Given a signed 32-bit integer x, return x with its digits reversed. If reversing x causes the value to go outside the signed 32-bit integer range [-2³¹, 2³¹ - 1], then return 0.

Assume the environment does not allow you to store 64-bit integers (signed or unsigned).

中文翻譯

給你一個 32 位元的有號整數 x，請把它的每一位數字反轉後回傳。如果反轉後的結果超出 32 位元有號整數的範圍 [-2³¹, 2³¹ − 1]，就回傳 0。

假設執行環境不允許你存 64 位元整數（不論有號無號）。

這題的真正考點是溢位，不是反轉

反轉本身在 Python 裡是一行：int(str(abs(x))[::-1])。題目真正想考的是那句「不准用 64 位元整數」。

INT_MAX = 2147483647 （2³¹ − 1，10 位數） INT_MIN = -2147483648 （−2³¹） x = 1534236469 → 反轉是 9646324351 → 超過 INT_MAX → 回傳 0 x = 1463847412 → 反轉是 2147483641 → 剛好在範圍內 → 回傳 2147483641 注意 INT_MIN 的絕對值比 INT_MAX 大 1： -(-2147483648) = 2147483648 > INT_MAX 在 C / Java 裡 abs(INT_MIN) 本身就會溢位！

Python 的整數是任意精度的，所以你在 Python 裡「感覺不到」這個問題。但面試官問的是：如果是 C 或 Java，你會怎麼寫？下面解法二就是那個答案。

範例

範例 1 輸入：x = 123 輸出：321 範例 2 輸入：x = -123 輸出：-321 說明：負號留在原地，只反轉數字部分。 範例 3 輸入：x = 120 輸出：21 說明：反轉後的前導零要去掉（021 → 21）。 範例 4 輸入：x = 1534236469 輸出：0 說明：反轉後是 9646324351，超出 32 位元範圍。

限制條件

  • −2³¹ ≤ x ≤ 2³¹ − 1，也就是 −2147483648 ≤ x ≤ 2147483647

LeetCode 原題

先看懂限制在說什麼

  • 輸入保證在範圍內，輸出不保證。要檢查的是結果，不是輸入。
  • x = -2147483648（INT_MIN）是必考測資。在 C/Java 裡 -x 或 abs(x) 都會溢位；而它反轉後是 8463847412，遠超範圍，答案是 0。
  • 前導零自動消失。120 → 021 → 21。用 int() 轉換會自動處理；用逐位算的方法也會自動處理（開頭的 0 乘進去等於沒乘）。
  • x = 0 → 0。逐位法的 while 迴圈一次都不會跑，剛好回傳初值 0。

解題思路

兩個層次：Python 的寫法（能過、三行）和 C/Java 的寫法（面試官真正想看的溢位處理）。建議兩個都準備。

解法一

字串反轉（Python 的作弊寫法）

class Solution: def reverse(self, x: int) -> int: INT_MIN, INT_MAX = -2**31, 2**31 - 1 sign = -1 if x < 0 else 1 r = sign * int(str(abs(x))[::-1]) return 0 if r < INT_MIN or r > INT_MAX else r

為什麼要先取 abs 再反轉？

因為 str(-123) 是 "-123"，直接 [::-1] 會變成 "321-"，int() 會拋例外。先把符號拆出來、只反轉數字部分，最後再乘回去，是最乾淨的做法。

這個解法在 LeetCode 上會過。但如果面試官說「假設不能用字串轉換」或「假設是 32 位元環境」，它就完全不成立了 —— 它靠的正是 Python 的任意精度整數。

複雜度說明
時間O(log x)位數是 log₁₀x，最多 10 位
空間O(log x)字串本身
解法二

逐位取出，並在溢位「之前」就攔下來

標準做法：不斷 % 10 取最低位、// 10 砍掉它，把取出的位數往結果的左邊推。

x = 123 輪 1： d = 123 % 10 = 3 x = 12 r = 0*10 + 3 = 3 輪 2： d = 12 % 10 = 2 x = 1 r = 3*10 + 2 = 32 輪 3： d = 1 % 10 = 1 x = 0 r = 32*10 + 1 = 321 x 變成 0，結束 → 321

關鍵：怎麼在「不能用更大的型別」的前提下判斷溢位？

直覺會想寫 if r * 10 + d > INT_MAX —— 但在 C/Java 裡，r * 10 + d 這個算式本身就已經溢位了，算出來的值是環繞後的垃圾，拿它去比較毫無意義。

解法是把不等式移項，讓兩邊都不會超過範圍：

想判斷： r * 10 + d > INT_MAX 移項： r * 10 > INT_MAX - d r > (INT_MAX - d) / 10 因為 r 和 d 都是整數，且 d ∈ [0, 9]： r > (INT_MAX - d) // 10 ← 這一行永遠不會溢位 左邊的 r 是現有的合法值， 右邊 (INT_MAX - d) // 10 最大是 214748364，也是合法值。 兩個合法值比大小，安全。
class Solution: def reverse(self, x: int) -> int: INT_MIN, INT_MAX = -2**31, 2**31 - 1 sign = -1 if x < 0 else 1 x = abs(x) r = 0 while x: d = x % 10 x //= 10 # 事前檢查：如果 r*10 + d 會超過 INT_MAX，現在就收手 # 寫成 r > (INT_MAX - d) // 10 可以完全避免溢位 if r > (INT_MAX - d) // 10: return 0 r = r * 10 + d r *= sign return 0 if r < INT_MIN or r > INT_MAX else r

常見的簡化寫法（以及它為什麼也對）

很多題解寫成： if r > INT_MAX // 10 or (r == INT_MAX // 10 and d > 7): return 0 INT_MAX // 10 = 214748364，INT_MAX % 10 = 7 r > 214748364 → r*10 一定超過 → 溢位 r == 214748364 且 d > 7 → 214748364*10 + d = 2147483640 + d > 2147483647 → 溢位 其他情況 → 安全 兩種寫法等價。移項版比較短，分case 版比較好讀， 但分case 版要記住那個「7」是哪來的（就是 INT_MAX 的個位數）。

負數怎麼辦？

這裡先取 abs(x)、全部用正數算、最後乘回符號，所以只要檢查上界。在 C 裡不能這樣做（abs(INT_MIN) 會溢位），標準 C 寫法是全程用負數算、只檢查下界 INT_MIN，因為負數那一側的範圍比較大，不會漏掉任何合法值。如果面試考的是 C，值得把這點講出來。

邊界條件檢查清單

  • x = 0 → 0。while 迴圈跑 0 次。
  • x = -2147483648（INT_MIN） → 0。C/Java 裡 abs 會溢位，必須小心。
  • x = 1463847412 → 2147483641。剛好沒溢位，用來驗證你的判斷式沒有多擋。
  • x = 1534236469 → 0。剛好溢位，用來驗證你的判斷式沒有漏擋。
  • 結尾是 0：120 → 21、1000 → 1。
  • 單一位數：7 → 7、-7 → -7。

常見追問

追問一：如果不准用取模和除法呢？

只能走字串／字元陣列的路：把數字一位一位印成字元、反轉、再手動累加回去。但累加時同樣要做溢位檢查，判斷式完全一樣。

追問二：反轉 64 位元整數呢？

邏輯一模一樣，把 INT_MAX 換成 2**63 - 1 即可。重點是：「事前檢查」這個模式與位元寬度無關，這才是這題真正要你帶走的東西。

追問三：為什麼不能寫 try: ... except OverflowError？

Python 的整數運算根本不會丟 OverflowError（它會自動變大整數）。而 C/Java 的有號整數溢位是 undefined behavior 或靜默環繞，也不會有例外可以接。溢位必須主動預防，不能被動捕捉 —— 這是系統程式設計的基本功。
