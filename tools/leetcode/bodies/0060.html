Problem

The set [1, 2, 3, ..., n] contains a total of n! unique permutations. By listing and labeling all of the permutations in order, we get the sequence for n = 3: "123", "132", "213", "231", "312", "321".

Given n and k, return the k-th permutation sequence.

中文翻譯

集合 [1, 2, 3, ..., n] 共有 n! 種不同的排列。把它們按字典序列出來並編號（從 1 開始），例如 n = 3 時依序是："123", "132", "213", "231", "312", "321"。

給你 n 和 k，回傳第 k 個排列。

核心：排列的字典序有「分組」結構

n = 4 的 24 個排列，依「第一位是誰」分成 4 組： 第一位是 1 -> 索引 0..5 （後面 3 個數字的 3! = 6 種排列） 第一位是 2 -> 索引 6..11 第一位是 3 -> 索引 12..17 第一位是 4 -> 索引 18..23 所以「第 k 個排列的第一位是誰」可以直接算： idx = k // 3! （k 用 0-indexed） 算完之後，k 減掉前面那些組，繼續決定第二位： k = k % 3! 第二位的分組大小是 2! 這就是【階乘進位制（factorial number system / factoradic）】： 8 (十進位) = 1 × 3! + 1 × 2! + 0 × 1! + 0 × 0! = (1, 1, 0, 0) 階乘進位 而 (1, 1, 0, 0) 的意思是： 第 1 位取「剩餘候選」的第 1 個 第 2 位取「剩餘候選」的第 1 個 第 3 位取「剩餘候選」的第 0 個 第 4 位取「剩餘候選」的第 0 個 這叫做 Lehmer code —— 排列和階乘進位數之間的一一對應。

關鍵是「取剩餘候選的第幾個」而不是「取數字幾」 —— 因為用過的數字要從候選裡移除，索引會跟著變。

範例

範例 1 輸入：n = 3, k = 3 輸出："213" 範例 2 輸入：n = 4, k = 9 輸出："2314" 範例 3 輸入：n = 3, k = 1 輸出："123"

限制條件

  • 1 ≤ n ≤ 9
  • 1 ≤ k ≤ n!

LeetCode 原題

先看懂限制在說什麼

  • n ≤ 9，所以 n! 最大是 9! = 362880。這個數字剛好落在「生成所有排列會慢但不會爆」的邊緣 —— 所以樸素做法（呼叫 k−1 次 next_permutation）能過，但慢很多。
  • k 從 1 開始（1-indexed）。程式裡第一件事就是 k -= 1，轉成 0-indexed 之後所有的除法和取模才會對。忘記減 1 是本題第一名的 bug。
  • 保證 k ≤ n!，所以不用處理「k 太大」。
  • 數字是 1..9，剛好是一位數，所以答案可以直接字串串接，不用擔心多位數的問題。

解題思路

解法一

階乘進位制直接構造（標準解）

class Solution: def getPermutation(self, n: int, k: int) -> str: # 預先算好階乘：fact[i] = i! fact = [1] * (n + 1) for i in range(1, n + 1): fact[i] = fact[i - 1] * i nums = [str(i) for i in range(1, n + 1)] # 還沒用掉的數字（遞增） k -= 1 # 轉成 0-indexed out = [] for i in range(n, 0, -1): block = fact[i - 1] # 固定第一位之後，後面有 (i-1)! 種排法 idx = k // block # 第一位該取「剩餘數字」裡的第幾個 k %= block out.append(nums.pop(idx)) # 取走並從候選裡移除 return "".join(out)

三個關鍵

① k -= 1 轉成 0-indexed 為什麼？因為除法的分組是從 0 開始的： k=0..5 -> 第一組（0 // 6 = 0） k=6..11 -> 第二組（6 // 6 = 1） 如果不減 1，k=6 會算成 6//6 = 1（第二組）， 但 1-indexed 的第 6 個其實還在第一組（"1432"）。 ② nums.pop(idx) 取走並移除 候選清單必須「動態縮短」。 n=4、第一位取了 '2' 之後， 剩下的候選是 ['1','3','4']， 第二位的 idx=1 對應的是 '3' 而不是 '2'。 如果不移除，第二位的 idx=1 會取到 '2' —— 重複了。 ③ block = fact[i-1] i 是「還剩幾個數字沒放」。 固定第一位之後，剩下 i-1 個數字有 (i-1)! 種排法。 所以每一組的大小是 (i-1)!。

為什麼 nums 必須保持遞增？

因為「字典序」要求：索引小的候選，對應字典序小的排列。nums 一開始是 ['1','2',...,'n']（遞增），而 pop(idx) 不會破壞剩下元素的相對順序 —— 所以它永遠保持遞增。

複雜度

外層迴圈 n 次，每次 nums.pop(idx) 是 O(n)（list 要往前搬）。所以是 O(n²)。n ≤ 9 時完全無所謂。

如果 n 很大，可以把 nums 換成樹狀陣列（Fenwick tree）或平衡樹來支援「找第 idx 個還沒用的數字」，做到 O(n log n)。但那是競賽等級的優化，面試不需要。

複雜度說明
時間O(n²)n 次迴圈 × pop 的 O(n)
空間O(n)候選清單 + 階乘表
解法二

反覆呼叫「下一個排列」（對照組）

class Solution: def getPermutation(self, n: int, k: int) -> str: # 對照組：從最小的排列開始，呼叫 k-1 次「下一個排列」 # 正確但 O(k·n)，k 可以到 9! = 362880，會慢很多 nums = list(range(1, n + 1)) def next_perm(a): i = len(a) - 2 while i >= 0 and a[i] >= a[i + 1]: i -= 1 if i >= 0: j = len(a) - 1 while a[j] <= a[i]: j -= 1 a[i], a[j] = a[j], a[i] a[i + 1:] = reversed(a[i + 1:]) for _ in range(k - 1): next_perm(nums) return "".join(map(str, nums))

正確，而且重複利用了第 31 題的演算法。但複雜度是 O(k · n) —— k 最大 362880，n 最大 9，約 300 萬次操作。LeetCode 上大概能過，但比解法一慢好幾百倍。

什麼時候這個做法比較好？當 k 很小的時候（例如 k ≤ 10），或者當你「已經有一個排列，想要它後面的幾個」時。「直接跳到第 k 個」和「一步一步往前走」各有適用場合。

複雜度說明
時間O(k·n)呼叫 k−1 次
空間O(n)只有排列本身

邊界條件檢查清單

  • k = 1：(3, 1) → "123"（最小的排列）。k -= 1 之後 k = 0，每一位都取候選的第 0 個。
  • k = n!：(3, 6) → "321"（最大的排列）。(9, 362880) → "987654321"。
  • n = 1：(1, 1) → "1"。
  • 忘記 k -= 1：(3, 3) 會回傳 "231" 而不是 "213"。
  • 忘記 pop（只用索引不移除）：會產生重複的數字，例如 "2214"。
  • 階乘表的邊界：fact[0] = 1（0! = 1）。最後一位的 block = fact[0] = 1，idx = k // 1 = k，而此時 k 必然是 0，所以取候選的第 0 個（唯一剩下的那個）✔

常見追問

追問一：反過來，給一個排列求它是第幾個？

這叫做求 Lehmer code（排列的排名，ranking）。

對每一位 i，數出「它右邊有幾個比它小的數字」，設為 c_i。 然後排名 = Σ c_i × (n-1-i)! （0-indexed），最後 +1 轉回 1-indexed。 "2314" 的排名： '2' 右邊比它小的：只有 '1' -> c_0 = 1 '3' 右邊比它小的：只有 '1' -> c_1 = 1 '1' 右邊比它小的：沒有 -> c_2 = 0 '4' 右邊比它小的：沒有 -> c_3 = 0 排名（0-indexed）= 1×3! + 1×2! + 0×1! + 0×0! = 6 + 2 = 8 1-indexed = 9 ✔ 樸素做法是 O(n²)（每一位都往右數）。 用樹狀陣列可以做到 O(n log n)。 「排名（rank）」和「反排名（unrank）」是一對 —— 本題是 unrank，這個追問是 rank。

追問二：如果集合裡有重複元素呢？

分組的大小就不再是 (i-1)!，而是「多重集合的排列數」(i-1)! / ∏(cⱼ!)。程式的骨架一樣，但每取走一個數字之後，要重新計算下一組的大小。比原題麻煩得多，但思路完全相同。

追問三：這個「直接跳到第 k 個」的技巧還能用在哪？

  • 第 22 題 Generate Parentheses：用卡塔蘭數算「走左分支有幾個答案」，就能直接定位第 k 個合法括號序列
  • 組合的第 k 個：用組合數 C(n,k) 分組
  • 子集合的第 k 個：直接用 k 的二進位表示
  • 格雷碼的第 k 個（第 89 題）：k ^ (k >> 1)

共同的模式：把「第 k 個」的問題，轉成「k 在某個進位制下的表示」。只要枚舉的結構有清楚的分組，就能跳過前面所有的答案直接算出目標。
