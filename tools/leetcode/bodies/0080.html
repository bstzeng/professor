Problem

Given an integer array nums sorted in non-decreasing order, remove some duplicates in-place such that each unique element appears at most twice. The relative order of the elements should be kept the same.

Return k after placing the final result in the first k slots of nums.

中文翻譯

給你一個非遞減排序的整數陣列 nums，請原地刪除重複的元素，讓每個值最多出現兩次，並保持原本的相對順序。

回傳處理後的長度 k，而且前 k 個位置要存放結果。

和第 26 題只差一個數字

第 26 題（每個值最多 1 次）： if k < 1 or x != nums[k - 1]: 第 80 題（每個值最多 2 次）： if k < 2 or x != nums[k - 2]: 一般化（每個值最多 m 次）： if k < m or x != nums[k - m]: 為什麼是「和 nums[k-m] 比」？ nums[k-m] 是「已經保留下來的、倒數第 m 個」。 如果 x 和它相同，表示「已經有 m 個和 x 一樣的值被保留了」 （因為輸入已排序，相同的值一定連續） -> 不能再收 ✘ 如果不同，表示保留的相同值不到 m 個 -> 可以收 ✔ 而 k < m 的檢查，處理「還沒收滿 m 個」的開頭情況 （此時 nums[k-m] 是負索引，在 Python 裡不會報錯但語意錯）。 這就是為什麼第 26 題我們堅持寫 nums[k-1] 而不是 nums[i-1]： 用 k 的版本可以一般化，用 i 的版本不行。

範例

範例 1 輸入：nums = [1,1,1,2,2,3] 輸出：k = 5，nums 的前 5 格是 [1,1,2,2,3] 範例 2 輸入：nums = [0,0,1,1,1,1,2,3,3] 輸出：k = 7，前 7 格是 [0,0,1,1,2,3,3]

限制條件

  • 1 ≤ nums.length ≤ 3 × 10⁴
  • −10⁴ ≤ nums[i] ≤ 10⁴
  • nums 已依非遞減順序排好

LeetCode 原題

先看懂限制在說什麼

  • 已經排序 —— 這是關鍵。相同的值一定連續，所以「已保留幾個相同的」可以從 nums[k-2] 讀出來。
  • 必須原地，而且只檢查前 k 格。
  • 值域有負數，不能用某個數字當哨兵。
  • n ≥ 1，但寫成能處理空陣列比較安全。

解題思路

雙指標：一個讀（for 迴圈的 x）、一個寫（k）。 nums = [1,1,1,2,2,3] x=1: k=0 < 2 -> nums[0]=1, k=1 x=1: k=1 < 2 -> nums[1]=1, k=2 x=1: nums[0]=1 == 1 -> 跳過（已經有兩個 1 了） x=2: nums[0]=1 != 2 -> nums[2]=2, k=3 x=2: nums[1]=1 != 2 -> nums[3]=2, k=4 x=3: nums[2]=2 != 3 -> nums[4]=3, k=5 nums = [1,1,2,2,3,3]，前 5 格 = [1,1,2,2,3] ✔ 回傳 5 注意第 6 格還是舊資料（3），但題目不檢查。 安全性：k <= i 恆成立（寫的位置永遠不超前讀的位置）， 所以 nums[k] = x 不會覆蓋掉還沒讀的資料 ✔
解法一

和「倒數第二個保留值」比較（最推薦）

class Solution: def removeDuplicates(self, nums: List[int]) -> int: k = 0 # 下一個要寫入的位置 for x in nums: # 保留的條件：還不足兩個，或和「已保留的倒數第二個」不同 if k < 2 or x != nums[k - 2]: nums[k] = x k += 1 return k

為什麼 nums[k-2] 能正確表達「已經有兩個了」？

因為輸入是【排序】的，所以： 如果 nums[k-2] == x， 那麼 nums[k-2] 和 nums[k-1] 一定都等於 x （排序後，介於兩個 x 之間的值也只能是 x） -> 已經保留了至少兩個 x -> 不能再收 ✔ 如果 nums[k-2] != x， 那麼保留的 x 最多只有一個（就是 nums[k-1]，如果它等於 x 的話） -> 還可以再收一個 ✔ 如果輸入沒有排序，這個推理就不成立 —— 例如 [1, 2, 1, 2, 1]，nums[k-2] 的值和「x 出現幾次」完全無關。 所以「已排序」這個前提， 讓我們不需要任何計數器就能知道「已經收了幾個」。

k < 2 這個檢查

處理開頭：前兩個元素無條件保留（因為最多允許兩個）。而且它擋住了 nums[k-2] 的負索引 —— 在 Python 裡負索引不會報錯（會拿到陣列尾端的值），所以這個檢查是必要的，不然會安靜地算錯。

三行核心邏輯，而且和第 26 題只差一個數字。

複雜度說明
時間O(n)掃一遍
空間O(1)只用一個下標
解法二

把 2 抽成參數（一般化）

class Solution: def removeDuplicates(self, nums: List[int]) -> int: return self._keep_at_most(nums, 2) def _keep_at_most(self, nums: List[int], m: int) -> int: """每個值最多保留 m 次 —— 把 2 抽成參數的通用版""" k = 0 for x in nums: if k < m or x != nums[k - m]: nums[k] = x k += 1 return k

同一份程式碼同時解了第 26 題（m=1）和第 80 題（m=2）。

這是一個很好的習慣：當你發現「這題和那題只差一個常數」時，就把那個常數抽出來。在真實的程式碼裡，這會變成一個可重用的函式；在面試時，它顯示你看到了問題的結構而不只是表面。

而且它讓「為什麼是 k-m」這件事變得明顯 —— 當 m 是變數時，你不可能把它誤寫成 i - m。

複雜度說明
時間O(n)同上
空間O(1)同上
解法三

明確用計數器（最直白）

class Solution: def removeDuplicates(self, nums: List[int]) -> int: # 比較直白的版本：明確數「目前這個值已經寫了幾次」 if not nums: return 0 k = 1 count = 1 for i in range(1, len(nums)): if nums[i] == nums[i - 1]: count += 1 else: count = 1 if count <= 2: nums[k] = nums[i] k += 1 return k

語意最直白：「數一數目前這個值連續出現幾次，超過 2 就不收」。

缺點：多一個變數、多一個 if，而且推廣到 m 次時要改的地方比解法一多（雖然也只是把 2 換成 m）。

但它有一個優勢：它不依賴「已排序」這個前提來判斷計數（雖然仍然依賴排序來讓相同的值連續）。如果題目改成「相同的值不一定連續」，這個版本比較容易改成用 Counter。

如果解法一的 nums[k-2] 讓你覺得不踏實，寫這個版本也完全可以。面試時清楚正確 > 精簡炫技。

複雜度說明
時間O(n)掃一遍
空間O(1)兩個變數

邊界條件檢查清單

  • 空陣列：[] → 0。解法一自然處理（迴圈不跑）。
  • 長度 1 或 2：[1] → 1；[1,1] → 2。k < 2 的檢查就是為了它們。
  • 全部相同：[1,1,1] → 2，前 2 格是 [1,1]。
  • 完全沒有重複：[1,2,3] → 3。每一格都會被寫（寫到自己身上）。
  • 剛好每個兩次：[1,1,2,2,3,3] → 6（全部保留）。
  • 混合：[0,0,1,1,1,1,2,3,3] → 7。
  • 忘記 k < 2：在 Python 裡 nums[-2] 會拿到陣列的倒數第二個元素 —— 不會報錯，但答案會錯。

常見追問

追問一：如果每個值最多保留 m 次呢？

就是解法二。if k < m or x != nums[k - m]，一個參數搞定。

追問二：如果輸入沒有排序呢？

「已排序」這個前提被拿掉之後，就得用 Counter 記錄「每個值已經收了幾次」：

from collections import Counter def keep_at_most(nums, m): seen = Counter() k = 0 for x in nums: if seen[x] < m: nums[k] = x k += 1 seen[x] += 1 return k 空間從 O(1) 變成 O(不同值的個數)。 「已排序」這個前提值多少？它省下了整個雜湊表。

追問三：這個「原地過濾」模板還能用在哪？

通用形式： k = 0 for x in nums: if <保留的條件>: nums[k] = x k += 1 return k 第 26 題 條件：x != nums[k-1] 去重（最多 1 次） 第 27 題 條件：x != val 移除特定值 第 80 題 條件：k < 2 or x != nums[k-2] 最多 2 次 第 283 題 條件：x != 0 移動零（之後再補零） 共同的安全保證： k <= i 恆成立（寫不超前讀） -> nums[k] = x 永遠不會覆蓋掉還沒讀到的資料 這是所有「原地過濾」演算法的正確性基礎， 也是 C++ 的 std::remove_if 的實作方式。

追問四：為什麼第 26 題我們堅持用 nums[k-1] 而不是 nums[i-1]？

因為那個選擇在這一題才顯出價值。第 26 題裡兩者等價（都對），但只有 nums[k-1] 的版本能直接一般化成 nums[k-m]。

這是一個很好的例子：寫程式時的「小選擇」，會在推廣的時候顯出高下。養成「用語意正確的那個變數」的習慣（這裡是「已保留的」而不是「原本的」），在之後的變形題上會省很多力氣。
